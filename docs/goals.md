# 目标与 `/loop`：跨会话的无人值守工作单元

**目标**是一份具名的清单文件，`/loop` 让它连续工作到清单上的条目全部完成。这一篇讲**现在怎么
工作**：文件长什么样、命令怎么用、循环在什么时刻做什么。为什么这么做留在
[`.scratch/goal-loop/spec.md`](../.scratch/goal-loop/spec.md) 与
[ADR 0009](adr/0009-goals-are-files-and-progress-is-derived.md)。

## 清单文件

`~/.local/share/fs-agent/goals/<名字>.md`（`$XDG_DATA_HOME/fs-agent/goals/`，两者都没设时
`/goal` 与 `/loop` 都会说找不到数据目录）。

```markdown
# grep-tool

- 01 看 bash 工具怎么注册
- 02 写 grep 工具骨架
- 03 补测试
```

人可读的 markdown：一行标题，然后一列 `- <id> <内容>`。条目**只有 id 与内容、不带状态**
——状态只有事件流一个真相源，文件里画一个复选框会让人误以为它才是进度。id 是两位十进制数字，
生成时分配、此后不动。

清单**开工前封闭**：执行中不能往里加条目，于是「所有条目都 `completed`」是一个稳定的判据。
执行中发现的新工作由模型用 `goal_note` 记下（见下），或者另开一个目标。

## `/goal new <名字> <来源> [--force]`

从一批票生成清单。`<来源>` 是一个 feature 目录（`.scratch/<slug>/`，读它下面的
`issues/NN-*.md`，没有 `issues/` 就直接读目录）或者单独一份票文件；票号变成 id，票的标题变成
条目内容。**只读票，不写回票**，生成一次之后清单与来源各自独立。

重名一律拒绝，除非加 `--force` —— 默默覆盖会抹掉一份已生成的目标定义。`/goal` 只有 `new` 一个
子命令；`list` / `show` / `rm` 都没有，清单就在磁盘上，人自己 `ls` / `cat` 就行。

它是一个**手势**：由循环直接执行，不走工具表、不走权限门、也不进事件流 —— 清单文件存在即是
「目标已创建」的证据。

## `/loop <名字>`

选定目标并连续工作。**三种启动边界，各说各的人话，而且在写任何事件之前判**：

- 权限档低于 `workspace` —— `readonly` / `ask` 档下第一次写就会停下来等人，那时「无人值守」
  是空话。按 `Shift+Tab` 或 `--mode` 换档再来。
- 清单文件找不到 —— 提示先 `/goal new`。
- 目标已经全部完成 —— 没活可干。
- 这个会话已经有一个 loop 在跑。

通过之后：落一条 `GoalSelected`，把清单注入上下文，然后一个回合接一个回合地跑。

**归属是一条只追加的事件**，所以当前目标永远是流上最后一条 `GoalSelected`。切换目标就是再记
一条；`sessions replay` 与 `--continue` 都从流派生它，没有第二处存储。

跑着的时候**输入区禁言**：键位照旧响应（转录能滚、`Shift+Tab` 能换档），只是不落字。要停按
`Esc` —— 它先弹一个确认框，**默认停在「继续跑」**（`Enter` 或 `Esc` 都是继续，只有明确按 `s`
才停）。

### 进度从流派生

`todo` 的每一项可以带一个可选的 `id` 引用清单条目：

```json
{"items": [{"id": "03", "content": "补测试", "status": "completed"}]}
```

条目状态由**这个目标横跨的所有会话**的 `todo` 调用合并出来，按 id 取最新（排序键是先会话时间、
后会话内的 `seq`）。所以「会话 1 把 `03` 标成完成、会话 2 的 `todo` 里根本没有它」仍然算完成
——那正是「一个目标跨几个会话」要保住的信息。一条都没被提过的条目是 `pending`。

引用清单里没有的 id 会被忽略，但**不静默**：转录里留一行，点名是哪些 id。

### 过半提醒与翻页

两个阈值是**窗口**的百分比（状态行那个「上下文 n%」的同一个数），在 `config.toml` 里配：

```toml
[goals]
remind_at = 50            # 过这条线注入一次提醒（缺省 50）
compact_at = 80           # 过这条线压缩 + 翻页（缺省 80）
no_progress_rollovers = 3 # 连续几次翻页零完成就停下（缺省 3）
provider_retries = 2      # provider 失败重试几次（缺省 2，上限 10）
```

- **过 `remind_at`**：向模型注入**一次**提醒，措辞是「把还没落流的东西落下来」——再过一会儿历史
  会被压成摘要，而摘要只留得住它读得到的东西。跨过阈值只注入一次，不是每一轮：每轮注入会每轮打掉
  前缀缓存，而本仓库有「前缀只增不改」的不变量。
- **过 `compact_at`**：把当前历史折成一段摘要（一次模型调用，照记 `UsageRecorded`），落一条
  `HistorySuperseded { reason: Compaction, summary }`，然后**结束当前会话、开一个新的**，并把
  摘要以 `ContextInjected { source: Compaction }` 注入新会话。压缩与翻页是**一个动作，总是成对
  发生**：不做「压缩后看空间够不够再决定翻不翻」那条分支。

翻页用的是**同一个渲染器与终端**（渲染器只能起一次，它占着键盘），只换会话。旧会话的文件留在
磁盘上，`--continue` 打开的是最新的那一场。

### 预算

额度认到**目标**上：闸门的求和范围是这个目标横跨的所有会话，所以**翻页不重置额度**。跨会话的
累计是派生的 —— 扫本桶、按归属筛出属于这个目标的会话，把它们的 `UsageRecorded` 加起来（与
[日账本](observability.md) 同一条路：不新增状态文件）。没有当前目标时，额度就是本会话的，与
从前一样。

撞顶沿用既有语义：**降级收尾，而不是中断**，并落一条收尾事件。

### 停止与恢复

| 停下是因为 | 流上落的收尾事件 |
| --- | --- |
| 所有条目都完成 | `GoalCompleted { goal, summary }` |
| 连续 N 次翻页零条目完成 | `GoalStopped { reason: no_progress, … }` |
| provider 调用重试耗尽 | `GoalStopped { reason: provider_failed, … }` |
| 人按 `Esc` 明确选「停下」 | `GoalStopped { reason: user_stopped, … }` |
| 额度撞顶 | `GoalStopped { reason: budget_exhausted, … }` |

完成时的**收尾汇总**由一次模型调用写（它照记用量），内容四项一个都不能省：目标名、条目完成
情况、跨了几个会话、以及**执行中冒出来但没进清单的新工作**。那次调用没成不改变「做完了」这个
事实，缺的只是那段叙述，于是退回一份机械的说明。完成后**不退出**：出汇总、落流，回到空闲态。

`--continue` 完全从流派生该怎么办：从**当前目标归属那一刻之后**有没有收尾事件，分出两条路。

- **没有收尾事件**（进程被杀、机器重启）→ 自动接着跑那个目标，不必人点头。风险是「同一个条目
  把进程反复弄崩」，由无进展判据兜住。
- **有收尾事件**（完成、无进展停、provider 失败停、人主动停）→ 回空闲等人，不自动开新 loop。
  主动停是人的意思，该尊重它。

没有目标归属的普通交互会话，`--continue` 行为一个字不变：只铺历史，不自动跑任何东西。

### `goal_note`

模型记「执行中冒出来的新工作」的工具：

```json
{"notes": ["补一条迁移脚本", "顺手把 README 的用法改掉"]}
```

与 `todo` 完全同构：真相是那条 `tool_call` 的参数，不为它新增任何事件、不改 schema、
`effect()` 是 `ReadOnly`（权限门从不为它发问），主会话、讨论者、执行者与 headless 都挂。结果只是
一句回执。它**不进侧栏**，只在转录里占一行；消费者是收尾汇总里的「新工作」那一项。

## `/clear`

**结束当前会话、开一个新的**（进程不重启，渲染器与终端留着）—— **不是**「清空上下文继续用」。
它复用翻页那条机制，差别只有一处：不带压缩、不带摘要注入，人是主动清场，没有「要带过去的历史」
这回事。

它是手势，**不进事件流**：这件事没有流上的痕迹，审计看的是**会话边界**（新会话的第一条
`SessionStarted`）。旧会话留在磁盘上，仍能被 `--continue` / `sessions` 找回。

## 事件与文件一览

| 东西 | 在哪 |
| --- | --- |
| 清单文件 | `~/.local/share/fs-agent/goals/<名字>.md`（只有条目与 id） |
| 归属 | `GoalSelected { goal }`（只追加；当前目标 = 最后一条） |
| 提醒 / 清单 / 摘要 | `ContextInjected { source: Reminder / Goal / Compaction }` |
| 压缩 | `HistorySuperseded { reason: Compaction, summary }`（旧会话那条流上） |
| 完成 | `GoalCompleted { goal, summary }` |
| 停下 | `GoalStopped { goal, reason, detail, stuck, count }` |
| 新工作 | `goal_note` 那次调用的参数（没有事件） |
| 条目状态 | 各会话 `todo` 调用参数的合并（没有事件、没有文件） |
| 跨会话额度 | 各会话 `UsageRecorded` 的和（没有事件、没有文件） |

真机验收清单在 [`tui-manual-checklist.md`](tui-manual-checklist.md) 的 ㉒。
