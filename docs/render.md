# 渲染

渲染是**每个前端都要经过的那一条边界**（spec §19）。每个进程只跑一个渲染器，启动时选定，
消费组装期创建的那一条广播通道。没有第二条事件总线：模型的增量文本与进流的事件走同一条
路，于是两者的相对顺序是定的，而增量文本永不进事件流。

## 一个 trait，三个实现

`src/render/` 就是这条边界：

| 模式 | 类型 | 用来干什么 |
| --- | --- | --- |
| headless | `Headless` | 机器模式。两个显式的写出口；`stdout` 只承载最终产物，别的什么都不放。 |
| plain | `Plain` | 给管道或简单终端看的人类转录：每行一个发言前缀、分节行、缩进的分歧块、每次工具调用一个块。 |
| TUI | `Tui` | ratatui 界面：备用屏幕（alt screen）上的一条左栏与一条主列，中间一条竖虚线，四周没有外框（`.scratch/tui-chrome/spec.md` §1）；主列顶上一条页签条（`对话` / `轨迹`），下面是**转录**（+ 回合条）/ 状态行 / 输入区 / 提示行（`.scratch/trace-in-main/spec.md` §1）；左栏**全高**、提示行落在主列里（`.scratch/tui-feedback/spec.md` §2，推翻 `tui-visual-language` §16 的「跨整屏」）；它占着键盘。左栏有两个宽度档，宽的那档画标记（见下文「外壳」）。见 ADR 0002。 |

这个选择就是值类型 `Renderer`（`Renderer::headless` / `::plain` / `::tui`）。因为选择是一个
值、不是一组订阅者，「只有一个渲染器在跑」是这个类型的性质。`OpenedSession::open` 创建那条
通道，并把消费端注入选中的渲染器（`render::channel` + `Renderer::spawn`）。

`Headless` 是唯一带纯度契约的模式：它只往两个显式的写出口写，而 `stdout_result` **只**接最终
产物 —— 单 agent 会话里那个完成的回合，或讨论里合成器的那条 `System` 消息。执行者的回合
永远不是最终产物，也永远不覆盖派发者的文本。`cargo test --test e2e_single_turn` 就是这一条
的回归断言。

## 一个呈现层，两个画家

`render::transcript` 把事件转成 `Block`，**只转一次**；plain 与 TUI 只负责画。有三条规矩
住在这里：

- **一次工具调用与它的结果是一个块，由结果绘制。** `ToolCallCompleted` 一到达就把这次
  调用发出去，所以工具一跑完，调用行就在屏幕上。后置 hook 的反馈不带 `tool_call_id` ——
  循环在它批注的那条结果之后紧接着发出它 —— 所以它作为自己的一个小块
  （`Block::ToolFeedback`）旅行，瞄准刚画好的那次调用。它**曾经**被并进调用块里，那意味着
  这次调用要一直开着，等下一个与它无关的事件来关 —— 在 TUI 里就是下一个回答的第一个流式
  增量：工具整个运行期间它都不可见，只有跑完了才被画出来。（它仍然由*结果*绘制，不是由
  开始绘制：让它在调用开始时出现是另一种形状，不是这一种。）结果永不到达的那次调用
  （一次取消）在流末尾被冲掉，而不是被丢掉。
- **增量文本原样透传**为 `Block::Delta`，因为增量绕过了事件流，事后无法重新推出来。
- **载荷*就是*数据的那次调用，画起来与别的行一样。** `todo` 把 agent 的列表放在一次
  `tool_call` 的参数里（`.scratch/todo-and-modes/spec.md` §2），所以转录里显示的是那条普通
  的折叠工具行，详情覆盖层显示的是参数；列表本身由这些参数经 `tools::todo::read_items`
  重算，**从不**从结果文本里解析 —— 结果只是一行回执。左栏的 `todo` 页是同一个函数的另
  一位读者（见「外壳」）。

`[speaker]` 前缀是**人**这一侧的生成器，刻意与投影的模型侧前缀分开（spec §5）：模型那一侧
每个合并块只写一次。**对话视图**里它**独占一行**（2026-10-05 的排版修订）：名字一行，话从
下一行起、顶格 —— 用户输入、assistant 的答案与别的系统行都一样，Markdown 的左边界因此就是
第 0 列。**同一个发言者连着说的几段只留一个名字**（2026-10-06 的修订）：第 2 段起不重复名字，
段与段之间空一行；换发言者时空一行这条照旧，同一人连发的工具行仍挨着。**轨迹视图**里前缀
仍跟着首行（`[name] 首行…`），因为那一页要的是密度 —— 它不去重名字。

Markdown 的渲染（`render::markdown::to_lines`）收**可用列数**：表格的列宽与超宽代码行的
折行都要知道它，所以**源行本身也不再宽度无关** —— 宽度变化时 TUI 按新宽度重跑 Markdown 并
重放全部块，而不是只重新折行（`.scratch/markdown-render/spec.md` §1、
[ADR 0008](adr/0008-markdown-parsing-by-pulldown-cmark.md)）。TUI 走的是同族的
`to_lines_indented(text, width, indent)`：`indent` 是消息第一行那个 `[name] ` 占的列数，
**需要左边界对齐的块**（表格、代码块）整块从那一列起、宽度预算扣掉它，于是表头与数据行、
语言名与代码行共享同一个左边界。

## 严重度

`render::severity` 把每一个 `StopReason` 归入 `Good` / `Note` / `Warn` / `Bad`。plain 渲染
器把它变成 ANSI 颜色，TUI 变成 ratatui `Style`；两者都必须永不把 `Completed` 塌缩成
`Aborted` 或 `Error`（用户故事 135）。`RoundsExhausted` 是 `Note`；`Aborted` 与
`MaxIterations` 是告警；`Error`、`MistakeLimit` 与 `BudgetExhausted` 是错误。

## 高亮

> **状态（2026-10-01 复核）**：语法层有生产消费者了 —— 转录里代码块的提供者，
> `render::markdown` 按围栏的 info string 挑文法（`.scratch/markdown-render/spec.md` §3、§4）。
> **diff 层仍然没有调用方**，它是为工具输出留着的。十种语言、延迟编译、crate 名与常量名的
> 那三个坑，见 [`highlight.md`](highlight.md)。

`render::highlight` 是两层，两者从不互相问话：

- **语法层**（`highlight_code`）说的是这段代码是什么语法元素；
- **diff 层**（`diff_tag`）说的是这一行在补丁里是什么：新增、删除、hunk 头还是上下文。

`highlight_diff` 把两者合起来：diff 标记被剥掉，剩下的代码当作一整份文档来高亮（所以多行
注释或字符串照样能解析），然后标记被贴回去。两层的样式一个当前景、一个当背景，于是一个
新增的关键字两个身份都占。

代码块里的那一段是「先高亮、再按宽度折行」：`highlight_code` 交回的是**按行**的 span 列表，
渲染器再把每一行折到可用宽度、续行保持那两格缩进。语言认不出、或文法构建失败时退纯文本 ——
**代码不消失，只是不上色**。

这套语法是 `tree-sitter` 经由 `tree-sitter-highlight` 使用。它避开的是 syntect 的 Oniguruma
那条 C 路径（spec §19，明确不做）；但十种文法各自都要编一个 C parser，所以首次构建并不
比纯 Rust 依赖快（见 `Cargo.toml` 那一段注释）。

## 外壳

左边是一条**左栏**（全高），右边是一条**主列**，而几何是终端尺寸的一个纯函数
（`layout::plan`，`src/render/layout.rs`）—— 画家从不重新推一遍降级阶梯。外框已经拆掉
（`.scratch/tui-chrome/spec.md` §1），所以内容区就是终端本身；剩下的分隔是一条竖虚线与主列
里那两条横虚线。

```
                      ┆ ┄ 对话┆轨迹 ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄
 标记 / 文字身份      ┆ 转录：当前那一页（滚动条 + 回合条在它的右缘）
 ┄┄ 页签条 ┄┄┄┄┄┄┄┄┄┄┆
 上下文 / token / …    ┆ 状态行：模型 X · high ┆ 询问 ┆ 上下文 n% ┆ 🌕 就绪
                      ┆ ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄
                      ┆ 输入区
                      ┆ ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄
                      ┆ 提示行（与输入区同列同宽）
```


- **左栏**在 120 列往上时 40 列宽，到 80 列是 28 列；再往下整栏隐藏，主列拿走全部。
  **去留 = 用户意愿 × 宽度档**：`Ctrl-O` 收起与叫回（意愿只活在这一次进程里，不落配置、
  不跨会话），窄档下它叫不回来 —— 宽度仍然决定那一栏画不画得下。它自己的高度决定页区装几
  行：**页区 = 内容行 − 身份 − 页签条**，身份先让位（块字 → 收起来那版 → 文字身份 → 什么都没有），
  只要页区还保得住 3 行地板（篆书那一档要 5 行，见下面标记那一条）；`SIDEBAR_FIELDS = 6`
  那个「用量字段数」已经退休，页高不再随读数有
  几项走（`.scratch/trace-tab/spec.md` §4）。收起时那 41 列（40 + 分隔线）整列还给主列，
  页签的命中矩形随帧一起消失（`.scratch/sidebar-toggle/spec.md` §2）。
- **标记**是**用小篆写的「衡」，用块元素字符拼出来**（半块 `█▀▄` 加十个四分之一块
  `▘▝▖▗▚▞▙▛▜▟`，一格一个 2×2 的子像素，所以弧线的转弯是照四分之一格走的），它上面一行标着
  拼音 `héng`，画在宽档左栏里、居中。这些字符住在 `wording::logo_lines`，与每一个别的给人看的
  短语一起；颜色住在画家那里（`mark_lines`）：标着拼音的那一行退一档，字形全亮，只设前景、
  不设背景，所以不跟终端正在跑的任何主题打架。网格的行数与宽度（23 行 × 38 列）是布局契约
  （`layout::LOGO_ROWS` 与 `LOGO_WIDTH`），与里面写几个字无关；篆书字身竖长，字宽只占三十一列，
  两侧的留白也归布局。**代价落在字体上**：等宽字体要画得出 U+2596–U+259F 那十个四分之一块，
  画不出来的会显示成豆腐块。
- **标记有大小两版**（2026-10-07 定）：真放得下二十三行的终端画篆书，矮一些的终端退回
  **拼音加一个汉字**那五行（`wording::logo_lines_compact`）。篆书那一档要求页区至少还剩 5 行
  （`layout::BLOCK_LOGO_MIN_PAGE_ROWS`），所以它从终端 32 行起才出现；24 行的左栏与换形之前
  逐格相同。
- **一次运行里，标记上扫过一束反光**（`.scratch/mark-sweep/spec.md` §1–§3、[ADR 0015](adr/0015-mark-light-sweep.md)）：
  一串斜亮带从**右下**走到**左上**，1.8 秒一轮、运行期间一直扫。每一格投影到那条轴上
  （`s = (最右列 − 列) + (最下行 − 行)`，右下角 0），光带就是 `s` 上的区间：核心 5 格是白
  （`palette::MARK_LIGHT`），两侧各 6 格退回字形本来就有的亮品红。帧来自**脉冲**那一个计数器
  （`state.busy().then_some(state.pulse)`），不为它另起时钟；**空闲时它是 `None`，整块逐格不动**。
  留白格刻意不吃这束光 —— 那里没有字形，改了颜色没人看得见。
- **下落短横与那圈色相环都不回来**：它们在真终端上试过、然后关掉了（`.scratch/tui-input-pulse/spec.md`
  §2，票 04–08），2026-10-06 的死代码收口把代码也删了
  （`.scratch/tui-visual-language/spec.md` §34）：`DASH_FALL`、`identity_falling`、
  `PULSE_PALETTE` 都不在了。**扫光不是它们回来** —— 它只在一次运行里出现、只描述"还在跑"，
  而不是给一块静止的东西加装饰（[ADR 0015](adr/0015-mark-light-sweep.md)）。那一族里最后
  退场的是**提示符 `❱` 的色相与呼吸**：2026-10-08 维护者点掉了输入框那个字形，色相没有
  载体，整套（`PROMPT_*` 常量、`palette::prompt_colour`、`hsv_to_rgb`）随之删掉，界面里
  再没有 24 位色（`.scratch/ui-trim/spec.md`）。
- **两条页签条**，同一个画法（标签夹在虚线之间、选中的那个亮、标签之间一个 `┆`、其余用
  `┄` 填满），跨的列不同：左栏那条给它自己翻页（调用量是会话的读数，`todo` 有列表时才在，
  `文件` 是工作区那棵树 —— 见「文件页」），主列那条在屏幕第一行上、给那块内容区翻页
  （`对话` / `轨迹`，见「两个视图」；`.scratch/trace-in-main/spec.md` §2）。**轨迹不再是左栏
  的一页**。两处页签都是**点出来的，从不给键位** —— `Tab` 归 `/` 菜单、`Shift+Tab` 归模式
  循环 —— 而三页如今都有内容（`调用量` 的读数、`todo` 的列表、`文件` 的树）。左栏自己有一个
  键位 `Ctrl-O`，那是**整栏**的开关，不是给页签的。
- **`todo` 是唯一来去的那一页签**（`.scratch/todo-and-modes/spec.md` §4）。第一次有**非执行者**
  提交一次参数里带非空列表的 `todo` 调用时它出现，此后整个会话都在：全完成的
  列表、被清空的列表、以及重放同几次调用的 `--continue` 都留得住它。那个闩
  （`TodoPanel::visible`）与当时生效的列表都是从渲染器已经看见的块推出来的渲染器状态 ——
  两者的任何一部分都不存在流旁边 —— 而页签条是由分隔符、填充与命中矩形所用的同一份标签
  列表建的，所以没被画出来的标签点不到。**执行者**的列表永远到不了这一页：那是那个执行者
  自己的记录，在转录里看得见，在左栏里哪儿都没有。这一页每项画一行（`☐` / `▸` / `✓`，加上**可选的条目 id**（`✓ 03 补测试`：id 是它引用目标
  清单哪一条的凭据），再加上内容），再加一行计数行 `已完成 2/5`，不滚动：装不下的那些在计数行上面用一行说出来
  （`＋3 项`），而只有一行容量的页面只显示计数。
- **回合条**是转录最右的那一列：一格 = 一个回合（讨论里则是一轮），最新的在底部，视口自己
  那一格画得亮。它的窗口跟着焦点走，所以永远恰好有一格是亮的；点一格跳到开启那个回合的
  问题，顶端对齐。
- **滚动条只画滑块**（`█`），轨道与两端的箭头都不画（`.scratch/tui-visual-language/issues/07`
  决定 1）：轨道与紧邻的回合条是同一族细竖线，并排读起来是噪音。跟着末尾与在读历史用滑块
  的字重区分。右缘那两列**永远预留**，画不画都留着 —— 那防的是文字重新折行。
- **外壳占 6 行**：主列页签条的**标签行与它下面那条线**、主列的**两条**分隔线、状态行与提示行
  （外框那 2 行早已拆掉）—— 于是 `转录行 = h − 6 − 输入行数`，其中输入区的行数夹在 3 … 10：
  草稿还没需要时也先留 3 行，而两个地板相遇处转录的最后一行胜出（40×10 下那份余地只够一边：
  **输入区 3 行、转录 1 行**；页签条那两行是从这里出的，`.scratch/trace-in-main/spec.md` §1）。
  **提示行落在主列里**（`.scratch/tui-feedback/spec.md` §2，推翻 `tui-visual-language` §16 的
  「跨整屏」）：它与输入区同列同宽、就在它正下方，左栏因此全高、那条竖虚线画到屏幕最后一行。
  代价是提示的宽度从终端宽度变成主列宽 —— 120 列终端给出 79 列提示（四条提示 + 出口）。
- 工作目录与时钟**根本不在屏幕上**（它们随旧顶栏一起退场）；`SessionFacts.session_dir` 仍然
  被注入，因为详情覆盖层要从它那里读落盘的工具输出。

## 两个视图

转录仍是**共享层**：事件只转成一份块（`painted`），而**主列页签条上的两页**各画它一份
（`.scratch/trace-tab/spec.md`；归属改到主列见 `.scratch/trace-in-main/spec.md`）。分工是一个
纯函数（`selects`，`src/render/tui.rs`），块的产生一个字节不改。

- **对话视图**是主列页签条的第一页（默认页）：只画用户文本、assistant 正文与**系统行的消息**（`Block::Message`
  里除执行者以外的每一类），加一份枚举出来的保留清单 ——
  错误、会话中断、失败的 hook、`Notice` 整类，以及**非正常**的收尾行（严重度不是 `Good`
  的 `TurnEnded` / `RoundEnded`，那是「为什么停下来」）。回合与轮次的开始、正常的收尾、
  权限询问与裁决、诊断都是**运行日志**，归轨迹。
- **轨迹视图**是主列页签条的第二页：画**全量**块，按**主列内容宽**排版 —— 120 列带左栏时
  正文 68 列，行首那 9 列归**时刻**（见「时间戳」一节）。消息只画**首行 + `…`**（点开是
  `DetailKind::Message`，全文在覆盖层里），每个
  **单位**（交互数回合、讨论数轮次）结束之后多画一整行虚线 —— 那条线就是轮次的边界，
  两边都**不铺底色**。前缀一律带方括号：主列最小 40 列，所以那条去括号的窄档分支到不了屏幕
  （分档量的是**页宽**，不是正文列数）。**一笔用量不再是自己的块**：它长在产生它的那次模型
  调用的行尾，写 `in=… out=…`；一次发言跨 ≥2 次调用时，收尾那一行的尾巴上多一条
  `合计 in=… out=…`。没有可承载的宿主时（合成器那次调用不属于任何回合）它照旧自己占一行
  （[ADR 0016](adr/0016-usage-rides-the-row-of-its-call.md)、`.scratch/trace-usage-tail/spec.md`）。
- **两个 pane 各持自己的**折行缓存、视口、跟随与「新行」计数，互不影响；宽度变化只清、只重放
  **宽度真变了**的那个（两个宽度同源，通常一起变）。**滚轮与键盘三键（翻页两键与回底键）都
  归当前显示的那一页**：同一时刻只有一页在屏幕上，所以「按指针位置分派」那条分派没有了。
  **回合条只画在对话页上** —— 它量的是对话视口的单位位置，画在轨迹页上会指着另一个视口。
- **永远可达**：轨迹页是主列的一页，所以 `Ctrl-O` 收起左栏或终端窄于 80 列时它照旧在屏幕上
  —— 分工规则不随左栏变（对话视图仍只收保留清单），但过程行不再有「看不到」的宽度档
  （推翻 `trace-tab` §6 的 2026-10-05 取舍）。
- 两处形态例外：**用户消息在对话视图里是一个气泡**（轨迹页仍左对齐），**三类前缀各一色**
  （注入 `LightBlue`、用户 `LightGreen`、助手 = 调色板首位）。气泡是一块**等宽底色**
  （`palette::BUBBLE`）：贴着转录的右缘、宽度封在三分之二以内、里面按那个宽度折行，名字行在
  它**外面**自己一行、右端与气泡右缘对齐。用底色而不用边框字符，是因为字符会被拖选带走而
  底色不会；靠右用行级右对齐，左边界由每行补齐到同一宽度保证 —— 逐行右对齐会把一段多行的
  输入折成参差的一列（`.scratch/trace-tab/spec.md` §2 的补记）。
- **详情覆盖层**记下打开时轨迹页在哪儿，关掉时把滚动状态还原给它。**入口只有轨迹页有**：那里
  的消息画的是首行 + `…`，点开才看得到全文；而**对话页的每一行都不是入口** —— 它画的就是全文，
  覆盖层不省任何东西，点普通文字却弹出一份同样的正文，那是一次意外
  （`.scratch/tui-feedback/spec.md` §3、§9）。
- **等待提示**：循环在跑、而正文尾巴还空着时，对话视图末尾给两行 —— **谁在答**（名册第一个
  的名字；讨论里几轮之间会换人，这里只是这一栏能给出的稳定猜测），以及它**在做什么**：有工具
  在跑就说那个工具在干什么（`正在查看 CONTEXT.md…`、`正在写 docs/render.md…`、
  `正在运行 cargo test…`），否则说它 `正在思考…`（点号每 8 帧挪一格，一帧 60 ms）。第一个
  正文增量一到两行都让位（2026-10-05）。

## 文件页

左栏 `文件` 页签画的是一棵**工作区文件树**（`.scratch/files-page/spec.md`）。数据是**会话级的
`FileIndex`** —— `@` 候选与它共用同一份快照（`file_index::scan`，遍历规则一个字不改），而
**树的顺序在渲染侧重排**：同层目录在前、同类之内保持索引序（`files::rows`，
`src/render/files.rs` —— 一个纯函数：路径列表加展开集合进去，可见行进出来）。所以这一页与
`@` 候选的顺序**有意不同**，两处都写在这里，免得后来者以为是漏改。

- **一行 = 缩进 + 名字**（每层 2 列）：目录带尾斜杠与折叠字形（收起 `▸`、展开 `▾`），文件
  都没有；两者**不给颜色**，只靠结构区分。超过页宽的名字用 `…` 收尾。初始**全部收起**。
- **展开状态、滚动位置与焦点行**收在一个 `FilesPage` 值里（与 `Panel` / `TodoPanel` 同一族）：
  不进事件流、不落盘，而一次重扫之后**不在索引里的路径直接丢掉** —— 目录回到工作区时是收起的，
  不带着上一次的展开状态复活。索引没就绪说「正在读取工作区…」，工作区真的是空的则说
  「工作区里没有文件」—— 两句话，两回事。
- **鼠标**：单击目录展开/收起、单击文件在**详情覆盖层**里打开内容；滚轮悬在左栏页区内时滚这
  一页（指针在主列时照旧滚主列那一页）。与别的文本区域一样，这一页照旧拖得动、复制得走。
- **键盘**：点这一页（页签或页区）把键盘交给它，焦点行落在点的那一行上、画成常驻选中
  （`ACCENT` + `BOLD`）—— 它是这一页唯一着色的东西。**点回输入区也把键盘还回去**：点在哪儿
  键盘就归哪儿，而输入区没有别的点击语义（那一下到头了）；切到另外两页、以及 `Ctrl-O` 收起
  左栏，也**把键盘还回去** —— 那两页没有能用方向键走的东西，扣着键盘只会让输入区静默失灵。
  （点输入区这条是 2026-10-07 维护者报的：原先只有 `Esc` 与 `Enter` 两条归还路径，点开过
  一个文件之后想接着打字，只能先按一下 `Esc`。）
- **内容弹窗**是既有的详情覆盖层加一个 `DetailKind::File`：渲染器**直接读盘**（按相对 `cwd`
  的路径），三档限额各自封顶（200 000 字节 / 2 000 行 / 一行 4 000 字符，截了就说出来），
  二进制与读不了的各报一句。
  正文按扩展名认语言（`files::language_for`，十种语言那一份名单）、走既有的高亮那一层，每个
  **逻辑行**前面带行号 —— 行号插在折行之前，折出来的续行自然不带。它**不进事件流、不进模型
  上下文**：这条路上没有打码，因为权限门约束的是模型的读写，而这是人在自己的终端里点开自己的
  文件。行号会进屏幕文本层，也就是跟着拖选被复制（与轨迹页的时间戳前缀同一个待遇）。
- **内容弹窗有两档**，由 `[ui] file_viewer` 挑（`.scratch/nvim-file-viewer/spec.md`）。
  `"builtin"`（缺省）是上面那一条：渲染器直接读盘、三档限额、高亮、行号。`"nvim"` 在同一个
  位置嵌一屏**真的 nvim**（`src/render/viewer.rs`）：只读（`-M -R`）、不折行（`-c set nowrap`）、
  鼠标给 nvim；浮层**去框留白**（宽 `min(屏宽 − 4, file_viewer_width)`），**它盖住的那一整块
  （含留白）由它自己交代**：每格都写，没有文字的也写一个空格（底色是「设好背景、再擦掉」的
  产物；2026-10-07 修，`tests/render_viewer.rs` 钉住）。键盘由它独占 —— `Ctrl-C` 关、`Ctrl-Z`
  挂起，别的（含 `Esc` 与 `Ctrl-D`）都进 nvim；框外一次左键也关，且那一下不穿透。两档都不进
  事件流、不进模型上下文。
- **重扫**：进 TUI 预热一次，此后「任何**非只读**的工具调用收尾」与「一次提交」各请一次 ——
  判据是既有的 `Effect`，不是一张工具名单（所以 `bash` 里的 `mv`、`git checkout` 也算），
  `/undo` 自己补一次。前端那个位把连着几次触发合并成一次遍历：一次遍历在飞时不并发，最多
  延后一轮。它是一条**静默信号**（`RenderEvent::WorkspaceChanged`）：不画一行、不进事件流，
  另外两个渲染器把它当没看见。

## 系统提示词

拼给模型的那段**私有身份**（`agent_identity()`）在轨迹页上是一条**可点开**的记录，与「注入的
上下文」同一排：`▸ 系统提示词（按当前代码拼，不进事件流）`，点开看全文。CLI 在启动横幅之前
推它一条（`RenderEvent::Identity`）。

它借的是注入那条记录的形状，但它**不是事件、不进事件流、也不写 `log.jsonl`** —— 身份在
每一次请求里现拼（`build_messages`，spec §15），所以屏幕上那一份是**按当前代码拼的**：
`--continue` 重开一场老会话，看到的也是今天的拼法。那句话由来源名自己说出来。

## 时间戳

轨迹页里每个块的第一行以 `HH:MM:SS ` 开头（本地时区、静音档色，`wording::stamp`），固定九列
（`layout::STAMP_COLUMNS`）：轨迹内容的排版宽度把这九列扣掉，而**折出来的续行从第 0 列起** ——
时刻是**块**的属性，不是每一行的（`.scratch/trace-in-main/spec.md` §5）。

时刻来自**产生这个块的那条事件的 `at`**（`Event` 的信封上早就有它），所以 `--continue` 重放
出来的是当初那一刻，而事件 schema 一个字节没改。两处例外：渲染层自己那两条
（`Diagnostic` / `Notice`）不是事件、没有信封可依，时刻在**源头**打上（`Renderer::diagnose` /
`notice` 各读一次时钟）；思考行**还开着**的时候就带着时刻 —— 推理增量本就没有信封，所以那是
收到它的那一刻，而定稿时就地重写成完成那一刻（实时路径上是正文第一个增量到达那一刻，重放
路径上是那条 `MessageCompleted` 的时刻），于是同一行的时间戳会跳一下
（`.scratch/trace-thought-stamp/spec.md`）。

那一行尾上的**用量尾巴不带来新戳**：时刻是**块**的属性，而尾巴不是块 —— 宿主行保留自己的
时刻，尾巴只是补在它末尾的一段静音档文本（`.scratch/trace-usage-tail/spec.md` §6）。

对话视图里没有时刻：它画的是对话，位置感由回合条给。

## 键盘

**输入区那个光标只在键盘真的在输入区时出现**（`keyboard_in_the_input`）—— 于是「有光标在闪」
就等于「你敲的字会落进草稿」。键盘交给文件页、详情或文件查看器浮层立着、问卷占着底部时它
都不在（问卷有自己的光标）。原先只要没有问卷就画，于是浮层立着时那个静止的光标在说谎
（2026-10-06 维护者报的）。

露面与收起按脉冲每 8 帧（≈0.5 秒）翻一次（`blink_on`），但那只收**可见性**：位置每一帧都
钉在同一格（位置由 `draw_frame` 设，可见性由 `paint_frame` 收）。这一分为二是必须的 ——
ratatui 的 `Frame` 只有「光标在哪」一个旋钮，用「不设位置」来表示暗就是 `Hide`，而 `Hide`
一个移动光标的字节都不发，终端会把它留在最后写入的那一格；那一格于是被空输入法与别的东西
抢，输入法的预编辑（画在物理光标上）会落在不属于它的地方（2026-10-07 维护者报的，
`tests/render_layout.rs` 的 `a_hidden_cursor_still_marks_the_input_area_not_the_status_row`
用真 crossterm 后端的字节加 vt100 回放钉住它）。

`render::input` 是循环与那个占着终端的前端之间的接缝。这里的流量是**按需请求**的，不是一
条流：循环只在准备好要一行时才要一行，只在闸门问出问题时才要一个答案。一个会预读的读取器
会把一个权限答案当成下一个提示符吞下去。

- 循环持有 `ConsoleHandle`（提示符与问题）与 `ConsoleEvents`（主动上行的手势：取消、模式
  循环、退出）。它们是两个值，因为循环同时 select 两者。
- 前端持有 `ConsolePort`。TUI 用自己的 `select!` 在 broadcast / console port / 键盘上加
  **两个计时器**来应答它（脉冲与退出手势的 deadline，见下一条）。没有别的东西在等着被*注意到*
  —— 待答的问题从 console port 来、事件从渲染通道来、按键就是按键。
- 那两个计时器：**脉冲一直在走**（`.scratch/tui-visual-language/spec.md` §32）—— 挂在上面的
  是「时间的纯函数」：状态行那个字形循环（运行中每 2 帧换一格、相位倒着走，就绪时定在满月；
  §30–§31 与 `.scratch/ui-trim/spec.md`）、左栏标记忙时那束扫光，以及光标闪烁与那几条回执的
  寿命。提示符的色相曾在名单里，2026-10-08 随提示符一起退场。退出手势的
  deadline 仍**只在第一下举手之后**的那半秒里 arm（`.scratch/exit-gesture/spec.md` §6）。
  它是一条 `interval`，而不是每一次循环新建的 sleep，因为一次突发里的每个事件都会把 sleep
  重置，而那恰好是会话最忙的时候，动画会停住。**代价**：空闲不再零唤醒。
  plain 模式用 `render::spawn_plain_console` 应答这个端口，它逐行读 stdin。
- `ConsoleAsker` 在同一个句柄上实现权限门的 `Asker`，所以权限问题与提示符用的是同一个
  键盘。
- `ConsoleQuestions` 在同一个句柄上实现模型提问端口，所以模型发起的问卷
  （`ask_user_question`）也到达同一个键盘。TUI 里它接管底部输入区 —— 一屏一问、分页、可以
  显式跳过 —— 而不是 harness 那些问题用的中段覆盖层；plain 模式逐行作答。**答完之后那份答案
  回到转录里**：`Transcript` 从那次调用的结果里认出它，推出一条 `Block::Answer`（一道题一行
  `题面：答案`），两个前端都把它画成**用户说的那一档** —— TUI 里是气泡、plain 里是 `[用户]`
  前缀。它只给人看：进模型上下文的仍是那次调用与它的结果（`.scratch/ui-trim/spec.md`）。

TUI 里 `TuiState` 是可测的那一半：它持有转录、输入行与任何待答的问题，而 `Key` 是它自己的
键位词汇，不是 crossterm 的，所以状态机不接终端也能测。

**换行有两个键**：`Ctrl-J` 到处都到得了，`Shift+Enter` 只在支持键盘增强协议（Kitty keyboard
protocol）的终端上到得了 —— 进终端时推 `DISAMBIGUATE_ESCAPE_CODES`、退出与挂起时成对弹回，
不支持的终端把那一串当没看见（于是那里的 `Shift+Enter` 仍旧提交）。提示行因此只写 `ctrl-j`：
提示是承诺，而那条承诺只有一部分终端兑现得了（`.scratch/tui-feedback/spec.md` §10）。

`Ctrl-O` 收起或叫回左栏（`.scratch/sidebar-toggle/spec.md`），是一个**纯视图手势**：**忙闲都
生效**、也不清掉退出举手，而**详情覆盖层与历史重放**这两处独占键盘的视图拦得住它（`PgUp` /
`PgDn` 与它同类，只是不占 Ctrl 位）。`Ctrl-Z`（挂起）在那两处仍然穿得过去 —— 它是终端层手势，
不属于任何键位表。

`Ctrl-T` 打开**模型**的**选择器**（`.scratch/model-switching/spec.md` §7）：它是这条接缝上
第四个上行手势，与 `Ctrl-O` 同一档 —— 不归任何视图管、**忙闲都生效**，而**选择器立着时归
选择器**。**不能取 `Ctrl-M`**：它在终端里就是回车（`\r`），crossterm 报成 `KeyCode::Enter`，
与「提交」正面撞车 —— 与 `Ctrl-J` 是同一件事，上面已经记过一次。

**键盘还能交给文件页**（`.scratch/files-page/spec.md` §5）：点左栏那一页（页签条或页区）之后，
走树的那几个键归**它** —— `↑` / `↓` 移焦点行、`→` 展开或开弹窗、`←` 收起、`Enter` 把那一
行的路径作为 `@路径` 插进草稿并把键盘还给输入区，而 `Esc` **只**把键盘还回去（一次手势一层：
它不取消正在跑的回合）。别的键照旧落到它们本来去的地方，所以点一下左栏不会把打字的手感弄丢。
它与详情覆盖层、历史重放同属「独占键盘的视图」那一族，只是不占满屏 —— 覆盖层立着时它拦得住
这一层（`Esc` 先关覆盖层、再还键盘）。**只有文件页收这份键盘**：切到调用量 / `todo`、`Ctrl-O`
收起左栏、或者**点回输入区**，键盘都立刻还回输入区。

终端那一半还有一个副作用：**终端标题**。进 TUI 时先发 `CSI 22 t` 把原标题存起来，再按当时
的状态写一条 `<路径> · <状态> · <目标名>`（`OSC 0`，40 列封顶，`wording::terminal_title`）；
此后在绘制路径上与一份快照比对，只在真变了的时候重写 —— 所以不必枚举 `running` /
`pending` / `replay` / 目标名四个来源；退出（含 panic 路径）发 `CSI 23 t` 还原。它是渲染器
的副作用，**不进事件流**、不落 `log.jsonl`、`--continue` 按当时的 cwd 重算，而 `--plain` 与
headless 一个转义序列都不多发（`.scratch/terminal-title/spec.md` §4–§6）。不支持 push/pop 的
终端上那两条序列是 no-op，标题会停在我们写的那条 —— 这是接受的退化，不加 fallback。

## 拖选与复制

应用占着鼠标，终端自己的选择因此被接管 —— 要按住 **shift** 才回到终端手里，而它按**终端的
网格**取文本：左栏、边框、弹窗会与它们盖住的行混在一起，TUI 自己折出来的续行也被当成硬换行。
所以 TUI 里有一条自己的路（`.scratch/tui-feedback/spec.md` §5–§6），**shift 原生选择照旧可用**。

- **屏幕文本层**（`render::selection`）每帧重建：画转录、详情主体、左栏页、问卷、输入区的每一处
  都顺手记下「这块区域这一帧画了哪些显示行」，以及每一行**是不是上一行软折出来的续行**。记录点
  与绘制点同处，所以记下来的与看见的不会漂开。
- **左键是三段的**：按下只记起点与它落进的那块区域（最上层者）；拖动**越过两格**才成为选择
  （两格以内算手抖 —— 一次真实点击很容易带那么点位移，一格的门槛会把点击吃成拖选），头的落点
  **夹在那块区域里**（选区不跨区域）；抬起时要么复制、要么把这一次点击交给原来那套分派（页签、
  回合条、链接、问卷按钮、关覆盖层）。**点击动作因此发生在抬起上** —— 拖选正是这样拦下它的。
  `Esc` 清掉一次进行中的选择。
- **反白**是绘制路径的最后一步，只往缓冲上加 `REVERSED`，所以覆盖层、菜单、问卷与名字的颜色都
  不因为选择改形。它只铺到每一行**最后一个有字的格子**：行内空白仍反白（那是选中文本自己的
  间隔），行尾填充不反白 —— 看起来是文字被选中，而不是屏幕上一块矩形。
- **取文本按区域来**：逐显示行切列区间（按显示列，宽字符不切半），行尾填充去掉，一行后面跟着它
  的软折续行就**不**落换行 —— 被折过的长命令复制回来仍是一条，而区域自己带的换行保留。靠右排
  出来的行还各带一个**起始列**（文本区域记的 `lead`）：**气泡**与它那行的名字左边是留白，光标
  扫过它也不捞出空格 —— 复制一个气泡得到的就是正文本身。左对齐的行没有这一说，也不去猜「这行
  前导有几个空格」（代码块与缩进正文本身就待空格开头）。
- **写出走 OSC 52**（`ESC ] 52 ; c ; <base64> BEL`）：终端自己的剪贴板通道，单向、没有回话的
  地方，所以写不进去也不报错、不探测。状态机只把字节**算**出来，写出去是运行期的事 —— 与标题
  同一个形状，所以 `TuiState` 仍然不接终端也能测。提示行随后给一句 `已复制 N 字 · M 行`，三秒
  后由既有的脉冲 tick 清掉；那一行里**出口永远保住**，放不下时让位的是提示。

## 可点链接

对话视图里的一段 URL 或一条**工作区内真存在**的文件路径是**点得开**的：单击一下，那个目标交给
系统默认程序（`.scratch/clickable-links/spec.md`）。`/eli5` 那种产物的形态正是后者 —— 它写在
正文里只是一串纯文本路径，连 Markdown 链接都不是。

- **识别**（`render::links`）从**画出来的显示行**上认，而不是在 Markdown 解析那一层：代码块里的
  URL、模型手写的路径都要认，而一条 URL 被窗格折成两片之后还得认得出（续行按复制那套拼回再
  认）。认的是协议头与「含 `/` 或末段带扩展名」；`path:line` 与 `mailto:` 一类都不算。
- **记录与选区同一层**（`render::selection`）：每帧在记那一行文本的同一处记下候选的列区间，
  指针事件读上一帧的账 —— 与拖选同一条纪律，「认出来的」与「看见的」不会漂开。除对话视图之外的
  每一块都记空表：那些地方的点击各有各的语义（轨迹页开详情、左栏切页、文件页展收）。
- **可点就是下划线**：候选那几列带 `UNDERLINED`（颜色沿用 Markdown 链接那一档）。识别在画之前，
  所以下划线铺在屏幕上的那一次与记下来的候选出自同一次识别。
- **单击即开，拖选优先**：左键按下与抬起落在同一格（两格以内都算点击）才是点击；跨过门槛就进
  拖选、松手只复制 —— 拖选**永不**打开任何东西。
- **目标解析在点击那一刻**（一次 `canonicalize`）：URL 原样；路径要解析成绝对路径、**真存在**、
  而且落在工作区里 —— 区外、不存在、解不开都是「什么都不发生」。这与**区外读**那条地板同一个
  立场。
- **打开是宿主侧的动作**：状态机只把目标放进一个槽位（与剪贴板同形），运行期 spawn
  `xdg-open`，目标作为**一个** argv 元素直传、**不经 shell**、不过 `bash` 工具、不过权限门、也
  不进沙箱 —— 交给系统的自始至终只是一个字符串。**模型触发不了它**：模型能做的只是把文本写进
  回答，开不开取决于人的指针，这就是它不需要权限门的原因。
- **回执**：成或不成都在提示行打一句（`已打开 …` / `打开失败：…`），寿命与复制那句一样三秒；
  解析不出来的那一下**不留**回执 —— 点一段普通文字本来就该没有反应。

## 切换模型与思考强度

四个入口共用一条路（`.scratch/model-switching/spec.md`，判据记在
[ADR 0017](adr/0017-model-and-effort-switch-mid-session.md)）：点**状态行**的模型格或档位格、
`Ctrl-T`（开**模型**那份）、`/model <model id>`、`/effort <档位>`。`--model` 仍然是**起手**
那一个，只是不再是唯一的办法。

**状态行从四段变五段**：`模型 X · high ┆ 模式名 ┆ 上下文 n% ┆ 状态词`。模型与档位之间**不放
`┆`** —— 它们是同一格的两半（这一场会话由谁答、答多深），所以段内用 `·`，而它们在宽度阶梯里
**同生共死**：先丢「模型 + 档位」，再丢模式，最后剩「上下文 + 状态词」。这**推翻**
`.scratch/tui-visual-language/spec.md` §17 的四段与它的降级顺序（那一条的其余部分 —— 标签退后、
值靠前、分隔符只是线 —— 不动）。80 列下这一格放不下了，100 列才回来。

**两格可点**：由画状态行的那一处每帧把两格的矩形记进 `Regions`（与页签、回合条同一条纪律：
只有真画出来的才点得到）。点它上行 `FrontEndEvent::OpenPicker(Model | Effort)` —— 前端**不知道
忙闲**（渲染器不知道什么在跑），所以只上行，判忙闲在循环那一侧。**讨论会话**（`SessionFacts`
的 `switchable` 为假）不上行，而是给一句「讨论里的两位是配置事实，不在会话中途换」。

**忙闲**：**运行中拒绝**并给一句「这一回合跑完再切」，空闲立刻生效。判据在循环侧那几处
`events.recv()` —— 「这个手势到达时有没有东西在跑」就是各自分派点的处境。

**候选由循环算好**（`ConsoleRequest::Picker`，`src/cli.rs` 的 `model_picker_options` /
`effort_picker_options`），渲染器只画拿到的清单。模型候选要过**两条**判据：它的 provider
**在 `config.toml` 里被显式配置过**（`Config::configured_providers` —— 五个内建 profile 无论有
没有被配置都在，`config.toml` 只做覆盖，所以「我配了哪几家」只能另记一份），**而且**有密钥。
再加一条兜底：**当前模型无条件在列** —— 一份什么都不写的配置里清单会空，而看不到自己正在用的那个
模型是最刺眼的一种不诚实。两条判据各砍掉一类候选：配置了但没给密钥的（切过去起不来，那属于配置
诊断），以及没被配置的（那正是注释掉 `[providers.kimi-code]` 的效果）。

档位候选是该模型能力表里那张表加一档**默认**（`None`，不发那个参数）。表为空
（`MiniMax-M3`、`kimi-for-coding-highspeed`）时给**空清单**，状态行那一格显示 `固定`。

**选择器浮层**是一块居中的盒子：**一行一个模型，每行三列** —— `模型 id ┆ profile ┆ 状态`
（`当前` / `可切换`）。列与列之间是 [`wording::PICKER_COLUMN`]（与状态行段分隔符同一个字形：它是
框架，不是正文）；每列按自己那一列**最长的值**左对齐，短的那些右面留白 —— 表格要对齐。第二列只给
profile 的**名字**（反引号包住，如 `` `minimax-cn` ``）：表格的列标签已经说明了那一列是什么，再加
「走」那种动词就把它说成一句散文了。当前项在行首一个 `▸`，高亮走焦点色 + 粗体；选不了的那行**没有**
记号（状态列已经说了它的状态），它自己灰着且点了不响应。宽度由内容定且**不超过**主列；高度按
候选数，多过就在内部滚动，于是回车回的永远是高亮那一行。

```
┌────────────────────────────────┐
│ 模型                          │
│▸ kimi-k3         ┆ `kimi`    ┆ 当前   │
│  deepseek-v4-pro ┆ `deepseek`┆ 可切换 │
└────────────────────────────────┘
```

因为一行一个，**横向与纵向是同一件事**：`j`/`k` 与四个方向键都走上一行/下一行，到两端停住（页脚
`j/k 或 ↑↓ 移动 · 回车 选择 · esc 取消`）。点按行命中，记录的是 `(屏幕行, 列起, 列宽, 下标)`。

它与问卷**同形而不同路**：键盘在它立着时归它（输入区禁言），**指针不被它独占**（框外点击关掉它），
关掉之后键盘原样还回去。`ctrl-t` 本身也进了底部提示行（`ctrl-t 换模型`，排在 `ctrl-o 左栏`
前面一格）—— 它是一条常用的会话手势，而开出来的那块浮层自带完整键位说明。

**换完推一条 `SessionUpdate`**（循环推、前端收，发完就完）：模型、档位、上下文窗口与新名册
—— 因为上下文窗口换了模型就可能换（1M ↔ 256K），而它是 `上下文 n%` 的分母。**发言者名册跟着
换**：发言者的名字是 provider profile 的名字而不是模型 id，换厂商就换名，新名字走
`SpeakerColors` 已有的「没人认领的槽位」那条路（与 `/discuss` 中途加入的讨论者同一条）。代价
说在明面上：转录里已经画过的行不改名（事件流只追加）。

**plain 前端没有选择器**（那条路径上没有键盘）：`Picker` 读作取消，于是 plain 下的全部手段是
`/model <id>` 与 `/effort <档>`。回执在两端都带那句代价：「前缀缓存重来，下一次调用会重新读一遍
上下文」。

## 问卷：区域与键位

模型发起的问卷（`ask_user_question`）在 TUI 里接管底部输入区，而它的键盘分成两个**区域**
（[`.scratch/questionnaire-keys/spec.md`](../.scratch/questionnaire-keys/spec.md)，判据记在
[ADR 0010](adr/0010-questionnaire-keys-dispatch-by-zone.md)）。区域是**问卷级**的一处状态
（每题共用，翻页按新题复位），不是每题一份。

- **选项区**：`j`/`k`、`Ctrl-N`/`Ctrl-P`、`↑`/`↓` 移动高亮，**空格**在高亮项上**切换**
  （单选下集合至多一个），而可打印字符与 `Backspace` 在这里**被吞掉** —— 键盘只在输入区
  让给文本。
- **输入区**：`j`/`k`（以及所有可打印字符）就是文本，`Ctrl-N`/`Ctrl-P` 与**四个方向键**都
  什么都不做（2026-10-06 起：原先 `↑`/`↓` 回选项区、`←`/`→` 翻页 —— 见
  `.scratch/questionnaire-keys/spec.md` §2），`Enter` 与选项区走**同一条**规则。
- 越过选项的**下**端就是进输入区（`j`/`↓` 在末项之后），而回来只有 `Esc`（回选项区并举起
  退出的手）、`Tab`（跳过并前进）、`Enter`（处置这一题）三条。没有选项的题只有输入区。

**往前走**的三个手势是同一个动作：`Enter`、`→`（只在选项区 —— 输入区里它静默）与页脚「下一题 →」先给**还没作答**的当前题
记一次**跳过**，再前进一题；而 `Enter` 在**每题都有着落**时改成**提交**（它是键盘上唯一的
提交路径 —— 走到末题时前面必然都有着落，所以「末题回车 = 提交」是这条规则的推论，不是另
一条位置判据）。`←` 与页脚「上一题」只移动、不记任何东西。`Tab` 仍是那个明确的跳过键。
**末题上的 `→` 什么都不做**（不记、不前进、不提交）—— 提交不可逆，不该由一个移动键承担。

**作答撤销跳过**：空格确认、点击选项行、或打进非空白字符，都会清掉这一题的跳过标记，只清
不回滚。跳过说的是「这道题此刻的处置」，所以当前题已被记跳过时页脚在进度后面挂一句
`已跳过` —— 它会进答案，必须看得见。

长选项与自由文本行都**折行**（续行对齐在标记后面），选项窗口按**渲染后的行数**滚动，所以
折成三行的选项整块可见。

问卷占的底部块有它**自己的高度上限**（`layout::plan_questionnaire`）：题面与选项要一起放
下来，所以它不像草稿那样停在十行，而是向上吃掉转录的行，只给转录留三行 —— 余地下到一份问卷
都画不出时（40×10 那个下界）才退回「留一行」。三条一起放不下时让位的是**题面**：打答案的那
一行与选项窗口的地板（三行）先占，题面拿剩下的行（至少一行），被削掉的尾部换成一行
`…（题面还有 N 行未显示）`。以前题面是钉死的，一份二十行的题面会把选项与输入行一起挤掉，
屏幕上只剩一截题面加一句教人怎么选的页脚
（[`.scratch/questionnaire-keys/spec.md`](../.scratch/questionnaire-keys/spec.md) §7 的补记）。

答案只有一个形状：`selected` 与 `custom` 可以同时出现（单选与多选一样），`selected: []`
且没有 `custom` 才是跳过。

问卷到达前端之前要先经过一条**端口**：循环把整批问题交给前端的那个值，带一条一次性回复
通道。**丢掉回复通道就等于「没有答案」**——取消、问卷里双击 `Esc` 的「退出这次询问」，或
输入结束都会走到这里——所以工具永远不必挂住等一个不会来的答案。它与权限门的那个请求并列：
问卷是**第三类发起者**，那条 `Asker` 接缝不为它扩展。

**一道题的选项**是模型在 `questions[].options[]` 里给的数据：`label`（原串就是答案值，
`(推荐)` 只做显示；旧会话里那条 `(Recommended)` 同样认，见
[`.scratch/tui-feedback/spec.md`](../.scratch/tui-feedback/spec.md) §1）加可选 `description`。前端
按钮的词汇里有一个同名的 `Choice`
（一个键加一句中文标签），两者**同名不同物**：前者是模型给的选项数据，后者是前端按钮的
键位定义，共同点只有「都可被选中」；保留两个名字是更小的改动，各自的层各自命名。

**一道题的作答草稿**活在键盘那一侧、每题一份、可来回翻页：已选 `selected`、自定义文本
`custom`、高亮下标 `highlight`、是否跳过 `skipped` 四项。`skipped` 记的是「没作答就走开了
一步」，一旦记下就编码成 `selected: []` 且无 `custom`；但**作答会把它清掉**（只清不回滚），
所以它读起来是「这道题此刻的处置」，不是一次盖章。`selected` 与 `custom` 可以同时成立，
单选与多选一个形状。

问卷一族的人类可见文案住在 `render::wording` 里，用 `questionnaire_*` 这个前缀命名
（`questionnaire_hint`、`questionnaire_option`、`questionnaire_plain_*` 等）。TUI 与 plain
共享同一个生成器；模型面文本不经过这里。

`Esc` 与 `Ctrl-C` 在问卷里问的是两个不同的问题，各有一把**举手**（共用一个槽位，所以互斥）：

| 键 | 第一下 | 第二下（半秒内） |
| --- | --- | --- |
| `Esc` | 举手（在输入区还顺带回到选项区，文本不清） | **退出这次询问**：drop 掉回复通道，工具读到「没作答」，模型继续跑 |
| `Ctrl-C` | 取消这次运行（不变）+ 举手 | 退出进程，130（不变） |

问卷立着时提示行整行被页脚替换，所以那句回执只能落在**页脚**：平时它是键位提示（**四档**：
宽档带 `ctrl-n/ctrl-p` 别名 → 丢掉别名 → 只剩 `esc 退出询问` → 连它也没有，页脚只剩进度与
按钮），举手期间被回执**替换**而不是追加。
提示最后那一句跟着 `Enter` 实际会做什么变（会提交时 `回车 提交`，否则 `回车 下一题`），而
`已跳过` 与回执一样**不参与降级** —— 前者说的是答案会被读成什么。同一时刻屏幕上只有一个
视觉焦点：**全屏唯一的反显就是键盘所在**（选项区聚焦时在选项行、输入区聚焦时在自定义行；
`DIM` 已退场，见 `.scratch/tui-visual-language/spec.md` §29）。

**问卷占的是底部输入区那一块，不是整个指针。** 落在它里面的点击归它（选项行、`自定义：`那
一行、页脚按钮）；落在别处的照旧走原来的分派 —— 主列页签（`对话` / `轨迹`）、左栏页签、回合
条、滚到底指示器都照常管用，所以问卷立着时也能翻到轨迹页去读上下文。而**键盘始终是问卷的**：
切页不把键盘交给文件页，也不打开任何详情覆盖层 —— 那两处都会把 `j`/`k` 从问卷手里抢走，而
「唯一的反显就是键盘所在」也会随之说谎。中间那三类确认（粘贴、清草稿、目标停下）是**覆盖
层**，它们仍占着整个指针：点别处什么都不做，因为一次误点绝不许关掉一个还没回答的问题
（`.scratch/questionnaire-keys/spec.md` §7 的补记）。

## 输入框里的记号

草稿里有两种**记号**：`/命令` 与 `@路径`。判据是**能兑现** —— `/` 命中命令表、`@` 命中工作区
的文件索引 —— 而上色与「不可分割」用的是**同一条判据**
（[ADR 0012](adr/0012-input-tokens-are-atomic.md)）。能兑现的记号是一块整体（chip）：光标进
不去、删除整块删、内部改不了，于是它读起来是一个**指称**而不是一段可以逐字改的文本；兑现不了
的（`看 /tmp/x` 里的 `/tmp/x`）就是普通文本。

两个前缀**共用一套浮层与键位**（`↑`/`↓` 移动、`Tab` 接受、`Esc` 关，窗口滚动与「高亮始终
可见」照旧），只有**边界**与**候选来源**各一份：

| 前缀 | 边界 | 候选来源 | 接受之后 |
| --- | --- | --- | --- |
| `/` | 草稿**任意行、任意位置**的 token 开头 | 命令表（`TuiState.catalog`） | 插 `/name `，`Enter` 照旧**插入并发送** |
| `@` | **草稿任意位置**的 token 开头（`src/@foo` 不触发） | 工作区文件索引 | 插相对路径，`Enter` **只接受、不发送** |

**接受之后补一个分隔的空格**（命令与文件；后面已经是一个空白时不补），于是接着打的就是下一
样东西 —— 这一段任务、下一句话 —— 不必自己记得敲那个分隔。**目录不补**：补全它要的是「钻进
去」，而一个空格会把记号当场结束在目录上，下一层就过滤不出来了。

**`/` 菜单把三类来源摆在同一张表里，名字按类别上色**（`.scratch/tui-feedback/spec.md` §11）：
**命令**用草稿里那个 `TOKEN_COMMAND` 蓝（同一个名字在草稿里与菜单里长得一样）、**技能**品红、
**MCP 提示词模板**青 —— 三色互不相同。**描述留在正文档**：它是一句解释，不参与分类。
**光标行仍旧反显、不叠类别色**（`tui-visual-language` §27 的另一半照旧）：光标是临时的，颜色
说的是这一行是什么。窗口一窗最多 **12 行、最宽 96 列**，宽度按**这一行实际要占的列数**算 ——
内建命令七条以前正好占满那一窗，技能与模板于是永远看不见，而最长的那条描述总会掉最后两个字。

`@` 列**文件与目录**：选中目录插 `@dir/` 并**保持菜单开着**（一路钻下去），选中文件插 `@path `
并关掉菜单。**裸 `@` 不列候选** —— 命令表只有几十条，「裸 `/` 是一份用来看的列表」成立，而
文件有几千个，「看全部」没有意义。**含空白的路径不进候选**：`@` 的记号按空白结束，插进去会
当场断掉。

**`@` 的匹配是分段的**（`.scratch/tui-feedback/spec.md` §4）：query 与路径都按 `/` 切段，query
的每一段按前缀落在路径的某一段上、段序保持，**第一段可以从路径的任意一段起** —— 于是 `cli`
配得到 `src/cli.rs`，`render/tui` 配得到 `src/render/tui.rs`。匹配起点更靠前段者排在前面，同分
保持索引里的字典序。上色与 chip 的「能兑现」判据不受影响：它照旧要求那条路径**精确**存在。

**工作区文件索引**是会话级的一个共享值（`Idle` / `Loading` / `Ready`）：在 `spawn_blocking` 里
用 `ignore::WalkBuilder` 遍历，规则与 `grep` 工具**同源**（遵守 `.gitignore`、非 git 仓库也能走、
固定字典序），而**隐藏条目这一处有意分家**：隐藏**目录**放行（`@.scratch/` 要能一路钻下去 ——
2026-10-05 真机反馈后改的），隐藏**文件**（`.env` 一类，那才是暴露面）与 `.git/` 仍不进候选。
进 TUI 预热一次，此后**每次提交一条消息**在后台重扫，而
`Loading` 挡住并发的那一份（两次遍历的结果不会互相盖掉）。**遍历**从不阻塞键盘，也从不被某次
按键触发；按键路径上只多一次**内存里**的「这个路径在不在索引里」查询 —— 上色与 chip 的判据
都要它。

**一条缝**：记号的判据要查命令表与索引，而 `Input` 是个不认识这两样的纯文本模型。所以区间由
`TuiState` 算好、同步进去（与 `slash.prefix` 那种「记着的值」同构），`Input` 只做纯几何的吸附
与整块删。**粘贴进来的文本按同一条推导**，不另设豁免。

`/` 的**提交语义**与 `@` 对等：整个草稿里任意行、任意位置的 `/name`（命令表命中）都算命令，
取**最靠左**的那个，它**前面的文字（含前面的行）并入任务**（`请 /loop 我的目标` → 任务
「请 我的目标」）；而 `/quit`、`/clear`、`/undo` 这类**无参命令仍要求整条只有它**，于是
「请把 `/clear` 加到文档里」不会被劫持成一次清空。**这条规则是有牙的**：`@` 被误认没有后果，
而 `/` 被误认会**真的执行** —— `用 /loop 做目标循环` 就是一条命令；这个权衡记在
[ADR 0012](adr/0012-input-tokens-are-atomic.md)。

## 挂起与恢复

TUI 里按一下 `Ctrl-Z` 把整个进程停到后台（`SIGTSTP`），在 shell 里干完活 `fg` 回来，画面
原地继续。它是**终端层手势**：不进事件流、不落 `log.jsonl`、不打回执（shell 自己会打一行
`Stopped`），而任何视图都拦不住它 —— 重放中、详情覆盖层立着、问卷立着、退出手势的举手正举
着，按下去都是挂起。**单下生效**，没有举手那一层（`.scratch/suspend-gesture/spec.md` §1、§2）。

顺序是这条接缝的全部内容：**先交还终端、再停**。

- **交还**：关鼠标上报与括号粘贴、发 `CSI 23 t` 把标题还回用户原来那条、`ratatui::restore()`
  关掉 raw 模式并离开备用屏幕 —— 然后才把处置置回 `SIG_DFL` 并 `raise(SIGTSTP)`。`raise` 是
  同步的：这一行返回就是 `fg` 回来了。（`kill(0, …)` 不行 —— 它异步，调用返回之后当前线程
  还会往前跑一段，交还与停止的先后就乱了。）
- **恢复**：`enable_raw_mode()` 加 `EnterAlternateScreen`（crossterm 的原语，不是
  `ratatui::init()` —— 那个每次都会再包一层 panic hook）、重新保存并写标题、重开鼠标与粘贴、
  `terminal.clear()`，然后走正常绘制路径**全量重绘**（挂起期间用户可能已经改过窗口尺寸）。

`--plain` 与 headless 不参与：plain 从不进 raw 模式，`Ctrl-Z` 是终端驱动直接产生的
`SIGTSTP`，应用根本看不到那个字节；headless 没有键盘。这条「plain 天然就对」由
`scripts/tui-startup-check.py` 的 `--plain` 挂起路径守着。

**停着的那段时间世界照常走**：`bash` 与动态工具的子进程各自成组、收不到这次停止，会继续跑
（输出管道填满后它们阻塞在写，恢复后接着走）；`bash` 的超时与 provider 的超时都是用户态
计时器，挂起期间照数 —— 所以挂得比剩余超时久，回来时那一回合会以 provider 断流或命令超时
收尾，走现有的错误呈现。**想让子进程一起停下，动作是先 `Ctrl-C` 取消、再 `Ctrl-Z`**：取消
路径本来就会 `killpg` 掉活跃的工具进程组。这些取舍记在
[`.scratch/suspend-gesture/spec.md`](../.scratch/suspend-gesture/spec.md) §6。

## 重新打开会话：历史重播

`--continue` 重开本工作区最新的那个会话（`--continue <id>` / `--session <id>` / `-c <id>` 改成重开指名的
那一场；那一场在别的工作区时，这一趟的工作目录跟着它走、并说一句），TUI 把它的整条事件流铺回转录里，于是屏幕不是空着
开始的。这条接缝是一个前端控制请求，不是一个渲染事件：CLI 在组装之后、启动横幅之前推进
`ConsoleRequest::Replay { events }`（`ConsoleHandle::replay`），带着**组装好的**快照
（`Harness::events()`），其中已经包含恢复期为悬空工具调用写下的那些合成结果。plain 模式
不理这个请求；它没有转录可供重播。`RenderEvent`、转录与 headless 渲染器都不动。

- **只有一条施加路径。** 每个被重播的事件都走活事件走的那个 `TuiState::apply`，于是块、折叠的
  提示行、名字颜色、信息面板、回合条与模式都是作为副作用重建的，而不是由第二套实现重建。
  这也正是历史行可以点的原因：详情命中表由 `apply` 维护，不为历史重建。
- **分帧，带一条进度行。** `replay_batch` 每轮循环施加一片，同时受 512 个事件与 2000 个源行
  两个上限约束，而重播还没结束时循环从不空等。底部提示行临时换成 `恢复历史 n/m`（更窄的
  终端得到 `恢复中 n/m`，再窄是 `恢复中`）；那条降级阶梯归
  `wording::history_progress_line` 所有。
- **那条接缝。** `TuiOptions::reopened` 说明有一次重播要来，而 TUI 在渲染任何东西之前先等
  那第一个 console 请求：组装已经在渲染通道上发出了恢复结果，它们与快照持有的那些是同一
  批事件，所以在拥有它们的重播上来之前，什么都不能画。最后一片落地时，插入一条渲染层的行
  `── 以上为历史 ──`（`wording::history_divider`）—— 只在历史真的画出了东西时才插 —— 也
  只有到这时，被按住不发的活事件才按到达顺序冲出去。所以横幅落在接缝之后。重播期间到达的
  一条*进流的*活事件被丢掉，而不是缓冲，因为快照已经含有它；只有永不进流的事件
  （横幅、诊断、流式增量）被按住。分隔行从不进流，所以下一次重开插进来的是新的一条。
- **按住的输入。** 重播进行中时草稿照样能编辑，但 `Enter` 不提交、指针被忽略、滚动键也被
  忽略：视口一直钉在转录末尾，直到历史走完。`Ctrl-C` 也走**双击**（第一下举手、第二下退出，
  `.scratch/exit-gesture/spec.md` §1）；`Ctrl-D` 与 `Esc` 没有反应。

这些行为在 `tests/history_replay.rs` 里对着一个固定尺寸的 `TestBackend` 断言；一次重开对
终端的占有由 `scripts/tui-startup-check.py` 里的 `--continue` 路径守着，而大会话的观感留
在手工清单上（`docs/tui-manual-checklist.md`，⑭）。

## 交互式 CLI

不带子命令的 `heng` 在当前工作区里开一个交互式会话。渲染器怎么选、`--continue` 怎么续
哪一场、`--mode` 覆盖哪一档，都见 [`README.md`](../README.md) 的「跑」一节。

会话从配置的那一档模式起步 —— `[permissions] mode`，或在其上覆盖的 `--mode`，默认 `ask`
—— 而组装把 console asker 注入进来，所以一次写在提示符来的同一个键盘上发问。模式是会话上
的一个值，流上没有任何东西携带它，所以前端组装时就带着它（`SessionFacts::mode`）、在状态
行里显示它，并在手势到来时走自己那份拷贝，同时循环走策略那一份；为什么如此见 ADR 0003。

真终端必须确认的东西 —— 光标、鼠标、缩放、干净退出 —— 写成了一份跟着走的清单，在
[`docs/tui-manual-checklist.md`](tui-manual-checklist.md) 里。固定尺寸 `TestBackend` 缓冲
或 `scripts/tui-startup-check.py` 看得见的一切，则在那里断言。
