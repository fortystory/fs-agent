# 外部 diff 工具的颜色不经过语义色板

`[ui] diff_viewer` 指一个外部命令时，那份 diff 由它来画。这一篇记下那一档的颜色为什么**不走
语义色板**，以及它与「一块外来屏幕」（[ADR 0013](0013-nvim-file-viewer-is-an-alien-screen.md)）
的界线在哪里。

规格在 [`.scratch/diff-page/spec.md`](../../.scratch/diff-page/spec.md)。

## 决定

- **那一档是「外来的输出」，不是「一块外来的屏幕」。** 我们把那份 diff 从 **stdin** 喂给一个
  命令、一次性收它的 stdout，按「只认 SGR 子集」解成带样式的行，画进**同一个**详情覆盖层。
  它不占键盘、不需要 pty、不铺满底色、也不进事件流。
- **它吐的颜色原样铺上去**：认下来的 `ESC[…m` 那一族 —— 重置、前景（8 色与 8 色亮档）、背景、
  粗体、暗淡 —— 直接落到那一片文字的样式上，**不查语义色板**。认不出的颜色档（256 色之后的
  写法、truecolor）保持现状；其它 CSI（光标移动、清屏、`K`）整段丢掉。
- **转义序列不留在文本里**：解成 span 之后，拖选复制出来的仍是干净的文本，行号与截断也仍是
  我们自己的。
- **我们只给环境变量**（`PAGER=cat` / `GIT_PAGER=cat` / `COLUMNS=<正文宽>`），一条命令行参数
  都不注入；argv 按整元素给，绝不过 shell。
- **失败与超时（2 秒）回退内置那一档**，并在提示行给一句带工具名的回执；它的 stderr 不许画
  进正文。
- **弹窗标题右端标出工具名**，内置那一档不标。

## 为什么

1. **语义色板管的是我们自己画的东西。** `palette.rs` 那两条纪律（界面域 / 内容域、一个语义
   一个具名常量）之所以成立，前提是每一片的颜色都由我们选。这一档的颜色由别人的程序选，
   硬把它映射进色板等于**重画** —— 而我们重画不出它的呈现，也不该假装能。
2. **装了 delta 的人要的就是 delta 的样子。** 这一档存在的理由是「用我自己顺手的呈现看
   diff」；把它的颜色换成我们的语义色，这一档就只剩一次没用的重排。
3. **代价是看得见的，而且被补偿了。** 同一份 diff 在两台机器上长得不一样 —— 标题右端那个
   工具名就是给这件事的答案。
4. **它比 ADR 0013 窄。** 那一档是**一块矩形**：铺满底色、独占键盘、要一个终端仿真器、还要
   应答 `DSR` 一类查询。这一档只有一次输出：没有底色、没有键盘、没有 pty —— 所以那条纪律的
   例外在这里也小得多。

## 代价

1. **这一档的颜色不受任何纪律约束**：它自己决定背景，可能在我们的配色下不好看，也可能与
   语义色板撞色。接受的代价 —— 它是**外来输出**，与外来屏幕同一族。
2. **仓库里多了一个 ANSI 解析件**（`src/render/changes.rs` 的 `parse_sgr`）。它**不是**终端
   仿真器：只认 SGR 里的那几档，别的整段丢掉。以后要支持 `--color-only` 之外的写法，得先
   想清楚它是不是还只是一个「解 SGR 的子集」。
3. **暗色 / 亮色终端各自由那个工具适配**，我们插不上手。
4. **多一次子进程**（每个文件一次），它落在已经有的那条「弹窗先立起来、正文后到」的路上。

## 被否决的替代方案

- **把 ANSI 剥掉、只画文本。** **否决**：装了 `delta` 的人只看到无色的重排结果，这一档一半的
  意义没了。
- **原样透传转义序列。** **否决**：文本里带着转义，拖选复制出来的就不是文本了 —— 而「复制
  出来的是文本」是这一层既有的底线。
- **把它的颜色映射进语义色板**（认一个 `+` 就画 `DIFF_ADDED`）。**否决**：那是重画，而且会
  与它自己的行号、重排、语法色打架。
- **内嵌一屏外来终端**（复用 ADR 0013 那一档）。**否决**：这是一次性输出，不需要 pty、不需要
  键盘转发、也不需要 `respond_to`；把它做成一块屏幕只是白付三样代价。
- **不标工具名。** **否决**：有人会以为是渲染器改版了 —— 同一份 diff 在两台机器上长得不一样
  这件事必须有个看得见的解释。
