# 模型与思考强度是会话中途可变的会话值

换模型与换档曾经只有一条路：退出、重开、把上下文重新喂一遍。这一篇记下它们怎么变成**这一场
会话里可改的两个值**：走 `FrontEndEvent` 上行 + `ConsoleRequest::Picker` 一问一答，**不进事件
流**。

规格在 [`.scratch/model-switching/spec.md`](../../.scratch/model-switching/spec.md)。

## 决定

- **模型与档位是会话值，可以中途换。** 换模型的落点是 `Harness::switch_model` —— provider、
  会话配置与发言者**一个动作**里一起换（只换一半就会拿新 id 去问旧 caps）；换档只是
  `SessionConfig::params` 里的一个值，**不重建 provider**。
- **前端只上行手势，不做决定。** 点状态行那两格或按 `Ctrl-T` 都只发
  `FrontEndEvent::OpenPicker(Model | Effort)`；判忙闲、算候选、等答案、真的切换都在循环那一侧 ——
  渲染器不知道什么在跑，也不知道有哪些模型可用。
- **候选由循环出。** `ConsoleRequest::Picker` 带一份已经算好的清单（`ConsoleRequest` 那一格
  与 `Ask` 同形，答 `Option<usize>`，`None` 是取消）；渲染器从不伸手去够配置。
- **换完推一条 `ConsoleRequest::SessionUpdate`**（模型、档位、上下文窗口、新名册）：那是
  **注入的只读值**，前端自己算不出换了模型之后那个百分比的分母。
- **运行中拒绝**，给一句「这一回合跑完再切」；空闲立刻生效。讨论会话里**只显示不切换**。
- **回执带上缓存的代价**：换档与换模型都会让厂商侧的前缀缓存失效，所以回执说「前缀缓存重来」。
  代价是真的，但它从禁令变成了**代价**。

## 为什么

1. **难回头**：这条通道的形状决定了以后「会话中途能改什么」的全貌。今天它是第一个走
   `FrontEndEvent` + `Picker` 的会话属性；下一个（预算？窗口？）会照它的样子来，所以第一次
   就该定清楚：上行只带意图，候选与答案在循环。
2. **离开上下文会显得奇怪**：为什么模型能换而预算不能、窗口不能？因为那两样是**能力表**的
   派生值，而模型与档位是**配置里那一条**。不写下这条判据，后人会把这理解成「能改的都是会话
   值」，于是把预算也做成一个选择器。
3. **真有替代方案**：**重启进程换模型**就是今天的做法（丢掉正在进行的对话）；**走渲染流**那条
   路是单向的（事件流只追加，一次换档会在转录里留下半条记录，而它其实不是这一场会话发生过
   的一件事）。两条都不选，才有了这条「上行 + 一次问答」的通道。
4. **不进事件流是刻意的**：事件流是**发生过的事**的追加日志，而模型与档位是**当前是什么**的值。
   放进流里，一份会话里先后两个模型会变成两条互相矛盾的历史记录，而 `--continue` 之后没有
   任何东西能告诉新一轮该用哪个 —— 它得靠重放那条历史去猜。
5. **忙闲判据属于循环**：换 provider 与请求参数与模式手势（纯渲染器状态）不同形，所以运行中
   必须拒绝而不是排队。而「有没有东西在跑」只有循环知道。

## 代价

1. **`minimax-provider/spec.md` 的「明确不做」那一段被推翻**：那里写的是「heng 的推理档位只有
   `low` / `high` / `max`（会话开始定死）」。那半个约束是同一个的两面 —— 那时还没有选择器，
   于是「只有三档」与「会话开始定死」是一回事。现在有了会话中途切换的需求，「定死」这一半
   作废；「三档」这一半由能力表从 `bool` 升成每模型一份的档位表一起作废（补上 `medium` 与
   `xhigh`）。
2. **`config.rs` 里两条注释被推翻**：`GenerationParams::reasoning_effort` 的「整个会话钉住；
   中途从不切换」与 `ReasoningEffort` 的「档位在会话开始时就定死」。它们给出的理由（换档会扔掉
   前缀缓存）**留着** —— 它变成了回执里那半句话，而不是一条禁令。
3. **`tui-visual-language` §17 被推翻一半**：状态行从四段变五段，降级顺序改成「先丢模型 + 档位」。
   §17 的行内三档不变。
4. **`CONTEXT.md` 的**状态行**词条被改写**：「都不可点」不再成立。讨论会话那条限制落在
   `SessionFacts::switchable` 上，由组装期定（讨论 CLI 那条路径传假）。
5. **状态行在 80 列下开始丢那一格**（多一段就是这么贵）；分母换模型之后可能变 1M ↔ 256K，
   `上下文 n%` 会跳一次。
6. **一场会话里能看到两个发言者名**：换到另一个厂商的 profile 就换了名字，而转录里已经画过的
   行不改名（事件流只追加）。这与 `/discuss` 中途加入讨论者是同一条纪律，不是新的问题。
7. **plain 前端拿不到选择器**：那条路径上没有键盘，`Picker` 读作取消，所以 `/model <id>` 与
   `/effort <档>` 必须带参数（不带参数是**用法错误**，不开弹窗）。

## 被否决的替代方案

- **重启进程换模型**（今天的做法）。**否决**：丢掉正在进行的对话，而「换模型」恰恰常发生在
  一次长对话的中途。
- **把切换记成事件**（`ModelSwitched` 之类）。**否决**：见「为什么不进事件流」。
- **走渲染流**（前端把请求画进流里）。**否决**：那条通道是单向的，只追加不改写；而档位是**当前
  是什么**，不是一个发生过的事件。
- **把模型与档位合成一个旋钮**（「快/中/慢」这类抽象档）。**否决**：档位是厂商各自的**请求参数**
  取值，每家认的档还不一样 —— 抽象档要么骗人（映射不到任何一个），要么每次都猜。展示成真值
  才诚实。
- **自动切档**（上下文过半就降档之类）。**否决**：换档要重新 prefill，一次自动的降档会在最贵的
  时刻付最贵的代价，而这正是要由人按下的那种决定。
- **`/model` 不带参数就开弹窗**（而不是给用法）。**否决**：plain 前端没有选择器，命令这一路
  必须能一步到位，否则那条路径上换模型就没了。
- **建一份统一的「厂商默认」**（把 `默认` 展开成 `max` 或 `high`）。**否决**：那是把「厂商自己挑」
  说成「你选的」，而两家的缺省本来就不同。
