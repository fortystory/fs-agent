# 输入框里的记号在能兑现时是一等单元

给输入区加上 `@` 提文件与记号的上色之后，这一篇记的是那两条**难回头**的决定：
**能兑现的记号（chip）在草稿里是不可分割的一块** —— 光标跳不进去、删除整块删、内部改不了；
以及 **`/` 命令的边界与 `@` 完全对等** —— 草稿里任意行、任意位置的 `/name` 都算命令，它前面
的文字（含前面的行）并入任务。前者改变的是输入框的编辑模型（`Input` 从「纯文本 + 光标」变成
「纯文本 + 光标 + 一组不许落进去的区间」），后者改变的是 `Submission` 的解析边界。

规格在 [`.scratch/input-tokens/spec.md`](../../.scratch/input-tokens/spec.md)，codex 那一侧的
一手调研在它旁边的 `research/` 里。

## 决定

> 输入框里的记号（`/命令`、`@路径`）在**能兑现**时是不可分割的一块；而 `/` 命令在草稿
> **任意行、任意位置**都算，它前面的文字（含前面的行）并入任务（无参命令仍要求整条只有它）。

具体地：

- **能兑现 = 上色 = chip**：一条判据管三件事 —— `/` 要在命令表里命中，`@` 要在文件索引里命中。
- **chip 的不变量是「光标永不落在记号内部」**：移动吸附到边界、删除整块删、内部插不进字。
- **推导不在 `Input` 里**：区间由 `TuiState` 算好同步进去，`Input` 只做纯几何的吸附与整块删。
- **`/` 与 `@` 共用一套浮层、键位与位置判据**，而**边界各按前缀**：`/` 在草稿任意行、任意
  位置开头，`@` 只在空白或草稿起点之后开头（`src/@foo` 不触发）。
- **`/` 的菜单与解析一起放宽**：只放宽一侧就是让界面说谎。

## 为什么

1. **两个视图分家比一个功能缺失更坏。** `/` 菜单原本只认同行首，解析也只认同行首 —— 两者
   一致。只放宽一侧，就会出现「菜单让你选、提交后它只是普通文本」那种界面说谎，而它比功能
   少一点难查得多。
2. **记号如果不是整体，「删除」就没有正确答案。** `@src/render/tui.rs` 是一个**指称**，不是
   一段可以逐字修改的文本：删掉中间一个字符，它指的东西就变了，而屏幕上看起来只是少了一个
   字母。整体删除把「改」这件事交回给补全。
3. **颜色是有承诺的。** 给 `看 /tmp/x` 里的 `/tmp/x` 上蓝色会教出错误直觉；所以上色、chip 与
   「它到底能不能兑现」必须是同一条判据，而不是三处各自的近似。
4. **命令出现在句子里时，丢字是不能接受的。** 今天那条「内建命令要么整条提交、要么什么都
   不算」的规矩（`src/cli.rs` 的 `submission()`）防的正是这个；放宽位置之后，
   记号前面的文字必须有个去处 —— 并入任务。位置既然与 `@` 对等，这条就一并管到前面的**行**。
5. **两个前缀只有一份边界规则。** 「`@` 能出现在句子中间、`/` 只能打头」是一条没有语义理由的
   不对称 —— 两者的**判据**（能不能兑现）既然不同，**位置**的规则就更不该各写一套。

## 代价

1. **记号内部不能逐字编辑。** 想改 `@` 路径里的一个字符，只能整块删掉重新补全。这是拿
   「精细编辑」换「指称的完整性」，也是这一轮最贵的一笔手感。
2. **`Input` 多了一条不变量要维持。** 十二个移动 / 编辑方法都要经吸附与整块删，而它今天只是
   `String` 加一个下标；此后新加的每个方法都得记得这条规矩。
3. **`Input` 与 `TuiState` 之间多了一根线。** 「什么算记号」的知识在 `TuiState`（那里有命令表
   与文件索引），区间要同步进去 —— `Input` 因此多一份「记着的值」，与 `slash.prefix` 同构。
4. **`/` 的解析不再看位置。** 它要在整个草稿里找第一个命中的记号，而「前文并入任务」对无参
   命令不适用（它们仍要求整条只有自己）—— 这条不对称得记住。
5. **正文被劫持是明码标价的。** `@` 被误认没有后果（它只是个引用，模型读路径即可），而 `/`
   被误认**会真的执行**：`用 /loop 做目标循环` 这句话就是一条命令。访谈里考虑过用「要求整行
   以记号起头」挡住它，最终选了与 `@` 完全对等 —— 因为「两个前缀只有一份边界规则」更值得要。

## 被否决的替代方案

- **只放宽菜单、不放宽解析**（界面能弹，命令不生效）。**否决**：让界面说谎。
- **要求整行以记号起头才算命令**（`用 /loop 做目标循环` 不算，`  /loop 目标` 算）。它能挡住
   正文被劫持，但「前文并入任务」就不成立了 —— 而丢字正是那条既有规矩要防的事。**否决**。
- **无参命令也能出现在句子里**（`请把 /clear 加到文档里` 执行 `/clear`）。那会清空会话。
   **否决**。
- **让 `@` 在任意位置触发**（含 `src/@foo`）。路径中间那个 `@` 更可能是别的意思，codex 的边界
   （空白起始的 token）是对的。**否决**。
- **记号可逐字编辑，只有删除整块。** 那「整体」就不彻底：能删不能改的记号会让人更困惑。
   **否决**。
- **把 `Input` 重写成片段序列**（真正意义上的 chip 编辑器）。它会一并改掉折行、历史、鼠标
   定位与 `submitted()` 的形状，而收益只是把「不可分割」结构化一点。**否决**。
- **粘贴进来的文本不做记号推导。** 同一段文本因为输入方式不同而有两种身份，比那点意外更难
   解释。**否决**。
