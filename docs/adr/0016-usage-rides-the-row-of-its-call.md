# 用量长在产生它的那次调用的行上

轨迹页里每次模型调用本来独占一行 `用量 in=… out=… cached=… miss=…`。这一篇记下把它改成
**那次调用的一段尾巴**、并在回合收尾补一条合计：**一笔用量不再是自己的块**，它属于产生它的
那次调用；**尾巴跟着绘制记录走**，所以实时、宽度变化与 `--continue` 三处落点一致；**诊断通道
一个字不动**，`usage_summary` 仍是机器可读的那一份。

规格在 [`.scratch/trace-usage-tail/spec.md`](../../.scratch/trace-usage-tail/spec.md)。

## 决定

- **用量不再独占一行。** 它并进**到达那一刻这次调用最后画出的那条过程行**的末尾（推理过就是
  思考行，没推理就是回合开始那行），写 `in=… out=…`；`cached` / `miss` 留在 `usage_summary`
  与左栏 `调用量` 页。
- **到达就贴，并记进绘制记录。** 思考行随后定稿是整行重写、宽度变化又是整批重排，尾巴必须
  跟着那条记录走，否则会被重写吞掉或在重排里落错行。
- **没有可承载的宿主就保留独立用量行**：今天只有合成器那次调用 —— 它不属于任何回合。
- **一次发言跨 ≥2 次模型调用时，收尾行尾加 `合计 in=… out=…`**，口径是这条发言全部调用之和；
  只调用一次时不加。
- **尾巴是纯文本**：不给 `▸`、不加详情、不加颜色档；宿主行的详情与时刻戳都不动。
- **窄终端照折行**，不为尾巴另立降级链。

## 为什么

1. **归属是读者真正要的东西。** 「这次调用花了多少」只有贴在它的产物上才读得出来；独占一行
   时，它与那次调用之间隔着别的行，屏幕上的相邻关系甚至是错的。
2. **落点必须由结构决定，不能靠「流上恰好在最后」。** 今天 `settle_thinking` 用
   `replace_last` 就地重写窗格最后一行、不查那一行的身份，而用量行恰恰可能成为那一行 ——
   「只推理不产出正文」的调用会把刚 push 的用量整行顶掉。把用量记进绘制记录而不是当场写屏，
   这条路径自然消失。
3. **合计只有渲染层算得出来。** `UsageRecorded` 是逐次调用的读数，`TurnStarted` / `TurnEnded`
   给出这次发言的边界；把两者在渲染层对起来，是既有材料能做到的最省的做法，不必动事件流。
4. **诊断通道与显示制式分开。** `usage_summary` 的四个调用点里只有一个是屏幕，其余三个是
   诊断与机器可读出口（[`usage-stats-format`](../../.scratch/usage-stats-format/spec.md) 明写
   「保持原样」）；窄写法是轨迹页自己的事。

## 代价

1. **`trace-tab` §3 的「其余块今天就已经各占一行，不改」被推翻了一半。** 只剩「其余块」那一半
   成立；`Usage` 从此不是独立行。
2. **仓库里多了一份措辞。** `usage_summary` 旁边多了 `usage_tail` / `total_tail`，两者必须同步
   改（新字段出现时两边都要想一遍）。
3. **渲染层多了一组跨块的状态**：`in_call`、`turn_calls` / `turn_usage`，加上每条绘制记录上的
   `tail`。它们跟着 `painted` 一起重建，所以宽度变化那条路要保证「尾巴与合计进记录」而不是
   现算。
4. **尾巴会折行。** 轨迹排版宽 120 列带左栏时是 59 列，`in=… out=…` 通常放得下，但窄终端下
   这一行仍会折成两行 —— 这是接受的，不另立降级链。
5. **合成器的用量落单。** 它没有回合边界，既不进尾巴也不进合计，仍是独立一行。

## 被否决的替代方案

- **按屏幕行记账**（用量到达时 append 到最后一行，之后每处重写都记得带上尾巴）。**否决**：
  重写点不止一处，且工具行比用量晚到 —— 尾巴会落在错的行上，或在下一次重写时丢掉。
- **推迟到该次调用收尾再贴**（把工具行留作宿主）。**否决**：那次调用后面还会画**消息行**
  （`MessageCompleted` 无条件产生一条块），收尾时最后一行已经是内容行；而最常见的纯对话调用
  根本没有工具行 —— 推迟等于让它们贴不上。
- **把用量塞进宿主行的详情**。**否决**：数字就看不见了，而这笔数字是常读的。
- **改成事件流上的字段**（让 `UsageRecorded` 附着在某条事件上）。**否决**：事件流只追加，
  `plain` / `headless` / `sessions stats` 都要跟着改，为一个显示问题动数据层。
- **窄档给尾巴一条降级链**。**否决**：尾巴已经比原来短一半，第一步就会退到「整条不显示」——
  那是把账藏起来，不是把它排好。
