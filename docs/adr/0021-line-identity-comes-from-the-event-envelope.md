# 0021. 行的身份来自事件信封，不是它在窗格里的位置

- 状态：接受（2026-10-09）
- 背景：[`.scratch/trace-ledger/issues/10-grilling-history-and-selection.md`](../../.scratch/trace-ledger/issues/10-grilling-history-and-selection.md)（长历史与行选择）；事实底账在 [`.scratch/trace-ledger/research/03-line-identity-and-loading.md`](../../.scratch/trace-ledger/research/03-line-identity-and-loading.md) §1–§2。

## 决定

账本上一条源行的地址是**块身份 + 块内第几行**，而**块身份从事件信封的 `seq` 派生**：渲染层把 `seq` 从 `apply` 往下带进块（今天只取了 `at` 就把它丢了），另记一份「块身份 → 源行」的账，并给 `Pane` 开一个**按行键替换任意一行**的入口（今天只有 `replace_last`）。

**事件流一个字节都不改** —— `seq` 本来就在信封里，这条决定只发生在渲染层内部。

## 为什么

1. **位置型下标被两件事推翻**：`CAP`（20 000 条源行）裁剪时窗格内**一切**下标统一左移，宽度变化则让整批源行重放。而**选中、折叠、命中导航、层级跳转、详情跳转**五件事都要活过这两件事 —— 今天的行身份恰好是这两件事里最脆的那个。
2. **`seq` 是这套系统里唯一的身份编码**：它就是 JSONL 的行号，落盘与读回原样保留，于是**实时路径与会话恢复路径是同一个值**，不需要第二套编码去对账。
3. **一条事件可以产出零个到多个块**，所以块身份是 `seq` **加块内序号**，而不是 `seq` 本身。
4. **它是「组头随回合增长就地改写」的唯一解**：那件事要按行键替换任意一行，而 `Pane` 的字段全私有、公开面只有追加与改最后一条。
5. **`seq` 不可空。** 渲染层自己造的那几条记录**没有信封**：推理增量开出的思考行、诊断、通知、拼好的系统提示词 —— 增量绕过事件流，事后推不出来（`.scratch/trace-ledger/issues/12-block-identity-and-pane-replace-at.md` 的落地记录）。所以身份里那半行号是**可选**的，`None` 的那几种由渲染层一条单调计数补另一半：唯一，且**跨重放稳定**（重放走的是同一个事件序列，于是同一个计数）。这不是把决定改成「渲染时编号」—— 流上的那些仍然取信封；只是承认有一类记录不在流上。
6. **不做以块为键的反向索引**：那份映射每次裁剪都要全体下标左移，而查找只在读者按键或绘制选中高亮时发生（每帧至多一次、有上限的线性扫描）。要的是「源行 → 块」那一向，它与窗格同长同进同出。

## 代价

1. 轨迹页那份重放清单（`Painted`）要多带身份字段，`apply` 要把 `seq` 传下去，块内序号要在 `apply` 那一处编。
2. `Pane` 的公开面多一个入口，平行表要多一份按身份记的索引，`CAP` 裁剪时它也得跟着裁。
3. **身份不再等于位置**，于是「跳到第 k 行」这类操作以后都得经身份反查 —— 多一跳，而那一跳是唯一能扛住重放的路径。

## 被否决的替代方案

- **渲染时按顺序单调编号**（重放时同序重编，编号不变）。**否决**：它是**间接**的 —— 要拿「重放顺序与实时顺序逐条一致」当一条不许破的纪律，而那条一旦破掉，症状是**选中的行悄悄换成另一个块**，没有任何断言会响。
- **按块内容指纹**（摘要 + 首行文本的哈希）。**否决**：重放时要重算，且两块内容完全相同时撞键；而指纹对「同一段文本被工具输出两次」这种常见形状反而最不灵。
- **什么都不加，选中按源行下标尽力恢复**（今天的方向）。**否决**：那正是被上面第 1 条推翻的东西 —— 裁剪与重放之后「尽力」没有正确性可言。
