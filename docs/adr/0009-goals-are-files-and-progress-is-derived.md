# 目标是一份文件，进度与额度都从会话流派生

给 fs-agent 一个**目标**（一份具名的清单文件），它就用 `/loop` 连续工作到清单上的条目全部完成。
这一篇记的是那条**难回头**的决定：**目标不进会话状态**。目标只有一份文件（定义），其余全是派生量
——进度来自各会话 `todo` 调用的合并，额度来自各会话 `UsageRecorded` 的求和，当前目标是流上最后
一条 `GoalSelected`。全系统没有第二处存储。

规格在 [`.scratch/goal-loop/spec.md`](../../.scratch/goal-loop/spec.md)，现状说明在
[`docs/goals.md`](../../docs/goals.md)。

## 决定

> 一个目标的**定义**是输入数据，落文件；它的**进度**、**归属**与**跨会话花费**都是派生量，
> 从会话流现算。没有目标状态文件，也没有一个「当前目标」字段。

具体地：

- **定义**：`~/.local/share/fs-agent/goals/<名字>.md`，只有条目与 id、**不带状态**。
- **归属**：`GoalSelected { goal }`，只追加。**当前目标 = 流上最后一条**，所以切换就是再记一条。
- **进度**：`todo` 的每一项可以带一个可选 `id` 引用清单条目；条目状态 = 这个目标横跨的所有会话的
  `todo` 调用的合并，按（会话时间，`seq`）取最新。
- **额度**：闸门的求和范围扩到这个目标的所有会话（`SessionConfig.carried_tokens` 承载「别处已经
  花掉的那一份」），所以翻页不重置额度。
- **恢复**：从「当前目标归属那一刻之后有没有收尾事件」派生，不写恢复标记。

## 为什么

三条理由，按分量排：

1. **「事件流是唯一真相源」这条不变量在这里同样成立，而状态文件会让它第一次出现例外。** 本仓库
   的一切查询都是流上的函数（`pending_tool_calls`、`total_usage`、`current_goal`），所以重放、
   `--continue`、审计看的是同一个答案。一份 `goal-state.json` 会在任何一次崩溃之后与流漂开，而
   漂开之后没有任何权威能裁决谁对。
2. **有现成先例**：日账本（**DayLedger**）已经在做同一件事——扫会话文件、按 UTC 日聚合 token
   用量，**不新增状态文件**。目标跨会话的额度与进度走同一条路，于是「跨会话的账怎么算」在这个
   仓库只有一个答案。
3. **清单文件因此可以保持是**人**的东西**：人能读、能手改、能用 `cat` 看，因为它不是机器状态，
   只是输入。状态画进文件（复选框）会让人误以为它才是进度，而它其实只是开工前那份快照。

## 代价

1. **每次判进度都要扫本桶、读会话文件。** 一次 `/loop` 的回合边界上扫一次，成本与日账本同一量级；
   换来的是没有锁、没有并发写、没有「状态文件坏了怎么办」。
2. **`todo` 的 schema 多了一个可选字段。** 「参数是唯一真相源、零 schema 改动」那条设计被咬了
   一小口：**可选**意味着老流仍能反序列化、老调用照常解析，但形状确实动了。`SCHEMA_VERSION`
   刻意**没有涨**——加一个可选字段与几个新 payload 变体之后，老流读得回来，而跨版本从来不承诺
   兼容（见 `src/events.rs` 开头那句）。
3. **归属筛是「这个会话认领过这个目标」，不是「这次调用发生在属于它的那一段」。** 一个会话先做
   目标 A、再 `/loop` 目标 B 时，A 的进度派生会把 B 之后那些 `todo` 也算进来。实践里切换发生在
   一个目标做完之后，所以这条近似没有被观察到；真要收紧，判据要变成「按 `GoalSelected` 把一条流
   切成若干段」，那是另一个形状的决定。
4. **压缩给的经验压不出来。** 派生给的是**进度**（哪些条目完成了），不是**经验**（为什么这么做、
   踩了什么坑）。所以过八成时仍要用一次模型调用写摘要——它不在派生这一侧，它是另一件事。

## 被否决的替代方案

- **一份 `goal-state.json`，记当前目标 + 每个条目的状态。** 最直觉的做法，也是被否决得最彻底的
  一个：它把「真相」分成两半，而其中一半会在崩溃时过期。**否决。**
- **把归属放进 `SessionStarted`（加一个 `goal` 字段）。** 省一条事件，但 `SessionStarted` 是钉住
  的前缀的一部分，加字段会动 schema 的骨架；而且「一个会话换目标」会变成改一条已经写下的事件。
  只追加一条更省，切换天然支持。**否决。**
- **把条目状态写进清单文件**（复选框或 `status:` 一列）。人能直接看见进度，但文件就会被两方写：
  循环写状态、人改条目，而冲突之后没有任何权威。清单一旦生成就是**封闭**的，封闭的判据要的正是
  它不变。**否决。**
- **给模型一个「开新会话 / 翻页」的工具。** 分类上装不下：`Effect` 的三类全是**工作区**副作用，
  而「开新会话」不是。既然压缩与翻页都是循环的动作、模型不该请求它们，不给工具就不必现在处理那
  个缺口。**否决。**
