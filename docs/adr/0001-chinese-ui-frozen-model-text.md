# 人类可见文本用中文，模型可见文本冻结

前端文本（转录三个画家、CLI 的帮助与报错、`sessions *` 的输出）一律硬编码中文，不引入运行期区域设置（locale）——自用 CLI 没有第二种语言需求，省掉国际化（i18n）依赖与随之而来的断言复杂度。而**会投影进模型 `messages` 的文本保持英文**：包括 `AgentError.message` 与 fs-agent 自己生成的工具结果文本（`project()` 把它们投成 `user` / `tool` 消息），以及 `SessionError.detail`。

这条边界不是风格偏好，而是一条代码里看不见的约束：**模型可见文本是 provider 缓存前缀的头**，中途改它就会废掉前缀缓存（spec §4 / §17 已把这类操作列为明令禁止），恢复旧会话时还会出现中英混排的历史。事件流只追加、永久回放，所以进事件流、要永久回放的错误文本，写下的语言就冻在那里；好在 `SessionError` 根本不进投影（`src/provider/projection.rs:239`），它的中文只在渲染时按 `code` 映射，`detail` 原样透传。

> **2026-10-06 补注（正文不改，只记更名）**：程序已更名为**衡**（`heng`），本文里作为产品名的 `fs-agent` 读作「衡」（[ADR 0014](0014-renamed-to-heng.md)）。

## 后果

- 人类可见文案有唯一处（措辞层，先例是 `render::transcript::decision_source_label`），`sessions show` 不再自己重拼第四份。
- 新增字符串前要先判断它属于哪一侧：进 `messages` 的一侧只增不改。
- 界面术语一律用 `CONTEXT.md` 的中文名；词汇表（glossary）里没有的概念，先补词汇表再写界面。

## 后加（2026-09-30）：模型可见的那一半被重新打开

本文「**会投影进模型 `messages` 的文本保持英文**」那一半由 [ADR 0005](0005-model-visible-text-in-chinese.md) 推翻：工具声明与描述、工具结果（含 fs-agent 自己生成的错误文本）、`AgentError.message`、`SessionError.detail` 这类**散文**改走中文 —— 语言按「是不是标识符」分，不按「谁读它」分。触发点是「人读的是同一份文本」：详情弹窗与转录原样画工具结果（`DetailKind::Tool`），冻结的英文正好落在人眼前。

本文的**另一半原样保留、而且仍然最硬**：一个会话的前缀在会话内只增不改（中途切 `reasoning_effort`、中途改 `tools`、逐轮重写 system 都还是禁止的）。本文当初记的那两笔代价没有消失，只是被重新判定为值得付：老流永久中英混排（真的发生了），以及升级后每个新会话一次前缀未命中。
