# 0019. 命令留在流上，但不进模型上下文

- 状态：接受（2026-10-09）
- 背景：[`.scratch/command-echo/spec.md`](../../.scratch/command-echo/spec.md)；
  与它相邻的那半条是 [`.scratch/ui-trim/spec.md`](../../.scratch/ui-trim/spec.md) §2
  （`/<skill> 任务` 的技能名不再被删）。

## 决定

一条 `/` 命令被循环执行时，落一条 `EventPayload::CommandRun { text }`（原文）：

- **它在流上**：写进 `log.jsonl`、`--continue` 之后重播、`sessions show` 列成一行。
- **它在模型上下文之外**：投影把它当零，于是模型永远读不到 `/clear`、`/undo` 这类它压根
  没听见的东西（与 `GoalSelected` / `SandboxStatus` 同一档 log-only）。
- **判据是「这一条提交会不会变成一句 user 消息」**：会的那几条（普通消息、带任务的
  `/<skill>`）原文已经是用户发言，再记一遍是重复；不会的那些才另记。
- 转录里它是**一行原样回显**（`[命令] /clear`），用草稿里命令那个颜色；命令自己的回执若有，
  就在它下面一行。

## 为什么

1. **命令是手势，不是话。** `/clear` 结束会话、`/undo` 撤一次编辑、`/model …` 改配置 —— 它们
   改变的是这台机器与这场会话的状态，而模型对它们**没有发言权**：让模型看见 `/clear`，等于
   让它以为自己可以要求清场。
2. **而读的人必须有账。** 从前唯一的出处是**回执**，而回执只有成功才有：`/clear` 清完场什么
   都不说，`/undo` 失败时说的是另一件事。于是转录里出现过「我敲了什么」这一段空白 —— 滚动
   回去读不出那是 `/model` 还是 `/effort`。
3. **它与 `ui-trim` 那条同源，判据却相反。** 那里让 `/<skill> 任务` 的**整条原文**作为一条
   user 消息进上下文，因为技能正文是一句**要模型去做的事**；内建命令不是。同一族记号按「它
   有没有话说给模型听」分岔，而不是一律留或一律删。

## 代价

1. **多一个 `EventPayload` 变体**，投影、复盘与三个渲染器各要认它一遍（穷举匹配，没有
   `_` 分支，所以漏一处编译不过 —— 这正是我们要的）。
2. **命令原文要打码**：它是人敲的那一行散文，`/goal-new` 的来源路径也在里面。
3. **复盘视图多一行。** 它与工具调用那些行并排，读的人得认出方括号那一枚是命令。

## 被否决的替代方案

- **把命令原文作为一条 `user` 消息发进上下文。** **否决**：那是替用户说话，而且模型会真的
  读到 `/clear`（`.scratch/ui-trim` 只对**技能**这么做，正因为技能正文是一句指令）。
- **只留回执。** **否决**：回执只在成功时说话，而「我做了什么」要包括没成功的那几次。
- **用 `RenderEvent::Notice`（渲染通道）而不是事件。** **否决**：那样它不落 `log.jsonl`、
  `--continue` 之后不重播，而 `.scratch/ui-trim` 明确说过重放要重现同样的转录。

时也打得开」：浮层立着时键盘归浮层，`Esc` / `Ctrl-D` 关掉它之后键盘**原样还给问卷**。它推翻了
