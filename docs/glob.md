# `glob`

`glob(pattern)` 是内建的**文件枚举**工具：模型给一个 glob 模式，它列出工作区里匹配的那些文件
路径，一行一条、相对会话工作区、按路径排序。它存在的理由是**枚举**这件事今天只能靠 `ls` /
`find`：两者在 bash 里合计 832 段以上，而上游四家都给了专用的只读枚举工具。来源是
[`.scratch/tool-coverage/spec.md`](../.scratch/tool-coverage/spec.md) §4。

## 为什么它不是一条 shell 命令

`ls` 与 `find` 在 bash 里的权限代数和 `git` 那条一样错：`bash` 的 `effect()` 恒为
`Effect::Exclusive`，于是「列一下这个目录有什么」这种纯读取也要独占工作区、在 `readonly` 档下
被拒。而这一条工具的 `effect()` 恒为 `Effect::ReadOnly`：四档放行、不取工作区锁。

## 参数面

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `pattern` | 是 | 相对会话 cwd 的 glob：`src/render/*.rs`、`**/*.md`、`.scratch/*/spec.md` |

- **只有这一个字段**：路径前缀就写在 pattern 里，所以「只扫工作区」那个支点原样保留。
  **不加 `path` 参数** —— 它会把一条最干净的只读工具拖进「区内外」之分。
- `*` 不跨 `/`、只有 `**` 跨：`src/*` 表达「`src` 下有什么」，`src/**` 是整棵子树。
- **不做 `tree` 那档层级缩进**：那是渲染的活，而这份输出是要被逐条喂给别的工具的。

## 范围与忽略规则：与 `grep` 同一套

- **只扫会话 cwd**，不声明读路径 —— 与 `grep` 同一个支点，于是它绕开 `outside_read` 那套
  「工具声明过的读路径」语义。
- **忽略规则由 `tools/walk.rs` 给出**：`grep` 与 `glob` 共用同一遍遍历，所以遵守 `.gitignore`
  （含 `.ignore` 与 git 的全局忽略）、跳过隐藏文件与隐藏目录、按路径排序。
- 上游有一家让 `Glob` 与 `Grep` 用两套规则，本仓库**不跟**：同一张工具表里的两个工具看见的
  世界必须一致，否则模型得先弄清「为什么这条找得到那条找不到」才敢信任何一条。
- **filter 发生在遍历之后**，所以 `pattern` 永远选不出本该看不见的文件。

## 输出与上限

- **一行一条相对路径，按路径排序**，不带大小与时间：带 `stat` 就多一次系统调用，按 mtime 排
  就让输出不可预期。
- **没有匹配时**返回一句如实的说明（「工作区里没有匹配 `<pattern>` 的文件」），而不是空字符串。
- **上限 `MAX_PATHS = 500`**（与 `grep` 的 `MAX_MATCHES` 同一个值、少一个新常量），超出时末尾
  写一行「还有 N 条未列出：请把模式收窄一点」。token 那条界仍走统一的截断流水线。
- **列出来不等于读过**：`read_paths()` 是调用前的纯函数，声明不了运行时才知道的那些文件，
  所以随后的 `edit_file` 仍要求先 `read_file` —— 与 `grep` 同一决定。

## 与别的工具的分工

| 要知道什么 | 用哪个 |
| --- | --- |
| 这个工作区里定义了哪些符号 | **[`repo_map`](repo-map.md)**——「有哪些符号」 |
| 某个名字 / 模式出现在哪里 | **[`grep`](grep.md)**——「某个名字在哪」 |
| 这个工作区里有哪些文件 | **`glob`**——「有哪些文件」 |
| 某个文件里到底怎么写的 | **`read_file`**——路径你已经知道（[grep.md](grep.md) 里那张分工表的同一句）|

三条只读工具看见的是同一个工作区；`bash` 一个字没动（它确实什么都能写，仍是 `Exclusive`）。
