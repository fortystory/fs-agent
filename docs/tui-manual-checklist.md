布局本身按 ADR 0002：备用屏幕（alt screen）全屏，**一条左栏 + 一条主列**
（转录 / 状态行 / 输入 / 提示）—— 四周那圈外框已经拆掉，两者之间只剩一条竖虚线（⑳）；

左栏在 **≥ 120 列**时 40 列宽并画「衡」标记（**23 行小篆块字**：最上面一行是拼音 `héng`、其余
二十二行是拼出来的篆书；终端矮于 32 行时退回拼音加一个汉字那五行），

tab 的点击、回合条的焦点只有真终端能验，见 ⑩ 与 ⑮。

## ① 光标

1. 输入三行：`第一行` `Ctrl-J` `第二行` `Ctrl-J` `第三行`，光标应始终跟在最后一个
   字符后面，不进到边框、不跑到对话区。
2. `↑` `↓` 在**同一逻辑行**内走；`Ctrl-A` / `Ctrl-E` 到行首 / 行尾；`Ctrl-U` / `Ctrl-K`
   删到行首 / 行尾；`Ctrl-W` 删前一个词。
3. 输入长到软换行（超过内宽）后，`↑` 跨视觉行、`Home` 到该行首（不是整个草稿首），
   光标列按显示宽度算：`你好世界` 四个字占八列。
4. 行尾插入：把光标移到行中间打字，字应插在光标处而不是末尾。
5. 提交后光标回到输入区第一格（输入区没有前导字形，见 ⑯）。
6. 粘贴多行文本后**光标立刻可用**、草稿未提交（这条和 ⑤ 一起看）。
7. **输入法**：切到中文输入法，敲一串拼音但**先不选字** —— 预编辑的字母必须始终待在输入区
   光标处。它若在输入区与状态行之间来回跳，说明光标被收起来时位置漂了：
   `tests/render_layout.rs` 里那条物理光标测试管机制，IME 这一半只有真终端答得了。
8. 多行草稿按 `Esc`：覆盖层是**标题 + 正文 + 候选键行**、各占一行（不是一整句）：标题
   `清空输入`（加粗）、正文 `草稿有多行，Esc 会把它们全部丢掉`、候选键行 `[y] 清空`
   与 `[n] 保留`；`n` 后草稿原样还在。

## ② 权限模态

触发一次需要权限的写操作（让 agent 跑一条 `bash` 写文件之类的命令）。

1. 模态出现在**中区块内部**，四个区块的边框与标题不被挤坏。权限询问的正文是**三行**：
   `权限询问：`（**不带工具名**）、**与转录折叠行同一句话**的描述
   （`调用 bash 查看 git status`）、**要执行的原文命令**（`bash（command=…）`）——
   最后这行是授权时唯一必须看得见确切命令的地方，不要少；工具名与「要做什么」各只出现一次。
2. 按 `y` / `a` / `n` 任一回答：模态消失，**焦点立刻回到输入区**（接着打字能进草稿）。
   候选键行（`[y] 允许` / `[a] 总是允许` / `[n] 拒绝`）在覆盖层里**水平居中**，不贴在左边。
3. 模态在时 `Shift-Tab` 不改变权限模式（模态吃掉键盘）。

## ③ 鼠标

1. 先让转录长出可视区（跑几个回合），滚轮上滚看历史，`PgUp` / `PgDn` 翻页，
   `Ctrl-G` 到底。
2. 上滚后转录区**右下角**出现指示条：`↓ {n} 行新内容 · 点此到底`；没有新内容时是
   `点此到底`（它就是「到底」两个字）。**用鼠标点它**，视图回到最底。
3. **按住 Shift 拖拽选中文本并复制** —— 鼠标捕获开着，不按 Shift 选不中（ADR 0002
   的已知代价）。选完粘贴到别处，内容正确。
4. 权限模态在时滚轮不动转录、点击指示条无效。
5. **点击作答**：权限 / 粘贴确认 / 清空草稿三种覆盖层，用鼠标点候选键行里的
   `[y] 允许` / `[a] 总是允许` / `[n] 拒绝`（或对应问题的键）——效果和按那个键完全一样；
   点标题、正文、边框、覆盖层里的空白**没有反应**；窗口矮到候选键行被裁时，被裁掉的那截
   点不到。
6. **问卷点击**：模型发来 `ask_user_question` 时，单击某个选项行只**切换**它的选中状态 ——
   单选与多选一样，都不翻页、也不自动提交（「确认不翻页」是这一轮的约定）；底部
   `← 上一题` / `下一题 →` / `提交` 只画可用的那些，点它们翻页 / 提交；选项超出可视区时
   滚轮移动高亮（键盘在**输入区**时滚轮静默）；点 `自定义：` 那一行光标出现在那里，翻页后光标收回。
7. **折叠与详情**（**在轨迹页上** —— 对话页没有入口，见 ㉚）：转录里 `[执行者] ▸ ✓ 思考完成` 与
   `[执行者] ▸ 调用 bash 查看 <路径>`
   名字后面有 `▸`，用鼠标点它（或点工具失败行）打开详情覆盖层：标题是被点那行的原文、
   边框是被点那行说话人的颜色，正文分 `── 思考 ──` / `── 参数 ──` / `── 输出 ──` 三节，
   底部 `↕ n/m · esc 关闭`（滚到最底时 `n` 等于 `m`）；
   `↑` `↓` `PgUp` `PgDn` 与滚轮滚动，`Esc` 或**点击覆盖层以外的任何地方**关掉；
   **滚到最底时底部计数应读到 `n/n`**（与总行数相同）；覆盖层打开时转录冻住
   不动（新输出不会把它抽走）。**短输出（没被截断过的）就是全文**——不该出现 `全文不可用`；
   只有**被截断过**的结果才会去找 `outputs/<id>.txt`，那时文件被删掉才显示预览加 `全文不可用`，
   且超过 200 000 字符时末尾写 `已截断`。
8. **角色配色**：四种角色的名字前缀颜色不同 —— 讨论者 1 `浅青`、讨论者 2 `浅品红`、
   执行者 `浅黄`、用户 `浅绿`、系统 `灰`；正文仍是原来的语义色（成功绿、错误红、
   权限黄、narration 灰）。浅色主题下浅黄 / 浅绿 / 浅青的可读性弱是**已知取舍**。
9. **用量尾巴**（**在轨迹页上**，ADR 0016）：一次模型调用结束后，那笔用量长在**它那次调用**
   的某一行行尾 —— 推理过就是 `▸ ✓ 思考完成` 那行（读作 `… ✓ 思考完成 in=… out=…`），
   没推理就是 `回合开始（第 N 次迭代）` 那行；屏幕上**不再有**独立的
   `用量 in=… out=… cached=… miss=…` 那一行。一次发言跨两次模型调用（模型调过工具）时，
   `回合结束：…` 那一行尾上多一条 `合计 in=… out=…`，数值等于两笔之和；**只调用一次时没有
   合计**。讨论的合成器那一次仍自己占一行。窄终端下这一行按既有规矩折行，数字不省略、不消失。
   **拖宽拖窄（或 `--continue` 重放）之后落点不变、尾巴不多不少**，点那一行弹的还是它自己的
   详情（思考全文 / 工具参数），尾巴不改变可点性。

## ④ resize

1. 拖窗口：四区块重排不撕裂，没有半行残留、没有叠字（拖动本身会发 SIGWINCH，
   TUI 收到 resize 事件就重画）。
2. **锚点**（固定尺寸的 buffer 测不到，只能这样验）：吸底时拖窗口，转录仍贴底、
   不跳；先上滚几行进入脱离态，记住最上面那一**源行**，再拖窗口 —— 变宽变窄后
   仍应是**同一源行**在最顶（重排会改变它占的显示行数，但不该换成别的行）。
3. 拉到很窄：提示行按**主列宽度**（不是终端宽度）丢条目，`ctrl-c/ctrl-d 退出` **永远在**，
   `就绪` 先丢。`40` 列时是 `就绪 · enter 发送 · ctrl-c/ctrl-d 退出`（左栏已隐藏，主列 38 列）；
   `80` 列时左栏占掉 29 列，提示行只剩 49 列，于是是 `enter 发送 · ctrl-j 换行 · ctrl-c/ctrl-d 退出`。
4. 拖到 `40×10` 以下（下一个尺寸 `39×24`、`40×9`）：整屏只剩
   `终端太小：至少 40×10`，不画出半个布局。
5. 拖到 `120×24` 且草稿写到 10 行（输入上限）：**左栏不动**（它是自己一栏、高度不随之
   变），转录被压到 **10** 行（终端高度减去 4 行外壳、再减去 10 行草稿）。

## ⑤ 粘贴

1. 粘 5 行文本：**不提交**，全进草稿（行尾统一成 `\n`，Tab 变成四个空格）。
2. 粘超过 100 000 字符：覆盖层同样是**标题 + 正文 + 候选键行**、各占一行：标题
   `粘贴确认`、正文 `粘贴 {n} 字符`（`{n}` 是实际字符数）、候选键行 `[y] 粘贴` 与
   `[n] 取消`；`n` 丢弃、`y` 全收；`Esc` 与直接回车都算拒绝。
3. 粘一大段以 `/` 开头的文本：**不是内建命令**，按普通输入处理（多行则整段进草稿）。

## ⑥ Ctrl-J 与 Shift-Enter

1. `Ctrl-J` 换行（提示行写着 `ctrl-j 换行`）。
2. `Shift-Enter` 也是换行 —— 但它只在**支持键盘增强协议**的终端上做得到：进 TUI 时我们会推
   `DISAMBIGUATE_ESCAPE_CODES`，答应的终端才把带修饰的 `Enter` 报过来（kitty、foot、wezterm、
   Ghostty 这一系；tmux 里还要它自己允许透传）。不答应的终端里 `Shift-Enter` 与裸 `Enter` 在协议
   层不可区分，于是它**提交** —— 提示行也因此从不写 `shift+enter`（那是句只有一部分终端兑现得了
   的承诺）。**提交不是 bug**（`.scratch/tui-feedback/spec.md` §10）。
3. **别的基本键照旧**：推了协议之后，`Esc`、`Ctrl-C`、`Ctrl-D`、`Ctrl-O`、`Tab`、`Shift+Tab`、
   方向键与 `PgUp`/`PgDn` 一个都不能变（协议只把带修饰的键换个形式报过来，解析仍归一）。这一条是
   这一轮最该盯的回归面 —— 换了上报形式的终端里，坏掉的是那些**看起来无关**的键。

## ⑦ 退出后终端干净

1. **双击退出**（`.scratch/exit-gesture/spec.md` §1–§2）。空闲时 `Ctrl-C` 与 `Ctrl-D`
   **完全对等**：第一下只在提示行举手（出口那一段换成 `再按一次 ctrl-c/ctrl-d 退出`），
   500 毫秒内第二下退出 —— 两键混按也算第二下；超时不按，提示行恢复原样、下次要重新按两下。
   忙的时候 `Ctrl-C` 第一下只取消当前回合（提示行 `已取消 · 再按一次 ctrl-c 退出`）、第二
   下退出；忙时 `Ctrl-D` **没有任何反应**（也不清掉已经举起的那把手）。详情覆盖层打开时
   `Ctrl-D` 是**关掉详情**，不参与退出手势。`/quit` 仍然一下就退。**那个退出确认框已经拆了**
   —— 屏幕上不该再出现 `退出会话` / `[y] 退出` / `[n] 取消`。
   退出后终端干净、回执打在 shell 里，见下一节。
2. 退出后在 shell 里：

   ```
   stty -a | grep -E 'icanon|echo|isig'
   ```

   三个都**不带** `-` 前缀（是 `icanon` / `echo` / `isig`，不是 `-icanon`）—— 也就是
   回显、行编辑、`Ctrl-C` 都正常。再敲 `Ctrl-C` 能打断命令、`history` 能用。

3. 用鼠标拖拽选中终端里的文本：不需要按 Shift 也能选（鼠标报告模式已关）。
4. 备用屏幕退出后回到原屏幕，之前的 shell 内容还在。
5. **忙碌双击退出后终端干净 + 回执打在 shell 里**：起一个长回合，连按两下 `Ctrl-C`。
   退出后 `stty -a | grep -E 'icanon|echo|isig'` 三个都带 `-` 前缀的**反面**（即
   `icanon` / `echo` / `isig`），而且 shell 里出现一行 `heng: 会话 <id>；接着跑：
   heng -c <id>`（走 stderr；grep `会话 <id>；接着跑：` 就能找到它，而且那一行真的粘得回去）。这一条守的是 `std::process::exit(130)` 那个缺陷：旧实现跳过一
   切析构，终端会留在 raw + 备用屏幕里。
6. 脚本里 `Ctrl-C` 与 `/quit` 两条路径**每次跑都会各验一遍**（撤销序列 + termios）。
   **panic 路径手工复现不了**（没有可靠的触发方式），它靠 `TerminalModes::drop` 与
   panic hook 调同一个 `disable_terminal_modes()`：只要上面 2–4 项通过、也就是这个
   函数是对的，panic 时也走同一条。这是本清单里唯一一处「靠构造保证」而不是「靠操作验」
   的项目。
7. **重开后退出**：`--continue` 进一个有历史的会话，等底部进度行消失（重播收敛）再走
   上面 1–4 的退出路径 —— 终端的交还与普通启动完全一样（备用屏幕 / 鼠标 / 粘贴 /
   termios），历史重播不会把终端留在别的状态里。

## ⑧ 忙碌 Ctrl-C

1. 让 agent 跑一个长任务，`Ctrl-C`：回合中止（转录里是中止/取消的结论），进程仍在，
   输入区可用。
2. 空闲 `Ctrl-C`：直接退出。
3. 权限模态在时 `Ctrl-C`：先取消当前回合（不是关模态）。

## ⑨ 120×24 的几何（已自动化）

这一条原来要在 120×24 的终端上手工走三遍：把窗口拉到这个尺寸（改完还得随便敲一个键才会重画，`stty` 不发 SIGWINCH）、把草稿写到十行、再删回空草稿。现在这三步的几何都由两条测试逐值钉住，**不手工走**；它们红了再回来 —— `a_tall_draft_costs_the_transcript_and_never_the_sidebar` 管 120×24 与草稿 10 行（转录剩 10 行），`the_input_area_holds_three_rows_before_it_grows_and_the_transcript_pays_for_it` 管三行地板与删回空草稿后的 17 行。

## ⑩ 左栏：块字 / 收起来那版 / 文字身份 / 隐藏四档

左栏的宽档由**宽度**决定（≥ 120 列 → 40，80–119 列 → 28，< 80 列 → 整栏隐藏），
它的**内容**由自己的高度决定（先丢大块字 → 收起来的那版标记 → 身份行 → 字段尾部）。固定尺寸的
`TestBackend` 能断言两侧的档位与字段数，但标记的**字形、明暗与居中**只有真终端看得见。

1. 把窗口拉到 `160×40`（宽档）：左栏 40 列，**23 行小篆标记**居中（字形 31 列、留白左三右四，
   标记本身 38 列：第 1 行是拼音 `héng`、第 2–23 行是拼出来的篆书「衡」），
   下面是页签（tab）条（`调用量│文件` + 填充横线；`轨迹` 2026-10-06 起不在这一
   列里了），再下面是六个读数（上下文 / token / 回合 / 输入 / 输出 / 缓存）。**屏幕第一行**
   是另一条同款页签条：主列的 `对话┆轨迹`（见 ㉙）。空闲时**拼音那一行是暗品红、字形那
   二十二行是亮品红**（块字是图形，不许渐暗）、不换行、不被截断，右端的分隔线（`│`）整列
   完整；**跑起来时它整块变色**，见 ⑯。**这一档专门看两件事**：转弯应当是**四分之一格的
   圆润**、不是整格台阶；以及**一个豆腐块都不能有**（字形用到 U+2596–U+259F，字体缺哪个
   就在那儿显示方框）。
2. 把宽度收到 100 列：左栏变成 28 列、**文字身份**（`heng 0.1.0`，暗灰）替代 mark，
   六个读数还在。收到 79 列：**整栏消失**，转录吃掉全部宽度，状态行与回合条**仍然在**。
2.5 **扫光**（`.scratch/mark-sweep/spec.md` §1–§3）：敲一句会让模型跑起来的话，盯着左栏 ——
   一次运行里那束反光应当从**右下**斜着扫到**左上**（1.8 秒一轮、一直扫），最亮的一段是**白**、
   两侧退回字形的亮品红；运行一结束它立刻停住，空闲时整块一个像素都不动（连颜色都不变，
   可以对着格子看几秒确认）。光带**不该**扫到字形之外的留白格（那里没有字形，看不出变化是对的），
   也不该出现横平竖直的方块边缘 —— 那说明四分之一块没生效。
3. 把高度一步步收到 10 行（`stty rows 10 cols 120`，记得敲一下键触发重画）：先在 31 行看见
   **篆书退回拼音加一个汉字那五行**（页区从 5 行涨回 22 行），再到 11 行左右看见 mark 退成
   文字身份，最后到 10 行连身份行与「缓存」都让位 —— 上下文 / token / 回合
   这三行**最后才消失**（那是底线的三条）。
4. 终端配色是浅色主题时再看一眼：标记只有前景色、没有背景色，所以浅底上应该同样清楚；
   若你在浅色主题下看到标记里出现色块，说明背景色被带上了，是回归。

## ⑪ `/` 菜单

`/` 菜单是键驱动的：它只在按键之后出现、跟着光标走，`scripts/tui-startup-check.py` 只看启动
第一帧和退出时交还的终端状态、看不到它，所以按该脚本 docstring 的口径留在手工面（真终端的
按键、重画与位置在这里验，固定尺寸 buffer 里的框与筛选归 `cargo test`）。

1. 草稿行首敲 `/`：输入区那一行之上浮出一个带边框的菜单，按目录顺序列出内建命令
   （`/undo` `/discuss` `/quit`），每行是 `/<名字>` 加一句说明
   （`/undo` 后面是 `回滚上一次编辑`），再往后是本次会话发现的技能；只敲了一个 `/` 时
   **没有任何一行高亮**。接着敲 `/as`：只剩匹配的名字（大小写不敏感），框随光标右移、
   不盖住刚打进去的字；退格回到更短的前缀，列表跟着重新变宽——普通按键照常编辑草稿，
   菜单不吃键。
2. `↑` `↓` 移高亮：空 `/` 上 `↓` 落到第一行、`↑` 落到最后一行，到两端会绕回。
   高亮行是**反白**的（终端默认前景与背景对调 —— 菜单 2026-10-06 起不再有黄底），和未选中的
   行一眼分得开；光标停在哪一列与高亮哪一行是两回事。
3. `Tab` 只把高亮的完整名字填进草稿（菜单收起，光标停在名字后，能接着打
   `/ask-matt 优化这个`）；`Enter` 填名字**并当场提交**（`/ask` + Enter 是一次手势）。
   真终端上要看见草稿里是补全后的完整名字，而不是半截前缀。
4. `Esc` 收起菜单，草稿原样留着：不会顺手清空输入，也不会弹出 ①.7 的 `清空输入` 覆盖层。
5. 筛到没有匹配（例如 `/zzz`）：菜单整体消失，不是画一个空框、也不是留下上一次的半个
   边框；退格回到有匹配的前缀，菜单原样回来。
6. 画与位置：菜单框四条边完整，浮在转录之上但不压四区块的边框、不盖住输入行、不出屏；
   窄终端下宽度不够时不画说明列（只剩 `/<名字>`），再挤到放不下就干脆不画，**不要**看见
   一个压扁的框。菜单开着**拖窗口**（拖动本身会发 SIGWINCH）：框跟着重画、不撕裂、不留
   残影；要用 `stty` 改尺寸的话记得**改完随便敲一个键**触发重画（`stty` 不发 SIGWINCH，
   TUI 只在「脏」时重画，spec §11），重画后框仍锚在新的光标行上、上下都不出屏。
7. **三类来源一眼分得开**（2026-10-07 补，票 09）：`/` 一开，内建命令的名字是**蓝**的（与草稿
   里打出来的 `/undo` 同色）、技能是**品红**的、MCP 提示词模板（`<server>:<prompt>`）是**青**
   的；描述那一列仍是终端正文档色。走过列表时**高亮那一行不叠这三种颜色**（仍是反白）。
8. **说明文字不再是半句**（同上）：一窗最多 12 行 —— 以前内建命令七条正好占满，技能与模板
   永远看不见；宽度按最长的那条算、上限 96 列，于是宽终端上任意一条的描述整句读得完（`回滚
   上一次编辑` 这种短的照旧窄框）。窄终端上的降级与第 6 条一致。

## ⑫ 折叠提示与详情覆盖层

转录里的「思考」与「工具输出」是折起来的：思考只留一行提示，工具只留调用行，正文都在详情
里。固定的 buffer 能断言文案、颜色与滚动位置（`tests/render_layout.rs`），真终端要验的是
**点击精度、滚动惯性、覆盖层与转录同屏的观感**。

0. **转录不会被抹掉**（最要紧的一条）：跑一个会**思考**的回合（默认就是），等它定格出
   `[执行者] ▸ ✓ 思考完成`，然后看**这行之前**的历史还在不在、中段是不是仍然占满高度、
   `PgUp` 能不能往回翻。曾经有一版会在定格时把整段历史从屏幕上清掉，只在活会话里复现。
   同时确认调用行：跑一条 `bash`，工具**执行完**的瞬间转录里就该有
   `[执行者] ▸ 调用 bash 查看 <路径>`（一开始不画，见票 02 的第二次修正）。
1. 让 agent 跑一个会思考 + 调工具的回合（例如让它跑一条 `bash`）：转录里先出现
   `[执行者] … 正在思考`，正文一开始就**原地变成** `[执行者] ▸ ✓ 思考完成`（不新增一行）；
   工具行是 `[执行者] ▸ 调用 bash 查看 <路径>` 这样的**一句描述**（名字是角色色、描述是灰），
   失败时行尾是 `失败`（红），错误正文与完整命令都只在详情里。
2. 点 `▸` 那行：详情覆盖层**在屏幕上居中**弹出，宽度是 `min(屏幕宽 − 4, 135)`
   （120 列终端上是 116；139 列以上才顶到 135 的天花板）、
   上下各留一行转录可见；**压住左栏与输入区左边那几列**（屏幕居中之后横向盖过左栏、纵向盖到底部输入区，这是「屏幕居中」的应有之义，判断见 ⑳ 第 5 条）；**边框是你点的那一行的说话人的颜色**、边框与文字之间留 1 格；分节横线、
   标题、底部 `↕ n/m · esc 关闭` 都在。工具详情里 `── 参数 ──` 是格式化过的参数，
   `── 输出 ──` 是完整输出（不是转录里那截预览）。
3. 用 `↑` `↓` 与滚轮在详情里走一遍：内容长时底部计数跟着变、不会滚过头；`PgUp` / `PgDn`
   一次翻一屏多一点。`Esc` 关掉；**点覆盖层以外的任何地方也关掉**（原行、转录、左栏、
   状态行、提示行都行）；点覆盖层**里面**不动作。
4. 覆盖层开着的时候让 agent 继续输出（或者点开历史里的行）：转录**停在原处**，新内容不会
   把它抽走；关掉后视图回到原来的位置。
5. `outputs/<tool_call_id>.txt` 手工删掉再点那一行：显示事件里的预览 + `全文不可用`，
   不是空白框、也不崩。
6. 讨论会话（`/discuss`）里同样试一遍：合成器的思考只有增量、没有全文，提示行仍会定格，
   详情里写 `本次未记录思考全文`。

## ⑬ 鼠标作答的边界

1. 有待答问题（权限模态 / 问卷）时，**点轨迹页里的 `▸` 行没有任何反应**（问题拥有指针）。
2. 详情覆盖层打开时，**点它背后的转录没有任何反应**；滚轮滚的是详情，不是转录。
3. `40×10` 这种最小尺寸下：覆盖层只有一行正文、候选键行可能被裁掉一截，**被裁的那截点
   不到**，露出来的部分仍可点；问卷只画一行时只有那一行能点。
4. 终端 resize 之后再点：命中跟着重画后的位置走（旧坐标不该再有效）。

## ⑭ `--continue` 重开

历史重播只有真终端能验观感；重播**内容**的正确性（块与顺序、分隔行、面板与模式、
历史详情的四种文件状态）都在 `cargo test`（`tests/history_replay.rs`），
`scripts/tui-startup-check.py` 的 `--continue` 路径只看**收敛**与**终端交还**。

1. 先在同一个工作区跑一个有两三个回合、至少一条工具调用的会话，退出；再 `--continue`
   进来：启动时底部提示行短暂显示 `恢复历史 n/m`，跑完**自动消失**、恢复普通提示行
   （`ctrl-c/ctrl-d 退出` 在）。
2. 历史铺完后屏幕上是上一段对话：`[角色] ▸ ✓ 思考完成` 与工具调用行都在；历史与本次
   新内容之间有一条 `── 以上为历史 ──`，**启动横幅排在它后面**。
3. 点历史里的 `▸` 行：详情覆盖层与 live 完全一样（边框是说话人的颜色、`Esc` 或点外面
   关闭、`↑` `↓` `PgUp` `PgDn` 与滚轮滚动）。把那个会话目录里的
   `outputs/<tool_call_id>.txt` 手工删掉再点同一行：显示事件里的预览 + `全文不可用`。
4. 重播**没跑完**时上滚 / `PgUp` / `Ctrl-G` / 滚轮：**预期无响应**（吸底）；此时照常
   打字，`Enter` 不提交（草稿留着）。
5. 超大会话（几千条以上事件）的启动手感：进度行看得见、界面不冻结、中途 `Ctrl-C`
   随时退出。
6. 重开一个**升级前**、被杀在计划模式的旧会话（流里还留着 `ContextInjected{PlanMode}` 与
   `HistorySuperseded{ModeChange}`）：它照常打开、历史照常重播（那两行读作「计划模式」/
   「模式变更」），而**状态行**显示的是**这次启动的那一档**（默认 `询问`，`--mode` 可覆盖）——
   档位是组装期的值，历史里的事件不会把它改回去（ADR 0003）。
7. 重开的历史里回合条**已经有格子**（历史是一段段真实回合），焦点落在最后一格。

## ⑮ 外壳改版：左栏 tab、状态行、回合条

这三样是新的，固定尺寸的 buffer 已断言它们**存在、档位与命中矩形**（`tests/render_layout.rs`）；
真终端要验的是**字形对齐、点击手感、焦点随滚动变化的观感**，以及 120 列那一档的提示行读起来够不够。
本轮的实现由 agent 完成、**没有真终端可跑**，所以这一节与 ⑩ 的条目都是**待人工过一遍**的，
不是「已验证」。

1. **tab 点击**：在宽档（≥ 120 列）用鼠标点左栏的 `文件`：标签变成亮品红加粗、`调用量`
   变暗灰，页区换成工作区文件树（这一页自己的走查在 ㉛）；点 `调用量` 换回来。
   点标签**之间的** `│`、点标签右边填充的 `─`：**什么都不发生**（那不是按钮）。
   窄档（< 80 列）没有页签条，自然点不到。
1.5. **主列的页签条**：屏幕第一行是 `对话┆轨迹`。点 `轨迹` 切到轨迹视图（走查在 ㉙），
   点 `对话` 切回来；两个标签之间的 `┆` 与右边的填充不是按钮，点它们什么都不发生。
2. **tab 与弹窗**：故意让权限模态弹出来（跑一条需要授权的命令），再点 `文件`：
   模态**不消失**、页面也不切换（问题拥有指针）；`Esc` / `y` 照常作答，作答后 tab 才能点。
   切到文件页时注意：**屏幕上只剩状态行的 `上下文 n%`** 是会话读数 —— 这是接受的代价，
   不是 bug（`Tab` 键归 `/` 菜单，所以 tab 只能点）。
3. **状态行**：输入区上方那一行是 `模型 X │ 模式 Y │ 上下文 Z%`。把宽度从 160 收到 100、再到
   79、再到 40 列：先丢**模型**、再丢**模式**、最后只剩 `上下文 Z%`，**这一行永远在**
   （不会整行消失）。跑一次真实调用后 `Z%` 应变成实际占比（没有用量时是 `上下文 —`）。
4. **回合条**：跑三四个回合，转录最右一列应该有几格 `┊`，**最新的一格在最下**、并且是亮品红的
   `┃`。往上滚（`PgUp` / 滚轮）：亮格跟着视口往下移 —— 停在某一轮的中间时，亮的应该是**那一轮**
   的格子；滚到最上面时，条的最下面出现 `⋮`（说明下面还有），最上面那格变亮。
   条的右端要贴着外框、不与滚动条打架（滚动条紧挨它左边一列）。
5. **点格跳转**：点某一格，视口**顶端对齐**跳到那一轮**你自己敲的那句**（`[用户] …`）——
   不是协议行、也不是「回合开始」；点最新那一格时看起来「没动静」是**预期**（它本来就到底了）。
   跳转之后再滚动，条上的亮格应立刻跟着新位置走，不残留。
6. **120 列那一档的提示行**：`120×24` 空闲时提示行是 `enter 发送 · ctrl-j 换行 · esc 取消 ·
   shift+tab 模式 · ctrl-c/ctrl-d 退出`（**四条 + 退出，放不下 `就绪`**）。这是**预期值**：
   左栏吃掉 40 列后主列只有 77 列，比 80 列的终端还窄。读起来是否够用请如实记下来 ——
   若觉得别扭，那是左栏宽档的取舍要重新议，不是提示行的 bug。
7. **左栏与转录的宽度账**：宽档下转录右缘恒留两列（滚动条 + 回合条），文本宽度是
   `主列宽 − 2`；把窗口从 160 收到 120 再收到 80，文本宽度应跟着档位跳（主列 117 → 77 → 49），
   而不是被"挤"出半格。

## ⑯ 输入区的几何、就绪时的静止与左栏

输入区的三行地板、「mark 不动」、就绪时状态字形定在满月，都由固定尺寸的 `TestBackend` 断言过
（`tests/render_layout.rs` + `src/render/tui.rs` 的单元测试）。真终端要验的是**光标落点**、
**运行中的观感**与**那几个 Emoji 字形在所用字体里的宽窄**。

1. **三行地板**：空草稿时输入区就是 3 行 —— 第 1 行就是草稿本身（**没有前导字形**：提示符
   `❱ ` 于 2026-10-08 退场，`.scratch/ui-trim/spec.md`），下面两行是空的，提示行仍在它下面
   一行、`Ctrl-J` 换行后**几何不动**（转录的行数不跳）。写到第 4 行才看见框长高，第 10 行封顶。
2. **光标**：在第 1、2、3 行各敲几个字，光标应始终跟在最后一个字符后面、停留在**那一行**；
   在两行之间用 `↑` `↓` 走，别让它跑到留白的行上或者溜出输入区。
3. **40×10 的地板**：把窗口收到 40×10（记得敲一下键触发重画）：输入区仍是 **3** 行
   （`MIN_INPUT_ROWS` 的地板，不随窗口缩）、转录只剩 **1** 行 —— 这是**预期**，转录的最后一行
   比输入区的最小高度优先。
4. **就绪时状态行那一格不动**：等你打字时，状态词前面那个字形应当定在 `🌕` 上，怎么等都不换。
   按 `Enter` 发一个回合：**这时**它才开始走月相（每 2 帧一格、约 0.96 秒一轮，相位**倒着**走
   `🌘 → 🌗 → 🌖 → 🌕 → 🌔 → 🌓 → 🌒 → 🌑`）。回合结束、键盘回到你手上时它**回到满月并
   停住**。判断标准是「空闲时一格都不许动」—— 它若还在转，说明 `status_spinner` 的空闲分支
   丢了，是回归。
5. **输入区没有前导**：第一列就是草稿的第一个字，软换行之后每一行也顶格（原来那两列缩进随
   提示符一起没了）。打字、`←` 走光标、`Ctrl-J` 换行，光标都该落在你数得出来的那一格上。
6. **左栏完全静止**：跑一个回合，左栏的 mark（宽档那条 `heng` 字符画）与窄档的身份行
   `heng 0.1.0` 都应当**一动不动** —— 下落短横与那圈色相环两套代码都已删（§34 与
   `.scratch/ui-trim/spec.md`），只有忙时那束扫光会经过它。如果看到短横在落、在转、或者整块
   变色，那是有人把它接回去了。
7. **60ms 的节拍不该被饿死**：让 agent 跑一个会疯狂输出的命令（比如 `yes` 那种要被截断的
   输出），再看状态行那个字形：**它应当照样在走**。如果输出越猛它越不动，说明脉冲那条臂被
   饿死了（实现上脉冲走的是 `interval` 而不是每轮重建的 `sleep`，正是为了这条）。
8. **空闲的代价**：空闲时那台时钟**一直在走**（光标闪烁与那几条回执的寿命挂在上面），所以它
   每 60ms 醒一次、重画需要重画的那几格。`top` / `htop` 里空闲的 heng 应当只占很小一角；
   一个核被吃满说明某处每帧都在全量重绘。
9. **切进忙碌 / 回合结束时不跳**：按 `Enter` 之后那个字形从满月开始走，跑的过程里连续换格；
   回合结束时它回到满月 —— 那是**有意的**一次切换，意思是「轮到你了」。如果它在回合中间莫名
   回零，那是计数器归零的时机出了问题（它应当**只在运行结束时**归零）。

## ⑰ 模式循环与 `todo` 标签

这两样都是这一轮新加的，固定尺寸的 buffer 已经把状态行的文案、标签的进退、页内容与命中
矩形断言过（`tests/render_layout.rs`、`tests/modes.rs`）；真终端要验的是**按键手感**、
**字形**与**28 格宽度下读起来够不够**。

1. **`Shift+Tab` 循环四档**：空闲会话起步在 `询问`（`[permissions] mode` 的默认档），所以按
   `Shift+Tab` 时状态行的 `模式 …` 依次变成 `工作区` → `自动` → `只读` → `询问`（四下回到起点；
   若启动时写了 `--mode readonly`，起点就是 `只读`）。顺序是**严格度**，所以按一次总是松一档。
   **不再有任何计划模式的弹窗、提示或 `/plan` 命令** —— 如果按下去弹出一个问「覆盖 / 追加 /
   保留」的框，那是没删干净。
2. **档位真的生效**：切到 `只读`，让模型写一个文件（或跑一条会写东西的命令）：它应当被拒，
   动作不执行，拒绝理由里写着 `mode readonly`（`sessions show` 里看 `PermissionDecided.reason`）。
   再按一下 `Shift+Tab` 到 `询问`，同一个动作再试：这次会弹权限模态。
3. **`todo` 标签的出现**：新会话里左栏只有 `调用量` / `文件`（`轨迹` 在主列那条页签条上）。让模型干一件会立待办的
   活（例如「把这个仓库里某个文件改一下」）：第一条非空 `todo` 调用落地后，`todo` 标签**插到
   `调用量` 右边**。点它，页上应是一行一项（`☐` / `▸` / `✓` + 内容）加最后一行 `已完成 n/m`。
4. **常驻**：让模型把清单全部标完、甚至清空（`items: []`）：标签**仍然在**，页上只剩
   `已完成 0/0`。这是用户选的语义（一旦出现就不再消失），**不是 bug**。
5. **`＋N 项` 在窄档**：把窗口收到 80–119 列（左栏 28 格），让清单长到十几项：页上应只画得下
   几行，计数行**上面**那一行写 `＋N 项`。读一下这个数字与那几行的截断是否清楚 —— 28 格下
   一项内容大约 24 格，看不清就如实记下来（那是要重新议的取舍，不是 bug）。
6. **执行者的清单不上左栏**：让模型派一个执行者去做会立待办的活（`task` 一段多步的 brief）：
   执行者的 `todo` 调用在转录里各占一行，而左栏的 `todo` 标签**不动**（如果会话此前没有
   主会话的清单，它甚至**不该出现**）。
7. **旧会话**：`--continue` 一个升级前的老会话（流里有 `PlanMode` 注入）：`todo` 标签**不该**
   因为历史而出现（历史里没有 `todo` 调用），状态行照旧显示这次启动的档位。

## ⑱ 沙箱：内核真的拦住了

前两层（`wrap()` 的逐字断言、`tests/sandbox.rs` 的集成与那条真机测试）覆盖得到的东西不在
这里。这一节记的是 **2026-10-01 在一台 Linux 机器上逐条跑过的原文与结论**（bubblewrap
0.13.0，非特权用户 uid 1000）。跑的是 `wrap()` 拼出来的那条 argv —— 它的逐字形状由
`tests/sandbox.rs` 钉住，所以手工命令与 heng 真正会跑的东西是同一条。这台开发机**没有
provider key**，所以「经由 `bash` 工具」的整条链路由 `tests/sandbox.rs` 的端到端测试覆盖
（`PATH` 上放一个假 `bwrap`，断言它真的被 spawn、原命令落在 `--` 之后、不可用时是工具错误），
而**内核行为**在这里。

准备：工作区取 `W=$(mktemp -d)`（注意它在 `/tmp` 下 —— 这恰好是第 3 条要验的那件事），可写根
取 `C=$(mktemp -d)`，然后按「整机只读 + 私有 `/tmp` + 工作区与缓存可写 + 四个 unshare」那条
前缀跑。下面每一条都是先做、后记原文。

1. **写工作区**：新建一个文件、再把它删掉，都成功，宿主上读得回内容。这是「工作区内的修改
   照常」那条用户故事，也是沙箱**不该**挡住的唯一一类写。
2. **写 `$HOME`、写 `/etc`** → 都被拒，原文里带「只读文件系统」，退出码 1。回到宿主侧确认那
   两个文件都没出现 —— 拒绝不只是屏幕上的一个字，落盘也没有发生。
3. **工作区在 `/tmp` 下**（本清单第 3 条为什么存在）：一开始按 spec 的字面顺序把私有 `/tmp`
   排在可写根之后，结果连工作区里写自己的文件都报「只读文件系统」—— 挂载是叠上去的，后挂的
   tmpfs 把那条 `--bind` 盖掉了。实现改成「私有 `/tmp` 在所有可写根之前」，重跑第 1 条通过。
   **顺序是行为，不是风格**。
4. **`/tmp` 的语义**：同一条命令里建一个目录再列它，成功；**下一条命令**再列同一个路径，报
   「没有那个文件或目录」。与 `bash` 工具描述里那句「每次调用都是新的」一致。
5. **遮住 provider key 那一格**（那台机器上配置文件真实存在、两千多字节）：沙箱里读它报
   「没有那个文件或目录」，列目录得到 **0 个条目**（是「目录还在、但是空的」），往它里面写报
   「只读文件系统」。也就是说这不是「藏起来」，而是一个空的只读挂载。
6. **遮住 `~/.ssh`**（宿主上真实有 agent、authorized_keys、config 三样）：沙箱里列目录同样是
   **0 个条目**，读私钥报「没有那个文件或目录」。
7. **工作区里的 `.env`**：往里追加报「只读文件系统」；换 `.env.example` 追加则成功 —— 模板
   后缀不携带真密钥，不在保护之列，两条都要看到。
8. **`git` 的读写**：`status`、`add`、`commit`、`log` 全部正常，两次提交都在历史里。
   `git config user.name hack` 被拒，报的是「无法写入配置文件 .git/config: 设备或资源忙」；
   写 `.git/hooks/pre-commit` 被拒，报的是「只读文件系统」。两处的措辞不同这一点值得记住：
   **拒绝消息从来不是判据**，判据只有 `bwrap: ` 前缀一条。提交能跑的原因也很具体：
   `.git/index` 没有被压回只读，被压住的只有 `config` 与 `hooks` 两个入口。
9. **可写根**：往缓存目录里 touch 一个文件，成功，宿主上确实看得到它。这台开发机的 `$HOME`
   本身处在一个只读挂载里，所以「写 `~/.cargo`」在**这个环境**里验不了 —— 换 `/tmp` 下的一个
   目录代替，`--bind` 的语义完全相同。整条 `cargo test` 没在沙箱里跑（要联网拉依赖），可写根
   本身由这一步验。
10. **探测**：用规格里那条最小 profile 跑 `/bin/true`，退出码 0，说明这台机器上可用。注意它比
    spec §3 的原文多带一个 `--proc /proc`：§3 的另一条要求是「`/proc` 建不起来也算不可用」，
    两条要一起满足。

**没验到的，如实记在这里**：这台机器没有 provider key，所以下面两条只由 `tests/sandbox.rs`
的端到端测试覆盖（假 `bwrap`），**没有**在真会话里手工跑过：

- 「把 `PATH` 上的 `bwrap` 拿掉再起一次 → `bash` 拒绝运行、文案给出两条出路」；
- 「把 `[sandbox] mode` 设成 `"off"` → 照旧直接跑」。

它们的内核那一半（真 bwrap 起来、真拦住区外写）由 `tests/sandbox.rs` 的
`the_real_bubblewrap_keeps_writes_inside_the_workspace` 在有 `bwrap` 的机器上每次 `cargo test`
都真跑一遍。

## ⑲ `workspace` 档与升级手势

纯函数那一层由 `tests/permission_gate.rs` 钉住（四档 × 方向 × 升级的矩阵），端到端那一层由
`tests/workspace_mode.rs`（文件工具的区外写、组装期拒绝）与 `tests/sandbox.rs`（假 `bwrap`
下的升级全链路：被拒 → 带 `escalation` 重试 → 弹一次问 → 批准后 argv 里多一条 `--bind`）
覆盖。真终端要验的是**手感**、**弹窗读起来够不够**、以及真内核下那条出口确实通。

前置：这台机器上 `bwrap` 可用（第 ⑱ 节的那条探测通过），工作区取一个可写的临时目录，
`[permissions] mode = "workspace"`，并在 `$HOME` 下准备一个**不存在**的目标目录
（例如 `~/.npm`）—— 升级要验的正是「建它」。

1. **区内一路放行**：让模型在会话工作区里 `touch a.txt`、`cargo test`、`git commit` 各来一次：
   一次都不该弹窗。这一档存在的意义就是这一步。
2. **区外写弹一次问**：让模型 `bash -lc "touch ~/x"`（或写一个 `~/.npm/...` 的文件）。第一条
   命令应当**失败**（内核说只读文件系统），而这是**命令结果**、不是工具错误 —— 转录里照常
   显示退出码与 stderr。
3. **升级弹窗那几行**：模型带上 `escalation` 重试同一条命令时，弹窗除问题行与命令行之外还应有三行：
   `被沙箱拒绝，申请写工作区之外`、`理由：…`、`要放开的路径：…`，而**命令行仍是最后一行**。执行者发起的询问，第一行要点名
   `执行者 <id> 发起`；讨论者发起的写 `讨论者 <id> 发起`。
4. **批准之后真的通**：点 `[y] 允许`，同一条命令成功，**宿主上真的出现那个文件**
   （`ls -l ~/.npm/probe`）。再让模型跑**另一条**越界命令：它应当照旧被拒 —— 批准只活在那一次
   调用里。顺便试一次**声明一条不存在的路径**（例如 `~/.npm/newdir`）：结果应当是一条写明
   「路径不存在」的工具错误，而不是一条什么都没发生的成功 —— `bwrap` 只能绑已经存在的源。
5. **只给一次重试**：对同一条被拒的命令连着来两次带 `escalation` 的重试：第一次弹窗，拒绝之后
   第二次**不再弹**，命令照常失败。模型该换做法或报告受阻。
6. **写死的边界批不了**：让模型申请 `~/.ssh/authorized_keys`：**不问**，直接拒，理由里写着
   「这一条没有任何通道放宽」；工作区里的 `.env` 与 `.git/config` 同理。三个都试一遍。
7. **`outside_read` 三个值**：在 `[permissions] mode = "ask"`（或 `workspace`）下分别配
   `outside_read = "deny" | "ask" | "allow"`，让模型读一个工作区之外的普通文件
   （**别拿 `~/.config/heng/config.toml` 当第一个探针** —— 那一条会连带验打码）：
   `deny` 时不问直接拒；`ask` 时弹一次问；`allow` 时不问、读得到。
8. **没有沙箱就没有这一档**：把 `[sandbox] mode` 改成 `"off"`（或者把 `bwrap` 从 `PATH` 上
   拿掉），再以 `--mode workspace` 启动：**启动错误**，stderr 上写着这一档需要沙箱，并给出
   两条出路（换回 `"bwrap"`、或换一档）。退出码非零。同一份配置换成 `--mode ask` 启动，
   再按 `Shift+Tab`：`工作区` 那一档应当被**跳过**（`询问` → `自动`），循环里进不去它。
9. **状态行照旧**：这一档下状态行显示 `模式 工作区`；沙箱状态有它自己那一行（转录里的叙述、
   `sessions show` 里那一行），这里不重复。

## ⑳ 外壳收干净：没有外框、虚线框架、详情居中与按位置滚动

这一轮（[`.scratch/tui-chrome/spec.md`](../.scratch/tui-chrome/spec.md)）给外壳做了减法：
四周不再有边框、状态行上方那条线也不画了、剩下的框架全换成**更沉的虚线**、详情覆盖层改成
**屏幕居中**、问题立着时**滚轮按指针位置分派**。几何与字形的纯函数那一层由
`tests/render_layout.rs` 钉住（118 条用例）；真终端要验的是**读起来舒不舒服**、
**虚线分不分得清**、以及那个随配色而变的深度。

前置：120×24 的终端，一个能写文件的会话（要看到转录、状态行与输入区同时在屏上）。

1. **四边没有框线**：转录从终端第 0 行开始、左栏从第 0 列开始，最外一圈再没有一条线。
   左栏与主列之间仍然有一条竖虚线，两栏还分得开。
2. **状态行上方那条线不在**：转录的最后一行紧贴着状态行，两者之间没有横线；输入区上方
   与提示行上方那两条横线还在（一共两条，不是三条）。
3. **三层虚线分得清**：竖分隔线 `┆`（三重）、两条横线 `┄`（三重），而**回合条**的普通格仍是
   `┊`（四重）、焦点格是 `┃`。三者同屏时不该糊成一样。
4. **`CHROME_LINE` 的深度**：`src/render/tui.rs` 的
   `CHROME_LINE = Color::Rgb(0x4a, 0x4a, 0x4a)` 是照「框架退到内容后面」取的。**你自己的
   终端背景色**下它是否还看得见、是否仍然偏亮，只有你看得出来 —— 不合适就改那一个常量，
   并把实测值记在这里。（这是本轮唯一一个随终端配色而变的取值。）
5. **详情覆盖层屏幕居中**：点一个工具调用那一行，打开它的详情。框应当在**屏幕**正中而不是
   偏右；它现在压着左栏，也压住输入区左边那几列 —— 这是「屏幕居中」的代价，看一眼能不能
   接受。
6. **问卷立着时的滚动**：让模型发一个 `ask_user_question`。鼠标放在**转录**上滚 → 转录滚动，
   选项高亮不动；鼠标放在**问卷**（底部那块）上滚 → 高亮走，转录不动；而键盘已经在**输入区**
   时滚轮静默（那里没有可滚动的位置）。
7. **权限模态立着时的滚动**：弹一次权限询问。指针在**模态之外**（比如左栏那一列）滚 → 它
   背后的转录滚动；指针在**模态之内**滚 → 什么都不动（模态没有可滚的内容）。
8. **40×10 那一档**：把终端缩到 40×10。转录 3 行、输入区 3 行、提示行在第 9 行 —— 外框与
   状态行上方那条线让出来的那三行都归了内容，读一眼确认它仍然能用。
9. **左栏顶上那一行空行**：标记（宽档）或 `heng 0.1.0`（窄档）从第 1 行开始，第 0 行只有
   那条竖虚线；页签条与读数页也跟着下移了一行（2026-10-01 真机反馈）。
10. **竖线贯通**：状态行、输入区、提示行左边那一列的 `┆` 与上下其它行连成**连续的一列**；
    输入区上方与提示行上方那两条横线接在它**右边**（`┆┄┄┄…`），不再把它截断。

## ㉑ 转录里的 Markdown：表格、代码块高亮与续行顶格

这一轮（[`.scratch/markdown-render/spec.md`](../.scratch/markdown-render/spec.md)）把 Markdown 的
**解析**交给 `pulldown-cmark`（[ADR 0008](adr/0008-markdown-parsing-by-pulldown-cmark.md)），
渲染仍是自己的：表格从「join 竖线」变成真网格、代码块接回 tree-sitter 高亮并扩到十种语言、
assistant 的续行不再缩进。几何与结构由 `tests/render_markdown.rs` 与 `tests/render_layout.rs`
钉住；真终端要验的是**语法高亮与 CJK 折行的组合**——那只有真终端看得出来。

前置：120×24 的终端，一个能写文件的会话，让模型吐几段带结构的回答（也可以直接把下面
几段贴给自己看：`heng` 里用户输入不走 Markdown，所以要看**回答**）。

1. **表格装得下**：让模型吐一张 3–4 列的表。表头是粗的、下面有一条 `─┼─` 分隔线，各列
   沿着竖直方向对得齐，表格顶格、**撑满转录的宽度**（余量在最后一列）。
2. **表格装不下**：把终端拉窄到 80 列以下再来一次。装不下的格子应当**折行**（不是截断），
   同一行的其它格一起撑到同样的高度，网格的竖线在每条续行上都连着。
3. **代码块的语言名**：贴一段 ```rust。块**上方**单独一行，语言名**右对齐到转录的右缘**，
   那一行不缩进；代码**两格缩进**，`**不是粗体**` 这类字面量原样保留。
4. **语法高亮分得开**：同一段 Rust 里关键字、字符串、注释的颜色要分得开；再让模型给一段
   超宽代码行，折出来的**续行仍以两格缩进开头**（不是顶到最左边）。
5. **十种语言各看一眼**：`rust` / `bash` / `json` / `toml` / `html` / `javascript` /
   `typescript` / `php` / `sql` / `python` 各来一个最小样例（比如 `struct A;`、`echo $HOME`、
   `{"a": 1}`、`a = 1`、`<p>x</p>`、`const a = 1`、`const a: number = 1`、`<?php echo 1;`、
   `SELECT 1 FROM t`、`def f(): pass`）。十种都该有**非默认色**的片段；认不出的语言
   （比如 `brainfuck`）该**照原文显示语言名**、代码退纯文本，而不是消失。
6. **图片语法**：让模型写一句 `![图](https://example.com/a.png)`。屏幕上是
   `[图片] 图 (https://example.com/a.png)`，而不是旧的 `!图 (…)`。
7. **assistant 的续行顶格**：问一句会写出多行的回答。除第一行那个 `[name] ` 之外，每一行都
   从**最左边**起（不再是 11 格缩进）；而自己用 `Ctrl-J` 敲一条多行消息时，续行**仍然**按
   `[name] ` 的显示宽度对齐缩进。
8. **拖动宽度时表格不碎**：让一张表停在屏上，然后**慢慢拖动终端宽度**。表格应当跟着按新
   宽度重排（列仍然对齐、该折的折），而不是留着一份按旧宽度排好的行、被硬折成一堆错位的列。

## ㉒ 目标循环：禁言、`Esc` 确认框与翻页那一刻

这一轮（[`.scratch/goal-loop/spec.md`](../.scratch/goal-loop/spec.md)）给无人值守的目标循环
定了人机边界：跑着的时候输入区禁言（§5），`Esc` 先问一句再决定停不停（§5），而上下文过八成
时压缩 + 翻页（§7）。几何与状态由 `tests/render_layout.rs`、`tests/goal_loop.rs` 与本文件
里 tui 的那几条单测钉住；真终端要验的是**手感**。

前置：`workspace` 或 `auto` 档（`ask` 档下 `/loop` 会拒绝启动，这正是 §5 那条前提），先
`/goal-new <名字> <来源>` 生成一份清单，然后 `/loop <名字>`。

1. **输入区禁言**：循环跑着的时候随便打字。字符**不落进**草稿，草稿与输入区都不动；方向键、
   `PgUp`/`PgDn` 与 `Shift+Tab` 照旧响应（转录能滚、模式能换）。
2. **`Esc` 默认停在「继续跑」**：按一下 `Esc`，中段立起那个确认框，两个答案里「继续跑」在前。
   直接按 `Enter`、或者再按一次 `Esc` —— 框关掉，循环**照常在跑**（转录还在往下走）。
3. **明确停下**：再按一次 `Esc`，这回按 `s`。循环停下，转录里出现「目标 … 被主动停下」那一
   行，而流上落了一条 `GoalStopped { reason: user_stopped }`（`sessions show` 看得到）。
4. **停完回空闲**：停下之后状态行那个字形回到满月并停住、pulse 归零，`/quit`、`/undo` 这些照常能用，
   而 `/loop` 再跑同一个目标时，进度从流派生出来（已完成的那几条还在）。
5. **翻页那一刻的观感**：让它跑到过八成（长活最容易，或者把 `[goals] compact_at` 临时调低）。
   翻页那一刻：转录里出现「历史压成摘要：会话 … → 会话 …」这一行，新的 `SessionStarted`
   跟着落下来，侧栏的进度接着走 —— **不能看起来像崩了**。`sessions` 里旧的会话仍在，
   `--continue` 打开的是新的那个。
6. **过半提醒只来一次**：过 50% 时转录里出现「上下文已到 …%，已提醒模型把还没落流的东西落
   下来」。此后连续几个回合都在 50% 以上，这一行**不再重复**（每轮注入会每轮打掉前缀缓存）。

## ㉓ 终端标题：内容、更新与还原

这一轮（[`.scratch/terminal-title/spec.md`](../.scratch/terminal-title/spec.md)）让跑着
heng 的那一格终端说得出自己在哪个目录、在不在跑。能自动化的那两条腿已经钉住：拼法与
40 列封顶在 `tests/wording.rs`，状态与目标名的来去在 `tests/render_tui.rs`，「我们发出了
哪些序列」在 `scripts/tui-startup-check.py`（保存 `CSI 22 t`、写入 `OSC 0`、还原 `CSI 23 t`）。
剩下这一半只有真终端答得了：**标题看起来对不对、退不退出得回来**。

前置：`cargo build`，`cd` 进一个基名认得出的目录（仓库根就够），跑
`./target/debug/heng`。要验状态变化的那几条得能触发一次权限询问、或者让一回合跑起来。

1. **内容**：跑起来看标题。路径段是工作目录的形态 —— 落在 `$HOME` 之下时写 `~/…`
   （`~/code/fortystory/heng`），别处写 `父目录/基名`；空闲时**没有**状态词。用
   `--cwd /别的/目录` 起来，路径段跟着那个目录走。
2. **更新**：让一回合跑起来（问一句话），标题里出现 `运行中`；出现权限询问或问卷时变成
   `等你`；`--continue` 重放期间是 `重放中`，重放收敛后回到空闲那条。`/loop <名字>` 跑着时
   目标名跟在后面（`… · 运行中 · <目标名>`），`/loop` 停下后它消失。
3. **不闪**：一次长回合里盯着标题。它只在状态或目标变时写一次，**不随增量文本翻动**。
4. **还原**：进 TUI 之前先用终端自己的办法给这一格设一条标题（例如
   `printf '\e]0;原来的标题\a'`），然后跑 heng、退出（空闲时双击 `Ctrl-C`、`/quit`
   各一次）。退出之后标题应当回到那一条；`--continue` 退出也一样。
5. **三种终端各走一遍**：`xterm`、`tmux`（窗格里的 TUI）、一个 VTE 系（`gnome-terminal` /
   `Tilix` / `xfce4-terminal` 任一），每一处都做第 1–4 条。
6. **tmux 的 `allow-passthrough`**：`tmux set -g allow-passthrough off` 与 `on` 各走一遍
   第 1–4 条，两种结果都如实记下来（开 / 关各自是更新、还原，还是没动）。
7. **不支持的终端如实记**：某个终端上如果保存 / 还原是 no-op、退出后标题停在我们写的那条，
   就在这里点名记下来 —— 这是**接受**的退化，不加 fallback、也不补发「清空标题」（那会把
   用户原本的标题抹掉，比不还原更糟，spec §4）。

## ㉔ 挂起：`Ctrl-Z` 停到后台、`fg` 回来还在这块画面上

这一轮（[`.scratch/suspend-gesture/spec.md`](../.scratch/suspend-gesture/spec.md)）让 TUI 里
按一下 `Ctrl-Z` 就把整个进程停到后台。能自动化的两条腿都钉住了：手势与状态机在
`tests/render_tui.rs`，「真的停住 + 停之前终端已交还 + 回来重进重绘 + 出口干净」在
`scripts/tui-startup-check.py` 的挂起两轮（TUI 与 `--plain`）。剩下这一半只有真终端答得了：
**画面回来之后对不对、标题回不回来**。

前置：`cargo build`，跑 `./target/debug/heng`。

1. **空闲挂起**：按一下 `Ctrl-Z`。shell 提示符立刻回来、打一行 `Stopped`，屏幕上是挂起前的
   shell 历史 —— **不是**一屏 TUI 残影，而且终端不是 raw 模式（能正常打字、回显，`Ctrl-C`
   有反应）。`fg` 回来：画面重新画出来，转录的滚动位置与未发送的草稿都在，标题回到
   `… · <状态>`。
2. **忙碌挂起**：问一句话让它跑起来，跑到一半按 `Ctrl-Z`。`fg` 回来后回合还在跑（或者按
   第 3 条那样以它自己的错误收尾）—— 界面不能卡死、不能留下半截的工具块。
3. **挂久了会超时**：跑一条长命令（`sleep 200` 那种），挂起它、在 shell 里等过这条命令的
   超时，再 `fg`。预期是那一回合以命令超时收尾、错误走现有的呈现 —— 这是**接受**的取舍
   （spec §6），不是缺陷。
4. **窗口尺寸变过**：挂起后在 shell 里把窗口拉窄再拉宽，然后 `fg`。画面按新尺寸重排，没有
   残影、没有错位的分隔线。
5. **plain 也照旧**：`./target/debug/heng --plain` 里按 `Ctrl-Z` —— 同样停到后台，
   `fg` 回来还能继续输入。它走的不是应用的手势，而是终端驱动那条路。
6. **三种终端各走一遍**：`xterm`、`tmux`（窗格里的 TUI）、一个 VTE 系（`gnome-terminal` /
   `Tilix` / `xfce4-terminal` 任一）。**tmux 这一格要如实记**：它自己也可能对 `Ctrl-Z` 有
   想法，按下去到底是谁处理的、`fg` 还能不能回到 TUI，照实写下来。

这一节真正要看的不是「按下有没有反应」，而是**交还与停止的先后**：终端必须在进程停下之前
就已经还回去。顺序反了的话，你回到 shell 时面对的是一屏还停在备用屏幕上的残影，连 `fg`
都未必打得出来 —— 那种状态一眼就该认出来，而不是被记成「手感有点怪」。

## ㉕ 问卷：区域、折行与两把举手

这一轮（[`.scratch/questionnaire-keys/spec.md`](../.scratch/questionnaire-keys/spec.md)）把问卷的
键盘分成**选项区**与**输入区**、给选项加了 `j`/`k` 与 Emacs 的 `Ctrl-N`/`Ctrl-P`、让长选项
折行，并把 `Esc` 改成「退出这次询问」。状态机与帧断言在 `tests/ask_user_question_tui.rs` 与
`tests/render_layout.rs`；剩下这一半只有真终端答得了：**区域高亮对不对、折行之后光标在不在
该在的地方、那两句回执看不看得见**。

前置：`cargo build`，跑 `./target/debug/heng`，让模型发起一次问卷
（例如「用 `ask_user_question` 问我一个问题」，或者自己写一条带选项的提示）。

1. **区域分派**：问卷打开时先别打字 —— 敲 `j`/`k`（以及 Emacs 那两个别名键 `Ctrl-N`/`Ctrl-P`）
   看高亮在选项间移动；在选项区敲一个字母，屏幕上**不该**多出字符，那一行也不该出现光标。
2. **进输入区**：一直敲 `j` 直到越过最后一项，键盘落进「自定义：」那一行（光标出现、那一行
   变亮，而选项高亮**降暗**、不再反显）；这时 `j`/`k` 就是普通文本，刚才那两个别名键则什么
   都不做 —— 它们在这里既不是移动、也不落字符。
3. **回选项区**：`↑`/`↓` 从输入区回来并移动高亮；`Esc` 也回选项区，而且**已经打的字不清**。
4. **自由文本行的光标**：在输入区一路打字，光标跟着最后一个字符走；打到超过一行宽度时它
   跟着折行走到**下一行的末尾**，不跑到行外去、也不留在第一行。没有选项的题上按一下 `Esc`
   之后仍然打得进字（那条路不该把它推向一个不存在的选项区）。
5. **折行**：让模型给一个很长的选项。它应该折成多行、续行对齐在标记后面，而不是被截断；
   高亮落在它上面时**整块**都在窗口里。输入区自己打很长也一样 —— 续行看得见，页脚不被挤掉。
6. **页脚降级**：把窗口拉窄，看页脚先丢掉 Emacs 那对别名、再砍到只剩「`esc` 退出询问」
   那一句，而页码与能点的按钮一直在（按钮跟着可用性增删，所以没作答完时本来就没有「提交」）。
7. **两把举手**：选项区按一下 `Esc`，页脚说「再按一次 esc 退出询问」；半秒内再按一下，
   问卷收起、**模型继续跑**（不是这次运行被取消）。`Ctrl-C` 的第一下仍然取消这次运行，
   而页脚这次说得出「已取消 · 再按一次 ctrl-c 退出」—— 这句话在这一轮之前是看不见的。
8. **三种终端各走一遍**：`xterm`、`tmux`（窗格里的 TUI）、一个 VTE 系（`gnome-terminal` /
   `Tilix` / `xfce4-terminal` 任一）。折行、光标位置与页脚降级在这三处的差异照实记下来。
9. **超长题面**：让模型发一道题面很长的题（例如「把这段二十行的分析原样放进 `question`」）。
   底部区里应当先看见题面的开头、一行 `…（题面还有 N 行未显示）`，然后是编号的选项与
   「自定义：」那一行 —— 而不是只剩半截题面、选项一个不见。窗口高一点（40 行上下）时那行
   说明应当消失，整段题面都放得下。这一条以前是真的丢过选项
   （[`.scratch/questionnaire-keys/spec.md`](../.scratch/questionnaire-keys/spec.md) §7 的补记）。
10. **问卷立着时的指针**：让问卷立着，点主列页签条上的 `轨迹` —— 应当翻得过去，而问卷还留在
    底部、按 `j`/`k` 仍能挪选项的高亮；再点左栏的 `文件` 页签 —— 也翻得过去，但键盘**没有**
    交给文件页（`j` 仍是问卷的键），也没有弹出任何详情覆盖层。这一条以前是坏的：问卷把每一次
    点击都吃掉了（[`.scratch/questionnaire-keys/spec.md`](../.scratch/questionnaire-keys/spec.md)
    §7 的补记）。
11. **该拍板时会不会弹问卷**：给模型一件「你必须先选一条路才能往下做」的活，看它是把问题写进
    回答正文，还是调 `ask_user_question` 把问卷摆出来。主会话身份里有一句正面引导
    （[`ASK_GUIDANCE`](../src/agent.rs)，2026-10-08 加，见
    [`.scratch/ask-guidance/seed.md`](../.scratch/ask-guidance/seed.md)），这一条就是它的真机
    效果账；顺手记一句它有没有往「什么小事都弹问卷」那边漂。

这一节真正要看的是**区域分派的边界**：`j`/`k` 在选项区是移动、进了输入区就是文本，而
选项区的字符一律被吞掉。手感上最容易错认的是「打字没反应」——那是设计，不是卡了。

## ㉖ 左栏开关：`Ctrl-O` 收起与叫回

这一轮（[`.scratch/sidebar-toggle/spec.md`](../.scratch/sidebar-toggle/spec.md)）给左栏加了一个键：
`Ctrl-O` 收起、再按叫回。行为断言在 `tests/render_layout.rs`（收起后的几何、页签命中、窄档
无效、busy 与覆盖层两处守卫）与 `tests/wording.rs`（提示行的档位）；剩下这一半只有真终端
答得了：**那 41 列换来的东西值不值、提示行最末那条在你自己的窗口里出不出现**。

前置：`cargo build`，跑 `./target/debug/heng`，窗口至少 120 列。

1. **收起与叫回**：按 `Ctrl-O`。左栏（标记、页签条、读数）连同那条竖分隔线**整列**消失，
   转录立刻拿到那 41 列 —— 长行会重排一次。再按一下左栏原样回来，**选中的页签与它的内容
   还在**（收起过不该把页签重置回 `调用量`）。
2. **窄档**：把窗口拉到 80–119 列（左栏 28 列那一档）。收起与叫回都该正常；这一档换回来的
   29 列读起来值不值，照实记。
3. **窄到看不见左栏**：缩到 79 列以下。这时按 `Ctrl-O` **什么都不该发生**——没有报错、没有
   文案、画面一个像素都不动。这是设计：宽度是可行性，意愿是偏好。
4. **跑着的时候**：让模型跑一个长回合（例如「跑 `cargo test` 并把输出讲给我」），在它跑的
   时候按 `Ctrl-O`。它照样管用（纯视图手势）。收起期间按回来，`调用量` 的数字应当是接着走
   的，不是从零重来。
5. **详情覆盖层立着时**：点开一条 `▸ 调用 …` 的详情，再按 `Ctrl-O` ——**没反应**（覆盖层
   独占键盘）；`Esc` 关掉它之后才恢复。
6. **提示行**：看提示行最末有没有 `ctrl-o 左栏`。它排在最末，所以窄窗口看不见它 —— 记下你
   自己常用宽度下它出不出现，那正是这条提示的可发现性边界。
7. **`todo` 页签**：让模型调一次 `todo`（「用 `todo` 工具列三步」）。列表落地时左栏**不该
   自己弹回来**；按 `Ctrl-O` 叫回来时 `todo` 页签应当在、页内容也在。

这一节真正要看的是**那 41 列换来的东西值不值**：收起之后的阅读舒适度，以及想叫回来时那个
键在不在手边。

## ㉗ 问卷的回车：下一题与提交

这一轮（[`.scratch/questionnaire-keys/spec.md`](../.scratch/questionnaire-keys/spec.md) §11）把
回车从「与空格等价的确认键」改成「处置这一题、往前走」，空格仍是唯一的选中键。状态机与文案
断言在 `tests/ask_user_question_tui.rs` 与 `tests/wording.rs`；剩下这一半只有真终端答得了：
**一路回车过去的节奏顺不顺、`已跳过` 看不看得见、末题那一下是不是提交**。

前置：`cargo build`，跑 `./target/debug/heng`，让模型发起一次**三道题**的问卷。

1. **回车就是下一题**：在第一题敲一个空格（选中一项）再按回车 —— 它去第二题，而刚才的选择
   **没有被改动**；`←` 回看第一题，选中还在。
2. **回车不选中**：在第一题不按空格、直接按回车 —— 高亮那一项**没有被选中**，人去了第二题。
3. **空格不前进**：连按几次空格 —— 高亮项只是来回切换，人一直停在这一题。
4. **`已跳过`**：用回车走掉一道没作答的题，页脚进度后面应当出现 `已跳过`；`←` 回到那一题，
   它还在；空格选一项，它**消失**（作答撤销了跳过）。
5. **`←` 不记跳过**：按 `→` 到下一题、再按 `←` 回来，回看过的题**不该**被记成跳过。
6. **末题提交**：在最后一题按回车 —— 问卷收起并提交；在那之前页脚显示的应当是 `回车 提交`
   （前面几题都有着落时才是这一句，否则是 `回车 下一题`）。
7. **末题的 `→` 无动作**：在最后一题按 `→`，画面一个像素都不动 —— 不记跳过、不前进、不提交。
8. **提示的宽度档**：把窗口拉窄，看提示段先丢掉 Emacs 别名、再砍到只剩 `esc 退出询问`，
   而 `已跳过` 与举手回执**任何宽度下都在**。
9. **三种终端各走一遍**：`xterm`、`tmux`（窗格里的 TUI）、一个 VTE 系（`gnome-terminal` /
   `Tilix` / `xfce4-terminal` 任一）。回车连按的节奏、以及页脚那行小字在这三处的差异，
   照实记下来 —— 提示被裁掉半截与它根本没画，是两种不同的毛病。

这一节真正要看的是**回车的手感**：一路回车过去应当像「翻页」而不是「作答」—— 而这正是它把
「没作答就走开」记成跳过之后最容易误解的一处：跳过会进答案，所以它必须看得见。

补一句 `已跳过` 的来历：跳过原先只有一个入口（`Tab`），人按下它的时候自己心里有数；这一轮
之后，往前走也会记跳过，于是「我什么都没答」与「我跳过了」在键盘上成了同一个动作。把它画在
页脚，是为了让人翻回来的时候知道这一题交回去的是什么，不必靠回忆 —— 这也是本次改动里唯一
一处「手感之外」的负担。

真到了终端里，最容易出偏差的一处是**节奏**：回车连按时，中间那几道没作答的题会静默变成
「跳过」，而屏幕只在停下的那一题上给你回执。所以走查时要特意慢下来，看一眼每一下之后页脚
写的是什么 —— 那行小字就是这一轮全部的可见性。

## ㉘ 输入框里的记号：`@` 提文件、上色与 chip

这一轮（[`.scratch/input-tokens/spec.md`](../.scratch/input-tokens/spec.md)）给输入区加了两种
记号：`@` 提工作区文件、`/` 与 `@` 一起上色、能兑现的记号变成**不可分割**的一块
（[ADR 0012](../docs/adr/0012-input-tokens-are-atomic.md)）。状态机与文案断言在
`src/render/editor.rs` 的单元测试与 `tests/` 里；剩下这一半只有真终端答得了：**候选弹得对不对、
颜色分不分得清、chip 的手感是不是「一块东西」**。

前置：`cargo build`，跑 `./target/debug/heng`，工作目录里要有几十个文件。

1. **`@` 触发**：打「帮我改 @」，候选应当浮在光标处；接着打几个字母，列表按**分段前缀**收窄
   —— `cli` 也认路径中间那一段（`src/cli.rs`，`.scratch/tui-feedback/spec.md` §4）。
   在路径中间打（`src/@x`）**不该**弹。
2. **目录下钻**：选中一个目录 —— 插入 `@dir/` 而菜单**还开着**，接着打就继续过滤那一层；
   选中一个文件 —— 插入路径、**自带一个分隔空格**、菜单关掉；补完直接接着打字，不该粘在
   路径上（目录那一侧则**不该**有空格，否则钻不下去）。
3. **`Enter` 只接受**：在 `@` 菜单里按 `Enter`，**不该**把消息发出去；再按一次才发送。
   命令那一侧同样自带分隔空格：`Tab` 补出 `/ask-matt ` 之后可以直接接任务。
4. **颜色**：`/loop` 是命令色、`@Cargo.toml` 是引用色，而「看 /tmp/x」里的 `/tmp/x`
   **是普通文本色**（它兑现不了）。打字途中颜色忽隐忽现是对的 —— 兑现那一刻才凝固。
5. **chip**：把光标停在有效记号旁边按 `←`/`→`，它应当**整块跨过去**；`Backspace` 一下删掉
   整块；光标进不了内部，也插不进字。
6. **粘贴**：把含 `@Cargo.toml` 的一段文字粘进来，它应当**就地变成 chip**（与手打一条规则）。
7. **`/` 与 `@` 同一条边界**：打「请 /loop 我的目标」提交 —— 它应当当成命令执行，任务里带着
   「请 我的目标」；**写在第二行也一样**（位置不看行）。再打「请把 /clear 加到文档里」提交
   —— 它应当**当普通消息送给模型**，会话不被清空。最后试一次「用 /loop 做目标循环」：
   它**会**被执行 —— 那是这一档明码标价的代价，不是 bug。
8. **新文件**：让模型新建一个文件，提交之后立刻 `@` 它 —— 应当找得到（提交后重扫过一遍）。
9. **点目录与隐藏文件**：打 `@.scratch/` —— 隐藏**目录**应当列得出来并钻得进去；打 `@.env`
   或 `@.gitignore` —— 隐藏**文件**不该出现在候选里（`.git/` 也不该）。这一条是 2026-10-05
   真机反馈后按「放行隐藏目录、挡住隐藏文件」修的。
10. **三种终端各走一遍**：`xterm`、`tmux`（窗格里的 TUI）、一个 VTE 系（`gnome-terminal` /
   `Tilix` / `xfce4-terminal` 任一）。

这一节真正要看的是**记号是不是「一块东西」**：颜色、跨越、整块删除三处必须一致 —— 只要
有一处还像普通文本，人就分不清哪些字是自己能改的。

补一句关于**颜色**的来历：命令色与引用色不是装饰 —— 它们各自对应一个「这个东西能不能被
兑现」的判断，而兑现不了的记号一律保持普通文本色。所以走查时不要只看「有没有颜色」，要看
**同一段字在什么时刻变色**：打错的路径不该有颜色，一旦补全成真路径就该立刻有；打不成命令
的前缀也一样。颜色是这一轮唯一一处「你不需要记规则」的提示，它要是错了，别处再对也没用。

最后记一条**顺序**：颜色先于跨越 —— 只有先认出「这块能兑现」，才谈得上整块跨过去、整块
删掉。所以走查时先看颜色对不对，颜色对了再看移动与删除；反过来查容易把「两种毛病」混成
一条记下来。

## ㉙ 轨迹视图：账本、时间轴与可寻址的那一层

这一轮（[`.scratch/trace-ledger/spec.md`](../.scratch/trace-ledger/spec.md)）把轨迹页从「一条可扫的流」
升格成**可寻址的账本**（十二张实现票 12–23；`trace-in-main` 那一轮把它搬进了主列）。能自动化的
那一半在 `tests/render_layout.rs` / `tests/render_timeline.rs` / `tests/history_replay.rs` 与
`src/render/tui.rs` 的单测里；剩下这一半只有真终端答得了：**真实字体下 79 列正文里组头与行尾
并排的密度、两档底色在不同主题上的可分辨性、时间轴在真实字体下的读法、长会话里折叠与过滤的
手感**。

前置：`cargo build`，跑 `./target/debug/heng`，先让模型跑几个用了工具、带思考的回合 —— 要够长，
长到能折起来、也能搜。

1. **两个视图的分工**：主列只应当剩你问的话与助手的正文（加错误、中断、失败的 hook、`Notice`
   这类「说给人听」的行）；工具行、思考行、注入行、**回合与轮次的开始、正常的收尾、权限裁决、
   诊断**都在 `轨迹` 那一页上。点主列**第一行**上的 `轨迹` 标签核对。
2. **时间戳**：轨迹页里每个块的第一行以 `HH:MM:SS ` 开头（本地时区、静音档色），折出来的续行
   顶格。核对三件事：同一屏里时刻**递增**；跟 shell 里 `date +%H:%M:%S` 差在几秒之内；**深色与
   浅色两种主题**下那九列都读得清、不与正文抢眼。
3. **79 列的表格**：让模型答一条含 Markdown 表格的回答 —— 轨迹页里消息只画**首行 + `…`**，
   所以表格要**点开**才看全；覆盖层里 135 列的表应当排得正常。
4. **消息首行 + `…`**：一条多行回答在轨迹页只占一行、末尾一个 `…`；点它，覆盖层里是全文。
5. **「N 条新行」指示器**：在轨迹页往上滚，右下角应当出现 `↓ N 行新内容 · 点此到底`；点它回到
   最新。滚回底部时指示器自己消失。
6. **滚轮与键盘同一页**：滚轮在**任何位置**都滚当前显示的那一页；`PgUp` / `PgDn` / `Ctrl-G`
   也一样 —— 切到哪一页就动哪一页，另一页的阅读位置一分不动。
7. **两级分组与组头**：轨迹页里每个**单位**（交互数回合、讨论数轮次）以一行**组头**开头 ——
   它占的就是本来那条边界虚线那一行，读作 `09:12:04 ┄ 回合 1 · 49 s · bash×2 read×2`，虚线
   一直填到正文右缘；每个回合里每次**迭代**（模型调用）另起一行弱色、**不带虚线**的二级头
   `第 3 次迭代 · 18 s`。**成员不缩进**：工具行与消息行都从第 9 列起。跑一个还在进行的回合：
   那一行组头的直方图**当场长格**、跨度跟着变，而**不新起一行**，回合收尾后它定稿不动。把窗口
   拖窄：超宽时先丢直方图尾部、再丢整段直方图，序号与跨度最后才丢。
8. **永远可达**：按 `Ctrl-O` 收起左栏（或把窗口收到 80 列以下）—— 轨迹页**照旧在**：点主列第一行
   上的 `轨迹`，过程行都在。对话页仍只有对话（分工不随左栏变），这是本轮推翻 `trace-tab` §6 的地方。
9. **切页与详情**：切到 `对话` 再切回 `轨迹`，滚动位置还在；在轨迹页点开一条详情、关掉，
   应当还在打开它的位置，而对话页没动。
10. **回合条只在对话页**：轨迹页上那一列是空的（只有滚动条在它左边一列）；切回 `对话`，
    格子照旧，焦点格仍然亮。
11. **名字独占一行**：对话页里 `[用户]` / `[kimi]` 各占一行，话从下一行起、顶格（**这一页的每一
    行都不是入口** —— 名字行与正文行点了都不弹窗，见 ㉚）；轨迹页仍是一
    行里 `[名字] 首行…`（那一页要密度）。两处看起来不该一样。
12. **等待提示**：提交之后，对话页末尾应当出现 `[名字]` 一行加一行提示（没有工具在跑时是
    `正在思考...`，点号大约每半秒挪一格；模型一调工具就换成**真实动作** —— 读文件是
    `正在查看 <路径>...`、写文件是 `正在写 <路径>...`、shell 是 `正在运行 <命令>...`）。
    第一个字或工具结果一到它就换掉或消失；轨迹页**不该**出现它。
13. **两条页签条的观感**：120 列以上时左栏那条与主列那条落在**同一个屏幕行**上 —— 看它们读起来
    是一根条还是两根、眼睛会不会把它们当一套。这是本轮唯一没法在 `TestBackend` 里判断的东西。
14. **每行耗时与失败那一行**：成功工具行的行尾是 `摘要 · 1.5 s in=… out=…`（耗时在用量**之前**，
    10 秒以上不带小数）；这次调用**还没有结果**时耗时那一段**空着**（没有 0、没有占位符）。
    让一条命令失败：行尾是红 `失败`，**下一行**从第 9 列起另起一行是错误正文的**首行**，行首
    没有 `✗`；失败而没有错误正文时那一行不画。空输出行补 `· 无输出`。
15. **无主段落的小标题**：开场那几条注入之上有一行 `开场 · N 条注入`（不缩进、弱色、**不带
    虚线**），上下文压缩那一段有 `压缩 · 前面若干轮压成摘要`。两条都**不是把手** —— 点它们
    不折也不展。
16. **时间轴那三行**：轨迹页内容区顶上固定三行（刻度 / 模型泳道 / 工具泳道），**滚动账本时它
    不动**。模型泳道里每一次调用占一段，有首 token 时刻的那几次应当读得出「等首 token」与
    「吐字」两段（同一字形、**两档颜色**）；短于**一格**的调用**不画**（宁缺勿假），老会话上
    整段一个颜色、不插占位符。工具泳道里并发调用**叠着**看（两种密度的块字）。刻度行上有一段
    **区间底色**标出当前视口，滚账本时它跟着走；回合边界是模型泳道上的一道 `│`，而**迭代边界
    没有**。**两档底色**（视口的与命中的）在你这台终端的主题下**分不分得开**，只有你看得出来 ——
    分辨不开就改那两个常量的值并记在这里。
17. **横带不可聚焦**：点横带、把滚轮悬在它上面滚 —— **什么都不该发生**（它不进键盘阶梯、不产生
    过滤）。把窗口一路收窄：刻度先变稀疏、再退成一行三态版、最后整条不画，而**账本还在**；
    高度不够时让位的是横带、不是账本。
18. **选中与折叠（键盘流）**：在轨迹页上按 `↓` / `j` 走几格 —— 选中是**整行**亮（`ACCENT` +
    `BOLD`），一个块只停一次（失败那行、还在长的思考行不会成为落点）；`g` 到账本第一条、`G` 跳
    最新并恢复跟随。按 `Space`：选中一个回合的组头就折成一行
    `▸ 回合 N · 12 个步骤 · 9 个工具调用 · 2.1 s`（虚线还在），再按展开；折行上按 `Enter` 开的是
    **段首那一次调用**的详情。按 `{` 全折到只剩组头与折行（正在跑的回合也折）、`}` 回到全折之前
    你自己折的那一份。**展开态的账本里一个 `▸` 都不该有**。
19. **点组头 / 点折行**：用鼠标点组头那一行（或折行）折 / 展一次，再点一下展 / 折回来 ——
    两次相邻的单击就是两次单击（**没有双击**，也没有悬停）。
20. **搜索与过滤的键盘流**：在轨迹页上按 `/`（在输入区打字时它仍是记号菜单）—— 输入区切到搜索
    模式，**进搜索之前的草稿整份存着**；打一个词，账本**当场只剩命中块**（未命中一条行都不占），
    右下角那行写 `n 个命中`；按 `n` / `N` 沿命中走、选中跟着过去；`Enter` 离开搜索模式**不发

## ㉚ 指针与提示：提示行归位、名字行不可点、拖选复制

这一轮（[`.scratch/tui-feedback/spec.md`](../.scratch/tui-feedback/spec.md)）把提示行搬回输入框正下方、

前置：`cargo build`，跑 `./target/debug/heng`，窗口至少 120 列（要左栏与主列同时在场）。

1. **提示行的位置**：提示（`enter 发送 …`）应当从**输入框那一列**起、就在输入框正下方 ——
   左栏底下不再有它，而左栏那条竖虚线一直画到屏幕最后一行。
2. **提示的宽度**：120 列下主列是 79 列，所以提示比从前少一条（`ctrl-o 左栏` 排在最末、先让位）；

3. **对话页不弹窗**：点 `[kimi]` / `[用户]` 独占的那一行，以及它**下面那几行正文** —— 都不该

4. **`@` 认中间那一段**：打 `@cli`，第一条候选应当是 `src/cli.rs`；打 `@render/tui` 应当给出
   `src/render/tui.rs`；`@src/` 的老行为一个字不变。
5. **拖选**：在转录正文上按住左键拖过两格 —— 那一带反白；松开后提示行给一句
   `已复制 N 字 · M 行`，三秒后自己走掉。用 `wl-paste` / `xclip -o` 粘一下，确认真的进了剪贴板
   （有些终端或 tmux 不开 OSC 52，剪贴板拿不到 —— 那是终端设置，不是这条坏掉）。
6. **软折拼回**：找一段被折过的长命令（详情覆盖层里最容易复现），整段拖选复制 —— 粘出来应当是
   **一条**长行，而不是屏幕上那两截。
7. **点击照旧**：页签、回合条、`▸` 行、问卷按钮、点覆盖层外面关掉它 —— 都还点得动
   （点击动作挪到了**抬起**上，这一条盯的就是它没被挪坏）。
8. **shift 原生选择**：按住 shift 拖 —— 终端自己的选择照旧工作。
9. **`Esc` 撤选**：按住拖动时按 `Esc`，反白消失、且不复制。
10. **点击与拖选的分界**：**挪一格**就算拖（门槛是一格 —— 2026-10-06 试过两格之后按维护者的
    要求撤回）。在**轨迹页**点一行、按下-抬起不动 —— 那是点击、详情照开；按住拖过一格 —— 那是
    拖选，抬起时复制而不是开详情。对话页两种都不弹窗（第 3 条）。
11. **反白铺到文字**：拖过一行时，反白应当在那一行最后一个字之后收住 —— 右边那一大片空白不反白，
    看起来是文字被选中，而不是一块矩形。
12. **`Shift-Enter`**：在支持键盘增强协议的终端里按它 —— 换行、不提交（与 `Ctrl-J` 相同）；
    不支持的终端里它仍旧提交，见 ⑥。
13. **用户消息的气泡**：发一条**三行**的输入（三行长短不同）。它们应当装在**一块等宽的底色**
    里、贴着转录的右缘，三行从**同一条左边界**起 —— 而不是长行往左伸、短行缩到最右边；名字行
    在气泡**外面**、自己一行。再发一条很长的输入：气泡宽度封在转录宽度的**三分之二**，长文在
    里面折行，屏幕左边那一大片留白仍在。最后拖选复制气泡里的文字：粘出来应当**只有正文**，
    行尾那些填到块宽的空格、气泡左边那片留白、你自己写的缩进各归各位
    （[`.scratch/trace-tab/spec.md`](../.scratch/trace-tab/spec.md) §2 的补记）。

这一节真正要看的是**提示行与指针**：位置（第 1、2 条）在宽屏上一眼可见，而拖选那一半只有手上有
鼠标才答得了 —— 尤其第 5 条与第 7 条：前者验证 OSC 52 这条通道，后者验证点击挪到抬起之后没有
漏掉任何一处入口。

## ㉛ 文件页：树、焦点行与内容弹窗

这一节真正要看的是**密度与焦点行**（第 1–4 条）与**重扫那一瞬间**（第 9 条）：前者只有在真字体

7. 拖选弹窗里的一段 diff 复制出来：里面**只有文本**，除了行号没有别的装饰，也没有转义序列。
8. 在**另一个终端**里 `git add` 一个文件，回到 TUI 按 `r`：清单跟着变，提示行有一句回执。
9. 键盘：点左栏任意处之后 `↑` / `↓` 走焦点行（跳过分组标题）、`Enter` 开那份 diff、
   `Esc` 只把键盘还回去（正在跑的时候**不取消回合**），`r` 之外的可打印字符不落进草稿。
10. **装了真外部工具之后**（`[ui] diff_viewer = "delta"`，`diff_viewer_args = ["--paging=never"]`）：
    点开一份 diff，标题右端应当有 `· delta`，颜色是 delta 自己的。把它改成 PATH 上不存在的
    名字：正文**回退成内置那一档**，提示行给一句 `找不到 …`。这一档的观感（与语义色板搭不搭）
    只有在真装了工具的机器上才看得到 —— 写 `[ui]` 那两行之前先 `command -v delta` 确认一下。

这一节真正要看的是**两档密度**（28 列下这一页读不读得下去）、**diff 两色在真配色下的分辨度**，
以及外部工具那一档的颜色落在这台机器的配色里是什么样子。

## ㊳ 问卷期间读详情

模型发问的同一时刻，让它把上一次调用摊开给你看 —— 这是这一轮要修的那件事（改前那几扇门
全关着，理由记在 [`.scratch/questionnaire-reading/spec.md`](../.scratch/questionnaire-reading/spec.md)）。

1. 让模型发一次 `ask_user_question`，在它那屏问卷上切到 `轨迹`，点**上一次工具调用**那一行：
   详情覆盖层开着，而**下面的题面与选项看得见** —— 浮层的底边停在问卷块的顶上（要看的是
   两者之间那条缝，以及有没有哪一行被压掉半个字）。
2. 覆盖层开着时按 `Esc`：它关掉，键盘**原样还给问卷** —— 高亮仍在原来那一项，而你已经
   按过空格选中的那些**还在**（这一条是这一轮的核心，不是顺手）。
3. 覆盖层开着时按 `j` / `↓`：滚的是**覆盖层**，问卷的高亮不动。
4. `Esc` 之后按空格、按回车：问卷照常作答与提交，答案回到转录（`ask_user_question` 的结果）。
5. 在问卷上点左栏 `文件` 页的一行：内容弹窗开着，题面同样看得见。再点一个**目录**：它展收，
   键盘**不**跟着去文件页（还在问卷里）。
6. 覆盖层开着时**点框外**：它关掉；若那一下点在问卷里，落点仍归问卷（看那一处页脚按钮是否
   照旧响应 —— 这是「框外点击关闭」与「问卷吃自己那块」两条判据叠在一起的地方）。
7. 把终端压到 **40×10**：问卷立着时点轨迹行**开不出来**（那一段高度装不下正文），而且什么
   都不留 —— 键盘还在问卷上。
8. 配了 `[ui] file_viewer = "nvim"` 的话重复第 1、2 步：内嵌那一档同样接管键盘，`Ctrl-C`
   关掉它（`Esc` 归 nvim 自己），下面那道题原样留着。

## ㊴ 命令留痕

1. 在输入区敲 `/clear` 回车：转录里留下一行 `[命令] /clear`，**下面没有别的**（清场成功时
   本来就没有回执）—— 看得见的就是这一行。用的是草稿里命令那个蓝，不是 `Notice` 那一档灰。
2. 敲 `/undo`（没有可撤销的修改）：`[命令] /undo` 一行，**下面**是那句回执。两行叠起来读。
3. 敲一条普通的话、以及 `/<skill> 带任务`：转录里是**用户气泡**，**没有** `[命令]` 那一行 ——
   原文已经是用户说的话，不重复记。
4. 敲一个不存在的 `/no-such`：转录里 `[命令] /no-such` + 下面那句「未知命令 …」两行。
5. 另开一个终端 `heng -c <id>` 重开这场会话：`[命令]` 那一行还在（它进 `log.jsonl`）；而
   `heng sessions show <id>` 里也列得出它。

## ㊵ 左栏 `todo` 页：摘要 + 详情弹窗

1. 模型立一份待办之后点左栏的 `todo` 签：第一行是 `2/11 · 1 个在做`，那一行右端写着 `详情`；
   下面全是**没做完**的项，正在做的那条（`●`）排在最前，做完的（`✓`）不在页上。
2. 两档宽度（120 列与 80 列）各看一遍：一条 25 字的中文待办在窄档折 3 行，**续行缩进到内容列**；
   带 id 的与不带 id 的两行内容起于同一列。
3. 点页里**任何一格**（含条目行）都弹出一份完整清单：进度行、未完成项、做完的项（更暗的那些），
   标题是 `待办 · <那个模型的名字>`。关掉之后左栏仍停在那一页。
4. 开着弹窗的时候让模型再提交一份新清单：开着的那个**不动**；关掉重开才是新的那份。
5. 在这一页上拖选一段折行的待办：提示行给「已复制」，**而这次拖选没有顺手把弹窗开出来**。
6. 列表被清空之后页上是一句 `还没有待办`，而**页签还在**、那一块按钮不见了、点哪里都开不出
   空弹窗。全部做完之后页上只剩那一行 `11/11 完成`。
7. 终端缩到 80 列以下、或按 `Ctrl-O` 收起左栏：这一页就是看不见，没有别处替代入口。
8. 换一套字体再看：`●` `☐` `✓` 三个字形是不是都还占一列（它们都是「歧义宽度」）；以及
   完成项的降暗在真配色下退不退得后。
9. 让一条待办里带一个长路径或英文词，看折行把它**从中间断开**时刺不刺眼（这一页照旧硬切，
   断词是已知的取舍）。
9. 把终端压到 12 行高（宽档 40×3）：页上只剩进度行与溢出，条目最多露一行、末尾一个 `…`。
