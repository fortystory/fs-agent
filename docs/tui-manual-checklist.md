# TUI 手工清单（真终端）

`cargo test` 与 `scripts/tui-startup-check.py` 覆盖得到的东西不在这里。这份清单只列
**必须在真终端里用眼睛和键盘验**的项目 —— 光标、鼠标、终端状态、真实的时间序列。
每项都给了怎么做、该看见什么；看不见就是回归。

来源：`.scratch/tui-layout/spec.md` 的 §Testing Decisions「手工清单」与 §2/§4/§5/§7，
外壳改版的 `.scratch/tui-sidebar/spec.md`（§Testing Decisions 的「手工清单」），
模式与待办那一轮的 `.scratch/todo-and-modes/spec.md`（§4、§Testing Decisions → ⑰），
以及外壳收干净那一轮的 `.scratch/tui-chrome/spec.md`（§1–§5、§Testing Decisions → ⑳）、
终端标题那一轮的 `.scratch/terminal-title/spec.md`（§1–§6、§Testing Decisions → ㉓）。
布局本身按 ADR 0002：备用屏幕（alt screen）全屏，**一条全高左栏 + 一条主列**
（转录 / 状态行 / 输入 / 提示）—— 四周那圈外框已经拆掉，两者之间只剩一条竖虚线（⑳）。
左栏在 **≥ 120 列**时 40 列宽并画 fs 标记（5 行字符画），
**80–119 列**时 28 列宽画一行文字身份，**< 80 列**整栏隐藏 —— 标记的边缘与颜色、
tab 的点击、回合条的焦点只有真终端能验，见 ⑩ 与 ⑮。

准备：`cargo build`，然后 `./target/debug/fs-agent`（或 `target/debug/fs-agent`）。
下面 ①③⑤⑥⑨ 需要一个能写文件/跑命令的会话，权限模态出现时按提示回答即可。

## ① 光标

1. 输入三行：`第一行` `Ctrl-J` `第二行` `Ctrl-J` `第三行`，光标应始终跟在最后一个
   字符后面，不进到边框、不跑到对话区。
2. `↑` `↓` 在**同一逻辑行**内走；`Ctrl-A` / `Ctrl-E` 到行首 / 行尾；`Ctrl-U` / `Ctrl-K`
   删到行首 / 行尾；`Ctrl-W` 删前一个词。
3. 输入长到软换行（超过内宽）后，`↑` 跨视觉行、`Home` 到该行首（不是整个草稿首），
   光标列按显示宽度算：`你好世界` 四个字占八列。
4. 行尾插入：把光标移到行中间打字，字应插在光标处而不是末尾。
5. 提交后光标回到输入区第一格，`❱ ` 提示符还在（它的颜色见 ⑯）。
6. 粘贴多行文本后**光标立刻可用**、草稿未提交（这条和 ⑤ 一起看）。
7. 多行草稿按 `Esc`：覆盖层是**标题 + 正文 + 候选键行**、各占一行（不是一整句）：标题
   `清空输入`（加粗）、正文 `草稿有多行，Esc 会把它们全部丢掉`、候选键行 `[y] 清空`
   与 `[n] 保留`；`n` 后草稿原样还在。

## ② 权限模态

触发一次需要权限的写操作（让 agent 跑一条 `bash` 写文件之类的命令）。

1. 模态出现在**中区块内部**，四个区块的边框与标题不被挤坏。权限询问的正文是**三行**：
   `权限询问：`（**不带工具名**）、**与转录折叠行同一句话**的描述
   （`调用 bash 查看 git status`）、**要执行的原文命令**（`bash（command=…）`）——
   最后这行是授权时唯一必须看得见确切命令的地方，不要少；工具名与「要做什么」各只出现一次。
2. 按 `y` / `a` / `n` 任一回答：模态消失，**焦点立刻回到输入区**（接着打字能进草稿）。
   候选键行（`[y] 允许` / `[a] 总是允许` / `[n] 拒绝`）在覆盖层里**水平居中**，不贴在左边。
3. 模态在时 `Shift-Tab` 不改变权限模式（模态吃掉键盘）。

## ③ 鼠标

1. 先让转录长出可视区（跑几个回合），滚轮上滚看历史，`PgUp` / `PgDn` 翻页，
   `Ctrl-G` 到底。
2. 上滚后转录区**右下角**出现指示条：`↓ {n} 行新内容 · 点此到底`；没有新内容时是
   `点此到底`（它就是「到底」两个字）。**用鼠标点它**，视图回到最底。
3. **按住 Shift 拖拽选中文本并复制** —— 鼠标捕获开着，不按 Shift 选不中（ADR 0002
   的已知代价）。选完粘贴到别处，内容正确。
4. 权限模态在时滚轮不动转录、点击指示条无效。
5. **点击作答**：权限 / 粘贴确认 / 清空草稿三种覆盖层，用鼠标点候选键行里的
   `[y] 允许` / `[a] 总是允许` / `[n] 拒绝`（或对应问题的键）——效果和按那个键完全一样；
   点标题、正文、边框、覆盖层里的空白**没有反应**；窗口矮到候选键行被裁时，被裁掉的那截
   点不到。
6. **问卷点击**：模型发来 `ask_user_question` 时，单击某个选项行即选中并立即作答（单选；
   最后一题只确认、不自动提交），多选单击只切换勾选、再用底部 `提交` 提交；底部
   `← 上一题` / `下一题 →` / `提交` 只画可用的那些，点它们翻页 / 提交；选项超出可视区时
   滚轮移动高亮；点 `自定义：` 那一行光标出现在那里，翻页后光标收回。
7. **折叠与详情**：转录里 `[执行者] ▸ ✓ 思考完成` 与 `[执行者] ▸ 调用 bash 查看 <路径>`
   名字后面有 `▸`，用鼠标点它（或点工具失败行）打开详情覆盖层：标题是被点那行的原文、
   边框是被点那行说话人的颜色，正文分 `── 思考 ──` / `── 参数 ──` / `── 输出 ──` 三节，
   底部 `↕ n/m · esc 关闭`（滚到最底时 `n` 等于 `m`）；
   `↑` `↓` `PgUp` `PgDn` 与滚轮滚动，`Esc` 或**点击覆盖层以外的任何地方**关掉；
   **滚到最底时底部计数应读到 `n/n`**（与总行数相同）；覆盖层打开时转录冻住
   不动（新输出不会把它抽走）。**短输出（没被截断过的）就是全文**——不该出现 `全文不可用`；
   只有**被截断过**的结果才会去找 `outputs/<id>.txt`，那时文件被删掉才显示预览加 `全文不可用`，
   且超过 200 000 字符时末尾写 `已截断`。
8. **角色配色**：四种角色的名字前缀颜色不同 —— 讨论者 1 `浅青`、讨论者 2 `浅品红`、
   执行者 `浅黄`、用户 `浅绿`、系统 `灰`；正文仍是原来的语义色（成功绿、错误红、
   权限黄、narration 灰）。浅色主题下浅黄 / 浅绿 / 浅青的可读性弱是**已知取舍**。

## ④ resize

1. 拖窗口：四区块重排不撕裂，没有半行残留、没有叠字（拖动本身会发 SIGWINCH，
   TUI 收到 resize 事件就重画）。
2. **锚点**（固定尺寸的 buffer 测不到，只能这样验）：吸底时拖窗口，转录仍贴底、
   不跳；先上滚几行进入脱离态，记住最上面那一**源行**，再拖窗口 —— 变宽变窄后
   仍应是**同一源行**在最顶（重排会改变它占的显示行数，但不该换成别的行）。
3. 拉到很窄：提示行按**主列宽度**（不是终端宽度）丢条目，`ctrl-c/ctrl-d 退出` **永远在**，
   `就绪` 先丢。`40` 列时是 `就绪 · enter 发送 · ctrl-c/ctrl-d 退出`（左栏已隐藏，主列 38 列）；
   `80` 列时左栏占掉 29 列，提示行只剩 49 列，于是是 `enter 发送 · ctrl-j 换行 · ctrl-c/ctrl-d 退出`。
4. 拖到 `40×10` 以下（下一个尺寸 `39×24`、`40×9`）：整屏只剩
   `终端太小：至少 40×10`，不画出半个布局。
5. 拖到 `120×24` 且草稿写到 10 行（输入上限）：**左栏不动**（它是自己一栏、高度不随之
   变），转录被压到只剩 1 行。

## ⑤ 粘贴

1. 粘 5 行文本：**不提交**，全进草稿（行尾统一成 `\n`，Tab 变成四个空格）。
2. 粘超过 100 000 字符：覆盖层同样是**标题 + 正文 + 候选键行**、各占一行：标题
   `粘贴确认`、正文 `粘贴 {n} 字符`（`{n}` 是实际字符数）、候选键行 `[y] 粘贴` 与
   `[n] 取消`；`n` 丢弃、`y` 全收；`Esc` 与直接回车都算拒绝。
3. 粘一大段以 `/` 开头的文本：**不是内建命令**，按普通输入处理（多行则整段进草稿）。

## ⑥ Ctrl-J 与 Shift-Enter

1. `Ctrl-J` 换行（提示行写着 `ctrl-j 换行`）。
2. `Shift-Enter` **在大多数终端里就是提交** —— 没有键盘增强协议时它在协议层与 `Enter`
   不可区分，所以提示行从不写 `shift+enter`。若你的终端支持该协议，按下去也是提交，
   不会换行。**这不是 bug**（spec §Further Notes）。

## ⑦ 退出后终端干净

1. **双击退出**（`.scratch/exit-gesture/spec.md` §1–§2）。空闲时 `Ctrl-C` 与 `Ctrl-D`
   **完全对等**：第一下只在提示行举手（出口那一段换成 `再按一次 ctrl-c/ctrl-d 退出`），
   500 毫秒内第二下退出 —— 两键混按也算第二下；超时不按，提示行恢复原样、下次要重新按两下。
   忙的时候 `Ctrl-C` 第一下只取消当前回合（提示行 `已取消 · 再按一次 ctrl-c 退出`）、第二
   下退出；忙时 `Ctrl-D` **没有任何反应**（也不清掉已经举起的那把手）。详情覆盖层打开时
   `Ctrl-D` 是**关掉详情**，不参与退出手势。`/quit` 仍然一下就退。**那个退出确认框已经拆了**
   —— 屏幕上不该再出现 `退出会话` / `[y] 退出` / `[n] 取消`。
   退出后终端干净、回执打在 shell 里，见下一节。
2. 退出后在 shell 里：

   ```
   stty -a | grep -E 'icanon|echo|isig'
   ```

   三个都**不带** `-` 前缀（是 `icanon` / `echo` / `isig`，不是 `-icanon`）—— 也就是
   回显、行编辑、`Ctrl-C` 都正常。再敲 `Ctrl-C` 能打断命令、`history` 能用。
3. 用鼠标拖拽选中终端里的文本：不需要按 Shift 也能选（鼠标报告模式已关）。
4. 备用屏幕退出后回到原屏幕，之前的 shell 内容还在。
5. **忙碌双击退出后终端干净 + 回执打在 shell 里**：起一个长回合，连按两下 `Ctrl-C`。
   退出后 `stty -a | grep -E 'icanon|echo|isig'` 三个都带 `-` 前缀的**反面**（即
   `icanon` / `echo` / `isig`），而且 shell 里出现一行 `会话 <id>；复盘：fs-agent sessions
   show <id>`（走 stderr）。这一条守的是 `std::process::exit(130)` 那个缺陷：旧实现跳过一
   切析构，终端会留在 raw + 备用屏幕里。
6. 脚本里 `Ctrl-C` 与 `/quit` 两条路径**每次跑都会各验一遍**（撤销序列 + termios）。
   **panic 路径手工复现不了**（没有可靠的触发方式），它靠 `TerminalModes::drop` 与
   panic hook 调同一个 `disable_terminal_modes()`：只要上面 2–4 项通过、也就是这个
   函数是对的，panic 时也走同一条。这是本清单里唯一一处「靠构造保证」而不是「靠操作验」
   的项目。
7. **重开后退出**：`--continue` 进一个有历史的会话，等底部进度行消失（重播收敛）再走
   上面 1–4 的退出路径 —— 终端的交还与普通启动完全一样（备用屏幕 / 鼠标 / 粘贴 /
   termios），历史重播不会把终端留在别的状态里。

## ⑧ 忙碌 Ctrl-C

1. 让 agent 跑一个长任务，`Ctrl-C`：回合中止（转录里是中止/取消的结论），进程仍在，
   输入区可用。
2. 空闲 `Ctrl-C`：直接退出。
3. 权限模态在时 `Ctrl-C`：先取消当前回合（不是关模态）。

## ⑨ 120×24 草稿 10 行 → 转录被压到 7 行

1. 把窗口拉到 120×24（`stty size` 确认）。要用 `stty rows 24 cols 120` 改的话，
   **改完随便敲一个键**：TUI 只在「脏」的时候重画（spec §11），而 `stty` 不会发
   SIGWINCH，它要等下一次输入才会看到新尺寸。
2. 草稿写到 10 行：转录只剩 7 行，输入区不遮提示行，**左栏与状态行一动不动**。
3. 删回空草稿：转录回到 14 行（输入区的三行地板），左栏宽度与位置与之前一致（不抖）。

## ⑩ 左栏：mark / 文字身份 / 隐藏三档

左栏的宽档由**宽度**决定（≥ 120 列 → 40，80–119 列 → 28，< 80 列 → 整栏隐藏），
它的**内容**由自己的高度决定（先丢 mark → 身份行 → 字段尾部）。固定尺寸的
`TestBackend` 能断言两侧的档位与字段数，但标记的**字形、渐变与居中**只有真终端看得见。

1. 把窗口拉到 `160×40`（宽档）：左栏 40 列，5 行 fs 标记**居中**（左右各 1 格空白，标记
   本身 38 列），下面是页签（tab）条（`调用量│轨迹│文件` + 填充横线），再下面是六个读数
   （上下文 / token / 回合 / 输入 / 输出 / 缓存）。空闲时标记是**亮品红→品红渐变**（上亮下暗）、
   不换行、不被截断，右端的分隔线（`│`）整列完整；**跑起来时它整块变色**，见 ⑯。
2. 把宽度收到 100 列：左栏变成 28 列、**文字身份**（`fs-agent 0.1.0`，暗灰）替代 mark，
   六个读数还在。收到 79 列：**整栏消失**，转录吃掉全部宽度，状态行与回合条**仍然在**。
3. 把高度一步步收到 10 行（`stty rows 10 cols 120`，记得敲一下键触发重画）：先在 12 行左右
   看见 mark 退成文字身份，再到 10 行连身份行与「缓存」都让位 —— 上下文 / token / 回合
   这三行**最后才消失**（那是底线的三条）。
4. 终端配色是浅色主题时再看一眼：标记只有前景色、没有背景色，所以浅底上应该同样清楚；
   若你在浅色主题下看到标记里出现色块，说明背景色被带上了，是回归。

## ⑪ `/` 菜单

`/` 菜单是键驱动的：它只在按键之后出现、跟着光标走，`scripts/tui-startup-check.py` 只看启动
第一帧和退出时交还的终端状态、看不到它，所以按该脚本 docstring 的口径留在手工面（真终端的
按键、重画与位置在这里验，固定尺寸 buffer 里的框与筛选归 `cargo test`）。

1. 草稿行首敲 `/`：输入区那一行之上浮出一个带边框的菜单，按目录顺序列出内建命令
   （`/undo` `/discuss` `/quit`），每行是 `/<名字>` 加一句说明
   （`/undo` 后面是 `回滚上一次编辑`），再往后是本次会话发现的技能；只敲了一个 `/` 时
   **没有任何一行高亮**。接着敲 `/as`：只剩匹配的名字（大小写不敏感），框随光标右移、
   不盖住刚打进去的字；退格回到更短的前缀，列表跟着重新变宽——普通按键照常编辑草稿，
   菜单不吃键。
2. `↑` `↓` 移高亮：空 `/` 上 `↓` 落到第一行、`↑` 落到最后一行，到两端会绕回。
   高亮行是**反白**的（黄底黑字），和未选中的行一眼分得开；光标停在哪一列与高亮哪一行
   是两回事。
3. `Tab` 只把高亮的完整名字填进草稿（菜单收起，光标停在名字后，能接着打
   `/ask-matt 优化这个`）；`Enter` 填名字**并当场提交**（`/ask` + Enter 是一次手势）。
   真终端上要看见草稿里是补全后的完整名字，而不是半截前缀。
4. `Esc` 收起菜单，草稿原样留着：不会顺手清空输入，也不会弹出 ①.7 的 `清空输入` 覆盖层。
5. 筛到没有匹配（例如 `/zzz`）：菜单整体消失，不是画一个空框、也不是留下上一次的半个
   边框；退格回到有匹配的前缀，菜单原样回来。
6. 画与位置：菜单框四条边完整，浮在转录之上但不压四区块的边框、不盖住输入行、不出屏；
   窄终端下宽度不够时不画说明列（只剩 `/<名字>`），再挤到放不下就干脆不画，**不要**看见
   一个压扁的框。菜单开着**拖窗口**（拖动本身会发 SIGWINCH）：框跟着重画、不撕裂、不留
   残影；要用 `stty` 改尺寸的话记得**改完随便敲一个键**触发重画（`stty` 不发 SIGWINCH，
   TUI 只在「脏」时重画，spec §11），重画后框仍锚在新的光标行上、上下都不出屏。

## ⑫ 折叠提示与详情覆盖层

转录里的「思考」与「工具输出」是折起来的：思考只留一行提示，工具只留调用行，正文都在详情
里。固定的 buffer 能断言文案、颜色与滚动位置（`tests/render_layout.rs`），真终端要验的是
**点击精度、滚动惯性、覆盖层与转录同屏的观感**。

0. **转录不会被抹掉**（最要紧的一条）：跑一个会**思考**的回合（默认就是），等它定格出
   `[执行者] ▸ ✓ 思考完成`，然后看**这行之前**的历史还在不在、中段是不是仍然占满高度、
   `PgUp` 能不能往回翻。曾经有一版会在定格时把整段历史从屏幕上清掉，只在活会话里复现。
   同时确认调用行：跑一条 `bash`，工具**执行完**的瞬间转录里就该有
   `[执行者] ▸ 调用 bash 查看 <路径>`（一开始不画，见票 02 的第二次修正）。
1. 让 agent 跑一个会思考 + 调工具的回合（例如让它跑一条 `bash`）：转录里先出现
   `[执行者] … 正在思考`，正文一开始就**原地变成** `[执行者] ▸ ✓ 思考完成`（不新增一行）；
   工具行是 `[执行者] ▸ 调用 bash 查看 <路径>` 这样的**一句描述**（名字是角色色、描述是灰），
   失败时行尾是 `失败`（红），错误正文与完整命令都只在详情里。
2. 点 `▸` 那行：详情覆盖层**居中于主列**弹出，宽度是 `min(主列宽 − 4, 135)`
   （120 列终端上主列 77 列，所以是 73；200 列以上才顶到 135 的天花板）、
   上下各留一行转录可见；左栏不被压住；**边框是你点的那一行的说话人的颜色**、边框与文字之间留 1 格；分节横线、
   标题、底部 `↕ n/m · esc 关闭` 都在。工具详情里 `── 参数 ──` 是格式化过的参数，
   `── 输出 ──` 是完整输出（不是转录里那截预览）。
3. 用 `↑` `↓` 与滚轮在详情里走一遍：内容长时底部计数跟着变、不会滚过头；`PgUp` / `PgDn`
   一次翻一屏多一点。`Esc` 关掉；**点覆盖层以外的任何地方也关掉**（原行、转录、左栏、
   状态行、提示行都行）；点覆盖层**里面**不动作。
4. 覆盖层开着的时候让 agent 继续输出（或者点开历史里的行）：转录**停在原处**，新内容不会
   把它抽走；关掉后视图回到原来的位置。
5. `outputs/<tool_call_id>.txt` 手工删掉再点那一行：显示事件里的预览 + `全文不可用`，
   不是空白框、也不崩。
6. 讨论会话（`/discuss`）里同样试一遍：合成器的思考只有增量、没有全文，提示行仍会定格，
   详情里写 `本次未记录思考全文`。

## ⑬ 鼠标作答的边界

1. 有待答问题（权限模态 / 问卷）时，**点转录里的 `▸` 行没有任何反应**（问题拥有指针）。
2. 详情覆盖层打开时，**点它背后的转录没有任何反应**；滚轮滚的是详情，不是转录。
3. `40×10` 这种最小尺寸下：覆盖层只有一行正文、候选键行可能被裁掉一截，**被裁的那截点
   不到**，露出来的部分仍可点；问卷只画一行时只有那一行能点。
4. 终端 resize 之后再点：命中跟着重画后的位置走（旧坐标不该再有效）。

## ⑭ `--continue` 重开

历史重播只有真终端能验观感；重播**内容**的正确性（块与顺序、分隔行、面板与模式、
历史详情的四种文件状态）都在 `cargo test`（`tests/history_replay.rs`），
`scripts/tui-startup-check.py` 的 `--continue` 路径只看**收敛**与**终端交还**。

1. 先在同一个工作区跑一个有两三个回合、至少一条工具调用的会话，退出；再 `--continue`
   进来：启动时底部提示行短暂显示 `恢复历史 n/m`，跑完**自动消失**、恢复普通提示行
   （`ctrl-c/ctrl-d 退出` 在）。
2. 历史铺完后屏幕上是上一段对话：`[角色] ▸ ✓ 思考完成` 与工具调用行都在；历史与本次
   新内容之间有一条 `── 以上为历史 ──`，**启动横幅排在它后面**。
3. 点历史里的 `▸` 行：详情覆盖层与 live 完全一样（边框是说话人的颜色、`Esc` 或点外面
   关闭、`↑` `↓` `PgUp` `PgDn` 与滚轮滚动）。把那个会话目录里的
   `outputs/<tool_call_id>.txt` 手工删掉再点同一行：显示事件里的预览 + `全文不可用`。
4. 重播**没跑完**时上滚 / `PgUp` / `Ctrl-G` / 滚轮：**预期无响应**（吸底）；此时照常
   打字，`Enter` 不提交（草稿留着）。
5. 超大会话（几千条以上事件）的启动手感：进度行看得见、界面不冻结、中途 `Ctrl-C`
   随时退出。
6. 重开一个**升级前**、被杀在计划模式的旧会话（流里还留着 `ContextInjected{PlanMode}` 与
   `HistorySuperseded{ModeChange}`）：它照常打开、历史照常重播（那两行读作「计划模式」/
   「模式变更」），而**状态行**显示的是**这次启动的那一档**（默认 `询问`，`--mode` 可覆盖）——
   档位是组装期的值，历史里的事件不会把它改回去（ADR 0003）。
7. 重开的历史里回合条**已经有格子**（历史是一段段真实回合），焦点落在最后一格。

## ⑮ 外壳改版：左栏 tab、状态行、回合条

这三样是新的，固定尺寸的 buffer 已断言它们**存在、档位与命中矩形**（`tests/render_layout.rs`）；
真终端要验的是**字形对齐、点击手感、焦点随滚动变化的观感**，以及 120 列那一档的提示行读起来够不够。
本轮的实现由 agent 完成、**没有真终端可跑**，所以这一节与 ⑩ 的条目都是**待人工过一遍**的，
不是「已验证」。

1. **tab 点击**：在宽档（≥ 120 列）用鼠标点 `轨迹`：标签变成亮品红加粗、`调用量` 变暗灰，
   左栏的六个读数换成一行 `此页尚未实现（另有票在跟）`（暗灰）；点 `调用量` 换回来。
   点标签**之间的** `│`、点标签右边填充的 `─`：**什么都不发生**（那不是按钮）。
   窄档（< 80 列）没有页签条，自然点不到。
2. **tab 与弹窗**：故意让权限模态弹出来（跑一条需要授权的命令），再点 `轨迹`：
   模态**不消失**、页面也不切换（问题拥有指针）；`Esc` / `y` 照常作答，作答后 tab 才能点。
   切到占位页时注意：**屏幕上只剩状态行的 `上下文 n%`** 是会话读数 —— 这是接受的代价，
   不是 bug（`Tab` 键归 `/` 菜单，所以 tab 只能点）。
3. **状态行**：输入区上方那一行是 `模型 X │ 模式 Y │ 上下文 Z%`。把宽度从 160 收到 100、再到
   79、再到 40 列：先丢**模型**、再丢**模式**、最后只剩 `上下文 Z%`，**这一行永远在**
   （不会整行消失）。跑一次真实调用后 `Z%` 应变成实际占比（没有用量时是 `上下文 —`）。
4. **回合条**：跑三四个回合，转录最右一列应该有几格 `┊`，**最新的一格在最下**、并且是亮品红的
   `┃`。往上滚（`PgUp` / 滚轮）：亮格跟着视口往下移 —— 停在某一轮的中间时，亮的应该是**那一轮**
   的格子；滚到最上面时，条的最下面出现 `⋮`（说明下面还有），最上面那格变亮。
   条的右端要贴着外框、不与滚动条打架（滚动条紧挨它左边一列）。
5. **点格跳转**：点某一格，视口**顶端对齐**跳到那一轮**你自己敲的那句**（`[用户] …`）——
   不是协议行、也不是「回合开始」；点最新那一格时看起来「没动静」是**预期**（它本来就到底了）。
   跳转之后再滚动，条上的亮格应立刻跟着新位置走，不残留。
6. **120 列那一档的提示行**：`120×24` 空闲时提示行是 `enter 发送 · ctrl-j 换行 · esc 取消 ·
   shift+tab 模式 · ctrl-c/ctrl-d 退出`（**四条 + 退出，放不下 `就绪`**）。这是**预期值**：
   左栏吃掉 40 列后主列只有 77 列，比 80 列的终端还窄。读起来是否够用请如实记下来 ——
   若觉得别扭，那是左栏宽档的取舍要重新议，不是提示行的 bug。
7. **左栏与转录的宽度账**：宽档下转录右缘恒留两列（滚动条 + 回合条），文本宽度是
   `主列宽 − 2`；把窗口从 160 收到 120 再收到 80，文本宽度应跟着档位跳（主列 117 → 77 → 49），
   而不是被"挤"出半格。

## ⑯ 输入区三行、提示符色相与静止的左栏

输入区的三行地板、提示符的起始颜色、以及「mark 不动」都由固定尺寸的 `TestBackend` 断言过
（`tests/render_layout.rs` + `src/render/tui.rs` 的单元测试）。真终端要验的是**光标落点**、
**颜色的观感**与**模糊宽度的字形**，这三样只有真终端有。

1. **三行地板**：空草稿时输入区就是 3 行 —— 第 1 行 `❱ `、下面两行是空的，提示行仍在它下面
   一行、`Ctrl-J` 换行后**几何不动**（转录的行数不跳）。写到第 4 行才看见框长高，第 10 行封顶。
2. **光标**：在第 1、2、3 行各敲几个字，光标应始终跟在最后一个字符后面、停留在**那一行**；
   在两行之间用 `↑` `↓` 走，别让它跑到留白的行上或者溜出输入区。
3. **40×10 的地板**：把窗口收到 40×10（记得敲一下键触发重画）：输入区在这档只有 **2 行**、
   转录只剩 1 行 —— 这是**预期**，转录的最后一行比输入区的最小高度优先。
4. **提示符只在 fs-agent 干活时变色**：空闲（等你打字）时输入区第一个字符 `❱` 应当**静止**
   在它那个固定的静止色上（一个偏红的颜色），你敲键盘、移动光标它都不变。按 `Enter` 发一个
   回合：**这时**它的颜色才开始走 —— 色相约 3.3 秒绕一圈（红 → 黄 → 绿 → 青 → 蓝 → 品红 →
   回红），同时饱和度轻轻呼吸（约 2.1 秒一个周期）。回合结束、键盘回到你手上时它**停在静止
   色**上。判断标准是「像在呼吸」；**它不该闪** —— 如果一秒跳一格，是节拍太粗（`PULSE_FRAME`
   是唯一的旋钮）；如果它空闲时也在动，说明那条 `if state.busy()` 守卫丢了，是回归。
5. **提示符占两列**：在 `❱ ` 后面打字、按 `←` 走光标、敲到软换行 —— 草稿应当从**第 3 列**
   开始（提示符 2 列），换行的行首缩进也是 2 列。**这一条专门查模糊宽度**：有些终端（尤其
   CJK 配置）把 `❱` 这类字符按双列画，那时整个输入区右移一格、光标与文字对不上 ——
   看到了就说明要换一个 glyph，代码那边只有 `editor::PROMPT` 一个常量要改。
6. **左栏完全静止**：跑一个回合，左栏的 mark（宽档那条 `fs-agent` 字符画）与窄档的身份行
   `fs-agent 0.1.0` 都应当**一动不动** —— 下落动画已关（票 08）。如果看到短横在落、在转、
   或者整块变色，那是有人把它接回去了：色环与下落两套代码都还在仓库里，但都不在屏幕上。
7. **60ms 的节拍不该被拖慢**：让 agent 跑一个会疯狂输出的命令（比如 `yes` 那种要被截断的
   输出），再看提示符：**它应当照样在呼吸**。如果输出越猛它越不动，说明脉冲那条臂被饿死了
   （实现上脉冲走的是 `interval` 而不是每轮重建的 `sleep`，正是为了这条）。
8. **空闲不烧 CPU**：空闲时那台时钟**不存在**（那条 `select!` 臂带 `if state.busy()` 守卫），
   所以 `top` / `htop` 里空闲的 fs-agent 应当几乎不占 CPU；只有跑回合时才会每 60ms 醒一次、
   重画两个格子。空闲还在稳定地转，说明守卫丢了，是回归。
9. **切进忙碌 / 回合结束时不跳**：提示符从静止色**开始走**（第一帧就是静止色的下一帧，
   不是另一个颜色），跑的过程里连续变色；回合结束时它回到静止色 —— 那是**有意的**一次切换，
   意思是「轮到你了」。如果它在回合中间莫名回零、或者静止色每次都不一样，那是计数器归零的
   时机出了问题（它应当**只在运行结束时**归零）。

## ⑰ 模式循环与 `todo` 标签

这两样都是这一轮新加的，固定尺寸的 buffer 已经把状态行的文案、标签的进退、页内容与命中
矩形断言过（`tests/render_layout.rs`、`tests/modes.rs`）；真终端要验的是**按键手感**、
**字形**与**28 格宽度下读起来够不够**。

1. **`Shift+Tab` 循环四档**：空闲会话起步在 `询问`（`[permissions] mode` 的默认档），所以按
   `Shift+Tab` 时状态行的 `模式 …` 依次变成 `工作区` → `自动` → `只读` → `询问`（四下回到起点；
   若启动时写了 `--mode readonly`，起点就是 `只读`）。顺序是**严格度**，所以按一次总是松一档。
   **不再有任何计划模式的弹窗、提示或 `/plan` 命令** —— 如果按下去弹出一个问「覆盖 / 追加 /
   保留」的框，那是没删干净。
2. **档位真的生效**：切到 `只读`，让模型写一个文件（或跑一条会写东西的命令）：它应当被拒，
   动作不执行，拒绝理由里写着 `mode readonly`（`sessions show` 里看 `PermissionDecided.reason`）。
   再按一下 `Shift+Tab` 到 `询问`，同一个动作再试：这次会弹权限模态。
3. **`todo` 标签的出现**：新会话里左栏只有 `调用量` / `轨迹` / `文件`。让模型干一件会立待办的
   活（例如「把这个仓库里某个文件改一下」）：第一条非空 `todo` 调用落地后，`todo` 标签**插到
   `调用量` 右边**。点它，页上应是一行一项（`☐` / `▸` / `✓` + 内容）加最后一行 `已完成 n/m`。
4. **常驻**：让模型把清单全部标完、甚至清空（`items: []`）：标签**仍然在**，页上只剩
   `已完成 0/0`。这是用户选的语义（一旦出现就不再消失），**不是 bug**。
5. **`＋N 项` 在窄档**：把窗口收到 80–119 列（左栏 28 格），让清单长到十几项：页上应只画得下
   几行，计数行**上面**那一行写 `＋N 项`。读一下这个数字与那几行的截断是否清楚 —— 28 格下
   一项内容大约 24 格，看不清就如实记下来（那是要重新议的取舍，不是 bug）。
6. **执行者的清单不上左栏**：让模型派一个执行者去做会立待办的活（`task` 一段多步的 brief）：
   执行者的 `todo` 调用在转录里各占一行，而左栏的 `todo` 标签**不动**（如果会话此前没有
   主会话的清单，它甚至**不该出现**）。
7. **旧会话**：`--continue` 一个升级前的老会话（流里有 `PlanMode` 注入）：`todo` 标签**不该**
   因为历史而出现（历史里没有 `todo` 调用），状态行照旧显示这次启动的档位。

## ⑱ 沙箱：内核真的拦住了

前两层（`wrap()` 的逐字断言、`tests/sandbox.rs` 的集成与那条真机测试）覆盖得到的东西不在
这里。这一节记的是 **2026-10-01 在一台 Linux 机器上逐条跑过的原文与结论**（bubblewrap
0.13.0，非特权用户 uid 1000）。跑的是 `wrap()` 拼出来的那条 argv —— 它的逐字形状由
`tests/sandbox.rs` 钉住，所以手工命令与 fs-agent 真正会跑的东西是同一条。这台开发机**没有
provider key**，所以「经由 `bash` 工具」的整条链路由 `tests/sandbox.rs` 的端到端测试覆盖
（`PATH` 上放一个假 `bwrap`，断言它真的被 spawn、原命令落在 `--` 之后、不可用时是工具错误），
而**内核行为**在这里。

准备：工作区取 `W=$(mktemp -d)`（注意它在 `/tmp` 下 —— 这恰好是第 3 条要验的那件事），可写根
取 `C=$(mktemp -d)`，然后按「整机只读 + 私有 `/tmp` + 工作区与缓存可写 + 四个 unshare」那条
前缀跑。下面每一条都是先做、后记原文。

1. **写工作区**：新建一个文件、再把它删掉，都成功，宿主上读得回内容。这是「工作区内的修改
   照常」那条用户故事，也是沙箱**不该**挡住的唯一一类写。
2. **写 `$HOME`、写 `/etc`** → 都被拒，原文里带「只读文件系统」，退出码 1。回到宿主侧确认那
   两个文件都没出现 —— 拒绝不只是屏幕上的一个字，落盘也没有发生。
3. **工作区在 `/tmp` 下**（本清单第 3 条为什么存在）：一开始按 spec 的字面顺序把私有 `/tmp`
   排在可写根之后，结果连工作区里写自己的文件都报「只读文件系统」—— 挂载是叠上去的，后挂的
   tmpfs 把那条 `--bind` 盖掉了。实现改成「私有 `/tmp` 在所有可写根之前」，重跑第 1 条通过。
   **顺序是行为，不是风格**。
4. **`/tmp` 的语义**：同一条命令里建一个目录再列它，成功；**下一条命令**再列同一个路径，报
   「没有那个文件或目录」。与 `bash` 工具描述里那句「每次调用都是新的」一致。
5. **遮住 provider key 那一格**（那台机器上配置文件真实存在、两千多字节）：沙箱里读它报
   「没有那个文件或目录」，列目录得到 **0 个条目**（是「目录还在、但是空的」），往它里面写报
   「只读文件系统」。也就是说这不是「藏起来」，而是一个空的只读挂载。
6. **遮住 `~/.ssh`**（宿主上真实有 agent、authorized_keys、config 三样）：沙箱里列目录同样是
   **0 个条目**，读私钥报「没有那个文件或目录」。
7. **工作区里的 `.env`**：往里追加报「只读文件系统」；换 `.env.example` 追加则成功 —— 模板
   后缀不携带真密钥，不在保护之列，两条都要看到。
8. **`git` 的读写**：`status`、`add`、`commit`、`log` 全部正常，两次提交都在历史里。
   `git config user.name hack` 被拒，报的是「无法写入配置文件 .git/config: 设备或资源忙」；
   写 `.git/hooks/pre-commit` 被拒，报的是「只读文件系统」。两处的措辞不同这一点值得记住：
   **拒绝消息从来不是判据**，判据只有 `bwrap: ` 前缀一条。提交能跑的原因也很具体：
   `.git/index` 没有被压回只读，被压住的只有 `config` 与 `hooks` 两个入口。
9. **可写根**：往缓存目录里 touch 一个文件，成功，宿主上确实看得到它。这台开发机的 `$HOME`
   本身处在一个只读挂载里，所以「写 `~/.cargo`」在**这个环境**里验不了 —— 换 `/tmp` 下的一个
   目录代替，`--bind` 的语义完全相同。整条 `cargo test` 没在沙箱里跑（要联网拉依赖），可写根
   本身由这一步验。
10. **探测**：用规格里那条最小 profile 跑 `/bin/true`，退出码 0，说明这台机器上可用。注意它比
    spec §3 的原文多带一个 `--proc /proc`：§3 的另一条要求是「`/proc` 建不起来也算不可用」，
    两条要一起满足。

**没验到的，如实记在这里**：这台机器没有 provider key，所以下面两条只由 `tests/sandbox.rs`
的端到端测试覆盖（假 `bwrap`），**没有**在真会话里手工跑过：

- 「把 `PATH` 上的 `bwrap` 拿掉再起一次 → `bash` 拒绝运行、文案给出两条出路」；
- 「把 `[sandbox] mode` 设成 `"off"` → 照旧直接跑」。

它们的内核那一半（真 bwrap 起来、真拦住区外写）由 `tests/sandbox.rs` 的
`the_real_bubblewrap_keeps_writes_inside_the_workspace` 在有 `bwrap` 的机器上每次 `cargo test`
都真跑一遍。

## ⑲ `workspace` 档与升级手势

纯函数那一层由 `tests/permission_gate.rs` 钉住（四档 × 方向 × 升级的矩阵），端到端那一层由
`tests/workspace_mode.rs`（文件工具的区外写、组装期拒绝）与 `tests/sandbox.rs`（假 `bwrap`
下的升级全链路：被拒 → 带 `escalation` 重试 → 弹一次问 → 批准后 argv 里多一条 `--bind`）
覆盖。真终端要验的是**手感**、**弹窗读起来够不够**、以及真内核下那条出口确实通。

前置：这台机器上 `bwrap` 可用（第 ⑱ 节的那条探测通过），工作区取一个可写的临时目录，
`[permissions] mode = "workspace"`，并在 `$HOME` 下准备一个**不存在**的目标目录
（例如 `~/.npm`）—— 升级要验的正是「建它」。

1. **区内一路放行**：让模型在会话工作区里 `touch a.txt`、`cargo test`、`git commit` 各来一次：
   一次都不该弹窗。这一档存在的意义就是这一步。
2. **区外写弹一次问**：让模型 `bash -lc "touch ~/x"`（或写一个 `~/.npm/...` 的文件）。第一条
   命令应当**失败**（内核说只读文件系统），而这是**命令结果**、不是工具错误 —— 转录里照常
   显示退出码与 stderr。
3. **升级弹窗那几行**：模型带上 `escalation` 重试同一条命令时，弹窗除问题行与命令行之外还应有三行：
   `被沙箱拒绝，申请写工作区之外`、`理由：…`、`要放开的路径：…`，而**命令行仍是最后一行**。执行者发起的询问，第一行要点名
   `执行者 <id> 发起`；讨论者发起的写 `讨论者 <id> 发起`。
4. **批准之后真的通**：点 `[y] 允许`，同一条命令成功，**宿主上真的出现那个文件**
   （`ls -l ~/.npm/probe`）。再让模型跑**另一条**越界命令：它应当照旧被拒 —— 批准只活在那一次
   调用里。顺便试一次**声明一条不存在的路径**（例如 `~/.npm/newdir`）：结果应当是一条写明
   「路径不存在」的工具错误，而不是一条什么都没发生的成功 —— `bwrap` 只能绑已经存在的源。
5. **只给一次重试**：对同一条被拒的命令连着来两次带 `escalation` 的重试：第一次弹窗，拒绝之后
   第二次**不再弹**，命令照常失败。模型该换做法或报告受阻。
6. **写死的边界批不了**：让模型申请 `~/.ssh/authorized_keys`：**不问**，直接拒，理由里写着
   「这一条没有任何通道放宽」；工作区里的 `.env` 与 `.git/config` 同理。三个都试一遍。
7. **`outside_read` 三个值**：在 `[permissions] mode = "ask"`（或 `workspace`）下分别配
   `outside_read = "deny" | "ask" | "allow"`，让模型读一个工作区之外的普通文件
   （**别拿 `~/.config/fs-agent/config.toml` 当第一个探针** —— 那一条会连带验打码）：
   `deny` 时不问直接拒；`ask` 时弹一次问；`allow` 时不问、读得到。
8. **没有沙箱就没有这一档**：把 `[sandbox] mode` 改成 `"off"`（或者把 `bwrap` 从 `PATH` 上
   拿掉），再以 `--mode workspace` 启动：**启动错误**，stderr 上写着这一档需要沙箱，并给出
   两条出路（换回 `"bwrap"`、或换一档）。退出码非零。同一份配置换成 `--mode ask` 启动，
   再按 `Shift+Tab`：`工作区` 那一档应当被**跳过**（`询问` → `自动`），循环里进不去它。
9. **状态行照旧**：这一档下状态行显示 `模式 工作区`；沙箱状态有它自己那一行（转录里的叙述、
   `sessions show` 里那一行），这里不重复。

## ⑳ 外壳收干净：没有外框、虚线框架、详情居中与按位置滚动

这一轮（[`.scratch/tui-chrome/spec.md`](../.scratch/tui-chrome/spec.md)）给外壳做了减法：
四周不再有边框、状态行上方那条线也不画了、剩下的框架全换成**更沉的虚线**、详情覆盖层改成
**屏幕居中**、问题立着时**滚轮按指针位置分派**。几何与字形的纯函数那一层由
`tests/render_layout.rs` 钉住（118 条用例）；真终端要验的是**读起来舒不舒服**、
**虚线分不分得清**、以及那个随配色而变的深度。

前置：120×24 的终端，一个能写文件的会话（要看到转录、状态行与输入区同时在屏上）。

1. **四边没有框线**：转录从终端第 0 行开始、左栏从第 0 列开始，最外一圈再没有一条线。
   左栏与主列之间仍然有一条竖虚线，两栏还分得开。
2. **状态行上方那条线不在**：转录的最后一行紧贴着状态行，两者之间没有横线；输入区上方
   与提示行上方那两条横线还在（一共两条，不是三条）。
3. **三层虚线分得清**：竖分隔线 `┆`（三重）、两条横线 `┄`（三重），而**回合条**的普通格仍是
   `┊`（四重）、焦点格是 `┃`。三者同屏时不该糊成一样。
4. **`CHROME_LINE` 的深度**：`src/render/tui.rs` 的
   `CHROME_LINE = Color::Rgb(0x4a, 0x4a, 0x4a)` 是照「框架退到内容后面」取的。**你自己的
   终端背景色**下它是否还看得见、是否仍然偏亮，只有你看得出来 —— 不合适就改那一个常量，
   并把实测值记在这里。（这是本轮唯一一个随终端配色而变的取值。）
5. **详情覆盖层屏幕居中**：点一个工具调用那一行，打开它的详情。框应当在**屏幕**正中而不是
   偏右；它现在压着左栏，也压住输入区左边那几列 —— 这是「屏幕居中」的代价，看一眼能不能
   接受。
6. **问卷立着时的滚动**：让模型发一个 `ask_user_question`。鼠标放在**转录**上滚 → 转录滚动，
   选项高亮不动；鼠标放在**问卷**（底部那块）上滚 → 高亮走，转录不动。
7. **权限模态立着时的滚动**：弹一次权限询问。指针在**模态之外**（比如左栏那一列）滚 → 它
   背后的转录滚动；指针在**模态之内**滚 → 什么都不动（模态没有可滚的内容）。
8. **40×10 那一档**：把终端缩到 40×10。转录 3 行、输入区 3 行、提示行在第 9 行 —— 外框与
   状态行上方那条线让出来的那三行都归了内容，读一眼确认它仍然能用。
9. **左栏顶上那一行空行**：标记（宽档）或 `fs-agent 0.1.0`（窄档）从第 1 行开始，第 0 行只有
   那条竖虚线；页签条与读数页也跟着下移了一行（2026-10-01 真机反馈）。
10. **竖线贯通**：状态行、输入区、提示行左边那一列的 `┆` 与上下其它行连成**连续的一列**；
    输入区上方与提示行上方那两条横线接在它**右边**（`┆┄┄┄…`），不再把它截断。

## ㉑ 转录里的 Markdown：表格、代码块高亮与续行顶格

这一轮（[`.scratch/markdown-render/spec.md`](../.scratch/markdown-render/spec.md)）把 Markdown 的
**解析**交给 `pulldown-cmark`（[ADR 0008](adr/0008-markdown-parsing-by-pulldown-cmark.md)），
渲染仍是自己的：表格从「join 竖线」变成真网格、代码块接回 tree-sitter 高亮并扩到十种语言、
assistant 的续行不再缩进。几何与结构由 `tests/render_markdown.rs` 与 `tests/render_layout.rs`
钉住；真终端要验的是**语法高亮与 CJK 折行的组合**——那只有真终端看得出来。

前置：120×24 的终端，一个能写文件的会话，让模型吐几段带结构的回答（也可以直接把下面
几段贴给自己看：`fs-agent` 里用户输入不走 Markdown，所以要看**回答**）。

1. **表格装得下**：让模型吐一张 3–4 列的表。表头是粗的、下面有一条 `─┼─` 分隔线，各列
   沿着竖直方向对得齐，表格顶格、**撑满转录的宽度**（余量在最后一列）。
2. **表格装不下**：把终端拉窄到 80 列以下再来一次。装不下的格子应当**折行**（不是截断），
   同一行的其它格一起撑到同样的高度，网格的竖线在每条续行上都连着。
3. **代码块的语言名**：贴一段 ```rust。块**上方**单独一行，语言名**右对齐到转录的右缘**，
   那一行不缩进；代码**两格缩进**，`**不是粗体**` 这类字面量原样保留。
4. **语法高亮分得开**：同一段 Rust 里关键字、字符串、注释的颜色要分得开；再让模型给一段
   超宽代码行，折出来的**续行仍以两格缩进开头**（不是顶到最左边）。
5. **十种语言各看一眼**：`rust` / `bash` / `json` / `toml` / `html` / `javascript` /
   `typescript` / `php` / `sql` / `python` 各来一个最小样例（比如 `struct A;`、`echo $HOME`、
   `{"a": 1}`、`a = 1`、`<p>x</p>`、`const a = 1`、`const a: number = 1`、`<?php echo 1;`、
   `SELECT 1 FROM t`、`def f(): pass`）。十种都该有**非默认色**的片段；认不出的语言
   （比如 `brainfuck`）该**照原文显示语言名**、代码退纯文本，而不是消失。
6. **图片语法**：让模型写一句 `![图](https://example.com/a.png)`。屏幕上是
   `[图片] 图 (https://example.com/a.png)`，而不是旧的 `!图 (…)`。
7. **assistant 的续行顶格**：问一句会写出多行的回答。除第一行那个 `[name] ` 之外，每一行都
   从**最左边**起（不再是 11 格缩进）；而自己用 `Ctrl-J` 敲一条多行消息时，续行**仍然**按
   `[name] ` 的显示宽度对齐缩进。
8. **拖动宽度时表格不碎**：让一张表停在屏上，然后**慢慢拖动终端宽度**。表格应当跟着按新
   宽度重排（列仍然对齐、该折的折），而不是留着一份按旧宽度排好的行、被硬折成一堆错位的列。

## ㉒ 目标循环：禁言、`Esc` 确认框与翻页那一刻

这一轮（[`.scratch/goal-loop/spec.md`](../.scratch/goal-loop/spec.md)）给无人值守的目标循环
定了人机边界：跑着的时候输入区禁言（§5），`Esc` 先问一句再决定停不停（§5），而上下文过八成
时压缩 + 翻页（§7）。几何与状态由 `tests/render_layout.rs`、`tests/goal_loop.rs` 与本文件
里 tui 的那几条单测钉住；真终端要验的是**手感**。

前置：`workspace` 或 `auto` 档（`ask` 档下 `/loop` 会拒绝启动，这正是 §5 那条前提），先
`/goal-new <名字> <来源>` 生成一份清单，然后 `/loop <名字>`。

1. **输入区禁言**：循环跑着的时候随便打字。字符**不落进**草稿，提示符与草稿都不动；方向键、
   `PgUp`/`PgDn` 与 `Shift+Tab` 照旧响应（转录能滚、模式能换）。
2. **`Esc` 默认停在「继续跑」**：按一下 `Esc`，中段立起那个确认框，两个答案里「继续跑」在前。
   直接按 `Enter`、或者再按一次 `Esc` —— 框关掉，循环**照常在跑**（转录还在往下走）。
3. **明确停下**：再按一次 `Esc`，这回按 `s`。循环停下，转录里出现「目标 … 被主动停下」那一
   行，而流上落了一条 `GoalStopped { reason: user_stopped }`（`sessions show` 看得到）。
4. **停完回空闲**：停下之后提示符回到静止色、pulse 归零，`/quit`、`/undo` 这些照常能用，
   而 `/loop` 再跑同一个目标时，进度从流派生出来（已完成的那几条还在）。
5. **翻页那一刻的观感**：让它跑到过八成（长活最容易，或者把 `[goals] compact_at` 临时调低）。
   翻页那一刻：转录里出现「历史压成摘要：会话 … → 会话 …」这一行，新的 `SessionStarted`
   跟着落下来，侧栏的进度接着走 —— **不能看起来像崩了**。`sessions` 里旧的会话仍在，
   `--continue` 打开的是新的那个。
6. **过半提醒只来一次**：过 50% 时转录里出现「上下文已到 …%，已提醒模型把还没落流的东西落
   下来」。此后连续几个回合都在 50% 以上，这一行**不再重复**（每轮注入会每轮打掉前缀缓存）。

## ㉓ 终端标题：内容、更新与还原

这一轮（[`.scratch/terminal-title/spec.md`](../.scratch/terminal-title/spec.md)）让跑着
fs-agent 的那一格终端说得出自己在哪个目录、在不在跑。能自动化的那两条腿已经钉住：拼法与
40 列封顶在 `tests/wording.rs`，状态与目标名的来去在 `tests/render_tui.rs`，「我们发出了
哪些序列」在 `scripts/tui-startup-check.py`（保存 `CSI 22 t`、写入 `OSC 0`、还原 `CSI 23 t`）。
剩下这一半只有真终端答得了：**标题看起来对不对、退不退出得回来**。

前置：`cargo build`，`cd` 进一个基名认得出的目录（仓库根就够），跑
`./target/debug/fs-agent`。要验状态变化的那几条得能触发一次权限询问、或者让一回合跑起来。

1. **内容**：跑起来看标题。路径段是工作目录的形态 —— 落在 `$HOME` 之下时写 `~/…`
   （`~/code/fortystory/fs-agent`），别处写 `父目录/基名`；空闲时**没有**状态词。用
   `--cwd /别的/目录` 起来，路径段跟着那个目录走。
2. **更新**：让一回合跑起来（问一句话），标题里出现 `运行中`；出现权限询问或问卷时变成
   `等你`；`--continue` 重放期间是 `重放中`，重放收敛后回到空闲那条。`/loop <名字>` 跑着时
   目标名跟在后面（`… · 运行中 · <目标名>`），`/loop` 停下后它消失。
3. **不闪**：一次长回合里盯着标题。它只在状态或目标变时写一次，**不随增量文本翻动**。
4. **还原**：进 TUI 之前先用终端自己的办法给这一格设一条标题（例如
   `printf '\e]0;原来的标题\a'`），然后跑 fs-agent、退出（空闲时双击 `Ctrl-C`、`/quit`
   各一次）。退出之后标题应当回到那一条；`--continue` 退出也一样。
5. **三种终端各走一遍**：`xterm`、`tmux`（窗格里的 TUI）、一个 VTE 系（`gnome-terminal` /
   `Tilix` / `xfce4-terminal` 任一），每一处都做第 1–4 条。
6. **tmux 的 `allow-passthrough`**：`tmux set -g allow-passthrough off` 与 `on` 各走一遍
   第 1–4 条，两种结果都如实记下来（开 / 关各自是更新、还原，还是没动）。
7. **不支持的终端如实记**：某个终端上如果保存 / 还原是 no-op、退出后标题停在我们写的那条，
   就在这里点名记下来 —— 这是**接受**的退化，不加 fallback、也不补发「清空标题」（那会把
   用户原本的标题抹掉，比不还原更糟，spec §4）。
