# 两个视图的滚动与跟随语义

Type: grilling
Status: resolved
Part of: ../map.md
Blocked by: —

## 问题

冻结项 5 定了「轨迹视图有自己的滚动与贴底跟随」，但它与对话视图的关系还没定死。要谈的是：

1. **切页**：从轨迹页切到调用页再切回来，滚动位置保留，还是回到底部？
2. **跟随**：两个视图各自的 `follow` 独立吗？用户在轨迹页回看时，新内容到达要不要像对话视图那样亮出「有新内容」的指示（`pane` 的 `fresh` / `holding` 那一套，`src/render/pane.rs:226-253`），还是安静地在底部累积？
3. **回到最新**：冻结项 13 已定「轨迹视图只吃滚轮」，那它「回到底部」靠什么——滚轮到底就算，还是需要一个可点的指示器（对话视图今天有指示器，`src/render/tui.rs:4098-4102`）？
4. **裁剪**：`pane::CAP = 20_000`（`src/render/pane.rs:19`）是**每个视图**各算，还是**每个源**只算一次？冻结项 11 要两个 pane 同步裁剪，那是谁触发、谁记账？
5. **联动**：点轨迹视图里的一行，要不要把对话视图滚到对应的那一回合？反向（对话里点某回合，轨迹跟着跳）呢？
6. **详情覆盖层**：从轨迹行打开的详情，关掉之后滚动位置归谁——今天 `close_detail` 会把转录送回底部并恢复跟随（`src/render/tui.rs:5123-5129`）。

## 产物

一张定死的滚动语义表（每个视图持有哪些状态、每个手势落在哪里、切页与开关覆盖层的前后关系），落进 `/to-spec` 的 spec。

## 咨询的 skills

`/grilling` + `/domain-modeling`（新术语要进 `CONTEXT.md`：轨迹视图 / 对话视图的滚动状态各自叫什么）。

## 作答

**决定（2026-10-05，HITL：维护者拍了六条）**：

1. **切页保留滚动位置** —— 每个视图各持自己的 `top` / `follow`，切页只换「谁被画」。
2. **两个视图的 `follow` 独立**，各自有 `fresh`；**轨迹视图也画那个「N 条新行」指示器**。
3. **回到最新**：滚到底即恢复跟随（既有语义，`pane.rs:178-191`，免费继承）+ 可点指示器（复用 `tui.rs:4098-4102` 那个矩形）。
4. **裁剪各自记账**：每个 pane 各按 `pane::CAP` 裁自己的窗口，平行表按 `Pane::push` 返回的 dropped 裁；**两个窗口不要求相同**。`painted` 保持今天的全量保留 —— 实测它今天就不裁（`tui.rs:678` / `1789` / `2011` / `2090`，全仓无 `truncate` / `drain`），本票不改变这一点。
5. **不做跨视图联动**：点轨迹行只开详情；从对话跳回某回合仍走**回合条**。
6. **详情关掉后还原打开前的位置**（维护者选 (b)，**这是对今天行为的有意改动**）：两个视图各记一份「打开前的滚动状态」，关掉把该视图放回原处。

**Q6 的精确后果**（给 `/to-spec` 与实现票）：

- `close_detail`（`tui.rs:5123-5129`）从「无条件回底 + 恢复跟随」改成「还原打开方记下的位置」；`open_detail`（`5109-5117`）要多接「打开方是谁」与「打开前的滚动状态」，后者存在 `DetailView` 旁边，不要塞进覆盖层自己那份 `top`。
- `draw_detail` 每帧的冻结那两行（`5279-5280` 的 `set_following(false)` + `set_holding(true)`）要**按打开方**作用：打开详情只冻结**打开它的那个视图**，另一个视图继续跟随（决定 2 的直接后果）。
- **行为差别的半径只有一种情形**：打开前**在回看**（`follow == false`）时，今天会被弹到底部，改后回到读者原来读的那一行；打开前**贴底**的情形，还原就等于跟随，行为与今天逐字相同。
- **要改的既有测试**：`tests/history_replay.rs:1044-1055`（「`Esc` 关上它，视口回到最底下 …… 而视口又开始跟随了」）断言的正是旧行为，必须改写。

**本票实测的两条事实**：

- 滚到底恢复跟随是 `Pane::scroll` 的既有语义（`pane.rs:178-191`），轨迹视图免费继承；`scroll_to_source` 同理。
- `fresh` / `holding` 的语义（`pane.rs:226-253`）与详情覆盖层的关系照旧，只是作用域按视图分开。

**未证实**：没有实跑 `cargo test` 去数 Q6 波及多少用例 —— 上一条是按 grep 到的断言点给的最小集合。
