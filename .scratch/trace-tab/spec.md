# 轨迹视图与对话视图的分工：构建计划

Status: ready-for-agent（决策图 [`map.md`](map.md) **6/6 已走完**，可以交给 `/to-tickets` 拆实现票）

- **来源**：wayfinder 决策图 [`map.md`](map.md)（charting 两轮 grilling 十四问）+ 四张已 resolved 的决策票：[页高撑满之后左栏三页的形态](issues/03-prototype-sidebar-page-height.md)、[轨迹视图在 40/28 列里的排版与密度](issues/01-prototype-trace-page-layout.md)、[两个视图的滚动与跟随语义](issues/04-grilling-scroll-and-follow.md)、[两个 Pane 共享 `painted` 的改造面](issues/05-research-shared-painted-two-panes.md)。产物在 [`prototype/`](prototype/) 与 [`research/`](research/)。
- **术语**：`转录`（Transcript）仍是「事件流 → 展示单元的**共享层**」；本 effort 新增**轨迹视图（Trace）**（左栏 `轨迹` 页）与**对话视图（Conversation）**（主列那块区域）；`跟随（Follow）` 是一个视图自己的滚动意志。三个词条已进 [`CONTEXT.md`](../../CONTEXT.md)。

## 问题陈述

今天界面只有一条流。主列的转录把**对话**与**过程**混在同一条时间线上：用户提问与助手回答之间，夹着工具调用、思考行、上下文注入、回合边界、hook 裁决、执行者进出与用量行。

三个后果：

1. **回看「我们刚才聊了什么」要在一堆工具行里翻。** 一次用了三次工具调用的往返，对话本身只剩三四行，其余全是过程。
2. **过程行挤占行数与宽度。** 原型实测：一条 5 行的回答在 28 列里折成 6 行 —— 它自己就能吃掉左栏轨迹页的整屏。
3. **左栏的 `轨迹` 页签从 `tui-sidebar` 起就挂着「此页尚未实现」**，而它本该是这条流的第二个去处。

## 方案

把转录拆成**两个视图**，共用同一份事件流与同一份块列表：

- **对话视图**（主列）：只画**用户文本**、**assistant 正文**，加一份**保留清单**（错误、会话中断、失败的 hook、`Notice` 整类，以及非正常的收尾行；2026-10-05 维护者把权限裁决、诊断与边界行收进了轨迹，见 §2）。宽度与今天一致，长内容照旧全文。
- **轨迹视图**（左栏 `轨迹` 页）：画**全量块**，对话本身也在内。宽档 40 列、窄档 28 列；消息正文画**首行 + `…`**（点开看全文），其余块今天就已经各占一行。
- **不降级**（2026-10-05 维护者改掉了原先的 §6）：左栏不可见时（`w < 80` 或 `Ctrl-O` 收起）对话视图**照旧只收保留清单** —— 收起左栏就是「过程行暂时看不到」。

两个视图各持自己的滚动位置与跟随意志，互不影响。

## 用户故事

### A. 分工

1. 作为用户，我想让主列只留下我问的话与助手答的话，以便回看对话时不被工具行打断。
2. 作为用户，我想让全部过程行（工具、思考、注入、回合边界、hook、执行者、用量）进左栏轨迹页，以便它们仍然在、只是不在对话里。
3. 作为用户，我想让错误、会话中断、权限裁决与 hook 拒绝**仍然留在对话视图**，以便立刻知道「为什么没有回答」。
4. 作为用户，我想让轨迹视图画**全量**块（含对话本身），以便它是这条流的完整记录。
5. 作为用户，我想让讨论会话里**讨论者的发言留在对话视图**、讨论的**过程行**进轨迹，以便讨论仍读得通。
6. 作为用户，我想让合成器的结论留在对话视图，以便那是「回答」。
7. 作为用户，我想让执行者（子 agent）的行全进轨迹，以便对话不被委派的细节淹没。
8. 作为用户，我想让 `Notice` 那一类（命令回执、启动横幅、错误报告、目标与重试提示）**留在对话视图**，以便 `/undo`、`/goal` 这些命令的回执不会消失 —— 口径是**整类留下**。

### B. 轨迹视图的排版

9. 作为用户，我想让轨迹页每条块只占合理的一行或几行，以便在 40 / 28 列里读得下去。
10. 作为用户，我想让消息正文只画**首行 + `…`**，以便一次回答不霸屏。
11. 作为用户，我想**点开那条消息看全文**，以便截断不丢信息。
12. 作为用户，我想让窄档（28 列）的前缀去掉方括号，以便省下的列给内容。
13. 作为用户，我想让 markdown（表格、代码块）照常排版，以便轨迹里的回答仍读得像回答。
14. 作为用户，我想让工具行、思考行、注入行与叙述行各占一行（今天就是这样），以便轨迹页的密度可预期。
15. 作为用户，我想让轨迹页里点一行能开详情覆盖层，以便看工具参数、思考全文、注入正文。

### C. 对话视图

16. 作为用户，我想让对话视图的宽度与今天一致，以便回答的排版不变。
17. 作为用户，我想让讨论会话里多条发言按发言者排布（今天的标签与颜色照旧），以便分辨谁说的。
18. 作为用户，我想让错误行在被掏空之后的对话视图里仍然显眼，以便不忽略它。
19. 作为用户，我想让回合条仍然指示「我在对话的哪一段」，以便位置感不变。
20. 作为用户，我想让对话视图的形态**一律照旧**（speaker 标签、`▸` / `⋮`、rail 段首规则都不动），以便这次改动的全部内容只是「过滤掉进轨迹的那些块」。

### D. 左栏与页高

21. 作为用户，我想让左栏页区**撑满**剩余高度（120×24 → 15 行、80×24 → 19 行），以便轨迹视图有行可读。
22. 作为用户，我想让调用量页仍然贴顶画它的 6 个字段，以便读数页的观感不变。
23. 作为用户，我想让 todo 页自动画下更多条目（今天塞不下才画 `＋N 项`），以便页高变大是白送的改善。
24. 作为用户，我想让极矮终端（120×10 / 80×10）保住那行文字身份，以便知道这是什么程序。
25. 作为用户，我想让页签条的 y 与命中矩形不变，以便点击行为不动。

### E. 滚动与跟随

26. 作为用户，我想让轨迹视图**独立滚动**，以便回看过程时对话视图仍跟着最新。
27. 作为用户，我想让轨迹视图在离开底部时显示「N 条新行」并可点回到最新，以便不丢新内容。
28. 作为用户，我想让滚轮按指针位置分派（指针在左栏就滚轨迹页），以便两个视图共用一个滚轮。
29. 作为用户，我想让切页**保留**滚动位置，以便切到调用量页再回来不丢阅读进度。
30. 作为用户，我想让详情关掉之后**回到我打开它之前的位置**，以便回看时不被打断。
31. 作为用户，我想让详情打开时**只冻结打开它的那个视图**，以便另一个视图继续跟着新内容。
32. 作为用户，我想让轨迹视图只吃滚轮（键盘三键仍归对话视图），以便键位表不动 —— 代价是纯键盘用户滚不了轨迹页，这条**显式接受**。

### F. 不变量

33. 作为用户，我想让事件 schema 一个字节不改，以便已有会话仍能重放。
34. 作为用户，我想让 plain 与 headless 渲染器不受影响，以便管道化照旧。
35. 作为用户，我想让模型可见文本一个字节不变，以便前缀缓存不被废掉。
36. 作为用户，我想让 `--continue` 的历史重播照旧长出来（只进对话视图），以便回放行为不变。
37. 作为用户，我想让 `cargo test` 全绿、`cargo clippy` 干净、`cargo fmt --check` 只留既有漂移，以便改动可验收。

## 实现决定

### §1 两个视口与共享源

- **共享源是 `painted`**（宽度无关的块列表）。`RenderedLine` **不能**当共享源：markdown 的表格列宽与代码续行缩进在进入 pane 之前就按宽度排过。
- **两个 `Pane`**：各持自己的折行缓存、宽度、`top`、跟随与「新行」计数；各自按 `pane::CAP`（20 000 源行）裁自己的窗口，**两个窗口不要求相同**。
- **平行表每 pane 一套**：对话 pane 有行链接表 + 回合条，轨迹 pane 有自己的行链接表。裁剪的**唯一权威**是 pane 的 push 返回的「本次丢了几行」；绘制侧据此裁平行表，删掉今天那个独立数 `CAP` 的循环（它与 pane 的 evict 只是碰巧同速）。
- **宽度变化带目标掩码**：只清空并重放**宽度真变了**的那个 pane（重放是追加，对没清过的 pane 重放会推两遍）；回合条的清空只在对话 pane 重放时做。判定位置上移到两个宽度都知道之后。同一帧里排版用的宽度与 pane 取景的宽度必须同源。
- **分派点在块的绘制处**：对每个被选中的目标各排版一次（发言者配色分配是幂等的），结果喂给各自的 pane。流式尾巴不需要新缓存：pane 每帧取景时就按自己的宽度折一次。
- **`painted` 的保留策略不变**：它今天全量保留（全仓没有对它做裁剪），本 effort 不改。
- 细节与切片见[两个 Pane 共享 `painted` 的改造面](issues/05-research-shared-painted-two-panes.md)与[它的调研](research/02-shared-painted-change-surface.md)。

### §2 哪些块进哪个视图

- 分工是一个**纯函数**（块 → 目标集合），住在绘制侧；块的产生（`Block` 层，plain 与 TUI 共用）一个字节不改。
- 对话视图收：用户消息、assistant 正文、**保留清单**。
- **保留清单**（2026-10-05 维护者收紧之后）：用户消息与 assistant 正文、`AgentError` / `SessionError`、`SessionEnded`、失败的 `Hook`、**`Notice` 整类**（命令回执、启动横幅、错误报告、目标与重试提示、历史分隔线），以及**非正常**的收尾行 —— `TurnEnded` / `RoundEnded` 里严重度不是 `Good` 的那些，那是「为什么停下来」。
- **进轨迹的过程行**：回合 / 轮次的**开始**（`TurnStarted` / `RoundStarted`）、**正常的**收尾（`TurnEnded` / `RoundEnded`）、权限询问与裁决（`PermissionAsked` / `PermissionDecided`）、诊断（`Diagnostic`），加上执行者（`SpeakerId::Executor`）的全部行、`Usage`、`Divergence`、`Sandbox`、`History`、`ContextInjected`、`Tool` / `ToolFeedback`、思考行、以及**对话本身**（轨迹是全量）。
- **对话视图的形态基本照旧**：speaker 标签照旧，`▸` / `⋮` 照旧，错误行不为它新增显眼规则，rail 的段首规则不变（「单位内第一条用户消息」仍在对话视图里），讨论会话的合成器结论照旧。实现因此是「一条过滤 + 照旧渲染」，只有下面两处是例外。
- **例外一：用户消息在对话视图里右对齐**（轨迹视图仍左对齐）。要的是「我说的话靠右」那种聊天感；行级右对齐是一条现成能力（折行时也保留），不新增渲染路径。
- **例外二：三类前缀各一色** —— 注入、用户、助手要一眼分得开。今天的实际配色是：**注入 = 叙述灰**（与其它叙述行同色，所以「分不开」的正是它）、用户 = `LightGreen`、助手 = 调色板首位 `LightCyan`。改动因此只是**给注入行一个专色**（建议 `LightBlue`），另外两类不动。

### §3 轨迹视图的排版

- 宽度就是左栏页矩形的宽（40 / 28）。
- **消息**：首行 + `…`（超出即截），行上挂一个新详情 `DetailKind::Message`，全文进覆盖层；对话视图仍画全文。
- **前缀分档**：宽档 `[名字] ` 照旧；窄档去方括号（`用户 ` / `助手 ` / `讨论1 `）。今天前缀在消息归属与工具行那两处写死，要多一档「这个视图多宽」的输入。
- **markdown 照排**：把左栏宽度喂给既有的按宽排版入口，渲染器不新增分支。**未证实**：28 列下表格实际挤成什么样没跑真渲染器；若不可读，退路是「宽档照排、窄档退成纯文本」。
- **其余块**今天就已经各占一行，不改。
- **轮次之间一条分隔线**（2026-10-05 维护者改掉了原先的隔行底色）：每个**单位**（交互会话数回合、讨论数轮次 —— 与回合条同一判据）结束之后，轨迹页多画一整行虚线（`┄`，与外壳同一种框架色），下一个单位从它下面开始。线是**行**，所以滚动时它跟着内容走、不会重排；轨迹页与对话视图都**不铺底色**。
- 帧：[`prototype/trace-pages.txt`](prototype/trace-pages.txt) 与整屏示例 [`prototype/split-view.txt`](prototype/split-view.txt)。

### §4 左栏页高

- 页区高度 = **内容行 − 身份行 − 页签条**，其中内容行 = 终端高 − 顶留白；内容**贴顶**。
- 「用量字段数」那个常数（6）**退休**：它今天唯一的作用是撑页高。阶梯判据改成「身份 + 页签条 + 3 ≤ 内容行」，那个地板常数建议改名成「页的地板」。
- 实测三档：120×24 页高 6→**15**；80×24 6→**19**；120×10 / 80×10 身份行**回来了**、页区 6→5（调用量页丢「缓存」—— 那正是它字段序里第一个丢的）。
- 调用量页与 todo 页**零代码改动**：前者不看高度、最多返 6 行并从顶部画；后者本来就按页高自适应（计数行占最后一行、条目拿剩下的、塞不下才画一行 `＋N 项`）。
- 帧：[`prototype/frames.txt`](prototype/frames.txt)。

### §5 滚动、跟随与详情

- 两个视图的跟随与「新行」计数**完全独立**；切页保留滚动位置。
- 轨迹视图也画「N 条新行」指示器（复用对话视图那个矩形）；可点 = 回到底部并恢复跟随。滚到底**自动**恢复跟随是既有语义。
- 滚轮按指针位置分派（既有规则）：指针在左栏页矩形里就滚轨迹 pane，在转录里就滚对话 pane。键盘三键（翻页两键与回底键）仍只作用于对话 pane —— 代价显式接受。
- **详情覆盖层**：打开时记下「打开方是哪个视图」+ 打开前的滚动状态；关闭时**还原到那个视图**（另一个视图完全不动）；每帧的冻结也只作用于打开方。行为差别只在一种情形：打开前在**回看**时，今天会被弹到底部，改后回到原处；打开前贴底时行为与今天逐字相同。
- 既有测试 `tests/history_replay.rs:1044-1055` 断言的正是旧行为，随实现改写。

### §6 左栏不可见时不降级（2026-10-05 推翻原先的「退回全量」）

- 左栏不可见 = 页矩形为 `None`（`w < 80`，或 `Ctrl-O` 收起）。此时**对话视图照旧只收保留清单**：
  过程行只在轨迹视图里，而那一栏此刻不在屏幕上 —— 它们暂时看不到，这是明码标价的取舍。
- 规则因此只有一个：分工函数（`selects`）在任何宽度、任何左栏状态下都返回同一张表。
  原先那条「退回全量」要求分工依赖「左栏在不在」，两套规则在收起的那一刻互相打脸
  （主列刚被清干净，收起又全冒回来）。
- 这是**视图选择**，不是第二条渲染路径：块的产生、详情入口与 markdown 排版都不变。

### §7 不改

事件 schema；`Block` 层与它的产生；plain / headless 渲染器；`sessions replay` / `sessions show`；键位表；左栏的宽度两档与 `Ctrl-O` 意愿那一层；讨论会话回合条的「轮次」语义；模型可见文本。

## 测试决定

- **一个 seam：现有的 TUI 帧测试层**（`TestBackend` + 「画一帧、读屏幕」那套 helper），**不新增 seam**。理由：这次改动的全部内容都是「同一帧里画出什么」，而那一层已经能画帧、能按键、能点击、能断言文本。
- **在这一层断言**：分工（同一个会话在左栏可见与不可见两种情形下，过程行出现在/不出现在对话视图）、页高三档、两个视图滚动独立、指示器出现与点击、详情关闭后的位置还原、窄档前缀、降级退回全量。
- **纯函数层**：「块 → 视图」的判据在自己的单测里穷举（每一类块至少一条）—— 它是一个穷尽 match，不该只在帧里被间接覆盖。
- **prior art**：`tests/render_layout.rs` 的 tab 命中组、回合条焦点组、详情覆盖层组；`tests/history_replay.rs` 的重播 + 屏断言（其中一条要改）。
- **不测实现细节**：不断言 pane 的内部字段、不断言共享源的长度、不为「两个视口」写白盒测试 —— 只断言屏上的结果。
- **手工清单**（`docs/tui-manual-checklist.md`）：左栏 `轨迹` 页在真终端里的可读性（28 列的表格、前缀分档、指示器点击、滚轮分派）。

## 明确不做

- **`文件` tab 的内容**：另一个 effort。
- **跨视图联动**（点轨迹里的某行把对话视图滚到那一回合，或反向）：从对话跳回某回合仍走**回合条**。
- **轨迹视图的持久化**：它只是视图，不进事件流、不落盘、不跨会话。
- **plain / headless 渲染器**：它们没有左栏，拆分是 TUI 专属。
- **`sessions replay` / `sessions show` 的输出**。
- **键位表新增**。
- **左栏的宽度档与 `Ctrl-O` 意愿那一层**。
- **讨论会话回合条的「轮次」语义**。
- **共享源 `painted` 的裁剪策略**（它今天全量保留，本 effort 不动）。
