# 可点链接：对话视图里点 URL 或工作区文件，宿主用系统默认程序打开

来源：2026-10-06 一次 `/eli5` 之后的意向（「如何让 fs-agent 用浏览器打开 html 文件或 URL？
我想在对话中点击就用浏览器打开」）。同日四问四答把它折成这份 spec：**打开方式**选了
「TUI 自己接点击」（不是 OSC 8 终端超链接）、**可点内容**三种（Markdown 链接、裸 URL、
工作区里存在的文件路径）、**agent 侧**不要任何新工具或命令、**交付**先 spec 与票。

## 问题陈述

1. **对话视图里的链接只画不可点。** Markdown 的链接由 `render::markdown` 画成「标签下划线 +
   灰色 ` (url)`」（[`src/render/markdown.rs:449-477`](../../src/render/markdown.rs)），它把
   `dest_url` 记进 `Frame` 之后就再没有出口 —— 那一帧画完，谁知道那段文字指向哪儿这件事就丢了。
2. **`/eli5` 的产物是一条路径，不是链接。** 真实产物长这样：
   `.scratch/sandbox/eli5-bubblewrap.html`（`find . -name '*.html'` 能捞到它）。模型在正文里
   写的是纯文本路径，既不进 `Tag::Link`，也没有任何东西认它。
3. **轨迹页有可点行，但那是另一种入口。** 轨迹页点一行开详情覆盖层（`TuiState::trace_link_at`，
   [`src/render/tui.rs:3390`](../../src/render/tui.rs)），而对话页「每一行都不是入口」是一条
   **刻意**的决定（`tui-feedback` §3，2026-10-06 走查后改写，同一次改动删掉了旧的
   `conversation_links` 表）。那条决定管的是**不弹正文覆盖层**（点 `你好！` 弹一份同样的
   `你好！` 是意外），它没有说「对话页里任何东西都不许有反应」—— 本 feature 正是要在那条
   边界的另一侧加一种**外部的**反应。
4. **打开外部程序是宿主侧的动作。** TUI 进程持有终端、跑在沙箱之外；模型跑 `bash` 才过权限门
   与沙箱。指针是**人的**输入，不是模型的输出 —— 这个区别决定了本 feature 不需要新权限档、
   也不需要新工具。

## 方案

- **生效面**（§1）：只在**对话视图**的转录区里生效。左栏、状态行、提示行、输入区、轨迹页一律
  不生效。
- **手势**（§1）：**左键单击**（按下与抬起落在同一格、没有越过拖选门槛）打开；拖选照旧复制，
  两件事不互相抢。
- **可点三类**（§2）：Markdown 链接的目标、正文里的裸 `http(s)` URL、**工作区内存在的**
  文件或目录路径。
- **识别是纯函数、每帧重建**（§2）：新增 `render/links.rs`，从画出来的显示行文本里找出候选
  区间；不做 IO，存在性留到点击那一刻判。
- **打开走一条新接缝**（§3）：TUI 只产生一个打开请求，`Tui::run` 取走并 spawn `xdg-open`；
  argv 直传、不经 shell、不过权限门、不进沙箱。
- **看得见**（§4）：候选区间画下划线；成功与失败各在提示行留一句回执。

## 用户故事

1. 作为刚跑完 `/eli5` 的人，我希望**点一下正文里那条 `.html` 路径**，浏览器就打开那个页面，
   而不是让我把路径抄进另一个终端。
2. 作为读回答的人，我希望 Markdown 链接的 URL 与正文里裸写的 URL 一样点得开 —— 它们在我眼里
   是同一件事。
3. 作为习惯拖选复制的人，我希望拖过一段带链接的文字仍然只复制、不打开任何东西。
4. 作为按住 shift 用终端原生选择的人，我希望那一路完全不被 TUI 打扰。
5. 作为点了点的人，我希望**看得出**哪一段是可点的（下划线），而不是靠猜。
6. 作为点了一个不存在或工作区外的路径的人，我希望**什么都不发生**，而不是被弹一个浏览器或
   被打开一个我没想到的东西。
7. 作为读模型回答的人，我希望模型**不能**替我打开任何东西 —— 只有我的指针能触发。
8. 作为维护这个仓库的人，我希望这条边界（「人的指针能开外部程序，模型的文本不能」）写在
   词表与 `docs/render.md` 里，而不是只活在代码里。

## 实现决定

### §1 交互与范围

- **只认对话视图的转录区。** 点击落点必须在 `conversation` 窗格这一帧画出来的矩形里
  （`click_at` 里与轨迹页那条 `over_trace` 对称的一条判据）。左栏、状态行、提示行、输入区、
  详情覆盖层、问卷、文件查看器浮层各自照旧。
- **单击即打开，不加修饰键、不做双击。** 对话页的单击今天什么都不做（`tui-feedback` §9 之后
  连详情入口都没有了），所以这一格没有第二个语义可抢。读的人嫌误触时，终端原生选择那条路
  （shift+拖）还在。
- **拖选优先。** 按下到抬起跨过 `DRAG_THRESHOLD` 就进选择态、
  松开手复制，**永不**打开。判定顺序照旧走 `release_at`：`drag.selecting` 为真先复制，
  为假才当一次点击（[`src/render/tui.rs:2743-2752`](../../src/render/tui.rs)）。
- **轨迹页不加热区。** 那一页的点击已经是详情入口，两套热区叠在一起只会让人点到不该点的
  东西。轨迹页要开链接，走本 feature 之外的另一轮。
- **`plain` 与 `headless` 一个字不改**：它们没有指针。

### §2 识别：什么算候选

识别是一个**纯函数**（新模块 `render/links.rs`，形状例如
`fn hotspots(line: &str) -> Vec<(Range<usize>, Candidate)>`），输入是**一条画出来的显示行
的文本**，输出是候选的**列区间**（列，不是字节，与 `render::width` 同一套数法）。

| 文本 | 结果 | 为什么 |
| --- | --- | --- |
| `https://example.com/x`、`http://…` | URL 候选 | 协议头是硬判据 |
| `见 https://a.example/b。` | URL 候选，尾部的 `。` **不在**区间里 | 中文标点收尾是常态 |
| `（见 .scratch/sandbox/eli5-sandbox.html）` | 路径候选，外层全角括号不在区间里 | eli5 的真实形态 |
| `prototype/embed-nvim/README.md` | 路径候选 | 含 `/` |
| `README.md` | 路径候选 | 含扩展名、且真存在 —— 可点是正确的 |
| `src/render/tui.rs:2867` | **不是**候选 | `path:line` 是编辑器那一档 |
| `已经写好了` | 不是候选 | 没有 `/`、没有扩展名、没有协议头 |
| `foo.html; rm -rf ~` | 至多是一个不存在的路径名 | 见 §5：不经 shell |

- **存在性不在这一层判**：纯函数不做 IO，而且每帧对每条候选都 `stat` 一次是浪费。点击那一刻
  才解析与判定（§3）。
- **每帧重建，指针事件读上一帧的账。** 记录点与绘制点同处：`note_rows`
  （[`src/render/tui.rs:5372`](../../src/render/tui.rs)）记 `TextRow` 的同一处把候选也记进
  `selection::ScreenText`（形状实现定：`TextRow` 上加一个字段，或平行一份索引）。这是选择层
  已经立好的纪律 —— 「记下来的」与「看见的」不可能漂开。
- **软折续行按复制那套拼回。** 一条 URL 被窗格折成两片时，两片要拼成一条再识别，命中区间
  按列映射回屏幕（第一片起点 + 片宽）。判据与 `selection::text` 拼回逻辑同源：`folded`
  为真的行属于上一片。
- 一条显示行里可以有多个候选，各自独立命中。

### §3 点击 → 解析 → 打开

1. **命中判据**：点击列减去这一行的起点（`rect.x + lead`，见 `note_rows` 的 `row_lead`）落在
   某个候选区间里。列落在链接文字（Markdown 链接的 label 是 `文字 (url)` 里的 `文字`）上时
   不命中 —— 本层认的是**画出来的目标文本**，不是 label。
2. **解析目标**：
   - URL 候选 → 原样。
   - 路径候选 → 以会话 cwd 拼成绝对路径、规范化（`..`、符号链接一并解开），要求
     `fs::metadata` 成功**且**结果落在工作区内。目录也算（`xdg-open` 会开文件管理器），但
     **区外一律不认** —— 与 `[permissions] outside_read = "deny"` 这条地板同一个立场。
   - 解析失败（不存在、区外、规范化失败）→ **什么都不发生，也不留回执**：点一段普通文字
     本来就该没有反应，而一句「打不开」在每一处行文里都会出现，是噪音。
3. **打开**：
   - TUI 只把请求放进一个槽位（`open: Option<Target>` + `take_open_request()`），形状与
     `take_clipboard`（[`:2774`](../../src/render/tui.rs)）同构；`Tui::run` 取走并执行。
   - 真 spawn 集中在 `render/opener.rs` 一处：`xdg-open <target>`，**argv 直传**，不经过
     shell、不经过 `bash` 工具、不过权限门、不进沙箱（§5）。stdout/stderr 丢掉，不等待它退出
     —— 浏览器活多久与我们无关，也不能让它拖住 TUI（僵尸进程由 `Child::drop` 之外的一次
     `wait` 或 `spawn` 后的显式 reap 收掉，形状实现定）。
   - 目标传什么：URL 原样；文件传**绝对路径字符串**（不用 `file://` URL —— 路径里的空格、
     非 ASCII 都能原样传给 argv，而 `file://` 要自己做百分号编码）。
4. **失败**（spawn 不了、`xdg-open` 不在）：提示行一句回执（§4），不重试、不改模式。

### §4 视觉与回执

- **可点就是下划线**：候选区间画 `Modifier::UNDERLINED`，颜色沿用 `palette::CODE_QUIET`
  （与 Markdown 链接今天给 URL 部分的那一档同色，[`src/render/markdown.rs:474`](../../src/render/markdown.rs)）。
  于是「链接看起来可点」这条在两种来源上是同一个样子。
- **怎么加**：识别发生在 `note_rows` 这一层，而那条行已经排好版了 —— 要给一段列区间加样式，
  得按列切开那一行的 span（`Line` 的 span 逐段算宽、在边界处切）。切分的实现放在
  `render/links.rs`（纯函数，好测），绘制路径只调用它。
- **不做 hover**：指针移动不改变画面。终端上的 hover 意味着每动一格重画一次，收益不值这个
  抖动。
- **回执**（提示行，走 `copy_receipt` 那一槽位与寿命）：
  - 成功：`已打开 <目标>`（目标按列宽截断）。
  - 失败：`打开失败：<一句原因>`。
  - 措辞进 `render/wording.rs`（与 `copy_receipt` 那条 `已复制 … 字 · … 行` 同一处）。

### §5 边界与安全

- **argv 直传、不经 shell。** 模型的正文是**不可信输入**，而 `open` 只拿到一个字符串：
  `foo.html; rm -rf ~` 会作为一个（不存在的）路径名被拒绝，不会被拆成两条命令。
- **只有存在的、工作区内的目标会被打开。** 区外路径与 `file://` 一类都不认 —— 这条地板与
  读那一侧 `outside_read` 的缺省一致。
- **打开是人触发的，模型触发不了。** 模型能做的只有把文本写进回答；能不能打开取决于人的
  指针。这就是本 feature 不需要权限门、不需要新工具、也不需要「打开前问一句」的原因 ——
  要记进 `CONTEXT.md` 的词条里。
- **不进事件流、不写状态文件、不打日志**：与挂起、复制、模式循环同一条规矩。它是渲染器
  状态，不是会话内容。
- **不经 `bash` 工具**：那条路会带上沙箱与权限门的全套语义（还有升级手势），而这里要的
  只是「把这一个字符串交给系统默认程序」。

## 测试决定

- **单测（`render/links.rs` 内，纯函数）**：上表每一行各一条；另加一行两个候选、URL 被窗格
  折成两片后仍能拼回命中、全角标点收尾、行尾就是 URL（无收尾标点）。
- **单测（`tests/render_tui.rs`）**：造一帧带链接的对话页（沿用现有的状态脚手架），然后
  - 单击链接 → `take_open_request()` 是期望目标（URL 与工作区内路径各一条）；
  - 单击后请求被取走、第二次取是 `None`；
  - 拖过链接 → 没有请求、走的是复制那条路；
  - 点普通文字 → 没有请求；
  - 点工作区外或不存在的路径 → 没有请求；
  - 点左栏 / 状态行 / 轨迹页的同一列 → 没有请求。
- **不真开浏览器**：单测只断言请求，不断言 spawn。opener 的 argv 拼装是纯函数，单独测。
- **手工（`docs/tui-manual-checklist.md`）**：真机跑一次 `/eli5`，点正文里那条 `.html` 路径
  → 默认浏览器打开该文件；点一条 `https://` URL → 浏览器打开；拖选跨过链接仍只复制；
  shift+拖的终端原生选择照旧。
- **文档**：
  - `docs/render.md` 新开一节「可点链接」：识别层、每帧重建、打开接缝、为什么不过沙箱。
  - `CONTEXT.md` 的「渲染」一节加**链接热区**词条（含 §5 那条「模型触发不了」）。
  - `.scratch/tui-feedback/spec.md` §3 补一句：那一节说不弹正文覆盖层，**不**说不许有外部
    反应；本 feature 加的正是后者。

## 明确不做

- **不做 OSC 8 终端超链接**（把链接交给终端、由 Ctrl+点击打开）。它确实是一条成立的路
  （ratatui 官方有 [`hyperlink` 例子](https://ratatui.rs/examples/apps/hyperlink/)，ghostty
  1.3.1 的 `link-url` 默认开着），但它把「什么算目标」交给终端、把「打开了吗」交给别人，
  `file:line`、区外路径这类判据一个也落不下来；而两种手感（有下划线的链接要按住修饰键才开）
  会同时存在于一个界面里。这一版只走 TUI 自己接点击。
- **不给 agent 加工具或命令**（`/open` 一类）。模型今天已经能跑 `bash`，而「打开浏览器」是
  人的动作（§5）。
- **不做 `path:line` 跳编辑器**、不做 `mailto:` 等其它 scheme、不做区外路径。
- **不做轨迹页的热区、不做右键菜单、不做 hover、不做双击**。
- **不加配置项**：opener 写死 `xdg-open`（v1 只 Linux x86_64，见 [README](../../README.md)）；
  要换的人自己改路径或者装一个 `xdg-open` 替身。
- **不做「打开前问一句」**：单击是人的明确动作，问一次只会让点击变钝。
- 不把打开写进事件流、不写状态文件、不打日志。

## 补充说明

- **这段代码住在哪**：识别与样式切分在 `render/links.rs`；记录候选在 `note_rows` 与
  `selection::ScreenText`；命中与解析在 `click_at` 那条分派里；spawn 在 `render/opener.rs`；
  回执措辞在 `wording.rs`；`Tui::run` 里多一段「取走请求 → 打开 → 失败留回执」。
- **为什么不像 `trace_links` 那样按来源行记账**：轨迹页的热区按**来源行**寻址，因为一次点击
  打开的是那条块。本 feature 认的是**画出来的文本**（一条 URL 可能来自代码块、可能来自模型
  手写的路径，来源行的概念在这儿没有用），所以它跟选择层走，跟画出来的行走。
- **与拖选的关系**：两个功能共用同一层的记录（`ScreenText`）与同一条命中时机（抬起），但判定
  互斥，顺序是「先看是不是拖选」。
- **一手事实**：ghostty 1.3.1-arch2 的默认配置里 `link-url = true`、`link-previews` 开着
  （`ghostty +show-config --default --docs`，2026-10-06 量的）；工作区里的 eli5 产物实例：
  `.scratch/sandbox/eli5-sandbox.html`、`.scratch/sandbox/eli5-bubblewrap.html`。
