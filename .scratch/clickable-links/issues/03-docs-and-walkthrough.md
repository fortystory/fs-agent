## 具体行为

### 1. `docs/render.md`

一节写完四件事：候选长什么样（URL / 工作区路径，`path:line` 不算）、识别与记录和**选区**同层
（每帧重建、指针事件读上一帧的账）、点击与拖选怎么互斥、打开为什么走宿主进程的 argv 直传
（不经 `bash`、不过权限门、不进沙箱）以及为什么模型触发不了它。用词表里的**链接热区**，
别写「超链接」（那是终端 OSC 8 那一套，本仓库不做）。**现状文档只讲现在什么样**：不搬
spec 的理由与替代方案。

### 2. `docs/tui-manual-checklist.md`

一条走查，四个判断点，按现有条目的写法（编号、一句判断标准、怎么做）：
① 点 `/eli5` 产物那条 `.html` → 默认浏览器打开该文件；② 点一条 `https://` URL → 浏览器打开；
③ 拖过一段带链接的文字 → 只复制、不打开；④ 按住 shift 拖 → 终端原生选择照旧。

### 3. `.scratch/README.md`

把 `clickable-links` 那一行的票数改成实数。表格那一行的一句话按落地结果写实，不抄 spec 的
理由。

### 4. `.scratch/tui-feedback/spec.md` §3

补一句：那一节否掉的是**详情覆盖层**那一类入口（点普通文字不该弹一份同样的正文），
**不**否掉「点一段可点的文本会有外部反应」——后者是 `clickable-links` 加的**链接热区**，
判据与入口完全不同。别改 §3 的结论，只把边界写清。
