> 规格：[`../spec.md`](../spec.md) §9。这一票不写代码，只把已经落地的两个工具写进唯一的那处
> 逐面文档与两个索引；它被前两张票 block，因为文档要写的正是它们落地后的行为。

## 目标

`docs/web.md` 落地、README 的文档表指向它、架构一节的边界数字跟着改；`.scratch/README.md`
的进度反映实际结果；词表收下这一层新名词；真会话的走查步骤有地方可查。

## 现状（2026-10-03 核实，改前先复核）

- 逐面文档的先例是 `docs/repo-map.md` / `docs/sandbox.md`：一个面一份，讲它怎么工作、以及为什么。
- 索引在 `README.md` 的「文档」一节；**架构一节写着「13 个顶层边界」**，加 `src/web/` 之后是 14
  （清单要与 `src/lib.rs` 对齐）。
- `.scratch/README.md` 的 feature 表里 `web-search-tool` 那一行现在写着占位票数。
- `CONTEXT.md` 需要一个新词：`src/web/` 引入了「**搜索提供方 / 抓取提供方**」这一层名词
  （它只收领域词汇与流程词汇，格式照邻居：中文名 + 英文标识符 + `_Avoid_`）。

## 落点

`docs/web.md`（新）、`README.md`、`.scratch/README.md`、`CONTEXT.md`。

## 具体行为

1. **`docs/web.md`**：
   - 三层结构（工具 / 服务 / 后端）与各自的职责，以及「工具层绝不问后端可用吗」这条；
   - 两个工具的声明、上限、结果形状与引用格式；
   - `[web]` 配置段的每个字段与默认值；
   - SSRF 实际做了什么（解析一次 + 连接固定 + 仅同源重定向 + 每跳重校验 + DNS64）；
   - **两条边界**：「**关工具不等于关出网**」（`bash` 照样能 `curl`）与「**不做 JS 渲染**」；
   - 费用口径（一次搜索 = 一个完整模型轮次，没有单独的搜索费；peak 时段换算）。
2. **`README.md`**：文档表加一行；架构一节的 13 → 14。
3. **`.scratch/README.md`**：`web-search-tool` 那行的票数与状态改成实际结果。
4. **`CONTEXT.md`**：加「搜索提供方 / 抓取提供方」词条（或一个统称），英文槽位放它们在
   `src/web/` 里的 trait 名。
5. **真会话走查**：把票 02 的人工项（读一次 `usage` 钉死计费口径）与本节合并成一处，
   写在 `docs/web.md` 里。

## 验证

1. `python3 scripts/check-language.py` 通过（`docs/web.md` 与 `CONTEXT.md` 的新词条都在它的
   检查面里 —— 中文占比有下限，别写成键名清单）。
2. README 的文档表链接可达；架构一节的边界数与 `src/lib.rs` 的清单一致。
3. **文档与实现逐条对一遍**：上限、字段名、错误 code、结果形状 —— 这四处最容易写成「应该
   如此」而不是「就是如此」。

## 不做什么

- 不重写 `docs/` 里其它任何一份文档。
- 不在这一票里改代码（发现实现与文档不一致时，改文档或另开一条 bug）。
- 不把 `.scratch/web-search-tool/research/` 的一手调研搬进 `docs/`（那是材料，不是结论）。
