# 全高左栏、回合条与状态行：TUI 外壳改版

Status: ready-for-agent（`issues/01` 的帧已跑完，争议档已定并折回下文；实现票 `02`–`05`）

- **来源**：一次 grilling（本文件是那轮问答的折叠）+ 用户手绘的布局草图。**不是** wayfinder 图。
- **推翻了 `.scratch/tui-layout/spec.md` §2 的四条**：
  1. **面板在右改到左**，并且从「中段里的一条竖栏」变成**全高左栏**；
  2. **「四个区域各带 1 行边框」改成一圈外框 + 内部分隔线**（转录不再有自己的边框）；
  3. **取消整宽 header 块**：mark 进左栏，模式进状态行；
  4. **cwd 与时钟不再显示**（时钟在界面里彻底消失）。
- **术语**：新增 `CONTEXT.md` 词条 **回合条（TurnRail）**、**焦点回合（FocusedTurn）**。特别注意 **轮次（Round）≠ 回合（Turn）**：交互会话数回合，讨论会话数轮次（§4）。
- **实现票落点**：`.scratch/tui-sidebar/issues/NN-*.md`，`01` 是 prototype 票，实现票从 `02` 起。

## Problem Statement

1. **会话读数被放在最容易消失的地方。** 信息面板在最右缘、只有 25–31 列，而且是退化阶梯的第一级：宽 <80 或中段 <4 行就整栏消失，token 与上下文用量随即变成「滚走就没」的东西。
2. **顶栏花了 7 行只为了让 mark 站岗。** 它同时承载的四件事里，cwd 与时钟是可以不要的；而这 7 行是从转录身上拿的（120×24 下转录只剩 9 行）。
3. **界面完全没有「我在对话的哪一段」的位置感。** 转录有滚动条回答「第几行」，没有任何东西回答「第几回合」；一轮对话结束之后，想回去看那一轮只能靠手动翻。
4. **左栏空着、右栏挤着。** 界面左右两侧的信息量极不对称。

## Solution

外壳改成**一圈外框、一条全高左栏、一条主列**：

- **左栏（全高）**：mark（宽度不够时退成文字身份行）→ **tab 条**（调用量 / 轨迹 / 文件）→ 用量字段。宽度不够整栏隐藏。
- **主列**（自上而下）：**转录**（右缘恒留 1 列滚动条，最右恒留 1 列**回合条**）→ **状态行**（模型 · 模式 · 上下文）→ **输入区** → **提示行**。
- 块与块之间**只画一条共享的分隔线**，不再各画一圈边框；转录、状态行、输入区、提示行共用一条竖列分隔线（`│`，端点补 `┬`/`┴`/`├`/`┤`）。

## User Stories

### A. 左栏与 tab

1. 作为用户，我想让左栏占满整个终端高度，以便它不跟转录抢行数。
2. 作为用户，我想让 mark 画在左栏顶部，以便它还在，但不花转录的行。
3. 作为用户，我想在宽度不够画 mark 时看到一行文字身份，以便窄终端也知道这是什么程序。
4. 作为用户，我想让左栏有一条 tab 条（调用量 / 轨迹 / 文件），以便将来能在一栏里放多种东西而不再加宽。
5. 作为用户，我想用鼠标点 tab 切换页面，以便不用记键位。
6. 作为用户，我想让还没实现的页面点进去看到一句「尚未实现」而不是空白，以便知道是没做，不是坏了。
7. 作为用户，我想让选中 tab 一眼可辨（亮色加粗），以便知道自己在哪一页。
8. 作为用户，我想让左栏在宽度不够时整栏消失（而不是被压扁），以便转录拿到全部宽度。
9. 作为用户，我想让左栏行数不够时先丢 mark、再丢次要字段，以便「上下文 / token / 回合」这三个读数最后才消失。

### B. 回合条

10. 作为用户，我想在转录右缘看到一条竖着的回合条，一格一轮，以便知道这次会话进行了多少轮。
11. 作为用户，我想让回合条**贴着状态行往上长**（最新的一轮在最下），以便它和转录的阅读方向一致。
12. 作为用户，我想让焦点回合那一格用**粗线 + 亮色**画，其余用**细虚线 + 暗色**，以便一眼找到自己在哪。
13. 作为用户，我想让焦点回合 = 「视口顶端那一行所属的回合」，以便我滚到哪儿，条上就亮到哪儿——不需要另一份会漂移的状态。
14. 作为用户，我想在回合条比屏幕还长时，最上一格显示一个省略标记（`⋮`），以便知道更早的回合还在、只是不在这条上。
15. 作为用户，我想点某一格就跳到那一轮，以便回看某次提问不用手动翻。
16. 作为用户，我想点下去跳到的是**我自己敲的那句**（`[用户] …`），以便落地时看到的是问题而不是协议标记。
17. 作为用户，我想跳转是**顶端对齐**的（最后那一轮自然夹到底），以便每次跳转都落在可预测的位置。
18. 作为用户，我想在讨论会话里这条按**轮次**数，以便它回答的还是「讨论进行到第几轮」。
19. 作为用户，我想在没有回合时可以（条为空），以便刚启动时不显示一个假的第一格。

### C. 状态行

20. 作为用户，我想在输入区上方看到一行 `模型 … │ 模式 … │ 上下文 …%`，以便任何时候都知道自己在用什么、什么模式、还剩多少上下文。
21. 作为用户，我想让状态行按宽度丢字段（先丢模型、再丢模式、最后只剩上下文百分比），以便窄终端先保最重要的那个读数。
22. 作为用户，我想让状态行的三段都不可点，以便界面上没有「看着能点、点了没用」的东西。

### D. 降级与终端

23. 作为用户，我想让左栏的宽度有档位（宽屏 40 / 中屏一档 / 刚好放下字段一档），以便不在小屏上白占 40 列。
24. 作为用户，我想让左栏只在宽度不够时消失（高度不是它的门槛），以便它自己一栏自己算账。
25. 作为用户，我想让回合条与状态行**不随左栏一起消失**，以便窄终端仍然有模式与上下文占用这两个读数。
26. 作为用户，我想让 40×10 仍然画完整降级外壳，以便极窄终端也还能用。
27. 作为用户，我想让提示行的宽度按**主列**算（不是终端宽），以便左栏吃掉的那 40 列不会偷偷少给一条提示。
28. 作为用户，我想在宽度或高度不足 40×10 时仍然只看一句「终端太小：至少 40×10」，以便知道是尺寸问题。

### E. 不变量

29. 作为用户，我想让所有人类可见文案仍然只由措辞层产生，以便界面改版不会把字符串散进渲染代码。
30. 作为用户，我想让模型可见文本（system prompt、投影前缀、`AgentError.message`、工具结果）一个字节都不变，以便前缀缓存不被废掉。
31. 作为用户，我想让 plain / headless 两个渲染器完全不受影响，以便管道化照旧可用。
32. 作为用户，我想让面板的累加口径与 `events::total_usage` 保持一致，以便左栏的数字不会与事后统计打架。
33. 作为用户，我想让 `cargo test` 全绿、`cargo clippy` 干净、`cargo fmt --check` 只留既有的两处漂移，以便改动可验收。

## Implementation Decisions

### §1 区域树与几何

**一圈外框 + 一条竖分隔线 + 主列里的三条横分隔线**，没有第二个 Block：

```
┌─ 外框（暗灰，1 圈）─────────────────────────────────────────────┐
│ 左栏（全高）        │ 转录（右缘：滚动条 1 列 + 回合条 1 列）      │
│  mark / 文字身份    │                                            │
│ ── tab 条（3 行）── ├── 状态行上分隔线 ─────────────────────────┤
│  上下文 / token /…  │ 状态行：模型 … │ 模式 … │ 上下文 …%        │
│                     ├── 输入区上分隔线 ─────────────────────────┤
│                     │ 输入区（1–10 行）                           │
│                     ├── 提示行上分隔线 ─────────────────────────┤
│                     │ 提示行（就绪 · 快捷键 · 退出）              │
└─────────────────────┴────────────────────────────────────────────┘
```

- **`Regions` 新字段**：`sidebar`（左栏内容，**不含**分隔线）、`tabs`（tab 条那一行标签的内容）、`divide`（分隔线所在列 `x`）、`rail`（回合条 1 列）、`SidebarKind { Mark, Text, Hidden }`、`status`（状态行内容，恒在）、`transcript` / `input` / `hints`（保留语义，坐标改到主列）。**删除** `header` / `header_content` / `middle` / `panel` / `seam()` / `header_kind()` / `HeaderKind`；`SidebarKind` 的判定在 `layout` 里，画笔不重算。
- **固定 chrome = 7 行**：外框上下 2 + 主列三条横分隔线 3 + 状态行 1 + 提示行 1。因此 `转录行 = h − 7 − 输入行数`。相比 v1（header 内容 + 7），**mark 不再向转录收租**：120×24 下转录从 9 行涨到 16 行。
- **分隔线的字形表**（一个函数按行算，像今天的 `draw_seam`）：外框顶 `┬`、外框底 `┴`、左栏自己的横线（tab 条上下）`┤`、主列的横线（状态行/输入/提示上边框）`├`、其余 `│`。外框仍用 `Block` 画，分隔线**后画**、覆盖掉边框那一格。
- **转录文本宽** = 主列内容宽 − 1（滚动条，恒留）− 1（回合条，恒留）。`transcript_text()` 的算法不变，只是右边多了两样东西。
- **覆盖层重新定心**（v1 是「居中于中段，压住转录 + 面板」）：现在**居中于主列**（横向范围 = 分隔线右侧到外框右侧），宽度上限照旧（问题 72 / 详情 135）。理由是左栏现在是「会话读数」的所在地，问答期间把它压掉没有好处。`menu()` / `menu_room()` 的横向边界从 `header` 改到主列。

### §2 降级阶梯

**顺序固定**：先压左栏宽度 → 再隐左栏 →（左栏内部按高度丢内容）。宽度定去留，高度定内容。

| 档 | 条件 | 左栏内容宽 | 左栏内容 |
| --- | --- | --- | --- |
| 宽（有 mark） | `w ≥ 120` | `40`（mark 38 居中，左右各 1 格 air） | mark(5) + tab 条(3) + 6 字段 |
| 窄（无 mark） | `80 ≤ w < 120` | `28` | 文字身份(1) + tab 条(3) + 6 字段（**上下文那一行的 `（6%）` 被丢**，见 §3） |
| 无 | `w < 80` | — | 整栏隐藏 |

**只有两档**：prototype 实测 40 居中画的留白够用（帧 `frames/120x24.txt`），而 28 档丢掉的那个
`（6%）` 在状态行里本来就有，不值得为它多占 6 列文本宽。原先设想的中间档 34 **撤销**。

**去留只由宽度决定**（左栏是一栏自己的高度 = 终端高 − 2，不与转录抢行），所以 v1 那条
「中段内容行 < 4 就隐栏」的门槛**取消**。

**左栏内部行数不够时**（内容行 = `h − 2`）：先丢 mark（→ 文字身份行 → 连它也丢），再从尾部丢字段（缓存 → 输出 → 输入）。**tab 条占 3 行**（上下横线 + 标签行），底线 = **tab 条(3) + 上下文 / token / 回合(3) = 6 行**。实测（spec 的档位）：`h = 10` → 身份行与「缓存」已让位；`h ≥ 12` 才有身份行；`h ≥ 16` 才有 mark。

**状态行的阶梯**（宽度不够时按序）：

1. 三段齐全：`模型 <name> │ 模式 <mode> │ 上下文 <n>%`；
2. 丢**模型**（最长、一次会话内不变）→ 剩 `模式 <mode> │ 上下文 <n>%`；
3. 丢**模式** → 只剩 `上下文 <n>%`（仍带标签）。

**没有第 4 档**：prototype 实测，要触发「整行消失」得让主列内容宽 < 11，而左栏隐藏时主列内容宽 = `w − 2`，即要 `w < 13` —— 早于 40×10 地板就被 `too_small` 拦下。**状态行永远在场**；「整行消失、2 行还给转录」随实测删除，超窄由 `truncate_columns` 兜底。

**转录的退化**：`w < 40 或 h < 10` → 只有一句「终端太小：至少 40×10」（不变）。提示行宽度 = **主列内容宽**（不是终端宽）。实测：120 列宽屏下主列内容 77 列 → **4 条 + 退出（放不下 `就绪`）**；忙碌态因退出提示 `ctrl-c 退出` 比 `ctrl-c/ctrl-d 退出` 短 7 列，反而放得下 `就绪`。其余：100 列 → 3 条 + 退出 + 就绪；80 列 → 2 条 + 退出；40×10 → 1 条 + 退出 + 就绪。**这是预期行为，不是 bug。**

**输入区行数**：`clamp(草稿折行数, 1, min(10, h − 7 − 转录底线行))`；转录底线行取 `1`（草稿长高先吃转录）。

### §3 左栏与 tab

- **顶部**：`SidebarKind::Mark` 时画 mark 5 行（颜色渐变照旧：上 `LightMagenta`、底 `Magenta`，前景色、不填背景）；`SidebarKind::Text` 时画一行 `wording::identity()`（`fs-agent 0.1.0`，暗灰）。
- **tab 条**：上下各 1 行横线（左端 `├`、右端 `┤`，与分隔线相接），中间一行是标签。标签占自身宽度、之间 1 列 `│`，**选中**亮品红加粗、**未选中**暗灰；余下空间用 `─` 填到右端。三个标签固定为 `调用量` / `轨迹` / `文件`。
- **页面内容**：`调用量` = 现有信息面板的字段（**`模型` 行删除**，它搬到状态行）：上下文 / token / 回合 / 输入 / 输出 / 缓存，标签列 6 列左对齐、数值右对齐，千分位半角逗号（口径一字不改，仍与 `events::total_usage` 一致）。`轨迹` / `文件` = 一行占位符 `此页尚未实现（另有票在跟）`（暗灰）。
- **宽度基本不再丢字段**：prototype 实测，最宽的值 `12,345 / 200,000（6%）` 连标签共需 **29 列**，所以窄档（28）会走 v1 的老路（丢掉 `（6%）`，先丢分隔符再丢尾），宽档（40）完整。**v1 的「宽度先丢百分比、再丢缓存行」保留为代码路径**。丢掉的百分比在状态行里仍有（`上下文 n%`），这是接受 28 档的前提。
- **点击**：每个标签文字范围一个命中矩形（`HitAction::SwitchTab(Tab)`），切换选中页。**不给键盘**（`Tab` 归 `/` 菜单、`Shift+Tab` 归计划模式，仓库又不开键盘增强协议）。
- **切到占位页时面板读数不可见** —— 状态行的 `上下文 <n>%` 是那时唯一的读数。这是接受的代价。

### §4 回合条

- **单位**（`TurnRail` 的一格）：`SessionFacts.speaker_order.len() > 1` → 讨论会话，数 **`RoundEnded`（轮次）**；否则数 **`TurnEnded`（回合）**。不需要新管道，判定用现成的注入事实。
- **位置**：条占转录右缘**最右 1 列**（外框内侧），行数 = 转录行数；吸底时格子**贴底**排（最新一格紧贴状态行上分隔线），回看时按下面那条「窗口跟着焦点走」。
- **字形与颜色**：普通格 `┊`（`DarkGray`）；**焦点格** `┃`（粗）**`LightMagenta`**（与 mark 同族，不占用黄的「可以动手」语义；prototype 出过黄与亮品红两张对照帧，选定亮品红）；被裁掉时那一端画 `⋮`（`DarkGray`）。
- **焦点（`FocusedTurn`）是派生量**：= 视口顶端那一行所属的单位；吸底时 = 最新单位。**不存在**「存储的选中项」——那份状态一定会与视口漂移。焦点回合 ≠ 最新回合。
- **索引**：转录需要两份与源行平行的索引（与现有 `links` 同形、同样随 20 000 上限裁剪）：每源行 → 单位序号；每单位 → **段首源行**。段首 = 该单位之前最近的一条用户消息（`[用户] …`）；讨论会话没有用户消息，退化到该轮的首个源行。
- **点击**：命中某格 → 滚到该单位段首并**顶端对齐**（最后一格自然夹到底，不需要特例）；点焦点格 = 同样顶端对齐，因此绝大多数时候看起来「没有动静」（视口顶端本来就在该单位里）。命中矩形 = 该格那一行 × 条的 1 列。
- **溢出：窗口跟着焦点走，条上永远有焦点那一格。** 吸底（焦点 = 最新单位）时窗口贴底、最上一格是 `⋮`；回看时窗口跟着焦点移，两端各自按「上面 / 下面还有没有被裁掉的单位」画 `⋮`。
  > **这是 prototype 挖出来的洞**（票 01 §Answer）：原写法「只保留最近 `N` 格」在视口停在第 12/30 个单位时，会让整条**没有一个格子是亮的**（帧 `frames/120x24-rail-30-units-focus-12-gap.txt`），用户故事 12「一眼找到自己在哪」直接失效。窗口跟着焦点走是唯一让那条故事在任何滚动位置都成立的写法。
- **空会话**：零个单位 → 条为空（那一列什么都不画）。
- **历史重播**：条随重播逐格长出（纯派生，无特例）。

### §5 状态行

- 内容：`模型 <model> │ 模式 <mode> │ 上下文 <n>%`，三段用 `│` 分隔、左起排列、段宽 = 文本宽 + 左右各 1 格内边距、余下留白。
- **`上下文 <n>%` 是新措辞**（`wording::context_share`，短形式）：分子 = 最近一条 `UsageRecorded.input_tokens`，分母 = 注入的 `context_window`；没有用量时是 `—`。
- 三段**都不可点**。
- 阶梯见 §2（三档，状态行恒在）。

### §6 措辞层（`src/render/wording.rs`）

新增：`TAB_USAGE`（调用量）/ `TAB_TRACE`（轨迹）/ `TAB_FILES`（文件）、`tab_placeholder()`（此页尚未实现（另有票在跟））、`context_share(used: Option<u64>, usable: u64) -> String`、`status_row(model, mode, share, width) -> String`（阶梯在这里，不在渲染器里）、回合条的 `RAIL_CELL` / `RAIL_FOCUS` / `RAIL_TRUNCATED` 字形常量。

**删除**：`clock` / `clock_short`（时钟不再显示）。**保留**：`identity`（左栏窄档）、`logo_lines`（mark 还在）、`mode_field`（状态行用）、`PANEL_*` 全套（`PANEL_MODEL` 由状态行用）。

### §7 鼠标与键盘

- **键位表零新增零删除**。
- `mouse()` 的分派从三段扩到五段，顺序：**详情覆盖层 > 待答问题 > 回合条 > 左栏 tab > 转录**（前两者原本就吃掉一切；后三者互不重叠，顺序只为确定性）。
- 命中矩形一律「这一帧真的画了什么就记什么」（沿用现有 `state.regions`）：tab 标签、回合条格子、指示器、折叠行、覆层按钮。
- **`Ctrl-D` 的语义照旧**：空闲时确认退出，详情覆盖层打开时先关覆层。

### §8 不变量与删除清单

- **不动**：plain 与 headless 渲染器、语法高亮、Markdown 渲染器、ADR 0001 冻结的模型可见文本、事件 schema、面板的累加口径、键位表、`too_small` 文案与 40×10 地板。
- **删除**：`layout::HeaderKind` 与 `header_content_rows` / `HEADER_TWO_LINE_WIDTH` / `LOGO_MIN_WIDTH` / `LOGO_MIN_HEIGHT` / `LOGO_HEIGHT` / `LOGO_GAP_ROWS` / `LOGO_INFO_ROWS` / `PANEL_MIN_WIDTH` / `PANEL_MIN_ROWS` / `MIN_MIDDLE_ROWS`；`tui.rs` 的 `draw_header` / `draw_mark`（改写进左栏）/ `header_lines` / `edges` / `draw_seam`（改写成 `draw_divide`）；`TuiState.clock` 与 `SessionFacts` 里不再被任何区域读的字段（`cwd`：左栏与状态行都不显示它，删字段而不是留一个没人读的注入值）。
- **`TICK` / `interval` 臂**：它唯一的职责是「时钟走字」置脏；时钟没了它就没事做，而待答问题经由 console port 到达、事件经由广播到达，都不靠它。**实现期确认后删除**（倾向删；若发现别处依赖这条唤醒，改成注释说明而不是留着猜）。
- `draw_indicator` / 滚动条 / `/` 菜单 / 详情覆盖层的行为不变，只是坐标改到主列。

- **布局用 `TestBackend` 断言**（默认特性下可用，v1 已证），不需要 pty：尺寸矩阵 `40×10` / `60×24` / `80×14` / `80×24` / `100×24` / `120×24` / `174×50`，每档断言左栏档位、状态行档位、转录行数、回合条列存在与否。

  - 点击：点第 N 格 → 转录顶端 = 该单位段首；点 tab → 页面切换且命中矩形随之变；

- **`scripts/tui-startup-check.py`**：它的 `MARK_ROW = "▄▀▀█"` 锚点在 260×30 下仍然有效（该档左栏 40 列画 mark），`ctrl-c` 提示行锚点也仍然有效（提示行在主列里照旧含 `ctrl-c/ctrl-d 退出`）。要改的是**注释**（「header」→「左栏的 mark」）与 `BORDER_H` / `BORDER_V` 的注释（不再是「每块一圈」）。**不要**把 MARK_ROW 锚点改成身份串——那会让宽屏失去「mark 画出来了」这条断言。

## Out of Scope

- **`轨迹` 与 `文件` 两个 tab 的内容**（这轮只有占位符），单独开票。
- 讨论会话里回合条的**轮次配色 / 轮次标签**（这轮只按轮次数格子）。
- 任何键位新增（tab 不给键）。

## Further Notes

### prototype 的实测结论（票 01，已折回上文）

1. **左栏宽档 = 40（mark 居中、左右各 1 格 air）+ 28（文字身份）**；42 与「贴左画 mark」都否决，中间档 34 撤销。
2. **焦点格颜色 = 亮品红**（黄那张只作对照保留在 `prototype/frames/120x24-variant-focus-yellow.txt`）。
3. **40×10 地板已实测**：左栏隐藏、主列 38 列、转录 2 行 × 36 文本列、状态行退到「模式 + 上下文」、提示 1 条 + 退出 + 就绪。**认得出来，能用。**
4. **两个 spec 的洞已修**：状态行「整行消失」不可达（改三档）；回合条溢出改为「窗口跟着焦点走」。见 §2 / §4。
5. **三处被我写错的数字已改**：tab 条实占 3 行；左栏高度**确实**会触发降级（`h = 10` 时身份行与「缓存」已让位）；120 列空闲态提示是 4 条 + 退出（`就绪` 只在忙碌态放得下，因为 `ctrl-c 退出` 比 `ctrl-c/ctrl-d 退出` 短 7 列）。

### 我在实现层面替你定的（写在这里以便否决）

- **覆盖层居中于主列**（不压左栏）：左栏是会话读数所在地，问答期间没有理由把它盖掉。
- **`SessionFacts.cwd` 删除**（而不是留一个不再显示的注入值）；`wording::clock*` 删除。
- **状态行永远在场**（第 4 档不可达，见 §2），它的那一行与分隔线不会还给转录。
- **左栏的去留只由宽度决定，但内容由高度决定**（`h = 10` 时已丢身份行与「缓存」，见 §2）。
