# 重新打开会话：历史重播与历史详情

Status: ready-for-agent

- **来源**：`.scratch/tui-history-replay/map.md`（wayfinder 地图，5 张决策票全部 `resolved`）。本 spec 是那张图的**折叠**，不是新决定——唯一例外是 `Further Notes` 记的两处勘误。
- **实现票落点**：`.scratch/tui-history-replay/issues/NN-*.md`，**编号从 `06` 起**（`01`–`05` 是设计票，不要覆盖）。`/to-tickets` 已切出 **`06`–`09`**：接缝与分帧重播 → 分隔行/面板/模式 → 历史详情 → 验证迁移与文档；`06` 是开工点，`07` 与 `08` 互不阻塞但共用同一个新测试文件（建议串行）。
- **回改的既有 spec**：`.scratch/fs-agent-v1/spec.md` §19（新增历史重播一条、修掉过时的 inline viewport 一行）与 §11（恢复结果同时进转录）已由本 spec 折回正文。
- **术语**：叙述用中文，标识符用英文。词汇表在 `CONTEXT.md`——本项目**只有概念「事件」，没有「重播」这个领域词**：它是渲染侧的动作（把历史事件按同一 `apply` 路径喂给转录），不新增词汇，也不与 `sessions replay`（那是**投影重算**）混用。

## Problem Statement

`--continue` 重新打开一个已有会话时，屏幕是空的。用户昨天那一段对话、其中的「思考完成」行与工具调用行、以及那些行背后的详情，一个都看不到——像是开了一个新会话，尽管模型其实还带着全部上下文。

具体地：

1. **转录从零开始。** `--continue` 只把会话目录里的事件流读进内存里的会话，**不重播给渲染器**。全仓库唯一的渲染写入路径只覆盖本进程新追加的事件，所以重开时没有一条历史事件走到画面上。
2. **历史里的行没有详情。** 折叠提示行与详情覆盖层（`tui-ux` 已落地）是为 live 事件做的；历史块不存在，自然也没有可点的 `▸`。
3. **派生信息一起归零。** 信息面板的 token 累计与回合数、header 的模式，都是从事件流推出来的；历史不重放，它们就从零开始，与「模型记得的上下文」不一致。
4. **「看不见」是真正的痛点，不是「丢数据」。** 数据一直在盘上、也一直进了模型；缺的是把它呈现给人。

## Solution

**启动时把整条事件流重播进转录**，分帧推进、不冻结界面，进度显示在底部提示行；重播完成后插一条历史分隔行，启动 banner 排在其后。

- **历史与 live 走同一条路径**：历史事件逐条走渲染器已有的 `apply`，所以块、折叠提示行、名字配色、详情命中全都自动继承——不为历史另写一套。
- **派生信息自然重建**：信息面板与 header 模式是逐条 `apply` 的副作用，不另写重建逻辑。
- **历史详情与 live 同一套覆盖层**：工具全文从会话目录的 `outputs/<tool_call_id>.txt` 读、思考从 `MessageCompleted.reasoning` 重建；取不到就如实降级，不伪造。
- **一次性、可打断**：重播是一过性状态，期间不接受提交（草稿照打）、live 事件先缓冲、`Ctrl-C` 直接退出。
- **边界**：只动 TUI 与 CLI 组装；**不改事件 schema**；plain 与 headless 一行不动。

## User Stories

### A. 看到历史

1. 作为用户，我想在 `--continue` 之后立刻看到上一段对话，以便接着昨天的思路继续，而不是对着一块空屏回想说到哪了。
2. 作为用户，我想看到历史里的「思考完成」行与工具调用行，以便知道上次到底做了哪些动作。
3. 作为用户，我想看到历史里的轮次分节线，以便分辨哪几段属于同一轮讨论。
4. 作为用户，我想看到历史里被中断的那次工具调用显示为失败结果，以便知道上次是断在什么地方。
5. 作为用户，我想看到历史里执行者派发与收尾的记录，以便知道上次派出去的子任务结果如何。

### B. 历史详情

6. 作为用户，我想点开历史工具行看到那段工具输出的全文，以便不必回终端 scrollback 里翻。
7. 作为用户，我想点开历史「思考完成」行看到当时的推理，以便理解上次为什么那样做。
8. 作为用户，我想让历史详情用与 live 完全相同的覆盖层（`Esc` 关闭、可滚动、90 列上限），以便不用学第二套交互。
9. 作为用户，我想在工具全文文件缺失或为空时看到预览加「全文不可用」，以便知道这不是完整输出。
10. 作为用户，我想在没有溢出注记的结果上**不**看到「全文不可用」，以便不被一句假警告误导。
11. 作为用户，我想让合成器等没有推理的历史**不出现**可点的思考详情，以便不被一个空框或伪造内容骗到。

### C. 启动过程诚实

12. 作为用户，我想在重播时看到底部一行进度（`恢复历史 n/m`），以便知道要等多久、而不是以为卡死了。
13. 作为用户，我想让重播分帧进行、界面保持响应，以便不必盯着一个冻住的窗口。
14. 作为用户，我想在重播期间照常打草稿，以便等待的时间不被浪费。
15. 作为用户，我想让 `Enter` 在重播期间不提交，以便不会在半截历史上误触发一次回合。
16. 作为用户，我想在重播期间上滚不生效（保持吸底），以便不会被甩到一段还没铺完的历史中间。
17. 作为用户，我想让重播结束后视口落在最新一行，以便从「现在」继续看。
18. 作为用户，我想让重播完成后的草稿还在，以便我打了一半的内容不会丢。
19. 作为用户，我想让重播期间到达的 live 事件（banner、恢复诊断）在历史之后按序出现，以便时间顺序不会错乱。

### D. 历史与 live 的接缝

20. 作为用户，我想在历史与本次新内容之间看到一条分隔行（`── 以上为历史 ──`），以便一眼分出哪些是旧的。
21. 作为用户，我想让启动 banner 出现在历史之后（作为最新一行），以便它不会插在历史中间。
22. 作为用户，我想让分隔行在每次重开时都重新出现一次、但不会在历史里层层累积，以便它始终只在最新的那条接缝上。
23. 作为用户，我想让信息面板的 token 累计与回合数包含历史、并且继续累加新事件（不重置），以便数字与真实会话一致。
24. 作为用户，我想让 header 的模式反映历史最后的状态，以便重开一个被杀在计划模式的会话时看到的是真实的当前策略。
25. 作为用户，我想在空会话或只有骨架事件的会话上重开时不看到进度行与分隔行，以便不出现一条无意义的空操作。

### E. 打断与失败

26. 作为用户，我想在重播期间按 `Ctrl-C` 直接退出，以便不必等它铺完。
27. 作为用户，我想在重播期间按 `Ctrl-D` 或 `Esc` 不产生任何效果，以便不会因为手滑而退出或取消掉什么。
28. 作为用户，我想让窗口在重播期间 resize 正常重排、分帧继续，以便调整终端大小不会被忽略。
29. 作为用户，我想在历史读失败时拿到一条诊断而**不是**启动失败，以便会话照常可用、转录从空开始（与今天一致）。
30. 作为用户，我想在会话很大时启动仍然可用（分帧有预算、不以条数当唯一代理），以便历史大小不至于让启动卡死。

### F. 不被打扰的既有行为

31. 作为用户，我想让 plain 与 headless 的历史呈现完全不变，以便脚本与管道行为不被这次改动影响。
32. 作为用户，我想让事件 schema 不变，以便已有会话文件仍可读、`sessions` 子命令族不受影响。
33. 作为用户，我想让重开保持会话 id 不变，以便前缀缓存与 `sessions` 的寻址照旧。
34. 作为用户，我想让历史详情在重播期间对鼠标完全无响应，以便与键盘边界保持一致。
35. 作为用户，我想让历史详情打开时视口冻结、关闭后恢复吸底，以便行为与 live 完全一致。

## Implementation Decisions

### 1. 接缝：组装后推一条控制请求

- **不新增渲染事件变体，也不在启动选项里注入历史。** 载体是既有的前端控制请求（`ConsoleRequest`）新增一个 **`Replay { events }`** 变体，配套的 handle 方法照既有的 `Catalog` 先例写（组装后一次性推控制消息）。
- **发送点是 CLI 在组装之后、与 `Catalog` 同一段。** 入口**不是** `Harness` 上的方法——它不持有前端 handle。
- **历史取组装后的全量快照**（`Harness::events()`），**不是**组装前的文件读取快照：`--continue` 的恢复会把悬空调用的合成失败结果**写进日志**，两份快照因此不同，而用户要看到的是恢复后的那一份。
- **为什么这是最高的一层**：前端通道是无损的；`RenderEvent`、转录、plain、headless 一行不用动；推送发生在恢复之后。
- **否掉的两条**：启动选项注入会拿到恢复前的快照；新增渲染事件变体会强迫转录与 plain/headless 处理一个只有 TUI 消费的载荷。

### 2. 分帧：每轮迭代一批，双闸预算，不等 tick

- 渲染状态新增一个一过性的 **replay 态**：持有事件序列、已消费下标、已产出的源行数。
- 主循环形状：**有 replay 待办就取一批，否则才进 `select!`**；两路之后照常 emit 与按脏绘制。**重播未完成时不进 `select!`**——否则每帧被 tick 间隔卡住，近百帧会累积成十几秒。
- **预算同时满足两条闸**：`≤ 512 条事件` **且** `≤ 2000 源行`，先到先停。理由是单帧成本由**文本量与源行数**决定（转录满上限后每多一行要整体平移），只数事件会让「512 条里全是巨型工具输出」的帧爆掉。
- 每条历史事件走与 live 同一条 apply 路径。
- **完成**：消费完 → 清 replay 态、flush live 缓冲、置脏。**事件总数为 0 时完全不进重播态**，也不显示进度行。
- **每批之后显式置脏**：apply 自己会置脏，但进度行的 `n` 若只改状态、不置脏，就永远不会重画。

### 3. 顺序与输入

- **live 事件缓冲**：重播期间到达的 live 事件（banner、诊断、恢复补写的工具结果）先进**按到达顺序**的缓冲，重播完成后按同一顺序 flush（到达顺序即发送顺序）。
- **缓冲不设上限**：重播期间没有回合在跑，真正会到的只有组装后的少数几条消息。
- **`Enter` 不提交，拦在提交入口的最前面**：提交函数开头判「在重播态就直接返回」。草稿编辑与光标键照常工作。
- **重播期间吸底**：翻页键、跳转键、滚轮一律忽略；完成后恢复正常滚动。

### 4. 进度与提示行

- 文案：**`恢复历史 {n}/{m}`**（`m` = 事件总数，`n` = 已 apply 数），暗灰；**复用提示行、临时替掉提示集**，完成后恢复原本的状态行。
- 降级：`40×10` → **`恢复中 {n}/{m}`**；更窄 → **`恢复中`**。
- 重播期间**不显示** `Ctrl-C` / `Ctrl-D` 的退出提示——此刻键盘上只有 `Ctrl-C` 有意义。

### 5. 重播期间的行为边界

**重播不复用「忙」状态**：那个状态驱动「`Ctrl-C` 是取消还是退出」以及状态词，而重播期间没有回合可取消，`Ctrl-C` 必须**退出**。所以用独立的一过性标志，并在键盘分派里**优先**判它：

| 键 | 重播期间 |
| --- | --- |
| `Ctrl-C` | **退出**（中断重播） |
| `Ctrl-D` | 忽略 |
| `Esc` | 忽略 |
| `Enter` | 不提交（草稿保留） |
| 可打印字符 / 编辑键 | 照常进草稿 |
| `PgUp` / `PgDn` / `Ctrl-G` / 滚轮 | 忽略（吸底） |
| `resize` | 正常重排，分帧继续 |
| 鼠标（点击） | 一律不响应（含历史详情） |

空日志 / 1 条 / 少于一批 / 恰好整除都不需要特殊处理；事件总数为 0 走 §2 的跳过分支。

### 6. 保真度：块的来源与边界

- **「原样」的实现口径 = 逐条 apply 已记录事件**，块由转录层**唯一**决定——不另写过滤器。
- **只有已记录事件能重播**：`Notice` / `Diagnostic` 是渲染层事件、不落日志，所以启动 banner、技能加载、渲染器丢弃、恢复诊断这些**历史里没有**、也不重建。
- 例外与说明：
  - `SessionStarted` 是骨架事件，不产块。
  - 合成器的 `MessageCompleted.reasoning` 为 `None`，所以历史里**没有**「思考完成」行——与 live 一致（live 的增量也不留）。
  - 执行者的派发与收尾、权限询问与裁决、hook、usage、轮次分节：照 live 原样产出。
  - 悬空工具调用：恢复时**已写进日志**的合成失败结果照常重播。
- **历史分隔行**：重播结束、flush live 缓冲**之前**插一条渲染层合成的 `Notice`——**`── 以上为历史 ──`**（暗灰）。
  - **仅当这次重播至少产出一个块**才插；空日志 / 只有骨架事件时不插。
  - 它是**渲染层合成行、不落日志**，所以下一次 `--continue` 不会把旧的那条重复带出来（会新插一条）。
  - 顺序固定：**`[历史块] → [分隔行] → [缓冲的 live 事件：banner / 恢复诊断] → …`**。

### 7. 信息面板与 header 模式的重建

- **信息面板**：逐条 apply 让面板**自然累加一次**；`last_input` = 最后一条 usage 记录的输入量，回合数 = `TurnEnded` 的条数。口径与 live 完全一致（缓存命中/未命中是输入量的拆分，**不重复计**）。与 live 衔接时**不重置**，继续累加。
- **已知代价**：上下文窗口与预算上限来自组装期的**当前**配置；若配置变过，历史 token 数与当前预算可能不自洽——**如实显示、不做调和**。
- **header 模式**：逐条 apply 顺序更新（计划模式注入 → 计划；模式变更事件 → 询问；其余块不动模式）。**恢复补写的模式变更也算**，所以被杀在计划模式的会话重开后显示「询问」——与 harness「重开从配置模式开始」的实际策略一致。没有任何模式事件时保持初值「询问」。
- **静态事实的自觉**：注入的事实里那个「cwd」装的是**会话目录**，不是工作目录——本 spec 不把它当工作目录用。

### 8. 历史详情：复用与取数

- **不新增形态**：历史详情**就是** `tui-ux` 那套覆盖层（分节标题、列宽上限、内部滚动、`Esc` / 再点关闭）。历史行要可点，必须**经同一条 apply 路径**（它维护与转录平行的命中表）；绕过它直接往面板推行**不会有 `▸` 命中**。
- **命中按绘制当帧记录**：转录满上限后的整体平移因此被天然吸收，**不需要历史专用例外**。
- **可点范围**：历史里的「✓ 思考完成」行与工具行带 `▸`、可点；**历史分隔行不可点**；轮次分节线与无 `▸` 的行一律不可点。
- **工具详情判据 = 事件文本里有没有溢出注记 `full output at <path>`**：

| 事件文本 | `<会话目录>/outputs/<id>.txt` | 详情显示 |
| --- | --- | --- |
| 含注记 | 存在且非空 | 文件全文（仍受既有的 200 000 字符上限约束 → 超出标 `已截断`） |
| 含注记 | 不存在（`prune` / 手删） | 事件里的预览 + `全文不可用` |
| 含注记 | 存在但为空 | 预览 + `全文不可用` |
| **不含注记** | （从不尝试读） | 事件文本**本身就是全文**，直接显示、不报「不可用」 |

  - 路径规则与 live 相同：取 `<会话目录>/outputs/<tool_call_id>.txt`。
  - 悬空调用的**合成结果不含注记** → 按最后一行显示那段文本，**不会误报「不可用」**。
- **思考详情只来自 `MessageCompleted.reasoning`**，与 live 相同（超限同样 `已截断`）；`None` 的历史没有思考行、也就没有可点的思考详情——**不伪造、不弹空框**。
- **覆盖层行为与 live 完全一致**：`Esc` / 再点同一行关闭；方向键、翻页、滚轮滚详情；打开时**视口冻结（吸底暂停）**，期间到达的 live 事件照常追加但视口不跟随；关闭后**恢复吸底**。它不是「待答问题」状态，所以不拦既有的键盘 / 鼠标分派。
- **不新增文案**：复用既有的 `全文不可用` / `已截断` / 滚动指示。

### 9. 失败降级

- 历史来源是组装后的全量快照，读的是已被日志开启流程修好残尾的文件；即便改从文件侧读，既有的读取器本来就把不可解析的**末行**当残尾跳过。
- **整体读失败**（文件消失 / 权限）→ **降级为不重播**：转录从空开始（与今天一致）+ 一条诊断，**不阻塞启动**，`--continue` 不因此失败。

### 10. 新增的文案与符号

- 新增文案一族：`恢复历史 {n}/{m}` / `恢复中 {n}/{m}` / `恢复中`，以及分隔行 `── 以上为历史 ──`。落渲染层的文案模块，与既有人类可见文案同处。
- **函数名用 `history_*`，不用 `replay_*`**：`history_progress(n, m)` / `history_progress_narrow(n, m)` / `history_progress_minimal()` 与 `history_divider()`。理由是文案模块里**已经有一整个 `replay_*` 家族**服务于 `sessions replay`（**投影重算**，如 `replay_needs_id` / `replay_system` / `discussion_replay`）；本特性是渲染侧的历史重播，同一模块里两个「replay」含义不同会立刻误导读代码的人。`history_*` 与既有的 `history_reason` 同族。
- 新增渲染状态：replay 态（事件、下标、已产出源行数）与 live 缓冲。
- 新增前端控制请求变体与对应 handle 方法（§1）。
- **不改**：事件 schema、转录的块定义、投影、plain / headless。

## Testing Decisions

### 什么样的测试是好测试

- **只测外部行为。** 这次的「外部行为」有两个面：**一个定尺寸的 `TestBackend` 缓冲里画出来的帧**（人看到什么），以及**状态机对请求与按键的回应**（循环会收到什么答案）。两者都是既有 TUI 测试的断言对象。
- **不测实现细节**：不断言分了几批、每批几条、内部字段长什么样、命中表怎么存。预算与批次的正确性由**帧的内容**与**进度行的出现/消失**间接证明，不由内部计数证明。
- **不断言时间戳**，也不引入注入时钟。
- **测试里没有网络、不跑真 provider**。

### 唯一的接缝（现有，不新增）

**TUI 状态接缝**：

- 一个渲染状态值收**前端控制请求**（含新的 `Replay`）与**渲染事件**，经 `apply` 与 `draw_frame` 进入定尺寸 `TestBackend`，断言缓冲内容。**这就是 `tui-ux` 与问卷接管已经在用的接缝**，本 spec 不新开一条。
- **大多数重播断言根本不需要文件**：直接构造事件序列喂 `Replay`，再出帧即可。
- **需要文件时**用 `tests/support/` 里新增的**会话 fixture**：临时目录 + 直接落一条 JSONL（照 `tests/session_store.rs` 既有的 append 写法），需要 `outputs/` 时再写 `outputs/<tool_call_id>.txt`。它只服务「工具详情四种文件状态」，不用于驱动重播本身。
- **生产侧唯一的接缝**是本特性自己需要的那个控制请求变体（§1）——它不是为测试而加，测试只是恰好也走它。

### 先例（prior art）

- `tests/render_tui.rs`：渲染**状态机与按键**的主先例（提示行 / 面板 / 模式 / 转录内容的既有断言都在这里，**不经 `TestBackend`**，直接断言状态）。
- `tests/render_layout.rs`：**定尺寸 `TestBackend` + `draw_frame`**——「一个状态进去、一个缓冲出来」的写法先例（几何与 header）；本 spec 的帧断言照它写。
- `tests/ask_user_question_tui.rs`：同一接缝上**一个特性开一个文件**的先例（它自己在文件头说明了为什么不并进 `render_layout.rs`），以及 `ConsoleRequest` 注入状态的写法。
- `tests/session_store.rs`：直接落 JSONL 的 append fixture。
- `scripts/tui-startup-check.py`：pty 起真 CLI、断终端归属的既有脚本。
- `docs/tui-manual-checklist.md`：只能靠手感确认的部分。

### 要覆盖的断言

1. **内容与顺序**：`[历史块] → [分隔行] → [缓冲的 banner / 诊断] → …`。
2. **分帧中途**：喂进历史后**不跑完**，断言「部分历史 + 进度行 `恢复历史 n/m`」；跑完断言进度行消失、原状态行恢复。
3. **面板**：历史 usage / 回合事件累加后的总量、最后输入量、回合数（经右栏文本断言）。
4. **模式**：历史含计划模式注入后跟一条模式变更 → 重开后 header 是**「询问」**；只有计划模式注入 → **「计划」**。
5. **边界**：空（不进重播态、不插分隔行）/ 1 条 / 恰好一批 / 超过一批（两批）。
6. **顺序与输入**：重播期间 `Enter` 不提交（草稿仍在、没有用户消息入流）；重播期间喂一条 live 事件 → 进缓冲 → 完成后按序追加在分隔行之后。
7. **历史详情**：历史 `▸` 行可点；下列四种文件状态各自的文案；**重播期间点击不响应**。

| 事件文本 | `outputs/<id>.txt` | 断言显示 |
| --- | --- | --- |
| 含注记 | 存在且非空 | 文件全文 |
| 含注记 | 不存在（`prune` / 手删） | 预览 + `全文不可用` |
| 含注记 | 存在但为空 | 预览 + `全文不可用` |
| **不含注记** | （从不尝试读） | 事件文本即全文（不出现 `全文不可用`） |

8. **吸底**：重播后吸底、无「到最下」指示条。
9. **重播期间鼠标**：滚轮与点击都不改变视口、也不开详情。

### 分层：什么进 `cargo test`、什么不进

- **行为进 `cargo test`**（上面 1–9）。
- **终端归属进 pty**：脚本加一条 `--continue` 路径——同一临时数据目录里**先造一个会话**（跑一次普通启动，或直接写最小 JSONL），再 `--continue` 启动；断言**不崩**、重播**收敛**（进度行消失）、退出后终端**交还干净**（alt screen / 鼠标 / 粘贴 / termios）。**重播内容的正确性不进 pty**——那是 `cargo test` 的活。
- **手感进手工清单**：新增 **⑭ `--continue` 重开**（真会话开一次看进度观感、历史详情点击、分帧中途上滚、超大会话的启动手感），并在既有的退出项下补一条「重开后退出」（`--continue` → `Ctrl-C` / `Ctrl-D` → 终端干净）。**注**：设计票里写的编号是 ⑫，但 `tui-ux` 已占用 ⑫ / ⑬，实际落 **⑭**。

### 既有测试与纪律

- 控制请求加变体会**编译期强制**：TUI 的请求分派与 plain 侧的匹配各补一个分支。
- 现有断言（提示行 / 几何 / 面板 / 模式 / 问卷接管）**预期不变**；开工前重新核实 `cargo test --all-targets` 的通过数（**tui-ux 落地后是 664 passed**）。
- `cargo clippy --all-targets` 干净；`cargo fmt --check` 只留 `src/context/repo_map.rs` 与 `tests/repo_map.rs` 的既有漂移（**不**顺手格式化）。

## Out of Scope

- **新增恢复入口**（按 id 恢复 / 从会话列表里挑一个）：本 spec 只覆盖现有 `--continue`（取当前工作区桶里最近一个会话）。
- **历史搜索 / 过滤 / 分页浏览**。
- **历史编辑 / 分叉（fork、rewind、跨会话 `/undo`）**。
- **plain / headless 的历史呈现**：只做 TUI。
- **事件 schema 改动 / 逐段增量落流**：沿用既有决定。
- **重播期间的鼠标悬停反馈**。
- **转录上限处逐行整体平移的优化**（环形缓冲 / 偏移代替平移）：实测在可接受范围内，本 spec 不优化；若实现后观感不够，另开 effort。
- **历史块的高亮 / 语法着色**：工具输出走折叠 + 详情纯文本（`tui-ux` 已如此），本 spec 不回调。
- **本次 effort 的执行本身**：本 spec 只产可建计划，实现发生在后续实现票。

## Further Notes

- **本 spec 是折叠，不是新决定。** 五张设计票的契约（接缝与调度、保真度与派生信息、详情复用与降级、验证分层）是全部内容的来源；只有下面两处勘误是本 spec 新增的。
- **勘误一（编号）**：设计票 05 说手工清单「新增 ⑫」，但 `tui-ux` 落地后 ⑫ / ⑬ 已被占用，实际应为 **⑭**（同时把「重开后退出」补进既有的退出项下）。
- **勘误二（回改落点）**：设计票 01 说 spec 回改落在 `.scratch/fs-agent-v1/spec.md` 的 §7；经核对 §7 是工具 trait，与「转录从空开始」无关。实际回改落在 **§19（渲染与 CLI 组装）与 §11（会话存储、`--continue`）**，已折回正文。
- **文档回改清单（实现落地时一并做；2026-09-23 已随票 06–09 全部落地，逐条清空）**：
  - ✅ `docs/render.md`：补了「Reopening a session: the history replay」一节——新增的前端控制请求、历史行经同一条 apply、分隔行、分帧与进度行。
  - ✅ `docs/tui-manual-checklist.md`：新增 **⑭ `--continue` 重开**，并在 ⑦ 退出项下补了「重开后退出」。
  - ✅ `scripts/tui-startup-check.py`：每条 run 追加一次 `--continue` 路径（先由前几条 run 造出会话），断言不崩、重播收敛、终端交还干净。
  - ✅ 渲染层文案模块：新增 `history_progress` / `history_progress_narrow` / `history_progress_minimal` / `history_progress_line` / `history_divider`。
  - 这些文档描述的是**已实现**的系统，所以留到实现落地时改，避免文档先于行为。
- **已知代价（不是缺陷，写下来免得被当成 bug）**：
  - 历史 token 数与当前预算 / 窗口可能不自洽（配置变过时），**如实显示不调和**。
  - 每次 `--continue` 都会新插一条分隔行，且**只有本次**；旧分隔行不落日志、不会出现在历史里。
  - 转录满上限后每行成本随上限线性上升，超大会话的启动时间由**文本量**而非事件条数决定。
- **⚪ 未证实（实现时优先验证）**：本机 51 个会话里 `outputs/*.txt` 样本为 **0**，所以「文件存在且非空」这条详情分支**没有真实样本**，降级分支才是唯一可观测分支；`prune` 删目录后详情降级的端到端路径未真跑；超大会话的启动成本是**上界**（合成基准 50 000 事件、release 约 0.78 s，且 `TestBackend` 不是真 tty、未测内存）。
- **实现顺序**：`tui-ux` 已实现并提交，本 spec 可直接开始。历史行**必须经同一条 apply 路径**才会带 `▸` 命中——这是最容易踩的一条。
- **验收基线**：`cargo test --all-targets` 开工前复核 664 passed / 0 failed；`cargo clippy --all-targets` 干净；`cargo fmt --check` 的既有漂移不要顺手格式化。
