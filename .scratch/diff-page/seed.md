## 它要什么

- 左栏多一页 **`diff`**：列出**改动的文件**。
- 点其中一个 → **详情弹窗**里看那个文件的 diff（`git diff` 的输出，或者更漂亮的呈现）。

两半是分开的：「哪些文件改了」是列表，与「这个文件改了什么」是弹窗。列表是**读**的那一面，
所以这一页今天最像的邻居是左栏的 `文件` 页，不是转录。

## 现状（2026-10-07 核实）

- **左栏今天三页**：`Tab::{Usage, Todo, Files}`（[`src/render/tui.rs:5360`](../../src/render/tui.rs)），
  页签名是 `wording` 的 `TAB_USAGE` / `TAB_TODO` / `TAB_FILES`
  （[`src/render/wording.rs:1764`](../../src/render/wording.rs)）。页签**点出来、不给键位**，
  键位只有文件页那一套（`sidebar_key`，[`src/render/tui.rs:3403`](../../src/render/tui.rs)）。
  窄档左栏 28 列（`SIDEBAR_NARROW`，[`src/render/layout.rs:67`](../../src/render/layout.rs)）——
  页签条再加一格放不放得下，是这一页的硬件约束。
- **仓库里没有 git 集成**：`src/` 里 `git` 只作为**命令名**出现在权限策略与文案里
  （[`src/permissions.rs:255`](../../src/permissions.rs)、[`src/render/wording.rs:538`](../../src/render/wording.rs)），
  没有任何地方跑过一个 `git` 子进程。这一页要的取用点是**新的一件**。
- **「改动的文件」有两个现成读数，但都不是它**：
  - 文件页与 `@` 补全共用一份**会话级文件索引**（工作区里**有什么**，与 git 无关，
    `.scratch/files-page/spec.md` §1）；
  - `sessions show --files` 记的是**这个会话碰过哪些文件**（`已写入：` 那一行，
    [`src/tools/file.rs:27`](../../src/tools/file.rs)）—— 那是复盘用的历史，不是工作区此刻
    相对 HEAD 的状态。
- **弹窗那一半有现成件**：详情覆盖层已有五种 `DetailKind`（Thinking / Context / Message /
  File / Tool，[`src/render/tui.rs:7363`](../../src/render/tui.rs)），支持滚动、宽度上限 135 列。
  `File` 那一种就是「正文在**打开那一刻**由渲染器直接读盘」
  （`.scratch/files-page/spec.md` §6）—— 所以「渲染器自己取内容、不进事件流、不进模型上下文」
  这条路**已经有先例**。
- **高亮也有现成件**：代码块走 tree-sitter（10 种语言，`.scratch/markdown-render/spec.md`），
  而它高亮的是**语言**，不是 diff；`+`/`-` 那一套颜色要新进色板
  （[`src/render/palette.rs`](../../src/render/palette.rs)）。
- **权限与沙箱只约束工具调用**：`bash` 与文件工具过沙箱和权限门，而**渲染器直接读盘**
  （文件页弹窗）与**后台遍历**（文件索引预热）都不经它们。于是「前端自己跑 `git diff`」在架构上
  不是被禁止的，但它会绕开审计 —— 这件事要正面决定，不要顺手。
- **刷新信号已经有**：非只读工具调用收尾时那条静默的 `WorkspaceChanged`
  （`.scratch/files-page/spec.md` §2）就是「工作区刚被改过」，`/undo` 也会发它 ——
  这一页可以借它，不必自己再猜。

## 待谈的分叉

1. **"改动"是哪一种**：`git diff`（工作区 vs index）、`git diff HEAD`（含已暂存的）、
   还是 `git status --porcelain` 列文件名。三者的"改了"不是同一件事，而未跟踪文件在
   `git diff` 里**根本不出现**——第一眼最容易踩的就是这个。
2. **谁去跑 git**：渲染器直接 `Command::new("git")`（像它直接读盘那样），还是走 `bash` 工具
   （过权限门与沙箱、结果进事件流、可审计）。前者轻且不打扰模型，后者与「工具是唯一动作入口」
   一致。若选前者，要不要至少给用户一个开关。
3. **多久刷一次**：每帧跑 git 显然不行。借 `WorkspaceChanged`（同上）够不够；要不要一个手动刷新
   键；页面不在前台时还跑不跑。
4. **"更漂亮的工具"落在哪一档**：自己给纯文本 diff 上色（`+` 绿 `-` 红、hunk 头、行号）／
   外部 `delta` 一类（要装、要进白名单、输出是 ANSI 还是结构化）／复用 tree-sitter（它对 diff
   没有语法）。第一档最可控，第二档"更漂亮"但要处理它是外部进程这件事。
5. **列表里显示什么**：只要文件名，还是带状态字形（M/A/D/`??`）与 `+N/-M` 统计 —— 统计要另跑
   一次 `--numstat`，是第二次取数。
6. **点开之后看什么**：一个文件的完整 diff（长起来必然要滚）、逐 hunk 折叠、还是先给摘要；
   多文件时弹窗里给不给「下一个」。
7. **列表的顺序与分组**：路径字典序、按状态分组、还是按"这次会话碰过"排（那又回到
   `sessions show --files` 的口径）。
8. **空态与不可用态**：工作区干净时说什么；**不是 git 仓库**时整页消失还是写一句；`git` 不在
   `PATH` 时同理。文件索引那边已经做过「非 git 仓库也能走」的降级（`.scratch/files-page/spec.md`
   §1），这一页要对齐还是分家。
9. **`todo` 页那种条件出现**：`todo` 页签是「主会话第一次提交列表才出现」的
   （`.scratch/todo-and-modes/spec.md` §4）。`diff` 页要不要也在"第一次发现有改动"时出现，
   还是常驻第四个签。
10. **这一页与文件页的关系**：点 diff 里的文件名，能不能顺手跳到文件页的同一份文件（两页之间
    的指针今天不存在）。

## 默认不做（除非访谈时正面推翻）

- **不做任何写操作**：暂存、提交、丢弃、切分支都不做（`git add` / `git commit` /
  `git checkout -- <path>`）。那些要过权限门，是另一条路。
- 不做 conflict 解决、rebase、`git log` 的历史浏览。
- 不动文件页与 `@` 补全共用的那份索引：它回答「工作区里有什么」，与 git 无关。
- 不把 diff 塞进模型上下文：这一页与文件页弹窗一样，**只给人看**。
