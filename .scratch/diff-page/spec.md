## 问题陈述

左栏的三页各回答一个问题：`调用量` 回答「花了多少」，`todo` 回答「干到哪了」，`文件` 回答
「工作区长什么样」。**「相对 HEAD 改了什么」没有答案。** 今天要看它就得离开 TUI：切到 shell 里
`git status`、`git diff`。

代价落在三处。**模型刚改过什么，看不见** —— 转录里只有一行摘要，而它在这一次会话里改了哪些文件、
改了多少，屏幕上没有一处说得出来。**未跟踪的新文件最容易隐形** —— 它们不在 diff 里，而模型刚
建出来的文件恰恰是这一类。**看一份 diff 得离开 TUI** —— 想确认某一个文件到底改成什么样，要切出去
到编辑器或终端。

另外一件事值得记在台面上：**仓库里今天没有任何 git 集成**，`git` 只作为命令名出现在权限策略与
文案里。这一页要的取用点是一件新东西。

## 方案

左栏加**第四页 `改动`**，并把「看一份 diff」这条读法补齐：

1. **一列改动的文件**：口径是**相对 HEAD**（已暂存 + 未暂存 + **未跟踪**），未跟踪的目录按
   `-uall` 展开成文件，所以**一行永远是一个文件**。先按状态分组、组内路径字典序，一行 = 状态
   字形（占满两格）+ 相对 cwd 的全路径。
2. **点开就是那份 diff**：落在既有的**详情覆盖层**上，整份、可滚、带行号、diff 三色、按扩展名的
   语法高亮 —— 与文件页那个内容弹窗同一个东西、同一套纪律（渲染器直接取、**不进事件流、不进模型
   上下文**）。
3. **数据由渲染器自己在宿主侧跑 git**：不进事件流、不进 `messages`、不过权限门与沙箱（只读、不写
   盘），失败只给一句回执。
4. **刷新**：进 TUI 一次、`WorkspaceChanged`（模型改过工作区）、提交之后、`/undo` 之后各重取一次，
   外加键盘在改动页时按 **`r`** 手动重取 —— 因为在外部 shell 里做的 `git add` 不会触发任何信号。
5. **一档外部工具**：`[ui] diff_viewer` 写成一个外部命令时，把那份 diff 喂给它、一次性收 stdout、
   按「只认 SGR 子集」解成带样式的行画进**同一个弹窗**；缺省仍是内置那一档。

## 实现决定

### §1 位置与形状

- 左栏加**常驻第四签**，页签文案是 `wording` 里的一条常量（写成 `改动`）。实算：四签在窄档
  （28 列）下占 21 列，还剩 7 列填 `┄` —— 放得下，不必压别的签。
- 页的几何照既有算式，不新增布局分支：宽档 120×24 下页区 **40 列 × 15 行**，窄档 80×24 下
  **28 列 × 19 行**。加页**不用动** `layout.rs`（页签行高是常量、标签宽画时算）。
- 页区**没有滚动机制**：它是「一页已经排好的行」，与另外两页一致；滚轮在这块区域今天归文件页，
  这一页要接同一支分派。

### §2 数据与口径

- **「改了」= 相对 HEAD**：已暂存 + 未暂存 + 未跟踪。`git diff`（工作区 vs index）那一档被否决 ——
  它看不见已暂存的，也看不见未跟踪的。
- 列文件走 `git status --porcelain=v2 -z`，`-z` 是 NUL 结尾、路径**原样不加引号**；改名行里两个
  路径之间也是 NUL。不用 `-z` 时引号与转义归 `core.quotePath`，所以**用 `-z`**。
- 未跟踪**全展开**（`-uall`）：一行永远是一个文件，与「一行 = 一个文件 + 一个状态字形」这条
  不变式一致。实测代价很小（10 万未跟踪文件 + `-uall` ≈ 60 ms）。
- 一个文件的正文走 `git diff HEAD -- <path>`。**它对未跟踪文件是空输出 + 退出码 0** ——
  所以未跟踪那一档**直接读盘**给全文（标题写 `新文件`）。
- 状态字形是 `XY` 两列的**最小折法**：优先取**工作区**那一位，它为空时取 index 那一位；`??` 是
  整列的单字符。于是 `MM` / ` M` / `M ` 都画 `M`。**已暂存与未暂存在这一页上不分家。**

### §3 取数件（宿主侧、只读）

- **渲染器自己跑**（像 `opener` 起 `xdg-open` 那样），不进事件流、不进 `messages`、不过权限门与
  沙箱：它只读、不写盘，而权限门约束的是**模型**的读写。
- 形状：`tokio::process::Command` + `process_group(0)` + `kill_on_drop` + `tokio::time::timeout`，
  超时后自己 `killpg`。**零新依赖**（`tokio` 的 `time` / `process` / `rt` 与 `libc` 都在）。
- **必须 `tokio::spawn` 出去**：一帧的 `select!` 只等通道与两个定时器，任何一支里都不许 await。
  结果经既有那条「后台跑、通道回填」的路回到 `TuiState`（`file_index` 那套形状）。
- **超时 2 秒**（git 三个读数的实测是百毫秒级）。
- **锁法逐条照抄调研结论**：**diff 那条**带 `--no-color`、`--no-ext-diff`、
  `--src-prefix=a/ --dst-prefix=b/`、`--unified=3`；**status 那条**带 `-uall` 与
  `-c status.relativePaths=true`（porcelain v2 仍跟随用户配置，只有 v1 有那句「与配置无关」的
  保证）；两条都带 `--no-pager` 与全局 `--no-optional-locks`（**`git status` 默认会写回 index**，
  不锁就是动用户的仓库）。`--no-color` 只在 diff 那条上：`git status` 不接这个选项（它会当场报
  「未知选项」），而 porcelain 本来就无色。环境里清掉继承来的 `GIT_DIR` / `GIT_WORK_TREE` /
  `GIT_INDEX_FILE`（实测污染会改语义，最后一个会换成另一套 index 的世界）。
- **不把错误文案当判据**：git 的 stderr 随 locale 本地化，判据是退出码与 `ErrorKind`。
- 失败态：不在仓库里 `status` = 128；无 HEAD 的空仓库里 `status` 照常成功而 `diff HEAD` = 128；
  `git` 不在 `PATH` 是 `ErrorKind::NotFound` —— 三种各自的页内文案见 §5。

### §4 刷新与陈旧

- 触发点：**进 TUI 一次**、`WorkspaceChanged`（非只读工具调用收尾那条静默信号）、**提交之后**、
  **`/undo` 之后**（它不走工具派发，要在它自己那条分支上单独补一次）、**执行者与讨论者的调用**
  （它们落在同一条父流、同一个渲染器上）。
- 合并与不丢：**自己的一个位**，形状照 `file_index` 那道守卫（一个位 + 在飞时不发、位留着补发，
  最多延后一轮）。**不共用 `file_scan_wanted`**：两件事的节奏与失败模式不同。
- **页面不在前台也照旧取数**（与文件索引的重扫同构），切回来即时看到。
- **不画陈旧**：页里不出现「上次取数时刻」，也不做阈值提示。代价说在明处 —— **在外部 shell 或
  编辑器里做的改动不会自己冒出来**，那是 `r` 的活（这一条同时写进「明确不做」）。
- **手动重取 = 键盘在改动页时的 `r`**，回执走提示行一句。不给全局键（`r` 是普通字符，会与输入区
  抢键）。
- **失败保留上一次读数**：列表与正文都不动，提示行给一句失败回执。**一次都还没取到过数**时
  页里写 `读不出改动`（不是继续挂着「正在读取改动…」—— 那是在说一件没发生的事），而还没开始
  读过时页里写 `正在读取改动…`。

### §5 排版

- 分组标题**占一整行、不带计数、不给色**，空组不画，标题与第一行之间不空行。
- 一行 = **字形（占满两格）+ 空格 + 全路径**。字形列每行都占满两格，于是名字严格同列（与文件页
  那条真机反馈后的规矩同源）。
- 路径是**相对 cwd 的全路径**，超宽**尾部 `…`** 收尾（与文件页「名字超宽用 `…` 收尾」同一条）。
- 放不下时：**画满页区 + 末行一句 `还有 M 处改动`**。
- 页内文案五条（都落 `wording` 常量）：工作区干净 `没有改动`；不是 git 仓库 `这里不是 git 仓库`；
  找不到 `git` `找不到 git`；还没取过数 `正在读取改动…`；取数失败而一次都没成功过 `读不出改动`。
- **不给色**：字形与分组标题都不着色，层次交给结构与字形（「过程退后、内容保持、信号着色」）。
  焦点行照文件页那一档（常驻选中）。

### §6 弹窗

- 落在既有的**详情覆盖层**上：`DetailKind` 加一个变体，`detail_body` 是唯一 switch；照文件页那条
  路加一个 `open_*_detail` 与一个 `DetailOpener` 变体（不冻任何页）。
- **正文宽用 `Regions::detail_text_width()`**（框宽 − 4），不是框宽 —— 那处落差文件页已经对齐过，
  这一页照抄。（120 列屏 ⇒ 正文 112 列；80 列屏 ⇒ 72 列。）
- **行号列 = 最长行号位数 + 1**，右对齐 + 一格空格，与 `file_body_lines` 同形；折行在插前缀之后按
  剩余预算算，续行顶格。行号取值：新增与上下文取**新文件**的号、删除取**旧文件**的号；hunk 头与
  头行留空。
- **第一个 hunk 之前的一切都不留**：`diff --git`、`index`、`---`、`+++`，以及
  `new file mode` / `similarity index` / `rename from` 那一族 —— 弹窗标题已经说明是哪个文件。
  `@@` 那行**留**（它带函数上下文，也是读的人定位的锚）。进了 hunk 之后一行以 `---` 开头的
  可能是删掉的内容，那是正文，不是文件头。
- **上色内置兜底**：复用现成的 diff 标记层（`diff_tag`，吐的是**背景**色，正好与语法前景叠加）+
  按扩展名认语言的语法高亮。**一处既有落差要顺手修**：`highlight_diff` 今天写死按 Rust 高亮，
  按扩展名认语言那条映射要接上。
- **有界截断**照文件页那三档（行数、字节、行宽）与二进制那一句，文案
  `二进制文件，不显示内容` / `只显示前 N 行，还有 M 行`（N 数的是**画出来的那些行**，头行不算）。
  只剩头行、没有 hunk 的那种 diff 给一句 `这份改动没有可显示的内容`，而不是一块空白。
- 标题 = 路径（超宽尾部 `…`，**所有详情标题统一这个口径** —— 从前是硬截断）；未跟踪文件的标题
  写 `新文件`。
- **不进事件流、不进模型上下文、不打码**（与文件页弹窗同一立场）。正文进屏幕文本层，所以照旧
  可拖选复制。

### §7 键盘与指针

- 新增的键盘归属复用**文件页那一套**：点左栏任意处把键盘交给这一页，焦点行 = 点的那一行。
- 键位：`↑` / `↓` 移焦点行、`Enter` 开那份 diff、`Esc` 只还键盘（**不**取消回合）、`r` 手动重取。
  **`@路径` 插入不搬过来** —— 那是文件页的语义。
- 滚轮按指针位置分派；左栏那一支今天归文件页，这一页接同一支。
- 页签切换仍然只靠点。

### §8 外部工具那一档

- 配置：`[ui] diff_viewer`（程序名）配相邻的 `diff_viewer_args`（argv 数组），按**整元素**替换、
  **绝不过 shell**；不写 `diff_viewer` = 内置那一档。这与 `[ui] file_viewer` 的「配置开关挑呈现」
  同形，但形状不同：**不是**内嵌 nvim 那种一屏外来终端。
- 输入从 **stdin** 进（我们把 `git diff HEAD -- <path>` 的输出喂进去）。**未跟踪文件也走这一档**：
  它的「那份 diff」是全文，读者选了外部呈现就一视同仁。
- 我们**只给环境变量**：`PAGER=cat`、`GIT_PAGER=cat`、`COLUMNS=<正文宽>`。**一条命令行参数都不
  注入** —— 认不出未知参数的工具会直接报错。
- 输出按**「只认 SGR」**画：认 `ESC[…m` 那一族（重置 / 前景 / 8 色与 8 色亮档的前景 / 背景 /
  粗体 / 暗淡），**其他 CSI 序列整段丢掉**（我们不搬终端模拟器）。**认不出的颜色档保持当前样式**
  —— 256 色与 truecolor 那两种写法不改变已经认下来的那一档（没有认下来的就是 `PLAIN`），而不是
  猜一个近似的颜色。画完仍走我们自己的正文管线（按正文宽折行、有界截断、可滚）。
- 失败 / 超时 → **回退内置那一档** + 提示行一句回执；**不把 stderr 画进正文**。
- 标题右端**标出工具名**，内置那一档不标。
- **代价说在明处**：这一档的颜色**不经过语义色板** ⇒ 落一条 **ADR**（与「一块外来屏幕不受视觉
  纪律约束」同族，但形状不同：那是外来**屏幕**，这是外来**输出**）。

## 测试决定

- **一个 seam：既有的 TUI 帧测试层。** 不新增 seam。理由：这次改动的全部内容是「同一帧里画出
  什么」加「一次输入之后状态里是什么」，而这一层已经在钉页签、todo 页、文件页、详情覆盖层。
- **数据怎么进帧**：用既有那套**状态机口子** —— 测试拉「该做什么」（取数位）、再把结果送回来
  （结果回填），不起真任务、不跑真进程。`file_index` 的重扫测试就是这个形状（
  `take_file_scan()` / `files_loaded(...)`），这一页照抄。
- **断言对象是外部行为**：屏幕上画出来的行、点击 / 滚轮 / 按键之后的帧、弹窗里的行与行号、
  `r` 之后的取数位与回执、空态与不可用态那四句文案。**不断言** pane 的内部字段，也不为「改动
  怎么存」写白盒测试。
- **纯函数层的小单测**（不算新 seam，是本仓库既有做法）：porcelain v2 的 `-z` 切分与 `XY` 折
  字形、路径尾部截断、行号列宽与取值、SGR 子集解析（含「认不出 → PLAIN」「非 SGR 的 CSI 整段
  丢掉」两条）、有界截断的三个上限、二进制判据。
- **起真进程的集成测试**（prior art 是 `tests/sandbox.rs`、`tests/mcp_stdio.rs`）：真 git 的
  临时仓库 —— 已暂存 / 未暂存 / 未跟踪三态、空仓库（无 HEAD）、非仓库、锁法生效（`status` 不写回
  index）、超时；外部工具那一档用一个**假的脚本**当工具（prior art 是
  `tests/support/fake_mcp_server.rs`）。
- **两档宽度（40 / 28）各要有排版断言**：窄档是这一页最容易读不下去的地方。
- **prior art**：`tests/render_layout.rs`（页签组、文件页那几组、详情覆盖层的点击与滚动）、
  `tests/history_replay.rs`（详情相关断言）、`tests/todo.rs`（侧栏断言）、
  `tests/render_highlight.rs`（高亮层）。
- **真机项**（不写成自动化断言，列进手工清单）：光标形状、鼠标拖选、真配色下的观感。

## 明确不做

- **任何 git 写操作**：暂存、提交、丢弃、切分支、`git add -p` 那一类都不做 —— 它们要过权限门，
  是另一条路。
- **conflict 解决、rebase、`git log` 的历史浏览**。
- **把 diff 塞进模型上下文**：这一页与它的弹窗只给人看，不进 `messages`、不进事件流、不打码。
- **逐 hunk 折叠、弹窗里翻上/下一个文件、搜索与过滤**。
- **外部工具的一屏外来终端**（内嵌 nvim 那一档的复用）：`diff_viewer` 是一次性输出，不占键盘、
  不需要 pty。
- **外部分页器那一套**（外部工具自己的 pager / 交互模式）：输出交回来之后由我们画。
- **两页之间的跨页指针**：点改动页的一行跳去文件页、在改动页插 `@路径`、让文件页的焦点行去看
  diff —— 三条都不做。两页各自回答一个问题，要看文件本身去 `文件` 页。
- **watch 工作区**：不盯文件树的 mtime、也不盯 `.git/index`，所以外部改动不会自己冒出来。
- **改动页与文件页共用一份索引**：git 的口径与遍历的口径不是一回事，两页各自取数。
- **给这一页加滚动**：放不下就画满 + 一句提示，等真机反馈再谈。
- **页签上带读数**（比如改动件数）。
