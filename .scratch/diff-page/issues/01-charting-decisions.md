## 问题

[`seed.md`](../seed.md) 记的意向只有一句：「在左侧栏中添加 diff 标签，在里面显示改动的文件，
点击文件弹窗显示 diff 内容」。它自己列了十条待谈的分叉（`git diff` 的口径、谁去跑 git、多久刷
一次、「更漂亮的工具」落在哪一档、列表显示什么、点开看什么、顺序、空态与不可用态、页签条件
出现、与文件页的关系），外加四条默认不做。

这一票把它们按 charting 的三轮问答收拢成决定，并补上 charting 时实测的几件事实（见图的「起点」
一节与 [research：宿主侧子进程、ANSI 与 `[ui]` 配置的接线](03-research-host-side-subprocess.md)）。

## 作答

### A. 终点与范围

1. **终点是一份可执行的 spec**：本图只产决策，不写代码 —— 与 [`files-page`](../../files-page/map.md)
   同一个走法（图走完 → `/to-spec` 折成构建计划 → `/to-tickets` 拆实现票）。**被否决**：
   把执行也划进这张图。
2. **seed 那四条默认不做照旧保留**：不做任何 git 写操作（暂存 / 提交 / 丢弃 / 切分支）、不做
   conflict 解决与 rebase 与 `git log` 历史浏览、不动文件页与 `@` 补全共用的那份 `FileIndex`、
   不把 diff 塞进模型上下文。补一条：这一页**不消费** `FileIndex` —— git 的口径与遍历的口径
   不是一回事。

### B. 「改了」是哪一种

3. **相对 HEAD**：已暂存 + 未暂存 + **未跟踪**（`??`）。列文件名的那一次取数走 `git status`
   那一套，点开的正文取 `git diff HEAD -- <path>`，**未跟踪文件直接读全文**。
   **被否决**：只要 `git diff`（工作区 vs index，看不见已暂存的、也看不见未跟踪的）；
   「相对 HEAD 但不含未跟踪」（未跟踪的新文件恰恰是最该看见的一类）。
   理由：这一页回答的是「这一场活里工作区改成了什么」，而不是「暂存区里放了什么」。

### C. 列表

4. **一行 = 文件名 + 状态字形**（`M` / `A` / `D` / `??`）。**不带** `+N/-M` 统计 —— 那要另跑
   一次 `--numstat`（第二次取数），而窄档 28 列也挤不下。
5. **顺序 = 先按状态分组，组内路径字典序**。与文件页「同层目录在前」是同一族思路：同类的东西
   在一起。**被否决**：纯字典序；「按这次会话碰过的先后」（那回到 `sessions show --files` 的
   口径，与「工作区此刻相对 HEAD 的状态」不是一回事）。
   还说不清的部分（未跟踪的粒度、已暂存/未暂存要不要分组、`R`/`C`/`U` 怎么画）记在图的
   「尚未明确」一节，不在这里定。

### D. 弹窗

6. **弹窗 = 那一份 diff，整份可滚**，落在既有的详情覆盖层上（`DetailKind` 加一个变体，
   照 `File` 那条路：打开那一刻由渲染器取内容并排版、`Esc` 关掉）。**不做**逐 hunk 折叠，
   **不给**「下一个文件」。
   理由：折叠与翻页都要新的按键与状态，而「一份 diff 从头读到尾」是这个尺度上最常用的读法。

### E. 取数与刷新

7. **正文点开时才取**：列表那次只跑 status（轻），点开某个文件时才为它单跑一次
   `git diff HEAD -- <path>`。**被否决**：刷新时就把整份 diff 一起取回来（大仓库上传一大坨，
   而其中大多数文件读者一个也不点开）。
8. **git 由渲染器自己在宿主侧跑**：不进事件流、不进 `messages`、不过权限门与沙箱（只读、
   不写盘），失败给一句回执。**被否决**：复用 `src/tools/process.rs` 那套工具域的进程形状
   （要新开一条循环↔前端的通道）；走 `bash` 工具（会花 token，且「工具是动作的唯一入口」
   是针对模型的，而这是人在自己的终端里点开自己的仓库）。
   代价说在明处：渲染层今天**没有**「跑一次子进程、收 stdout、带超时」的形状（`opener.rs`
   不等退出也不收输出，`viewer.rs` 是交互式 pty），这一件是新写的；
   [research：宿主侧子进程、ANSI 与 `[ui]` 配置的接线](03-research-host-side-subprocess.md)
   要把可借的形状查清。
9. **刷新借既有的信号 + 一把手动键**：模型改完工作区（既有的 `WorkspaceChanged`）与提交之后
   各重取一次；再加一个手动刷新键（键位与手势归
   [grilling：刷新、陈旧与手动那把键](05-grilling-refresh-and-staleness.md)）。
   代价明说：**在外部 shell 或编辑器里自己 `git add` 不会触发那条信号**，所以数据可能旧着 ——
   这正是手动键存在的理由。**被否决**：只在选中这一页时取（切来切去会重跑 git）；
   页面可见时定时重取（多一条常驻定时器与持续的子进程开销）。

### F. 上色，以及外部工具那一档

10. **内置上色兜底**：复用现成的 `diff_tag`（它给的是**背景**色，正好与语法前景叠加）+
    **按扩展名挑语言**的 `highlight_code`（照文件页那样）。一处要改：`highlight_diff` 今天
    写死按 Rust 高亮（`src/render/highlight.rs:436`）。
    diff 三色今天写死在 `highlight.rs` 里、不在 `palette.rs` —— 收不收进语义色板由 spec 定。
11. **另有一档 `[ui] diff_viewer`**：写成外部命令时，把那份 diff 交给它，**一次性收 stdout、
    当静态正文画进同一个弹窗**。**被否决**：像内嵌 nvim 那样嵌一屏外来终端（[ADR 0013](../../docs/adr/0013-nvim-file-viewer-is-an-alien-screen.md)
    那一档）—— `delta` 这类工具本身不是交互式程序，而 alien screen 要把键盘独占、pty 与
    `respond_to` 全买一遍；代价与收益不成比例。**也否决**了隐式探测 `PATH`（同一份代码在
    不同机器上画出来不一样）与「弹窗里逐个切」（多一套按键与状态）：**选法就是配置开关，
    缺省内置**，与 `[ui] file_viewer` 同形。
    这一档自己的形状（命令怎么被调用、输出是不是 ANSI、命令不在时怎么办）归
    [grilling：外部工具那一档的形状](06-grilling-external-viewer.md)，它等
    [research：git 的三个读数与输出的稳定性](02-research-git-readouts.md) 与
    [research：宿主侧子进程、ANSI 与 `[ui]` 配置的接线](03-research-host-side-subprocess.md)。

### G. 页签与不可用态

12. **常驻第四签，页签写 `改动`**。实算：四签在窄档 28 列下占 21 列，还剩 7 列填 `┄`。
    **被否决**：像 `todo` 那样「第一次有东西可显示才出现」（左边那条签的位置会在会话中途跳），
    页签写英文 `diff`（左栏是中英混排，但这一页回答的是中文问题「改了什么」，
    与 `调用量` / `文件` 更亲）。
13. **不是 git 仓库、或 `git` 不在 `PATH` 时：页签仍在，页里写一句**（与「工作区干净」同一处
    文案）。**被否决**：页签整个不出现 —— 那会让左栏的页签位置随工作目录变。
    具体文案归 [prototype：列表与弹窗在两档宽度下的排版](04-prototype-layout.md)。

### H. 键盘

14. **照文件页那套**：点左栏任意处把键盘交给这一页（焦点行 = 点的那一行）、`↑`/`↓` 移行、
    `Esc` **只**还键盘（不取消正在跑的回合），滚轮按指针位置归这一页。
15. **但 `Enter` = 开那份 diff**，不是插 `@路径` —— 「把一个路径搬进草稿」是文件页的语义，
    不搬过来（要那个出路，去文件页）。不做键盘的「只认鼠标」那一档：纯键盘也要能开 diff。
16. **页签切换仍然只靠点、不给键位**（`Tab` 归 `/` 菜单、`Shift+Tab` 归模式循环）——
    与文件页那条规矩一致。
