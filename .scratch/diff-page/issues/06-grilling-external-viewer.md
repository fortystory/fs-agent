# 06 — grilling：外部工具那一档（`diff_viewer`）的形状

Type: grilling
Status: resolved
Part of: ../map.md
Blocked by: 02, 03

## 问题

[01 号票](01-charting-decisions.md) 定了两半：**内置上色兜底**（现成的 diff 三色 + 按扩展名的
语法高亮），外加一档 **`[ui] diff_viewer`**：写成外部命令时，把那份 diff 交给它、**一次性收
stdout、当静态正文画进同一个弹窗**。选法是**配置开关、缺省内置**（与 `[ui] file_viewer` 同形），
**不是**隐式探测 `PATH`、也不是弹窗里逐个切；形状上**明确不是**内嵌 nvim 那种一屏外来终端
（[ADR 0013](../../docs/adr/0013-nvim-file-viewer-is-an-alien-screen.md)）。

这一票是在上面这些已经定死的前提下，把**这一档自己的形状**问清楚。它等两件事先落地：

- [research：git 的三个读数与输出的稳定性](02-research-git-readouts.md)（diff 原文长什么样、
  argv 与环境的卫生怎么写）；
- [research：宿主侧子进程、ANSI 与 `[ui]` 配置的接线](03-research-host-side-subprocess.md)
  （有没有通用 ANSI → span 的解析件、`[ui]` 配置的文法、进程形状）。

要谈清的：

1. **配置的文法与缺省**：`diff_viewer = ""`（空 = 内置）还是一个程序名？还是像 `CustomTool`
   那样允许**带参数**（`diff_viewer = "delta --paging=never"` —— 那就牵出「怎么切词、过不过
   shell」）。本仓库「argv 模板按整元素替换、绝不过 shell」那条规矩（`docs/custom-tools.md`）
   要不要直接搬过来。
2. **diff 从哪进那个程序**：走 **stdin**（`delta` 的常见用法就是被 pager 调用、吃 stdin）、
   还是给它一个路径让它自己去跑 `git diff`（那它就要自己处理 cwd、HEAD 与未跟踪文件，
   我们对它输出的控制也更弱）、还是落一个临时文件。三档各要什么代价（临时文件的清理、
   打码那套要不要管、`/tmp` 在沙箱外）。
3. **参数由谁给**：要不要由我们注入几个默认参数（禁分页、强制颜色 / 不强制、`--width` 之类
   与弹窗宽度对齐），还是全交给用户配。若注入，注入哪些、用户配的能不能覆盖。
4. **输出怎么画**：这一档的输出由**外部程序**决定形状 —— 它的 ANSI 我们要不要解析成我们的
   span，还是原样透传（原样透传意味着它的颜色不受语义色板管、也与我们自己的底色叠加时可能
   花掉）。答案取决于 03 查回来的「有没有通用 ANSI 解析件」：有就解析成 span，没有就要在
   「只认 SGR 子集」与「不解析、原样画」之间选一个，并说清代价。
5. **失败与超时**：命令不在 `PATH`、非零退出、超时 —— 回退内置那一档（并给一句回执），
   还是把 stderr 当正文画出来？临时文件那一档还要说清清理。
6. **弹窗里要不要标出这一份是谁画的**：标题上写一笔（`delta` 画的）还是完全不提 ——
   不提的代价是同一份 diff 在两台机器上长得不一样，而读者不知道为什么。
7. **它有没有底线**：我们**能**保证的还是原样那份文本吗（拖选复制出来的是外部工具的着色
   输出，还是我们手里那份干净的 diff）？这一条与**选区**那条既有规矩（复制出来的是文本、
   不是样式）相邻，要有明确答案。

每问给一个推荐答案与理由；答案收进本票 `## 作答`。若某一问的答案取决于一台真装了 `delta`
的机器上的观感，那一问就按 `/prototype` 走：把那个工具的输出真跑一遍、贴几行关键帧。

## 作答

### 前提：这台机器上没有可试的工具

`delta`、`diff-so-fancy`、`colordiff`、`difft` **一个都没装**（`command -v` 逐个查过；只有
`/usr/bin/bat`），用户的 git 配置里也没有 `core.pager` / `diff.external`。所以票尾那句「真跑
一遍 delta」的原型**跑不了** —— 这一档今天装上也没有真实工具可验，只能拿假输出验。
替身是 [`prototype/external_tool.py`](../prototype/external_tool.py)：它扮演一个 delta 类的
工具（丢头行、给行号、按标记上色、hunk 头重排），吐真 SGR，再按下面的规则解回 span。
**真机观感项**（装了真工具之后这一档好不好看）交给折 spec 时写进 `docs/tui-manual-checklist.md`。

### 七问的答案

1. **做到全档**：配置 + argv + stdin + 一个**只认 SGR 子集**的解析器 —— 外部工具的颜色保留。
   **被否决**：只做配置与接线、ANSI 一律剥掉（装了 delta 只能看到无色的重排结果，等于砍掉
   这一档一半的意义）；整档推后（那是把 seed 里那条意向往后扔）。
   代价写在这里：新写一个解析件；而且**这一档的颜色不经过语义色板** —— 折 spec 时要落一条
   **ADR**（与 [ADR 0013](../../docs/adr/0013-nvim-file-viewer-is-an-alien-screen.md)
   「一块矩形不受视觉纪律约束」同族，但形状不同：那是一条外来**屏幕**，这是一次外来**输出**）。
2. **文法 = 程序名 + 相邻的 argv 数组**：`diff_viewer = "delta"` 配
   `diff_viewer_args = ["--paging=never"]`。沿用本仓库「argv 按**整元素**替换、**绝不过 shell**」
   那条规矩（`docs/custom-tools.md`），不涉及切词歧义。**不写 `diff_viewer`（或写空串）= 内置
   那一档**，与 `[ui] file_viewer` 的缺省同一个立场。
   **被否决**：只有程序名（想要 `--paging=never` 得自己写包装脚本）；一整行按 shell 切词。
3. **diff 走 stdin**：我们把 `git diff HEAD -- <path>` 的 stdout 喂进去。delta 这类工具的常见
   用法就是被 pager 调用、吃 stdin，而我们对「喂什么」完全掌控。
   **被否决**：给它路径让它自己跑 git（它要自己处理 cwd、HEAD 与未跟踪文件）；落临时文件
   （多一份要清理的临时数据，而 `/tmp` 在沙箱之外）。
4. **只给环境变量，不注入命令行参数**：`PAGER=cat` 与 `GIT_PAGER=cat`（不让它去起自己的
   pager 把我们卡住）、`COLUMNS=<正文宽>`（宽度对齐 —— 120 列屏是 112，80 列屏是 72）。
   一条命令行参数都不注入：工具那么多，猜谁认什么是白猜，认不出的直接因未知参数报错。
   **被否决**：注入一组「约定俗成」的参数；什么都不给。
5. **输出按「只认 SGR」画**：认下来的是 SGR（`ESC[…m`）那一族 —— 重置、前景、背景、粗体、
   暗淡；**认不出的颜色档**（256 色之后的写法、truecolor）落到「退成 `PLAIN` 或按最近似的一档
   收下」，由绘制侧定；**其他 CSI 序列**（光标移动、清屏、`K` 那一类）**整段丢掉** —— 我们
   不搬一台终端模拟器。原型证明一个 ~30 行的解析器够用（`prototype/external_tool.py` 第 2、3
   段就是它在真 SGR 上的读数）。
   画出来之后**仍走我们自己的正文管线**：按正文宽折行（`pane::wrap_line`）、有界截断、
   可滚动 —— 外部工具只决定「文本与颜色长什么样」。
6. **失败与超时**：超时 **2 秒**（git 那三个读数实测是百毫秒级，这一档给它宽出一大截）；
   命令不在 `PATH`、非零退出、超时 —— 一律**回退内置那一档**（正文永远是那份 diff），
   并在提示行给一句回执（`delta 不可用，用内置呈现` / `delta 超时`）。
   **被否决**：把 stderr 画进正文（读者会把它当成 diff）；只写一句错误不回退（他点开就是
   想看 diff）。
7. **标题右端标出工具名**（`delta`），内置那一档不标 —— 同一份 diff 在两台机器上长得不一样时，
   读者知道为什么。**被否决**：完全不提（有人会以为是渲染器改版了）。

### 一条底线（顺带答的）

**拖选复制出来的仍是文本。** 因为我们把 ANSI **解成了 span**、而不是把转义序列留在文本里，
所以选区那套照旧成立（「复制出来的是文本，不是样式」）。这是「只认 SGR」那条路的附带好处，
也是它比「原样透传」更值的地方。

### 边界

- **未跟踪文件也走这一档**：那种情况下「那份 diff」是全文，读者选了外部呈现就一视同仁。
- **执行者 / 讨论者不参与**：这一档是渲染层的呈现，与谁在跑无关。
- 这一档**不新增 git 调用**：diff 仍是第 3 条那一次，只是多了一次「把它喂给谁」。
