# 09 — 改动页画出一列改动的文件（tracer bullet）

Type: implement
Status: done
Part of: ../map.md
Blocked by: —

> 规格：[`../spec.md`](../spec.md) 的实现决定 §1 / §2 / §3 与用户故事 A、D 的一部分。
> 这是这一 feature 的 **tracer bullet**：页签壳、宿主侧取数件、列表排版一次打通。

**What to build:** 进 TUI，左栏就有第四签 `改动`，里面是**真实的**改动清单。这一票把「渲染器自己
跑 git」那一件从无到有立起来：后台线程上跑、结果经既有那条回填通道回来、列表按状态分组画出来。
用户看得见的是三样：页签出现、清单出现、四句文案按情形出现。

## 验收

- [x] 左栏页签条上出现第四签 `改动`，**常驻**（不因工作区状态出现或消失）；40 / 28 两档都画得下
- [x] 页区列出改动的文件：口径是**相对 HEAD**（已暂存 + 未暂存 + **未跟踪**），未跟踪的目录按
      `-uall` 展开成文件，所以一行永远是一个文件
- [x] 一行 = 状态字形（占满两格）+ 空格 + 相对 cwd 的**全路径**；`XY` 折字形取「工作区那一位
      优先」（`MM` / ` M` / `M ` 都画 `M`）
- [x] 先按状态分组（`已修改` / `新增` / `已删除` / `未跟踪`：占整行、不带计数、**不给色**、空组不画），
      组内按路径字典序
- [x] 超宽路径**尾部 `…`**；放不下时画满页区并在末行写 `还有 M 处改动`
- [x] 四句文案：干净 `没有改动`、不是 git 仓库 `这里不是 git 仓库`、找不到 git `找不到 git`、
      还没取到数 `正在读取改动…`
- [x] 取数跑在 `tokio::spawn` 出去的子进程里，超时 2 秒，**一帧里不 await**
- [x] 锁法逐条落实：`--no-color`、`--no-ext-diff`、`--src-prefix=a/ --dst-prefix=b/`、`--no-pager`、
      `--unified=3`、`-unormal` / `-uall`、`--no-optional-locks`；环境里清掉 `GIT_DIR` / `GIT_WORK_TREE`
- [x] 失败判据是退出码与 `ErrorKind`，**不靠 stderr 文案**（它随 locale 本地化）
- [x] 取数**不进事件流、不进 `messages`、不过权限门与沙箱**
- [x] 帧测试用**状态机口子**驱动（拉取数位、回传结果），不起真任务、不跑真进程
- [x] 纯函数单测：porcelain v2 的 `-z` 切分与路径原样、`XY` 折字形、路径尾部截断
- [x] 集成测试（真 git 的临时仓库）：三态齐备、**空仓库（无 HEAD）**、非仓库、`status` 不写回 index
- [x] `CONTEXT.md` 的**左栏**词条写上第四页；`docs/render.md` 的左栏一节写上这一页是什么

## 评论

落地（2026-10-08）：`src/render/changes.rs`（porcelain v2 的解析、分组排序、取数）与
`src/render/hostproc.rs`（宿主侧子进程：进程组 + 2 秒上限 + 收 stdout）一次打通页签、清单与取数
三件。帧层断言走状态机口子（`take_changes` / `changes_loaded`），真 git 的临时仓库覆盖三态齐备、
空仓库（无 HEAD）、非仓库与「读一次不写回 index」。真终端 pty 里确认过：第四签在 128 列的左栏上
画得出来、点开之后清单是真实的改动（`已修改` + `M ` + 全路径 + 末行「还有 33 处改动」）。
