# 07 — grilling：改动页与文件页之间要不要一个指针

Type: grilling
Status: resolved
Part of: ../map.md
Blocked by: —

## 问题

左栏从这一天起有两页在说**文件**：`文件` 页说「工作区里有什么」（会话级索引，与 `@` 补全同源），
`改动` 页说「相对 HEAD 改了什么」（git 的口径）。两页的指针今天互不相通 —— 点 `改动` 页里的一行
只能开它的 diff，没有路回到那个文件本身。

seed 把这条记成第十个分叉（「点 diff 里的文件名，能不能顺手跳到文件页的同一份文件」）。
把它问清楚，因为它决定这一页要不要多两个手势与一个跨页状态。

要谈清的：

1. **点一行要不要第二条出路**：今天 `Enter` / 单击 = 开那份 diff。要不要再加一条
   （跳到文件页的同一份文件、或直接开文件内容弹窗、或右键菜单那一类）？三档：
   **不做**（要看文件本身，点 `文件` 页自己找）、**跳到文件页**（左栏切页 + 焦点行落到那一行 +
   必要时展开路径上的目录 —— 文件页的展开状态活在 `TuiState` 里，这条要写它）、
   **直接开文件内容弹窗**（弹窗里再给一条「看它的 diff」的对称出路）。
2. **`@路径` 插入在改动页有没有意义**：文件页的 `Enter` 是插 `@路径`，而这一页的 `Enter` 已经
   给了 diff。未跟踪的新文件恰恰是最值得插进草稿的一类（「我刚建的这个文件」）—— 要不要给一条
   键（`i`？）做同一件事，还是**不搬**（要插路径去文件页）。
3. **键盘归属要不要联动**：两页今天各自是一个「键盘在左栏」的归属位（文件页那套点在左栏任意处
   接管）。跨页跳的时候键盘跟着走还是留给输入区？
4. **这一页要不要反向指路**：文件页的焦点行上要不要也能「看这个文件的 diff」（那要求文件页知道
   git 的状态）—— 这条属于把 git 状态铺到两页，代价明显更大，要有明确的「做 / 不做」。

每问给一个推荐答案与理由；答案收进本票 `## 作答`。**任何一档都不要悄悄扩大范围**：真正的
grep / 跳转（`gd` 那种）、在 TUI 里编辑文件都在「明确不做」里。

## 作答

1. **不做第二条出路**：点一行与 `Enter` 都只开那份 diff。
   理由落在一句话上：**两页各自回答一个问题** —— 文件页答「工作区长什么样」（会话级索引，
   与 `@` 同源），改动页答「相对 HEAD 改了什么」（git 的口径）。想看那个文件本身，点 `文件` 页。
   **被否决**：跳到文件页的同一文件 —— 四件事换一次「少点一下」（切页、定位焦点行、展开路径上的
   目录、定跳过去之后键盘归谁，文件页的展开状态还活在 `TuiState` 里）；直接开文件内容弹窗 ——
   弹窗里再套一层弹窗，入口与返回手势都要重想。
2. **`@路径` 插入不搬过来**：这一页的键位就五个（`↑` / `↓` / `Enter` / `Esc` / `r`）。
   理由：`@` 记号是「把一段路径搬进草稿」，那是文件页的语义；而未跟踪的新文件在文件页那棵树里
   也有（索引与 git 无关，遍历照旧）。**被否决**：给一条键插 `@路径`。
3. **键盘归属不联动**（跨页跳转不做，这一问随之消失）。
4. **文件页不反向指路**：不让文件页的焦点行上再挂一条「看这个文件的 diff」—— 那要求文件页知道
   git 状态，而它今天只认那份与 git 无关的索引，代价明显更大。这一条与第 1 条一起写进图的
   「明确不做」。
