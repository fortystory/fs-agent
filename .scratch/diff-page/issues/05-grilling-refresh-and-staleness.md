# 05 — grilling：刷新、陈旧与手动那把键

Type: grilling
Status: resolved
Part of: ../map.md
Blocked by: —

## 问题

[01 号票](01-charting-decisions.md) 定了刷新**借既有的 `WorkspaceChanged` + 提交之后，另加一把
手动刷新键**，并且挑明了代价：**在外部 shell 或编辑器里自己 `git add`、自己改文件不会触发那条
信号**，所以这一页可能旧着。这一票要把「旧着的时候怎么办」问清楚 —— 它决定这一页会不会让
读者信错数据。

要谈清的：

1. **手动那把键**：哪个键？（文件页今天没有刷新键，左栏页的键位只有文件页那一套 `↑↓←→ Enter
   Esc`；`r` 空着。）它是**键盘在改动页时**才有效，还是全局？「页面没被选中时按」算不算？
   要不要像 `Ctrl-O` 那样给提示行一句回执？
2. **陈旧怎么表达**：要不要把「上次取数的时刻」画出来（页脚一行？`wording` 里怎么措辞）？
   还是只在**旧于某个阈值**时才提示？还是干脆不表达、靠那把手动键兜着？三档的取舍：页面上多
   一行常驻信息 vs 读者可能信错数据 vs 界面更干净。
3. **外部改动能不能也发现**：有没有办法知道「工作区被本进程之外的谁改过」（文件 mtime、
   `.git/index` 的 mtime、inotify）—— 若答案是「要 watch 一整棵树」，那是另一个 effort，
   本票只要一句「不做」加理由。**这一条要查事实**（`git status` 自己会不会读 index /
   fsmonitor、`.git/index` 的 mtime 在 `git add` 之后确实变），不要凭印象。
4. **触发点的合并与不丢**：连续几次 `WorkspaceChanged`（模型连跑几条 `bash`）该合并成一次重取；
   `files-page` 的 `FileIndex::begin()` 守卫 + `file_scan_wanted` 位是先例 —— 这一页照抄还是
   共用同一个位（共用的话，改动页的重取会跟着文件索引的重扫一起被合并，那是好事还是坏事）？
   重取进行中又来触发：丢掉、排队、还是置位等下一次。
5. **页面不在前台时跑不跑**：`WorkspaceChanged` 到达时这一页没被选中（左栏收起了、或停在
   `文件` 页）—— 照旧重取（一帧里画不出来的活白跑），还是标一个「脏」位、等这一页被选中再取？
6. **`/undo` 与执行者 / 讨论者**：`files-page` §2 给 `/undo` 单独补了一次触发（它不走工具
   派发），而执行者与讨论者的调用都算触发点（同一条父流、同一个渲染器）—— 这一页照旧吗？
7. **失败怎么读**：git 跑了但失败（超时、仓库在但 HEAD 不存在、stderr 有话说）—— 页里写什么、
   提示行要不要给一句、旧内容要不要留着（留着更可能被误读）。

每问都给一个推荐答案与理由，答案收进本票 `## 作答`。

## 作答

1. **手动刷新 = 键盘在改动页时的 `r`**。`r` 今天没人用（`Char('a')` / `g` / `j` / `k` / `s` / `S` /
   `x` / `y` / `Y` / `z` 都被占着），它落在**文件页那套键盘归属**上 —— 点左栏任意处把键盘交给
   这一页之后才生效，与 `↑`/`↓`/`Enter`/`Esc` 同一层。回执走提示行一句（`已重取改动`）。
   **不给全局键**：`r` 是普通字符，全局按会与输入区的打字抢键。
   **被否决**：点页签顺带重取（从外部 `git add` 完回来，还得切到别的页再切回来）。
2. **陈旧不表达**：页里既不画「上次取数时刻」，也不做阈值提示。理由：页区只有 15 / 19 行，
   常驻一行的成本是永久的，而它买到的东西按一下 `r` 就有。重取与失败各给一次提示行回执，
   页里只在**还没取到数**时写 `正在读取改动…`（[04 票](04-prototype-layout.md) 定那一句）。
3. **不做 watch**：不盯工作区、也不盯 `.git/index` 的 mtime 或 inotify。理由：那要 watch 一整棵
   树，或者引入一个文件监视器并想清楚它与沙箱、与外部编辑器的关系 —— 那是另一个 effort；而三个
   读数的成本是百毫秒级（[research：git 的三个读数与输出的稳定性](02-research-git-readouts.md)），
   `WorkspaceChanged` + 一把 `r` 已经够。**这一条写进图的「明确不做」**。
4. **合并与不丢照抄 `file_index` 那道守卫，但用自己的一位**：形状就是「一个位 + 在飞时不发、
   位留着补发」，最多延后一轮（`.scratch/files-page/spec.md` §2 那一套）。
   **不共用 `file_scan_wanted`**：文件索引的重扫与改动页的重取是两件事（一个走遍历、一个走子进程），
   节奏与失败模式都不同，共用一位会让一方的失败拖住另一方。
5. **页面不在前台也照旧重取**：与 `files-page` 的重扫同构（那条也不管在不在前台），切回来即时
   看到。代价明说：没人看时也会跑一次子进程（实测百毫秒级，且 `--no-optional-locks` 保证它
   不写 index）。
6. **`/undo`、提交之后、执行者与讨论者的调用都算触发点**：照
   [`files-page` §2](../../files-page/spec.md) —— 执行者与讨论者的调用落在同一条父流、同一个
   渲染器上；而 **`/undo` 不走工具派发**，要在它自己那条分支上单独补一次。
7. **失败保留上一次读数 + 提示行回执**：列表与正文都不动，提示行写 `改动取数失败：…`。
   **被否决**：页里换成一句错误 —— 一次超时就把读者正在看的那份列表抹掉。
