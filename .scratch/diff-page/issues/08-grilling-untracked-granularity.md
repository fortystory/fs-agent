# 08 — grilling：未跟踪的粒度（目录一行，还是展开成文件）

## 问题

这条原本写在图的「尚未明确」里，[research：git 的三个读数与输出的稳定性](02-research-git-readouts.md)
查回事实之后它**可以说清了**，于是升级成票。

事实（findings 在 [`research/02-git-readouts.md`](../research/02-git-readouts.md)）：

- `git status` 默认把未跟踪的**整个目录**折成一行（`?? dir/`），展开成文件要 `-uall`；
- 代价实测：本仓库 4–6 ms；10537 个文件的真仓库 23–25 ms；**10 万个未跟踪文件 + `-uall`
  ≈ 60 ms、输出 1.5 MB** —— 代价由**未跟踪文件的个数**驱动，不是被跟踪文件数；
- 这一页**明确不做过滤与搜索**，所以一屏几千行时读者没有出路。

要谈清的：

1. **列表里那一行是不是「一个文件」**：这一页今天的不变式是「一行 = 一个文件 + 一个状态字形」，
   而目录行破坏它（目录没有单一的「改动」）。三档：
   - **全展开**（`-uall`）：一行永远是一个文件，不变式干净；代价是新建一整个目录（比如
     `target/` 那种生成物没被 `.gitignore` 挡住时）会灌进几千行。
   - **保留 git 的折叠**：目录一行，点它**在列表里展开**成它下面的文件（这一页自己的一份展开
     状态，像文件页那棵树；不进 git、不改索引）；代价是多一层状态与手势，且「先按状态分组」
     之后组里混着目录与文件。
   - **保留折叠**，点目录行**在弹窗里列出**它下面的文件（列表不动）；代价是读者要开弹窗才知道
     里面有什么，而弹窗那一套今天只画「一份正文」。
2. **`?? dir/` 与 `?? file` 在列表里长得一样**：状态字形都是 `??`，要不要在字形或字形列上
   分出「这是目录」（文件页那边目录是 `▸` / 尾斜杠 + 每行占满两格的字形列）。
3. **上限**：若选全展开，超过多少行时要写一句「还有 N 个未跟踪文件」（选一个数，`prototype`
   票的语域），还是让它照实列完。

每问给一个推荐答案与理由，答案收进本票 `## 作答`。

## 作答

1. **全展开（`-uall`）**：列表里**一行永远是一个文件**，与「一行 = 一个文件 + 一个状态字形」
   这条不变式一致。实测代价很小：10 万个未跟踪文件 + `-uall` ≈ 60 ms、输出 1.5 MB，本仓库
   4–6 ms（[research：git 的三个读数与输出的稳定性](02-research-git-readouts.md)）。
   而 `.gitignore` 挡住的目录（`target/` 一类）根本不会出现，所以「一处新目录灌进几千行」的
   风险只落在**没被忽略**的真源码目录上。
   **被否决**：保留 git 的目录折叠（要多一层展开状态与手势，而且「先按状态分组」之后组里会
   混着目录与文件）；点目录行开弹窗列文件（弹窗那一套今天只画「一份正文」，为它再长一层不成比例）。
2. **`?? 目录` 与 `?? 文件` 的区分**：随上一问消失 —— 列表里只有文件行。
3. **上限不另立**：照 [prototype：列表与弹窗在两档宽度下的排版](04-prototype-layout.md) 那条
   「画满页区 + 末行写一句「还有 M 处改动」」。
