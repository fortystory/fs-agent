# 语言迁移：散文一律中文

Status: done（2026-09-27 收尾：两张票都落地，没有未做的了）

- **决定**：[`docs/adr/0004-prose-in-chinese-identifiers-and-model-text-in-english.md`](../../docs/adr/0004-prose-in-chinese-identifiers-and-model-text-in-english.md) —— **散文一律中文**（代码注释、`docs/` 下的设计文档与 `docs/agents/`、测试的断言消息、只给人看的错误文本）；**英文只留给三类**：标识符、**模型可见**的文本、**进事件流要永久回放**的文本。`docs/research/` 是一手引文，一个字不改。
- **动机**：读者是人（注释与设计文档服务的是读代码的人），而模型可见 / 进流那一侧动一次要付两笔（前缀缓存整体作废 + 老流永久中英混排）、收益又几乎没有（那一侧的读者是模型）。
- **它取代**：`README.md` 的「约定」一节里「`docs/` 与 `docs/agents/` 写英文」那一条（已改），以及 ADR 0001 里「写成英文」那半句（ADR 0001 的「模型可见文本冻结」那一半被原样保留并**加强**成可执行检查）。
- **术语**：`CONTEXT.md` 是词汇源；迁移时用它给的中文名（事件流 / 投影 / 转录 / 左栏 / 状态行 / 回合条 / 讨论者 / 执行者 / 权限模式 / 待办列表…），标识符保持英文。

## 规模（迁移前实测）

`src/` + `tests/` 的英文注释 **9,211 行**（≈59 万字符）、`docs/*.md` 英文正文 ≈10 万字符（17 份）、`tests/` 的英文断言消息 **1,082 条**（≈4.9 万字符）、给人看的错误文本 ≈2 万字符。合计约 92 万字符。

## 方法（下次照这个做，别重新发明）

1. **按模块切批**，一批 ≈1,000–1,500 行注释（一个 `src/` 大模块，或几个中小文件合起来）。派一个 subagent 做一批，它只改自己那批的文件。
2. **批次 brief 的硬性内容**（措辞可以变，这几条不能少）：
   - 只翻 `//` / `///` / `//!` 的正文，以及（测试模块内外的）`assert!` / `assert_eq!` / `panic!` / `expect("…")` 的**说明性字符串消息**；
   - **除此之外一个字符都不许改**：代码、标识符、类型名、字段名、模式匹配、数字、**字符串字面量**（除断言消息）；
   - 明确点名**该批文件里不能碰的串**（工具声明与结果、`reason`、`detail`、投影前缀、协议标记、身份提示、测试数据、被断言的字面量）；
   - 术语照 `CONTEXT.md`，风格照已翻好的邻居：**保留原文里「为什么这么做」「这是刻意的，不是 bug」「代价是什么」「踩过的坑」这类判断**，不要压缩成正确的废话；
   - 分节线 `// --- 标签 ----`：标签翻中文、破折号补齐到**与本文件其它分节线相同**的宽度；纯破折号行原样；
   - 行宽 ≤ 100 视觉列（中文按 2 列算）；不删注释、不合并、不重排代码；
   - **不要新建文件**（临时脚本写 `/tmp/`，别写进仓库——有两次执行器在 `.scratch/` 下留过 py 脚本）；
   - 改完**用一次 `git commit` 提交本批的文件**（中文提交信息，逐文件 `git add`，别 `-A`）；
   - 回报：翻了多少行/条、拿不准的地方、提交 hash。
3. **每批的验收**（我这边做，不交给执行器）：
   - `python3 scripts/check-translation-batch.py --diff $(git show --stat --name-only --format= HEAD) [--assert-msgs]` —— diff 里除注释行（与测试断言消息）外不许有代码改动；
   - `cargo test`：**757 passed / 0 failed**（条数不能变）；
   - `python3 scripts/check-language.py`：必须 OK。
4. **收批**：`git add -A`（或点名）+ 中文提交信息；一批一个提交。
5. **全部翻完后**跑一次 `cargo fmt`（中文注释的视觉宽度不同，`rustfmt` 会连带重排带行尾注释的代码行；实测约 180 处），再提一次纯格式提交。

## 已知代价与取舍（如实记）

- **中文注释更长**（同义句长 10–20%），注释行数会变少或变多，语义不许变；`rustfmt` 会因此重排少量代码行（见方法第 5 步）。
- **老流与新流在语言上仍是混的**：`reason` / `detail` / 工具结果 / 投影前缀永不翻译（ADR 0001 的冻结面），所以升级前的会话重放出来和升级后一样是英文的 —— 这一侧没动，这是刻意的。
- **迁移窗口期双语言**：`git log` 上有一串「只动注释」的提交，看不懂代码时按提交分界读。
- **翻译是判断活**：注释里写着「这是刻意的，不是 bug」的地方必须保留那个判断；批量机翻会把它们压成正确的废话 —— 所以按模块小批、逐条翻，不用一次性 bulk。
