# 用量不再是独立一行：它长在产生它的那次调用的行上

Status: 2 done + 1 ready-for-walkthrough（2026-10-07 一轮六问的 grilling；三张实现票
[`issues/01`](issues/01-usage-tail-on-call-row.md)、[`issues/02`](issues/02-turn-total-tail.md)、
[`issues/03`](issues/03-tests-docs-and-existing-misplacements.md)）

轨迹页里每次模型调用都独占一行：

```
12:21:07 [deepseek] 用量 in=9607 out=1014 cached=8320 miss=1287
12:21:07 [deepseek] ▸ ✓ 思考完成
```

第二行属于**这次**调用，第一行却不属于它 —— 一笔花费与产生它的那次调用隔着一堆行，读的时候
要来回配对。这份 spec 把它长到产生它的那次调用的行尾，并在回合收尾补一条合计。

它推翻 [`trace-tab/spec.md`](../trace-tab/spec.md) §3 的「**其余块**今天就已经各占一行，不改」
那半句 —— **仅就 `Usage` 这一块**。其余块那一句仍然成立。

## 问题陈述

1. **归属错位。** `Block::Usage` 是流上一条独立的块，轨迹页照既有规矩给它一整行。它说的是
   「这一次模型调用花了多少」，而屏幕上它与那次调用之间没有关系可言 —— 相邻的那一行通常是
   上一次调用的残留，不是它的产物。
2. **落点还会出错。** 两句都对：`UsageRecorded` 排在 `MessageCompleted` **之前**，而工具行
   （`Block::Tool`）由 `ToolCallCompleted` 产出、排在 `MessageCompleted` **之后**；同时
   `settle_thinking` 用 `replace_last` 就地重写窗格最后一行、不查那一行的身份。于是
   「只推理、不产出正文」的那次调用会把刚 push 的用量行整行顶掉；宽度变化重放时若清单里
   `Usage` 夹在思考行与定稿之间，定稿会走追加、留一行「正在思考」永不消失。
3. **一个回合的总账无处读。** 工具循环里一次发言可以跨好几次模型调用，左栏 `调用量` 页给的是
   **会话**累计，轨迹页只有一串单次读数，没有「这一轮回答一共花了多少」。

## 方案

- 每次模型调用的用量**并入该次调用的最后一条过程行**（有工具就落工具行，没有就落思考行），
  在**该次调用收尾之后**贴上去。
- 没有可承载的过程行时（合成器那次调用；或该次调用只留下消息行）**保留独立用量行**。
- 一次发言跨 ≥2 次调用时，收尾的 `回合结束` 行尾加一条 `合计 in=… out=…`。
- 两处既有错位一并修掉：它们正是这次要动的那条路径。

## 用户故事

1. 作为读者，我想让一次调用的用量跟它的产物读在一起，以便一眼看出这笔花费是为什么花的。
2. 作为读者，我想在轨迹页上一眼看出「这一轮回答一共花了多少」，而不是自己把几次调用加起来。
3. 作为读者，我不想因为合并而少看见任何一笔用量 —— 贴不上行的那些仍然各占一行。
4. 作为读者，我想让合并后的那一行仍然点得开它原来的详情（思考全文 / 工具参数）。
5. 作为使用窄终端的读者，我接受这一行按既有规矩折行，不想为此多一套降级链。
6. 作为维护者，我想让尾巴与合计跟着绘制记录走，以便宽度变化重放、`--continue` 重放与实时
   三者落点一致。
7. 作为维护者，我想让 `usage_summary`、`plain`、`headless`、`sessions stats` 一个字不动 ——
   它们是诊断通道，不随显示制式走。

## 实现决定

### §1 尾巴落在哪一行

宿主 = **用量到达那一刻，这次调用最后画出来的那条过程行**。判据落在绘制记录上：贴的时候取
`painted` 清单最后一条，且它**不是消息行**、也不是一条独立的用量行。

用量到达时，这次调用画出过的行只可能是两种：**思考行**（这次调用推理过），或**回合开始
（第 N 次迭代）**行（没推理过）。归属因此永远正确 —— **上一次调用的行不可能还在末尾**，
因为每一次调用都以自己那条 `回合开始` 行打头。

- `Painted::Thought` / `Painted::Thinking`（思考行）、`Painted::Block` 里除 `Block::Message`
  与 `Block::Usage` 以外的块都能承载。
- **工具行不是宿主**：它在用量之后才落地（`Block::Tool` 由 `ToolCallCompleted` 产出，而那条
  事件排在 `MessageCompleted` 之后），而它记的也是工具执行、不是这次模型调用。
- `Block::Message` **不能**承载：它在轨迹页是「首行 + `…`」的内容入口，把数字挂在一条被省略
  号截断的内容行上读不出归属 —— 而它也排在用量之后。
- 清单为空、或最后一条不可承载时，走 §4。

### §2 到达就贴，不推迟

`UsageRecorded` 到达时当场贴到窗格最后一行，并把尾巴记进那条绘制记录。

曾考虑推到「这次调用收尾」再贴（好让工具行当宿主），**否决**：那次调用后面还会画**消息行**
（`MessageCompleted` 无条件产生一条块），等到收尾时最后一行是内容行，尾巴不是贴不上去、就是
贴错地方；而最常见的纯对话调用根本没有工具行。到达就贴则永远落在这次调用自己的行上。

`replace_last` 那条路要跟着走：思考行随后定稿是**整行重写**，所以尾巴存在绘制记录里
（`Painted::Thinking` / `Painted::Thought` 的 `tail`），重写时一起搬过去；宽度变化重放也从
同一条记录重建。

### §3 尾巴怎么写

`in={input} out={output}`，前面一个空格，`palette::MUTED`。整行于是读作

```
12:21:07 [deepseek] ▸ ✓ 思考完成 in=9607 out=1014
12:21:07 [deepseek] ▸ 调用 bash 查看 git status in=1204 out=88
```

- `cached` / `miss` **不进尾巴**：它们是缓存细节，完整四项仍归 `usage_summary` 那条通道
  （[`usage-stats-format/spec.md`](../usage-stats-format/spec.md) §「保持原样」）与左栏
  `调用量` 页。
- `wording::usage_summary` 一个字不改；尾巴是**另一份只给轨迹页用的措辞**（`usage_tail`）。
- `in` / `out` 保持原文，不给中文名（`CONTEXT.md` 的 **token** 条）。

### §4 缺位：保留独立用量行

没有可承载宿主的那一次调用，照旧自己占一行、与今天逐字相同：

1. **合成器**那次调用没有 `TurnStarted` / `TurnEnded`，不属于任何调用区间。
2. 绘制记录为空（理论上到不了：一次调用总以自己的 `回合开始` 行打头）。

### §5 回合收尾的合计

一次发言里模型被调用 ≥2 次时，该发言的 `回合结束：…` 行尾加一条 `合计 in=… out=…`，
口径是**这条发言内全部模型调用之和**。只调用一次时不加 —— 那笔数字就在那条尾巴上，再加一遍
是同一个数印两遍。

- 计数与累计都在渲染层：`TurnStarted` 记一次调用，`UsageRecorded` 累加，`TurnEnded` 读完之后
  清零。
- 合计文本要进绘制记录（`Painted`），否则宽度变化重放会拿到清零后的状态。
- 合计与尾巴一样是 `MUTED`，跟着那一行自己的严重度色走。

### §6 详情、时刻与宽度

- **详情一个字不改**：宿主行点开仍是它自己的详情（`DetailKind::Thinking` / `DetailKind::Tool`
  / …），尾巴是纯文本。`▸` 的判据「谁把内容折起来谁就有」不破 —— 尾巴没折任何东西。
- **时刻戳不动**：宿主行保留自己的戳，尾巴不带来新戳（时刻是**块**的属性，尾巴不是块）。
- **窄终端一律折行**：不新增降级链、不省略。尾巴比原来的四项短得多，`59` 列的轨迹排版宽下
  通常一行放得下。

### §7 两处既有错位一并修

1. 「只推理、不产出正文」的调用里，`settle_thinking` 的 `replace_last` 会顶掉刚 push 的用量行
   （`src/render/tui.rs` 的 `settle_thinking`、`src/render/pane.rs` 的 `replace_last`）。
2. 宽度变化重放时，若清单里思考行与它的定稿之间夹着 `Painted::Block{Usage}`，定稿走**追加**而
   不是就地替换，屏幕上留下一行永不消失的「正在思考」。

按 §2 的改法，用量不再作为独立条目插进清单中间，两处都自然消失；仍要各加一条回归断言。

### §8 明确不做

- **`usage_summary` / `plain` / `headless` / `sessions stats` 一字不动**：诊断与机器可读通道。
- **事件流与 `Block` 层一字不动**：`UsageRecorded` 仍是它自己那条事件，`transcript.rs` 不改。
- **对话视图不动**：过程行本来就不进对话视图，尾巴与合计只在轨迹页出现。
- **左栏 `调用量` 页不动**：它给的是会话累计与成本，与这里是一次调用的读数不是一回事。
- **不给尾巴加 `▸`、不加详情、不加颜色档**。
- **不做尾巴的降级链**（窄档照折行）。
- **合成器的用量不进任何合计**：它不属于任何发言边界。

## 决定速查

| 问 | 落点 |
| --- | --- |
| 尾巴落哪一行 | 用量到达时那次调用最后画出的那条过程行（思考行 / 回合开始行）；消息行与工具行都不承载（§1） |
| 什么时候贴 | 到达就贴；尾巴记进绘制记录，定稿重写与宽度重放都跟着走（§2） |
| 尾巴写什么 | `in=… out=…`，`cached` / `miss` 不进（§3） |
| 缺位怎么办 | 保留独立用量行：合成器那次调用（§4） |
| 回合合计 | ≥2 次调用时并进 `回合结束` 行尾，口径是该发言全部调用之和（§5） |
| 详情 / 时刻戳 | 都不动；详情仍归宿主行，尾巴不带来新戳（§6） |
| 窄档 | 照折行（§6） |
| 既有错位 | 一并修，各加一条回归断言（§7） |
| 诊断通道 | `usage_summary` 与三个非 TUI 渲染器一字不动（§8） |
