# fs-agent 运行时生命周期图：`docs/lifecycle.md`

Status: 8 done + 1 ready-for-walkthrough（2026-10-03 由 wayfinder 决策图 [`map.md`](map.md) 折成 —— 十五条冻结项 +
五张决策票全部 resolved；实现票由 `/to-tickets` 拆出，[`issues/06`](issues/06-doc-skeleton-and-overview-diagram.md)–[`14`](issues/14-close-out.md)
同日全部落地；票 14 剩下的只有「在 GitHub 上把五张图看一眼」）

fs-agent 有 15 个顶层边界、3 个前端、4 档权限模式、3 类问询发起者，还有嵌套会话与一条只追加的
事件流。这些**分别在 `docs/` 的逐面文档里讲清了**，但**没有一处把它们连起来**：今天想回答「从敲下
命令到退出，到底发生了什么」的人，得自己在 `src/cli.rs`、`src/lib.rs`、`src/agent.rs` 之间拼。

这份 spec 要做的是**一张跨阶段的运行时生命周期图**，配一份「节点 → 代码哪一行」的证据表，和一个
防止它腐烂的护栏脚本。

## 问题陈述

1. **没有一张跨阶段的图。** 今天 `docs/` 里是「**一段流水线 + 若干局部树**」：
   [`README.md`](../../README.md) 的「架构」一节只有一行
   （`hook.pre → 权限门 → [询问] → dispatch → hook.post → 追加事件`），
   [`docs/executor.md`](../../docs/executor.md) 画一次 `task` 的流向，
   [`docs/credentials.md`](../../docs/credentials.md) 画入流流水线，
   [`docs/web.md`](../../docs/web.md) 画出网三层。每一张都对，但没有一张回答「全貌」。
2. **新读者付不起那个代价。** 想弄明白「主循环怎么起」「一次 turn 里 provider 与权限门谁先」，
   得同时读四个文件；而这个仓库的散文规范（ADR 0004 / 0005）要求散文是中文、标识符留英文，
   靠 gdb 式地跳代码拼出来的理解很难转述给别人。
3. **改一处不知道牵动什么。** 仓库里最有价值的一批知识是**不变量**
   （事件流是唯一真相源、工具表组装后不变、权限门在沙箱之外、取消只向下…），它们现在散在
   `README.md` 的段落与各份 ADR 里，没有一张图把它们**钉在某条边上**。
4. **已有的手绘 ASCII 撑不住规模。** 五处 ASCII 图里最大的那张只有十来个节点；而生命周期图要画
   24 个节点、跨四层。手绘的对齐与连线靠眼睛保证，错一笔没人看得出来。
5. **图会腐烂。** 这是一张要跟着代码走的图：`src/` 里改一个阶段，图里对应的节点就旧了。没有
   机器可读的对账物，它会在某次重构后悄悄变成错的 —— 而错的图比没有图更糟。

## 方案

新建 `docs/lifecycle.md`，装五张 **mermaid** 图（一张鸟瞰 + 四张分层详图）、一张逐节点
「证据表」，以及一节「**图上不能断的边**」；同时新建一个护栏脚本
`scripts/lifecycle-check.py`，把图和它的证据表按七条规则对账。

- 图与代码的**连接**是那份证据表：每个节点、每条关键边都落到 `文件:行号`，改代码时行号会漂、
  但符号不会 —— 表因此是「可核对的」而不是「抄一遍」。
- 图与检查器的**连接**是一条受约束的 mermaid 方言：只认几种写法，**不认识的构造报红**而不是
  静默跳过（解析器漏掉一个节点会伪装成「图里有、表里没有」，必须让它可见）。
- 这条线顺带在 `docs/` 里开一个先例：**流程图用 mermaid**（今天仓库零 mermaid 图，五处全是
  手绘 ASCII）。它值得一条 ADR，因为未来读者一定会问「为什么只有这份文档不是 ASCII」。

## 用户故事

1. 作为**刚接手这个仓库的开发者**，我想要一张一眼看得到「敲下命令到退出」全貌的图，以便我不必
   先读完 15 个模块的代码就能问对问题。
2. 作为**新读者**，我想要先看到鸟瞰、再按兴趣点进四张分层详图，以便我不被 24 个节点一次压垮。
3. 作为**维护者**，我想要知道「一次 turn」里每一步的**先后与回边**，以便我判断一个改动插在哪
   一步之后才成立。

   （`hook.pre → 门 → [询问] → dispatch → hook.post → 追加`），以便我不会把权限判断写到门之后。

    骨架走到细节。
12. 作为**维护者**，我想要在重构之后**知道图有没有和代码脱节**，而不是某天忽然发现它早就错了。
13. 作为**维护者**，我想要护栏脚本对「**不认识的 mermaid 构造**」报红，以便解析器的天花板是
    可见的，而不是悄悄漏掉一个节点。
14. 作为**维护者**，我想要**行号漂移只是一条提示、不是失败**，以便脚本不会天天报红、最后被
    所有人忽略。
15. 作为**维护者**，我想要护栏脚本**退出码是唯一机器信号**（仓库没有 CI，靠手工调用），以便我

16. 作为**未来的维护者**，我想要知道**为什么这份文档用 mermaid 而邻居是 ASCII**，以便我不会

## 实现决定

### §1 落点与交付物

- **新建 `docs/lifecycle.md`**（逐面文档那一族的成员）；[`README.md`](../../README.md) 的
  「架构」一节加一行指向它、`## 文档` 表加一行。**两处都要**，漏一处它就成了孤儿文档
  （`.scratch/README.md` 的 feature 行也要更新，那是 tracker 侧）。
- **新建 `docs/adr/0011-diagrams-in-mermaid.md`**（见 §7）。
- **新建 `scripts/lifecycle-check.py`**（见 §6）。
- **改 `scripts/check-language.py` 的 `DOCS_MIN_RATIO` 一行**：新文档按实测值 − 2 设下限
  （照 `AGENTS.md: 23` 的先例，它也是「字节少、标识符密」因而单独压低），并在脚本注释里写明理由。
  注意 `check_docs()` 只遍历清单里的键、**不扫 `docs/*.md`**：不登记就完全不受护栏，所以这一步
  是**必须**的，不是可选的。

### §3 画法约定（写在 `docs/lifecycle.md` §1）

- **方言是受约束子集**：`flowchart <方向>` 一行；节点定义 `id[文本]` 与 `id{文本}`；边
  `id --> id`、`id -.-> id`、`id -->|文本| id`；空行；`%%` 注释。**不允许** subgraph、`&`、
  链式（`A --> B --> C`）、`classDef` / `class` / `style` / `linkStyle` / `click`、`[]`/`{}`
  之外的节点形状。禁止项不是洁癖 —— 每一条都是解析器的失效点。
- **先显式定义、后引用**：mermaid 的 `A --> B` 会**隐式定义** B，所以「边指向一个不存在的节点」
  在原生语义下几乎不发生。要立这条约定，C7 才有意义。节点 id 限 `[a-z][a-z0-9_]*`，避开
  `end` / `graph` 这类关键字。
- **虚实判据**（完整版见 [`research/02-dashed-inventory.md`](research/02-dashed-inventory.md) §2）：
  **实线** = 这条路径在**至少一个 CLI 生产组装点**（交互式 / `discuss` / `probe`）上会真实走到 ——
  含配置开关打开的，也含一条 `None` 的**降级分支**（probe 的 `asker: None` 让 `Ask` 降级为 `Deny`，
  那是生产路径）。**虚线只给两类**：① 可注入但 CLI 不注入（类型与端口都在、调用点也在，但**每一个**
  生产组装点都传 `None`，且 `src/` 内没有生产实现）；② 尚未实现（`src/` 零命中，但 spec 已定并
  拆出实现票，即有一个**已写下来的接缝**）。今天各只有一条：`hook` 与 MCP。
- **不该画虚线的四种情形**：默认值 + 运行期补齐（沙箱的 `availability`）；前端差异（probe 没有
  `asker` / `questions`、非交互式没有目标循环）；配置可选（`[web] enabled`、`custom__*`、`--tui`）；
  测试替身（`FakeProvider` / `ScriptedHook`）。这四种画实线，必要时加暗示性的**旁注**。
- **只有 `seed.md` 的 roadmap 不进图**：那些意向连类型都没有，画进去会把生命周期图变成路线图。
- **图编号**：正文写「图 1–5」+ 稳定小标题，别的文档可以写「见 `docs/lifecycle.md` 图 3」。
- **约定的住所**：全文只住在 `docs/lifecycle.md` §1；`scripts/lifecycle-check.py` 的 docstring
  写一句 + 指向它。**不做两份全文** —— 两份必然漂移。

### §4 证据表

- 形状：每张图一节，含**节点表**（节点 id · 一句话 · `路径:行号` · 符号）与**边表**（边 · 证据 ·
  说明）。符号只取稳定的那一批（`fn` / `struct` / `enum` / `trait` / `const` / `static` / `mod` /
  `type` / `union`）；`impl` 与 `macro_rules!` 不作为证据符号（写法不统一）。
- 内容来源：[`research/04-node-evidence.md`](research/04-node-evidence.md)（343 行，逐节点已核实）。
- **每条证据必须指向一个真实存在的符号** —— 这是这份表的锚：行号会漂，符号不会。

### §5 「图上不能断的边」

单独一节，把那 **12 条不变量**逐条映射到图上的边（映射表已备好在
[`research/04-node-evidence.md`](research/04-node-evidence.md) §6）：事件流是唯一真相源、
`append_event` 是唯一写路径且打码在其前、工具表组装后不变、权限门在沙箱之外且是纯函数、每次调用
的固定顺序、每个 `tool_call` 恰好一个结果、取消只向下、委派深度为一、`Allow` 不传播、
`workspace` 档离开沙箱即不存在、两个讨论者共享同一条流、合成器那一次绝不跳过。

**这一节是「变更影响分析」那半个用途的落点** —— 图给骨架，这一节给判据。

### §6 `scripts/lifecycle-check.py`

定位：**只守「指称完整性」，不守语义正确性** —— 它不知道一条边画得对不对，只知道它两端都有人
认领。**「通过 ≠ 图是对的」这句要进 docstring**，否则护栏会被当成事实来源。只读、只打印、
只用退出码表态。

七条**计失败**（退出 1）的校验：

| # | 校验什么 |
| --- | --- |
| C1 | 每条 `路径:行号` 的文件存在、行数够（区间 `路径:a-b` 一并认） |
| C2 | 点名的符号仍在该文件里（按词边界找，不搜裸名字） |
| C3 | `docs/lifecycle.md` 仍被 `README.md` 引用（「文档」表或「架构」节任一命中即可） |
| C4 / C5 | 证据表的节点键集合 **==** 图的节点集合 —— **按图分别比对**，双向分开打印 |
| C6 | 节点 id 不重复定义 |
| C7 | 每条边两端都已**显式**定义 |
| C8 | 只用约定方言；**不认识的构造报红，不静默跳过** |

**C9（行号精确性）降级为告警 + `--strict`**：行号是结构性易漂量 —— 在文件顶部插一个 `use`，
下面所有证据行号 +1，而图与代码其实没脱节；计成失败会让脚本变噪音机器。

CLI：`python3 scripts/lifecycle-check.py [docs/lifecycle.md]`（缺省盯这一份）、`--list`（打印
解析出的节点/边/证据，用来核清单本身）、`--strict`（C9 也算失败）。退出码照
[`scripts/wayfinder-check.py`](../../scripts/wayfinder-check.py)：`0` 通过 / `1` 有失败 /
`2` 用法错。

**C4/C5 按图分别比对**这一点是对检查器设计的一处修订（原设计是整个文档一个集合、要求跨图唯一）：
五张图的节点 id 天然会撞名（`cmd` / `loop` / `ok` / `gate` / `red` / `goal`），逼它们全局唯一只会
长出 `g1_boot` 这种噪音前缀。**让检查器适应图，不是让图适应检查器。**

### §7 决定记录：ADR 0011

新建 `docs/adr/0011-diagrams-in-mermaid.md`，照邻居（`docs/adr/0010-*.md`）的四节结构：
`## 决定` / `## 为什么` / `## 代价` / `## 被否决的替代方案`。**完整草稿已经写在
[票 05 的 `## 作答`](issues/05-grilling-doc-skeleton-and-adr.md) 里**，实现时照抄。

其中把选 mermaid 的**首要理由**写死为：**图的节点集合是机器可读的** —— ASCII 图没有可解析的
结构，C4/C5 那条检查根本无从谈起。不是好看。

代价四条必须写全：① **终端里读不到图**（`mermaid` 不在 `canonical_language` 里，fs-agent 自己的
TUI 只把它当普通代码块渲染；要真正在终端画图是另一个 effort）；② `DOCS_MIN_RATIO` 要单独降低限；
③ 仓库第一次有第二种图语言（已有五处 ASCII 不动，"流程图跟这条走、局部一行式小图仍可手绘"）；
④ 多一个护栏脚本要维护，而它守不住语义。

### §8 标题与用词

- 章节骨架照[票 05 的 `## 作答`](issues/05-grilling-doc-skeleton-and-adr.md)：
  开头一段（这张文档是什么 / 怎么读 / 与逐面文档的分工）→ §1 画法约定 → 五张图各一节 →
  §7 图上不能断的边 → 附录逐图证据表。每节除图之外要有「这张图在讲什么」+ 一张「细则在哪」
  的指向表。
- 节点与正文用 `CONTEXT.md` 的正式用词：事件流 · 投影 · 讨论者 · 执行者 · 合成器 · 询问 ·
  用户提问 · 待办列表 · 翻页 · 落点 · 渲染器 · 终端端口 · 沙箱 · 打码 · 回合 · 轮次 · 目标。
- **`CONTEXT.md` 不收「生命周期图」这个词**：它是一份文档的名字，不是领域概念；文档索引在
  `README.md`，`CONTEXT.md` 不该变成第二个索引。
- **文档不拆**：脚本要同时读图和表；篇幅也没到（估 300–400 行）。

## 测试决定

**接缝一个：`scripts/lifecycle-check.py` 的命令行接口。**

这个 feature 的其余交付物（文档、ADR、索引行）没有可执行行为，由人评审；唯一有真实逻辑的是那个
脚本 —— mermaid 行级解析（切块 → 摘引号字符串 → 剥注释 → 按行分类）、集合比对、文件/行号/符号
校验、八条检查。它的外部行为就是：**给定一份文档，打印报告并返回退出码**。

- **用 Python 标准库 `unittest`**，新增 `scripts/tests/test_lifecycle_check.py`，
  `python3 -m unittest` 一条命令跑完，**零新依赖**。这会是本仓库第一个 Python 测试
  （现有四个护栏脚本都没有测试；这是有意的偏离，见下）。
- **测的是脚本的 CLI，不是它的内部函数**：所有断言打在「退出码 + stdout 里有没有那一项」上。
  内部函数可以随意重构而不动测试。
- **命令进 `README.md` 的「开发」一节**，与 `cargo test` / `check-language.py` /
  `tui-startup-check.py` 并列。

**好测试的判据**：只测**外部行为**（退出码与报告文本）；不测内部结构、不断言输出格式的精确
换行、不依赖真实仓库文件（用临时目录里的 fixture 文档）。与仓库既有规矩一致：测试断言对象是
外部可见的产物，不是实现细节。

新增用例（每条都对着一条校验项）：

1. **干净文档 PASS**：一份小 fixture（两三个节点、表与图一致、引用的符号真实存在）→ 退出 0。
2. **C1 文件/行数**：证据指向一个不存在的文件 → 退出 1 且报出该项；行号超出文件行数 → 同。
3. **C2 符号**：证据点名的符号被改名 → 退出 1；符号存在但行号漂了 → 退出 0，且 stdout 里出现
   一条**提示**（C9 是告警）。
4. **C3 README 引用**：README 里删掉那行引用 → 退出 1。
5. **C4/C5 集合相等**：图里多一个节点 / 表里多一行，两个方向各一条用例，报出的方向要对。
6. **C6 id 重复**：同一 id 定义两次 → 退出 1。
7. **C7 边端点**：一条边指向一个从未显式定义的 id → 退出 1；该 id 在**另一张图**里有定义 →
   仍然退出 1（按图分别比对）。
8. **C8 方言**：fixture 里放一个 `subgraph`（或 `&`、链式、`classDef`）→ 退出 1，且报「不认识的
   构造」，**不是静默通过**。这一条是整套测试里最重要的：它钉住「解析器漏节点会伪装成假差异」
   这个失效模式。
9. **`--list`**：打印出解析到的节点/边与证据键，用来核清单本身；退出 0。
10. **`--strict`**：行号漂移（第 3 条那种）在 `--strict` 下退出 1。
11. **用法错**：多给一个参数 → 退出 2；文档不存在 → 退出 1。

**测试的 prior art**：`scripts/wayfinder-check.py` 与 `check-language.py` 的**输出风格**（分行
标签 + `FAIL` 缩进项 + 退出码）是被测对象要照抄的；`scripts/tui-startup-check.py` 是仓库里
「脚本自己就是被测物」的先例。

**为什么值得破一次「脚本不写测试」的一致性**：这个脚本最危险的失效模式是**假绿** —— 解析器漏掉
一个节点、检查却通过。护栏自己烂掉而没人知道，比没有护栏更糟。而它的解析器有一张**已知的失效
清单**（15 种能骗过它的写法），第 8 条用例就是钉住那张清单的。

## 明确不做

- **在 fs-agent 的 TUI 里渲染 mermaid**：那是产品功能，不是这份文档的图；已另立
  [`tui-mermaid`](../tui-mermaid/seed.md) 的意向与一份一手调研。本 spec 的「终端里读不到图」那条
  代价**不依赖**它。
- **开发 / 构建 / 安装 / 配置的生命周期**：范围是**运行时**。
- **重画或删除已有那五处 ASCII 图**：它们各有各的读者，新图引用它们、不取代。
- **从代码自动生成图**：本图是手写 + 证据表 + 弱校验，不做 codegen。
- **mermaid 之外的图语言**（graphviz / d2 / ASCII 版）：已选 mermaid。
- **接 CI**：仓库本来就没有 CI（也没有 Makefile），护栏照 `README.md` 的「开发」一节手工调用。
- **剥离代码块再算中文占比**：`check_docs()` 现在算整份文件原文；「先剥离再算」是**另开一票**的
  事，本 spec 只按现行为新文档设一条下限。
- **语义正确性**：图是否如实描述运行时，工具测不了 —— 那是人读图的事，docstring 里要写明。
