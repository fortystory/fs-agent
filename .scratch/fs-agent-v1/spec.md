## Problem Statement

我想要一个**自己的 coding agent CLI**：在终端里对着一个真实仓库干活——读代码、改文件、跑命令——但我不想要一个「一次一个 agent 闷头干」的黑盒。

具体难受的地方：

1. **单一模型的判断没有对照。** 同一个模型对同一个开放问题往往给一个答案，我看不到「换个模型会怎么说」。我想让两个**异构**模型（KIMI + DeepSeek）就同一个问题各自作答、只在结论真的冲突时才互相回应，最后把「哪些是共识、哪些是分歧、哪些未决」摆给我——**决定权在我，不在一个自动收敛的投票器**。
2. **探索和动手是两种活，我想要两种角色。** 讨论需要发散（保住多样性），而改代码需要收敛执行。一个模型一边讨论一边改文件，等于把两个目的挤进一次调用。
3. **上下文预算是硬的，而现在多数工具假装它不是。** 上下文窗口、轮数、token 花销和计费缓存是四个不同的量，混成一个「预算」以后，超限时的行为就变成了随机截断。
4. **权限、秘密、可撤销这三件事，自用场景反而更危险。** agent 自己的 API key 就在本机配置文件里；它能在我的仓库里真的写文件、跑命令。我需要「默认安全、放行有据、每次编辑能原样退回去」，而不是一个 `--yolo` 开关。
5. **我要能复盘。** 多 agent 讨论会产生一份读不动的 transcript。我想事后能问它：这一轮为什么停？是谁在哪一轮改了这个文件？这次编辑走了降级匹配吗？
6. **我不想被框架绑死。** 将来要加第三个讨论者、要加一个裁判、要加一个动态工具时，我希望加的是**配置或一个变体**，不是重构半张架构图。

## Solution

一个 Rust 从零实现的**单 crate CLI**（`fs-agent`），核心是一个**共享只追加事件流**加**每个 agent 自己的窗口**：

- **一次会话 = 一个事件流 + 一组投影。** 事件流是唯一真相源；每个讨论者 / 执行者这次调用要重放的 `messages`，都是从事件流 + 投影规则**重算**出来的纯函数产物。没有隐藏状态、没有「agent 的记忆」这种东西。
- **讨论是轮次化的**：两个异构讨论者**独立首轮**（互不可见，保住多样性）→ 揭示各自的**一行结论** → **只在结论冲突时**开一轮定向第二轮 → 合成器画出**选项空间**（共识 / 分歧（含各自成立的前提）/ 未决）。一次讨论 = 3 次或 5 次调用。
- **执行者是嵌套会话**：讨论者通过内建的 `task` 工具派出一个带 `parent_id` 与独立轮数预算的子 agent 去真实干活；它的事件落在**同一个流**里，但默认**不进任何讨论者的窗口**——只有它回传的摘要经派发者自己的发言进入讨论。
- **控制流在循环里，策略是纯函数**：每个工具调用走 `hook.pre → 权限门 → [询问] → dispatch → hook.post → 追加事件`，hook 输出的是**约束**、门输出的是**裁决**，两者在 `Allow < Ask < Deny` 上取上确界。类型里根本没有「放松权限」这个变体。
- **12 个顶层边界、只向下依赖**，`Session` 是唯一持有可变状态的值；投影住在 provider 适配器侧、按模型能力分叉。
- **默认安全**：`readonly` / `ask` / `auto` / `plan` 四个内置模式、断路器短路 deny、`.env` 家族默认拒、cwd 路径限制、秘密在入流前打码、会话目录 `0700`、root 拒绝启动。
- **三个前端**（plain / TUI / headless）共用一个渲染接缝与一条广播通道，headless 的 stdout 只有最终产物。

## User Stories

### A. 会话与启动

1. 作为用户，我想在任意工作目录直接启动 `fs-agent` 开始一次会话，以便不必先做配置就能问它问题。
2. 作为用户，我想让会话与当前工作目录绑定，以便 A 项目的会话不会把 B 项目的上下文搅进来。
3. 作为用户，我想用 `--continue` 恢复本目录最近一次会话，以便昨天问到一半的问题能接着问。
4. 作为用户，我想让恢复后的会话 id 保持不变，以便两家 provider 的前缀缓存继续命中、不为同一段历史重复付费。
5. 作为用户，我想在恢复时撞上「中断在工具调用中途」的会话得到一个明确结果（一条「结果未知」的失败结果），以便不重复执行一个有副作用的命令。
6. 作为用户，我想让一次会话的产物（事件流 + 工具输出落盘）是一个可搬运的目录，以便我把它整个拷到另一台机器继续。
7. 作为用户，我想让会话目录默认只对我可读（目录 `0700` / 文件 `0600`），以便同机其他用户读不到我的代码与讨论。
8. 作为用户，我想在没有交互能力时（headless / 管道）让需要询问的权限自动降级为拒绝，以便脚本不会挂住等我。
9. 作为用户，我想在 root 或 sudo 下让 `fs-agent` 拒绝启动，以便一次误判不至于变成系统级事故。
10. 作为用户，我想让会话历史不自动清理、但提供一个手动 `prune`，以便磁盘不会悄悄涨满、也不会在我没同意时删掉历史。
11. 作为用户，我想让「单 agent 默认 100 回合」这类上限可配，以便长任务不被默认值半路掐死。
12. 作为用户，我想在启动时看到本次实际使用的模型、模式与预算，以便我知道自己站在哪一档策略上。

### B. 配置

13. 作为用户，我想在 `~/.config/fs-agent/config.toml` 里配 provider 的 `base_url` 与 key，以便密钥不进项目仓库。
14. 作为用户，我想让 `[providers.*]` 与 `[models.*]` 分成引用 + 覆盖两级，以便多个模型共用一份 provider 配置又不互相污染。
15. 作为用户，我想让配置优先级是 `config.toml` > 已导出环境变量 > 内置默认，以便临时覆盖不用改文件。
16. 作为用户，我想让项目里的 `.env` **不被**自动加载，以便我 clone 下来的仓库改不了我的行为。
17. 作为用户，我想在配置里声明动态工具（一条命令 + 参数 schema），以便不必为每个内部小工具写 Rust。
18. 作为用户，我想让动态工具的参数按整个 argv 元素替换、不经 shell，以便模型拼不出命令注入。
19. 作为用户，我想让未登记的模型在启动时报错而不是静默降级，以便能力表失配是响的。
20. 作为用户，我想让「我显式传了但被适配器丢弃」的参数产生告警，以便能力差异不静默。

### C. 讨论

21. 作为用户，我想让两个异构讨论者（KIMI + DeepSeek）在同一会话里就我的问题各自作答，以便看到两个独立判断。
22. 作为用户，我想让首轮的两个讨论者互相不可见，以便多样性不被从众抹掉。
23. 作为用户，我想让每个讨论者在正文末尾另起一行给一行结论，以便「是否冲突」可机械判定、不花额外调用。
24. 作为用户，我想让「归一化后相等或互为子串」即判为一致，以便判定无假阴性、假阳性被 2 轮上限兜住。
25. 作为用户，我想让第二轮只在结论冲突时开，以便调用数接近最小、并回避无差别多轮共享带来的从众。
26. 作为用户，我想让第二轮明确告知「你看到了对方的回答、请针对分歧回应」，以便它回应分歧而不是重复首轮。
27. 作为用户，我想让讨论最多两轮且轮数可配，以便成本可预期。
28. 作为用户，我想让分歧被显式记录（含双方各自那行结论），以便我直接看到分叉点。
29. 作为用户，我想让收尾由合成器产出「共识 / 分歧（含各自成立的前提）/ 未决」三档，以便它画出选项空间而不是替我收敛。
30. 作为用户，我想让合成器不收敛成一个「新答案」，以便讨论服务于探索而不是投票。
31. 作为用户，我想让合成器看到发言全文、看不到对方的私有推理，以便它不替谁改写论点。
32. 作为用户，我想在一个讨论者这次调用失败时让该方本轮缺席、讨论继续，以便单点故障不废掉整次讨论。
33. 作为用户，我想让「缺席」能从事件流上查出来，以便合成器不会把「只有一份回答」读成共识。
34. 作为用户，我想在两个讨论者都失败时让讨论以错误收尾，以便我不必从半截输出里猜。
35. 作为用户，我想让同一轮的两个讨论者并发发出去，以便异构的两家 provider 各自承担并发预算、墙钟时间更短。
36. 作为用户，我想让讨论协议指令住在每个讨论者的私有身份里、不进事件流，以便「第二轮的 messages 能从流重算」这条不变量成立。
37. 作为用户，我想让讨论终止原因落在统一的终止枚举上（无分歧 / 收敛 / 轮数用尽 / 预算撞顶），以便一眼看懂「为什么停」。
38. 作为用户，我想让「第三轮」不是新机制（轮次模式已有槽位），以便将来放开轮数不用改 schema。
39. 作为用户，我想让轮次边界在界面上有分节线，以便读长讨论时不迷路。
40. 作为用户，我想让分歧块缩进显示，以便分叉点视觉上跳出来。
41. 作为用户，我想让讨论者绝不被换成弱模型（合成器与执行者可以），以便多样性这个最强杠杆不被动。
42. 作为未来维护者，我想让「再加一个讨论者」是**又一个 `Debater(AgentId)`**（零 schema 改动），以便扩展只动配置与成本式。

### D. 执行者

43. 作为讨论者，我想用一个内建的 `task` 工具派出执行者去真实干活，以便讨论与执行分开。
44. 作为用户，我想让执行者带自己的 `parent_id` 与独立轮数预算（默认 25），以便它的失控不吃掉讨论的轮数。
45. 作为用户，我想让执行者的 token 计入会话累计，以便「独立预算」不等于「看不见的花钱」。
46. 作为用户，我想让执行者默认继承派出它的那个讨论者的模型，以便默认行为合理。
47. 作为用户，我想能按角色覆盖执行者的模型与工具集，以便便宜任务走便宜模型。
48. 作为用户，我想让执行者继承**拒绝**、不继承**允许**，以便「派个子 agent 去写」绕不过 plan 模式或我的拒绝规则。
49. 作为用户，我想让委派只向下、递归深度为 1，且第一道防线是执行者的工具集里**没有** `task`，以便递归失控在结构上不可能。
50. 作为用户，我想让 read set 既不继承也不跨 agent 流动，以便「读过」不被当成「可以改」的许可。
51. 作为用户，我想让执行者回传「摘要 + 元数据（token、改动的文件）」，以便我拿到结论而不是全过程。
52. 作为用户，我想让执行者的过程事件默认不进任何讨论者的窗口、结论经派发者自己的发言进入讨论，以便不制造信息不对称。
53. 作为用户，我想让同一批里的多个 `task` 并发跑（默认上限 5），以便并行加速，同时真正的写互斥由共享路径锁保证。
54. 作为用户，我想让执行者的失败（错误 / 轮数用尽 / 被取消 / 连续错误超限）表现为一条错误内容的工具结果，以便讨论不因此中断。
55. 作为用户，我想让 `/undo` 对执行者造成的编辑同样有效，以便「谁改的」不影响可撤销性。

### E. 工具

56. 作为用户，我想让内建工具集足够干完核心闭环：读、写、编辑、跑命令、加载 skill、取符号地图、派执行者。
57. 作为工具作者，我想让 `Tool` 是一个对象安全的 `async-trait`（`spec()` / `effect()` / `call()`），以便注册表里放 `Box<dyn Tool>` 并支持运行期注册。
58. 作为用户，我想让每个工具声明自己的副作用类别（只读 / 写若干路径 / 独占），以便调度与权限基于同一个语义。
59. 作为用户，我想让 v1 的调度器即使串行执行也**已经**按副作用分流，以便并行只读是接线而不是重构。
60. 作为用户，我想让「改文件前必须先读过它」在工具层集中强制，以便护栏不依赖模型自觉。
61. 作为用户，我想让同一路径的写入互斥（且跨执行者有效），以便并行执行者不互相覆盖。
62. 作为工具作者，我想让编辑走一个有序的匹配梯（精确 → 行尾空白无关 → 每行 trim），以便模型的小格式偏差不让编辑失败。
63. 作为用户，我想让编辑命中的降级级别显式报出，以便降级不静默。
64. 作为用户，我想让编辑拒绝三类危险操作（非唯一匹配、匹配区间过大、占位符），以便「顺手改错一片」不常见。
65. 作为用户，我想让占位符判据是「注释形状的短语」而不是裸 `...`，以便不误伤 Rust 的 `..` / `..=`。
66. 作为用户，我想让编辑匹配全线失败时失效该路径的 read set，以便我被迫重读而不是凭记忆重试。
67. 作为用户，我想让动态工具的副作用恒为「独占」，以便「谎报只读」没有地方可说。
68. 作为用户，我想让动态工具有超时与进程树终止，以便它不会挂住我的会话。
69. 作为用户，我想让动态工具的命名空间是 `custom__<ns>__<tool>`（内建名永不含 `__`），以便「是不是自定义」词法可判。
70. 作为用户，我想让动态工具在启动时全局可见、组装期固定，以便工具表不中途变化、前缀缓存不被废掉。

### F. 权限与安全

71. 作为用户，我想让权限规则是 `subject + Scope + action + propagate`，以便一条规则能表达「谁、对什么、怎么样、是否传给子 agent」。
72. 作为用户，我想让作用域支持工具名通配 / 命令前缀 / 路径模式 / 精确路径集 / 全部，以便既能粗放也能精确。
73. 作为用户，我想让优先级是 `deny > ask > allow` 且忽略具体程度，以便规则、hook 收紧、执行者继承共用同一个代数。
74. 作为用户，我想让评估次序是「断路器 → 规则取上确界 → hook 收紧 → 无交互时降级为拒」，以便任何时候都有确定答案。
75. 作为用户，我想让断路器短路拒绝（敏感路径写入永不自动批准；`rm` 打到 `/`、`~` 及其父目录一律拒且任何 allow 与 hook 都翻不过来），以便最坏情况有硬底。
76. 作为用户，我想让「总是允许」只改会话内策略、不写我的 `config.toml`、也不进事件流，以便我的配置不被 agent 悄悄改。
77. 作为用户，我想让 `.env` 家族默认拒绝（示例 / 样例 / 模板除外），以便密钥文件默认不落进上下文。
78. 作为用户，我想让四个内置模式各有明确语义（只读 / 询问 / 自动 / plan），以便「模式」不是含糊的档位名。
79. 作为用户，我想让 `auto` 不等于「跳过权限」（断路器、规则、hook 照常生效），以便自动模式仍有底。
80. 作为用户，我想让任何模式的拒绝都沿委派链继承，以便 plan 模式的拒绝不能靠「派执行者去写」绕过。
81. 作为用户，我想让模式的进出只用手势，且不暴露成工具，以便「能不能写」不交回给模型。
82. 作为用户，我想让 plan 模式的计划落在项目根 `PLAN.md`，且它是该模式下唯一的写豁免，以便计划能被我和 agent 一起编辑。
83. 作为用户，我想让 `PLAN.md` 的豁免形状是「写入集的**全部**路径都是它」，以便不能借道别的文件。
84. 作为用户，我想在进入 plan 模式撞上已存在的 `PLAN.md` 时被问「覆盖 / 追加 / 保留」，以便 agent 不擅自删我的文件。
85. 作为用户，我想让被拒绝的工具**不从工具表里移除**，以便前缀缓存不被废掉。
86. 作为用户，我想让模型给的路径被限制在会话 cwd 及其子树（例外走权限规则），以便 agent 不会顺手读遍我的家目录。
87. 作为用户，我想让秘密在入流前被值级打码，以便流上的文本 == 模型看到的文本，而工具执行仍用真值。
88. 作为用户，我想让打码也覆盖消息正文，以便「他在发言里复述了密钥」这条跨 agent 通道也被堵上。
89. 作为用户，我想让 v1 不做进程级沙箱、但把升级路径写成「只做 Linux 的 bubblewrap」且不预做抽象，以便诚实而不是看起来安全。

### G. 上下文与成本

90. 作为用户，我想让「可用输入」按每个 agent 自己的模型计算，以便不同模型的窗口各管各的。
91. 作为用户，我想让「投影」与「裁剪」是两个各自纯净的步骤，以便「可重算」这条不变量成立。
92. 作为用户，我想让单次工具结果超限时在入流前截断（超限部分落盘 + 事件里只放预览与指针），以便事件流不爆炸、模型仍能按需读全文。

## Implementation Decisions

### 1. Crate 与模块布局

- **单 crate**：一个薄的二进制入口 + 一个公开的库入口。库入口是**组装点**，provider、路径锁、渲染 sink、配置都从参数注入，**不在库里读环境**——这是 e2e 用假 provider 的唯一入口（见 `Testing Decisions`）。
- **12 个顶层边界**，依赖**只沿 DAG 向下**，不允许环：

  `events` · `config` · `provider` · `tools` · `permissions` · `hooks` · `context` · `agent` · `discussion` · `session` · `render` · `cli`

  关键约束：`events` **零内部依赖**（大家都依赖它，它不依赖任何人）；`project()` 是 `provider` 的子模块（**不是**新边界）；`discussion` **不碰 provider**（它只驱动 `agent` 的循环）；`agent` 层是唯一写事件流的地方——循环与它驱动的执行者端口走**同一个** `append_event` 写入路径（票 11）。
- **`Session` 是唯一持有可变状态的值**（事件流句柄 + 名册 + 预算 + 策略 + 配置 + read set）。执行者 = **带 `parent_id` 的嵌套 `Session`**，有独立轮数预算，事件**追加到父流**。
- **架构深度到此为止**：本 spec 定到边界与关键 trait 签名，**不定**文件名、公开函数逐个签名与函数职责。
- 根目录 `CONTEXT.md` 是正式词汇表；代码标识符用其中的英文名。

### 2. 事件流与事件 schema

- **粒度 = 完成单元**（一条消息 / 一次工具调用 / 一条结果 / 一次裁决 / 一个轮次边界）。**增量文本不进事件流**：它走传输层旁路直达渲染；只有完成单元落进流。
- **信封 = `{ seq, at, speaker_id, payload }`**：
  - `seq` 是**唯一身份**（= JSONL 行号，不引入 ULID 之类的第二身份）；
  - **不带 `parent`**（线性日志；分支 = 新会话复制前缀）；
  - **不带任何可见性字段**——可见性是投影规则的输出，写进事件就等于让事件携带协议状态、破坏 `project()` 的纯函数性；
  - `speaker_id` **必填**，域 = `Debater(id) | Executor(id) | User | System`；归属**绝不**从 provider 的 `role` 反推。
- **一条总线 + 一个 payload 枚举**，消费者靠**过滤**取用（不按可见性分区）：

  ```rust
  EventPayload =
    // 会话骨架
    SessionStarted    { session_id, cwd, schema_version }
    ContextInjected   { source: AgentsMd | SkillsCatalog | PlanMode, content }
    SessionEnded      { reason: StopReason }
    // 讨论协议（何时发由讨论协议定，这里是槽位）
    RoundStarted      { round, mode: Independent | Targeted | Synthesis }
    RoundEnded        { round, reason: StopReason }
    DivergenceRecorded{ round, topic, positions }
    // 单个 agent 的一次 Turn
    TurnStarted       { agent, iteration }
    MessageCompleted  { role, text, reasoning? }
    ToolCallStarted   { tool_call_id, tool_name, args }
    ToolCallCompleted { tool_call_id, ok, output | error, duration_ms }
    UsageRecorded     { usage }
    TurnEnded         { reason: StopReason }
    // 权限
    PermissionAsked   { request_id, tool_call_id, request }
    PermissionDecided { request_id, decision, source: User | Hook | Policy, reason? }
    // hook
    HookExecuted      { point, command, outcome }
    // 子 agent
    ExecutorSpawned   { executor_id, parent, brief }
    ExecutorFinished  { executor_id, reason: StopReason, summary }
    // 错误（两种，因为可见性不同）
    AgentError        { message, recoverable }   // 模型要看到并纠正
    SessionError      { code, detail }           // 会话级运行失败，模型看不到
    // 历史操作
    HistorySuperseded { targets: [Seq], reason: Regenerate | Undo | Compaction, summary? }
  ```

  四处已收口的细节：**合成器的产出 = 一条 `speaker_id = System` 的 `MessageCompleted`**（枚举里没有它的家，`System` 正是「harness 自己产生的事件」那一档；渲染侧当最终产物，投影侧就是一条「他人的发言」）；`ContextInjected.source` 含 `PlanMode`；**讨论里「某方本轮缺席」不新增字段**——查询口径是「这一轮里有 `TurnEnded{Error}` 且没有对应的 `MessageCompleted`」；字段名是 **`PermissionDecided.reason`**，不是 `.why`。
- **hook 只拿到一个封闭的公开子集**（工具 + 权限 + 会话边界，共 7 个变体）——hook 是「只能收紧」的**策略**机制，观察面与策略面分开。
- **只追加、永不修改、永不截断。** 重新生成 / 撤销 / compaction 一律是**追加一条 `HistorySuperseded { targets, reason, summary? }`**，由投影规则把被替代区间排除。所以「让某区间不生效」= 规则 + 一条新事件，历史一条不动。
- **`StopReason` 一个枚举被三层循环共用**（挂在 `TurnEnded` / `RoundEnded` / `SessionEnded` / `ExecutorFinished` 上），共 9 个值：

  `Completed` · `MaxIterations` · `Aborted` · `MistakeLimit` · `Error`（单次循环五类）  
  `Consensus` · `NoDivergence` · `RoundsExhausted`（讨论三类）  
  `BudgetExhausted`（预算撞顶，第 9 个值）

  嵌套循环（执行者的回合循环在讨论的轮次循环里）**各自留下自己的原因**，诊断力不丢。
- **持久化**：一会话一 JSONL，**单一写入者**（绕开 `std` 的 append 不保证跨线程不交错）+ 每条 flush 但**不 fsync** + 容忍末行不完整 + schema 版本写在 `SessionStarted` 里且**不承诺向后兼容**。

### 3. 回合循环与控制流次序（含 hook 与权限门）

- **控制流归 `agent` 层的循环**：hook 与权限门都只是它按次序调用的**纯值变换**，次序固定为

  `hook.pre → 权限门 → [询问] → dispatch → hook.post → 循环追加事件`

- **`hook.pre` 的输出是「约束」**：`Continue | Rewrite(args) | Tighten(Ask|Deny) | Skip | Stop`。**类型里根本没有「放松」这个变体**，所以「hook 只能收紧、不能放松」是代数性质而非运行期检查。
- **权限门产出裁决**（封闭三态 `Allow | Ask | Deny` + 诊断字段）；**生效裁决 = 约束与裁决在决策格 `Allow < Ask < Deny` 上取上确界**。打开的是**门的输入侧**（模式 / 断路器 / 路径限制 / 规则表达式 / 委派链继承），不是输出侧。
- **`hook.pre` 在询问之前**：它能**阻止**询问发生（收紧到 deny），永远不能**绕过**询问；v1 **不设** `PermissionRequest` 这个挂载点（门本身就是询问的入口）。
- **失败语义不对称**：`hook.pre` 失败/超时 → **fail-closed**（阻止动作 + 诊断 + 合成一条错误结果）；`hook.post` 失败 → **只能丢反馈**（世界已经变了，post 侧买不到安全）。
- **PostToolUse 回灌 = 一条追加的 `HookExecuted` 事件**，由**投影合并**进那条工具消息（provider 只允许一个 `tool_call` 对一条 tool 消息，所以合并是被迫的）；可见性跟着它所评注的那条工具结果走。
- **「每个 `tool_call` 恰好一条结果」由循环在**一处**保证**：正常路径由 dispatch 产出；四条异常路径（权限拒绝 / 用户拒绝 / hook 跳过 / `hook.pre` 失败）各合成一条错误结果，**权限拒绝的产物由循环合成**（门是纯函数、工具没被调用）。取消是**第 5 条**异常路径（见 §6）。
- **Turn 自己算续不续**：最后一条 assistant 消息含 ≥1 个 `tool_call` 才继续；「还有没有未出结果的 tool_call」是**对事件流的查询**，不是隐藏状态。provider 的 `finish_reason` **只作诊断**，结束只认 `[DONE]`。
- **默认上限 100 回合**（可配）；撞上轮数上限时 `TurnEnded { reason: MaxIterations }`，理由里带上撞的是哪个上限。

### 4. Provider 适配器、多模型与能力表

- `Provider` 是 **`async-trait` + `Box<dyn Provider>`**（`async fn` in trait 不 dyn-compatible）。**dyn 的存在理由是「能注入 mock」**，不是「支持很多 provider」——KIMI 与 DeepSeek 是**同一个 client 的两个 profile**。
- trait **只流式**，输入是**已经投影好的** `ChatRequest`；输出的完成单元 = `TextDelta` / `ReasoningDelta` / `ToolCall{Started,Completed}` / `Usage` / `Finished`。
- **adapter 是执行点**：`tool_call` 分片拼接（含给 `index` 留位——Kimi 的 OpenAPI 漏声明但它 guide 依赖）、两家 usage 形状归一（Kimi 单独发 `choices: []` 统计 chunk；DeepSeek 搭在最后一个 content chunk）、**用户显式传了但被能力表判定不支持而丢弃时告警**（能力差异不静默）。
- **`reasoning_content` 必须建模并回放**：DeepSeek 带 tools 时不回传自己的 `reasoning_content` 直接 **400**。
- **能力表按 `model id` 建、只建模两家**、`#[non_exhaustive]`；**未登记即报错**（不静默降级）。
- **配置两级**：`[providers.*]`（`base_url` + key）→ `[models.*]`（引用某个 provider + 覆盖）。`base_url` 必须与 key 来源同域（Kimi 跨域混用返回 401，结构上堵死）。**Kimi 是两套互不通用的系统**：Open Platform（`platform.kimi.com`，`https://api.moonshot.cn/v1`，key env `MOONSHOT_API_KEY`）与 Kimi Code / coding plan（`https://api.kimi.com/coding/v1`，`sk-kimi-` 会员 key，key env `KIMI_API_KEY`）——key 与 base_url 不可互换，所以内置**两个 profile**（`kimi` / `kimi-code`），同域判定按 **key 来源**而不是 section 名。
- **`ProviderError` 六分类**，其中 **`QuotaExhausted` 与 `RateLimited` 必须分开**。**同一个状态码在不同家含义不同**：DeepSeek 欠费 **402**、限速 **429**；Kimi Open Platform 欠费与限速都走 **429**（靠 body 区分）；**Kimi Code 的额度窗口（5 小时 / 每周 / 每月）是 403、档位不足或鉴权失败是 401、瞬时限速才是 429** ⇒ **403 与 429 都必须按 body 细分**，不能只按状态码分类。**传输级有界重试归 adapter**，上层不重跑。
- `prompt_cache_key` = **会话 id**；不发 `user_id`。
- **两条破坏前缀缓存的操作写死**：Kimi 的 `reasoning_effort` **必须在会话开始前定死**（中途切档废掉整个前缀缓存）；投影必须**保序**。

### 5. 发言归属与投影（`project()`）

- **一份实现、住在 provider 适配器侧、按能力表分叉**（逐字段差异是**数据**不是代码分支）；纯函数，**不带任何裁剪状态**。
- **「哪些事件进模型上下文」是一张穷尽 match 表**（不放 payload 上，DAG 才不斜）。
- **他人的回合投三档**：文本**保留**；工具调用**只留一行摘要**；结果正文与 `reasoning_content`**都不投**。
  - 先决约束：他人一律投成 `user`，所以他的 `tool_calls` 不能以 `assistant` 出现，**配对的 `tool` 结果必须一起改写或丢弃**，否则线级配对校验会炸。
- **我自己的 `reasoning_content` 必须回放**（见 §4）；**我自己的工具往返 + PostToolUse 反馈按 `seq` 合并成一条 `tool` 消息**（provider 只允许一对一）。
- **合并规则**：按 role 序列合并、**轮次是硬边界**、**无条数阈值**、严格按 `seq`；**两条钉住的注入**（首条 `user` 消息、`ContextInjected`）**不参与合并**。
- **前缀 `[轮 N · 名字] …` 只加在他人发言上**（给自己加会污染回放）。这是**模型侧**的前缀，与渲染侧的前缀是**两套、不共用生成器**。
- **`name` 发但只发在 `user` / `assistant` 上**，值消毒到 `[A-Za-z0-9_-]` 且短，**绝不依赖它**（三家的 schema 都只写 `type: string` + 一句「optional name」，无 pattern / maxLength；**DeepSeek 的 tool 消息根本没有 `name` 字段**，所以 tool 消息不发）。
- **执行者的事件不进讨论者投影（`ExecutorFinished` 也不进）**，而**执行者自己的投影是全量的**——它自己的工具往返照投、不压缩。**可见性规则**双向不同；**窗口**那一半见 §16 的票 11 折回（执行者的窗 = 钉住的注入 + 它自己的事件，brief 由 `ExecutorSpawned` 投影而来，且它**不是**钉住 head 的一部分）。
- **plan 模式的注入与钉住的首条 `user` 同档：永不参与裁剪**（幂等注入消重复）。

### 6. 取消传播（spec 期新增的一条决定）

地图没有覆盖这一条，本 spec 定下最小语义——**只补语义，不动 schema**：

- **手势本身不进事件流**（与 `/undo` 的写回、`/plan` 的「覆盖」清空同规矩：流只记录 agent 的动作）。
- **一次取消手势（Esc）**：中断在飞的 provider 流与在跑的工具，当前 Turn 以**既有的** `TurnEnded { reason: Aborted }` 收尾。
- **在飞的 `tool_call`** 由循环合成一条错误结果（`ok: false`，说明被取消）——这是 §3 那四条异常路径之外的**第 5 条**，为的还是「每个 `tool_call` 恰好一条结果」。
- **取消只向下传播，不向父传播**：取消讨论时，正在跑的执行者收到取消，各自以 `ExecutorFinished { reason: Aborted }`（**票 14 的枚举里已有这个值**）结束并回一条错误内容的工具结果；执行者被取消**不会**让讨论以错误收尾——讨论照常处理这条工具结果。
- **在取消过程中再按一次** = 强退进程；会话仍然可恢复（`--continue` 对悬空 `tool_call` 的合成失败结果就是为这种中断准备的）。

### 7. 工具 trait、注册表与副作用

- `Tool` = **`async-trait` + `Box<dyn Tool>`**，签名三件套：
  - `spec()` → 线级工具声明（JSON Schema 原样就是 provider 的形状，零翻译）；
  - `effect(args)` → `ReadOnly | WritePaths(…) | Exclusive`（**「工作区副作用」这个语义**，不是「有没有副作用」——所以 `task` 判为**不碰工作区**）；
  - `call(ctx, serde_json::Value)` → `Result<ToolOutput, ToolError>`（args 类型擦除，为动态工具留门）。
- **内建集合是函数、注册表是运行期值**（无全局 static，随 `Session` 走）；`register` 就是动态工具的挂载点。
- **v1 的 dispatch 串行，但调度器此刻就按 `effect` 分流**——模型一定会批量发 tool call，所以「并行只读」是接线而不是重构。
- **`read-before-edit` 与 per-path 写互斥都在工具层 dispatch 集中强制**：read set 归 `Session`，**锁表是组装期注入的 `PathLocks`**（必须跨执行者共享；每会话一份等于没锁）。
- **内建工具集**（v1 全部）：读文件 / 写文件 / 编辑文件 / `bash` / `skill(name)` / `repo_map(focus?)` / `task`。

### 8. 编辑策略与降级匹配

- 线级契约：`edit_file(file_path 绝对路径, old_string, new_string, replace_all?)` 与 `write_file`。
- **匹配梯 = `tools` 内部的一个有序 `Matcher` 列表**（first-success-wins，**不是新顶层边界**）。v1 三层：**精确 → 行尾空白无关 → 每行 trim**。
- **命中级别必须报出**（进工具结果的约定文本），否则降级是静默的。
- **三样护栏都进 v1**：唯一性强制；匹配区间过大时拒绝；占位符拒绝——判据是**注释形状的短语**，不是裸 `...`（免伤 Rust 的 `..` / `..=`）。
- 编辑格式 v1 **固定 search-replace**，**不加** `edit_format` 之类的预留字段；换格式的挂点用既有的「注册表在组装期按 profile 构造」。
- **匹配全线失败 ⇒ 失效该路径的 read set**（读→写间隙无锁，这是不加内容哈希也拿到的同等安全性）。

### 9. skills 与 repo map（上下文的两类可插拔内容）

- **skills 是 `context` 的子模块**。**全文加载靠一个内建只读工具 `skill(name)`**——产物是流上的一条工具结果（单一收口：可记账、可计量、可被权限语言覆盖）；**追加在尾部所以不破坏前缀缓存**。
- `disable-model-invocation` 的 skill **既不进清单也拒绝加载**。
- **发现路径 = 项目 + 用户两级、各三处**：`.fs-agent` > `.agents` > `.claude`，项目 > 用户（本机这两套库已真实存在且 38 个同名，不跟随就全部作废）。
- **边界规则**：>80% 每轮都要 → 写进 `AGENTS.md`；按任务 / 长 → skill；必须无条件执行 → hook。
- **预算**：单 skill 5k / 已加载总 25k / 描述清单独立封顶 3k。
- **v1 的 skills 只装指令**，「把工具打包进 skill」不做（那会和「工具表组装期固定」冲突）。
- **`repo_map(focus?)` 与 `skill(name)` 同形**：内建只读工具、产物是工具结果、`effect()` = `ReadOnly`、落进同一套截断与丢弃——**不注入**（注入版「脏了就刷新」会让 map 之后的整段历史反复掉出缓存前缀）。
- **固定预算 1k、可配上限 4k、不接受模型传 `tokens`**。
- 抽取 = **tree-sitter + 官方 `tags.scm`**（**只有名字**，v1 不做签名渲染；增量解析后置）；排序 = **朴素可解释的纯函数**（会话相关度为主 + 结构信号为辅），**不做整图 PageRank**；`rank()` 留作可替换的纯函数接缝。

### 10. 上下文预算、截断与丢弃

- **可用输入**：`usable_input(agent) = caps.context_window − min(20_000, caps.max_output_tokens)`，**住在 `context`、按 agent 各自模型算、没有「全局预算」**。
- **`messages(agent) = trim(project(log, speaker, caps), budget, policy)`**：投影只做归属，**裁剪是投影之后的另一个纯函数**。
- **两个机制、不同时刻、不同数据**：
  - **单次结果截断在入流前**（超限部分落盘 + 事件里只放预览与指针）；
  - **超预算丢弃在 `trim` 里且只读**（日志一条不删）。
- **丢弃顺序**：`老普通工具结果 → 老 skill body → 老整轮 → 该回合硬失败`。**钉住的注入永不参与裁剪、也不在这个序列里**。
- **`AGENTS.md` + skill 清单合并注入为第一条 `user` 消息**（`System` 身份 → `User` 规则 + 清单 → 历史）：两者**各记成流上一条 `ContextInjected` 事件**（各带自己的 `source`，`project` 把**开头连续的**注入合并成这一条消息，所以线级不会出现连续两条同角色消息），**逐轮不变以保前缀缓存、永不被裁剪**（否则 `project` 不再是「流 + 规则」的函数）。
- **v1 = 字符/4 估 token + 粗暴丢弃**；compaction **后置且不返工**（前提已经满足：`trim` 是独立纯函数 + 摘要记成 `HistorySuperseded { reason: Compaction, summary }`）。
- **「当前预算」不是状态是函数** ⇒ 窗口层无需加锁；**会话累计是从 `UsageRecorded` 求和的派生值**。

### 11. 会话存储、拓扑与 `--continue`

- 数据落 `~/.local/share/fs-agent/sessions/<cwd-slug>/<session-id>/`，内含事件流（JSONL）与 `outputs/`（工具输出落盘）——**会话是一个目录、一个可搬运单元**。
- **会话与 cwd 绑定**（slug 只用于分桶，权威 `cwd` 在 `SessionStarted` 里）；`--continue` **只扫本目录桶、取 mtime 最新、不维护全局索引**。
- **会话 id = `<UTC 时间戳>-<短随机后缀>`，`--continue` 之后绝不改变**（§4 的 `prompt_cache_key` 靠它保住前缀缓存）。
- **拓扑 = 执行者的事件在同一个流里**（`ExecutorSpawned{executor_id, parent}` + `SpeakerId::Executor`）；「嵌套 Session」是**内存里的值结构**，不是文件布局；**存储层不做可见性裁剪**。
- **恢复撞上悬空 `tool_call`** → **补一条合成的失败结果**（`ok:false`，错误信息说明「会话中断于此，结果未知」；**不丢弃、不重执行**），**不追加第二个 `SessionStarted`**。
- **不变量精确措辞**：`流 + 落盘文件 + 投影规则 → messages`，且**投影不读落盘文件**（保持纯函数）；指针失效**降级为预览、绝不失败**，模型要全文就自己读文件（不需要新工具）。
- **`/undo` 不碰用户的 git**：编辑工具把**实际被替换区段的旧内容**（不是 `old_string`——降级梯会命中不同文本）落到 `outputs/<tool_call_id>.before`；`/undo` 按命名约定找回那次 `edit_file` 调用并写回。**不做「每次编辑自动 git commit」**（会裹走用户未提交的改动、且在非 git 目录失效）。`/undo` 必须取与编辑**同一把 per-path 锁**。
- 明确不做：fork / rewind 手势、shadow git、快照系统、完整 event-sourcing 框架、SQLite、全局索引、自动清理（只给手动 `prune`）。
- **会话目录创建即 `0700` / 文件 `0600`**（`umask 022` 下默认会是 0644 = 同机可读）。

### 12. 权限表达、模式与沿委派链的继承

- **规则 = `subject` + `Scope` + `action` + `propagate`**；`Scope` = `Tool(glob)` / `CommandPrefix(argv)` / `Path(pattern)` / **`PathSet(exact)`** / `All`。
- **作用域是「对这次调用的谓词」**：这样 plan 模式的 `PLAN.md` 豁免才成立——它是 deny 条件里的一个**与项**（「非 `ReadOnly` **且** 写入集 ≠ `{PLAN.md}`」），而不是一条会被宽 deny 压过的窄 allow。
- **优先级 = `deny > ask > allow` 且忽略具体程度**（让规则优先级、hook 收紧、执行者继承**共用同一个代数**，只有一套合并语义；「具体程度」无法定义）。
- **评估次序**：**断路器（短路 `Deny`，早于一切）→ 规则取上确界 → hook 收紧 → 无交互时 `Ask→Deny`**。
- **`propagate` 按动作定默认值**（`Deny` / `Ask` 为真、`Allow` 为假）⇒ 执行者策略 = 父级传播下来的 ∪ 自己的 ⇒「继承拒绝、不继承允许」是**默认值不是特例**，plan 模式的硬要求自动满足。
- **断路器进 v1，且是「短路」不是「规则」**：敏感路径写入**永不自动批准**；`rm` 打到 `/` / `~` 及其父目录一律 `Deny`，任何 allow 与 hook 都翻不过来。**诚实定位 = 减少误伤，不是抵抗攻击，别当主要防线。**
- **四个内置模式**（此前被多处引用却从未被定义，本 spec 把它固定下来）：

  | 模式 | 判据 | 说明 |
  | --- | --- | --- |
  | `readonly` | 非 `ReadOnly` → `Deny` | **没有任何写豁免**；`bash` 也拒（`Exclusive`，shell 里能写文件）。要放行就切模式 |
  | `ask` | 写类（`WritePaths` / `Exclusive`）→ `Ask`；只读 → `Allow` | 交互式默认：「默认安全又不打断」那一档 |
  | `auto` | 默认 `Allow` | **不等于「跳过权限」**：只受规则与断路器约束——断路器、`.env` deny、root 防呆照样生效 |
  | `plan` | 同 `readonly`，**唯一豁免**：`WritePaths` 的**全部**路径 = `<repo>/PLAN.md` → `Allow` | 「硬」plan 模式；与 `readonly` 的差别**只有那一条豁免**（见 §13） |

  四条对每个模式都成立的不变量：① **断路器短路在规则之前**，任何模式都翻不动；② **hook 只能收紧**（永远不能放松一个 `Deny`）；③ **沿委派链传播的是 `Deny` / `Ask`**（不给 `Allow`）；④ **无交互渲染器时 `Ask → Deny` 由循环在门外做**（门是纯函数、不读环境；门的裁决如实保持 `Ask`，理由进 `reason`）。另：**模式是 `Session` 的策略值、不进事件流**（`--continue` 回到 `config.toml` 的值，审计靠 `PermissionDecided`）。**执行者沿用父级的模式**（模式是会话对写的立场，子级不会拿到更松的那一档：`auto` 的子级也能写、`readonly` 的子级同样不能写），**收紧来自规则层**——`propagate` 为真的 `Deny`/`Ask` 照常 ∪ 下去，`Allow` 不传播；再加空的 read set，执行者的权限是派发者的**子集**（§16 的票 11 折回）。
- **`.env` 家族默认 `deny`**（`*.example` / `*.sample` / `*.template` 除外）。
- **「总是允许」只改会话内策略**、不写用户的 `config.toml`、不进流。
- **deny 不从上下文移除工具**（移除会废掉前缀缓存）——要「不存在」就在组装期不注册。
- **动态工具这一侧没有额外信任策略要落**：它就是普通目标，一条 `Tool("custom__*")` 规则兜底。
- **headless 的 `Ask` 自动降级为 `Deny`**：理由进 stderr 与 `PermissionDecided.reason`，**由循环在门外做**。

### 13. 硬 plan 模式

- **plan 模式 = 策略里的一条预设**（`effect()` 不是 `ReadOnly` 的调用一律 `Deny`），**不新增状态机**；是 `Deny` 不是 `Ask`（本模式的定义就是「硬」）。
- **进出只用手势**：`/plan` / `/endplan` / Shift+Tab，**不进工具面**（给模型一个 `exit_plan_mode` 等于把「能不能写」交回给模型）。
- **计划落项目根 `PLAN.md`，它是这个模式下唯一的写豁免**；豁免形状必须是「`WritePaths` 的**全部**路径都是它」（否则借道）；`Exclusive` **不可豁免**。
- **`/plan` 撞上已存在的 `PLAN.md` → 先问用户（覆盖 / 追加 / 保留）**；「覆盖」由 CLI 清空（read-before-write 会拒写已存在文件；工具绝不擅自删用户的文件）。
- **compaction 后不重新注入**：钉住的短指令已保证指向文件的那条不被裁剪，注入全文会占每轮预算且**每次改计划都废掉前缀缓存**。

### 14. 动态工具注册

- **声明语法里没有副作用类别这个字段** ⇒「谎报只读」没有地方可说；**`effect()` 恒为 `Exclusive`**（走既有的最保守路径，并行判定不需要特例）。
- 代价写明：真正只读的动态工具也全局串行，且 **`read-before-edit` 覆盖不到它**（`WritePaths` 未知）——所以约束落在**权限门**上。
- **声明复用同一套工具声明形状**（JSON Schema 原样就是 provider 的线级形状），住在 `~/.config/fs-agent/config.toml`。
- **执行形态 = argv 数组、不经 shell**；参数按**整个 argv 元素**替换（缺席则省略该元素；数组 / 对象序列化成一个元素，**不展开**）——这直接消灭 shell 注入。
- **命名空间 = `custom__<ns>__<tool>`**，内建名永不含 `__` ⇒「有 `__` ⟺ 自定义工具」是**词法可判定的谓词**。
- **可见性 = 启动即全局可见、组装期固定**（否决「挂在 skill 上」：`tools` 数组属于**前缀**，中途增删会废掉前缀缓存）。
- **必须有超时与进程树终止**。明确不做：MCP client 本身。

### 15. 讨论协议与轮次

- **轮次结构 = 独立首轮 → 揭示 → 定向第二轮 → 合成。**
- **「结论冲突」用机械判定**：每个讨论者在正文后**另起一行给一行自由结论**，归一化后**精确相等或子串包含**即视为一致。
  - **零额外调用、无假阴性、假阳性有界于 2 轮上限**；
  - 不用 `response_format`（两家能力不一致）；不用**受控极性标签**（开放问题没有自然标签，硬压就是失真且失真无上界）；不用**中立裁判**（MT-Bench 位置一致性 GPT-4 65.0% / Claude-v1 23.8%，75% 偏向第一个；Anthropic 自己发现多裁判更差）。
  - 它的价值是**把分歧显式化**（那两行结论就是 `DivergenceRecorded{positions}`），**不是省调用**。
- **N=2 不裁决**：冲突只被**判定与记录**，裁决发生在合成。
- **合成器（`Synthesizer`）职责 = 画出选项空间**：**一次独立的单发调用**（不是 agent 身份、无工具、无回合、不参与轮次），产出**共识 / 分歧（含各自成立的前提）/ 未决**三档——**不收敛**（与「探索 / 发散」的目的相反）、**也不放弃聚合**（「标出分叉点」本身就是聚合）。产出落在一条 `speaker_id = System` 的 `MessageCompleted` 上。
- **揭示发言全文、不揭示私有推理**（`reasoning_content` 根本不进投影；摘要则等于替他改写论点）。
- **上限 2 轮**（1 独立 + 1 定向，可配）；**第三轮不是新机制**（`RoundStarted{mode}` 已有槽位）。
- **终止四值**落在 `RoundEnded` 上：`NoDivergence` / `Consensus` / `RoundsExhausted` / `BudgetExhausted`。
- **单侧失败** ⇒ 该方本轮**缺席、讨论继续**，`RoundEnded` 照常发；⚠️ **缺席必须能从流上查出来**（该方本轮没有 `MessageCompleted`，由**该方自己的 `TurnEnded { reason: Error }`** 表达），否则合成器会把「只有一份回答」读成「共识」——这是这条路上最危险的一类误读。**双侧失败** ⇒ `RoundEnded { reason: Error }`，会话以 `SessionError` 收尾。**不重跑**。
- **协议指令常驻私有身份（system prompt）、不进流**：否则「第二轮的 `messages` 能从流重算」当场不成立；投影里的 `[轮 N · 名字]` 已给足轮次信息。
- **同一轮的两个讨论者并发发**（异构 ⇒ 并发预算天然分到两家 provider）。
- **一次讨论 = 3 次调用（无分歧）或 5 次（有分歧）**，机械判定不花钱。

票 10 落地时把上面几处留白写实成机制（都不改本节的任何决定，但**会束缚后续票**，故折回正文）：

- **轮次投影窗口是结构性的，不是时序的**：第 R 轮某讨论者的 `messages` = 「`seq ≤ 该轮 RoundStarted` 的事件」∪「它自己在该轮之后的事件」。两人同轮并发，「对方还没作答」这种时序假设在快 provider 下立刻破；把窗口切在 `seq` 上才与交错顺序无关。**票 17 的 `sessions replay` 必须复现这条规则**，否则重算的 `messages` 与实际发出的不等。单侧失败时不重开窗口：缺席方在本轮的事件本就不存在。
- **结论行的约定文本 = `CONCLUSION:` 前缀**（`discussion::protocol::CONCLUSION_MARKER`，**提示词与解析器共用同一常量**，同 §18 的约定文本规矩）。取**最后一条**非空的标记行（容忍尾随客套）；标记缺失即「无结论」，而**无结论绝不判为一致**——空串是任何串的子串，这条 guard 就是防「只有一份回答被读成共识」。
- **协议指令是常量的私有身份**：讨论者与合成器各有一条 `system` 身份，`Session` 持有、**不进流**、作为请求首条 `system` 消息前置；`trim` 把它计入预算但**永不可裁**。指令**全程不变**：定向第二轮的规则写在常量里，而不是每轮改 system prompt——system 是前缀的头，中途改会废掉整个前缀缓存（同 §4 的 `reasoning_effort`）。轮次对模型可见的信息来自投影的 `[轮 N · 名字]` 前缀与对方被揭示的作答。
- **`RoundEnded` 只由「结束辩论阶段的那一轮」发**（外加每个合成轮）。于是它的四个终局值（`NoDivergence` / `Consensus` / `RoundsExhausted` / `BudgetExhausted`）**总是终局理由**，渲染与统计可直接据它分发；为开定向轮而结束的那一轮**不**发 `RoundEnded`，下一个 `RoundStarted` 就是它的边界（投影侧同样以 `RoundStarted` 收口）。
- **单侧缺席的收尾理由取主张最少的一个**：`RoundEnded { NoDivergence }`，缺席本身仍由该方 `TurnEnded { Error }` + 该轮没有 `MessageCompleted` 表达（查询 `discussion::protocol::round_attendance`）。
- **合成器的输入由流上重算，且缺席必须被写明**：`synthesis_prompt(question, events)` 逐轮取 `round_attendance`，把缺席方写成「本轮缺席」，而不是把单方回答摆成共识——这是上面那条危险误读的收口。合成失败（provider 报错 / 流未到 `[DONE]` / 产出为空）⇒ `RoundEnded { Error }` + `SessionError`、产物为空串、**不重跑**（同双侧失败）。

### 16. 执行者

- **v1 = 一个通用 `task` 工具**，不做专职角色、不引入第三种身份。「角色」是**配置**不是代码结构（挂点是 args schema 里的 `role` + 组装期构造）。
- **模型默认继承派出它的那个讨论者**，可配覆盖；执行者的 system prompt **私有**，`AGENTS.md` + skill 清单照常注入，**不带讨论协议注入**。
- **独立预算：轮数默认 25**（可配），但「独立」**只指轮数不指钱**——它的 token 计入会话累计。
- **权限：继承拒绝、不继承允许**（拒绝是约束，沿链只可能变严）。
- **递归深度 1**，且**第一道防线是执行者的工具集里没有 `task`**（不是「有工具但拒绝」）。
- **read set 不继承，且任一方向都不流动**（护栏防的是「凭想象改文件」，而「想象」是每个 agent 各自的）。
- **回传 = 摘要 + 元数据**（token、改动的文件从流上推导）；**过程默认不进任何讨论者的窗**，**结论经派发者自己的发言进入讨论**，对派发者与其他人**一视同仁**（否则制造信息不对称）；按需 zoom 走可观测性的 `sessions show`。
- **`task` 是普通工具调用、同 Turn 内阻塞到执行者结束**（因果紧；「每个 tool_call 恰好一条结果」自动覆盖，不需要异步投递）。
- **同一批里多个 `task` 可并发**——因为 `task` 自己不碰工作区（`effect()` 判的是**工作区**副作用）；真正的写互斥在执行者内部的调用上、靠**共享 `PathLocks`**。**并发上限默认 5**（成本 / 速率闸门，不是安全闸门）。
- **失败**（`ExecutorFinished{reason: Error|MaxIterations|Aborted|MistakeLimit}`）= 一条错误内容的工具结果，**讨论不因此中断**。

票 11 落地时把上面几处留白写实成机制（都不改本节的任何决定，但会束缚后续票，故折回正文）：

- **执行者的窗口 = 「钉住的注入 + 它自己的事件」**，不是全流：它不参与讨论，派它出去的那个会话的发言（以及另一方的作答）**不进它的窗**，否则长讨论会被完整重放进每个执行者的上下文。brief 仍从流上来——`ExecutorSpawned` 归**执行者自己**（`parent` 字段记派发者），`project` 把只给目标执行者的那条 `brief` 投影成它的第一条 `user` 消息 ⇒「流 + 规则 → messages」在嵌套会话里同样成立。**`ExecutorFinished` 对谁都不进投影**：派发者拿到的是那次 `task` 调用的工具结果。
- 「**执行者自己的投影是全量的**」的另一半含义：它自己的工具往返（结果正文、按 `seq` 合并）照 `mine` 规则投，**不做**「他人回合只留一行摘要」的压缩——压缩是给他人准备的。
- **执行者的模型可覆盖**（`SessionConfig::executor_model`，默认继承派发者）：这是 §17 弱模型分流留好的那个机制；**client 不换**（执行者在派发者的 provider 上作答），所以覆盖值必须是同一 provider profile 能服务的 model id。turn 上限（默认 25）与并发上限（默认 5）同样是 `SessionConfig` 的值。
- **执行者 id = `<派发者>-<n>`**，`n` = 流上该派发者已派出的 `ExecutorSpawned` 计数（+ 同一回合内已建的端口数）。派生而非分配 ⇒ 不引入第二个身份来源，`--continue` 之后的会话也不会重发已用过的 id。
- **权限**：执行者的策略 = **父级的模式** ∪ **父级策略里 `propagate` 为真的规则**——即「立场照旧，约束照收，允许不传」；再加**空的 read set**，它的权限是派发者的**子集**（`auto` 的子级能写、`readonly` 的子级不能写；`Allow` 规则不传播，所以派发者挣来的「总是允许」到不了子级）。headless 下若父级是 `ask`，子级的写也走「无交互 ⇒ `Ask→Deny`」——这条对每个 agent 一律成立，不是执行者特有的。
- **递归深度 1 的第一道防线落在工具表上**：`Tool::delegable()`（`task` 为 `false`）+ `Registry::for_executor()` ⇒ 执行者的 `tools` 数组里**没有** `task`，模型连试的机会都没有（不是「有工具但拒绝」）。
- **`task` 的 `effect()` = `ReadOnly`**（`effect` 判的是**工作区**副作用），于是同一批里的多个 `task` 可以并发：循环把**已授权**的 `task` 调用**延迟**到本批其余调用之后，再用 `buffered(并发上限)` 一起跑，结果按**批内顺序**落流（`max_parallel_executors` 默认 **5**）。真写互斥仍在执行者内部的调用上、靠**共享** `PathLocks`。hook 在某次调用上 `Stop` 时，已延迟的 `task` 各补一条「hook 停了这一回合」的错误结果——「每个 `tool_call` 恰好一条结果」在新交错下照样成立。
- **回传的元数据是推导值**：token 从该执行者自己的 `UsageRecorded` 求和（`events::usage_of`），改动的文件**从成功结果里的路径行**（`tools::file::WROTE_PATH_PREFIX`）推导——读结果而不是读 `ToolCallStarted` 的参数，因为 `hook.pre` 可能已经改写了那次调用，「实际写了哪个文件」只有结果记着。产物是一条工具结果：`executor <id> finished: <reason>` + `files changed:` + `tokens:` + `report:`；失败四值走 `Err` 分支 ⇒ 一条错误内容的工具结果。
- **`/undo` 免费成立**：执行者的 `outputs/<tool_call_id>.before` 与派发者在**同一个会话目录、同一命名约定**下（票 11 的验收项）。
- **渲染（§19）**：执行者的一回合**不是**会话的最终产物——headless 的 `stdout` 只放最终产物，执行者的 `TurnEnded{Completed}` 既不打印、也不覆盖派发者那一回合的文本。

### 17. 成本与预算上限

- **预算的单位是三个量、各管一段**：**窗口**按 agent 的模型（§10）、**轮数**（讨论 2 / 执行者 25）、**token 累计是会话级且讨论者与执行者共享**（`UsageRecorded` 的求和派生值）。
- **硬停盯累计，行为 = 降级并收尾**：讨论不再开第二轮、**直接进合成**（合成是唯一不能省的调用）；执行者不再派新的、**已在跑的跑完**；降级复用讨论协议的「缺席」形状。
- **闸门用 token，费用只作显示**（可配价目表，且 **`cached` 与 `miss` 分开计价**）。
- **前置估算做**，但阈值用**剩余额度的比例**（字符/4 估不准，「估算 > 剩余」会频繁误拒）。
- **弱模型分流只有两个落点：合成器与执行者**（可配覆盖）；**讨论者绝不能换**（异构是多样性最强杠杆）；**v1 默认全用讨论者模型**——机制留好、取值等数据。
- **限额：没有限额响应头被文档化**，限额只能从**状态码 + body** 读：DeepSeek 欠费 **402**、限速 **429**；Kimi Open Platform **429**（`rate_limit_reached_error`）；**Kimi Code 把额度写成 403 + 明确文案**（5 小时滚动窗口 / 每周 7 天 / 每月计费周期 / 并发上限），瞬时限速与引擎过载才是 429 ⇒ **被动分类（403 与 429 都按 body 细分）+ 本地日账本**（按 UTC 日聚合，**从今天的会话文件派生**，不是新状态文件）。
- **缓存计量归一成 `cached` / `miss` 一等字段进 `UsageRecorded`**（Kimi `cached_tokens`；DeepSeek `prompt_cache_hit_tokens` / `prompt_cache_miss_tokens`；**不照抄 Anthropic 的 `cache_creation` / `cache_read`**，那两家没有）；Kimi 有 **>256 tokens 才缓存**的门槛。
- **`BudgetExhausted` 是撞墙值**，与 `Completed` **不能同色**，且与 `MaxIterations`（回数）/ `RoundsExhausted`（讨论轮数）是三个不同的上限。

### 18. 可观测性

- **查询接口 = 四个动词的 CLI 子命令族**：`sessions ls` / `show <id> [--round|--speaker|--kind|--tool|--only-error]` / `replay <id> --speaker X --round N`（**投影重算**，调试投影 bug 的唯一手段）/ `stats <id>`。
- **不建索引**（`seq` 就是行号，顺序读 + 内存过滤；索引会是第二个真相源）；输出表格或 `--json`，**stdout 只放结果、诊断走 stderr**；**这是给人用的，不是给 agent 的新工具**。
- **两个事后视图**：默认**按轮次分组的时间线**（工具调用与结果归成一条，前缀与实时同形），加一个 **`--files` 文件改动史**（唯一按**工作区对象**而非时间索引的视图，直接回答「谁在哪一轮改了什么」，且是**推导**不是新字段）；**不做交互式浏览器**。
- **诊断指标 = 流上的 group-by，不是新埋点**；一组固定指标：per-agent token / 花费 / 命中率、每轮调用数、**单侧缺席率** ⚠️、执行者失败原因分布、**编辑匹配梯降级分布** ⚠️、read-before-edit 拒绝与 read set 失效、权限决策分布、hook 三类结果、讨论分歧率与停法分布——标 ⚠️ 的两类是**静默**的，固定指标的价值就是**替你问了该问的问题**；**保留过滤原语 + `--json` 作逃生口**。
- **编辑匹配那类诊断量不加新变体**：以**约定文本**落在既有 payload 上，**渲染与解析共用一个格式常量**（漂移是文本方案唯一的真风险，会让统计悄悄变成 0）；若某诊断量将来升级为**权威**再给它结构化位置。

### 19. 渲染与 CLI 组装

- **同进程，渲染器是启动时选定的一个**（plain / TUI / headless 三模式互斥 ⇒ 一个 trait 三个实现，**不是并发订阅者**）；**否决两进程**（IPC 整条流会逼「单一写入者 + `seq` 唯一身份」重做；TUI 崩了不丢会话由 `--continue` 满足）。
- **消费者接口**：每种模式一个 `tokio::spawn` 的任务消费**同一条广播通道**，通道由 `cli` 在组装期注入；**增量与日志事件必须同通道**（分两条则相对顺序无定义）。
- **TUI 额外 `select!`(广播 / tick / 键盘)**，**输入归渲染器**（终端独占），答案经注入的 channel 回循环。
- **呈现**：说话人前缀**逐行**（`[kimi]` / `[deepseek]` / `[executor:<id>]` / `[user]`）、轮次分节线、分歧缩进块、工具调用一行摘要、hook 反馈与工具结果**归成一处**（同 `tool_call_id`）。
- **headless 纯净性靠结构**：渲染器只写两个显式 sink（`stdout_result` / `stderr_diagnostic`）；stdout **只放最终产物**（`TurnEnded{Completed}` / 讨论 `Consensus` 的 assistant 文本），其余全 stderr；**执行者的一回合不是最终产物**（它既不上 stdout，也不覆盖派发者那一回合的文本，§16）。
- **TUI 栈 = `ratatui` + `crossterm` 默认特性 + inline viewport**（定稿内容 `insert_before` 推进 scrollback、live 留 `Viewport::Inline`；**否决 alt screen**——转录要能滚动 / 复制）；**高亮 = `tree-sitter-highlight`**（树已在，闭包 15，不引 C 构建依赖；代价是终端渲染器自己写），diff 着色与语法高亮是**两层**。
- **配置**：`~/.config/fs-agent/config.toml`（TOML）；**不**自动加载项目 `.env`；优先级 **`config.toml` > 已导出 env > 内置默认**。
- **模式、名册、预算、路径锁、渲染器、provider 全部在组装期注入**——库入口不读环境。

### 20. OS 沙箱与凭据暴露面

- **v1 不上进程级隔离**（本机 Linux x86_64）——沙箱与「自用」有真实张力（要放行工作区 / 两家 API 的网络 / 读自己的配置与 skill，那份白名单**本身就是策略文件**），而并发的危险靠写串行化 + 权限门 + 断路器解决；**升级路径 = 「只做 Linux 的 bubblewrap」**，**不做抽象预留**。
- **cwd 路径限制 = 文件工具的「模型供路径」限定在会话 cwd 及其子树**（限的是模型给的路径，不是 harness 自己读的 `skill()` / 会话目录），**例外走权限规则**。它保护的是一件具体东西：**agent 自己的密钥就在 `~/.config/fs-agent/config.toml`**。
- **秘密打码做**：值级、best-effort、**在入流前**（与截断 / 落盘合成一条流水线 **打码 → 截断 → 落盘**）⇒ **流上的文本 == 模型看到的文本**（一致），而**工具执行时用真值**；范围**含消息正文**。
- **凭据路径清单**：(a) 文件工具读 → `.env` deny + cwd 限制**两条一起**；(b) 命令回显 → 入流前打码 + 建议的读断路器；(c) 跨 agent → 投影已把最强的通道关掉（他人工具结果正文不投），剩的靠打码消息正文；**(d) 外传 → 坦白写「基本无能为力」**（难判定 / 误伤合法 `curl`），真正的边界是「密钥不给 agent」。
  - **例外**：`outputs/<tool_call_id>.before` **不打码**（它是 `/undo` 的**字节级还原源**，内容本来就是用户自己的工作区内容）；`outputs/<tool_call_id>.txt` **要打码**。
- **prompt injection 定位为「降低上限」而非「解决问题」**：门是 `(policy, tool, args)` 的纯函数、**从不读对话文本** ⇒ 注入不可能说服门放行；**破坏半径 = 你的策略允许的半径**；缓解三条（身份指令 / 他人工具结果不投 / 门不看文本），**不把发言降权、不让门读对话**。
- **root / sudo 时拒绝启动、不给 bypass flag**（任何一次误判都变成系统级，而护栏都假设「最坏只到工作区」）。

## Testing Decisions

### 什么样的测试是好测试

- **只测外部行为。** 这套架构把「外部行为」变得非常好断言：**事件流就是可观察的契约**。测试断言 `EventLog`（JSONL 里的 `seq` + 信封 + payload）与**工作区副作用**（磁盘上的文件、临时 git 仓库的状态），不断言函数被调用了几次、内部结构体长什么样、私有函数返回什么。
- **不测实现细节**。`project()` 的中间产物、锁的持有顺序、`[轮 N · 名字]` 前缀的拼法**不是**契约——它们是可重算的派生层，断言它们会让重构变贵。
- **不断言 `at` 时间戳**，只断言 `seq` 与 payload（避免 flaky；也避免为了可测性引入一个「注入时钟」的新机制）。
- **测试里没有任何网络**：所有 provider 都是假 provider（理由见下）。

### 唯一的 e2e 接缝：组装入口

- **一个接缝**：库入口的组装函数。测试从这里构造一个 `Session`，注入：
  - **假 provider**（按调用序脚本化返回：文本 / 工具调用 / 推理 / usage / 各类错误），
  - **临时工作目录**（必要时是一个临时 git 仓库），
  - **组装期注入的 `PathLocks`** 与配置值（模式、预算、名册），
  - **捕获的 sink**（`stdout_result` / `stderr_diagnostic`）。
- 然后**通过公开库 API 驱动整个闭环**（讨论 → 派执行者 → 工具 → 权限 → 事件 → 渲染），最后断言事件流、磁盘状态与两个 sink。
- **为什么必须是假 provider**：两家 provider **都没有 `seed`** ⇒ 真调用不可复现；而且真调用会把测试变成网络依赖。假 provider 因此不是「测试技巧」而是**唯一可行的验收手段**。
- **假 provider 必须能演出的场景**：分片到达的 `tool_call`（拼装）、`reasoning_content` 的往返、两家的 usage 形状差异、六个 `ProviderError` 分类（含 `QuotaExhausted` vs `RateLimited`）、流中途失败（用来触发「单侧缺席」）。

### 直接测的纯函数（不新增接缝）

这四个本来就是纯函数，直接调用即测——它们不需要、也不应该各占一个 mock 接缝：

1. **`project()`**：给定流 + 发言归属 + 能力 → 断言 `messages`（他人的工具调用只剩一行摘要、结果正文与推理不投、自己的推理回放、工具往返按 `seq` 合并、钉住的注入不参与合并、轮次是硬边界）。
2. **`trim()`**：给定 `messages` + 预算 → 断言丢弃顺序与「日志一条不删」。
3. **权限门**：`(policy, tool, args)` → 裁决。用真值表覆盖 `模式 × 动作 × Scope × propagate`，外加断路器短路、上确界合并、无交互时 `Ask→Deny`。
4. **编辑匹配梯**：`(文件内容, old_string, new_string)` → 命中级别或失败；含三样护栏与「全线失败即失效 read set」。
   另外两个小的纯函数也在此列：**结论归一化的相等 / 子串判定**、**`repo_map` 的 `rank()`**。

### 先例（prior art）

- **本仓库没有先例**——greenfield，零 Rust 代码。**第一个 tracer bullet 的产出之一就是这个 harness**，之后的票只会扩展它的脚本化能力，不重造。
- **可模仿的先例在图上**：`.scratch/multi-agent-architecture/prototype/05-hook-permission-ordering.html` 是一个 headless 验证过的可点击状态机（7 个剧本）。那 7 个剧本**应当逐个变成权限门 / hook 次序的测试用例**，并额外补上「取消」这条第 5 路径。

### 要覆盖的测试类别

1. **循环不变量**：「每个 `tool_call` 恰好一条结果」，**含 5 条异常路径**（权限拒绝 / 用户拒绝 / hook 跳过 / `hook.pre` 失败 / 取消）。
2. **事件流不变量**：只追加、`seq` 与行号一致、**增量不进流**、单一写入者、末行不完整可容忍。
3. **可重算性（最重要的一条）**：跑完一次会话后，**用 `sessions replay` 重算的投影 == 当时实际发给 provider 的 `messages`**。这条是「事件流是唯一真相源」的验收，也是投影 bug 的唯一探测器。
4. **权限真值表** + 断路器 + 四个内置模式的不变量。
5. **讨论协议剧本**：无分歧（3 次调用）/ 有分歧（5 次调用）/ **单侧缺席**（不能读成共识）/ 双侧失败 / `BudgetExhausted` 提前收尾。
6. **上下文**：丢弃顺序、钉住的注入不被裁剪、单次结果超限落盘 + 预览指针、compaction 不走（v1）。
7. **崩溃恢复**：悬空 `tool_call` → 合成失败结果、不重执行、不追加第二个 `SessionStarted`；`--continue` 后**会话 id 不变**（前缀缓存的前提）。
8. **秘密打码**：入流前的文本已打码而工具执行用真值；`.txt` 打码、`.before` 不打码。
9. **取消传播**：向下传到在跑的执行者、执行者以 `Aborted` 收尾、讨论继续。
10. **渲染**：headless 的 stdout 只有最终产物（其余全 stderr）；TUI / plain 用同一个事件序列喂、只断言 sink。
11. **动态工具**：argv 元素替换**不展开**、不经 shell、超时与进程树终止、命名空间词法判定。
12. **`/undo`**：按 `outputs/<tool_call_id>.before` 还原的是**实际被替换的区段**（含走了降级匹配的那次）。

## Out of Scope

- **证据型砍掉项**（判据变化不翻它们）：AST / tree-sitter **编辑**、unified diff 编辑格式、原生多 provider 协议、**MCP client**、SWE-bench 跑分与多模型 dashboard。
- **向量检索 / RAG**：会引入第三个 API 面（embeddings）与索引存储，反向压到「只做一个 OpenAI-compatible client」；grep + 符号检索够用。
- **形态扩展**：IDE 集成、Slack / Web / 移动端接入、会话分享。
- **进程级沙箱**：v1 不做（升级路径写明是「只做 Linux 的 bubblewrap」，且**不预做抽象**）。
- **裁判 / 仲裁者**：已被证据否决（位置偏见 + 多裁判更差）。若将来要做，形状是**合成器那种单发调用**，不是新参与者种类。
- **N > 2 的讨论者**：机制上零 schema 改动，但**必须同时重开「N=2 不裁决」那条**（N ≥ 3 时它的依据消失）。**给枚举预留空位是纯亏**，不做。
- **两进程渲染、alt screen、syntect 的 C 路径、内置编辑器。**
- **fork / rewind 手势、shadow git、快照系统、SQLite、全局会话索引、自动清理**（只给手动 `prune`）；**每次编辑自动 git commit**。
- **compaction 的实现**（形状已钉死：`HistorySuperseded { reason: Compaction, summary }`，但 v1 不建）。
- **把工具打包进 skill**（会与「工具表组装期固定」冲突）。
- **交互式 transcript 浏览器。**
- **弱模型分流的取值**：机制留好（合成器 + 执行者可配覆盖），但「哪些任务默认给哪个弱模型」**等数据**，v1 全用讨论者模型。

- **术语照 `CONTEXT.md`。** 地图里有两处**有意留下的别名**（票 16 §2 标题的「聚合器」、票 14/22 的「子 agent / subagent」）：实现与票面都按词汇表走（**合成器 / 执行者**），不要跟着那两处写。

- **票 10 回改**（2026-09-21）：讨论协议落成三层——`discussion`（纯策略：结论判定、轮次策略、身份与合成提示）、`agent`（控制流：轮次循环、两个并发回合、单发合成调用，仍是唯一写流者）、组装层（`assemble_discussion`：一块 `SessionScaffold` 开两个讨论者会话 + 一个合成器会话）。§15 新增的六条机制里有两条会束缚后续票——**轮次投影窗口**（票 17 的 replay 必须复现）与**常量私有身份**（system 是缓存前缀的头）——所以折回正文而不只写在票的评论里。**边界未变**：`discussion` 不碰 `provider`，provider 调用全在 `agent`。为让两个讨论者并发写同一条流，`EventLog` 变成可 `Clone` 的共享句柄（内部 `Mutex`，每条事件仍原子落入、`seq` 仍是行号），`project()` 的入参从 `&EventLog` 收窄成 `&[Event]`（更纯，也让轮次窗口自然）。两个讨论者会话共享一份**权限策略**：用户在同一个终端上说的「本会话记住允许」是会话级事实，不是某个讨论者的私产——§12 的「不继承允许」讲的是**委派链向下**（讨论者 → 执行者），兄弟会话之间不在那条链上。
- **回数 / 成本的事实**（用来判断实现是否走样）：一次讨论 3 或 5 次调用；执行者默认 25 轮、并发上限 5；单 agent 默认 100 回合；一次机械判定不花钱。
- **三条不变量，任何实现票都不许绕**：(1) 每个 `tool_call` 恰好一条结果；(2) 存在未出结果的 `tool_call` 时**绝不**调 provider（pending 是对事件流的查询，**作用域 = 发起调用的那个 agent**：票 10 起两个讨论者并发在飞，**对方**未出结果的 `tool_call` 不是本方的欠账，会话级那次全量查询留给 `--continue` 的悬空恢复）;（3）**只有循环写事件流**。
- **两条「看起来像优化、实际会毁掉前提」的操作，明令禁止**：中途切 Kimi 的 `reasoning_effort`（废掉前缀缓存）；带 tools 时丢弃 DeepSeek 自己的 `reasoning_content`（直接 400）。
- **给 `/to-tickets` 的切片建议**：greenfield ⇒ **没有 prefactoring**。第一个 tracer bullet 应当是**垂直**的：crate 骨架 + 事件流 + 假 provider + 一个 Turn + headless 的 stdout 只放最终产物——它一次性把**唯一那条 e2e 接缝**建起来，之后的票都往这条接缝上加场景，而不是各自新开 mock 接缝。
- **实现者请勿「顺手改进」**：向量检索、MCP、裁判、进程沙箱升级都被逐条评估过并**有理由地**排除（见 `Out of Scope`）。要动它们，先改这张 spec，而不是在实现里悄悄加一条路径。
