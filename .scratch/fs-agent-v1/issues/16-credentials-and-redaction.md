# 16: 凭据暴露面与打码流水线

**What to build:** 密钥不会顺着事件流、落盘文件或跨 agent 的发言漏出去，同时工具执行仍然拿得到真值。agent 自己的 key 就在本机配置文件里，所以这条是自用场景的真风险。

Blocked by: 07, 12

Status: ready-for-agent

**参考:** spec §20（凭据暴露面）、§10（截断落盘）

- [ ] 流水线固定为 **打码 → 截断 → 落盘**，打码发生在**入流前** ⇒ **流上的文本 == 模型看到的文本**，而**工具执行时用真值**
- [ ] 打码是**值级、best-effort**，范围**含消息正文**（跨 agent 那条路径的唯一剩余形态就是「他在发言里复述了密钥」）
- [ ] `outputs/<tool_call_id>.txt` **打码**；`outputs/<tool_call_id>.before` **不打码**（它是 `/undo` 的字节级还原源，内容本来就是用户自己的工作区内容）
- [ ] 文件工具的**模型供路径**限定在会话 cwd 及其子树；例外走权限规则（限的是模型给的路径，不是 harness 自己读的 skill / 会话目录）
- [ ] `.env` deny + cwd 限制**两条一起**挡住凭据文件读取；命令回显靠入流前打码
- [ ] root / sudo 下**拒绝启动**、**不给 bypass flag**
- [ ] 定位写进文档：prompt injection 是「降低上限」而非解决问题——门是 `(policy, tool, args)` 的纯函数、从不读对话文本，所以破坏半径 = 你的策略允许的半径
- [ ] e2e：让一个假密钥流经工具输出与消息正文，断言事件流与 `.txt` 里是打码值、而工具实际拿到真值；`.before` 里是真值
