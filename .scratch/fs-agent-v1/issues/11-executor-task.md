# 11: 执行者 `task`

**What to build:** 讨论者能派一个执行者去真实干活——执行过程不污染讨论，结论经派发者自己的发言回到讨论，且「派个子 agent 去写」这条路径**绕不过**已经定下的拒绝规则。

Blocked by: 04, 10

Status: ready-for-agent

**参考:** spec §16（执行者）、§12（继承）、§5（投影过滤）

- [ ] 内建 `task` 工具派执行者：**嵌套 `Session`** + `parent_id`、独立轮数预算默认 **25**、事件落**同一个流**（`ExecutorSpawned` / `ExecutorFinished{reason}`）
- [ ] 权限**继承拒绝、不继承允许**（`propagate` 按动作定：`Deny`/`Ask` 真、`Allow` 假）⇒ 沿链只可能变严
- [ ] **递归深度 1**，且第一道防线是执行者的工具集里**没有** `task`（不是「有工具但拒绝」）
- [ ] read set **不继承**，且任一方向都不流动
- [ ] 回传 = **摘要 + 元数据**（token、改动的文件从流上**推导**）；执行者事件**不进**讨论者投影（`ExecutorFinished` 也不进），而**执行者自己的投影是全量的**
- [ ] 同一批里的多个 `task` 可**并发**（上限默认 5）；`effect()` 判为「不碰工作区」⇒ 不参与写互斥；真正的写互斥靠**共享** `PathLocks`
- [ ] 失败四值（`Error` / `MaxIterations` / `Aborted` / `MistakeLimit`）表现为**一条错误内容的工具结果**，讨论**不因此中断**
- [ ] `task` 同 Turn 内**阻塞**到执行者结束（因果紧，不需要异步投递）
- [ ] `/undo` 对执行者造成的编辑**同样有效**（同一会话目录、同一命名约定）
