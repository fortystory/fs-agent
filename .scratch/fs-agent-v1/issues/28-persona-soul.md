**参考:** spec §5（发言归属与投影）、§10（钉住的注入不参与裁剪）、§15（讨论协议）、票 27、`docs/discussion.md`

- [x] **配置**：`[[discussion.debaters]]` 增加可选 `soul`（简写形式没有）；空 `soul` 与超长（`MAX_DEBATER_SOUL = 2000` 字符）都是启动错误——注入是钉住的，得有上限

- [x] **钉住**：`trim` 对注入一律视为 pinned，soul 不会被预算裁掉（这也是给它设上限的原因）
- [x] **测试**：配置解析 / 空 / 超长；投影「自己看得到、对方与合成器看不到」；集成「两边的实发请求各含自己的 soul、不含对方的」+「流上有两条署名正确的 `Persona` 注入」+「该轮 replay 仍是实发内容」

## Comments

**2026-09-22（实现）** 为什么不是把 soul 塞进私有身份（那样角色服从性更强）：

1. **身份必须能从流重算。** 规范 §15 那句「协议指令常驻私有身份、不进流，否则第二轮的 messages 能从流重算当场不成立」的成立条件是**身份是名字的纯函数**。soul 打破它，所以要么进流、要么 replay 就得去读配置（那会让重算随配置漂移）。
2. **进流就该按用户文本的既有路子走。** 用户写的指令（AGENTS.md、技能清单、计划模式覆盖）本来就以 `ContextInjected` 进流并被投影成注入的 `user` 消息；soul 是同一类东西，所以复用它，**零 replay 改动、零 schema 改动**。
3. **唯一的新规则是「可见性」。** 别的注入是用户对整场说的，人物注入是这个人自己的，所以投影里只有它按 `mine` 过滤——一条规则，一句话说得清。

**代价**：同一个人物在同一会话里参与第二次讨论时，它的 soul 会再注入一次（窗口里出现两遍同样的设定）；不重开机制去重，因为「同一份文本说两遍」无害，而去重需要「本次讨论从哪开始」的状态。
