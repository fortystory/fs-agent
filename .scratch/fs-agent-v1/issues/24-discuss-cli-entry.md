# 24: 讨论的 CLI 入口（`fs-agent discuss`）

**What to build:** 讨论协议在库层已经完整（票 10 + `tests/discussion.rs`），但从命令行起不来——`fs-agent` 的子命令只有 `probe` / `prune` / `sessions` 与单 agent 交互会话。这一票把 `assemble_discussion` 接到一个真正的入口上，让「两个讨论者 + 合成器」成为一条命令，而不是一段要自己写的组装代码。

Blocked by: 10（讨论协议）、18（渲染接缝）、19（动态工具 / 配置）

Status: done

**参考:** spec §15（讨论协议与轮次）、§17（成本与预算）、§19（渲染与 CLI 组装）、`docs/discussion.md`

- [x] **配置里加 `[discussion]`**：`debaters = ["模型", "另一个模型"]`（恰好两个）+ 可选 `max_rounds`；解析期就拒绝「不是两个」「不在 `[models.*]` / 内置表里」——组装期只负责组装。（**「必须不同厂商」这条已被票 25 推翻**：一个订阅到期不该让讨论不可用，现在是「允许 + 一行提示」。）

- [x] **`fs-agent discuss "问题"`**：`--plain` / `--tui` / `--config` / `--cwd`；问句也可以从 stdin 来（终端问一行，管道读到结尾）

- [x] **不再需要 `examples/discuss.rs`**：子命令取代它，示例删掉，README 的「诚实的缺口」那句改写

## Comments

**2026-09-22（实现）** 三条设计取舍，都是「不给第二种说法」：

1. **roster 属于配置，不是 flag。** 谁讨论是一次会话级决定，而讨论者是唯一绝不被路由的参与者（`Routing::apply` 的注释写着「没有讨论者的键，这就是要点」）。所以 `discuss` 故意没有 `--model`。
2. **合成器复用 `[routing].synthesizer_model`。** 它是 `LandingPoint::Synthesizer` 的落点，不再加一个 `[discussion].synthesizer_model`——一个值一种拼法。
3. **`max_rounds` 可配、不设上限。** 协议机制上第三轮不是新机制（`RoundStarted { mode }` 早就有槽位），默认 2 = 独立首轮 + 至多一次定向第二轮。

顺带修掉两处 TUI 的谎话（新入口把它们放大了）：**没有人在读行的时候**（回合在飞、或 `discuss` 这种一次性前台），回车不再把草稿丢掉、提示行也不再承诺 `enter 发送` / `shift+tab 计划`。

**已知不精确**：TUI 的信息面板只有一个「模型」字段与一行「上下文」，对两个讨论者 + 一个合成器只能用第一个讨论者的窗口近似；转录才是读讨论的地方（面板是展示量，不是账本）。

**2026-09-22（后续）** 上面那条「必须不同厂商」的校验在票 25 里被推翻：改成允许同厂商 / 同模型 + 一行多样性提示 + 同身份守卫。

**2026-09-22（后续，`/code-review`）** 收尾那条勾选**是空的**：`examples/discuss.rs` 在本仓库历史里从未存在过（`git log --all -- examples/` 无输出，HEAD 也没有 `examples/`），所以「示例删掉」没有可删的东西。子命令确实取代不了任何示例——因为本来就没有。这条记在这里而不是回改勾选，是为了让「当时为什么勾上」有据可查：正文写的是意图（不该再有第二套组装代码），而勾选读起来像一次已完成的删除。
