# 13: 取消传播

**What to build:** 一次取消手势干净地停下当前回合，并把取消**向下**传到正在跑的执行者——不留悬空状态、不把讨论误判成失败。

Blocked by: 11

Status: done

**参考:** spec §6（取消传播，spec 期新增的唯一决定）、§3（第 5 条异常路径）

- [x] 手势本身**不进事件流**（流只记录 agent 的动作，与 `/undo` 写回、`/plan` 覆盖同规矩）
- [x] Esc 中断在飞的 provider 流与在跑的工具；当前 Turn 以**既有的** `TurnEnded { reason: Aborted }` 收尾
- [x] 在飞的 `tool_call` 由循环合成一条错误结果——这是 **第 5 条**异常路径 ⇒「每个 `tool_call` 恰好一条结果」仍成立
- [x] 取消**只向下、不向父**传播：在跑的执行者各自以 `ExecutorFinished { reason: Aborted }` 结束并回一条错误内容的工具结果；讨论**不**因此以错误收尾
- [x] 取消过程中再按一次 = 强退进程；随后 `--continue` 能正常恢复（走悬空 `tool_call` 那条合成路径）
- [x] e2e：假 provider 卡住流 → 触发取消 → 断言事件流形状（`Aborted` 收尾 + 合成结果）与执行者收尾

## Comments

**落地（2026-09-21）。** 机制在 `agent::cancel`：`CancelSignal`（信号端，只有前端能发起）与 `CancelObserver`（观察端，逐层克隆进回合与执行者）。两个类型分开是刻意的——「只向下、不向父」因此是**类型性质**（回合手里没有能发起取消的东西），而不是要靠人记住的约定。手势的生命周期是**一次运行**：`run_turn` / `discuss` 开始时清零（否则一次 Esc 会让同一进程里的会话再也跑不动下一轮），运行内部发起的手势则不因一时没有观察者而丢（`send_replace` 而非 `send`）；观察端等到信号端被丢弃时**永久 park**，所以「发送端没了」不会被读成「被取消」。

手势落在**每一次「还要做事」的地方**：开下一次 provider 调用之前、`send` 本身与流读取（`select!`，`biased` 让手势赢过就绪的 delta）、内联工具派发的前后、讨论的轮次边界与 `run_single_shot`，以及执行者自己的那一回合（它拿的是同一个观察端的克隆，因而是**优雅收尾**而不是被 drop：`ExecutorFinished { Aborted }` + 一条错误内容的 `task` 结果照常落流）。

「每个 `tool_call` 恰好一条结果」在取消下的三条补法：已开始但还没派发的（`task` 会被 defer）→ 循环补一条「did not run」；内联工具在飞行中被停 → 补一条「in flight，结果 unknown」（与 `--continue` 的恢复文案同调，因为工具 future 被 drop，它到底跑没跑没人知道）；执行者在飞行中被停 → 它自己回那条报告。补结果的形状集中到 `close_deferred_calls` 一处，和 hook `Stop` 共用；两条消息各自成为一个常量。

**回改 spec（不是只写评论）**：讨论层「取消后不再开新轮、也不合成」是**后果上的改动**，不只把留白写实——已同步改 §6、§16 的失败那条、Testing Decisions 第 9 条与 Further Notes，点明「讨论照常处理这条工具结果 / 讨论不因此中断」只指「这条失败本身不中断讨论」，手势会停掉这次运行。另外补了一条：**已完成单元不被撤销**（合成器若在按 Esc 之前已到 `[DONE]`，产物照常 `Completed`）。

**这一票证明到哪、没证明到哪**（测试在 `tests/cancellation.rs`，8 例）：

- 证明了：流在飞、内联工具在飞、`task` 已 defer 而批次里另一个调用在飞（走 `close_deferred_calls`）、执行者在跑、双方都停、合成器被停、手势只作用于一次运行、强退后 `--continue` 恢复。
- **Esc 键本身没接**：库里没有读终端的地方，`cancel_signal()` 目前只有测试在按；键位、第一次/第二次的判定属于渲染器（票 18）。这条验收项按「信号 + 下游语义已就绪」勾选，键位留给票 18。
- 「执行者被取消不会让派发者失败」是**结构性质**而不是可单测行为：v1 只有一个取消源，无法只取消执行者而不取消派发它的那次运行；能测的是它的可观察后果（执行者 `ExecutorFinished { Aborted }` + 错误结果照常落流、讨论不记 `SessionError`）。
- 「按 Esc 时合成器刚好已到 `[DONE]`」这条竞态窗口在实现里处理了（产物优先于迟到的手势），但没有确定性的测试手段。

**顺手的一处重构**：`process_call` 加上观察端后参数到了 8 个（clippy 上限 7），把回合内不变的五个值收进 `TurnContext` 一个值传入。
