# 33 — 问卷自定义答案里的空格被吃掉：有选项的题上空格一律当「确认」

Type: implement
Status: done
Blocked by: —

> *This was generated by AI during triage.*

## Agent Brief

**Category:** bug
**Summary:** 有选项的问卷题上，人在自定义答案栏里打空格会被当成「确认选项」——单选下还会翻页并清掉已经打进去的文本。

**Current behavior:**
一道**有选项**的问卷题，人在它的自由文本栏里打字（中文里夹几个英文词，比如 `llm wiki`），再按空格：这个键被当成「确认高亮选项」。单选问题因此**直接翻到下一题**，而且 `confirm_highlight` 会清掉自由文本 —— 那句话连同空格一起没了。多选问题不翻页，但同样不会插入空格，而是切换高亮选项。

**Desired behavior:**
空格只在**焦点不在自定义答案栏**时才当确认；焦点在文本框里时，它与任何别的可打印字符一样落进文本。

- 焦点在文本框（人已经在那道题上打过字，或点过「自定义」）：空格插入一个空格，不确认、不翻页、不动已输入的内容。
- 焦点不在文本框：行为**不变** —— 单选确认高亮并翻页，多选切换高亮选项。
- 没有选项的题：不变，空格本来就是普通字符。
- `Enter`、`Tab`、`←/→`、`↑/↓`、`Backspace` 一律不变。

**Key interfaces:**
- `Questionnaire::press(key)` 的分派 —— 现在 `Key::Char(' ')` 那一支只看「这道题有没有选项」，要它同时看「焦点是不是在自定义栏」。那个焦点已经作为问卷的状态存在、也已经被绘制读取，只是分派里没人读它，所以这里**不需要新状态**。
- 通用 `Key::Char(ch)` 那一支的行为（置焦点 + 插入字符）保持不动；空格应当落进它。
- 单选确认时清掉自由文本（自定义覆盖选择）是既有设计，**保留**。

**Acceptance criteria:**
- [ ] 一道有选项的题上，在自由文本栏打几个字再按空格：屏幕上仍是同一个问题、文本框里多了一个空格、已输入的字一个不少
- [ ] 同样一路答完并提交，答案里的自定义文本含那个空格（不是被某个选项替换掉）
- [ ] 一道有选项的题上**没**打过字时按空格：仍然确认高亮（单选前进、多选切换），与今天一致
- [ ] 一道没有选项的题上按空格：仍然只是普通字符，与今天一致
- [ ] 多选问题、已选过选项但焦点不在文本框时按空格：仍然切换高亮选项
- [ ] 新增测试钉住第一条与第三条（第三条是防「把空格改成永远不确认」的回归）
- [ ] `cargo test` 全绿、`cargo clippy --all-targets` 干净

**Out of scope:**
- 改问卷的键位表本身（票 32 定下的那一套一字不动）。
- 动 `Enter` 的既有分支 —— 它落地时已经为**同一类** bug 修过一次（「当前题已作答 ⇒ 只前进」），是对的。
- 弹窗之外的手感意向：`j`/`k` 选择、选项折行、多选下三键的分工 —— 那些挂在 `.scratch/questionnaire-keys/seed.md` 上，要单独访谈。
- 输入法：本票只管「中文文本里自己打的那个空格」，不管 IME 选字上屏。

## 现状（2026-10-02 核实，改前先复核）

- `Questionnaire::press`（`src/render/tui.rs:798-841`）里，`Key::Char(' ') if self.has_options()`（`:815`）排在通用 `Key::Char(ch)`（`:834`）**之前**，所以只要这道题有选项，空格永远走确认那一支：`confirm_highlight()`，单选再 `advance()`。它**不读**焦点。
- 焦点这个字段是存在的：`custom_focused` 在 `Questionnaire` 上（`:761`），打字置真（`:835`）、移动/选择/翻页置假（`:905`、`:912`、`:930`），点击自定义项置真（`:941`）、点选项置假（`:946`），并被 `draw_questionnaire` 读来切换那两行标签（`:3816`）。**分派里没人读它**。
- 单选清文本：`confirm_highlight`（`:852-874`）在非多选分支里 `draft.custom.clear()` —— 这是票 32 的设计（自定义文本覆盖选择），保留。
- **票 32 写过这件事**：它记录了 `Enter` 落地时发现同一个 bug 并修掉（「当前题已作答（已选或已输入）⇒ `Enter` 只前进」），紧接着把 `Space` 留在原地并写了一句理由 ——「『Space 确认』与『可打印字符进文本框』在空格上互斥，按题面『Space confirms it』优先」。本票推翻的正是后半句：互斥只在**没有焦点**的时候成立。
- **测试零覆盖**：`tests/ask_user_question_tui.rs` 与 `tests/ask_user_question.rs` 里 grep `空格` / `Space` 没有命中。
- 复现（triage 当时的临时测试，跑完已撤）：一道有选项的单选 + 打「你好」+ 空格 → 屏幕翻到第二题、页脚 `2 / 2`、自定义栏空。

## 来源与决定

- 2026-10-02 一次 `/triage`：维护者报告「用 `ask_user_question` 时，答案里输入空格就直接进入下一题」；场景是**中文答案里夹英文词**（`llm wiki` 这类），不是输入法选字。
- 维护者选定**方案 A**：空格的分派加一条「焦点不在自定义栏」的守卫。方案 B（按「本题是否已作答」判定，与 `Enter` 完全对称）被否 —— 它的差别在多选：已选过选项、人没在文本框里时，B 会让空格不再切换选择。
- 票 32 的那条决定由本票推翻，票 32 已加一条 Comments 指向这里，不做静默改写。
- 本票不新增 ADR：它是一次实现修正，不是难回头的决定。
