# grilling：多台 server 的启动与命名

Type: grilling
Status: resolved
Part of: ../map.md
Blocked by: —

## Question

同一台机器上配了多台 MCP server 时：

1. **启动**：会话开始时**并发**起（快，但一时间拉起好几个进程）还是**串行**起（慢，但一台失败
   不影响其余的）？某台起不来时，剩下的要不要继续起（冻结项 14 说「报错即可、不自动重连」，
   但没说启动阶段怎么办）？
2. **上限**：单会话最多连几台？（`task` 派执行者的并发上限是 5，那是成本与速率闸门、不是安全闸门。）
3. **重名**：配置里两台 server 同名 —— 是**启动错误**（早说早好，与 `deny_unknown_fields` 同一
   调性）还是后一台盖掉前一题？工具重名不存在：元工具方案下工具名拆成 `server` + `tool` 两个参数。

## Answer

**并发起，失败的跳过；不做数量上限；重名是启动错误。**

- **并发起**：会话开始时对配置里所有启用的 server 并发发连接（stdio 是 spawn、HTTP 是握手），
  每台各自一个超时（部署设置，照 `[web] fetch_timeout_ms` 那一类）。启动阶段的等待因此是
  「最慢的那一台」，而不是「所有台之和」。
- **谁失败就跳过谁**：其余照常起来，失败的那几台经 `mcp_list` 报成结构化错误 —— 与冻结项 14
  「报错即可、不自动重连」同一条线，只是它发生在启动阶段。
- **不做数量上限**：写进配置的 server 数量就是人要的，再加一道上限是给自用工具上枷锁；启动的并发
  成本由「并发 + 单台超时」自然兜住。
- **重名是启动错误**：两台 server 同名直接拒绝启动，消息里点名是哪个键 —— 照
  `deny_unknown_fields` 那条「配了等于没配，当场纠正比事后排查便宜」的调性。**不用「后盖前」**：
  那会让人以为两台都活着。
