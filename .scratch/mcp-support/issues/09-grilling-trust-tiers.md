# grilling：第三方 server 的信任分级

Type: grilling
Status: resolved
Part of: ../map.md
Blocked by: —

## 问题

冻结项 11 定了「结果算不可信外部数据、带中文标记」，冻结项 8 定了「外来工具默认最严（`Exclusive`）、
人在配置里逐条放宽」。剩下的是**信任的分级**：

- **统一按不可信处理**：所有 server 一视同仁 —— 结果都带标记、工具都默认最严。
- **允许逐台声明「这台可信」**：server 配置里加一位，声明后它的结果不带（或换一种）不可信标记、
  它的工具可以默认走较宽的 `Effect`。

要压的具体场景：**自己写的、跑在本机的那个 server**（比如一个包装了内部脚本的小服务）—— 它既不是
第三方代码、也不在远端。按「统一不可信」处理，会不会让人每次都被那句标记烦到？

如果允许逐台声明，那个声明是**一个布尔**（可信 / 不可信），还是**一组能力**（结果可信 / 工具可放宽 /
可不过沙箱）？

## 作答

**允许逐台声明，而且声明是一组能力，不是一个布尔。**

server 配置里加一段信任声明，三个位**各自默认关**：

1. **`trust_results`**：这台 server 的结果**不带**不可信标记（默认关 —— 不声明就是不可信）。
2. **`trust_effects`**：它的工具可以按配置声明较宽的 `Effect`（默认关 —— 不声明就是全 `Exclusive`）。
3. **不过沙箱**：一个**独立**的位（默认关）。冻结项 9 定了「过 bubblewrap」，要让某台不过沙箱就得
   单独声明它。

**为什么一组而不是一个布尔**：「这台是我们自己写的」不蕴含「它的结果可以当指令读」，也不蕴含
「它可以写任意路径」。捆成一个 `trusted = true` 会让人为了省一句标记，顺手把写权限一起放出去。
三个位各自默认关，与沙箱 fail-closed 的调性一致。

**它同时回答了那个场景**：自己写的本机 server 照样带标记、工具照样全 `Exclusive` —— 嫌烦就在配置里
把 `trust_results` 打开，那是一次**显式且局部**的声明，不是把整类 server 拉进可信圈。
