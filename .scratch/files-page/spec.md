# 文件页：左栏「文件」页签

Status: ready-for-walkthrough

- **来源**：维护者 2026-10-06 的要求 ——「实现一下左边栏的文件标签页」。核实下来它不是照
  spec 填空：`trace-tab/spec.md` 的「明确不做」与 `tui-visual-language` 票 07 的「接受的边界」
  都把「`文件` 页的内容」划给了另一个 effort，而 `tui.rs:3413` 那条注释还留着**另一套**语义
  （「这个会话碰过的文件」）。于是先走了一轮 charting（`.scratch/files-page/map.md`，22 问），
  再折成本 spec。
- **术语**：**左栏**、**页签**、**详情覆盖层**、**文本区域**、**选区**、**跟随**、**语义色板**、
  **字形语法**都照 [`CONTEXT.md`](../../CONTEXT.md)，不另立词。本 spec 新引入的两个说法是
  **文件页**（左栏 `文件` 那个页签画的东西）与**焦点行**（键盘交给这一页时高亮的那一行）。
- **来源票**：[grilling：文件页的形态与手势](issues/01-page-shape.md)（22 条决定）、
  [research：详情覆盖层与语法高亮的接线](issues/03-research-overlay-and-highlight.md)、

  见「补记」。

## 问题陈述

左栏页签条上的 `文件` 是最早就在的那三个页签之一，而它到今天只画一行占位：「此页尚未实现
（另有票在跟）」。同一栏的另外两页各回答一个具体问题（`调用量` 回答「花了多少」，`todo` 回答
「干到哪了」），只有它没有内容。它欠着的是三件事：

1. **工作区里有什么，看不见。** 会话级的 `FileIndex` 早就做好了（`input-tokens` 票 01），当初
   票面就写着「`@` 候选与**将来的文件页签**共用」—— 那个「将来」到现在没来。今天要知道工作区
   长什么样只有两条路：`@` 补全（你得先知道要找什么），或者切到 shell 里 `ls`。
2. **一个路径要搬进草稿，只能手抄。** `@` 补全解决了「知道名字」的场合，没解决「先看见、
   再拿过来」。
3. **看一个文件的内容得离开 TUI。** 模型读了什么、改了哪一行，屏幕上只有转录里那几行摘要；
   想自己看一眼那个文件，要切出去用编辑器。

## 方案

把 `文件` 页做成**一棵工作区文件树**，数据就是 `@` 候选那份索引（同一份快照），并配两件事：
鼠标点得开、键盘拿得到。

1. **一页树**：缩进 + 名字，目录可展开 / 收起，初始全部收起；同层目录在前。目录与文件只靠
   结构区分（缩进、折叠字形、尾斜杠），**不给色**。
2. **鼠标**：单击目录展开 / 收起，单击文件打开内容弹窗（就是既有的详情覆盖层：居中浮层、
   `Esc` 关掉）；滚轮悬在这一栏上时归这一页。
3. **键盘**：点左栏任意处把键盘交给这一页（焦点行 = 点的那一行），`↑` / `↓` 移行，
   `Enter` 把该行路径作为 `@路径` 插进草稿（目录带尾斜杠），`Esc` **只**还键盘 —— 不取消
   正在跑的回合。
4. **内容弹窗**：渲染器直接读盘 + 有界截断，带语法高亮与行号；**不进事件流、不进模型上下文**。
5. **索引**：共用那一份 `FileIndex`，重扫的触发点从「提交之后」扩到「任何**非只读**的工具调用
   之后」加「提交之后」—— 模型改完文件，这一页跟着变。

**shift + 点击明确不做**：主流终端在应用开启鼠标上报之后都把 shift 当成本地选择的 override 键，
带 shift 的左键事件到不了应用（而且终端会顺手启动一次原生选择）；`docs/render.md` 的「选区」
一节已经承诺「按住 shift 的终端原生选择照旧可用」，这条承诺不动。

## 实现决定

### §1 数据源

- 用会话级那份 `FileIndex`（`Idle | Loading | Ready`），**不新增遍历路径**：进 TUI 预热一次，
  之后按 §2 重扫。
- 这一页只**消费**它。要新增的只是查询接口（按某一层取子节点、判某条路径在不在），而遍历规则
  一个字不动：`.gitignore`、隐藏**文件**与 `.git/` 的挡法、`sort_by_file_path`、目录带尾斜杠。
- **树的同层顺序在渲染侧重排**（目录在前、同类型内保持索引给的字典序）。索引本身不动，所以
  `@` 候选仍是索引序 —— 两处顺序因此**有意不同**，这一点写在文档里。
- 展开状态活在 `TuiState` 里（一个路径集合），不落盘、不进事件流；一次重扫之后，不在索引里的
  路径直接丢掉。

### §2 重扫的触发

- 触发点是「任何**非只读**的工具调用之后」加「提交之后」。判据用既有的 `Effect`
  （`ReadOnly` / `WritePaths` / `Exclusive`，调度器与权限门共用的那套副作用词汇），**不维护
  工具名单**：只认 `write_file` / `edit_file` 会漏掉 `bash` 里的 `mv`、`mkdir`、`git checkout`。
- 事实（[findings](research/02-rescan-channel.md)）：`Tool::effect` 全仓库只在 `Registry::facts`
  被调用一次，它唯一的上游是循环里的 `process_call`；一次调用完成之后「工具名 / 结果 / effect」
  三者同时在手的也只有那里（收尾函数手里只剩 `exclusive` 这一个投影）。**所以触发点落在每次
  `process_call` 里。**
- 通道：`ConsoleRequest` 是唯一「循环→前端、静默、发完就完」的既有通道（`Muted` / `RunState`
  是先例）。今天「提交之后」是**前端置位、循环拉**（`submit()` 置位 → 循环问 `take_file_scan()`），
  新的触发沿相反方向推，两条最终都落到同一个位与同一次遍历上。
- **`/undo` 单独触发**：它不走工具派发（直接写盘加一条 `HistorySuperseded`），所以在它自己那条
  分支上补一次。
- **执行者与讨论者都算**：两者的调用落在同一条父流、同一个渲染器上，按判据都是触发点。
- 合并与不丢更新：`FileIndex::begin()` 那个守卫加 `file_scan_wanted` 那个位，把 N 次触发合并成
  一次，且补发的那次遍历晚于所有触发（最多延后一轮）。代价：`bash` 一律是 `Exclusive`（它不看
  里面到底干了什么），所以模型连跑几条 `bash` 会各触发一次，由守卫合并。
- 遍历仍跑在 `tokio::task::spawn_blocking` 的线程上，**不另起进程**。已知弱点照旧：一次永不返回
  的遍历会让这个位钉死（索引永远陈旧）—— 这是这个方案明码标价的代价。

### §3 树的排版

- 一行 = **缩进 + 名字**（目录带尾斜杠）。缩进每层 **2 列，不封顶**（28 列下四层也还剩 20 列
  给名字）。名字超宽时截断（具体口径见「补记」里那张 prototype 票）。
- **初始全部收起**。
- 折叠字形：收起态复用符号表里那个「有折起来的内容」（`▸`），展开态**新添**一个（`▾`）。两个都
  进符号表，语义按「这一行里有没有折着的东西」写，与 todo 页那个「进行中」的双义靠**区域**区分。
- **不给色**：目录与文件只靠结构（缩进、折叠字形、尾斜杠）区分。「过程退后、内容保持、
  信号着色」那条纪律不动。
- 焦点行要画得出来（键盘交给这一页时）—— 取哪一档（常驻选中 / 临时光标）见「补记」。

### §4 鼠标与指针

- 单击：目录 = 展开 / 收起，文件 = 开弹窗。
- 点击必须落在既有的**三段式**上（按下只记起点、拖动越过门槛才是拖选、抬起才算点击）——
  左栏页区今天已经是一块**文本区域**（`note_rows`），所以它本来就能被拖选复制；新增的点击动作
  不能把那条吃掉。
- 滚轮：在 `wheel_at` 现有的次序（详情覆盖层 → 问卷 / 模态 → 主列当前那一页）里，**在主列之前
  插一支左栏**：指针落在左栏页区内时归文件页。

### §5 键盘归属

- 新增一个键盘归属位：**键盘在左栏**。它与既有的两个「独占键盘的视图」（详情覆盖层、历史重放）
  同一族，只是不占满屏。
- **进入**：点左栏任意处（页签条与页区都算）。焦点行 = 点的那一行；那一下同时仍是展开 / 开弹窗。
  **归还**：`Esc`，以及 `Enter` 插入之后（接着就要打字）。
- 键位：`↑` / `↓` 移焦点行；`→` 展开（目录）或开弹窗（文件）；`←` 收起；`Enter` 插入 `@路径`；
  `Esc` 还键盘。**`Esc` 只还键盘，不取消回合** —— 一次手势一层，要取消就等键盘回去之后再按一下
  （那一下仍按既有的 busy / idle 分叉走）。
- 页签切换仍然只靠点，不给键位（`Tab` 归 `/` 菜单、`Shift+Tab` 归模式循环）。

### §6 内容弹窗

- 落在既有的**详情覆盖层**上：`DetailKind` 加一个变体。
- 事实（[findings](research/01-overlay-and-highlight.md)）：`detail_body` 是唯一的 switch，加变体
  是「定义 + match 加一支 + 一条新入口调 `open_detail`」三处。**两处既有假设必须一起处理**：
  1. `detail_opener` / `close_detail` / `draw_detail` 里有一处「**打开方恒为轨迹页**」的硬编码
     记账（冻结与还原都无条件给轨迹页）。文件页是第二个打开方，这套记账要么复用要么扩展。
  2. 正文的排版宽度今天用的是**框宽**，而实际文本区比它窄 4 列 —— 往每行前面加行号之前，这个
     口径要先对齐，否则行号本身也会被算错。
- **读法**：渲染器直接读盘（只读），**有界截断**：行数、字节、行宽都封顶；二进制只报一句。
  理由：权限门约束的是**模型**的读写，而这是人在自己的终端里点开自己的文件 —— 与 `@` 补全列出
  路径同一性质。
- 事实：**行数上限、字节上限、二进制检测这三件在渲染层都没有现成件**（`read_file` 那一套绑死在
  工具层，二进制检测全仓库只有 `grep` 工具里有），是新的活。渲染器手里有注入的 `cwd`，所以
  「按相对路径读工作区文件」不缺「工作区根从哪来」这个答案。
- **高亮**：复用既有的那一层（tree-sitter，与 markdown 代码块同一个源）。它以「整段源码 + 语言名」
  为输入、吐逐行的样式 span；语言今天只来自 markdown 围栏的 info string，**按扩展名挑语言的映射
  不存在**，要新写。
- **行号**：借既有的「先按 `\n` 拆逻辑行、再逐条折行」那个顺序，在折行**前**给逻辑行插前缀 ——
  折出来的续行自然不带行号。（块级那个前缀形状不对，那是给整个块只插第一条显示行的。）
- **不进事件流、不进模型上下文**（已核实：渲染层对文件系统的唯一调用是一次只读，不 emit 事件、
  手里没有 `Session`）。因此**打码那套不适用**（渲染器也拿不到打码器）。一条要顺手决定的：
  详情正文会进屏幕文本层、也就是**可以被拖选复制**的那一份，行号与截断提示要不要一起被复制。

### §7 与既有的撞点

- **`docs/render.md` 的「选区」一节**承诺「按住 shift 的终端原生选择照旧可用」—— shift 手势的
  否决正是守它，那条承诺一个字不改。
- **左栏的宽度两档与 `Ctrl-O` 意愿**（`sidebar-toggle/spec.md`）不动。
- **语义色板与字形语法**（`tui-visual-language/spec.md`）：新添的字形与取色进那两张表，不新起体系。
- **`docs/render.md`** 要写：左栏那一节（这一页是什么、焦点行的键盘归属、点击与滚轮的分派、
  滚轮在左栏与主列之间的次序）。
- **[`CONTEXT.md`](../../CONTEXT.md)**：**左栏**词条今天只是把 `调用量` / `todo` / `文件` 三个
  名字并列，要写上这一页到底是什么；另加一个新词条承接**文件页**与**焦点行**。
- **`docs/tui-manual-checklist.md`**：真终端要看的是 40 / 28 两档下树的密度、焦点行读不读得清、
  深路径的名字怎么截、弹窗的高亮与行号在真配色下的样子。

## 测试决定

- **一个 seam**：既有的 **TUI 帧测试层**（`TestBackend` 渲染整帧 + 「读屏幕」那套 helper，
  `TuiState::new(facts, cwd, home)` 在测试里直接构造）。**不新增 seam。** 这次改动的全部内容都是
  「同一帧里画出什么」加「一次输入之后草稿里是什么」，而这一层已经在钉页签、todo 页、索引重扫与
  详情覆盖层。
- **prior art**：`tests/render_layout.rs` 的页签组（`tab_cell` / `click_in_row`）、todo 页那几组、
  `the_file_index_is_warmed_once_and_rescanned_after_a_submission`、详情覆盖层的点击与滚动几组、
  `tests/history_replay.rs` 的详情相关断言、`tests/todo.rs` 的侧栏断言。
- **断言对象是外部行为**：屏幕上画出来的行、点击 / 滚轮 / 按键之后的帧、`Enter` 之后草稿里那一段
  文本、索引重扫的次数与时机。**不断言** pane 的内部字段，不为「树节点怎么存」写白盒测试。
- **纯函数层的小单测**：展开 / 收起之后的行序与缩进、名字截断、同层排序（目录在前）、按扩展名定
  语言、二进制判据、有界截断的三个上限。
- **两档宽度（40 / 28）各要有排版断言**；窄档是这一页最容易读不下去的地方。

## 明确不做

- **「这个会话碰过的文件」那套语义**：那是 `tui.rs:3413` 那条旧注释的想法。要找「这一场改过
  哪些文件」，既有出路是 `sessions show --files`。
- **过滤 / 模糊查找**：`@` 补全已经承担「知道要找什么」的场合，这一页只回答「工作区长什么样」。
- **给页签加键位**：页签仍是点出来的。
- **`FileIndex` 的遍历规则**：忽略规则、字典序、目录带尾斜杠都是 `input-tokens` 的契约。
- **独立进程去重扫**：进程模型在这个尺度上买不到东西，而它要重想一整套 IPC、生命周期与沙箱边界。
- **shift + 点击**：终端会吞掉它（见「方案」末段）。
- **模型可见的一切**：这一页与它的弹窗都不进 `messages`、不进事件流、不打码。
- **在 TUI 里编辑文件、或把文件递给外部编辑器**：这一页只读。
- **文件页与转录的联动**（比如从弹窗跳到引用这个文件的回合）：仍走回合条与轨迹视图。

## 补记

- **`02` 那张 prototype 票仍然开着**（`ready-for-human`）：40 / 28 两档下的帧草图还没做 ——
  密度（一屏几行）、焦点行取哪一档（`ACCENT` + `BOLD` 的常驻选中，还是 `REVERSED` 的临时光标）、
  折叠字形的最终字形、名字与弹窗里行号的列宽口径、加载与空态那两句文案。本 spec 在这几处给的是
  **可调的推荐值**，帧草图做完之后按它校正 —— 那几处不构成「还要再决定什么」，只是要挑一个数。
- **两处既有落差要在实现时处理**（[findings](research/01-overlay-and-highlight.md) 记着证据）：
  详情正文的排版宽度口径（框宽 vs 文本区），以及「打开方恒为轨迹页」的记账。它们不是这次引入
  的，但这次会踩到。
- **键盘的 `→` / `←` 是这份 spec 补的**：来源票只定了 `↑` / `↓` / `Enter` / `Esc`，而目录没有
  键盘展收就说不通。
- **同层排序是这次唯一一处与索引顺序有意分家**：树要目录在前，而 `@` 候选与 `grep` 都按索引序。
  两处都写在文档里，免得后来者以为是漏改。
- **为什么弹窗由渲染器直接读盘**：这个弹窗不进流、不进上下文，所以「流上的文本 == 模型看到的
  文本」那条打码纪律在这里没有对象；而权限门约束的是模型的读写，不是人在自己终端里点开自己的
  文件。代价是有界截断那三件限额要自己写（渲染层没有现成件）。
