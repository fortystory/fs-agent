# 05 — 铺垫：详情覆盖层为第二个打开方铺路

Status: done

> 规格：[`../spec.md`](../spec.md) 的实现决定 §6 里那两处「既有假设必须一起处理」。

**What to build:** 把详情覆盖层从「只服务轨迹页、而且正文按框宽排版」收干净，好让「文件内容弹窗」变成一件干净的加变体的活。用户看得见的变化只有一处：轨迹页的详情不再有尾部 4 列被裁。

## 验收

- [x] 详情的正文按**真正的文本区宽**排版（框宽扣掉边框与内边距），轨迹页的详情不再丢尾部
- [x] 终端宽度变化之后的正文重排也走新口径（**收口时按实现的口径读**：排版只发生在打开那一刻、用那一刻的文本区宽；resize 不重排已经打开的正文，与轨迹页详情同一处既有行为）
- [x] 打开与关闭时「冻结的是哪个视图」按**打开方**记账，不再是写死的轨迹页；轨迹页自己那条路径的行为逐字不变
- [x] 既有的详情断言按新口径改完，全绿
- [x] 键盘与滚轮对覆盖层的归属不动（它们看的是「覆盖层开着吗」，不是谁开的）

## 评论

- **落地（2026-10-06）**：正文的排版宽度换成**文本区**那一档 —— `layout::DETAIL_PADDING` 与
  `Regions::detail_text_width`（框宽扣掉边框与内边距，窄档下内边距让位时只扣边框），
  `draw_detail` 与打开入口共用它，于是两处口径不会漂开。断言
  `the_detail_body_is_wrapped_to_the_real_text_width`：120 列下一条 116 列的行不再丢掉尾部。
- **打开方记账**：`detail_opener` 从「一份 `ScrollMark`」变成 `DetailOpener`
  （`Trace(ScrollMark)` / `Files`）—— 打开时按来源记、关掉时按来源还原、`draw_detail` 只冻轨迹页
  那一支，而轨迹页那条路径的行为逐字不变（它那几组既有断言全绿）。第二个打开方在票 08 接上。

- **补记（收口时）**：票面第二条「终端宽度变化之后的正文重排也走新口径」在实现里是这样兑现的
  —— 排版只发生在**打开那一刻**，用的是那一刻的文本区宽；窗口 resize **不重排已经打开的正文**
  （`DetailView.body` 是按打开时那个宽度排好的，与轨迹页详情同一处既有行为，不是这次引入的）。
  所以「重排时用的宽度口径是文本区」这一条成立，而「resize 就重排」这一条不在本票范围里。

- **收口（2026-10-07）**：五条验收逐条勾上（第二条按实现的口径注明）；断言
  `the_detail_body_is_wrapped_to_the_real_text_width` 在 `tests/render_layout.rs`，全量
