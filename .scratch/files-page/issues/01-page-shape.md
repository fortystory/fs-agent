## 问题

左栏页签条上的 `文件` 页到今天只画一行占位（`wording::tab_placeholder()`）。它该画什么？
`FileIndex`（[`input-tokens` 票 01](../input-tokens/issues/01-file-index.md)）当初就是为它做的，
而 `tui.rs:3413` 还留着**另一套**语义（「这个会话碰过的文件」）。除了「列什么」，还有一串悬着
的事：怎么排、鼠标与键盘各做什么、点开一个文件能看多深、那份索引什么时候重扫。

## 作答

### A. 页与范围

1. **终点是「先定清再实现」**：本图折成 spec，再由实现票落地 —— 与仓库里其它 feature 同一个走法。
2. **页内容 = 工作区文件索引**（与 `@` 同源），**不是**「这个会话碰过的文件」。理由：数据源已经
   做好、当初就是为这一页埋的；而「这一场改过哪些文件」既有的出路是 `sessions show --files`，
   语义也更贴轨迹视图。**被否决**：会话碰过的文件（`tui.rs:3413` 那条旧注释）。
3. **数据源共用那一份 `FileIndex`**：进 TUI 预热一次、每次提交后重扫一次，就是
   [`input-tokens`](../input-tokens/spec.md) 定下的那条节奏；不另起第二条遍历 —— 仓库里
   「什么算工作区文件」只该有一个答案。代价明说：这一页与 `@` 候选永远是同一份快照。

### B. 树的形态

4. **形态是一棵树**：点目录就在原行展开 / 收起它的子节点。**这推翻了 charting 中途的一个答案**
   （那一轮选的是「平铺全路径 + 超宽从头部截断」），以树为准。
5. **一行画什么：缩进 + 名字**（`▸ render/`，它下面一层是 `  tui.rs`）—— 不写全路径。树的全部
   意义就是「路径由位置表达」，省下来的列全给名字。代价：同名文件（两处都有 `tui.rs`）只能靠
   位置分辨。
6. **初始全部收起**：一打开看到的是工作区顶层，逐个点开。重扫之后不在索引里的展开路径直接丢掉。
7. **缩进每层 2 列，不封顶**：28 列档下四层也还剩 20 列给名字。
8. **同层排序：目录在前，同类型内按字典序**。**这偏离索引给的顺序** —— `scan` 的
   `sort_by_file_path` 是纯路径序（`README.md` 会排在 `src/` 前面）；树的同层重排一次，而 `@`
   候选仍是索引序。
9. **不给色**：目录与文件的区分全靠结构（缩进、折叠字形、尾斜杠），守住「过程退后、内容保持、
   信号着色」那条既有纪律。

### C. 鼠标与键盘

10. **单击目录 = 展开 / 收起；单击文件 = 打开内容弹窗。**
11. **shift + 点击插入 `@路径` 被否决** —— 这是一条硬事实，不是偏好。主流终端（xterm、
    VTE / GNOME Terminal、Konsole、kitty、WezTerm、Alacritty、Windows Terminal）在应用开启鼠标
    上报之后都把 shift 留作**本地选择的 override 键**，带 shift 的左键事件根本不会发给应用
    （xterm 的 `shiftEscape`、WezTerm 的 `bypass_mouse_reporting_modifiers = "SHIFT"`、VTE 源码里的
    `start_selecting`）；它还不静默 —— 终端会顺手启动一次原生选择。crossterm 0.29 的
    `MouseEvent::modifiers` 读得到也没用，因为事件不来。**它还与本仓库已有的承诺正面冲突**：
    [`docs/render.md`](../../docs/render.md) 的「选区」一节写着「按住 shift 的终端原生选择照旧
    可用」。
12. **插入改走键盘**：`↑` / `↓` 移行，`Enter` 把该行的路径作为 `@路径` 插进草稿（目录带尾斜杠，
    与索引里那个拼法一致）。键盘是唯一完全绕开终端鼠标语义的选择，而且与「滚轮看、键盘选」天然
    分工。
13. **键盘的进出**：**点左栏任意处**就把键盘交给这一页（焦点行 = 点的那一行，那一下同时仍是
    展开 / 开弹窗）；`Esc` 还回去；`Enter` 插入之后也自动还回去（接着就要打字）。这与既有的
    「独占键盘的视图」（详情覆盖层、历史重放）是同一族，只是不占满屏。**代价**：焦点行必须画得
    出来（高亮），所以 charting 中途那条「无状态、不做 hover 高亮」要让一步 —— 让掉的只是
    「页里记一个当前行」，不是「页里留一串选中痕迹」。
14. **`Esc` 只还键盘，不取消回合**：一次手势一层。要取消（那是掐断正在跑的 provider 调用与
    工具）就等键盘回去之后再按一下 —— 与仓库那把「先举手、再真做」的手感同一套。
15. **滚轮悬在左栏上时归这一页**：照覆盖层与问卷已经在用的「指针在哪就归哪」分派，不发明新规矩；
    键盘不掺合滚动，所以「页签从不给键位」那条界线不动。
16. **不做过滤**：这一页回答「工作区长什么样」，`@` 回答「我要那一个」。合在一处会让这一页多出
    一个输入态（与输入区抢键盘）与一套「过滤时还算不算树」的降级。

### D. 内容弹窗

17. **渲染器直接读盘 + 有界截断**：行数、字节、行宽都封顶，二进制只报一句。理由：权限门约束的
    是**模型**的读写，而这是人在自己的终端里点开自己的文件 —— 与 `@` 补全列出路径同一性质。而且
    这个弹窗**不进事件流、不进模型上下文**，所以「流上的文本 == 模型看到的文本」那条打码纪律
    不适用。**被否决**：走 `read_file` 工具那条路（重，而且那是给模型的工具）。
18. **语法高亮：要**（按扩展名走既有的那一层，与 markdown 代码块同一个源）。点开 `tui.rs` 看到
    一整块不着色的原文，会让这一页读起来像二等公民。
19. **行号：要。**
20. 弹窗落在既有的**详情覆盖层**上（居中浮层、`Esc` 关掉那套）。

### E. 重扫

21. **触发点是「任何非只读的工具调用之后」加「提交之后」**。判据用现成的 `Effect`
    （`src/tools/tool.rs:24` 的 `ReadOnly | WritePaths | Exclusive`，调度器与权限门共用的那套副作用
    词汇），不维护一张工具名单。**被否决**：只认 `write_file` / `edit_file` —— 那会漏掉 `bash` 里的
    `mv`、`mkdir`、`git checkout`。`/undo` 回滚也算。代价：`bash` 一律是 `Exclusive`（它**不看**
    里面到底干了什么），所以模型连跑几条 `bash` 会各触发一次重扫 —— `FileIndex::begin()` 那个
    守卫会把在飞的那一次合并掉。
22. **进程模型：保持 `spawn_blocking` 的线程，不另起进程**。它已经在渲染循环之外
    （[`input-tokens` 票 01](../input-tokens/issues/01-file-index.md) 的验收就是「键盘与绘制从不被它
    挡住」），而进程隔离能挡的那类风险（内存、崩溃、权限）在这里本来就不在。独立进程要重想一整套：
    结果怎么回来、进程何时回收、退出与 `--continue` 时怎么收尾、过不过沙箱、拿哪些环境变量 ——
    仓库里 MCP server 那一层就是为这些才那么厚。**已知弱点**：一个永不返回的遍历（网络文件系统上
    某条 `stat` 挂住）会让 `Loading` 卡住，之后的重扫都被守卫吃掉、索引永远陈旧；独立进程加超时
    能治它，但那是另一个量级的复杂度。

## 给下游 / spec 的落点

- **`src/render/tui.rs`**：`draw_sidebar_page` 里 `Tab::Files` 那一支换成真的一页；鼠标分派里
  左栏页区要有命中（今天只有页签条的 `HitAction::SwitchTab`）；键盘分派要在「详情覆盖层 / 历史
  重放」那一族旁边加一位「键盘在左栏」；`wheel_at` 的次序要在主列之前插一支左栏。
- **`src/render/file_index.rs`**：只加消费方要的接口（按层取子节点、按路径判在不在），遍历规则
  一个字不动。
- **`src/render/wording.rs`**：折叠字形（展开态是新的，收起态复用符号表里那个「有折起来的内容」）、
  加载与空态、弹窗的标题与截断提示、焦点行相关的话。
- **[`CONTEXT.md`](../../CONTEXT.md)**：**左栏**词条要写上这一页到底是什么（今天只是把
  `调用量` / `todo` / `文件` 三个名字并列）；可能还要一个新词条承接「文件页 / 文件树」这个概念。
- **[`docs/render.md`](../../docs/render.md)**：左栏那一节。
- **[`docs/tui-manual-checklist.md`](../../docs/tui-manual-checklist.md)**：真终端里要看的是 40 / 28
  两档下树的密度、焦点行读不读得清、深路径的名字怎么截、弹窗的高亮与行号在真配色下的样子。
- **测试**：走既有的 TUI 帧测试那一层（`TestBackend` + 「画一帧、读屏幕」），不新增 seam；树的
  展开与收起、焦点行、插入、弹窗、两档宽度各要有断言。
