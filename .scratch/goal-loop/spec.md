# 目标：跨会话的无人值守工作单元

给 fs-agent 一个**目标**（一份具名的清单文件），它就用 `/loop` 连续工作：上下文过半时收到提醒、过八成时压缩并开一个新会话接着干，直到清单上的条目全部完成 —— 然后出一份汇总，回到空闲等人。会话、条目状态与预算都围绕这个目标组织。

来源：2026-10-01 的一轮 grilling（Q1–Q30）。种子材料在 [`seed.md`](seed.md)（本文件把它折成构建计划，14 条分叉的关闭记录也在那里）。它吞并了 `loop-and-goals`、`clear-command`、`context-compaction` 三条老种子，那三条只留指向 [`seed.md`](seed.md) 的记录。

## 问题陈述

**fs-agent 今天只能一段一段地干，而且必须有人守着。** 三个具体缺口：

- **没有跨会话的工作单位。** `todo` 是会话级的：[`src/tools/todo.rs`](../../src/tools/todo.rs) 的列表活在那条 `tool_call` 的 args 里 —— `--continue` 能把它带回来，但**新会话是空的**。而真实的活通常跨几天、几十个会话。
- **两个时间尺度挤在一个工具上。** 短的是「这次会话打算做什么」，长的是「这件事要做到什么程度」。今天只有前者，于是「我做到哪了」这个问题没有承载物。
- **没人看着就跑不下去。** 窗口靠 [`context::trim`](../../src/context.rs) **静默丢弃**旧内容满足，它**不产生任何事件**，所以今天没有「快满了」这个信号（`src/context.rs` 那个「真的溢出」是最后一道，不是提醒）。而权限门在 `ask` 档下第一次写就停下来等人 —— 无人值守在默认档位下是空话。

结果是：长活必须有人守着，每隔一阵回一句「继续」。

## 方案

- **目标** = 一份具名的清单文件：`~/.local/share/fs-agent/goals/<名字>.md`，**只有条目与 id，不带状态**。
- **`/goal-new <名字> <来源>…`** 从一批票生成它，一次性；此后清单独立，票再变也不跟。
- **进度从流派生**：`todo` 项加一个可选 `id` 引用清单条目，条目状态由各会话的 `todo` 重算（`todo` 是 `ReadOnly`，从不触发权限门）。
- **归属是一条事件**：`GoalSelected`；**当前目标 = 流上最后一条**，所以切换天然支持。
- **`/loop <名字>`** 选定目标并连续工作：过 50% 注入一次提醒，过 80% 压缩 + 开新会话；**预算认到目标上**；连续无进展就停下报告。
- **无人值守有前提**：权限档不低于 `workspace`，否则拒绝启动。
- **收尾落流**：完成汇总与失败收尾各一条事件；执行中冒出来的新工作由 `goal_note` 记，**args 即真相**。
- **`/clear`** 结束当前会话、开一个新的（名字保持），旧的留在磁盘上。

## 用户故事

1. 作为用户，我想给 fs-agent 一个目标就不再管它，回来时看到「做完了什么、还有什么冒出来」。
2. 作为用户，我想在走开**之前**就知道它不会卡在权限询问上 —— 不该跑的组合直接拒绝启动，而不是跑到一半停住。
3. 作为用户，我想让长目标跨过上下文上限继续跑（压缩、开新会话、带着摘要与进度过去），而不是半路停下等我。
4. 作为用户，我想让目标定义是一份**我能读、能改**的文件，而不是藏在某个数据库或状态文件里。
5. 作为用户，我想让 `--continue` 开回最新的会话；**崩溃**后自动接着跑，但我**主动停掉**的回来别自己又跑起来。
6. 作为用户，我想让误按 `Esc` 不会掐掉一个已经跑了两小时的目标。
7. 作为用户，我想让目标卡住时它**自己停下来报告**（连续的翻页一条都没完成），而不是烧一晚上钱。
8. 作为模型，我想在上下文过半时收到一句提醒，好把还没落流的东西落下来 —— 因为再过一会儿历史就会被压成摘要。
9. 作为模型，我想用 `todo` 按 `id` 引用清单条目，好让「哪条做完了」是确定的，而不是靠文本对得上。
10. 作为模型，我想有一个 `goal_note` 把执行中冒出来的新工作记下来，而不必去改那份封了口的清单。
11. 作为审计者，我想在流上看到目标选定、完成汇总与失败收尾，以便回头核对某一次无人值守到底干了什么。

## 实现决定

### §1 目标与清单文件

- **清单文件**：`~/.local/share/fs-agent/goals/<名字>.md`（`<名字>` 就是 `/loop` 的参数），人可读的 markdown。状态派生自流，所以它**只读**，沙箱不是约束。
- **内容只有条目与 id，不带状态**。条目带一个**稳定 id**，格式 `- <id> <内容>`（id 形如 `01`，生成时分配、此后不动）。**不画复选框**：状态只有流一个真相源，文件里画一个会让人误以为它才是进度，而它其实只是开工前那份快照。
- **清单开工前封闭**：执行中不能往目标里加条目。于是「完成」有稳定判据；执行中发现的新工作**另开一个目标**，或由 `goal_note` 记下（§11）。
- **完成的判据是机械的**：**所有条目都 `completed` 就算目标完成**，循环自己判，不需要人点头 —— 与「不需要人再参与即可完成的工作」那句自洽。注意它的信任假设：`completed` 是**模型自己填的**，所以判据机械**不等于**结果可靠。

### §2 `/goal-new`：从票生成清单

- **`/goal-new <名字> <来源>…`**：来源**显式给出**，不猜、不扫全仓库。
- **来源可以是一个或多个**（空格分开）：一个目标可以是「一个 feature」，也可以是「几个需求合起来
  一起做」。多个来源时，条目按**来源顺序**排、来源内部按票号升序，而 id 与内容要跟着变：
  - **一个来源**：id 就是票号（`03-foo.md` → `03`），内容就是票的标题。
  - **多个来源**：票号在来源之间必然撞号（每个 `issues/` 都有 `01`），所以 id 按最终顺序重新分配
    `01..`；内容前面带凭证 `<来源目录名>/<票号> <标题>`，否则模型读到一条标题也不知道去哪张票上
    找它（`.scratch/<来源目录名>/issues/<票号>-*.md`）。
- **命令名用连字符写成一条**：`/goal-new`，将来这一族的 `/goal-list` / `/goal-show` / `/goal-rm`
  照走。理由是补全：`/` 菜单按命令名的前缀过滤，而空格形状的子命令（`/goal new` 里的 `new`）是
  第二个词、补不出来；连字符形状下 `/goal-` 一个前缀就能把这一族全列出来（实现时定的，见
  「实现注记」）。
- **生成一次**：此后清单**独立** —— 票再变也不跟。清单一旦生成就是目标定义的唯一真相源。
- **重名一律拒绝**，除非加 `--force`：默默覆盖会抹掉一份已生成的定义。
- 生成器读票（`.scratch/<feature>/issues/NN-*.md` 那类），把票的标题与编号落成条目与 id。**它只读**，不写回票。
- **`/goal` 本轮只做 `new`**：`list` / `show` / `rm` 都不做 —— 清单就在磁盘上，人自己 `ls` / `cat` 就行。

### §3 条目身份与状态派生

- **`todo` 项加一个可选 `id` 字段**（[`src/tools/todo.rs`](../../src/tools/todo.rs)）：它引用清单条目的稳定 id。这是「机械判定」的前提 —— 靠 `content` 文本对应会漂，而且那样判定就不是真机械。
- **代价要认**：`todo` 当初的设计理由是「参数是唯一真相源、零 schema 改动」。加一个**可选**字段不破坏那条（老流仍能反序列化、老调用照常解析），但 schema 确实动了，`SCHEMA_VERSION` 要不要涨在这一票里定。
- **条目状态 = 各会话 `todo` 调用的合并**：按 id 取**最新**状态；会话 1 标过 `completed`、会话 2 的 `todo` 里没有它，**仍算 completed**（这正是「一个目标跨几个会话」要保住的信息）。
- **id 越界是模型可读的工具错误**（引用了清单里不存在的 id），与 `todo` 既有的严格解析同一形状。

### §4 归属与 `/loop` 的启动

- **归属是一条事件**：`GoalSelected { goal }` 之类。**不动 `SessionStarted`** —— 只追加一条更省，而且「切换目标」天然就是再记一条，于是**当前目标 = 流上最后一条**（与 `todo` 同一条派生纪律，`--continue` 后自然重建）。
- **一个会话可以在一个目标完成后接着做另一个**：再 `/loop <另一个名字>` 就是再记一条。
- **`/loop <名字>`**：选定目标并开跑。
- **启动边界三种都明确拒绝**（各说各的人话，不做意外的事）：
  - 名字不存在（清单文件找不到）→ 说找不到，提示先 `/goal-new`；
  - 目标已全部完成 → 说没活可干；
  - 已经有一个 loop 在跑 → 说正在跑。
- **找全一个目标的 N 个会话，按归属筛**：扫本桶、按 `GoalSelected` 过滤。`--continue` 只开最新的那个，所以「这个目标的全部会话」不能靠它。

### §5 无人值守的前提

- **`/loop` 要求权限档不低于 `workspace`**，否则**拒绝启动**并说明原因。`readonly` / `ask` 档下第一次写就停在等人 —— 那时「无人值守」是空话。模式是会话的一个值、不进事件流，所以 `--continue` 回到配置里那一档。
- **运行期间输入区禁用**：不能打字插话 —— 那是 [`interjection-flow`](../interjection-flow/seed.md) 那条种子的事。要停按 `Esc`。
- **`Esc` 之后弹一个确认框，默认停在「继续跑」**，要停得明确选。误按一下不该掐掉一个长任务。
- **确认框是渲染器的确认框**（与权限询问同一条中段覆盖层通道，但发起者是渲染器自己），不是模型发起的提问。

### §6 阈值与提醒

- **两个阈值做成配置项**（`[goals] remind_at` / `compact_at` 之类），**默认 50 / 80**。分母是**窗口**（[`context::usable_input`](../../src/context.rs)，也就是状态行那个百分比），**不是预算**。
- **过 50%：向模型注入一次提醒**。措辞是「**把还没落流的东西落下来**」—— 不是「你该收敛了」。因为再过一会儿历史会被压成摘要，而摘要只能留住它读得到的东西：模型只在脑子里、没写进 `todo`、没写成结论的推理会丢。这条提醒就是给它一次**自救**的机会。
- **跨过阈值时注入一次，不是每轮**：每轮注入会每轮打掉前缀缓存，而本仓库有「前缀只增不改」的不变量。
- **过 80%：压缩 + 翻页**（§7）。
- 今天的窗口靠**静默丢弃**满足、不产生任何事件，所以「快满了」这个信号要新造 —— 判据取投影前的估算（`context::estimate_messages_tokens`），在回合边界比对。

### §7 压缩与翻页

- **压缩与翻页是一个内部动作，总是成对发生**：80% → 压缩 → 开新会话。不做「压缩后看空间够不够再决定翻不翻」那条分支 —— 少一条路径、少一种状态要测。
- **压缩**：把当前历史折成摘要，落成既有的 [`HistorySuperseded { targets, reason: Compaction, summary }`](../../src/events.rs)（形状早已钉死在 schema 里，`summary` 字段都在）。摘要用**一次模型调用**生成，那次调用**照记 `UsageRecorded`** —— 它就是一次 provider 调用，所以自然落进目标预算（§8），无人值守时的花费不会被低估。
- **翻页（rollover）**：收掉当前会话 → 组装一个新的（同一进程、同一渲染器与终端）→ 把摘要**注入**新会话 → 继续。`/clear`（§12）与这里的翻页是**同一个动作的两个入口** —— **两段入口、一段机制**，spec 要钉死这一点，否则会长出两套「开新会话」的语义。
- **摘要走 [`ContextInjected`](../../src/events.rs) + 一个**新的 `ContextSource` 变体**（`Compaction` / `GoalHandoff` 之类），与技能注入、人物注入同形状：进流、可重放，`--continue` 后还在。
- **压缩与翻页都是循环的动作，不是模型的工具**：模型不「调用」`/clear`，也没有那个能力（`/clear` 只是给键盘的入口，`Submission` 那一侧）。模型在这一侧只有 §6 那条提醒。
  - 顺带避开一个分类缺口：[`Effect`](../../src/tools/tool.rs) 三类全是**工作区**副作用，装不下「开新会话」；不给模型工具，这个缺口就不必现在处理。
- 翻页只能发生在**回合边界**（不能在 `tool_call` 还挂着结果的时候）。

### §8 预算认到目标上

- **预算的求和范围是「这个目标横跨的所有会话」，不是单个会话**。现状 [`Budget`](../../src/config/cost.rs) 是**会话级**、花费从本会话事件流求和 —— 翻页开新会话会重新获得一整份额度，那就是**每翻一次页多一份预算**，无人值守会变成无人看管地烧钱。这是要修的那个口子。
- **跨会话累计照样是派生的**，有现成先例：日账本扫会话文件按 UTC 日聚合、**不新增状态文件**（见 [`CONTEXT.md`](../../CONTEXT.md) 的**日账本**条）。目标预算走同一条路 —— 按归属筛出这个目标的会话，把它们的 `UsageRecorded` 加起来。
- 撞顶时沿用既有语义：**降级收尾，而不是中断**。

### §9 无进展与停止

- **停止条件**：目标完成（§1）或 **provider 调用失败**（要有重试逻辑：重试若干次、耗尽后停下并写一条收尾事件）。
- **「连续无进展」的判据**：**连续 N 次翻页零条目完成**（N 做成配置项）→ **停下并报告**。它和完成判据同源，所以是机械可算的。
- 这条是给「总是相似的那几条在循环跑」那类失败准备的 —— 没有它，一个卡住的目标会一直翻页重试到烧完预算。

### §10 崩溃恢复与主动停

- **崩溃**（进程异常终止、机器重启）之后 `--continue` 回去，**自动接着跑**，不必人点头。风险是「同一个条目把进程反复弄崩」，由 §9 的无进展判据兜住。
- **人主动停**（`Esc` + 确认）之后 `--continue` 回去，**不自动接**：主动停是人的意思，该尊重它。
- 所以恢复时要能**区分两者**：正常收尾（完成 / 主动停）落过收尾事件，异常中断没有。

### §11 `goal_note` 与收尾

- **`goal_note`**：一个像 `todo` 那样的新工具，给模型记「执行中冒出来的新工作」。`effect()` 是 `ReadOnly` —— 它不碰工作区（`todo` 的先例：正因为不碰工作区，权限门从不为它发问），所以两次调用可以并发、无人值守时不会停下来等人。
- **它的真相源是那条 `tool_call` 的参数**，与 `todo` **完全同构**：零 schema 改动、`sessions replay` 可重算、`--continue` 后自然重建。**不为它新增事件**。
- **完成汇总与失败收尾各落一条新事件**（它们不是工具调用的产物，没有 args 可依）。
- **汇总说明包含**：目标名、条目完成情况、**跨了几个会话**、以及**执行中冒出来但没进清单的新工作** —— 清单是封闭的，新工作只能在这里交代，所以这一项最不能省。
- **完成后不退出**：出一条汇总、落流，然后回到空闲态待着（提示符停在静止色、pulse 归零 —— 现在空闲时本来就是这个样子）。

### §12 `/clear`

- **`/clear` = 结束当前会话、开一个新的**（进程不重启，渲染器与终端留着）。**不是**「清空上下文继续用」—— 那条老种子的措辞要改。
- **名字保持 `/clear`**：与 DSH、Claude Code 的手势一致，肌肉记忆在。
- 旧会话**留在磁盘上**，仍能被 `--continue` / `sessions` 找回；`--continue` 打开**最新的**那个。
- 它和 §7 的翻页是**同一个 rollover 动作的两个入口**：一个由键盘触发，一个由阈值触发。

### §13 `/` 补全

- 内建命令现在有 `/quit` `/exit` `/undo` `/discuss` `/clear` `/loop` `/goal-new`（[`src/cli.rs`](../../src/cli.rs) 那张 `Submission` 表），加上技能回退。
- **补全里内建命令在前、技能在后；同前缀时命令优先**：命令是固定的、技能是用户装的，固定项优先更可预测。
- **一族命令写成一条连字符命令**（§2）：于是 `/goal-` 这个前缀在菜单里列出整族，而空格形状的
  子命令补不出来。

### §14 文档与决定记录

- 逐面文档：新增 `docs/goals.md`（或把 `/loop`、目标、翻页写进既有那篇），并在 [`README.md`](../../README.md) 的「文档」表登记。
- [`CONTEXT.md`](../../CONTEXT.md) 要立词条：**目标**（跨会话的工作单元；注一句别和**落点**那条 `_Avoid_` 里的「路由目标」混）、**翻页**（rollover）、**`goal_note`**，并更新**待办列表**那条（加 id、跨会话派生）。
- 手艺记录：`.scratch/goal-loop/` 保持「seed 是来源、spec 是计划」的分工；`loop-and-goals` / `clear-command` / `context-compaction` 三条只留指向这里的记录。

## 测试决定

同既有约定：断言的对象是**事件流**（JSONL 里的 `seq` + payload）与**工作区副作用**，不是内部结构；不断言 `at` 时间戳；provider 全部是假 provider。

**单元**

- 清单解析：条目与 id 读得出、读不出的读成**空**（绝不半份、绝不 panic），与 `todo::read_items` 同一形状。
- `todo` 项的 `id`：合法引用、越界 id 是模型可读的错误、缺省 `id`（老调用）仍能解析。
- 「所有条目 `completed`」的判定，含「会话 1 标过、会话 2 没提」那条**合并**规则。
- 无进展计数器与阈值判定（50 / 80 的边界值）。

**e2e（组装入口 + 假 provider）**

- **一个目标跨两个会话跑完**：会话 A 完成一部分 → 阈值触发 rollover → 会话 B 接着干并完成。断言流上按序有 `GoalSelected`、`HistorySuperseded { reason: Compaction }`、完成事件，且 `sessions replay` 重算出的进度与会话里的 `todo` 一致。
- **`/loop` 的启动边界**：`ask` 档被拒；`workspace` 档启动；名字不存在 / 已完成 / 已在跑三种各自拒绝。
- **无进展**：连续 N 次 rollover 零完成 → 停下 + 一条收尾事件，且不再继续翻页。
- **恢复的两条路**：造一个「loop 中途异常断掉」的流，`--continue` 后自动接着跑；造一个「人主动停」的流，`--continue` 后回空闲态。
- **预算跨会话**：两个会话的 `UsageRecorded` 累加，撞顶降级收尾；翻页不重置。
- **`goal_note`**：合法调用回执与 args 形状；`effect() == ReadOnly`；主会话与执行者的表里都有它、headless 也有；断言流上那条 `tool_call` 有且只有一条结果，且**汇总读到的是 args 里的 note**。

**TUI 手工**（进 [`docs/tui-manual-checklist.md`](../../docs/tui-manual-checklist.md)）

- `/loop` 运行期间输入区禁用；`Esc` 弹确认框且默认停在「继续跑」；确认后回到空闲态。
- 翻页那一刻的观感：转录清空、新会话开场、侧栏进度接着走 —— 不能看起来像崩了。

**护栏**

- `python3 scripts/check-language.py` OK；新增的散文与模型可见文本走中文（[ADR 0005](../../docs/adr/0005-model-visible-text-in-chinese.md)）。

## 明确不做

- **清单的自动同步**：票变了清单跟着变 —— 清单是生成一次的产物，独立。
- **`/goal` 的 `list` / `show` / `rm`**。
- **目标的并行**：一个会话同时跑两个目标（一个会话一个当前目标，可切换但串行）。
- **运行中插话**：那是 [`interjection-flow`](../interjection-flow/seed.md)。
- **MCP / RAG / web 搜索 / 后台服务**：各自是别的种子。
- **网络隔离**：沙箱那半没做的一半，见 [`sandbox`](../sandbox/spec.md)。
- **多人 / 多机共享目标**、目标的版本历史与冲突解决。
- **跨目标的排序与优先级**：`/loop <名字>` 一次只认一个。
- **压缩之外的历史管理**（fork / rewind、历史编辑）。

## 补记

- **与 `todo-and-modes` 的关系**：`todo` 加可选 `id` 是那份 spec §2 的 schema 扩展 —— 它当时把「跨会话持久」列为 明确不做，理由是「要新存储」；本 spec 走的是**派生**那条路，所以那个理由不成立，但**执行中的清单封闭**仍然成立（那是另一回事）。
- **与 `sandbox` / `workspace-mode` 的关系**：`/loop` 要求的 `workspace` 档正是 [`workspace-mode`](../workspace-mode/spec.md) 那一档；沙箱给它兜底。
- **与 `tui-history-replay` 的关系**：§10 的崩溃恢复复用它那条「重开时把历史铺进转录」的路径，`--continue` 的行为不变。
- **前缀缓存的代价**：§6 的提醒与 §7 的压缩都必然打掉前缀缓存，所以两者都被设计成**低频**（跨阈值一次、过一次八成一次）。这条代价要在实现时如实记账。
- **一条值得 ADR 的决定**：「目标不进会话状态，它的进度从各会话的 `todo` 派生」—— 难回头（它定 schema 的形状）、离开上下文会显得奇怪（为什么不存一份 goal 状态？）、且真有替代方案（存一份状态文件，像日账本当初拒绝的那样）。**已落地**：[ADR 0009](../../docs/adr/0009-goals-are-files-and-progress-is-derived.md)，逐面文档在 [`docs/goals.md`](../../docs/goals.md)。

## 实现注记（2026-10-01，15 张票落地时回改）

按本仓库的规矩（实现票若改了 spec 的任何决定，必须回改 spec），这里是落地时与上文有出入的地方：

- **`SCHEMA_VERSION` 没有涨**（§3 把这件事留给票 02 定）：加一个可选字段与四个新 payload 变体
  （`GoalSelected` / `GoalCompleted` / `GoalStopped` + `ContextSource` 的三个变体）之后老流仍读得
  回来，而跨版本从来不承诺兼容。票 03 也明说不涨。
- **§7「收掉当前会话（写收尾）」的实际形状**：旧会话最后落的是那条
  `HistorySuperseded { reason: Compaction }`，**没有** `SessionEnded`——今天没有任何地方产出它，
  而 `StopReason` 里也没有一个「被翻页取代」的值。§10 的恢复判据不受影响：它看的是**最新**那条
  流有没有收尾事件。
- **停止事件是一个 payload 而不是几个**：`GoalStopped { goal, reason, detail, stuck, count }`，
  `reason` 取 `no_progress` / `provider_failed` / `user_stopped` / `budget_exhausted`（§5 的主动
  停也走它，于是恢复一眼分得出四种停）。§11 点名的「完成汇总」另有一条 `GoalCompleted`。
- **跨会话额度落在 `SessionConfig.carried_tokens`**（§8）：闸门的求和仍是整条流，循环把「这个目标
  更早那些会话的 `UsageRecorded` 之和」填进去 —— 值，不是状态文件。
- **`[goals]` 有四个旋钮**：`remind_at` / `compact_at`（§6）之外，票 11 加了
  `no_progress_rollovers`（缺省 3）与 `provider_retries`（缺省 2、上限 10）。
- **`/loop` 的启动边界多了一条**（§5 的档位裁决也放在同一个判据里）：`check_start` 判四条 ——
  已经在跑 / 档位不够 / 清单不在 / 没活可干。
- **§11 的汇总多了一条机械兜底**：那次模型调用没成时（`single_shot` 交回 `None`），退回一份
  模板说明（目标名 / 完成情况 / 跨几个会话 / 新工作四项照摆）。判据是机械的，所以「做完了」
  不依赖模型能不能开口 —— 缺的只是那段叙述。
- **§6 / §9 的两组配置项各多了一条校验**：`remind_at` 必须在 `compact_at` 之前（反过来提醒
  永远轮不到），`no_progress_rollovers` 至少是 1，`provider_retries` 有上限。挡的是「看起来
  配好了、实际不会发生」的组合。
- **越界 id 的提示在循环里也报**（§3「忽略它，但不静默」）：启动时报一次，此后每个回合边界
  重算发现集合变了再报 —— 只在启动时报，运行中新冒出来的那些就一直没人说。
- **`/goal-new` 吃一个或多个来源**（§2）：多来源时票号必然撞号，于是 id 按最终顺序重排、内容
  带上 `<来源目录名>/<票号>` 凭证。一个来源时的行为（id = 票号、内容 = 标题）一个字没变。
- **命令名从 `/goal new` 改成 `/goal-new`**（§2、§13）：空格形状的子命令在 `/` 菜单里补不出来
  （菜单按命令名的前缀过滤），而连字符形状下 `/goal-` 一个前缀就能把整族列出来。这条形状定成
  **这一族命令的命名规矩**，将来的 `/goal-list` / `/goal-show` / `/goal-rm` 照走。退役的空格
  形状读作**未知命令**，与 `/plan` 同一条规矩（不做别名）。
