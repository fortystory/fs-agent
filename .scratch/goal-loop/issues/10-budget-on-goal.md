# 预算认到目标上

Type: implement
Status: ready-for-agent
Blocked by: 03

> 规格：`.scratch/goal-loop/spec.md` §8。
> 现状 `Budget` 是**会话级**、花费从本会话事件流求和 —— 翻页会重新获得一整份额度，于是**每翻一次页多一份预算**，无人值守就变成无人看管地烧钱。这一票堵的就是这个口子。

## 目标

把预算的求和范围从「本会话」扩到「这个目标横跨的所有会话」。

## 落点

- `src/config/cost.rs` 与闸门的比对处
- 循环侧：按归属筛会话
- `tests/goal_loop.rs`

## 具体行为

1. **求和范围 = 这个目标的全部会话**：按 `GoalSelected`（票 03）筛出本桶里属于该目标的会话，把这些会话流里的 `UsageRecorded` 加起来。翻页开的那些会话都在里面，所以**翻页不重置额度**。
2. **照样是派生的，不新增状态文件**：这正是日账本那条先例（`CONTEXT.md` 的**日账本**条 —— 扫会话文件按 UTC 日聚合，零新状态文件）。别为它造一个 ledger。
3. **撞顶沿用既有语义**：**降级收尾，而不是中断**（`CONTEXT.md` 的**预算**条）。降级收尾要落收尾事件（票 05 / 11 的形状），以便票 12 的恢复能区分。
4. **闸门仍然只数 token**：费用仍只作显示（`PriceTable` 那条），这一票不改它。
5. **没有当前目标时退回会话级**：既有行为不变 —— 普通交互会话的预算就是本会话。
6. **讨论者 / 合成器 / 执行者共用一个额度**（既有约定），这一票不碰它；跨会话累计的对象是**这个目标下所有会话的全部用量**。

## 测试

- 一个目标跨两个会话：两个会话的 `UsageRecorded` 累加，且**翻页不清零**（造一个「会话 A 用掉大半额度 → rollover → 会话 B 继续」的场景，断言闸门在累计值上判）；
- 撞顶 → 降级收尾 + 一条收尾事件，而不是中断；
- 无当前目标时退回会话级（与既有测试对照）；
- 归属筛：另一个目标的会话用量**不算进来**；
- 派生的口径与日账本一致（同一批会话文件、同一种求和方法）。

## 不做什么

- 不改日账本本身（它按 UTC 日聚合，是另一个口径）。
- 不做「按目标看花了多少」的查询面（侧栏与 `sessions` 不动）。
- 不动 `Budget` 的类型与配置形状。
