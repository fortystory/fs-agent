# 完成判据与汇总落流

Type: implement
Status: done
Blocked by: 01, 03, 04

> 规格：`.scratch/goal-loop/spec.md` §1（完成判据）、§11（汇总说明）。
> 这一票让 loop 知道自己什么时候**做完了**，并把「做完了什么」变成流上的一条事实 —— 而不是屏幕上刷过去就没了的一句话。

## 目标

- 机械判据：所有条目 `completed` → 目标完成；
- 完成后出一份汇总，**落流**；
- 然后不退出，回空闲态。

## 落点

- `src/events.rs`：新 payload `GoalCompleted { goal, summary }`、`kind()`、打码穷尽匹配
- 循环侧：完成判据的调用点、汇总生成的调用
- `tests/goal_loop.rs`

## 具体行为

1. **完成判据**：每次 `todo` 落地之后、以及每个回合边界，重算一次进度（票 04 的派生）。**所有条目都是 `completed`** → 目标完成。判据是机械的、循环自己判，不需要人点头。
   - 信任假设要写在注释里：`completed` 是**模型自己填的**，所以判据机械**不等于**结果可靠。
2. **新 payload `GoalCompleted { goal, summary }`**：`goal` 是标识符（不打码），`summary` 是散文（**要打码** —— 穷尽匹配那一处必须覆盖它，否则新变体会被忘在那张单子外）。
3. **`summary` 的内容**（规格 §11，四项都不可省）：
   - 目标名；
   - 条目完成情况（几条 / 几条）；
   - **跨了几个会话**（从归属筛出来的会话数）；
   - **执行中冒出来但没进清单的新工作** —— 清单是封闭的，新工作只能在这里交代。
4. **`summary` 由一次模型调用生成**（它是叙述性的，不是模板能拼出来的）：这次调用与压缩那次同类，**照记 `UsageRecorded`**，所以它落进目标预算（票 10）。
5. **完成后不退出**：出汇总、落流，然后回到空闲态（提示符停在静止色、pulse 归零 —— 现在空闲时本来就是这个样子）。
6. **不会重复触发**：`/loop` 对「已全部完成」的目标本来就拒绝启动（票 03），所以完成后不会自己再跑一轮。

## 测试

- 最后一条 `todo` 把全部条目标成 `completed` → 流上**恰好一条** `GoalCompleted`，且 `summary` 里报的条数与实际一致；
- 造一个跨两个会话的场景 → 汇总里的「跨了几个会话」是 2；
- 中途有 `goal_note` 记下的新工作 → 汇总里能看到它（票 13 的接口先留出来，没有就为空）；
- 汇总那次调用的用量落进 `UsageRecorded`；
- 完成后进程不退出、回到可输入状态（TUI / plain 各一条）。

## 不做什么

- 不做阈值、翻页、压缩（票 07/08）。
- 不做无进展判据（票 11）—— 这一票只管**正常**完成。
- 不改「完成后不退出」以外的会话生命周期。
