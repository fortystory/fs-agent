# 阈值与提醒：50% 与 80%

Type: implement
Status: done
Blocked by: 07

> 规格：`.scratch/goal-loop/spec.md` §6。
> 今天窗口是靠 `context::trim` **静默丢弃**旧内容满足的 —— 它不产生任何事件，所以「快满了」这个信号要新造。

## 目标

- 过 50%：向模型注入**一次**提醒，要它把还没落流的东西落下来；
- 过 80%：触发票 07 的 rollover。

## 落点

- `src/config/`：两个配置项
- 循环侧：回合边界的阈值比对
- `src/events.rs`：提醒用的 `ContextSource` 变体（或复用票 07 那个）
- `tests/goal_loop.rs`

## 具体行为

1. **两个配置项**，默认 50 / 80（`[goals] remind_at = 50` / `compact_at = 80`）。数字是**窗口的百分比**。
2. **分母是窗口**（[`context::usable_input`](../../src/context.rs)），也就是状态行那个 `上下文 n%` 的同一个数 —— **不是预算**（预算是累计 token，见 `CONTEXT.md` 的**预算**条）。同源的好处是：用户眼睛看到的数就是触发的数。
3. **判据取投影前的估算**（`context::estimate_messages_tokens`），在**回合边界**比对 —— 不能在一个工具跑到一半时判。
4. **过 50%：注入一次提醒**，措辞是「**把还没落流的东西落下来**」，不是「你该收敛了」。理由写进注释：再过一会儿历史会被压成摘要，而摘要只留得住它读得到的东西 —— 模型只在脑子里、没写进 `todo`、没写成结论的推理会丢。这条提醒是给它一次**自救**的机会。
   - **跨过阈值时注入一次，不是每轮**：每轮注入会每轮打掉前缀缓存，而本仓库有「前缀只增不改」的不变量。用一个跨回合的标记记住「这一档已经提醒过」。
5. **过 80%：触发票 07 的 rollover**（压缩 + 翻页）。翻页后新会话的用量回到低位，标记随之复位，所以下一个窗口还会再提醒一次 —— 那是**新会话**的提醒，正确。
6. **提醒本身是一次注入**，所以它进流、可重放；用 `ContextSource` 的一个变体（`Reminder`），与技能注入同形状。
7. **plain / headless**：注入照常发生（它是给模型的，不是给人看的）；状态行的百分比照旧。

## 测试

- 阈值边界：49 / 50 / 51 与 79 / 80 / 81 各一条（用假 provider 造出对应估算的会话）；
- **只注入一次**：连续多个回合都在 50% 以上，流上只有**一条**提醒；
- 过 80% → 触发 rollover（断言有 `HistorySuperseded`）；
- 翻页后标记复位：新会话再次过 50% 时会有第二条提醒；
- 判据用的是窗口不是预算（造一个预算高但窗口低的会话）；
- 提醒的文案是中文、走措辞 / 常量，不内联。

## 不做什么

- 不做「提醒了但模型不理」的补救（那属于无进展判据，票 11）。
- 不做可交互的阈值调整（只有配置项）。
- 不改 `context::trim` 的丢弃策略本身 —— 这一票只在它之前加一个**信号**。
