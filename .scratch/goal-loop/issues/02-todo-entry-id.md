# `todo` 项加一个可选 `id`

Type: implement
Status: ready-for-agent
Blocked by: —

> 规格：`.scratch/goal-loop/spec.md` §3（条目身份）。
> 「机械判定」要真机械，得先能认出「清单第 3 条」和「`todo` 里那一项」是同一个东西 —— 靠 `content` 文本对应会漂，而且那样判定就不是真机械。

## 目标

让模型的待办项能引用目标清单的条目。

## 落点

- `src/tools/todo.rs`：`Item` 加字段、解析与渲染、工具描述
- `src/render/todo.rs`：侧栏那一页
- `tests/todo.rs`

## 具体行为

1. **`Item` 加一个可选 `id`**，线级形状 `{"id": "03", "content": "补测试", "status": "pending"}`。
2. **缺 `id` 照旧**：老调用（没有 `id`）能原样解析 —— 这一条是加**可选**字段而不是新字段的理由，也是它不破坏「参数是唯一真相源」那条设计的原因。
3. **格式校验在这一票做**：id 必须是两位十进制数字（`01`…`99`）。`3`、`003`、`ab`、`1a` 都是**模型可读的工具错误**，照该文件既有的手写解析风格（错误说清是第几项、哪个字段、期望什么）。
4. **存在性校验不在这一票**：工具不认识清单。「id 在不在当前清单里」由循环在派生进度时判（票 04），未知 id 在那里被忽略**但不静默**。
5. **侧栏**：有 id 的项在状态字形之后带上 id（`✓ 03 补测试`）；没 id 的项照旧。宽度阶梯与 `＋N 项` 那行不动。
6. **`effect()` 仍是 `ReadOnly`**：这一票不改副作用类别，权限门仍然从不为它发问。
7. **挂载面不变**：主会话、讨论者、执行者、headless 都有它。

## 测试

- 合法 id 的解析与渲染往返；
- 非法格式各自的错误文本（`3` / `003` / `ab` / 空串）；
- 缺 `id` 照旧解析（老形状的 fixture）；
- 侧栏渲染：带 id 与不带 id 混在一份列表里；
- `effect() == ReadOnly`；
- 端到端：假 provider 起真会话，模型调 `todo` 带 id，断言流上那条 `tool_call` 的 args 里有 id，且侧栏读到的是 args 里的列表。

## 不做什么

- 不改 `status` 的三个值，不加优先级 / owner / 依赖关系。
- 不让工具去读清单文件（它不认识清单；存在性归票 04）。
- 不动权限、不动投影。
