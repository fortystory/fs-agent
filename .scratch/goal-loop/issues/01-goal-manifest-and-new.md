# 目标清单文件与 `/goal new`

Type: implement
Status: done
Blocked by: —

> 规格：`.scratch/goal-loop/spec.md` §1（目标与清单文件）、§2（`/goal new`）。
> 这一票不碰 agent、不碰 `/loop`：它只做文件的读、写与从票生成，所以**每一个分支都能在单测里断言**，不需要假 provider。

## 目标

让「目标」在磁盘上有一个具名的、人能读能改的载体 —— 一份清单文件，外加一个生成它的命令。

## 落点

- `src/goals.rs`（新增）：清单的解析与渲染、id 分配、从票生成
- `src/cli.rs`：`/goal` 进那张 `Submission` 表
- `tests/goals.rs`（新增）

## 具体行为

1. **位置与名字**：`~/.local/share/fs-agent/goals/<名字>.md`。`<名字>` 就是 `/loop` 的参数，校验它是**不断开的单个词**（与人物名字同一条规矩），且不含路径分隔符。
2. **文件形状**：人可读的 markdown —— 一行标题，然后一个条目列表：

   ```markdown
   # grep-tool

   - 01 看 bash 工具怎么注册
   - 02 写 grep 工具骨架
   - 03 补测试
   ```

   **条目只带 id 与内容、不带状态**（规格 §1）：状态只有流一个真相源，文件里画复选框会让人误以为它才是进度，而它其实只是开工前那份快照。
3. **id**：两位十进制、从 `01` 起、按生成顺序分配，此后不动。解析时 **id 必须唯一**，重复是文件级错误，报错文本指向那一行（照 `src/tools/todo.rs` 的手写解析：错误说清是哪个字段、哪一项）。
4. **`/goal new <名字> <来源>`**：`<来源>` 是一个 feature 目录（`.scratch/<slug>/`）或一份票文件。读该目录下的 `issues/NN-*.md`（或那一份票），按编号升序，把**每张票的标题**变成一条条目，票号 → id。
   - **只读票，不写回票。**
   - 来源不存在、或里面一张票都没有 → 拒绝并说明。
5. **重名一律拒绝**，除非加 `--force` —— 默默覆盖会抹掉一份已生成的目标定义。
6. **`/goal` 本轮只做 `new`**：`list` / `show` / `rm` 都不做。清单就在磁盘上，人自己 `ls` / `cat`。
7. **它是个手势，不是工具调用**：`/goal new` 由循环直接执行（与 `/undo` 的写回同规矩），**不走工具表、不走权限门、不进事件流**。清单文件存在即是「目标已创建」的证据。

## 测试

`tests/goals.rs`，全是纯函数与文件断言：

- 从 `.scratch/sandbox/issues/`（5 个文件）生成 → 5 条条目、id `01`–`05`、内容等于各票的标题；
- 从**单份票文件**生成（`<来源>` 指到文件）→ 一条条目；
- 重名 → 拒绝；加 `--force` → 覆盖；
- 来源不存在 / 目录里没有票 → 拒绝，且错误文本说清是哪一种；
- 名字含 `/`、空格、或为空 → 拒绝；
- 手写的一份清单能被解析回来（往返：渲染 → 解析 → 相等）；
- id 重复 → 文件级错误，报错指向那一行；
- 条目行形状不对（没有 id、id 不是两位数字）→ 拒绝。

## 不做什么

- 不碰 `Session`、不碰事件流、不改 `EventPayload`。
- 不做 `/goal list` / `show` / `rm`。
- 不做「清单与票的后续同步」—— 生成一次，此后独立。
