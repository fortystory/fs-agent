# 条目状态从流派生

Type: implement
Status: ready-for-agent
Blocked by: 02, 03

> 规格：`.scratch/goal-loop/spec.md` §3（状态派生与合并规则）。
> 这是「一个目标跨几个会话」的核心：**会话 2 的 `todo` 里没有的条目，状态要从会话 1 的流里读回来。**

## 目标

算出一个目标下每个条目的完成状态 —— 且这条规则在跨会话时成立。

## 落点

- `src/goals.rs`：派生函数（纯函数）
- 循环侧：进度重算的调用点
- `tests/goals.rs` / `tests/goal_loop.rs`

## 具体行为

1. **派生函数**：入参是「清单条目集」+「这个目标横跨的所有会话的 `todo` 调用」（每个调用是 args + 它所在的会话与 `seq`），出参是 `id → status`。
   - **纯函数**：入参是事件切片，不读文件、不读环境 —— 所以它能脱离运行期单测。
2. **合并规则**：按 id 取**最新**状态。排序键是（会话时间，`seq`）。具体地：
   - 会话 1 把 `03` 标成 `completed`、会话 2 的 `todo` 里**根本没有** `03` → `03` **仍是 completed**；
   - 同一条目在后续调用里被改回 `pending` → 以最新的为准；
   - 一条都没提过的条目 → `pending`（清单是封闭的，所以它始终存在）。
3. **未知 id**：`todo` 里出现清单没有的 id → **忽略它，但不静默**：在转录里留一行（措辞走 `src/render/wording.rs` 的措辞层）。沉默会让模型以为它记下了。
4. **作用域**：某个目标的会话集 = 按 `GoalSelected` 筛出的本桶会话（票 03）。没有当前目标时这个派生不启动。
5. **侧栏不变**：`todo` 页继续显示**本会话**的列表（既有行为）；目标进度是另一处 —— 它进票 05 的判据与汇总，以及转录里的进度行。

## 测试

- 合并规则三个场景：跨会话（会话 2 缺项）、同会话多次调用、条目从未被提及；
- 未知 id 被忽略且留了一行；
- 排序键：同一会话内按 `seq`，跨会话按会话时间；
- 端到端：假 provider 起两个会话（同一目标），会话 1 完成一条，断言会话 2 的进度重算把它算作完成。

## 不做什么

- 不写回文件（清单不带状态）。
- 不改侧栏 `todo` 页对「本会话列表」的既有语义。
- 不做完成判据本身（票 05）。
