# 无进展与停止

Type: implement
Status: done
Blocked by: 07

> 规格：`.scratch/goal-loop/spec.md` §9。
> 这是给「总是相似的那几条在循环跑」那类失败准备的 —— 没有它，一个卡住的目标会一直翻页重试到烧完预算。

## 目标

两条停下并报告的判据：**连续无进展** 与 **provider 调用失败重试耗尽**。

## 落点

- 循环侧：翻页计数、重试计数
- `src/config/`：两个配置项
- `src/events.rs`：收尾事件（复用票 05 的 `GoalCompleted` 之外的形状 —— 见下）
- `tests/goal_loop.rs`

## 具体行为

1. **无进展判据**：**连续 N 次翻页零条目完成**。N 是配置项（`[goals] no_progress_rollovers`，缺省 3）。
   - 计数对象是**翻页**（rollover），不是回合 —— 单位更长，误判更少；
   - 「零条目完成」用票 04 的派生算：这次翻页相对上一次，`completed` 的条目数没有增加；
   - **中途完成任意一条就归零**，重新计。
2. **provider 调用失败**：重试若干次（配置项，缺省取既有语义），**耗尽后停下**。重试的次数与间隔在这一票定死并写进注释。
3. **两种停止都「停下并报告」**：
   - 落一条**收尾事件**（形状：与 `GoalCompleted` 并列的一个新 payload，带 `reason` —— 无进展 / provider 失败 —— 与人可读的说明）；
   - 转录里说清楚（措辞层）：连续几次翻页没有任何条目完成 / 哪个调用失败了几次。
4. **停下之后不自动恢复**：`--continue` 的行为由票 12 定 —— 这一票只需要保证那条收尾事件**落了流**，否则 12 分不出来。
5. **报告要可核对**：事件里带上计数与相关 id（如卡住的条目 id），这样回头能核对「它是怎么卡住的」。

## 测试

- 连续 N 次翻页零完成 → 停下 + 恰好一条收尾事件，且**不再继续翻页**（断言后面没有新的 `HistorySuperseded`）；
- 中途完成一条 → 计数器归零，再攒 N 次才停；
- N 的边界（N-1 次不停、N 次停）；
- provider 连续失败 → 重试到上限 → 停下 + 收尾事件；中途成功 → 计数归零；
- 收尾事件里带了计数与条目 id；
- 停下后进程不退出（回空闲态）。

## 不做什么

- 不做「自动换个思路重试」这类补救。
- 不做跨目标的全局熔断。
- 不改 `Cancel`（那是一次手势，与这里的两条判据无关）。
