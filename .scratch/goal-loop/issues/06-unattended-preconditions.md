# 无人值守的前提：档位、输入禁用与 `Esc` 确认框

Type: implement
Status: ready-for-agent
Blocked by: 03

> 规格：`.scratch/goal-loop/spec.md` §5。
> 「无人值守」不能是空话：`ask` 档下第一次写就停在等人，所以这一票把前提**写进门里**。

## 目标

让 `/loop` 只在一个能真的没人看着跑的组合里启动，并让它运行期间的人机边界清楚。

## 落点

- 循环侧：启动时的档位裁决（写任何事件之前）
- `src/render/tui.rs`：输入区禁用、`Esc` 确认框
- `src/render/wording.rs`：三条文案进措辞层
- `tests/goal_loop.rs`、`docs/tui-manual-checklist.md`

## 具体行为

1. **档位裁决**：`/loop` 启动时看当前权限档（`src/permissions.rs` 的 `Mode`）：
   - `readonly` / `ask` → **拒绝启动**，并说明原因（「无人值守时第一次写会停在等人」）；
   - `workspace` / `auto` → 放行。
   模式是会话的一个值、不进事件流，所以 `--continue` 回到配置里那一档 —— 这条行为照旧，这里只是读它。
2. **运行期间输入区禁用**：TUI 里打字不进草稿（键位照旧响应，只是不落字）；plain 渲染器不读行、或读到就提示当前禁言。转录照常滚动。
3. **`Esc` 弹一个确认框**：
   - 走中段覆盖层（与权限询问同一条通道），但**发起者是渲染器自己**，不是 `Asker` 那个接缝；
   - **默认停在「继续跑」**，要停得明确选 —— 误按一下不该掐掉一个长任务；
   - 取消 → loop 继续跑，什么都不发生。
4. **确认框立着的时候 loop 继续跑**：它是「问一句」，不是暂停。不引入「暂停」这个状态。
5. **确认后**：停下 loop，并落一条收尾事件（票 12 靠它区分「人主动停」与「异常中断」）。
6. **文案走措辞层**（`src/render/wording.rs`）：三条 —— 档位拒绝、输入禁用提示、确认框的标题与两个按钮。

## 测试

- 档位裁决的真值表（四档各一条）；
- 端到端：`ask` 档下 `/loop` 拒绝，且**流上没有** `GoalSelected`（拒绝发生在写事件之前）；
- 端到端：`workspace` 档下能启动；
- TUI 手工清单新增一节：输入区禁用、`Esc` 默认停在「继续跑」、取消后 loop 还在跑、确认后回空闲；
- 措辞层的三条常量有中文、且不内联在渲染器里。

## 不做什么

- 不做「运行中插话」（那是 `.scratch/interjection-flow` 那条种子）。
- 不引入暂停 / 恢复语义（只有跑与停）。
- 不改四档本身的裁决逻辑。
