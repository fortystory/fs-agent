# 崩溃恢复与主动停

Type: implement
Status: done
Blocked by: 03, 05, 07

> 规格：`.scratch/goal-loop/spec.md` §10。
> 「走开」意味着没人看着。进程崩了要能自己接着跑；但人**主动**停掉的，回来别又自己跑起来。

## 目标

让 `--continue` 能区分两种中断，并各自做出正确的行为。

## 落点

- 循环侧：恢复路径的判定
- `tests/goal_loop.rs`、`tests/history_replay.rs`（恢复那一片）

## 具体行为

1. **判定完全从流派生**（不新增状态文件、不写恢复标记）：
   - **正常收尾**：流上最后有一条收尾事件（`GoalCompleted`、无进展停、provider 失败停、或票 06 的「人主动停」）；
   - **异常中断**：没有收尾事件 —— 例如最后一条不是 `TurnEnded`，或 `SessionError` 之后什么都没了。
2. **异常中断 → `--continue` 后自动接着跑**：不必人点头，接着做当前目标（当前目标同样从流派生：最后一条 `GoalSelected`）。
   - 风险是「同一个条目把进程反复弄崩」，由票 11 的无进展判据兜住 —— 这一点写进注释。
3. **正常收尾 → `--continue` 后回空闲态等人**：不自动开新 loop。
4. **「人主动停」必须落收尾事件**：否则它和崩溃分不出来。票 06 的确认框确认后要落一条（这一票要核对它确实落了）。
5. **恢复时的可见性**：转录里说清楚发生了什么（「接着上次的目标跑」/「上次是正常收尾，停在这里」）—— 措辞层。
6. **不改变既有 `--continue` 的行为**：没有目标归属的会话（普通交互会话）照旧 —— 只铺历史，不自动跑任何东西。

## 测试

- fixture 一：`GoalSelected` + 若干回合 + **没有**收尾事件 → `--continue` 后自动接着跑（断言有新回合）；
- fixture 二：`GoalSelected` + 回合 + `GoalCompleted` → `--continue` 后回空闲（断言没有新回合）；
- fixture 三：主动停的收尾事件 → 同上（回空闲）；
- fixture 四：普通交互会话（无 `GoalSelected`）→ 行为与今天完全一致；
- 判定不写任何新文件（断言会话目录里没有多出来的东西）；
- 转录里那一行措辞是中文、走措辞层。

## 不做什么

- 不做「崩溃后换一个模型 / 换一个策略」。
- 不做恢复提示的交互确认（自动就是自动）。
- 不改 `sessions replay` 的既有语义。
