## 它要什么

让 fs-agent 围绕一个**目标**无人值守地干活：

- 人给出一个目标 —— 一份「不需要人再参与即可完成的工作」，例如一份 `/to-spec` 生成的文档，
  或同形状的清单。
- fs-agent 连续工作（`/loop <名字>`），上下文快满时自己压缩、开一个新会话接着干，
  **直到目标完成**。
- 人在中途可以走开；回来时看得到做到哪了，以及一份收尾说明。

## 已拍的决定

### 词汇与三层模型

- **目标（Goal）** 是这个 effort 的中心词：具名、跨会话的工作定义。
- 三层：**目标 ⊃ 会话 ⊃ todo**。一个目标可以横跨几个会话；一个会话里的 `todo` 只属于这个会话。
- **`todo` 是会话级的计划，目标是跨会话的工作单位** —— 两层，不是同一个东西换了作用域。
- 立词条时要注一句：`CONTEXT.md` 的**落点**那条 `_Avoid_` 里已经有「路由目标」，别混。

### 归属与状态

- **当前目标由 `/loop <名字>` 选定，可以切换** —— 不是会话开场绑死；一个会话可以在一个目标完成
  之后接着做另一个。
- **会话要记下自己属于哪个目标**（归属信息落流，现在 `SessionStarted` 没有它）。**这是翻页的地基**：
  新会话得靠它知道自己在为谁干活、做到哪了。
- 三样东西放三个地方**（推论）**：
  - 目标的**定义**（名字 / 条目 / 验收）是**输入数据**，落文件 —— 它不是谁的副本，它就是原始数据；
  - 目标的**进度**是**派生量**，从会话流现算；
  - 当前的**选择**是**派生量**，读流上最后一条「选定目标」事件（于是 `--continue` 后自然重建，
    与 `todo` 同一条纪律）。
- **目标列表就是一份独立的清单文件**（2026-10-01 拍）：fs-agent 自己的格式，**不直接依赖
  `.scratch/` 的运行时约定**；但**可以从 `.scratch` 的票生成**（时机与方向见分叉 8）。
- **清单开工前封闭**（2026-10-01 拍）：执行中不能往目标里加条目。于是「所有条目 `completed`
  即完成」有稳定判据；执行中发现的新工作**另开一个目标**。
- **条目状态从各会话的 `todo` 派生**（2026-10-01 拍）：清单文件只存条目的**定义**，状态不进文件。
  好处是 `todo` 是 `ReadOnly`、**从不触发权限门**，无人值守友好；代价是要有**条目身份**
  （见分叉 13）。
- **找全一个目标的 N 个会话，靠那条归属筛**（2026-10-01 拍）：扫桶、按归属过滤。
- **归属是一条事件**（2026-10-01 拍）：`GoalSelected { goal }` 之类，只追加、**不动
  `SessionStarted`**。于是**当前目标 = 流上最后一条**，切换天然就是再记一条 —— 与 `todo` 同一条
  派生纪律。
- **条目身份靠 `todo` 项上的一个可选 `id`**（2026-10-01 拍）：清单条目带稳定 id，`todo` 项用 `id`
  引用它。「机械判定」要真机械，这是它的前提；代价是 `todo` 的 schema 多一个可选字段。
- **清单文件落在 `~/.local/share/fs-agent/goals/<名字>.md`**（2026-10-01 拍），人可读的 markdown；
  状态派生自流，所以它只读，沙箱不是约束。
- **清单由一个独立动作生成**（2026-10-01 拍）：`/goal new <名字>`，人主动触发；`/loop <名字>`
  只管执行。职责不混。生成是一次性的 —— 此后清单**独立**，票再变也不跟。
- **清单里只有条目与 id，不带状态**（2026-10-01 拍）：状态只有流一个真相源；文件里画复选框会让人
  误以为它才是进度，而且那只是开工前那份快照。
- **来源显式给出**（2026-10-01 拍）：`/goal new <名字> <feature 目录或票路径>` —— 读哪些票不靠猜。
  **重名一律拒绝**，除非加 `--force`：清单是目标定义的唯一真相源，默默覆盖会抹掉它。
- **执行中冒出来的新工作由模型显式记**（2026-10-01 拍）：一个像 `todo` 那样的新工具
  （`goal_note`），`ReadOnly`、不问权限。它落成什么形状见分叉 14。

### `/clear` 与翻页

- **`/clear` = 结束当前会话、开一个新的**（进程不重启，渲染器与终端留着）。**不是**「清空上下文
  继续用」——`clear-command/seed.md` 原来的措辞要改。
- **名字保持 `/clear`**（2026-10-01 拍）：与 DSH / Claude Code 的手势一致，肌肉记忆在。
- 旧会话**留在磁盘上**，仍能被 `--continue` / `sessions` 找回。
- 触发翻页的是**上下文将满**，不是目标边界：目标完成不必换会话（直接 `/loop <下一个>`）。
- 翻页**自动进行，不问人**。
- 底下是一个 **rollover** 动作**（推论）**：收掉当前会话 → 组装一个新的 → 从旧流派生进度 +
  注入摘要 → 继续。`/clear` 与 `/loop` 的翻页是它的两个入口 —— **两段入口、一段机制**。spec 里
  要钉死这一点，否则会长出两套「开新会话」的语义。

### 压缩

- 压缩**不是**多余的：派生给的是**进度**（哪些条目完成了），压缩给的是**经验**（为什么这么做、
  踩了什么坑、读过哪些文件）—— 后者派生不出来。
- 阈值：**过 50% 提醒模型**、**过 80% 压缩一次再开新会话**。**两个数做成配置项，默认 50 / 80。**
- **压缩与翻页是一个内部动作，总是成对发生**（2026-10-01 拍）：80% → 压缩 → 翻页，
  不做「压缩后看空间够不够再决定翻不翻」那条分支。
- **提醒跨过阈值时注入一次**（不是每轮），措辞是「**把还没落流的东西落下来**」（2026-10-01 拍）
  —— 因为 80% 之后历史会被压成摘要，只留在模型脑子里的东西会丢。
- 80% 那一次**由循环执行** —— 压缩与开新会话都是 harness 的动作，不是模型请求的（见下节），
  然后把压缩后的上下文**注入**新会话。
- 形状是现成的：`HistorySuperseded { targets, reason, summary }` 已在 schema 里、`summary`
  字段都在，`HistoryReason::Compaction` 也早有枚举值。
- **摘要走 `ContextInjected` + 一个新的 `ContextSource` 变体**进新会话（2026-10-01 拍），
  与技能注入、人物注入同形状：进流、可重放，`--continue` 后还在。
- **压缩那次调用照记 `UsageRecorded`**（2026-10-01 拍），所以它自然落进目标预算 ——
  无人值守时的花费不会被低估。

### 谁执行这些动作

- **压缩与翻页都是循环的动作，模型不管这件事。** 模型不「调用」`/clear`，也没有那个能力：
  `/clear` 只是给键盘的入口（`Submission`，`src/cli.rs:1081-1147` 消费）。
- 模型在这一侧只有一样东西：**50% 那条提醒**（一条注入）。它不决定翻页，也不请求翻页。
- 于是原先列的两个分叉都关闭了：「模型怎么调用 `/clear`」不存在，「模型不调怎么办」也不存在。
- 顺带避开一个分类缺口：[`Effect`](../../src/tools/tool.rs#L21-L33) 三类全是**工作区**副作用，
  装不下「开新会话」；既然不给模型工具，这个缺口就不必现在处理。

### 无人值守的前提

- **`/loop` 要求权限档不低于 `workspace`**（2026-10-01 拍）：`readonly` / `ask` 档下直接**拒绝
  启动**并说明原因 —— 否则「无人值守」是空话（`ask` 档下第一次写就停在等人）。
- **崩溃后自动接着跑**（2026-10-01 拍）：`--continue` 回到一个在 loop 中途断掉的会话时，循环接着
  往下走，不必人点头。风险是「同一个条目把进程反复弄崩」，由无进展判据兜住。
- **启动边界都明确拒绝**（2026-10-01 拍）：名字不存在 / 目标已全部完成 / 已经有一个 loop 在跑 ——
  各说各的人话，不做意外的事。
- **`/loop` 运行期间输入区禁用**（2026-10-01 拍）：不能打字插话 —— 那是
  [`interjection-flow`](../interjection-flow/seed.md) 那条种子的事。要停按 `Esc`。
- **`Esc` 之后弹一个确认框**（2026-10-01 拍）：**默认停在「继续跑」**，要停得明确选 —— 误按一下
  不该掐掉一个长任务。

### 预算

- **预算认到目标上**，不是会话上：跨会话累计，**不随翻页归零**。
  现状里 `Budget` 是会话级、花费从本会话事件流求和，翻页会重新获得一整份额度 —— 这是要修的口子。

### 收尾

- 停止条件：**目标完成**，或 **provider 调用失败**（要有重试逻辑）。
- **目标完成的判据是机械的**（2026-10-01 拍）：**所有条目都 `completed` 就算完成，循环自己判**，
  不需要人点头 —— 与「不需要人再参与即可完成的工作」那句自洽。
  注意它的信任假设：`completed` 是**模型自己填的**，所以**判据机械不等于结果可靠**。
- 目标完成后出一份**汇总说明**，并且**落流**（只打印的话 `--continue` 之后就没了）。
- **完成汇总与失败收尾各落一条新事件**（2026-10-01 拍）—— 都进流，于是可重放、`--continue` 后
  看得见。**执行中冒出来的新工作不在此列**：它由模型调 `goal_note` 记下，而**那条调用的参数就是
  真相**（与 `todo` 同构，零 schema 改动）。
- **汇总说明包含**（2026-10-01 拍）：目标名、条目完成情况、跨了几个会话、以及**执行中冒出来但
  没进清单的新工作** —— 清单是封闭的，新工作只能在这里交代，所以这一项最不能省。
- 完成后**不退出**，回到空闲态待着。
- `--continue` 打开**最新的**会话。
- **「连续无进展」的判据**（2026-10-01 拍）：**连续 N 次翻页零条目完成**（N 做成配置项）→
  停下并报告。它和完成判据同源，所以机械可算。

## 现状（2026-10-01 核实）

- **没有 `/loop`，也没有 goal**：`grep goal` 只命中编辑器光标的目标列（`src/render/editor.rs:77`）。
- **没有 `/clear`**，但**内建命令表已经有了** —— 两份老种子那句「`/` 只走技能、没有内建斜杠命令表」
  都过期了：`src/cli.rs:1226-1253` 处理 `/quit` / `/exit` / `/undo` / `/discuss`，其余回退技能。
- **`todo` 已有，且是派生形状**：列表活在那条 `tool_call` 的 args 里，`--continue` / `sessions replay`
  / 侧栏都从它重算，没有第二处存储（`src/tools/todo.rs` 的模块注释）。
- **压缩未实现，地基与占位都在**：`HistorySuperseded { targets, reason, summary }`（`src/events.rs:381`）、
  `HistoryReason::Compaction`（`src/events.rs:223`）、「真的溢出」那个信号（`src/context.rs:121`），
  以及三处明说「将来的一次压缩要重新注入什么」的注释（`src/context.rs:121`、
  `src/context/skills.rs:231`、`src/context/repo_map.rs:168`）。
- **预算**：`Budget`（`src/config/cost.rs:38`）是**会话的**累计额度，花费从事件流求和。
- **窗口**：`context::usable_input`（`src/context.rs:58`）靠 `context::trim`（`src/context.rs:137`）
  **丢弃旧内容**满足 —— 它**不产生任何事件**，所以今天没有「快满了」这个信号。
- **`SessionStarted` 没有目标归属**：只有 `session_id` / `cwd` / `schema_version`（`src/events.rs:280`）。
- **跨会话派生有先例**：日账本（`CONTEXT.md` 的**日账本**条）扫会话文件按 UTC 日聚合，
  **不新增状态文件**。
- 容易混淆的既有物：`Pending::ClearDraft`（`src/render/tui.rs:582`）只清**输入框里的草稿**，
  与上下文无关。
