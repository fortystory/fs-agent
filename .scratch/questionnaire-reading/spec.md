# 问卷期间读得进详情

Status: done

- **来源**：维护者 2026-10-09 的两条要求里的一条 —— 「在用户回答问题时不能查看『轨迹』中的
  详情，也不能查看『文件』中的文件，这个需要修下」。
- **术语**：问卷 / 区域 / 详情覆盖层 / 文件查看器 照 [`CONTEXT.md`](../../CONTEXT.md)。
  判据与键盘顺序照 [ADR 0010](../../docs/adr/0010-questionnaire-keys-dispatch-by-zone.md)，
  那里的**区域分派一个字未动**；被推翻的是
  [`questionnaire-keys/spec.md`](../questionnaire-keys/spec.md) §7 补记里的「切页不打开任何
  详情覆盖层」那半句（ADR 0010 里有同日的补注）。

## 改动前的样子

问卷立着时，`click_at` 里 `questioning` 一串门把**详情这一族全挡在外面**：

- 轨迹页点一行（`trace_link_at` → `open_detail`）：挡
- 文件页点一行（`files_click`）：挡 —— 连目录展收都挡
- 改动页点一行（`changes_click`）：挡
- 对话页里的可点链接（`follow_link`）：挡

理由写在 `docs/render.md`：浮层一立着就把 `j`/`k` 从问卷手里抢走，而「全屏唯一的反显就是键盘
所在」会随之说谎。**代价**是读模型做决定之前没法看上一次调用发生了什么，也没法看文件，而
问卷恰恰是最需要看的时候。

## 方案

1. **指针**：那几扇门全开。落在底部问卷块之外的点击照旧分派 —— 切页、开详情、开 diff、
   滚到底，都在。
2. **键盘跟着当前那一层**，不是永远归问卷：没有浮层时归问卷（区域分派照旧）；**详情覆盖层与
   文件查看器立着时归浮层** —— 它们本来就排在问卷那一支前面，所以 `Esc` / `Ctrl-D` 关掉的是
   浮层，**关掉之后键盘原样还给问卷**：作答、焦点、翻到第几题都留着。
3. **浮层不许压住问卷**：`layout::Regions` 多一个 `overlay_floor`（平时是屏幕底边，问卷立着
   时是问卷块的顶边），`overlay_area` 在**自己那段高度**里居中。平时那块形状一个字不变。
4. **放不下就不开**：那一段高度装不下正文时 `overlay_area` 回答 `None`，与别处一样 —— 于是
   「点得开」在极小终端上仍然让位给「答得了」（40×10 那档）。
5. **中间那三类确认（粘贴 / 清草稿 / 目标停下）仍占着整个指针**：一次误点绝不许关掉一个还没
   回答的问题，那一条不动。

## 代价

- **同一个键在两层之间换含义**：`j`/`k` 在浮层立着时是滚动（或 nvim 的键），关掉之后才是问卷
  的高亮。这是「键盘跟着当前那一层」的应有之义，`Esc` / `Ctrl-D` 是唯一那把出口。
- **中间那段时间问卷是停着的**：作答能按键，但读者看不见自己在选什么，直到关掉浮层 —— 所以第
  3 条（浮层不压住它）不是锦上添花，是这一条的地板。
