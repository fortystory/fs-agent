# 问卷的键位：选项区 / 输入区、`j`/`k`、答案形状与 `Esc`

来源：2026-10-01 记下的第一批意向（`j`/`k` 选择、光标落到自定义项才进文本、超长选项折行）与
2026-10-02 追加的第二批（区域命名、选项区键位、焦点流转、`Esc` 分区域、快捷键提示），
两次都记在 [`seed.md`](seed.md) 里；2026-10-02 经 `/grill-with-docs`（18 问）折成这份 spec。

开头先纠正 seed《现状》一节里两处与代码不符的措辞，后面所有决定都以纠正后的事实为起点：

- **「`custom_focused` 只被绘制读来切换『回答：』与『自定义：』两行标签」——不对。** 它只决定
  **光标显不显示**（[`src/render/tui.rs:3824-3838`](../../src/render/tui.rs)）；两行标签是按
  **这道题有没有选项**选的（[:3825-3829](../../src/render/tui.rs)）。事件分派里读它的仍然只有
  空格那一支（[:818](../../src/render/tui.rs)），这一半是对的。
- **「页脚带宽度降级阶梯」——没有。** `draw_questionnaire_footer`
  （[`src/render/tui.rs:3845-3904`](../../src/render/tui.rs)）只有两件事：按钮按可用性增删、
  `hint_region` 越界就丢掉点击区域（文字仍画，被裁掉半截）。有宽度阶梯的是**普通状态行**的
  `hint_line`（[`src/render/wording.rs:1121-1144`](../../src/render/wording.rs)，40/60/80/120 四档）。

另有两处事实是这份 spec 的直接依据：**问卷立着时提示行整行被问卷页脚替换**
（`draw_bottom` 在 [`src/render/tui.rs:3716-3731`](../../src/render/tui.rs) 提前 return，
`draw_questionnaire_footer` render 到 `panes.hints`，[:3903](../../src/render/tui.rs)），
所以问卷期间的 `ctrl-c` 举手是**看不见**的；以及 **`Enter` 今天是兼职的**
（[`press`:800-812](../../src/render/tui.rs)）——提交、前进、确认三件事共用一个键。

## 问题陈述

1. **问卷没有「区域」这个概念**：只有一个布尔 `custom_focused`，分派里只有空格那支读它；
   `j`/`k` 和别的可打印字符一样直接落进文本。于是「按区域分派键位」这件事在代码里没有落点。
2. **问卷一打开就能直接打字**，第一下同时把焦点从选项区搬进输入区——而 10-01 记下的意向是
   「**只有**光标落到自由文本那一项时，才把键盘让给文本输入」。两者冲突。
3. **超长选项被截断**（`truncate_columns`，[:2904](../../src/render/tui.rs)、
   [:2917](../../src/render/tui.rs)），而「高亮项保持在窗口里」的滚动按**选项条数**算
   （[:2832-2842](../../src/render/tui.rs)、[:3789-3802](../../src/render/tui.rs)）——折行会让
   这个前提失效。
4. **单选的答案形状与多选不对称**：自定义文本**覆盖**选择（`type_custom` 清 `selected`，
   [:903-905](../../src/render/tui.rs)；`confirm_highlight` 清 `custom`，[:874-875](../../src/render/tui.rs)；
   `answers()` 里再清一次，[:979-983](../../src/render/tui.rs)），而这条约定**写进了模型侧的契约**
   （[`fs-agent-v1/spec.md` §7](../fs-agent-v1/spec.md)）。于是「选一项再补一句话」这条路单选走不通。
5. **`Esc` 在问卷里只有「取消整个运行」一个意思**（busy 分支，[:2446-2448](../../src/render/tui.rs)），
   没有「这道题不答了、模型继续」的出口。后者的语义其实已经存在——问卷立着而回合不忙时，
   `Esc` 走的是 `decline(pending)`（[:2462-2463](../../src/render/tui.rs)）。
6. **问卷期间 `Ctrl-C` 的第一下没有可见回执**（提示行被页脚替换，见上）。
7. **问卷的真机手感没有手工清单**：分页页脚、折行、自由文本行光标、区域高亮至今只有
   `TestBackend` 帧断言，而票 33、34 两个真机 bug 正是这一类。

## 方案

- **区域**（§1）：引入 `Zone { Options, Input }` 替换布尔，让「键位按区域分派」有一处结构性的落点。
- **键位**（§2）：`j`/`k`/`Ctrl-N`/`Ctrl-P`/`↑`/`↓` 在选项区共一条分派、两端环绕、越界进输入区；
  选项区里可打印字符与 `Backspace` 一律吞掉；输入区里 `j`/`k` 就是文本。
- **答案形状**（§3）：单选与多选统一成 `selected` + `custom` **并存**，单选按键语义成 toggle；
  回改 §7 那条编码约定与工具描述。
- **`Enter`**（§4）：按区域拆——选项区里与空格完全一致，输入区里是「前进」；提交仍归 `Enter`。
- **`Esc` 与两把举手**（§5）：问卷里 `Esc` 只管「退出这次询问」（双击、drop sender、模型继续），
  「取消运行」归 `Ctrl-C`；两把手互斥，共用一个中性名的 500ms 窗口。
- **页脚**（§6）：进度 + 可点按钮 + 键位提示，举手期间最后一段换成回执；新造一条三档宽度阶梯。
- **折行**（§7）：选项折行，窗口改按**渲染行数**算。
- **呈现**（§8）：同一时刻只有一个视觉焦点，非当前区域那处降暗。
- **落点**（§9）：词表、逐面文档、索引与 ADR。

## 用户故事

1. 作为习惯 vim/Emacs 的人，我希望 `j`/`k`（以及 `Ctrl-N`/`Ctrl-P`）能在选项间移动，不用去够方向键。
2. 作为在写自由文本的人，我希望 `j`、`k`、空格就老老实实是文本，别一边打字一边把选项挪了。
3. 作为打错字才发现的人，我希望在选项区敲下的字符不会偷偷把键盘搬进输入区。
4. 作为要「选一项再补一句话」的人，我希望单选也能把选项和文本一起交回去。
5. 作为按错了的人，我希望在输入区按一下 `Esc` 就回到选项区，而且刚打的字还在。
6. 作为不想答这道题的人，我希望 `Esc` 两下就能放下它、让模型继续，而不是把整个回合掐掉。
7. 作为想中止这次运行的人，我希望 `Ctrl-C` 仍然管这事，而且第一下之后屏幕告诉我它生效了。
8. 作为在窄终端里的人，我希望页脚先丢掉教学性的提示、保住进度和能点的按钮。
9. 作为读长选项的人，我希望它折行显示，而不是被截断。

## 实现决定

### §1 区域：`Zone { Options, Input }`

- `Questionnaire.custom_focused: bool`（[`src/render/tui.rs:761`](../../src/render/tui.rs)）换成
  `Zone` 枚举。三个写入点（`press` 的字符分支 [:838](../../src/render/tui.rs)、
  `move_highlight` [:890](../../src/render/tui.rs)、`advance` [:913](../../src/render/tui.rs)、
  `back` [:920](../../src/render/tui.rs)、`select_option` [:938](../../src/render/tui.rs)、
  `focus_custom` [:948-950](../../src/render/tui.rs)、`unfocus_custom` [:953-955](../../src/render/tui.rs)）
  与唯一读点（[:3824](../../src/render/tui.rs)）一起改。
- **Zone 与 `highlight` 正交**：`highlight` 仍然是**选项区里**的位置，越界进输入区**不写进**
  `highlight`。理由：没有选项的题没有下标可写，而「这道题的选项一个都没选」这个状态要能表达。
- **进输入区**：选项区里向下越过最后一项、向上越过第一项（两端**环绕**，今天 `move_highlight`
  是 clamp，[:893](../../src/render/tui.rs)），落点都是 `Zone::Input`。
- **出输入区**：`↑`/`↓` 回选项区并移动高亮（票 34 的行为，保留）；`Esc` 回选项区并同时举起
  「退出询问」的手（§5）。
- **没有选项的题**：`Zone` 恒为 `Input`（构造时就定，见 [:2293](../../src/render/tui.rs)），
  可打印字符直接进文本；`j`/`k`/`Ctrl-N`/`Ctrl-P`/`↑`/`↓` 一律静默——那里没有选项区可回。

### §2 键位分派表

| 键 | 选项区 | 输入区 |
| --- | --- | --- |
| `j` / `Ctrl-N` | 高亮下移（末项之后 → 输入区） | 文本 |
| `k` / `Ctrl-P` | 高亮上移（首项之前 → 输入区） | 文本 |
| `↓` / `↑` | 同上 | 回选项区并移动高亮 |
| 空格 | 高亮项 toggle；全部处理完时**提交** | 文本 |
| `Enter` | 高亮项 toggle；全部处理完时**提交** | 该题已成立时**前进**（§4） |
| `Tab` | 跳过并前进 | 同左 |
| `←` / `→` | 上一题 / 下一题 | 同左 |
| 可打印字符 | **吞掉** | 文本 |
| `Backspace` | **吞掉** | 删一个字符 |
| `Esc` | 第一下举手、第二下退出询问 | 回选项区 **并且**举手（§5） |
| `Ctrl-C` | 取消这次运行 + 举手（页脚给回执） | 同左 |
| 滚轮 | 同 `j`/`k`（能越界进输入区） | 静默 |

- **`j`/`k` 不存在键位冲突**：裸 `j`/`k` 在全局没有任何绑定（只有 `Ctrl-j`/`Ctrl-k`，
  走编辑器的换行与 kill-to-line-end，[:1845-1846](../../src/render/tui.rs) 一带）。
- **`Ctrl-N`/`Ctrl-P` 有既有绑定，但在问卷里是空档**：`map_key` 已经认识它们
  （[:133-134](../../src/render/tui.rs)），编辑器里是历史上下条（[:1845-1846](../../src/render/tui.rs)），
  问卷里今天落 `press` 的 `_ => {}`。于是同一个键在**编辑器 / 选项区 / 输入区**是三处含义，
  这条要进词表（§9）与工具文档。
- **吞掉**（可打印字符与 `Backspace`）是 10-01 那条意向的字面结果：键盘只在光标落到自由文本
  那一项时让给文本。代价是**问卷打开后直接打字不再有效**，得先按一下 `↓`/`j`——这是明确接受的。
- 输入区里 `←`/`→` 维持翻页：问卷的输入区没有行内光标，这不是区域模型的漏洞（§10）。

### §3 答案形状：并存，且单选成 toggle

- **删掉三处互斥**：`type_custom` 里的单选 `selected.clear()`
  （[:903-905](../../src/render/tui.rs)）、`confirm_highlight` 里的 `custom.clear()`
  （[:874-875](../../src/render/tui.rs)）、`answers()` 里的单选清零
  （[:979-983](../../src/render/tui.rs)）。这三处一删，「并存」就是结构性的，不需要新状态。
- **单选语义成 toggle，但集合至多一个**：高亮项**未选中**时确认 = **替换**现有选择（单选仍是单选）；
  高亮项**已选中**时确认 = **取消它**（集合变空）。多选维持今天的 toggle。
  理由：并存之后「替换」不再带来任何编码差异，而保留它就得为「取消已选」另造一个键；
  统一之后单选与多选的差别只剩模型给的 `multi_select` 元信息。
- **清文本靠自己删**：`Backspace` 逐字删，删空之后 `custom` 回 `None`（今天的 trim 逻辑，
  [:977-978](../../src/render/tui.rs)）。不做「清空」快捷键（§10）。
- **编码约定回改**：[`fs-agent-v1/spec.md` §7](../fs-agent-v1/spec.md)
  「**单选**下 `custom` **覆盖**已选（`selected: []`）、**多选**下**补充**」这条改成
  「两者都**并存**交回」；`ask_user_question` 的**工具描述**同改——模型必须从工具描述就读得出
  「`selected` 与 `custom` 可以同时出现」，否则它会当成脏数据。
- **不改的**：「`selected: []` 且无 `custom` = 跳过」、「`answers` 里没有该 `id` = 没走到那题」
  两条约定照旧（§7 原样保留）。
- 牵动的既有测试：`tests/ask_user_question_tui.rs:248`（自定义覆盖单选/补充多选）与其后几条
  断言同一形状的测试。

### §4 `Enter` 的兼职按区域拆

- **选项区**：与空格**完全一致**（在高亮项上 toggle）——第 2 条要的「不用为确认去够 `Enter`」，
  反过来说就是空格能确认；但**全部题都处理完**（`all_handled()`）时 `Enter` 仍然是**提交**
  （保留 [:801-803](../../src/render/tui.rs)）。键盘上唯一的提交路径不该被「等价」吃掉。
- **输入区**：`Enter` = **前进**——当前题已成立（`handled()`：有选择、有文本、或已跳过）时前进
  （今天 [:804-805](../../src/render/tui.rs) 的语义整个移到这里）；未成立时不动。
- **删掉** [:804-805](../../src/render/tui.rs) 在**选项区**的适用：留着它，选了一项再按 `Enter`
  就会前进，而按空格是 toggle，两者立刻不再等价。
- **不再自动前进**：今天单选确认一次就 `advance`（[:808-810](../../src/render/tui.rs)、
  [:820-822](../../src/render/tui.rs)）的两处删掉。翻页留给 `→` 与页脚按钮。
  理由：并存的意义就是「选项和文本可以一起给」，选完就跳走把这个意义取消了一半。

### §5 `Esc` 与两把举手

**归属**：问卷里 `Esc` 只管「退出这次询问」，**取消这次运行完全交给 `Ctrl-C`**
（它今天在问卷里已经举手、第一下 Cancel，[:1472-1476](../../src/render/tui.rs)）。

- **问卷立着时 `Esc` 不再走既有分叉**：今天它按 busy / idle / 禁言分四支
  （[:2445-2476](../../src/render/tui.rs)），改后问卷立着就一律走问卷自己的区域逻辑，与运行状态无关。
  理由：区域模型要的是一套不依赖运行状态的键位；而「退出询问」根本不掐回合（§5 下一段），
  所以禁言那一支要保护的东西在这里不存在。
- **选项区**：第一下**举手**（页脚说「再按一次 esc 退出询问」）；500ms 内第二下 = **退出询问**。
- **输入区**：那一下**同时做两件事**——回选项区**并且**举手。于是任何区域连按两下 `Esc`
  都是退出询问，不用记「先回选项区、再按两下」这种三下的路。
- **退出询问的结果**：`drop` 掉那条 `oneshot::Sender`（今天的 `decline`，[:2462-2463](../../src/render/tui.rs)），
  工具侧于是读到 [`src/render/input.rs:295`](../../src/render/input.rs) 那句「这份问卷没被作答就搁下了」，
  **模型继续跑**，当前回合**不**中止。spec §7 已经定了「`answers` 里没有该 `id` = 没走到那题」，
  而「用户退出询问」与「没走到」是同一件事的两面——不造一条假的「用户跳过」。
- **`Ctrl-C` 在问卷期间**：第一下 `Cancel` **并且**举起**退出**那把（不变），第二下 `Quit`、退出码 130
  （不变，[:1462-1466](../../src/render/tui.rs)）。**新的是回执**：举手期间页脚必须把这句话显示出来
  （「已取消 · 再按一次 ctrl-c 退出」）——今天它被问卷页脚盖掉，屏幕上一个字都没有。
- **两把举手互斥**：举着其中一把时另一把作废。举 `Esc` 那把期间按 `Ctrl-C` **不作数**，
  走 `Ctrl-C` 自己的第一下（清掉旧手 → Cancel → 举起退出手）。理由：退进程是这里最贵的一击，
  不该借一把属于「退出询问」的窗口把它变得更容易；反过来也一样。
  exit-gesture §1 那条「窗口内任意一个键的第二下都退出」是**空闲态两键共用一把**的规矩，
  问卷里是两把不同的手，不适用。
- **实现形状**：`exit_deadline: Option<Instant>`（[:595](../../src/render/tui.rs)）保留为**同一个槽位**，
  旁边加一把「这是哪把」的标签（`Gesture { Exit, DeclineQuestion }`）——互斥于是是结构性的，
  不靠额外规则维持。`exit_gesture_busy: bool`（[:601](../../src/render/tui.rs)）不动。
- **窗口**：把 `EXIT_GESTURE_WINDOW`（[:3504](../../src/render/tui.rs)，测试钉在 [:4884](../../src/render/tui.rs)）
  改名成一个**中性**的常量，两把手势共用，值仍是 **500ms**，不做配置项。理由：两把手势要求人记住
  同一个时间感，各写一个 500 会漂。
- **别的键清旧手**照旧（[:2436-2438](../../src/render/tui.rs)）：举手之后按任何其它键，先清手再照常处理。

### §6 页脚

- **排版**（`draw_questionnaire_footer`，[:3845-3904](../../src/render/tui.rs)）：
  `1 / 3   ←上一题  下一题→  提交   j/k 移动 · 空格选中 · esc 退出询问`。
  可点按钮**紧跟进度**——`hint_region` 越界就丢掉点击区域（[:3907-3915](../../src/render/tui.rs)），
  功能性内容必须最靠左；键位提示垫最后。
- **举手期间最后那一段被替换**（不是追加）：「再按一次 esc 退出询问」/
  「已取消 · 再按一次 ctrl-c 退出」——与 exit-gesture §2「替换出口段」同构。
- **新造一条三档宽度阶梯**（今天没有，见开头第二条纠正），按「先丢教学性的」排序：
  1. 丢 Emacs 别名（`ctrl-n/ctrl-p`）；
  2. 键位提示砍到只剩 `esc 退出询问`；
  3. 只留进度与按钮。
  **举手回执在任何宽度下都保**——它是「刚才那下生效了没有」的唯一回答。
- 文案进 [`src/render/wording.rs`](../../src/render/wording.rs)（`questionnaire_*` 一族）。

### §7 折行与滚动

- **选项与自定义行都折行**（今天 `truncate_columns`，[:2904](../../src/render/tui.rs)、
  [:2917](../../src/render/tui.rs)）。折行宽度按渲染时的可用列宽算。
- **窗口改按渲染行数算**：`option_window_start`（[:2832-2842](../../src/render/tui.rs)）与
  `draw_questionnaire` 里重复的那一遍（[:3789-3802](../../src/render/tui.rs)）一起改——
  今天两处都假设「一个选项占一行」，注释 [:2804](../../src/render/tui.rs)、
  [:2830-2831](../../src/render/tui.rs) 明说了这个前提，**注释要一起改**。
- **高亮项保证完整可见**；它自己就超过可视高度时，从它的**头部**开始画。
- 不做「翻页键」「整页滚动」：选项多于可视高度时窗口跟着高亮走，这是今天的模型，只是换单位。

### §8 焦点视觉

- **同一时刻只有一个视觉焦点**，与 `Zone` 这个单一状态对齐：
  - 输入区聚焦：`自定义：`那一行提亮 + 光标（今天光标只在 [:3824-3838](../../src/render/tui.rs) 给）；
  - 选项区聚焦：高亮项反显；
  - **非当前区域那处降暗**——输入区聚焦时选项高亮不再反显，只留一个暗色标记。
- **保留两处**，不做「两个焦点框」：选项高亮仍然是「回到选项区时落在哪」的答案。

### §9 落点

- [`CONTEXT.md`](../../CONTEXT.md)「提问」节新增两条词条：**选项区**、**输入区**（由
  [ADR 0010](../../docs/adr/0010-questionnaire-keys-dispatch-by-zone.md) 背书）；「作答草稿」条目里
  点明两件事：区域是**问卷级**的、每题共用（它不是草稿的字段），以及 `selected` 与 `custom`
  可以同时成立。
- [`docs/render.md`](../../docs/render.md) 补问卷的键位 / 区域一小节——今天它只在
  [:160](../../docs/render.md)、[:179](../../docs/render.md) 两处顺带提到问卷。
- [`docs/tui-manual-checklist.md`](../../docs/tui-manual-checklist.md) 补**问卷一节**（独立票）：
  分页页脚的降级、折行、自由文本行光标、区域高亮、`Esc` 举手回执，以及「输入区里 `j`/`k` 是文本、
  选项区里是移动」这条分界。
- [`.scratch/README.md`](../README.md) 索引里 `questionnaire-keys` 那行从 seed 改成 spec。
- 回改 [`fs-agent-v1/spec.md` §7](../fs-agent-v1/spec.md) 与 `ask_user_question` 的工具描述（§3）。

### §10 明确不动的部分

- **问卷之外**的 `Esc`（取消）、`Ctrl-C`、`Ctrl-D`、模式循环、`/quit`：全部不变。
- **plain 路径**（[`src/render/input.rs`](../../src/render/input.rs)）：一次一行，表达不了并存，
  维持原样。spec 里写明「并存是 TUI 的能力」，不假装两者是同一个交互。
- `Tab`（跳过并前进）与页脚三个按钮的点击动作：不变。
- 问卷输入区**没有**行内光标：`←`/`→` 仍翻页，`Backspace` 仍只从末尾删。
- **不加** `Ctrl-U`/`Ctrl-W`（清行、删词）与 `Ctrl-J`/`Ctrl-K`：那是另一条意向。
- **不给窗口加可配时长**，不做 `gesture_ms` 一类配置项。

## 测试决定

- **键位与区域**（[`tests/ask_user_question_tui.rs`](../../tests/ask_user_question_tui.rs)）：
  - 选项区 `j`/`k`/`Ctrl-N`/`Ctrl-P`/`↑`/`↓` 移动、两端环绕、越界进输入区；
  - 输入区里 `j`/`k` 落进文本、`Ctrl-N`/`Ctrl-P` 静默、`↑`/`↓` 回选项区并移动；
  - 选项区里可打印字符与 `Backspace` 吞掉（屏幕上不多出字符）；
  - 没有选项的题：可打印字符直接进文本。
- **答案形状**：改写 `:248` 那条（自定义覆盖单选）为并存；新增单选 toggle 两条
  （已选再确认 = 取消；确认另一项 = 替换）与「确认不前进」一条。
- **`Enter`**：选项区与空格等价、`all_handled()` 时提交、输入区里已成立则前进。
- **`Esc`**：改写 `escape_still_cancels_the_run_and_never_answers_the_questionnaire`（[:502](../../tests/ask_user_question_tui.rs)）
  ——它是这次**语义被推翻**的那条：新语义是「双击退出询问、模型继续跑、回合不中止」；
  另加：输入区第一下回选项区（文本不清）并同时举手；超时后第一下作废（直接调 `expire`，不等真实时间）。
- **两把举手**：举 `Esc` 期间按 `Ctrl-C` 不作数（走 `Ctrl-C` 第一下）；举 `Ctrl-C` 期间按 `Esc` 同规矩。
- **退出询问的结果**：drop sender ⇒ 工具读到「没作答」那条 `Err`，且**回合没有** `Aborted`。
- **帧**（[`tests/render_layout.rs`](../../tests/render_layout.rs)）：折行后的窗口按行算（一条超长选项
  占多行时高亮仍完整可见）；页脚三档宽度下的降级顺序；举手期间页脚那段回执；非当前区域降暗。
- **文案**（[`tests/wording.rs`](../../tests/wording.rs)）：页脚键位提示与两句举手回执。
- **手工**（[`docs/tui-manual-checklist.md`](../../docs/tui-manual-checklist.md)）：新增问卷一节。

## 明确不做

- 不做「选项区打字自动搬焦点进输入区」：那正是这次要否掉的行为（§2）。
- 不给输入区加行内文本光标、行内历史（`Ctrl-N`/`Ctrl-P` 在那里静默）。
- 不把「退出询问」做成给模型的合成答案（§5）。
- 不做第二个焦点框、不做「两个区域同时高亮」。
- 不在 plain 里实现并存。
- 不给折叠/翻页加新键。
