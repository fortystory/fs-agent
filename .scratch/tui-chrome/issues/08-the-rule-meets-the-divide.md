# 横线挨着竖线画，不把它截断

Type: implement
Status: done

> 规格：`.scratch/tui-chrome/spec.md` §6（b）。
> 来源：同一条真机反馈的另一半 —— 「输入框的竖线被截断了，改成竖线是贯通的」。

## 目标

主列那两条横线（输入区上方、提示行上方）不再盖住分隔列那一格：它们从**分隔列右边一格**起画，于是左栏与主列之间那条 `┆` 从屏幕顶贯通到底，横线接在它旁边。

## 落点

`src/render/tui.rs`（`draw_shell` 里横线的左端）；`tests/render_layout.rs` 里断言横线与分隔列交点的两处。

## 具体行为

1. **`draw_shell`**：横线的左端从 `panes.divide.unwrap_or(area.x)` 改成

   ```rust
   let left = panes.divide.map_or(area.x, |divide| divide + 1);
   ```

   有左栏时留出分隔列那一格（`┆` 不被 `┄` 覆盖），没有左栏时仍是屏幕左缘 —— `unwrap_or` 那支不能顺手加一，否则无左栏的档位上第一列会空着。
2. **`paint_rule` 本身不改**：签名与字形都不动，变的只是调用方给它的左端。
3. **页签条那两条线本来就是这样**：它们画到 `divide` 为止（不含那一格），所以现在两处一致了 —— 左栏的隔间与主列的两条横线都从竖线**旁边**起笔。

## 测试

- `the_sidebar_has_two_widths_and_a_hidden_third` 里 `frame[(divider, 18)]` 的期望从 `"┄"` 改回 `"┆"`（分隔列在横线那一行仍然是竖线）。
- **新增**：输入区上方与提示行上方那两行，分隔列那一格的符号都是 `"┆"`，而它右边一格是 `"┄"`。
- `transcript_rows()` 的探针不受影响：它找的是 `ends_with('┄')`，横线仍然一直延伸到屏幕右缘。

## 验收

- [x] `cargo test --all` 全绿（44 个套件）。
- [x] 真机：状态行、输入区、提示行那三行左边的 `┆` 与上下其它行的 `┆` 连成连续的一列。
