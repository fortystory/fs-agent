# 按 id 接着跑：`-c <id>` 与 `--session <id>`

`-c` / `--continue` 一直只认「**本工作区最新**的那场会话」。id 于是只有一半用处：它能精确指认一场
会话（`fs-agent sessions show <id>`、退出回执里那一行），但**不能拿它接着跑**。同时开几个工作区的人
想回到其中某一场，只能 `cd` 过去再 `-c`，而「最新」未必是想要的那场。

这次让 `-c` 吃一个可选的 id，并给出显式拼写 `--session <id>`：指名的那一场在**别的工作区**时，
这一趟的工作目录跟着它走（权威依据是那场会话流里 `SessionStarted.cwd`）。

来源：2026-10-02 用户一句话提的需求（「让 `fs-agent -c` 支持 session id，如
`fs-agent -c 20261001T155845Z-7a69cbff`，现在只支持最近一次会话」），随后一轮访谈定下三条分叉。
**它顺带推翻了 [`exit-gesture/spec.md`](../exit-gesture/spec.md) 里的一句判断**（那句说「退出时打
session id 好让 `-c` 直接用」理由不成立）—— 已在那边加日期更正。

## 问题陈述

1. **id 与「能接着跑」之间缺一条路。** 退出回执、`sessions show` 都给出 id，而它指的那场会话除了
   被查看，没有第二条用法。
2. **跨工作区只能靠 `cd`。** 会话桶按 cwd 分（见 `CONTEXT.md` 的**会话桶**），所以「接着跑那场」
   与「在哪个目录里跑」是同一个问题；这正是 `-c <id>` 必须回答工作目录的原因。
3. **`-c` 是布尔旗标，形状上容不下一个 id。**

## 方案

- **形状**（§1）：`-c [<id>]` / `--continue [<id>]` 与 `--session <id>`；不带 id 仍是「最新」，
  两者等价。
- **去哪找**（§2）：先在本桶找，找不到再全 store 找（id 全局唯一）；给的如果是会话目录的路径，
  直接用那个目录。
- **工作目录**（§3）：命中**别的工作区**时，用那场会话自己的 cwd，并说一句；读不出它的 cwd
  （流坏了）就退回请求的目录，且不说那句话。
- **回执**（§4）：退出回执行改成 `会话 <id>；接着跑：fs-agent -c <id>` —— 这一行现在真的粘得回去。

## 用户故事

1. 作为同时开几个工作区的人，我希望 `fs-agent -c <id>` 直接回到那场会话，而不是先 `cd` 过去。
2. 作为刚拿到退出回执的人，我希望那一行能原样粘回终端就把这一场续上。
3. 作为按 id 续上别处会话的人，我希望这一趟的工作目录是**那场会话自己的**，并在屏幕上看到这件事
   被说出来 —— 否则下一步 `ls` 出来的东西与横幅对不上，我会以为是自己敲错了。
4. 作为打错 id 的人，我希望报错里看得见我打的 id、以及它搜过哪儿，而不是被悄悄开一场新会话。
5. 作为一直用 `-c` 续最新那场的人，我希望我的用法一个字都不用改。

## 实现决定

### §1 旗标形状

- `-c` / `--continue` 带一个**可选**的值：后面那个词不以 `-` 开头时它就是 id，否则仍按「续最新」
  解析 —— 于是 `fs-agent -c --plain` 仍然是「续最新 + plain」，不会去找一场叫 `--plain` 的会话。
- `--session <id>` 是同一件事的显式拼写，而它**必须**给 id（缺值、或后面跟一个旗标都报
  `needs_value`）。两个入口都收，因为「续最新」那种简写要短，「指名」要能读出来。
- 解析结果是一个三值枚举（不续 / 续最新 / 续哪一个），不是布尔 —— 布尔容不下 id。

### §2 去哪找

- 先在本桶（`--cwd` 或当前目录那个桶）找；找不到再全 store 找，与 `sessions show <id>` 同一条路
  （id 全局唯一）。
- id 也可以直接写成**会话目录的路径**（`find_session` 一直这么收）：给了路径就用那个目录，
  不经过桶查找 —— 那是「我知道它在哪」的说法，不是「帮我找找」。
- 找不到就报错退出（点名 id、说清搜过哪儿），**不**回退到「新开一场」：`-c` 是接着跑，接不上
  必须说出来。

### §3 工作目录跟谁走

- 命中**别的工作区**的会话时，工作目录取那场会话自己的（它流里第一条 `SessionStarted.cwd`）——
  续写要发生在它自己的目录里，否则工具的相对路径、前缀缓存与横幅全不对。
- 判「在不在请求的工作区里」判的是**桶**（`SessionStore::is_in_bucket`），不是比路径：
  `fs-agent --cwd .` 这样的相对写法与流里记的绝对路径不相等，但它们说的是同一个工作区。
- 读不出桶就当它在**本桶**（保守：宁可少换一次目录，也不凭一次读失败去改工作目录）；读不出它
  自己的 cwd 就退回请求的目录，并且**不说**那句「跟着走了」—— 那时它说的会是假话。
- 跟着走了就在横幅之后加一句「接着跑的是 `<目录>` 里的那场会话」。

### §4 回执与 spec 回改

- `wording::session_receipt` 从「复盘：`fs-agent sessions show <id>`」改成
  「接着跑：`fs-agent -c <id>`」。它由 `discuss` 收尾与交互式退出**共用**，所以讨论会话的回执
  也跟着变 —— 两边都确实能这样续上，这正是共用一个生成器的理由。
- [`exit-gesture/spec.md`](../exit-gesture/spec.md) 那句「『退出时打 session id 好让 `-c` 直接用』
  理由不成立」**保留原文并加日期更正**：那条判断在当时是对的，这次把它反了过来。逐面文档
  （`docs/render.md`、`docs/discussion.md`、`README.md`）同步改成现在怎么工作。

## 测试决定

同既有约定：断言的对象是**契约**（解析出什么、选中哪一场、工作目录落在哪、文案是什么），不是内部
结构；provider 与终端都不需要，因为这一整条路在组装之前就走完了。

**单元（三个 seam）**

1. `parse_interactive`：两种拼写、可选值、旗标不当 id（`-c --plain`）、`--session` 的两条缺值路。
2. `choose_session`（`src/cli.rs`）：新开 / 续最新 / 续最新但桶里没有 / 按 id 本桶命中 / 按 id
   别处命中（cwd 跟着走 + `elsewhere`）/ 按目录路径命中 / 找不到。用真的 `SessionStore` 与临时
   目录，流里手写一条 `SessionStarted`。
3. `wording::session_receipt` 与 `wording::session_followed` 的文案；两份 help 文本点名
   `--continue, -c [ID]` 与 `--session ID`。

**手工**：真机跑过五个出口（在别的工作区用 `-c <id>` / `--session <id>` 续上并看到目录跟过去、
打错的 id、桶里没有可续的会话、回执那一行的形状）—— 断言的是启动路径，pty 脚本管的是 TUI 的
退出路径，两件事互不覆盖。

## 明确不做

- 不做 `-c` 的模糊匹配（前缀、按时间「倒数第 N 场」）：id 要么精确命中，要么报错。
- 不动 `prune`、`sessions` 一族，也不给它们加新旗标。
- 不给「续上一场**已经结束**的会话」加任何特判：会话流本来就是可继续追加的，结束只是最后一条
  收尾事件。
- 不引入全局索引文件：桶结构与「权威 cwd 在 `SessionStarted` 里」这两条不变量都不动。
