# 会话存储形状与 `--continue`

Type: grilling
Status: closed

## Question

决定会话持久化的形状。综述切片 10 把它标为"✅ 可以后置"，但理由是**存储格式一旦落地就难改**——本票要确认 v1 到底包含它，还是只留接口。

要回答：

1. **格式与落盘时机。** 综述的收敛结论：JSONL 追加写、**每条消息立即落盘**（"格式本身不重要，『每条消息立即落盘』才重要"——goose 后期从 `.jsonl` 迁到 SQLite、Gemini 用 JSON，都印证这点）。落在哪个路径？
2. **`--continue` 如何找到最新会话。** 会话与目录绑定吗？（综述：Claude Code 会话与目录绑定，因此可以用 **git worktree** 开并行会话。）这个决定会反过来影响路径布局。
3. **与可观测性的关系。** 综述第 16 节说 transcript 落盘是"完整 transcript（含工具参数与结果）"的实现，且"是第 6 节会话恢复的同一份数据"。确认两者共用一份数据而不是两套。
4. 明确**不做**（综述均已砍）：fork / branch 会话、会话列表 / 检索 / 命名、event sourcing 架构、自建快照系统、SQLite。
5. **一份数据同时服务恢复与调试**这个不变量，是否要求"发送给模型的 messages == 可落盘 trajectory"？（综述切片 2 建议建立这条不变量，引 mini-SWE-agent 的线性历史设计。）

答案定到存储形状、路径策略与落盘时机，不要实现。
