## 词表（CONTEXT.md）

- **状态行（StatusRow）**：改写。去掉「都不可点」，写清现在是五段、模型与档位同生共死、
  那两格可点、运行中点它给回执。
- **思考强度（ThinkingEffort）**：**新词条**。它回答的是「这一场会话让模型想多深」，与
  **权限模式**、**窗口**、**预算**都不是一回事。定义按 spec §1/§5：档位集合是每个模型自己的
  （能力表里那张表），「默认」是一档（不发参数），空表显示 `固定`。要写 `_Avoid_`：
  推理档位（那是**请求参数**的名字）、思考模式（同上，且两家语义不同）、开关（没有那个东西）、
  effort（英文，ADR 0004 那条）。
- **切换（Retarget）** 或 **选择器（Picker）**：至少给**选择器**一条。它是「一块浮层、一列
  候选、`j/k` 移动、回车选中、`Esc` 取消」，与**问卷**的分界是「谁发起」—— 问卷是模型发起、
  答完就是那条工具调用的结果；选择器是人发起、答完回循环改会话属性。`_Avoid_`：
  问卷、选项区（那是问卷里的一个区域）、确认框（那是另一个形状）。
- **控制**一节：把「运行中拒绝」这条立场写进**权限模式**或新加一小段（它与模式手势是两种
  手势 —— 那个是纯渲染器状态、这个要换 provider）。

## 真机清单（docs/tui-manual-checklist.md）

新加一条目（下一号），走查这些点：

1. 状态行五段在 120 / 80 / 60 列下读得下，降级顺序是「先丢模型+档位」。
2. 点模型格弹选择器，选中之后状态行立刻换名，`上下文 n%` 的分母跟着换。

6. 切到缺 key 的模型 → 那一行灰着，detail 点名环境变量，选它没反应。
7. 讨论会话里点状态行那两格 → 一句「不在会话中途换」。
8. 换档之后那条「前缀缓存重来」的回执出现了。
9. 切到另一个 profile（如 `kimi` → `minimax-cn`）之后转录里出现第二个发言者名，且颜色不同。

## 那条 ADR

**留一条 ADR**（`docs/adr/0017-…`）：决定是「**模型与思考强度是会话中途可变的会话值，
走 `FrontEndEvent` + `Picker` 通道，不进事件流**」。

它够 ADR 的门槛：难回头（通道的形状决定了以后「会话中途能改什么」的全貌）、离开上下文会
显得奇怪（为什么模型能换而预算不能）、当初真有替代方案（重启进程换 = 今天的做法；
走渲染流 = 那条路是单向的）。

ADR 里要明写它与 `minimax-provider` 那个 spec 的冲突（spec 的「明确不做」那一段），照
`docs/agents/domain.md` 的要求挑明而不是静默推翻。
