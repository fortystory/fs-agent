# 转录右缘与左栏（prototype）

对应 [转录右缘与左栏](../issues/07-prototype-transcript-edge-and-sidebar.md)。**一次性素材**；对着真终端看：`python3 .scratch/tui-visual-language/prototype/edge-and-sidebar-demo.py`。

## 事实（读代码得到）

- **`TRAILING_COLUMNS = 2` 永远预留**。注释把理由写死了：「画不画都留着，这样文字不会因为转录长高了而重新折行」（`layout.rs:40-42`）。所以「只在需要时画」**已经是**现状：滚动条只在 `pane.total() > track.height` 时才画（`tui.rs:4399`），回合条在空会话里一格都不画（`4365-4368`）——但**列永远在**。
- **滚动条**：`Scrollbar(VerticalRight)`，track 与 thumb 都是 `DarkGray`；thumb 在「回看」时加 `BOLD`（`4403-4409`）。ratatui 的默认字形是 track `│`、thumb `█`。
- **回合条**：普通格 `┊`、焦点格 `┃`（`LightMagenta`+`BOLD`）、截断 `⋮`；每格记一个命中区域（`4374-4394`）。
- **轨迹页的右缘什么都没有**：只有 pane 与右下指示器。它有自己独立的滚动与贴底跟随（[`trace-tab` 票 04](../../trace-tab/issues/04-grilling-scroll-and-follow.md)），却没有位置指示。
- **占比条是 `bg(DarkGray)` 涂出来的**，而同一行的标签是 `fg(DarkGray)`（`panel.rs:183` / `194` / `196`）——**同一个值，一个当字一个当底**。条「不占列」，所以列宽与降级链完全不受它影响。
- **身份标记的品红坡道**（`LightMagenta` → `Magenta`，5 行）不在色板里 —— 它是这次唯一没有归属的色。

## 待拍板 1：右缘那两条并排的一列宽竖线

现状是 `正文 │ 滚动条 track │ 滚动条 thumb │ 回合条` 四列挤在一起，其中滚动条的 track 与紧邻的回合条**是同一族的细竖线**。

| 方案 | 做法 |
| --- | --- |
| **A 滚动条只画滑块** | 把 `track_style` 设成不画；位置靠滑块本身表达，右缘只剩一条连续的轨道感（回合条） |
| B 保持两条都有 track / thumb | 现状 |
| C 合并成一个「导航列」 | 语义不同（位置 vs 回合），合并需要重新定义，成本最大 |

➡️ 推荐 **A**。`TRAILING_COLUMNS = 2` 的预留**不动**（那是防止重新折行的，与画不画无关），改的只是滚动条的轨道要不要上屏。

## 待拍板 2：轨迹页的右缘要不要补上

| 方案 | 做法 | 代价 |
| --- | --- | --- |
| **A 补滚动条** | 与对话视图一致；它有自己的滚动状态，本来就该有位置指示 | 轨迹页从 40/28 列变成 38/26 列（`TRAILING_COLUMNS` 那 2 列） |
| B 什么都不加 | 保持现状，靠右下指示器 | 「我在这条流的哪儿」没有表达 |
| C 两个都补 | 再加回合条 | 38/26 列里再挤一列，且轨迹页本身按回合分段、可以直接滚 |

➡️ 推荐 **A**。[`trace-tab` 票 04](../../trace-tab/issues/04-grilling-scroll-and-follow.md) 明确给了轨迹页**独立的滚动与贴底跟随** —— 有独立滚动就该有位置指示，而回合一格一格的导航在轨迹页上是冗余的（它就按回合分段）。

## 待拍板 3：占比条怎么表达

| 方案 | 做法 | 代价 |
| --- | --- | --- |
| **A 字符条** | `▓▓▓░░░░░░`（前景用 `MUTED`）—— 结构承重，不依赖颜色对比 | 值列被条占掉，数字要另找地方或缩窄 |
| B 底色换亮灰 | `bg(Gray 7)` | 引回第二个灰值，与 05「静音只有一档」相冲 |
| C 保持 `bg(DarkGray)` | 现状 | 条太暗，且它与标签是同一个值 |

➡️ 推荐 **A**：05 定的手段就是「再退一档靠结构」，而这里是结构最该上场的地方 —— 一共 10 列的读数区，用块字符画条比用一整块暗底更清楚，也不引第二个灰。

## 待拍板 4：身份标记的品红坡道（map 的 `尚未明确` 之一）

宽档出现的 5 行 `fs` 标记，颜色从 `LightMagenta` 渐到 `Magenta`。它是品牌标记、不是语义色。

| 方案 | 做法 |
| --- | --- |
| **A 保留坡道，但在色板里给它两个具名条目** | `MARK_BRIGHT` / `MARK_DIM` —— 不留孤儿色，也不强行把它塞进语义体系 |
| B 不归色板 | 继续住在 `tui.rs` 里当特例 |
| C 单色 | 去掉坡道，整个标记一个色 |

➡️ 推荐 **A**：色板的意义是「颜色值集中一处」，标记的坡道也是颜色值；给它具名条目既不破「品牌特例」，又让 `grep Color::` 的结果干净。
