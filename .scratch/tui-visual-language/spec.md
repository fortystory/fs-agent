## 问题陈述

维护者每天自用这个 TUI，屏幕上的样式**没有语言**，于是每一处观感都得临场判断：

1. **同一个语义全屏好几个样子。** `Yellow` 一个色同时当「markdown 行内代码」与「警告」（共 11 种语义）；无名册与 `System` 两种灰（`DarkGray` / `Gray`）；严重度在 TUI 与 plain 各写一套映射、没有任何绑定，还已经漂移了一处（TUI 的 `Bad` 多一个 `BOLD`）。
2. **层级没有判据。** `DarkGray` 一个色扛了 **38 处**语义 —— 旁白、未选中页签、状态行、提示行、滚动条、面板标签、详情页脚……于是「次要」和「次要」之间没有区别，屏幕读起来是平的。想分层次只能凭手感挑颜色，而挑完之后下一处又不知道该怎么办。
3. **框架字形三套并存**：外壳手画 `┄`/`┆`、浮层用 ratatui 的三重虚线（**还带四个实线角**）、markdown 用实线；间距全是手写字面量（按钮之间 3 个空格出现在 4 处）。
4. **改一处观感要读遍六千行。** 颜色散在六个文件，`tui.rs` 一个文件就有 79 处 `Color::` 字面量 —— 没有一个地方能回答「这个语义该长什么样」。
5. **还有债**：退场的动画代码留着（下落短横、色环两版）、`docs/render.md` 与代码有 6 处矛盾（其中一处还在写早就拆掉的「一圈外框」）。（`DiffTag` 那套曾一并列在这里，2026-10-06 定为**保留**，见 §34 的注。）

后果是具体的：维护者说「我想再美化下 TUI 界面」时，**没有办法把这个愿望变成一个可执行的计划** —— 每一处都是孤立的手感问题。

## 方案

把「人眼看到的样式」收进两层，并给层级一条可判定的判据，最后把债收口。

- **一层是语义色板**：颜色值集中一处，绘制代码只引用语义名。界面域收敛到 **7 个条目**，`Yellow` 从 11 种用途降到 3 种。
- **一层是字形语法**：框架一套虚线（`┄`/`┆`，**四角为空**），内容一套实线（`─`/`│`/`─┼─`）；散落的字形收进一张**符号表**。
- **判据一句**：**过程退后、内容保持、信号着色**。它来自代码里那句既有的注释（`narration`：「用暗色，好让模型那个以全亮度渲染的回答成为显眼的东西」）—— 这次只是把意图写成规则。
- **手段收窄**：静音只有一档，再退一档只能靠**结构**（缩进、线型、留白），`DIM` 不参与（调研：它在主流终端至少三套实现方向，浅色主题下可能毫无变化）。
- **顺手收口**：退场死代码删掉，`docs/render.md` 与代码对齐，测试按「钉语义 / 钉色值」分清。

改完之后：「这个语义该长什么样」有一个地方可以回答；改一处观感只动色板或符号表。

## 实现决定

### 色板

1. 新建**语义色板模块**（`src/render/palette.rs`），与 `wording.rs` 同侪；导出以 `Color` 常量为主，需要组合的（如错误 = 红 + 粗）导出 `Style` 构造函数。命名是扁平的英文大写 —— 已在 `palette::` 命名空间下，再加族前缀是冗余。
2. **界面域七个条目**：`PLAIN`（默认前景）/ `MUTED`（`DarkGray`，索引 8）/ `CHROME`（固定深灰 `Rgb(0x4a,0x4a,0x4a)`，**只做装饰线**）/ `ACCENT`（`LightMagenta`，语义是「被系统认出来的 / 当前聚焦的」）/ `WARN`（`Yellow`）/ `BAD`（`Red`）/ `INJECTED`（`LightBlue`，**唯一为某个表面保留的专色**，理由是 `trace-tab` 的三类前缀要分得开）。外加**冻结的角色五色**与**提示符专色**。
   **例外一处**（2026-10-06 落定时记下）：草稿里两个记号颜色 `TOKEN_COMMAND` / `TOKEN_REFERENCE` 仍留在 `tui.rs` 当两个具名常量 —— [`input-tokens` §4](../input-tokens/spec.md) 把它们钉成**两个不同的**颜色（有一条断言钉着），本 effort 不重开那份契约，所以 §6 那句「输入记号用 `ACCENT`」在这两个前缀上不适用。
3. **内容域独立成一套**（markdown 与语法高亮），**允许与界面域撞值** —— 代码块内部上下文明确，`Green` 既是字符串又是成功不会被读混。这是本 spec 唯一的「两套规则并存」，代价显式接受。
4. **`Severity`**：语义归属仍只有 `Severity::of` 一处；色板提供 TUI 用的 `style(severity)`；**plain 的 `Severity::ansi` 输出不动**（它是 plain 可见输出的一部分）。收敛到「共用语义表」为止。
5. 身份标记的品红坡道保留原样，但**进色板当两个具名条目**（`MARK_BRIGHT` / `MARK_DIM`）。

### 层级

6. **判据：过程退后、内容保持、信号着色。**
   - 过程 → `MUTED`：「系统在说它自己干了什么」（旁白、等待提示、工具摘要、迭代号、权限询问与裁决、hook 事件、执行者派生、用量摘要、详情小节与页脚与空态、面板标签、状态行、提示行、问卷页脚、未选中页签、身份行、占位页、过小提示、滚动条、回合条普通格、轮次开始、`Severity::Good` 与 `Note`）。
   - 内容 → `PLAIN`：用户与助手正文、markdown 正文与标题（+`BOLD`）、问卷题面与选项、详情正文、菜单文字、输入区草稿、面板数值、`Notice` 那一类、分歧行（+`BOLD`）。
   - 信号 → `WARN` / `BAD`：诊断、hook 反馈、`Severity::Warn` / `Severity::Bad`、工具失败、会话错误。
   - 焦点 → `ACCENT` + `BOLD`（常驻）或 `REVERSED`（临时光标）；新内容指示器与输入记号用 `ACCENT`。
7. **静音只有一档**。要再退一档只能用**结构**（缩进、线型、留白）。`DIM` 不参与层级。
8. **选中态分两种**：常驻选中（选中页签、回合条聚焦格）= `ACCENT` + `BOLD`；临时光标（菜单光标行、问卷当前项）= `REVERSED`。**问卷的「已选」不用颜色**，只靠 `BOLD` 与已有的 `[x]` / `●` 标记。
9. **`BOLD` = 「这一行领起一块」**，与颜色正交：工具摘要、markdown 标题、问卷表头、轮次开始、详情小节标题。

### 字形与间距

10. **框架档**：`┄`(U+2504) / `┆`(U+2506)，**四个角是空格**（`border::Set` 的角本来就能设，不需要自绘）。
11. **内容档**：`─`(U+2500) / `│`(U+2502) / `─┼─`，用于 markdown 的分隔线、引用条、表格网格，**以及详情里的小节线**。
12. **一张符号表**（一个语义一个具名常量），收进 `wording.rs` 或新的字形模块：`▸`（**有折起来的内容**）、`☐`/`▸`/`✓`（todo 三态）、`❱`（提示符）、`┃`/`┊`/`⋮`（回合条焦点/普通/截断）、问卷四符、`…`（行内截断）、`┆`（状态行三段分隔）。**`▸` 的双义（转录 vs todo 页）靠区域区分，并在表里明写**。
13. **`▸` 的判据 = 谁把内容折起来谁就有**：思考行、工具行、**上下文注入行**、**轨迹视图的消息行**都有；**对话视图的消息行**已显全文，不给。
14. **三个字符级间距常量**（住 `wording.rs`，不新起体系）：`INDENT`（2 格，**附属行的缩进**）、`GAP`（3 格，**并列控件之间的距离**）、`SEP`（`" · "`，一行里各条目的分隔）。菜单的 1 格内边距与前缀后的 1 个空格**不立常量**（各只出现一次）。
15. **两套居中机制都保留**（`Alignment::Center` 与手算 `centred_inset`）：它们不是同一需求的两份实现 —— 手算那套还担着「命中测试与绘制必须是同一份算术」。把理由从注释提升为显式说明，避免被当遗留删掉。

### 底部三条

16. **提示行跨整屏**：它的矩形从「主列宽」改成整屏宽；**左栏因此不再全高**，画到提示行上一行为止；左栏与主列之间那条竖虚线同样收短。**代价：左栏页区少 1 行**（120×24 下 15 → 14；页高的公式不变）。
17. **状态行四段**：模型 / 模式 / 上下文占比 / **状态词**。行内分层：标签用 `MUTED`、值用 `PLAIN`、分隔符用 `CHROME`。**降级顺序重排**为「先丢模型、再丢模式，最后剩**上下文 + 状态词**」——「在跑」最后才丢。
18. **状态词从提示行移到状态行**（提示行只留键位提示与出口）；提示行不再有「打头的状态词」这一档。
19. **输入区草稿去掉整段 `BOLD`**：草稿归 `PLAIN`，提示符 `❱` 仍是界面上唯一会动的专色、唯一焦点。
20. **上下文占比不加阈值色**：它是读数、不是事件。

### 转录与左栏

21. **滚动条只画滑块、不画轨道**；`TRAILING_COLUMNS = 2` 的预留**不动**（它的理由防的是「转录长高后文字重新折行」）。
22. **轨迹视图补滚动条、不补回合条**：它有自己的滚动与贴底跟随，有独立滚动就该有位置指示；回合条那种「一格一跳」的导航在轨迹页上是冗余的（它本就按回合分段）。**正文宽度因此 38 / 26 列**。
23. **转录在换发言者时空一行**，同一人连发的块不拆散。**实现位置是块序列生成期**（与轨迹页隔行底色同一个位置的做法），不是绘制期 —— 于是两个视图各自决定，且滚动时不重排。
24. **左栏用量页的占比条改用块字符**（`▓▓▓░░░░`，前景 `MUTED`），不再用底色。注意它**占列**（现在的底色实现不占列），列预算与降级链要重算。

### 覆盖层与问卷

25. **四个表面共用一套框架**：`CHROME` 虚线 + 空角。框色**只剩 `CHROME` 一个**（问卷没有框）。
26. **模态拆成三件事**：边框 `CHROME` + 空角、正文 `PLAIN`、按钮行 `ACCENT`（键名 `BOLD`）。
27. **菜单去黄**：未选中行 `PLAIN`、光标行 `REVERSED`。
28. **详情的发言者色从整个框缩到标题行**（意图「不读一个字就知道是谁的行」没丢 —— 标题就在框内第一行），边框归 `CHROME` + 空角。
29. **问卷：全屏唯一的 `REVERSED` 就是键盘所在** —— 选项区聚焦时在选项行、输入区聚焦时在自定义行。**不再有 `DIM`**，也不再有两处同时表达焦点。

### 在跑

30. **状态词带一个字形循环** `◐ ◓ ◑ ◒`（由脉冲时钟驱动，与提示符的色相共用同一个计数器）。**不靠颜色、不靠 `DIM`**；退化时换 ASCII `| / - \`（那四个码位与框架线同为 Ambiguous 宽度）。
31. **空闲时也动，但更慢**：运行中约每 8 帧换一格（≈0.5 秒一圈），空闲约每 32 帧（≈1.9 秒一圈）。帧数留给实现期对着真终端定，这里定的是量级与它的存在。
32. **脉冲时钟从「仅运行时武装」放宽到「始终」**。**这是本 spec 最贵的一笔**：空闲不再是零唤醒。
33. 提示符的 24 位色相呼吸**保留不动**；**下落短横仍不上屏**。

    **`highlight::DiffTag` 整套（`diff_tag` / `highlight_diff` / `ansi_line`）不删**（2026-10-06 定）：它确实没有调用方，但它与本节原来的写法、§测试决定里「diff 的三处 ANSI 字节」被**明确保留**、以及票 16「不动 diff 那套独立的 ANSI 表（它是 plain 与未来的 diff 视图共用的）」三处相抵；保留，实现票 19 已同步回改。

## 测试决定

**唯一 seam：逐格缓冲快照。** 把一整帧渲染到 ratatui 的 `TestBackend`，读回 `Buffer`，断言每一格里是什么字符、什么 `Style`（前景 / 背景 / 修饰符）。**不新增 seam。**

- **为什么是它**：这次改动 100% 是「屏幕上的差异」（颜色、字形、间距、空行、布局、层级），而这正是这个 seam 测量的东西；再往上只有真的开 pty 读终端字节，那只能验启动帧、验不了观感。**prior art 足够厚**：`tests/render_layout.rs`（42 处断言站点）、`tests/render_tui.rs`（17）、`tests/render_markdown.rs`（20）、`tests/wording.rs`（3）、`tests/render_editor.rs`（1），另有 `tests/ask_user_question_tui.rs` 与 `tests/history_replay.rs` 用同一套夹具。
- **什么算好测试**：断言「屏幕上的这一格是 `palette::MUTED`」，**不是**「`palette::MUTED` 等于 `DarkGray`」。前者钉语义、改色板时不动；后者钉色值、是噪音。调研把现有 89 处断言站点分成了两类（钉语义 80 / 钉色值 9），实现期按这个口径新增与改写。
- **明确保留的「钉色值」断言**：提示符第 0 帧的精确 RGB（它是契约）、plain 的 `Severity::ansi` 三处 ANSI 字节（plain 的可见输出）、diff 的三处 ANSI 字节。**随死代码删掉的**：退场色环的色彩清单与「屏幕上没人穿它」那两条。
- **平台级验证不在 `cargo test` 里**：真终端的观感（呼吸快慢、字形是否等宽不跳、状态行加一段后 80 列窄档读不读得下、左栏短一行的观感、`CHROME` 深度）走 `docs/tui-manual-checklist.md`，本轮要在 ②/⑪/⑫/⑮/⑯/⑳/㉕ 留下实测记录。`scripts/tui-startup-check.py` 的三个字形锚点（`▄▀▀█` / `┄` / `┆`）**本 spec 一个都不改** —— 它不该红。
- **验收基线**：动手前先实测一次 `cargo test --all-targets` / `cargo clippy --all-targets` / `cargo fmt --check` 并把数字写进第一张实现票（决策图 charting 时**没有跑过**）。

## 明确不做

- **主题 / 配色配置项与 truecolor**：[`tui-ux/map.md`](../tui-ux/map.md) 明确不做的第 3 条仍在；色板是代码里的语义层，不是运行期可配的主题。
- **角色五色的重开**：`tui-ux` 冻结项 9 定的五色不动。
- **plain / headless 的呈现改动**：管道化输出保持逐行、无颜色；`Severity::ansi` 只收敛「语义来源」，输出不变。
- **下落短横接回渲染路径**：「真机上看下来不好看」这条记录没有被本 spec 推翻。
- **`文件` 页签的内容**：仍留给另一个 effort（本 spec 只碰它的占位行外观）。
- **键位、手势与命中行为**：只改视觉表达。唯一的例外是提示行跨屏带来的矩形变化，那是布局不是交互。
- **跨视图联动、左栏宽度档、`Ctrl-O` 意愿、轨迹页隔行底色**：都是既有 spec 的契约，只调色值。
- **浅背景终端的适配**：色板已选 `DarkGray` 当静音档并写下了代价（浅色主题下可能贴背景）；「浅色主题下可读」**没有**被写成验收项，留作待定。
- **详情覆盖层里正文本身的排版**（markdown 在 135 列上限里怎么排）：本 spec 只覆盖它的框架与层级。
