# 18 — 「在跑」：状态词的字形循环与空闲时钟

Type: implement
Status: ready-for-walkthrough
Part of: ../map.md
Blocked by: 11

> 规格：[`../spec.md`](../spec.md) 实现决定 §30–§33。
> **这是本轮最贵的一张票**：它推翻 [`tui-input-pulse`](../tui-input-pulse/spec.md) 的两条「明确不做」，其中一条动的是**唤醒模型**。

## 目标

「在跑」这件事有一个**会动的、在永远在场那一行上的**信号；空闲时那个信号也在，只是慢下来 —— 屏幕不再是死的。

## 现状（改前先复核）

- 屏幕上**唯一在动的东西**是提示符 `❱ ` 的 24 位色相呼吸，而且**只在一次运行进行中**才动（注释：维护者说过「一个在他们打字时手底下动来动去的颜色是噪声、不是生命」）。
- 空闲会话回到 `select!` 的三个来源，**一次唤醒都没有**。
- 既有 spec 明确不做：**「输入区以外任何忙碌动画都不取」**、**「空闲时没有时钟」**。
- **下落短横**已退出屏幕（真机上看下来不好看），代码与它自己的单元测试留着。

## 落点

- `src/render/tui.rs`：状态行的绘制、脉冲时钟的武装条件、`prompt_colour` 旁边新增的字形循环。
- `src/render/wording.rs`：状态词。
- `docs/render.md`、`docs/tui-manual-checklist.md`：跟着改。
- `../tui-input-pulse/spec.md`：**回改那两条「明确不做」**。

## 具体行为

1. **状态词前加一个字形循环**：`◐ ◓ ◑ ◒`，由**脉冲时钟**驱动（与提示符的色相共用同一个计数器）。**不靠颜色、不靠变暗**；退化时换 ASCII 的 `| / - \`（那四个码位与框架线同为 Ambiguous 宽度）。
2. **运行中约每 8 帧换一格（≈0.5 秒一圈），空闲约每 32 帧（≈1.9 秒一圈）**。具体帧数实现期对着真终端定；本票要保证的是**量级与「空闲也有」这件事**。
3. **脉冲时钟从「仅运行时武装」放宽到「始终武装」** —— 空闲不再是零唤醒。这是本票最贵的一笔，回改 spec 时要把它写在明面上。
4. **提示符的 24 位色相呼吸保留不动**；**下落短横仍不上屏**（「真机上不好看」那条记录**没有**被推翻 —— 本票要的不是它）。
5. **回改既有 spec**：把 `tui-input-pulse` 的两条「明确不做」划掉并写明被谁推翻、为什么 —— 那条禁令当年针对的是**给静态元素加装饰**，而本票加的是**一个新的信息通道**；「手底下动」那句针对的是**输入区**，而本票的动在输入区**上方**。

## 验证

1. 逐格缓冲快照：跑若干帧，**变化的格子必须恰好是「提示符占的两格 + 状态行状态词那几格」** —— 左栏的标记仍然逐帧相同。
2. **改写 `tui-input-pulse` 那条「变化的格子必须恰好是提示符两格」的断言**：它现在错了，实现前先改它并让它红一次，再让它绿。
3. 静态帧断言：**空闲**（没有运行）时状态词那几格**也**在变，且比运行时慢。
4. 真终端：手工清单 **⑮ / ⑯** 补三条 —— 空闲呼吸是否慢到不烦人、字形在所用字体里是否等宽不跳、状态行加一段后在 80 列窄档还读不读得下。

## 不做什么

- **不动输入区**（它仍然完全静止 —— 那是被保住的那半条决定）。
- 不把下落短横接回渲染路径。
- 不改提示符色相的速率、饱和度、明度与帧长。
- 不做任何**配置项**（快慢、开关都不是配置，是常量）。
