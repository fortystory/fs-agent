# 字形语法的两档（含浮层框）

Type: prototype
Status: resolved
Part of: ../map.md
Blocked by: 01

## 问题

[图](../map.md) 冻结项 4 定了「框架一套虚线、内容一套实线」，但今天屏幕上其实有**三套**语法并存，要把它们归位并落到具体字符：

- **框架档**：外壳竖线 `┆`、横线 `┄`（`src/render/tui.rs:3736-3755`）、页签条上下两条 `┄`（`3859-3916`）、轨迹页单位分隔线（`5296-5300`）、三个浮层的边框（模态与详情用 ratatui `LIGHT_TRIPLE_DASHED`，`4023` / `4777` / `5939`）、详情里的小节线 `── 思考 ──`（`wording.rs:318`）。
- **内容档**：markdown 主题分隔线 `─`（`markdown.rs:161-166`）、引用条 `│`（`markdown.rs:402-404`）、表格网格 `─┼─`（`markdown.rs:757`）。
- **归不了档的**：浮层边框要不要与外壳同一套（`LIGHT_TRIPLE_DASHED` 与手画的 `┄` 是不是同一个字符）？详情小节线算框架还是内容？markdown 的引用条 `│` 与外壳的 `┆` 语义上都是「区隔」，只是粗细不同 —— 这个区别是刻意的还是巧合？
- **符号表**：`▸`（可点标记）、`☐ / ▸ / ✓`（todo 三项）、`❱`（提示符）、`┃ / ┊ / ⋮`（回合条）、`> [x] [ ] ● ○`（问卷）、`⋮`（截断）。要不要一并收进一张符号表？**同一语义要不要同一个符号**（例如「可点」今天只在思考行与工具行有 `▸`，而同样可点的上下文注入行与消息行没有）？

## 产物

`.scratch/tui-visual-language/prototype/glyph-grammar.md`：两档各自的字形集合、**每个屏幕位置的归属表**（现状 → 归哪档 → 结论）、符号表（现状 → 归属）。附至少一帧对照草图片段（可用真渲染器的 TestBackend 快照，也可以手绘；不必接进产品代码）。

## 接受的边界

- **下落短横 `▀` 不在字形表里** —— 它已退出屏幕（`src/render/tui.rs:3785` 传 `mark_lines(None)`），[图](../map.md) 明确不做它；
- `CHROME_LINE` 那个**色值**不归本票（那是 [语义色板](03-prototype-semantic-palette.md)），本票只管**字形**；
- 字符必须落在 [终端能力边界](01-research-terminal-capability-bounds.md) 证实过的宽度与显示范围内。

## 已查明的硬约束（来自 01 与 02，2026-10-05）

- **`scripts/tui-startup-check.py` 钉的是字形与数量，不是颜色**：`MARK_ROW = "▄▀▀█"`（L76，用于 L738）、`BORDER_H = "┄"`（L81）、`BORDER_V = "┆"`（L82），判据是全屏横 / 竖虚线各 **≥3**（L740-746）。**换字形或改虚线密度会让它直接红**（改颜色不会）。
- **字形断言还散在两处**：`todo` 的 `☐ / ▸ / ✓` 由 `src/render/wording.rs:1643-1645` 定义，被 `tests/todo.rs` 与 `tests/render_layout.rs:3119/3142/3184/3263` 钉住；标记字形与 `❱` 在 `tests/render_layout.rs` 与 `tests/wording.rs` 里。
- **浮层与外壳在横竖上本就是同一码位**：`border::LIGHT_TRIPLE_DASHED` 只换横竖，四角与 T 形交叉仍是实线（`ratatui-core/src/symbols/line.rs`）。「两者同档」要处理的是**角**，不是换字符。
- **字形宽度不是 Unicode 保证**：`┄ ┆ ─ │` 全是 Ambiguous（A）；本机实测 Liberation Mono 有 `─` 而没有 `┄` / `┆`，但 Alacritty 与 xterm.js 默认自绘 U+2500–U+259F，风险被终端兜住一部分。

## 作答

**已解决（2026-10-05，HITL：维护者看完三处对照后拍板）**。产物：[`prototype/glyph-grammar.md`](../prototype/glyph-grammar.md) 与可跑的真终端对照 `prototype/glyph-demo.py`。

### 决定

1. **浮层的角 = 空角**（`border::Set` 的四个角设成空格）。框架档的全部字符因此都来自 U+2500 块，也**不需要自绘**。**代价**：四角开口 —— 但虚线框本来就是开口的。
2. **详情小节线留实线**（`── 思考 ──` 归内容档）。**判据**：分档看**这根线在分什么**，不看它待在哪个容器里 —— 浮层里既有框架线（边框，虚线）又有内容线（小节，实线），正是两档的意义。
3. **立一张符号表**（一个语义一个具名常量）。**`▸` 不拆**：todo 页的「进行中」与转录里的标记靠**区域**区分，并在表里把这条双义明写出来。**`▸` 的语义定为「这里有折起来的东西」**，因此注入行与消息行**不加**它 —— 它们显示的是全文、没有折叠；这样「可点标记时有时无」就不是不一致，而是两个不同的语义。

### 两档定稿

| 档 | 字形 | 位置 |
| --- | --- | --- |
| **框架** | `┄`(U+2504) / `┆`(U+2506)，**角为空** | 外壳竖横线、页签条、轨迹页单位分隔、浮层边框（四角空格） |
| **内容** | `─`(U+2500) / `│`(U+2502) / `─┼─` | markdown 分隔线、引用条、表格网格、**详情小节线** |

### 符号表（内容）

| 符号 | 语义 |
| --- | --- |
| `▸` | **有折起来的内容**（可点开详情）—— 只在思考行与工具行 |
| `☐` / `▸` / `✓` | todo 三态：待办 / 进行中 / 已完成（`▸` 的双义，靠区域区分） |
| `❱` | 输入区提示符 |
| `┃` / `┊` / `⋮` | 回合条：焦点 / 普通 / 截断 |
| `> [x] [ ] ● ○` | 问卷：光标 / 选中 / 单选 |
| `…` | 行内截断（轨迹页消息） |
| `┆` | 状态行的三段分隔（与外壳竖线同码位、语义不同，明写） |

### 补记（2026-10-05，[层级语言与选中态](05-grilling-hierarchy-and-selection.md) 关闭后回改）

**本票「决定 3」里的一条判据写错了，以本节为准。**

原文说「注入行与消息行显示的是全文、没有折叠」—— **注入行那半句与代码事实不符**：`Block::ContextInjected` 的绘制注释明写「这条记录**点得开**：转录上只有一行来源名，加载数据本身在详情里」（`src/render/tui.rs:5258-5259`）。它和工具行一样是**折叠**的。

修正后的判据：**谁把内容折起来了，谁就有 `▸`**。

| 行 | 折起来了吗 | `▸` |
| --- | --- | --- |
| 思考行 / 工具行 | 是 | ✓（原判不变） |
| **上下文注入行** | **是**（来源名 + 详情全文） | **新增 ✓** |
| **轨迹视图的消息行** | **是**（首行 + `…` + 详情全文） | **新增 ✓** |
| 对话视图的消息行 | 否（已显全文） | 不给 |

`▸` 的语义仍是「这里有折起来的东西」，没有变；变的是哪些行符合它。
