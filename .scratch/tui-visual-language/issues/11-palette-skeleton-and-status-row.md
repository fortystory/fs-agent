# 11 — 语义色板的骨架与状态行（tracer bullet）

Type: implement
Status: done
Part of: ../map.md
Blocked by: —

> 规格：[`../spec.md`](../spec.md) 实现决定 §1–§9（色板与层级）与 §16–§18（状态行的那半）。
> **这是本轮的 tracer bullet**：它把「色板定义 → 绘制代码 → 测试断言 → 真终端」这条路径整个走通一遍，后面每张票都照它的样子走。所以它挑的是**最窄的一条线**（一行），而不是最容易的一条。

## 目标

底部那一行变成四段——`模型 / 模式 / 上下文 / 状态词`——并且三段之间**终于有层次**：标签退后、值靠前、分隔符只是线。「在跑」不再藏在提示行里（那里它会被宽度阶梯丢掉），而是住在**永远在场**的那一行。

## 现状（改前先复核）

- 状态行整行一个 `DarkGray`（`tui.rs` 的 `draw_status`），三段只靠 `│` 分，**这一段里没有任何层级**。
- 状态词（`工作中` / `就绪`）住在**提示行**最前面（`wording::status_line` 的 state 参数），而提示行的阶梯**放不下就把它丢掉** —— 80 列屏根本看不见。
- 颜色散在六个文件；`tui.rs` 一个文件 79 处 `Color::` 字面量。没有一处能回答「这个语义该长什么样」。

## 落点

- 新建语义色板模块（`src/render/palette.rs`，与 `wording.rs` 同侪）。
- `src/render/tui.rs`：`draw_status` 与提示行的绘制。
- `src/render/wording.rs`：`status_row` / `status_line` / `status_word` 的归属。

## 具体行为

1. **色板骨架**：界面域七个条目（正文 / 静音 / 框架线 / 焦点 / 警告 / 错误 / 注入专色）+ **冻结的角色五色** + 提示符专色。**内容域不在本票**（它归[内容域](16-content-domain-markdown-and-syntax.md)）。命名是扁平的英文大写。
2. **状态行四段**：`模型 X │ Y │ 上下文 n% │ 状态词`。行内分层：**标签用静音、值用正文、分隔符用框架线**。
3. **降级顺序重排**：先丢模型、再丢模式，**最后剩「上下文 + 状态词」** —— 「在跑」最后才该丢。
4. **状态词从提示行移到状态行**：提示行不再有「打头的状态词」这一档（提示行的**跨屏**是[下一张票](12-hint-line-spans-the-screen.md)，本票不动它）。
5. 本票新增或改动的绘制代码**只引用色板常量**，不新增 `Color::` 字面量。

## 验证

1. **先实测验收基线**并把数字写进本票：`cargo test --all-targets`、`cargo clippy --all-targets`、`cargo fmt --check`（charting 期间**没有跑过**，spec 的測試决定里已交代）。
2. 逐格缓冲快照：状态行四段的字符与样式（标签 / 值 / 分隔符三档各断言一次）；窄档降级到「上下文 + 状态词」。
3. 断言**引用色板常量**，不钉色值 —— 这是本轮所有票共同的纪律（调研已把现有 89 处断言分成「钉语义 80 / 钉色值 9」）。
4. 真终端：手工清单 **⑮** 补一条 —— 状态行加一段之后，80 列窄档还读不读得下。

## 不做什么

- **不做提示行跨屏**（[12](12-hint-line-spans-the-screen.md)）。
- **不做字形循环与空闲时钟**（[18](18-busy-spinner-and-idle-clock.md)）—— 本票的状态词是静止的。
- 不动转录、左栏、浮层、内容域。
- 不引入主题配置，也不让色板带运行期状态（它是常量表）。
