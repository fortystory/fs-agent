# 层级语言与选中态

Type: grilling
Status: resolved
Part of: ../map.md
Blocked by: 03

## 问题

[图](../map.md) 冻结项 3 定了「收敛：减色，层级交给 `dim`/`bold` 与留白」。这是一句方向，不是一个可判定的规则 —— 本票把它落成规则，于是后面每张形态票都不用再各自猜。

要定：

- **静音分几级**。今天只有「有颜色 / 没颜色」两档，而 `DarkGray` **一个色承担了 38 处（`Color::DarkGray`，含 `ratatui::style::Color::` 写法）完全不同的语义**（旁白叙述、未选中页签、身份行、滚动条、状态行、提示行、问卷页脚、面板标签、详情页脚与空态、等待提示、工具摘要……）。收敛后「次要」要分几层？（例如：正文 = 默认前景色；次要 = `DIM`；再次要 = `DIM` + 结构（缩进 / 括号）而非更多颜色。）层数太多等于没收敛。
- **哪些语义降为静音**：旁白叙述、等待提示、工具摘要、详情小节标题与页脚、面板标签与占比条、状态行、提示行、滚动条与回合条 —— 各自归第几层？
- **哪些必须保留颜色**：严重度四档、工具失败、警示与诊断、上下文注入行、五类角色名。有没有要新增的（今天没有颜色的语义里，有没有哪个其实该有）？有没有要**去掉**的（今天有颜色但其实该静音）？
- **选中与高亮统一**。今天有五种不同画法，它们背后是不是五种语义？
  - 页签选中：`LightMagenta` + `BOLD`（`tui.rs:3890-3893`）
  - 回合条聚焦格：`LightMagenta` + `BOLD`（`4371-4373`）
  - 菜单选中行：反色 `Black on Yellow` + `BOLD`（`4809-4820`）
  - 问卷已选：`Yellow` + `BOLD`（`3580-3583`）
  - 问卷当前高亮：选项区 `REVERSED`、输入区 `DIM`（`3587-3594`）
  后两种尤其可疑：`DIM` 在 [终端能力边界](01-research-terminal-capability-bounds.md) 的结论下可不可靠？
- **「可点」的统一标记**：`▸` 今天只在思考行与工具行有（`2326` / `5356`），而同样可点的上下文注入行（`5263-5275`）与消息行（`5414-5426`）没有。三种都真的可点吗？可点要不要一个统一标记？
- **`BOLD` 的用法**：输入区草稿整段 `BOLD`（`4514-4517`）—— 这是「可输入」的语义，还是遗留？（charting 穷举把它列为「未能确定语义」。）

## 接受的边界

- **不重开角色五色**（[`tui-ux/map.md`](../../tui-ux/map.md) 冻结项 9）；
- 不改键位与交互语义，只改视觉表达；
- 层级要能用上 [语义色板](03-prototype-semantic-palette.md) 的常量与 [终端能力边界](01-research-terminal-capability-bounds.md) 的可靠性结论。

## 已查明的硬约束（来自 [终端能力边界](01-research-terminal-capability-bounds.md)，2026-10-05）

调研已经把三条前提钉死了，本票不得再假设相反的东西：

- **`DIM` 不可承重。** 它在主流终端里至少有三套互不兼容的实现方向（变暗前景 / 向背景混合 / 改背景不透明度），浅色主题下甚至可能毫无变化；而 SGR 22 会**同时**清掉 `BOLD` 与 `DIM`，两者不能当两级并存。所以「次级」只能主要落在**留白、缩进、缩排与线型**上 —— `BOLD` 用于「主」，颜色与 `DIM` 只做点缀。这正是冻结项 3 里「与留白」那半句该被读成的意思。
- **`DarkGray` 不适合作「中灰」承重。** 它落到 `38;5;8`，实际 RGB 由终端主题决定，浅色主题下可能贴近背景。需要「比正文淡」时，优先考虑 `Color::Reset` 的默认前景 + 结构差异（缩进 / 线型 / 括号），而不是换一个更灰的灰。
- **`Gray` / `DarkGray` 的取值不是 ratatui 文档表上的 37 / 90**，线缆上分别是 `38;5;7` / `38;5;8`；两者的对比在 Alacritty 默认主题下只有 3.74:1，**不足以单独承担两级信息层级**。

## 来自 [语义色板](03-prototype-semantic-palette.md) 的输入（2026-10-05）

色板已经拍板，它把本票的手段收窄了：

- **静音只有一档**，值 `DarkGray`（索引 8），即 `MUTED`。所以「次要」不能再分两级；要再退一档只能用**结构**（缩进、线型、括号），不能用第二个灰。
- **可用手段只剩四种**：`PLAIN`（默认前景）/ `MUTED` / `BOLD` / 结构。`ACCENT` 归选中与记号、`WARN` 与 `BAD` 归信号，都不参与层级。
- **`Severity::Good` 与 `Note` 已经归 `PLAIN`**（没有颜色）。本票要确认：**「正常完成」只靠文字判断够不够**？如果不够，给它一个**非颜色**的标记（字形或前缀），而不是把绿色还回来。
- **`ACCENT` 的语义被定为「被系统认出来的 / 当前聚焦的」**（选中页签、回合条聚焦、菜单选中、`/` 与 `@` 记号）。本票要检查今天那五种「选中」画法能否都收进这一个语义 —— 收不进去的必须说清为什么。

## 来自 [字形语法的两档](04-prototype-glyph-grammar.md) 的输入（2026-10-05）

- **`▸` 的语义已经定为「这里有折起来的东西」**，不是「这一行可点」；注入行与消息行**不加**它。本票若想用符号表达「可点 / 选中」，不能拿 `▸` 当通用标记，要么用它原本的语义、要么另立一个。
- 符号表已立：`▸` / `☐ ▽ ✓` / `❱` / `┃┊⋮` / 问卷四符 / `…` / `┆` 各有一个具名常量。**「选中态」在字形层面没有专用符号** —— 今天靠颜色（`ACCENT`）与 `REVERSED` / 反色底表达。本票要决定这是否够。

## 作答

**已解决（2026-10-05，HITL：grilling 三轮，全部由维护者拍板）**。

### 决定

1. **层级判据（一句话、可判定）：过程退后、内容保持、信号着色。**
   - 「系统在说它自己干了什么」→ `MUTED`；
   - 「用户与模型说的话」→ `PLAIN`；
   - 「要你注意的」→ `WARN` / `BAD`。

   依据不是偏好：`narration` 的既有注释写着「用暗色，好让模型那个以全亮度渲染的回答成为显眼的东西」—— 这个意图今天只活在一句注释里，现在它是规则。
2. **静音只有一档**（`MUTED` = `DarkGray` 索引 8）；要再退一档只能用**结构**（缩进、线型、位置），不能用第二个灰。`DIM` 不参与层级（[终端能力边界](01-research-terminal-capability-bounds.md)：三套实现方向、浅色主题可能无效）。
3. **`Severity::Good` 与 `Note` 归 `MUTED`** —— **修正 [语义色板](03-prototype-semantic-palette.md) 的 `PLAIN` 原案**：它们是过程行，正常完成不该抢注意力；`Warn` / `Bad` 保持颜色。
4. **选中态分两种**（这是本票对五种画法的收敛）：
   - **常驻选中**（「当前是这个」）→ `ACCENT` + `BOLD`：选中页签、回合条聚焦格；
   - **临时光标**（「回车会选它」）→ `REVERSED`：菜单光标行、问卷当前项。**不用 `DIM`**；
   - **问卷「已选」去掉黄色** → `BOLD` + 已有的 `[x]` / `●` 标记就够（它不是焦点，是用已确认的答案，多选时可以有多个）；
   - **菜单文字去掉黄色** → 内容档 `PLAIN`（菜单不是警告）。
5. **`BOLD` 只表示「这一行领起一块」**，与颜色正交：工具摘要、markdown 标题、问卷表头、轮次开始、详情小节标题。**输入区草稿的整段 `BOLD` 不构成层级**，由 [底部三条](06-prototype-bottom-three-rows.md) 去掉。
6. **三处边界按判据定案**：
   - `Notice` 那一类 → **内容档 `PLAIN`**（[`trace-tab`](../../trace-tab/spec.md) 把它整类留在对话视图，理由正是「说给用户听的」）；
   - **分歧行** → `PLAIN` + `BOLD`（`!! ` 前缀已经标记了它）—— 从 `Magenta` + `BOLD` 降下来；
   - **轮次开始** → `MUTED` + `BOLD` —— 从 `Cyan` + `BOLD` 降下来。
   - **例外（维护者点名保留）：上下文注入行保留专色** → 色板新增条目 `INJECTED = LightBlue`（索引 12）。理由是 [`trace-tab/spec.md`](../../trace-tab/spec.md) §2 例外二**明写**了「注入行与别的叙述行同灰，于是注入 / 用户 / 助手在轨迹页上分不开」。
7. **「N 行新内容 ↓」指示器 → `ACCENT`**（从 `Yellow` + `BOLD` 移走）：它不是警告，是「当前状态：你不在最新处」。**黄从此只留给诊断、hook 反馈与 `Severity::Warn`。**
8. **修正 04 的符号判据**：`▸` = 「这里有折起来的东西」，所以**上下文注入行**（一行来源名 + 详情全文）与**轨迹视图的消息行**（首行 + `…` + 详情全文）都该有它；**对话视图的消息行**已显全文，不给。

### 落到屏幕的三档全表

| 档 | 值 | 内容 |
| --- | --- | --- |
| **内容** | `PLAIN` | 用户与助手正文、markdown 正文与标题（标题 + `BOLD`）、问卷题面 / 选项 / 自定义行、详情正文、菜单文字、输入区草稿、面板数值、`Notice` 那一类、分歧行（+ `BOLD`） |
| **过程** | `MUTED` | 旁白（Sandbox / History / Notice 之外的那类）、等待提示、工具摘要、思考完成、迭代号、权限询问与裁决、hook 事件、执行者派生、用量摘要、详情小节 / 页脚 / 空态、面板标签、状态行、提示行、问卷页脚、未选中页签、身份行、占位页、过小提示、滚动条、回合条普通格、轮次开始（+ `BOLD`）、`Severity::Good` 与 `Note` |
| **信号** | `WARN` / `BAD` | 诊断、hook 反馈、`Severity::Warn` / `Severity::Bad`、工具失败、会话错误 |
| **焦点** | `ACCENT`+`BOLD`（常驻）/ `REVERSED`（临时）/ `ACCENT`（指示器、`/` `@` 记号） | 选中页签、回合条聚焦格、菜单光标行、问卷当前项、新内容指示器、输入记号 |
| **专色** | 冻结五色 + `PROMPT` + `INJECTED` | 角色名 / 提示符 / 上下文注入行 |

### 给下游票的落点

- **[06 底部三条](06-prototype-bottom-three-rows.md)**：状态行与提示行整体进 `MUTED`；输入区草稿去掉整段 `BOLD`；提示符仍是唯一会动的专色。
- **[07 转录右缘与左栏](07-prototype-transcript-edge-and-sidebar.md)**：占比条底色今天与面板标签同为 `DarkGray`，现在两者都是 `MUTED` —— 要另找对比手段（结构或 `ACCENT`）；轨迹页右缘与对话视图对齐。
- **[08 覆盖层与问卷](08-prototype-overlays-and-questionnaire.md)**：问卷已选去黄、当前项用 `REVERSED`（不用 `DIM`）；模态的「整块黄」要拆（边框 `CHROME` + 空角、正文 `PLAIN`、按钮 `ACCENT` 或 `REVERSED`）；详情小节线归内容档（04 已定）。
- **[09 间距与对齐](09-grilling-spacing-and-alignment.md)**：静音只有一档，所以「再退一档」全靠**结构** —— 缩进阶、块间距、线型由那张票定常量；本票只给原则。
- **`/to-spec`**：`docs/render.md` 的「严重度」「外壳」两节与 `docs/tui-manual-checklist.md` 的观感项要跟着改。
