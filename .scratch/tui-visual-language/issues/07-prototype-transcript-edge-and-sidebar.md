## 问题

维护者点名「转录 / 对话视图的排版」与「左栏」是痛点（[图](../map.md) 冻结项 7）。转录的分工与形态刚由 [`trace-tab/spec.md`](../trace-tab/spec.md) 定下（名字独占一行、正文顶格、用户右对齐、三色前缀），**本票不重开那些**；要查的是它落地之后露出来的边角：

- **转录右缘有两条一列宽的竖线相邻**：滚动条在倒数第二列（`src/render/layout.rs:42,162-169`），回合条在最右一列（`wording.rs:1717-1719`）。两条都常驻预留 2 列。挤不挤？要不要合并、或者只在需要时画其中一条？
- **轨迹页没有滚动条也没有回合条**（`tui.rs:3823-3835`），只有 pane 加右下指示器 —— 与对话视图的右缘不一致。这是刻意的（轨迹页窄）还是漏的？
- **左栏各页的形态**：身份标记（宽档才出现的 `fs` 五行）、页签条、`调用量` 页（标签 + 值 + `DarkGray` 底色占比条）、`todo` 页（`☐ / ▸ / ✓` + 计数行）、`文件` 页占位行 —— 在收敛后的层级语言（[05](05-grilling-hierarchy-and-selection.md)）下各自长什么样？占比条与标签今天同为 `DarkGray`，对比过低。
- **名字行与正文的对比**：名字行拿角色色，正文拿默认色；收敛之后这个对比够不够？

## 作答

**已解决（2026-10-05，HITL：维护者看完对照后拍板）**。产物：[`prototype/transcript-edge-and-sidebar.md`](../prototype/transcript-edge-and-sidebar.md) 与 `prototype/edge-and-sidebar-demo.py`。

### 决定

1. **滚动条只画滑块，不画轨道**（`track_style` 设成不画）。右缘那两条并排的细竖线里，轨道与紧邻的回合条是同一族字形，读起来是噪音；位置靠滑块本身表达。
   **`TRAILING_COLUMNS = 2` 的预留不动** —— `layout.rs:40-42` 把它的理由写死了：「画不画都留着，这样文字不会因为转录长高了而重新折行」。改的只是轨道上不上屏，不是列留不留。
2. **轨迹页补滚动条，不补回合条**。它有自己独立的滚动与贴底跟随（[`trace-tab` 票 04](../trace-tab/issues/04-grilling-scroll-and-follow.md)），有独立滚动就该有位置指示；而回合条那种「一格一跳」的导航在轨迹页上是冗余的 —— 它本来就按回合分段。
   - **宽度**：轨迹页复用同一份 2 列预留，滚动条画在**最右列**（那里没有回合条）；正文因此从 40/28 变成 **38/26** 列。
   - **已知代价**：[`trace-tab` 票 01](../trace-tab/issues/01-prototype-trace-page-layout.md) 记的「28 列下 markdown 表格的观感未证实」现在要在 **26 列**下再看一次。
3. **占比条改成字符条**（`▓▓▓░░░░░░`，前景 `MUTED`）。这正好是 05 说的「再退一档靠结构」：一共 10 列的读数区，用块字符画条比一整块暗底更清楚，也不引第二个灰值。
   - **实现影响**：现在的条是 `bg()` 涂出来的、**不占列**（`panel.rs:168-171`）；字符条**占列**，所以 `row()` 的列预算要重算，值列要给它让位置。
4. **身份标记的品红坡道保留，但在色板里给两个具名条目**：`MARK_BRIGHT`（`LightMagenta`）/ `MARK_DIM`（`Magenta`）。既不破「品牌特例、不受语义体系约束」这条性质，又让 `grep Color::` 的结果干净 —— 色板的意义就是「颜色值集中一处」。

### map 的「尚未明确」条目毕业

「**左栏身份标记算什么**」这条雾由本票答清：它是**品牌标记**，不参与语义体系；但它的颜色值仍归色板（决定 4）。map 的 `尚未明确` 里该条已删。

### 给下游 / spec 的落点

- **`panel.rs`**：`row()` 的列预算与 `fit()` 的降级链按「条占列」重算；`usage-stats-format/spec.md` §3 里「底色不占列，所以列宽计算与降级链一点都不用动」那句要改。
- **`layout.rs` / `tui.rs`**：轨迹页的 `Regions` 要加滚动条那一列；`draw_scrollbar` 要能被两个视图各调一次（各自的 `Pane`）。
- **`docs/render.md`**：两个视图的右缘形态、轨迹页列宽（38/26）要写进去。
- **测试**：`tests/render_layout.rs` 里轨迹页的排版断言（宽度相关的）会动；`usage-stats-format` 的占比条断言（`render_layout.rs:2356-2365`）要按字符条改。
