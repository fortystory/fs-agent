# 种子材料：让模型用 `ask_user_question`，而不是在正文里问

> **这不是 spec，也不是票。** 它是 2026-10-08 维护者在真机里发现的一个现象与当场定下的做法：
> 模型需要用户拍板时，有时把问题写进回答正文，而不是调用 `ask_user_question`。维护者的决定是
> 「在系统提示词中添加『在向用户提问时使用 ask_user_question』，**不用添加限制**」，当天落地
> （`src/agent.rs` 的 `ASK_GUIDANCE`）。**没有访谈、没有拆票**；效果要看真机。

## 要什么

模型要问用户时走 `ask_user_question` 那条路：问卷摆到界面上、答案作为那次调用的结果回来，
而不是在正文里问一句然后收回合。

## 落地了什么

- `src/agent.rs` 新增 `ASK_GUIDANCE`，拼在 `agent_identity()` 里 `todo` 那一段之后。
- **只写正面引导**：没有「不要在正文里问」这条禁则，也没有「能自己查的自己查」这条边界。
  来由是维护者的原话「不用添加限制了」—— 而否定式指令在提示词里最弱，`agent_identity` 当初
  删掉「你不是 Claude Code」那句用的就是同一条理由。
- 讨论者与合成器的身份**都不带**它；`ask_user_question` 不可 delegable，所以执行者的工具表里
  没有它（`src/tools/ask_user.rs`）。
- 断言在 `tests/ask_guidance.rs`：主身份含它、它排在 `todo` 段之后、另外两段公开身份不含。

## 代价与没做的

- 身份是**缓存前缀**的一部分，所以这一句让所有现有会话的前缀作废一次（ADR 0001 的规矩里，
  **加**一行是允许的，改一行才要另说）。
- **没写进身份的那条事实**：两种「停」在 harness 眼里不一样 —— 正文里问完正常结束回合，
  `/loop` 会立刻推下一轮（`run_goal_loop` 里只有 Error / 预算耗尽 / 取消 / 完成 / 无进展才停），
  模型于是带着一个没人答的问题继续；而 `ask_user_question` 是一次**没返回的调用**，循环被那个
  await 挡住。维护者这一次选的是纯正面引导，这条差别只记在这里。
- **真机待观察**：模型遇到要拍板的事时是否真的改用工具；以及会不会往「什么小事都弹问卷」那边
  漂。走查项在 [`docs/tui-manual-checklist.md`](../../docs/tui-manual-checklist.md) ㉕ 第 11 条。
