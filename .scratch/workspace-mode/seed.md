# 种子材料：`workspace` 权限模式

> **这不是 spec，也不是票。** 它是 2026-10-01 从沙箱那一轮访谈（Q7）里分出来的意向：
> 「工作区」作为一档权限模式的完整设计，与「进程级沙箱」是两件事，所以分开做。
> **写就于 2026-10-01**；下文凡说「现状」，指的都是那一天的代码。

## 它要什么

`workspace` = **项目目录（会话 cwd）内一律允许、目录之外需要审批**，对所有角色（主会话 / 讨论者 / 执行者）生效。

## 为什么当时停下来了

卡在 `bash` 那一格：它是唯一无法静态判定会不会写到工作区外的工具（`src/tools/bash.rs` 的 `effect()` 恒为 `Exclusive`，注释写着「shell 能写任何东西」）。没有可靠的「越界」信号，「区内自动、区外问」在 shell 上就只剩「一律问」或「一律放行」两端。

于是先做了**进程级沙箱**：判据交给内核，越界是 `EROFS`。那一轮的规格在 [`../sandbox/spec.md`](../sandbox/spec.md)，材料在 [`../sandbox/research/`](../sandbox/research/)。

## 依赖关系

- **shell 那一半**现在有了判据（沙箱会拒），但「拒了之后怎么办」还没定 —— 那正是沙箱 spec 明确留到下一个 effort 的**越界升级审批**（被拒 → 原样重试 + 一句理由 → 批一次）。
- **文件工具那一半**不依赖沙箱：`SessionPaths` 已经是「cwd 之外一律拒」，要把它改成「cwd 之外要问」，是权限代数的事。
- 沙箱只做 Linux，所以这个模式在多平台上的退化形状也要一起想。

## 已经拍过、别丢的决议

见 [`../sandbox/seed.md`](../sandbox/seed.md) 的《已拍但暂缓：`workspace` 模式那一版的决议》一节 —— 模式名与中文标签、两个入口、区内一律允许、区外读写都要问、对所有角色生效。**下次 grilling 时把它迁进本文件**：它本质属于这个 effort，只是当时寄存在沙箱那边。
