# 种子材料：`grep` / `rg` 工具

> **这不是 spec，也不是票。** 它是 2026-10-01 在一轮 `/ask-matt` 里记下的意向：把 grep / rg
> 做成一个正经的模型工具。

## 它要什么

搜索代码这件事有一个**只读、可分类、有输出上限**的工具，而不是每次都让模型去拼 shell。

## 现状

工具表里没有它（`src/tools/mod.rs:65-79`）：模型现在只能经 `bash` 调 `rg` / `grep`。
`bash` 的 `effect()` 恒为 `Exclusive`，注释写着「shell 能写任何东西」—— 也就是说
在**权限代数**里，一次纯读取的搜索也长得像一次可能写盘的操作。

## 待谈的分叉

1. 为什么需要它：是把只读搜索从 `bash` 的 `Exclusive` 里救出来（让「区内自动」这一类
   策略对搜索生效），还是只为输出上限与结果整形？
2. 与 `repo_map`（`src/context/repo_map.rs`）的分工：地图是「有什么」，grep 是「在哪」。
3. 输出上限与分页：复用 `src/context.rs` 的截断 + 指针约定。
4. 依赖：自带 ripgrep 库，还是仍 spawn 一个 `rg` 二进制（那就回到 `src/tools/process.rs` 那条路）。
