# 03 — 命中太多时的收尾与落盘

Type: implement
Status: ready-for-agent
Blocked by: 01

> 规格：[`../spec.md`](../spec.md) §5（输出形状与上限）。票 01 已经让最小的搜索跑通，
> 这一票只加「太多的时候怎么办」，**不新开截断逻辑** —— 仓库已经有一条唯一的流水线。

## 目标

命中极多时结果仍然可读、可操作：模型拿到的是「列出来的若干条 + 一句还省掉了多少 + 一条
可操作的出路」，而不是一次几千行的转储，也不是一句「被截断了」却没告诉它省了什么。

## 现状（2026-10-02 核实，改前先复核）

- 每个工具结果都过同一条流水线：`context::truncate_result`
  （`src/context.rs:336-371`）→ 唯一调用点 `agent.rs::emit_completed`
  （`src/agent.rs:2043-2054`）。没超限原样进事件；超了整份写进
  `<outputs_dir>/<tool_call_id>.txt`（0600），事件里留头尾预览与指针
  （`preview()` 在 `src/context.rs:373-396`，标记 `TRUNCATED_MARKER` 在 `:403`）。
- 上限是 `SessionConfig.max_tool_result_tokens`，缺省 25_000（`src/config.rs:57`），**不进
  `config.toml`**。
- **「工具自己截断并如实报告省掉多少」的既有先例是 `repo_map`**：
  `docs/repo-map.md:31-33` 记的末尾那一行（装不下的按符号边界切，末尾写出被省掉多少）。

## 落点

`src/tools/grep.rs`、以及票 01 新增的测试文件。

## 具体行为

1. **工具内先按条数收一刀**：一个常量上限（不进配置 —— spec §4 明说不照 `repo_map_tokens`
   再开字段，先跑一段看真实用量）。
2. **末尾如实写清省掉了多少**，并给一句可操作的出路（例如「还有 N 条未列出，请缩小搜索范围
   或加 `glob`」）—— 与 `repo_map` 末尾那一行同一种收尾。`glob` 那句在票 02 落地后才存在，
   本票先写前半句。
3. **token 上限那条路一个字不改**：超过 `max_tool_result_tokens` 时仍由既有流水线整份落盘、
   事件里留头尾预览与指针 —— 本票不新增第二套截断，也不自己写文件。

## 验证

`cargo test` + `cargo clippy --all-targets`：

1. **超 token 上限走落盘**：造一个超过 `max_tool_result_tokens` 的结果，断言事件里的文本是
   头尾预览 + 指针，且 `outputs/<tool_call_id>.txt` 存在（权限 0600）。
2. **超条数上限但没超 token 上限**：末尾有「还有 N 条未列出」那一句，且列出的条数就等于常量
   上限 —— 这一条钉的是「工具自己收一刀」，与上一条是两件事。
3. **没超限时逐字原样**：小于两个上限的一次搜索，结果与票 01 的形状逐字相同（回归锚）。

## 不做什么

- 不做工具内分页（`head_limit` / `offset`）：分页是模型要自己维持的一份记账，
  而这里有「落盘 + 指针」这条更简单的退路（spec §5）。
- 不新增配置项、不改 `max_tool_result_tokens` 的语义。
- 不动票 01 的命中形状与忽略规则。
