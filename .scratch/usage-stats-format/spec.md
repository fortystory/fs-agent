# 右侧统计：数字的书写制式与占比色条

右侧统计面板把会话用量的数字一律写成千分位（[`src/render/wording.rs`](../../src/render/wording.rs) 的 `thousands`，`12,345`），而在中文界面里，六位以上的数字用「万」读更快；面板也只有**上下文**那一行带占比（`（6%）`），「这场会话花掉了预算的多少」没有任何视觉。

这次做三件事：给数字一套**可配置的书写制式**（`cn` 用万/亿、`si` 用 k/M，默认 `cn`），给**有上限的两行**加一条底色进度条，并把这两件事都关在**显示**这一层——诊断通道与状态行一个字都不动。

来源：2026-10-01 一次 `/ask-matt` 里记下的种子（[`seed.md`](seed.md)），同日经 `/grill-with-docs` 折成这份 spec（五条决定：制式与配置项、适用范围、分母、色条、不参与降级）。

## 问题陈述

1. **数字的读法跟着英文走。** `thousands` 只做千分位，`1,234,567` 在中文语境里要数位；会话累计用量到百万级是常态。
2. **「花了多少」没有视觉。** `token_pair` 给出 `12,345 / 100,000`，但人要自己心算占比；面板里唯一有占比的是上下文行，且它是个括号里的数字。
3. **没有一处显示类配置。** `RawConfig` 的顶层小节里没有任何 `[ui]` 一类的先例（[`src/config.rs:720-745`](../../src/config.rs)），显示相关的选择目前没有地方可放。
4. **不能用「统一换一套」了事。** 同一份数字在三个通道里出现：TUI 面板、`--plain` / headless 的诊断行（`usage_summary`）、以及 `sessions stats` 的输出。后者面向脚本，换掉是破坏。

## 方案

- **制式**（§1）：一个纯格式化函数 `compact(value, style)`，`cn` 走「万 / 亿」、`si` 走 `k / M / G`；**小于 10000 一律退回千分位**。
- **配置**（§2）：配置文件新增 `[ui]` 一节、一个键 `number_style = "cn" | "si"`，缺省 `cn`；不新增 CLI 旗标。
- **色条**（§3）：上下文行（分母 `context_window`）与 token 行（分母 `budget_limit`）的值列里，把**前 N 列**涂成底色，`N = ceil(占比 × 值列宽)`；没有分母的行不涂。
- **不动的三处**（§4）：`usage_summary` 那族诊断输出、状态行的 `上下文 n%`、面板既有的宽度降级链。

## 用户故事

1. 作为读面板的人，我希望 `1,234,567` 写成 `123.5万`（或 `1.2M`，看我怎么配），这样我不用数位就知道量级。
2. 作为读面板的人，我希望小数字别被换算成小数（`9,999` 就是 `9,999`），这样精度不丢。
3. 作为读面板的人，我希望一眼看出这场会话花掉了预算的多少，而不是拿两个数字自己除。
4. 作为配这台机器的人，我希望在 `config.toml` 里一个键就能选制式，而不是靠改代码或环境变量。
5. 作为把 `--plain` 输出接进脚本的人，我希望诊断行里的 `用量 in=… out=…` 保持原样，这样我的解析不会被我升级 fs-agent 弄坏。
6. 作为窄终端用户，我希望窄档下该丢的还是那几样（百分比括号、缓存行），新加的色条不要把面板挤变形。

## 实现决定

### §1 单位制式与换算规则

- 新函数：`wording::compact(value: u64, style: NumberStyle) -> String`。`NumberStyle` 是一个两值枚举（`Cn` / `Si`），**定义在 `src/render/wording.rs`**——它管的是"给人看的文本怎么写"，而 `config.rs` 只是持有它（与 `Mode` 那类配置枚举的方向相反，但这里归属更清楚：制式是措辞，不是行为）。
- **门槛**：`value < 10_000` 时两套制式**都**返回 `thousands(value)`（`9,999`）。换算只在真省列的时候才划算，`1.2万` 未必比 `12,345` 好读。
- **`cn`**：`[10^4, 10^8)` 用「万」，`[10^8, ∞)` 用「亿」。
- **`si`**：`[10^3, 10^6)` 用 `k`，`[10^6, 10^9)` 用 `M`，`[10^9, ∞)` 用 `G`。
- **小数位**：一位；恰好是整数时去掉 `.0`。即 `10000` → `1万`，`12345` → `1.2万`，`1234567` → `123.5万`（cn）/ `1.2M`（si），`100000000` → `1亿`。
- 舍入用 `format!("{:.1}")` 的默认（四舍五入到一位）。
- **进位不换档**：档位由**原值**决定，不由格式化后的结果决定——`99_999_999` 写成 `10000万`（不是 `1亿`），`si` 下写成 `100M`。规则里不写"格式化后再检查一次区间"，那样每次进位都要多一轮判断，而边界上的读法并没有更好。
- **不做**「万亿 / 兆」——token 计数到不了，规则越少越好。
- `thousands` 保留（门槛档与诊断通道还要用它），`compact` 在它上面分派。

### §2 配置项 `[ui] number_style`

- 新增 `Config::number_style: NumberStyle`（[`src/config.rs:363-400`](../../src/config.rs)），缺省 `Cn`。
- 新增 `UiSettings`（`Default`）与 `RawUi`（`#[serde(deny_unknown_fields)]`），后者只放 `number_style: Option<String>`。
- 解析落点（照 `[goals]` 那一套走）：`RawConfig` 加 `ui: Option<RawUi>`（它自己也带 `deny_unknown_fields`）、`resolve_ui` 挂进 `resolve()`、缺省常量一处。
- **不新增 CLI 旗标**。现有覆盖只有 `--config` / `--model` / `--mode` / `--cwd`（[`src/cli.rs:149-186`](../../src/cli.rs)），显示制式不值得多一个。
- 文档：[`README.md`](../../README.md) 的「配置」一节（46–119 行）补一行说明与完整示例里的一行。
- 非法值（`"CN"`、`"wan"`）按现有配置错误的处置——报错并指出键名，不退化成默认值。

### §3 占比色条

- **只涂两行**：上下文行（分母 `SessionFacts::context_window`）与 token 行（分母 `SessionFacts::budget_limit`）。「回合」没有分母；「输入 / 输出」是累计量而不是"满不满"；「缓存」是命中/未中——给它们编一个分母只会让颜色骗人。
- **没有分母就不涂**：`budget_limit` 为 `None`（没设额度）或 `last_input` 为 `None`（还没报过用量）时那一行保持纯文本。
- **形状**：在 `row()` 的值列里，把**左起前 N 列**上底色，`N = ceil(占比 × value_columns)`，占比夹到 `[0.0, 1.0]`（超过 100% 就是涂满，不越出值列）。文字与对齐方式（值列右对齐）都不动，前景色不动。
- **颜色**：底色取暗档（`Color::DarkGray`），与 `render::severity` 的暗色一致；不引入主题系统。
- **不参与列宽降级**（这是本 spec 最不显然的一条）：底色**不占列**，所以 `value_columns` 的计算与既有降级链（先把上下文行的百分比括号去掉 → 整条缓存行不加入 → `fit()` 去千分位 → 省略号）**一行都不改**。改了制式之后，既有降级链的**行为一行不改**，但那两条既有测试的**前提会变**——数字变短了：
  - `the_narrow_sidebar_keeps_six_fields_and_drops_the_percentage_when_it_must` 的 fixture 在新制式下放得进值列，"必须丢百分比"的场景不再成立；
  - `a_number_too_wide_for_the_value_column_loses_its_separators_before_its_digits` 里那条 `fit()` 的"去千分位"档，在面板里**再也触达不到**（面板里 `thousands` 只剩 `< 10000` 的数字，最长 13 列，短于值列下限 16）。
  - **口径是"保降级行为、改测试前提"**：前一条改成断言百分比留着，后一条改成断言 `compact` 的输出并注明那一档已不可达；`a_cache_split_too_wide_for_its_column_is_left_out` 的期望串跟着换。
- 落点：`Panel::lines` 的 `rows` 现在是 `(标签, 值, 右对齐)` 三元组，要再带一个 `Option<f64>`（占比），由 `row()` 消费。

### §4 明确不动的三处

- **`usage_summary`**（`wording.rs:243-248`，`用量 in=… out=… cached=… miss=…`）与它的四个调用点（`render/plain.rs`、`render/headless.rs`、`render/tui.rs`、`cli.rs` 的 `sessions stats`）**保持原样**。它是诊断/机器可读通道，stdout 只放产物的契约（[`docs/render.md`](../../docs/render.md)）不为显示制式让路。
- **状态行的 `上下文 n%`**（`wording.rs` 的 `context_share`）保持纯文本。状态行有自己的降级阶梯（先丢模型、再丢模式），不该再叠一层视觉，而且它窄档最先挨刀。
- **面板的百分比括号**（`context_pair` 的 `（6%）`）：留着，它说的是精度，色条说的是比例。

## 测试决定

- **纯函数**（[`tests/wording.rs`](../../tests/wording.rs)）：`compact` 的两套制式逐档断言——每个量级一个代表值，加边界（`9999` / `10000` / `99999999` / `100000000`）、小数去零（`10000` → `1万`）。既有的 `the_panel_texts_read_like_the_prototype` 等断言 `thousands` 输出的测试要跟着改成断言 `compact`。
- **帧断言**（[`tests/render_layout.rs`](../../tests/render_layout.rs)）：色条落在哪些单元格上——用 `TestBackend` 读缓冲里单元格的 `bg`，位置放在 `the_panel_reads_its_numbers_off_the_stream` 旁边；再加一条「没有预算时不涂」。
- **配置**（[`tests/config_profiles.rs`](../../tests/config_profiles.rs)）：`[ui] number_style = "si"` 被解析、缺省是 `cn`、未知键被 `deny_unknown_fields` 拒。
- **回归**：窄档的**降级行为**不变，但那两条测试的字面量前提随数字变短而变（§3 的最后一条），照那里的口径改断言。

## 明确不做

- 不给 `usage_summary` / `sessions stats` / headless 换单位。
- 不给状态行加色条。
- 不新增 CLI 旗标、不读环境变量。
- 不做「万亿 / 兆」，不做多套自定义单位表。
- 不改面板的行序、标签列宽与高度裁剪规则。

## 补充说明

- 为什么不复用 `thousands` 加参数：`thousands` 是**诊断通道也在用**的函数，改它的签名会让那三处跟着动；`compact` 只在显示层替换调用点，边界清楚。
- `[ui]` 这一节是**为以后留的口子**：显示类的选择（颜色、密度、制式）以后都可以住在这里，而不是散进 `[permissions]` 那种语义小节。这也是这个键名选 `number_style` 而不是 `units` 的原因——它说的是"用哪套书写制式"，不是"用不用单位"。
