# 真机走查后的五条：提示行归位、名字行不可点、推荐标记中文化、`@` 匹配放宽、拖选复制

Status: 待实现（2026-10-06 立项：维护者走查 ㉙ 之后列的五条）

- **来源**：维护者 2026-10-06 的原话 —— ①「现在向用户提问时使用 '(Recommended)' 来显示推荐
  选项，改为中文的 '(推荐)'」；②「把快捷键提示改回输入框下，这样更符合直觉，现在在用的时候
  有时找不到，尤其在看有几个问题时」；③「在对话中点击**名字那一行**（`[kimi]` / `[用户]`），
  现在会弹窗 —— 我希望它不弹」；④「`@` 操作可以在输入 `cli` 时匹配 `src/cli.rs`」；⑤「优化
  鼠标选中逻辑，不再需要按 shift 才能选，选中的文本依照 fs-agent TUI 的区域/弹窗换行，而不是
  终端窗口的换行」。⑤的落地方式经六问定下：**TUI 内建拖选 + OSC 52 写剪贴板 + 按区域取行、
  软折拼回**，shift 原生选择保留。
- **术语**：**文本区域**（text block）是选择用的新词条 —— 一块画在屏幕上的、可被拖选的内容；
  **选区**（selection）是按下到抬起之间跨过的那一段。两者收进 `CONTEXT.md`。
- **推翻**：
  - [`tui-visual-language/spec.md`](../tui-visual-language/spec.md) §16 与决策 27「提示行跨整屏，
    以便宽屏时那 41 列不被左栏白吃」—— 真机反馈是找不到提示（左栏宽时提示从第 0 列起，眼睛在
    输入框上）。
  - [`trace-in-main/spec.md`](../trace-in-main/spec.md) §2 落下的那条顺手形态：对话页里**每一条**
    消息行都是详情入口 —— 名字独占一行之后，名字行也成了入口，点它弹出一份正文。
  - `fs-agent-v1` 票 32 与 `ask-user-question` 的 `(Recommended)` 后缀约定（模型侧那条），以及
    [`wording.rs`](../../src/render/wording.rs) 里只认英文后缀的 `recommended_label`。
  - [`input-tokens/spec.md`](../input-tokens/spec.md) §3 的候选规则里「前缀匹配」那半条（`starts_with`
    → 分段匹配，可从任意一段起）。

## 问题陈述

1. **推荐标记还留着英文壳。** 问卷行会把 `(Recommended)` 剥掉、换成一枚中文徽标，但**约定本身**
   是英文：工具描述让模型写 `(Recommended)`，答案回执与 label 原样处都带着这串英文。模型可见的
   散文已经一律走中文（[ADR 0005](../../docs/adr/0005-model-visible-text-in-chinese.md)），这一处
   是漏网的。
2. **提示行离输入框太远。** 它跨整屏、贴屏幕最底，提示第一条从第 0 列起 —— 而输入框在主列里。
   左栏在时两者横向错开 28 / 40 列，问卷立着时更明显：问题画在输入区，进度与按钮却从屏幕最左
   列开始，眼睛来回找。
3. **名字行是个假入口。** 一条消息的名字独占一行（`[kimi]`），话从下一行起。名字行**不是**正文，
   但它是整条消息那个详情入口的一部分：点它弹出一份正文详情。它应当退回去做一行标签。
4. **`@` 只认前缀。** `@cli` 配不到 `src/cli.rs`，得把路径从头打对。候选的用处正是「我不记得它
   在哪一层目录」，而前缀匹配恰好要求你记得。
5. **选中要按 shift。** 应用占着鼠标，终端原生选择因此被它接管，只有按住 shift 才回到终端手里。
   而原生选择按**终端**的网格取文本：左栏、边框、弹窗与它盖住的行会混在一起，TUI 自己折出来的
   续行也跟着被当成硬换行。自用工具里一天要复制好几次代码行与命令，这条摩擦每天都在。

## 方案

五条互不依赖（⑤的两票之间有一条阻塞边），各自都是「一块小改动 + 它的断言」：

- **推荐标记**：约定改成 `(推荐)`，判定**同时**认旧的 `(Recommended)` —— 旧会话与旧 label 不会
  丢徽标。工具描述、徽标、测试、文档一起走中文。
- **提示行归位**：`hints` 矩形从整屏宽改成主列宽，左栏回到全高、竖线贯通到屏幕底。提示行仍然
  只占一行、仍然在输入区正下方。
- **名字行**：`named_rows` 产出的名字行拿 `RenderedLine::from`（无入口），只有正文行 linked。
- **`@` 候选**：`FileIndex::candidates` 的判据从 `starts_with` 换成**分段前缀、可从任意一段起**；
  匹配起点更靠前段者优先，其余按路径序。
- **拖选与复制**：新增一层**屏幕文本**（每帧记录每块区域画出来的显示行），`Down`/`Drag`/`Up`
  三段手势，抬起时按区域取行、软折拼回、OSC 52 写剪贴板，提示行给一句回执。

## 实现决定

### §1 推荐标记中文化

- `wording::RECOMMENDED_SUFFIX = "(推荐)"`（新约定），另立
  `RECOMMENDED_SUFFIX_LEGACY = "(Recommended)"`（旧的，只为兼容）。
- `recommended_label` 两种后缀都剥，返回同一个 `(显示文本, 是否推荐)`；匹配仍然区分大小写、只
  在结尾。
- 徽标仍是 `（推荐）`（全角括号），**不改** —— 它是界面文案，与后缀是两件事。
- `src/tools/ask_user.rs` 的工具描述改成 `(推荐)`：让模型写中文后缀。旧会话里已经写进事件的
  `(Recommended)` 靠 §1 的兼容继续被剥掉。

### §2 提示行归位

- `layout::plan` 的 `hints` 从 `Rect::new(area.x, input.bottom() + 1, area.width, 1)` 改成主列宽
  （`main.x` / `main.width`）—— 与输入区同列同宽、就在它正下方。
- **左栏恢复全高**：`sidebar_rows` 不再减掉提示行那一行（`area.height − SIDEBAR_TOP_GAP`），
  `draw_divide` 画到 `area.bottom()`，`paint_rule` 的两条横线仍从分隔列右边一格起。
- 120×24 下左栏页区从 14 行回到 **15** 行；`CHROME` 一个字不改（提示行那一行还是它花的）。
- 问卷的页脚（`draw_questionnaire_footer`）与回执都跟着搬到主列里 —— 它们本来就画在
  `panes.hints` 上，改的是矩形本身。

### §3 名字行不是详情入口

- `paint_block` 的对话分支里，`named_rows` 交回来的名字行给 `RenderedLine::from(line)`，正文行
  仍走 `message_line`。名字行**从行首到行尾**都不是入口（它与正文行是两个显示行，链接按源行查，
  两条行各自的 link 独立）。
- 用户消息（右对齐那一支）与助手消息**同一条规矩**：名字行不可点。
- 轨迹页一个字不改：那里的名字与首行在同一行上（`[kimi] ▸ 首行…`），整行照旧是入口。

### §4 `@` 候选：分段前缀、可从任意一段起

- 判据：`query` 与候选路径都按 `/` 切段（空段丢掉），query 的第 i 段必须按前缀匹配候选的某一段
  `c[j]`（大小写不敏感），且 `j` 严格递增。第一段的 `j` 可以是**任何**一段。
- 于是 `cli` → `src/cli.rs`（段 `cli.rs` 以 `cli` 开头）；`render/tui` → `src/render/tui.rs`；
  `src/` → `src/` 本身与它底下的一切（前缀段在前）。
- 排序：匹配起点段号升序（越靠前段开始的越先），同分按索引里的路径序。菜单仍只取前
  `TOKEN_MENU_CANDIDATES` 条。
- `contains`（「能兑现」上色与 chip 的判据）**一个字不改**：它照旧要求精确存在。
- 含空白的路径照旧不进候选。

### §5 拖选：手势、反白、选区归属一个区域

新增 `src/render/selection.rs`：**屏幕文本层** + 选区 + 取值。

- **屏幕文本层**：每帧重建，每条记录是 `(rect, rows: Vec<String>, folded: Vec<bool>, kind)`，按
  绘制顺序入栈。`rows` 是这块区域**画在屏幕上**的显示行文本，`folded[i] == true` 表示第 i 行是
  上一行**软折**出来的续行（同一源行的下一片）。`kind` 区分转录 / 详情 / 左栏 / 问卷 / 输入区。
- 谁记录：`draw_transcript`（两个视图各记各自 pane 的显示行）、`draw_detail`、
  `draw_sidebar_page`、`draw_bottom`（问卷行与编辑器行）。记录点是**画那一行的同一个地方**，
  所以「记下来的」与「看见的」不可能漂开（照 `Regions` 那条纪律）。
- 转录的 `folded` 由 pane 推：显示行 i 与 i−1 的 `source_at` 相同就是软折续行。详情覆盖层的
  折行同理（它的正文折行归它自己的排版函数）。
- **手势**（`TuiState::mouse` 重构成三段）：
  - `Down(Left)`：记住 `anchor`（屏幕格子）与它落进的那块**文本区域**（最上层者），**不执行**
    原来的点击动作。
  - `Drag(Left)`：越过 1 格的门槛之后进入选择态，`head` 跟着指针走，并**夹在所属区域的矩形内**
    —— 选区不跨区域。没越门槛就什么都不做（手抖不该变成一次选择）。
  - `Up(Left)`：选择态 → 复制（§6）；否则把这一次点击**照旧**分派给原来的那些入口（页签、回合
    条、链接、问卷按钮、关闭覆盖层…）。原分派的判据一个字不改，只是从 `Down` 挪到 `Up`。
  - 滚轮、中键、右键照旧；`Esc` 与重放/历史期间的指针纪律照旧。
- **反白**：`draw_frame` 最后（详情之后）画一层 `Modifier::REVERSED` 覆盖选区矩形内的每一格。
  它只碰缓冲，不动任何绘制函数，所以覆盖层、菜单、问卷都不会因此改形。
- 覆盖层立着时照样能选它自己的文本（详情正文是常见的复制对象）；在它框内按下并拖动**不会**关掉
  它 —— 关它的是「框外的一次点击」，而那仍然按 §5 的 `Up` 分派判。

### §6 复制：按区域取行、软折拼回、OSC 52、回执

- **取文本**：只在所属区域内做。逐显示行取 `[列区间)` 那一段（按**显示列**算，宽字符不切半），
  行首行尾的填充空白去掉、行内空白保住。
- **软折拼回**：一行之后若下一行是它的软折续行，两行**拼成一行**（不加换行）；不是则加 `\n`。
  于是被 TUI 折过的长命令复制回来仍是一条，而区域自己的硬换行（Markdown 段落、代码块的多行）
  保留。
- **写剪贴板**：OSC 52（`ESC ] 52 ; c ; <base64> BEL`）直接写终端。不探测支持与否、不落外部
  命令：写不进去也不报错，因为没有任何终端回话这条通道可用。base64 自己编（一个小纯函数 + 它
  的单测），不为这一处引新依赖。
- **回执**：提示行给一句 `已复制 N 字 · M 行`，几秒后自己走掉 —— 由既有的脉冲 tick 驱动过期，
  不新起时钟。它排在提示集合**之前**（复制是你刚做的动作），举手时仍让位给举手回执。
- 选区为空（没拖过任何字符）时不复制、不给回执。

### §7 不改

- `(推荐)` 的**徽标**文案、问卷的键位与页脚四档、选项行生成器。
- 提示行的**内容**与它的阶梯（`KEY_HINTS` / `VIEWER_HINTS` / 出口四档）—— 只搬位置。
- 轨迹页的入口规矩、`selects` 分工、左栏的三页、回合条。
- `@` 的记号规则、chip、上色与「能兑现」判据；菜单的浮层、键位与窗口。
- 事件流 schema、plain / headless 渲染器、模型可见文本（除工具描述里那一处后缀）。
- crossterm 的鼠标捕获配置 —— **shift 原生选择继续可用**，内建拖选只是多一条路。

### §8 文档

- `CONTEXT.md`：新增**文本区域**与**选区**两条词条；**提示行**词条里「跨整屏」那半句改掉。
- `docs/render.md`：「外壳」一节那张图与 `hints` 的说明、两个视图的入口规矩（名字行不入口）、
  `@` 候选一段的匹配规则、新增的「拖选与复制」一小节。
- `docs/tui-manual-checklist.md`：㉙ 的名字行一条改掉，新增一节走查（提示行位置、`cli` 补全、
  拖选与复制、shift 原生选择仍在）。
- `.scratch/README.md` 索引行；`docs/agents/` 不动。

## 测试决定

- **一个 seam：现有的 TUI 帧测试层**（`TestBackend` + 「画一帧、读屏幕」）。这一批的全部内容仍然
  是「同一帧里画出什么、点下去发生什么」。
- 单测层：`recommended_label`（新旧后缀 + 不误伤）、`candidates` 的分段匹配与排序、base64 编码、
  `slice_columns`（宽字符）、软折拼回（纯函数）。
- 帧层：提示行的起点列等于输入区的起点列且宽度相同、左栏页区多回一行；点名字行与点正文行的
  两帧之差（前者无覆盖层）；`@cli` 的菜单里第一项是 `src/cli.rs`；拖选的 `Down`/`Drag`/`Up`
  三段（反白出现在拖动之后、抬起时退出不走原点击分支、未越门槛的按下-抬起仍切页签）。
- 剪贴板那一跳**不测终端**：只测「交给 OSC 52 的那串字节」与回执文案。真机项进手工清单。
- **不测实现细节**：不断言屏幕文本层的内部结构、不为拖选写白盒状态断言。

## 明确不做

- **跨区域的选区**（从左栏拖到主列）：选区夹在按下那一刻所属的区域里。
- **双击选词 / 三击选行 / 键盘 (`Shift+方向键`) 选择**：这一轮只有拖选。
- **选择时的自动滚动**（拖到边缘继续滚）。
- **`(Recommended)` 从历史事件里批量改写**：靠 §1 的兼容读法。
- **`@` 的字序模糊（子序列 / typo 容忍）**：只放宽到分段前缀。
- **复制进 tmux 缓冲、写外部命令、剪贴板历史**。
