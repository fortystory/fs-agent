# 轨迹视图进主列：主列页签条与轨迹时间戳

Status: 实现完成（2026-10-06：票 01–03 `done`、票 04 `ready-for-walkthrough` —— 自动化部分全绿，真机走查项在 [`docs/tui-manual-checklist.md`](../../docs/tui-manual-checklist.md) ㉙）

- **来源**：维护者 2026-10-06 的要求 ——「把左边栏的『轨迹』移动到右侧，右侧的对话中添加一个
  标签行，把『对话』和『轨迹』放入标签中，然后在轨迹中添加时间戳」；随后六问的答案（左栏保留
  其余三页、时间戳取 `Event.at`、`HH:MM:SS` 本地时区每块一行、消息仍「首行 + `…`」、键盘归当前
  显示的那一页、先 spec 后实现）。
- **术语**：**主列页签条（main tabs）**是主列顶部那条页签条（`对话` ┆ `轨迹`）；**轨迹视图**与
  **对话视图**仍是 `CONTEXT.md` 里那两个词条，只是轨迹视图现在住在主列。三个词条照旧。
- **推翻**：
  - [`trace-tab/spec.md`](../trace-tab/spec.md) 把「轨迹 = 左栏的一页」当基础设定的那几处：§2 的
    「轨迹视图（左栏 `轨迹` 页）」、§3 的「宽度就是左栏页矩形的宽（40 / 28）」、§4 里为左栏页高
    服务的实测、§5 的「滚轮按指针位置分派 / 轨迹只吃滚轮」、**§6 的「左栏不可见时不降级」**，
    以及用户故事 21 / 25 / 28 / 32 里以左栏为前提的那四条的**位置**部分（分工本身一条不改）。
  - `docs/render.md` 的「外壳」「两个视图」「键盘」三节里以左栏为前提的句子。
  - `CONTEXT.md` 的**轨迹视图**与**页签条**两条词条，以及**对话视图**词条里「它缩在左栏里」那半句。

## 问题陈述

轨迹视图（`trace-tab`）把过程行从对话里摘出来了，但它住进了左栏 —— 一条 40 / 28 列的窄栏。

1. **宽度是拿密度换来的。** 轨迹页正文宽档 38 列、窄档 26 列：表格挤成一团，消息首行也早早
   截断。而同一时刻主列常常是空的（对话里没几条消息时，那 79 列什么都没做）。
2. **左栏一收，过程行就没了。** `Ctrl-O` 收起左栏或终端窄于 80 列时，轨迹页连同它那一栏一起
   消失 —— 这是 `trace-tab` §6 明码标价的取舍，代价是那些宽度下**根本看不到过程行**。
3. **两块内容分居两处。** 要看过程得把指针挪到屏幕另一侧，切换要跨屏点，滚动要按指针位置分派
   —— 而这些机制全部存在，只为了一件「同一份转录的第二个视图」的事。
4. **轨迹没有时间。** 它是运行日志（工具、思考、边界、权限裁决、诊断），而日志最要紧的一列是
   「什么时候」。今天唯一的时刻线索是 `ToolCallCompleted.duration_ms`。

## 方案

**主列顶部加一条页签条，主列成为两个视图的家；左栏只剩调用量 / todo / 文件。**

```
 标记 / 文字身份      ┆ ┄ 对话┆轨迹 ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄
 ┄┄ 页签条 ┄┄┄┄┄┄┄┄┄┄┆
 上下文 / token / …    ┆ 04:16:53 [bash] ▸ 正在运行 cargo test…
                      ┆ 04:16:55 [助手] ▸ 首行…
                      ┆ ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄
                      ┆ 状态行：模型 X ┆ 询问 ┆ 上下文 n% ┆ 🌑 就绪
                      ┆ ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄
                      ┆ 输入区
 ┄ 提示行跨整屏（左栏到此为止）┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄
```

三条改动轴：

- **几何**：主列页签条花 3 行（线 / 标签 / 线），从转录里扣；左栏几何一个字不动。
- **归属**：轨迹视图的窗格、折行、滚动、跟随、指示器与详情入口全部跟着它搬进主列那块内容区，
  宽度从 38 / 26 变成主列内容宽，**常驻**（主列永远在）。
- **时间戳**：轨迹里每个块的第一行前面加 `HH:MM:SS `，时刻取**产生它的那条事件的 `at`**。

## 实现决定

### §1 几何

- **主列页签条花 3 行**（一条分隔线、标签、一条分隔线），与左栏页签条同一个常数
  （`layout::TAB_ROWS`）。于是 `CHROME` 从 4 涨到 7（主列的两条分隔线、状态行、提示行，加上页签条
  那 3 行），`转录行 = h − 7 − 输入行数`：120×24 下 17 → **14** 行。
- 页签条的标签行是主列的**第一行**，两条线在它上下一行，都从 `main.x` 画到屏幕右缘 —— 与左栏
  页签条同一种笔（`paint_rule`，`CHROME` 色虚线）。
- `Regions` 新增 `main_tabs: Rect`（标签行）。`transcript` / `rail` / `scrollbar` 全部随之下移 3 行；
  已存在的两条分隔线（输入区与提示行上面那两条）位置由 `input` / `hints` 推出来，自动跟着走。
- **左栏几何一个字不动**：它的页签条仍 3 行、身份阶梯仍两档、页高公式仍
  「内容行 − 身份 − 页签条」。

### §2 页签条与切换

- 标签两个：`wording::TAB_CONVERSATION`（新，`"对话"`）与 `wording::TAB_TRACE`（`"轨迹"`，复用）。
  之间一个 `┆`，这一行其余部分用 `┄` 填满 —— 与左栏页签条同一套画法，包括选中档
  （`ACCENT` + `BOLD`）与未选档（`MUTED`）两种样式。
- 每个标签画出来时记一个命中矩形（`HitAction::SwitchMainTab`），于是没被画出来的标签点不到 ——
  「记住读的人真看到了什么」这条纪律照旧。
- 状态是 `TuiState::main_tab: MainTab`（`Conversation` / `Trace`），默认 `Conversation`。它与左栏的
  `Tab` 同级：只活在这一次进程里，不落配置、不跨会话，重开回到 `对话`。
- **页签是点出来的，从不给键位**（照左栏页签那条既有规矩：`Tab` 归 `/` 菜单、`Shift+Tab` 归模式
  循环）。
- 左栏的 `Tab` 枚举去掉 `Trace` 变体，它的页签列表只剩 `调用量` / `todo`（有条件）/ `文件`；
  `draw_sidebar_page` 里那条轨迹分支整段搬进主列。
- `layout::Regions::sidebar_page_text` / `sidebar_page_scrollbar` 随轨迹页离开左栏而删除（它们只服务
  轨迹页），`TRAILING_COLUMNS` 的两列预留仍属于主列。

### §3 轨迹视图在主列的排版

- **宽度 = `Regions::transcript_text().width`**，即主列内容宽（120 列带左栏时 79）。
- **消息仍是「首行 + `…`」** + `DetailKind::Message` 详情（维护者的选择）——宽度变了，形态不变。
- **前缀分档**：判据从「左栏页宽 40 / 28」换成「主列页宽」（`panes.main.width`）。主列最小 40 列
  （终端下界就是 40），所以恒为宽档、恒带方括号；`PrefixStyle::Bare` 那一支留着不删（它与
  `render_block` 那条共享渲染路径共用一套签名，删它是另一条线索）。
- 单位之间的分隔线、不铺底色、注入 / 用户 / 助手三类专色 —— 全部照旧。
- **`trace_width` 永不为零**：轨迹 pane 与对话 pane 一样常驻。宽度变化的清空与重放照旧只对
  真变了的那个 pane 做（两个宽度现在同源，通常一起变）。

### §4 滚动、指针与键盘

- **滚轮滚当前显示的那一页**：主列只有一个视口在屏幕上，所以「按指针位置分派给哪个 pane」这条
  分派消失了（推翻 `tui-chrome` §5 与 `trace-tab` §5 的分派半句）。覆盖层与问卷占着指针时那条
  优先级**照旧**（详情滚它自己、问卷挪高亮、模态吃掉自己那块里的滚轮）。
- **键盘三键（`PgUp` / `PgDn` / `Ctrl-G`）作用于当前显示的那一页**（推翻 `trace-tab` 用户故事 32
  那条「轨迹只吃滚轮」的代价）。
- **点击**：`trace_rect` 仍是「这一帧真画了轨迹页吗」的判据，只是现在它等于主列内容区；行详情按
  当前页的链接表取，详情关闭时还原给打开方那个视图（`detail_opener`，一个字不改）。
- **回合条只在对话页画**：它量的是对话视口的单位位置，画在轨迹页上会指着一个跟它无关的视口。
  轨迹页只画滚动条（画在 `TRAILING_COLUMNS` 那两列里左边那一列，与对话页同一个位置）。
- **指示器**：两个视图各持一份矩形，但屏幕上只有当前那一页的那个会被画出来；点击「回到底部」
  只对当前页生效。
- 对话视图的等待提示（「谁在答 / 正在做什么」）只画在对话页；轨迹页照旧只画正文尾巴
  （`live`）。

### §5 时间戳

- **来源是 `Event.at`**（`src/events.rs:798`，早就在信封上、早就在 `log.jsonl` 里）。事件 schema
  一个字节不改，所以 `--continue` 重放出来的时刻就是当初那一刻。
- **渲染层自己那两条在源头打时**：`RenderEvent::Diagnostic` 与 `RenderEvent::Notice` 带上
  `at: DateTime<Utc>`（`Renderer::diagnose` / `Renderer::notice` 两个出口各调一次 `Utc::now()`）。
  「发生的时刻」属于它们的数据，而不是绘制时的环境。
- **挂在哪儿**：`Painted` 的两个块变体带上 `at`（`Painted::Block { block, at }`、
  `Painted::Thought { speaker, trace, at }`），于是宽度变化重放出来的行也带着同一个时刻。
  `Painted::Thinking`（还开着的那一行）不带：那一刻还不知道这个想法属于哪条消息。结算时
  （`settle_thinking`）用那条 `MessageCompleted.at`。
- **画在哪**：轨迹视图里每个块的**第一条显示行**前面加一个 `HH:MM:SS ` 前缀（半角冒号、秒级、
  `chrono::Local`），静音档色；同一个块的续行补 9 个空格对齐。对话视图**不加**（维护者只要求
  轨迹）。
- **排版宽度**：轨迹内容按 `主列内容宽 − STAMP_COLUMNS`（9 列）排版，加上前缀正好铺满 —— 于是
  markdown 表格与代码行不会与时间戳挤在同一段列里。流式尾巴（`live`）在轨迹页里不画时间戳
  （它是还没定稿的那一段）。
- **测试不依赖时区**：断言里的期望值现算（`at.with_timezone(&Local).format("%H:%M:%S")`），
  不写死一个挂着时区假设的字符串。

### §6 不改

事件 schema 与 `Event.at` 之外的任何时钟；`Block` 层与它的产生；plain / headless 渲染器；
`sessions replay` / `sessions show`；模型可见文本；详情覆盖层的施加路径与「打开方」记账；历史重播；
输入区、`/` 菜单、问卷、退出手势与挂起的键位；左栏的宽度两档、`Ctrl-O` 意愿与页高阶梯；
分工函数（`selects`）一个字节不改 —— 对话视图仍只收保留清单。

**`trace-tab` §6 的「左栏不可见时不降级」被推翻**：轨迹页现在在主列里，任何宽度、任何左栏状态下
都可达，所以那条取舍（「过程行暂时看不到」）不再存在。分工规则仍然只有一个：`selects` 依旧只看块，
不看左栏在不在。

### §7 文档

- `CONTEXT.md`：**轨迹视图**（左栏 → 主列）、**页签条**（两条：左栏一条、主列一条）、**对话视图**
  三条词条。
- `docs/render.md`：外壳那张图与「外壳」一节（主列页签条、`CHROME` 7）、「两个视图」一节（归属与
  宽度）、「键盘」一节（滚轮与三键的归属），以及新增的「时间戳」一小节。
- `docs/tui-manual-checklist.md`：⑩ 与 ㉙ 两节改成主列页签与轨迹页（真终端里要看的是 79 列的可读
  性与时间戳列）。
- `.scratch/README.md` 的索引行、`README.md` 的文档一节（若那里的描述提到轨迹在左栏）。

## 测试决定

- **一个 seam：现有的 TUI 帧测试层**（`TestBackend` + 「画一帧、读屏幕」那套 helper），不新增
  seam。这次改动的全部内容仍然是「同一帧里画出什么」。
- 在这一层断言：主列页签条的两个标签与选中档、点击切换、左栏页签里**没有** `轨迹`、轨迹页在主列
  画全量块（含左栏收起与窄终端两种宽度）、两页滚动位置互不影响、回合条只在对话页、时间戳文本
  （期望值现算）、从轨迹页打开的详情关掉后回到原处、键盘三键跟着当前页。
- 纯函数层：`prefix_style` / 时间戳格式各有一条自己的单测。
- 既有断言按新归属改写：`tests/render_layout.rs` 的 tab 组与轨迹页组（`tab_cell`、`click_in_row`
  的落点从左栏换成主列）、`tests/history_replay.rs` 的轨迹页断言、`tests/wording.rs` 的页签常量。
- **不测实现细节**：不断言 pane 内部字段、不为「两个 pane」写白盒测试。

## 明确不做

- **左栏本身的退休**（维护者选了保留）：`Ctrl-O`、宽度两档、页高阶梯都留着，调用量 / todo / 文件
  三页一个字不改。
- **窄档前缀（`PrefixStyle::Bare`）的删除**：它现在不可达（主列恒 ≥ 40 列），但删它要动共享渲染
  路径的签名，属于另一条线索。
- **时间戳进对话视图**、时间戳进 plain / headless。
- **主列页签的键位**（照左栏页签那条「点出来的」规矩）。
- **轨迹页与对话页的联动**（点轨迹里的一行把对话滚到那一回合）：仍走回合条。
- **轨迹页与时间戳的持久化**：都只是视图，不进事件流、不落盘。
- **`live` 尾巴行的时间戳**：它是还没定稿的那一段，定稿时自然带上时刻。

## 补记

- **为什么时间戳不新增时钟 seam**：`Event.at` 已经覆盖了除「诊断 / `Notice`」之外的全部块，而那
  两条在源头打时是它们本该有的形状；渲染层因此不需要一个可注入的时钟，测试也不必伪造时间。
- **为什么回合条不进轨迹页**：它是「我在对话的哪一段」的定位器（`trace-tab` 用户故事 19）。轨迹
  视口的窗口与对话视口不同，拿对话的焦点去标轨迹的格子会指错地方；轨迹页要位置感时有滚动条。

- **用户故事 21 的「还开着的那一行不带时间戳」被
  [`trace-thought-stamp`](../trace-thought-stamp/spec.md) 推翻**（2026-10-06）：开着的思考行按上
  思考开始那一刻，定稿时照旧跳成完成时刻。原文不改写，以那条 spec 为准。

- **实现时落定的三处形态**（与上面几条的初稿有出入，以这里为准）：
  1. 主列页签条花**两行**（标签行 + 它下面一条线），不是三行 —— 屏幕第一行就是标签那一行，
     上边界是屏幕自己。于是 `CHROME = 6`：120×24 给转录 **15** 行、40×10 只剩 **1** 行。
  2. 时间戳那九列里含**尾随那个空格**（`wording::stamp` 交回 `HH:MM:SS `），而**只有块的第一条行**
     带它：折行是窗格做的，那些续行从第 0 列起 —— 时刻是**块**的属性，不是每一行的。
  3. `PrefixStyle` 的窄档分支（去方括号）留着但**到不了屏幕**：主列最小 40 列，恒为宽档。
