# 检视器的面与内容

Type: grilling
Status: resolved
Part of: ../map.md
Blocked by: 07

## 问题

[检视器分面的形态](07-prototype-inspector.md) 给了几帧，这一票拍定。要拍的：

1. **哪些面**。逐个判定（每条给「做 / 变形做 / 不做 + 理由」，回填 [`parity.md`](../parity.md) C 节）：
   概述、原文（Raw）、参数、结果、用量、计时、Schema、上下文差异、来源（跳到产生它的那一行 /
   那一块）。哪些面对衡的七种 `DetailKind`（消息 / 思考 / 工具 / 注入 / 文件 / 改动 / todo）
   有意义 —— 不是每个面都该出现在每种详情里（DSH 就是按记录类型分派的），**分派表要写下来**。
2. **面的顺序与默认面**：打开时落在哪个面、`Tab` / `Shift+Tab` 还是别的键切、点击标签切、
   切面之后滚动位置怎么办（各自记住还是回到顶）。
3. **原文面**：衡今天渲染 markdown。原文那一档给什么（事件的原始 JSON？消息的原始字符串？
   注入的原文？）。**拿不到原文的地方要明说不做**，而不是拿渲染结果冒充。
4. **用量面**（[图](../map.md) 冻结项 5：两处都要）：桶的集合与名称、本次与累计怎么分组、
   一次发言跨多次调用时怎么读（ADR 0016 那条 `合计` 在这一面怎么表达）。
5. **计时面**：字段集合与格式；缺数据时的写法（不许编）；与[时间轴](06-grilling-timeline.md)
   那边同一批数字的分工（谁给精确值、谁给形状）。
6. **参数面与结果面**：JSON 的两种读法选哪个；结果超长怎么截（工具输出今天已经落盘到
   `outputs/<id>.txt`，详情是读盘还是用流上的截断版）；错误与 `ok = false` 各显示什么。
7. **层级跳转**。DSH 能从一条记录跳到它的父消息 / 所属请求。衡要不要（工具行 → 它所在的
   那次模型调用 / 它上面那条用户消息）；若要，它归这一票还是归
   [长历史与行选择](10-grilling-history-and-selection.md)。
8. **覆盖层的记账要不要升级**。今天「一份详情一个覆盖层」，「打开方 + 打开前的滚动状态」是
   `detail_opener` 级的（`files-page` / `questionnaire-reading` 那条线）。分面之后这份记账
   怎么并（同一个覆盖层换面 vs 换一个覆盖层）。
9. **`parity.md` C 节的收口**：每一条判定写回去。

**术语**：如果「面」「检视器」这类词要进 `CONTEXT.md`（今天只有**详情覆盖层**那条词条），
本票负责立词条（`/domain-modeling`）。

## 作答

**一句话**：详情覆盖层分成**面** —— 工具详情六个面（参数 / 输出 / Schema / 计时 / 来源 /
概述）、消息与思考各三个面（正文 / 思考 + 用量 + 概述）、注入两个面、文件与改动与待办**仍是
一个面**；面用顶部一条标签条切，`Tab` / `Shift+Tab` 翻，各面各记自己的滚动位置。

**这一票推翻了一帧的前提**：[检视器分面的形态](07-prototype-inspector.md) 帧 5a / 5b 给
**工具块**画了「本次调用」的用量面，而工具调用**没有用量** —— `UsageRecorded` 是独立事件，
带 `speaker` 但不带 `tool_call_id`（`src/events.rs:444`、`usage_of(events, speaker)`），
`set_tail` 也只挂在 `Painted::Block` / `Thinking` / `Thought` 上（`src/render/tui.rs:1836`）。
所以用量面挂**消息与思考**详情，与行尾那两个数同一处、同一口径。

### 1. 面的容器

**顶部一条标签条**，照主列页签条的画法（`draw_label_bar`，`src/render/tui.rs:6104`）：
标签 + `┆` + 线填满，选中那个 `ACCENT+BOLD`，每个标签在画出时记一个命中矩形。代价是从
主体借走一行（20 → 19）。窄屏截成 07 帧 1c 那一档 `… ┆▐计时▌`。

**面数 ≤ 1 时不画标签条** —— 于是 `File` / `Diff` / `Todo` 三种详情与今天逐字相同，不多一
次按键。（这一条也让「面集合」退化成 `DetailKind → &[Face]`：空表就是没有分面。）

**面里的小节标题只在「这一面有 ≥ 2 节」时画。** 单面正文不顶着与面名重复的那行字；「用量」
面有两组、「计时」面有两节，才需要在滚到中段时认位置。

### 2. 分派表（这张表就是实现的那张表）

按 `DetailKind` 穷举七行 —— `DetailKind` 的 match 本身就是穷尽的，测试可以断言「七种
`DetailKind` 每一种的面集合等于本表」，将来加一种 `DetailKind` 少了哪张表会被抓到。
**不是**「面自己声明适用性」：那会让同一个知识散在几处，而编译器不提醒。

| `DetailKind` | 面（标签条上自左至右） | 默认面 | 标签条 |
| --- | --- | --- | --- |
| `Message` | 正文 · 用量 · 概述 | 正文（今天那一面） | 画 |
| `Thinking` | 思考 · 用量 · 概述 | 思考（今天那一面） | 画 |
| `Context` | 注入 · 概述 | 注入（今天那一面） | 画 |
| `Tool` | 参数 · 输出 · Schema · 计时 · 来源 · 概述 | 参数 | 画 |
| `File` | （今天那一面） | — | 不画 |
| `Diff` | （今天那一面） | — | 不画 |
| `Todo` | （今天那一面） | — | 不画 |

**默认面永远是今天那一面** —— 六种非工具详情的默认面就是今天打开就看到的那一面（行为逐字
不变），「概述」排在标签条末尾。工具默认落在**参数**：它是这次调用最稳定的身份，而输出常常
很长。

**一处偏离，说明理由**：`File` / `Diff` / `Todo` 三种**不给概述面**。它们的主体本身就是一
个完整的可滚动对象（文件正文带行号与语法高亮、补丁带 hunk、清单带勾选），标题行已经说了它是
什么，今天还已经在正文尾部写着截断情况 —— 概述在这里是纯多一次按键。记录类的三面（消息、
思考、注入）不同：一条消息可以是几万 token 的输出，先看「多少字、什么时候、谁说的」有
实际价值。**若维护者要这三张弹窗也有概述面，加一行 `DetailKind → &[Face]` 即可，其余不动。**

### 3. 键位、点击与滚动

- **切面：`Tab` / `Shift+Tab`。** 覆盖层立着时独占键盘，那一支只认 `Esc` / `Ctrl-D` /
  `↑` / `↓` / `PgUp` / `PgDn`，其余键被忽略 —— 所以 `Tab` 在这里是**空着的**，不撞输入框
  的换行，也不撞 `Shift+Tab` 切 mode（那两支都排在覆盖层之后）。
- **点击标签切面**：今天框内的点击是「什么都不做，因为它没有自己的按钮」；标签条给每个标签
  记了命中矩形，落在里面就切面。框外点击照旧关掉整个覆盖层。
- **滚动：各面各记自己的 `top`**，新面第一次看时从顶开始，切回去时还在原处。切面不是滚动。
- **页脚**：仍是 `↕ {当前面内的 pos}/{当前面内的 total} · esc 关闭`。**不加面号** —— 标签条
  已经给了位置，页脚那对数只回答「读到这一面的哪里」。

### 4. 原文面：不做

DSH 的 Raw 面在衡里**缺口是假的**：`Message` / `Thinking` / `Context` 的正文本来就是流上的
原文字符串 —— `detail_body` 走的是 `folded_text(text, width)`，渲染层里没有任何 markdown 渲染
函数（`src/render/tui.rs:8682`）；`Tool` 的结果在没被裁过时就是完整预览，被裁过时读
`outputs/<id>.txt` 拿全文（`read_tool_body`，`:9016`）。那四类**今天已经是原文面了**。

真正缺的只有**事件信封的原始 JSON**，而它两条原因叠着拿不到：块 → 源事件没有记账
（[衡的数据面：数据有没有、缺的怎么拿](01-research-data-surface.md)的横切结论），且要额外读
盘、把渲染层绑到磁盘格式上，收益是让读者看一坨 JSON。**不做。**

### 5. 用量面

桶是 `events::Usage` 的五个（`input_tokens` / `cached_tokens` / `miss_tokens` /
`output_tokens` / `reasoning_tokens`），算法与左栏面板同一套（`Panel::observe` 用
`Usage::accumulate`），所以这一面不会与面板漂移。

**形状照 07 帧 5a**：两节 ——「本次」与「这一趟会话（到这条记录为止）」，每节五行
（输入 / 缓存读 / 未命中 / 输出 / 推理），条形沿用面板那套 `▓` / `░`。末尾一句口径：
**`输入 = 缓存读 + 未命中；推理已含在输出里，这两条不能再相加。`** 「推理」为 `None` 时写
`—（供应商未报）` 且**不画条**：没有分母的条形就是骗人。

**「本次」的口径**：一条消息跨 ≥ 2 次调用时，「本次」就是那几次之和，与行尾那条 `合计` 是
**同一个数**（ADR 0016）—— 两处同源同口径，读者来回对照不会看到两个数。

### 6. 计时面

**形状照 07 帧 7a / 7b**，与[时间轴与计时](06-grilling-timeline.md) §7 的分工一致：轴给形状、
这一面给精确值；等审批的切分（`PermissionAsked.at` → `PermissionDecided.at`）只在这里出现，
轴上不画。

- 每节末尾一行**计时来源**，写清是哪两个时刻相减：`first_token_ms`（ADR 0020）+ 事件信封的
  `at`，或 `ToolCallStarted.at → ToolCallCompleted.at`。
- 老流上没有 `first_token_ms`，那三个量**不存在**：写 `不可用`（DSH 的纪律，照抄）。填 0、拿
  总时长顶上去、或干脆不列都是编。**「不可用」的原因写进同一行的「计时来源」**，不另起一句
  —— 同一场会话里两种长相是预期形态（06 票已认下）。
- 工具的**两个口径**（`duration_ms` 与等审批切分）并排出现，所以要写清「两个口径，不是两个
  可相加的数」。

**降级（新增的一条，07 票没问）**：帧 7a 第一节写的是「这次模型调用」，而**工具行归属哪次
模型调用这件事今天没有记账**（块 → 源行是 10 票那一层）。拿不到归属时**这一面只出现「这次
工具调用」一节** —— 面上只画它自己能证明的那一段，不写「不可用」占位，也不用相邻消息的 `at`
去推。代价是看不到首 token / 生成 / 吞吐，除非 10 票的记账到位。

### 7. 参数面与输出面

**参数**：`serde_json::to_string_pretty` 之后按 88 列折行（今天就是这样，零改动）。缩进保住
类型的形状，嵌套看得见。

**输出**：**原文 + 缩进**，读 `outputs/<id>.txt` 的落盘全文（今天详情读的就是它，不是流上的预览）。
**不做 JSON 树** —— 07 票的理由成立：树要键入交互（展开 / 折叠）才划算，而折叠键位今天空着
（`{` / `}` 未绑，右键与双击连识别机制都没有）。只给静态树的话长数组仍然要竖向滚到底。

错误与「没有结果」照今天：`no_result` → `（流上没有结果）`；有 `error` 就画 `error`（**不标红**
是今天的样子，不在这一票动）；否则画输出；读不回落盘文件时给「全文不可用」。

### 8. 来源面与层级跳转

**来源面有，内容是祖先链三环**（07 帧 8b）：本行 → 它上面那条迭代的回复 → 那一回合 → 上面
那条用户消息，每一环带行首文字与位置。链深不封顶（一个回合最多 557 次迭代），所以**固定截到
三环**并写清。

**跳转的实现归 [长历史与行选择](10-grilling-history-and-selection.md)** —— 它与行选择、稳定
行键是同一层。本票**不押在它上面**：如果 10 票最终没给稳定行键，这一面退成**只读的祖先链**，
仍然有用，因为链上每一环的行首文字本身就是身份。所以 [衡的绘制与输入面](02-research-draw-and-input-surface.md)
指出的「行身份是位置型下标、`CAP` 裁剪让全体左移」这个问题**不阻塞这一面**。

**层级跳转（工具行 → 它所在那次模型调用 / 上面那条用户消息）整体归 10 票**，本票只给来源面里
那条只读链这一档。

### 9. 覆盖层记账：不升级

切面**不改变谁被冻住、关掉时还原给谁** —— `detail_opener` 逐字不动（`files-page` /
`questionnaire-reading` 那条线不受影响）。理由是覆盖层一关就没了，没有「回到上一个面」这回事；
要改记账的是「从覆盖层跳回账本」，那已经归 10 票。

### 10. 交给 spec 的形状清单

- `DetailView` 从「一个 `body`」变成「一组面 + 当前面」：`Vec<Face>`，每面 `{ name, rows,
  top }`，加上 `current`。面名与 `DetailKind` 一起由那张表算出。
- 标签条：借走主体一行；`draw_label_bar` 复用；每个标签记一个命中矩形供点击。
- 尺寸算术仍然只有 `detail_text_width` / `detail_padding` 一处，**覆盖层尺寸一行都不许动**
  （100×30 → 92×26，文字区 88 列 × 22 行 → 主体 19 行）。
- 小节标题的判据（「这一面有 ≥ 2 节」）要在生成面的那一步就决定，不要在画的时候回头看。
- 措辞全部走 `wording`：面名（`正文` / `思考` / `注入` / `参数` / `输出` / `Schema` /
  `用量` / `计时` / `来源` / `概述`）、「不可用」、`—（供应商未报）`、两节的小标题
  （`本次` / `这一趟会话（到这条记录为止）` / `这次模型调用` / `这次工具调用`）、末尾那句口径。
- 七行分派表落成一处可测的常量；测试断言「七种 `DetailKind` 各有本表那几面」。

### 11. 术语

见 [`../../../CONTEXT.md`](../../../CONTEXT.md) 的两条新词条：**详情覆盖层**（此前只有散落
的提及，没有词条）与**面**。`CONTEXT.md` 里既有的**时间轴**与**首 token 时刻**两条是
06 票立的，本票只在「面」那条里引用它们。

**没有新 ADR**：`DetailKind → &[Face]` 这张表改起来是局部的，不满足「难以回退」这一条；
[ADR 0020](../../../docs/adr/0020-first-token-time-rides-the-completion.md) 与
[ADR 0016](../../../docs/adr/0016-usage-rides-the-row-of-its-call.md) 已经为这一面的
两个数据源各自立过了。

### 12. `parity.md` C 节收口

已回填 [`../parity.md`](../parity.md) C 节：分面切换 **补齐**、用量面 **变形做**、计时面
**补齐**、Raw/Summary **已对齐**（今天那份就是原文）、参数与代码面 **变形做**（源码那一档
无对应物）、结果面 **变形做**、Schema 面 **变形做**（拿得到一半）、prompt 差异面 **不做**
（历史 system prompt 不进流，代价已知且不划算）、层级跳转 **补齐（归 10 票）**。图片与附件、
thinking 像素排版、拖拽调宽三条照旧是范围之外。

**新增一条范围之外**：**拖拽调面板宽度**之外，[检视器的面与内容](08-grilling-inspector.md)
这一票确认了**像素级布局手势**（双击复位标签条、右键切面）整类不做 —— 字符格里没有这些词。
