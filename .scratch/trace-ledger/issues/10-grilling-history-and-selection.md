# 长历史与行选择

Type: grilling
Status: resolved
Part of: ../map.md
Blocked by: 02

## 问题

两件事挤在一票里，因为它们是同一个问题的两面：**行是对象**（要选中、要能被键位驱动），而
**行的总量是有上限的**（DSH 用虚拟化 + 分页 + 「加载更早的历史」，衡用 `pane` 窗口 +
`CAP = 20 000` 源行、超出就丢最旧的）。

要拍的：

1. **行选择**（[图](../map.md) 冻结项 4）。键位（`↑` / `↓`，`j` / `k` 要不要）、选中态的形态
   （今天屏幕上没有「选中一行」这种样子，左栏那两页的选中行是 `ACCENT + BOLD` 的先例）、
   `Enter` 做什么（开详情？折叠？展开？）、`Esc` 做什么（清选中 / 关详情，与今天的分层怎么并）。
   选中与**点击**的关系（点一行是开详情还是先选中；今天的点击语义要被明确保护或推翻）。
2. **选中与滚动 / 跟随的关系**：选中之后换页、宽度变化重放（`rerender_if_width_changed` 会把
   轨迹 pane 清空重放）、新块到达时，选中留在哪。
3. **选中与另外两票的接口**：它是[搜索与折叠](09-grilling-search-and-folding.md) 的命中落点、
   是[时间轴与计时](06-grilling-timeline.md) 的区间聚焦落点 —— 三条线谁改谁、谁读谁，写清楚。
4. **`CAP = 20 000` 之后**：今天最旧的源行被丢弃（`the_transcript_keeps_the_newest_twenty_thousand_source_lines`）。
   而那批行其实还躺在会话的 `log.jsonl` 里（`docs/observability.md`、`sessions show` / `replay`
   那条线）。要不要开一个「加载更早」的入口（DSH 是 50 节点一页 + 滚到顶自动加载 + 锚点补偿）；
   要的话：从哪读（磁盘上的事件流？）、一次读多少、读进来的行怎么放进 `pane`（它会挤掉窗口
   末尾吗）、以及**行链接与折叠状态怎么活过这次前插**（DSH 专门讲了行键在 prepend 时的稳定性）。
5. **聚合条数**：账本顶部要不要一句「共 N 行 / 已加载 M 行」（DSH 的 `aria-rowcount`）。
6. **初始位置与边界**：打开会话时停在尾部（今天如此）；跳到最旧一页、跳到某个单位、回到最新
   各绑什么（回合条与「回到最新」指示器今天已经有）。
7. **键盘可达性这一条的边界**：哪些是「必须有」（轨迹页的键位不落空、`Esc` 能退出每一层），
   哪些是 Web 无障碍那一套的对应物、在 TUI 里不需要（`aria-*`、`role` 那批）。
8. **`parity.md` E 节的收口**：每一条判定写回去。

### 0. 本轮新核的事实，以及三处要更正的前提

- **`painted` 不受 `CAP` 影响**：它是 `TuiState` 上的一个 `Vec<Painted>`
  （`src/render/tui.rs:799`），只有 `push` 与宽度重放时的 `mem::take`/放回，**没有任何裁剪路径**。
  `CAP` 裁的是 `pane` 里的折好行加上两张平行表（`trace_links`、回合条），而这三样一律按
  `Pane::push` 返回的那个丢弃数裁（`src/render/pane.rs:61`–`:64`、`src/render/tui.rs:2516`–`:2536`）。
  **「每一块都还在内存里」**这一条是后面 §10 的全部前提。
- **`seq` 就是 JSONL 的行号，落盘与读回原样保留**（`src/events.rs:813`、`:1052`、`:1100`；
  `src/session/observe.rs:776`）。所以块身份从事件派生在两条路径上是同一套值 —— 实时路径与
  会话恢复路径逐字相同（`read_events` → `Session::events()` → `ConsoleRequest::Replay` →
  `replay_batch()` → `apply(RenderEvent::Logged)` → `transcript.push` → `Painted::Block`）。
- **`Pane` 只有追加与改最后一条**（`src/render/pane.rs:80`、`:90`、`:102`），十三个字段全私有
  （`:30`–`:55`）。09 票那个「折叠与过滤都是重放时推什么」的形状在代码上是**唯一可行的形状**，
  不是一种偏好；本票要补的「按行键替换任意一行」是**今天还没有的那一个**入口。

三处要更正的前提（票面与既有票面里的说法，本票以事实为准）：

1. **票面第 4 条的担心反了**。它假设「那批行还在 `log.jsonl` 里，要不要开个口子读回来」。事实是
   **块全都在 `painted` 里、根本没丢**，丢的只是 `pane` 里折好的 `Line<'static>` 加上它在两张
   平行表里的位置；而且从磁盘恢复会话走的是同一条 replay 路径、整场会话都在。所以「读更早的
   历史」这个入口在衡这里**没有要救的东西**（§10）。
2. **「命中高亮用底色」在界面上零先例**。全仓 `.bg(` 只有五处，全是**内容**语义（用户气泡
   `BUBBLE`、diff 的 `DIFF_ADDED`/`DIFF_REMOVED`、外部 ANSI、nvim 回放）。既有通道只有三个：
   `ACCENT + BOLD`（左栏文件页 `src/render/tui.rs:5866`、改动页 `:5976`、页签条 `:6117`）、
   `REVERSED`（**全屏只许一个**，纪律写在 `:5450`，今天的消费者只有问卷 `:5451`/`:5471` 与
   `/·@` 菜单 `:7453`/`:7460`，**详情覆盖层那一层不画反显**）、拖选直改缓冲
   （`src/render/selection.rs:205`）。[时间轴与计时](06-grilling-timeline.md) 那档「区间底色」
   是**第四个通道**，这条要在票里记着，spec 要自己开一条并说清理由。
3. **仓库里没有 `Focus` 类型**。「键盘在谁那里」今天用三套互不相同的机制表达：左栏那个
   `sidebar_keyboard: bool`（`:874`）、两页各自的 `focus: Option<usize>`（`:6372`、`:6392`）、
   以及 `REVERSED` 的隐式归属。而十六层守卫阶梯里**没有任何一层读主列页签**（逐层表见事实票
   §2.2），轨迹页今天只被最后一层内部的 `PgUp`/`PgDn`/`Ctrl-G` 与指针路径上的 `wheel_current`
   认领 —— `↑`/`↓`/`j`/`k`/`Enter` **全部落进输入区**。本票新增的那一层是**第四套**。

### 1. 行身份：块的身份从事件派生，不用位置型下标

- **块身份 = `Event.seq` + 块内序号**。`apply` 今天只取 `at` 就把 `seq` 丢了
  （`src/render/tui.rs:2166`），`Painted::Block`（`:1803`）与除 `Block::Tool` 外的所有 `Block`
  都没有身份字段 —— 这一层要接上。**一条事件可以产出零个到多个块**，所以「一个 `seq` 对应一个块」
  今天不成立，块内序号是必需的。
- **为什么不用另外两种**：渲染时按顺序单调编号（重放时同序重编）能成立，但它是**间接**的 ——
  它要求「重放顺序与实时顺序逐条一致」成为一条不许破的纪律，而那件事一旦破掉，症状是选中的行
  悄悄换成另一个块，没有任何断言会响。内容指纹则要重算，且两块内容完全相同时撞键。事件侧的
  `seq` 是这套系统里**唯一的身份编码**（`src/events.rs:813` 就这么写着），从那里取最省心，
  而且**实时与恢复两条路径自动一致**。
- **代价**：`Block` 与 `Painted` 要多带一个身份字段（渲染层内部的改动，`src/events.rs` 一个字节
  不用动 —— 这是本图第一张**不改事件流**的决策票，06 票那条 ADR 0020 之后没有第二张）。
- **`Pane` 要开一个「按行键替换任意一行」的入口**，并且要记一份「块身份 → 源行」的账
  （它在 `CAP` 裁剪与宽度重放下都要活过今天，这两份下标都被这两件事推翻）。这一层是
  [账本的两级结构与每行信息](04-grilling-ledger-structure.md) §2 那条「组头随回合增长就地改写」
  绕不开的唯一解 —— 09 票的三档折叠走重放所以绕开了，本票不能绕。
- **重放后的定位**：宽度变化重放之后，选中按**块身份**重新定位到那个块的第一条源行。同一件事
  对折叠、命中导航、`n`/`N` 都成立。

### 2. 行选择的粒度 = 块，不是一行一行地选

- 一个块今天能画成多个源行：失败行会多画一行错误正文、增量块会一直长（`Block::Delta`）。
  **选中落点是块的第一条源行**；附属行跟着所属块一起高亮，**不能单独选中**。
- 理由有两条：DSH 那边可选中的本来就是一个 node；而且附属行上 `Enter` 无事可做 —— 要么静默、
  要么报错，要么再加一条「按 `Enter` 把选中归到主行」的规则。三条里最便宜的是不给它这个落点。
- 折行（09 票的三档折叠）**占一个源行**，它就是那个块的落点，选中、展开、点开详情都照常。

### 3. 键盘归属：新增一层，判据是「主列当前显示的是轨迹页 且 未交还」

- 新增一层，排在**详情覆盖层之下、`L5` 记号菜单之上**（`/` 要先到搜索，见 09 票 §1），
  插进 `TuiState::key` 的守卫阶梯（`src/render/tui.rs:4337`–`:4542`）。
- 判据两半：**主列当前显示页是轨迹页**（这一层是十六层里第一个读主列页签的）**且没有处于
  「已交还」状态**（§4）。
- 覆盖层立着时它持有键盘，**嵌套在轨迹页那一层之上**；关掉覆盖层**恢复轨迹页层的原状态**
  （交还过就还是交还着）—— 这照 08 票定的 `detail_opener` **不升级**那条纪律。
- 窄屏降级时轨迹页也可能不在（`trace-in-main` 是主列页签，主列常驻所以通常在），这一层在它
  不在时整个不持有 —— 与那页今天的三键一起消失。

### 4. 焦点与 `Esc`：退完三层就把键盘还给输入区，点账本任何位置再拿回

- **`Esc` 层序**（09 票给的前三层照旧，第四层是本票定的）：搜索模式 → 有**过滤**则清过滤 →
  有**选中**则清选中 → **把键盘还给输入区**。
- 「交还」是**一个显式状态**，不是「轨迹页不再是当前页」。一旦交还，`↑`/`↓` 回到输入区移光标、
  `j`/`k`/`g`/`G`/`Enter`/`Space` 全部失效，直到用户拿回来。
- **拿回**：**点账本任何位置**都拿回 —— 点一行 = 拿回 + 开详情，点空白 = 拿回 + 清选中
  （清一个本来就没有的选中是无操作，所以两个动作叠在一个手势上不打架）。**不另绑键**。
- 轨迹页一旦重新成为当前显示页，**自动回到持有**（不必再点一次）。
- 这个形态**与左栏那两页完全同形**（[焦点行](../map.md) 那条词条：「点左栏任意处把键盘交给这一页，
  `Esc` 只把键盘还回去」），差别只在左栏是「点交还、`Esc` 交还」的反过来。理由写在这里是因为
  将来有人读到第四套机制会问「为什么不统一成一种」—— 统一方向是**以后**的事，本次只求每一处
  内部自洽。
- **轨迹页这一层不画「键盘所在」的反显**：全屏唯一的反显仍只给问卷与 `/·@` 菜单。理由是账本里
  **选中行本身就是那个锚点**，而把整片账本反显会把里面的 `ACCENT + BOLD` 行洗白、让选中反而
  看不见；只给选中行反显则与它的 `ACCENT + BOLD` 白给。这与详情覆盖层今天不画反显是同一条理由。

### 5. 键位表

轨迹页持有键盘的那一层；未列出的一律照旧。

| 键 / 手势 | 动作 | 备注 |
| --- | --- | --- |
| `↑` / `↓` | 选中上 / 下一块 | 收编自编辑器光标，**只在轨迹页持有键盘时** |
| `j` / `k` | 同上 | 全局无绑定，与 `↑`/`↓` 等价 |
| `Enter` | 开选中行的详情 | 09 票定的，不改 |
| `Space` | 折 / 展选中块（组头则折 / 展整个单位） | 09 票定的 |
| `n` / `N` | 下一个 / 上一个命中，**并把选中移到那个块** | 09 票定的，粒度由本票收紧成块 |
| `/` | 进搜索 | 09 票定的，与记号菜单换含义 |
| `g` / `G` | 跳到**第一条**行 / 跳到最新并恢复跟随 | 全局无绑定；跟 `j`/`k` 一套 vim 味 |
| `[` | 跳到所属组头（回合 / 迭代） | 全局无绑定；层级跳转第一向 |
| `]` | 跳到该组第一条成员行 | 全局无绑定；层级跳转第二向 |
| `{` / `}` | 全折 / 全展 | 09 票定的 |
| `Esc` | 搜索 → 清过滤 → 清选中 → **交还键盘** | §4 |
| `PgUp` / `PgDn` / `Ctrl-G` / 滚轮 | **照旧翻页，不动选中** | 已被轨迹页占用；翻页时选中留在原地，这是刻意要的 |
| 左键单击 | **开详情，不改选中** | 今天不变，明确保护 |
| 点空白 | 拿回键盘 + 清选中 | §4 |
| 点组头字形 / 点折行 | 折 / 展 | 09 票定的 |

- **翻页键不改**是刻意的：翻页是「看一眼」而选中是「我要在这里做事」，让前者推动后者会让长会话里
  随手翻页变成一处不可见的改动。`g` / `G` 补上「跳到头/尾」这两个今天没有的落点。
- **`Home` / `End` 不征用** —— 它们是编辑器行首/行尾（`src/render/tui.rs:2790`–`:2791`），
  `g` / `G` 在轨迹页持有时才是「跳到头/尾」，语义分工不重叠。
- **层级跳转**是 08 票明确交给本票的（那张票只给了详情里只读的祖先链，键盘上还没有对应物）。
  `[` 往上到所属组头、`]` 往下到该组第一条成员行；**从组头再按 `]` 就是进它的第一条成员**，
  于是两级分组兑现成可导航的结构。方向键里没有第三个方向可用（`←`/`→` 在左栏两页已被占用），
  所以用两个成对的括号键。

### 6. 选中态的画法：整行 `ACCENT + BOLD`

- 照左栏**文件页**（`src/render/tui.rs:5866`）、**改动页**（`:5976`）与页签条（`:6117`）的先例，
  **不新开通道**。选中行是「键盘在这」的可见锚点，所以它同时承担了「焦点可见」这件事（§4）。
- 不用底色：底色在界面上是**内容**通道（五处全在内容上），把它借给界面元素就把两条通道搅在一起；
  也不用反显：见 §4。
- 与命中底色的关系：两者**不同时出现**（选中行必然在过滤集里，所以它总在账本上；而命中底色在轴上）。

### 7. 点击与选中的关系：照旧

- **点一行就是开详情，不顺手选中**（今天不变，明确保护）。理由是点开详情那一刻行被详情覆盖层
  盖住大半，用户紧接着多半是 `Esc` 关掉它 —— 关掉之后「高亮突然落到刚才点的那一行」是能感觉到的
  跳动，尤其当用户只是**看一眼**一行的时候。
- **点空白 = 拿回键盘 + 清选中**（§4）：清掉一个空选中是无操作，所以清不清是同一件事。
- 于是**鼠标与键盘的模型不同但都不别扭**：鼠标负责「看一眼」（点开就走），键盘负责「在这里做事」
  （选中 + `Enter` / `Space` / `[` / `]`）。

### 8. 选中与滚动 / 跟随 / 重放

- **宽度变化重放**：选中锚在**块身份**上，重放之后重新定位到那个块的第一条源行（§1）。视口位置
  由 `Pane::clear` 保留的 `top_source` 兜住（事实票 §1.3）—— 两条纪律叠起来：**视口记位置、
  选中记对象**。
- **新块到达**：**视口照跟随走，选中留在原地**。代价是选中可能滚出视口（页很大时会），但把视口
  拉回选中会让实时账本没法看。滚出之后再按 `↑` / `↓` / `n` 就跳回来。
- **翻页 / 滚轮**：不动选中（§5）。
- **过滤集切换**：**选中的块若不在新过滤集里，选中留着、只是不画**。选中与折叠集、过滤集一样存在
  `TuiState` 侧按块身份记（09 票 §8 的纪律），而过滤是重放时推什么的结果，两者**不互相清**。
  清完搜索回到全量视图时，原先那一行还在高亮。
- **过滤期间跟随暂停**（09 票已定），本票不动它。

### 9. 与另外三票的接口

- **[搜索与折叠](09-grilling-search-and-folding.md)**：它把 `n` / `N` 定成「跳命中并把选中移到
  命中块」，本票把那个「移到块的第一条源行」的粒度钉死成**块**（09 票 §10 说「行级粒度由它收紧」，
  就是这一条）。它交出来的过滤集与折叠集**已经是按块身份存着的**，本票复用同一套身份、没另立
  一套。它定的「折行就是那一行、可选中」与本票的「粒度 = 块」一致。
- **[时间轴与计时](06-grilling-timeline.md)**：它把轴的输入钉成「行选中 + 搜索命中 + 折叠要按行替换」
  三条。本票兑现第一条的一半：**轴上那个位置标记画在选中块首行的那一刻**（块粒度，不是行粒度）；
  第三条它自己降级成了重放。**轴不因为选中而产生过滤**（09 票 §4 已定，本票不动）。
- **[检视器的面与内容](08-grilling-inspector.md)**：它把**层级跳转整体交给本票**，本票在 §5 给
  了 `[` / `]`。它的「来源」面是**只读的祖先链**（块 → 迭代 → 回合 → 用户消息），当初刻意**不押在
  稳定行键上**；现在行键有了，但**不改那张票的形状** —— 只读链仍然有用，而让键盘跳转复用它会把
  「面里的一环」与「键盘上的一跳」绑在一起，跳转一旦改动面也得改。
- **[账本的两级结构与每行信息](04-grilling-ledger-structure.md)**：§2 那条「组头随回合增长就地改写」
  绕不开重放，它的解就是本票 §1 的「按行键替换任意一行」。**它是那一层的唯一消费者**，本票这一层
  不再被别人用到。

### 10. `CAP = 20 000` 之后：这一版**不画回来**

- **判「不做」**，三条理由：
  1. **要救的东西没丢**：`painted` 里的块全在（§0 第一条），`CAP` 丢的只是折好的显示行与两张
     平行表；而整场会话在会话恢复路径上是从 `log.jsonl` **原样 replay** 回来的（`seq` 还是同一个
     `seq`）。所以「加载更早」在衡这里没有一个它是去救的场景。
  2. **要做只有一个办法，而且很贵**：让 `pane` 记住总量与视口、要滚回去就重放到那一行 —— 那是
     `Pane` 的结构改造加 O(k) 重放，块要能重新折行。换来的能力是「翻过第 2 万条源行」，而真实会话
     里翻到那儿的人极少（`CAP` 已经是 2 万）。
  3. **不做就没有两个真相源**。真去从磁盘补前插的块，`painted` 就有两份来源，而「回放时块序与
     `seq` 序一致」这条纪律就得再守一遍。
- **`parity.md` E 节「分页：50 节点一页、加载更早、滚到顶部自动加载、锚点补偿」整条判「不做」**，
  理由写在上面；DSH 那边的行键在 prepend 时的稳定性问题随之不存在 —— 我们根本没有 prepend。
- **诚实记一笔代价**：超过 2 万条源行的会话，**翻到顶也看不到头**（今天就有测试钉住这个行为：
  `the_transcript_keeps_the_newest_twenty_thousand_source_lines`，
  `tests/render_layout.rs:2997`）。以后若有人要把它拿回来，正解在 `pane` 那边（重放式虚拟化），
  不在磁盘那一侧。
- **这一版不做 ≠ 这一条永久关闭**：`CAP` 是不是该调大、以及要不要改成重放式虚拟化，是将来的
  独立 effort；地图把它记在**范围之外**，不在这张图上重开。

### 11. 聚合条数：**不做**

- DSH 的 `aria-rowcount` 是给屏幕阅读器的，字符格里**没有那个消费者**（票面第 7 条问的就是这个）。
- 而且 §10 定了「不加载更早」之后，「共 N 行 / 已加载 M 行」里那半个 M **恒等于总数** —— 一句
  恒真的信息不如不写。
- `parity.md` E 节那一行改判为**不做**，理由同上。

### 12. 初始位置与边界

- **打开会话停在尾部**（今天已有，`Follow` 一开始就是贴底），不动。
- **`g` / `G`**：`g` 跳到账本第一条行（不是「第一页」—— §10 之后没有页这个单位），`G` 跳到最新
  **并恢复跟随**（所以「新内容指示器」那一支不在这条键上，它归跟随自己）。
- 「跳到某个单位」由 `[` 覆盖（跳到所属组头）；回合条今天**只画在对话页**（唯一调用点
  `src/render/tui.rs:6873`），而「回到最新」指示器**两个视图各有一个**
  （`state.indicator` / `state.trace_indicator`，`:1022`/`:1024`）—— 所以轨迹页这一侧有的只是
  后半截，票面第 6 条里「回合条」那半个前提不成立。
- **切主页签不动选中**：切走再切回来，同一份选中还在（它在 `TuiState` 侧按块身份记）。

### 13. 键盘可达性的边界：哪些必须有

**必须有**（写进 `docs/tui-manual-checklist.md`）：

1. 轨迹页持有的键位不落空 —— 上面那张表里每一条都有确定行为。
2. **`Esc` 每一层都有出口**，且层序是**一次手势一层**（与左栏两页同一条纪律）。
3. **键盘拿得到、也还得了**：不靠鼠标就无法进入这一层（`Esc` 交还 → 点账本拿回 → 切页自动持有）。
4. 选中永远可见或可找回：滚出视口后 `↑`/`↓`/`n`/`G` 任一条都能回到它。

**不需要**（在 `parity.md` E 节那行「键盘可达」下写明，免得下次又当成差距）：

- `aria-*` / `role` / `tablist` 那一整套：那是 Web 无障碍树，字符格里没有消费者。真正对应的是
  「每一层都有出口」与「键位不落空」，这两条已经在上头。
- `Enter` / `Space` **选中**（DSH 用它们选中行）：衡把「选中」绑在方向键上、`Enter` 留给「开详情」，
  与「点一行开详情」的既有语义对齐；`Space` 留给折 / 展（09 票）。
- **悬停 tooltip / 像素手势**：见地图的范围之外。

### 15. 术语变更点（供 `/domain-modeling` 落到 `CONTEXT.md`）

- **新词：选中（Selection）** —— 轨迹视图里键盘认的那**一个块**。与左栏那两页的**焦点行**分界：
  那边是「左栏两页里的一行」且有页专属键（`→`/`←`/`r`），这边是「主列轨迹账本里的一个块」且只有通用
  键。判据四句：`ACCENT + BOLD` 画在整行；`↑`/`↓`（或 `j`/`k`）移动；`Esc` 依次清搜索 / 清过滤 /
  清选中 / **交还键盘**；点账本任何位置**拿回**键盘。
- **新词：行身份（LineIdentity）** —— 一条源行的地址不是它的位置下标，而是**块身份 + 块内第几行**，
  块身份从事件信封的 `seq` 派生。位置下标会被 `CAP` 裁剪与宽度重放推翻，行身份不会。
- **补：行（Line）** —— 09 票说这一条要等本票拍完才立得整条，现在立：**一条源行**是账本上可寻址的
  落点，**折行也是一个源行**（它代表整个块，详情链接照挂）；而**选中是块级**的，一条块的第一条源行
  才是它的落点。
- **不动**：**焦点行**那条词条已经写着左栏两页的同形纪律（「点左栏任意处交还、`Esc` 只还回去」），
  本票沿用它而不改它的内容。
