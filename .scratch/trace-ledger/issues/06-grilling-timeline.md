# 时间轴与计时

Type: grilling
Status: resolved
Part of: ../map.md
Blocked by: 01, 05

## 问题

[时间轴在字符格里的候选形态](05-prototype-timeline.md) 给了几帧，[衡的数据面](01-research-data-surface.md)
给了数据底账。这一票把它们合成**一个决定**：

1. **做不做、做哪一种**。三种候选里选一种（或组合）；如果数据面显示某几条关键量根本拿不到，
   要说清「拿不到的那部分时间轴上读成什么」（不编数字是纪律）。
2. **画在哪、占多少行**。顶部固定？跟着滚动？占几行、从谁的预算里出（轨迹页今天拿到的是
   主列内容区，`CHROME` 一行都不多给）。
3. **泳道怎么分**。DSH 是输入 / 模型 / 工具。衡这边「输入」对应什么（`ContextInjected` 与
   请求组装都是瞬时的）？模型调用的 span 用什么上下边界（`TurnStarted.iteration` 到哪）？
4. **TTFT / 生成 / 吞吐这一条路**（本票的核心分叉，吃数据面的结论）：
   - 不动事件流 → 时间轴与计时面只画「模型调用的总时长」，TTFT 那一格永远空缺；
   - 只渲染层记 → 实时会话有、`--continue` 重放没有（屏幕上会出现「有的会话有、有的没有」）；
   - 新增可选事件字段 → 要写一条 ADR、要动 [`parity.md`](../parity.md) 记下的那条不变量。
   **定下走哪条，并写清代价。**
5. **交互词汇**。DSH 是拖选区间 / 滚轮缩放 / 右键平移 / hover 500 ms。字符格里的对应物：
   有没有「选中一个区间」（用什么手势：拖选？点两下？键位？）、要不要缩放、要不要平移；
   还是干脆只读（只跟着当前选中的行高亮）。**明确写下放弃哪几样**（[图](../map.md) 的
   「范围之外」里已有像素手势那条，这里要落到轨迹页自己的取舍）。
6. **与另外两件事的关系**：区间聚焦与[搜索与折叠](09-grilling-search-and-folding.md) 的过滤
   是不是同一套机制；时间轴的选择与[长历史与行选择](10-grilling-history-and-selection.md)
   的行选中谁是主、谁跟着谁。
7. **计时面（检视器里那一份）与时间轴的分工**：同一批数字在两处出现时各显示什么（DSH 是
   inspector 给精确值、overview 给形状）。
8. **`parity.md` B 节的收口**：那一节每一条的最终判定写回去。

## 作答

**收口于 2026-10-09，五轮 grilling 共十五问。** 输入是 [时间轴在字符格里的候选形态](05-prototype-timeline.md)
的十二帧、[衡的数据面](01-research-data-surface.md) §2 / §3 / §8-B / §9 与
[衡的绘制与输入面](02-research-draw-and-input-surface.md)。下面按票面八条逐条落，最后是给 spec 的交接。

### 1. 做不做、做哪一种 —— 做，取候选一的三行版

**顶部横带 3 行：刻度行 + 模型泳道 + 工具泳道**，固定在轨迹内容区顶部、不随账本滚动。

- **候选二（行内迷你条）不做**。它必须有个分母：按整趟归一化时 0.2 s 与 0.4 s 的调用塌成同一格，
  按本回合最大值归一化时分母会随新调用变化、行与行从此不可比；而「这一行自己多长」这件事已经
  由 [账本的两级结构与每行信息](04-grilling-ledger-structure.md) 定在**行尾耗时**上 —— 同一个数字
  不画两遍。
- **候选三（贴状态行 / 并进状态行）不做**。贴状态行的那 1 行是从账本 15 行里挪的，贴底跟随时
  正好盖住最新一行；并进状态行只剩 14 列（一格 3.4 s，比横带粗 5.3 倍），且它在降级阶梯最末尾。
- **4 行的版本（多一条空档泳道）不做**：空档靠两条泳道之间的留白读，多一行换 27% 的可视高度太贵。
- **泳道恒为两条**：模型与工具。**「输入」泳道不做** —— 请求组装没有事件，`ContextInjected.at`
  只发生在会话开场 / 载技能 / 跨阈值三类时刻，拿它冒充输入耗时说谎（数据面 §2、§9 第 5 条）。

### 2. 画在哪、占多少行

- **位置**：轨迹内容区顶部固定 3 行。今天不参与 pane 滚动的顶部区域就是主列页签条那一支
  （`src/render/layout.rs:441`），照它抄。
- **代价**：120×24 下轨迹页可视 15 行 = 24 − `CHROME`(6) − 输入行(3)（`src/render/layout.rs:422`、
  `:29`、`:421`），带吃掉 3 行 → **账本 12 行**。
- **落地必须两处一起改**：固定区从 2 行撑到 5 行（矩形高度 + 画家那处硬编码的 `+1`），同时把
  `CHROME` 从 6 改成 9。只改前者会把状态行与底部块顶出屏幕，只改后者固定区没有位置。
- **横轴的宽度口径要更正**：prototype 帧里的 74 列是它自己的假设（把 79 当正文宽），实现里 79 是
  **主列宽** —— 扣掉滚动条与回合条那 2 列、再扣 9 列时间戳后正文 68 列
  （`src/render/tui.rs:2396`、`src/render/layout.rs:51`、`:58`），泳道标签再吃 5 列 → **横轴 63 列**，
  一格 ≈ **0.76 s**。帧里的代价结论方向不变、数值偏乐观（48 s 那趟是 74 格里一格 0.65 s）。
- **降级阶梯**：宽度不足先**稀疏刻度** → 再退成**一行的三态版**（帧 1c）→ 仍不够**整条不画**；
  高度不足时**账本优先**，整条让位。带在任何形态下**不可聚焦**：不进键盘阶梯、不响应鼠标、不产生过滤。
- 刻度标签的排布（帧 1a 的排法：起止 + 三个中点，`HH:MM:SS`）与稀疏化阈值归 spec。

### 3. 泳道怎么分（时间口径）

- **模型泳道**：一条 span = `TurnStarted(iteration=k).at` → 下一个**同 speaker** 的 `TurnStarted`
  或该回合 `TurnEnded` 的 `.at`（数据面 §3）。它含极少量的组装与预算检查时间（`src/agent.rs:590-632`），
  这就是诚实的「模型这一段」。
- **工具泳道**：一条 span = `ToolCallStarted.at` → `ToolCallCompleted.at`；**并发的调用会重叠**，
  泳道要能叠（数据面 §8 B 节）。口径是调用墙钟（含钩子、权限与排队，`src/agent.rs:956`）。
- **空档**：两条泳道都没盖住的列就是留白，不写解释性文本 —— 它的成因（组装？排队？）在流上没有名字。
- 与账本**同源**：轴读的是块级的 `at`（事件信封），与行首 `HH:MM:SS` 同一个来源。
- **整趟跨度增量累积**：照 `trace_links` / `turn_rail` 的先例，在数据到达时维护一份整趟 span 表，
  轴的每帧只读它，**不每帧重扫 `painted`** —— `pane` 有 `CAP = 20_000` 源行而 `painted` 完全没有裁剪，
  每帧重扫会随会话线性长（今天也没有别处每帧遍历全部块；寻址全是二分 / O(1)）。

### 4. TTFT / 生成 / 吞吐这条路 —— **动流**

**给 `MessageCompleted` 加一个可选字段 `first_token_ms: Option<u64>`**（首个增量 token 距本次调用
开始的毫秒），并写 [ADR 0020](../../../docs/adr/0020-first-token-time-rides-the-completion.md)。

- **口径 = 首个增量**：`TextDelta` 与 `ReasoningDelta` 先到者。屏幕上第一次动就是等待结束，而推理
  生成本来也是生成。
- **一个字段推三个数**：TTFT = 它；生成时长 = `MessageCompleted.at − (TurnStarted.at + 它)`；
  吞吐 = `output_tokens / 生成时长`。
- **代价**（数据面 §2 逐项查过）：可选字段双向兼容（老流缺字段读成 `None`，老二进制读新流忽略未知
  字段）；要涨 `SCHEMA_VERSION` —— 它只是记号，`src/` 里没有任何按版本分派的读取逻辑；三处产点
  在主循环与合成器（`src/agent.rs`），用户消息那一条恒 `None`。
- **被否决**：只在渲染层记（`--continue` 与宽度变化重排走不到增量事件，同一条流「实时有、重开没有」，
  屏幕上会出现「有的会话有、有的没有」）；新增一条事件变体（**单向不兼容**，老二进制 `read_events`
  拒读整条流，`--continue`、`sessions show`、`sessions replay` 全挂）。
- **时间轴怎么用它**：模型泳道按 TTFT 切成**「等首 token」与「吐字」两段**；**不足一格的段保底不画**
  （宁缺勿假），精确值归检视器。两段的字形 / 色调归 spec（等首 token 用 `MUTED` 族，吐字用前景）。
- **缺失三态、一律不写占位符**：老流 / 供应商没报 usage → 模型泳道**整段画**、检视器**不列**那三行
  （不写「未知」）；正在流的那一段 → 画到当前时刻、右端不收边、不给时长数字（parity B 节那条纪律，
  先例是思考行开始时只写开始时刻，`src/render/tui.rs:2840-2842`）。

### 5. 交互词汇 —— **不做独立手势**

- **明确放弃四样**：**拖选**（与终端自身的拖选 + OSC 52 复制冲突）、**缩放**（一格 0.76 s 的分辨率是
  硬约束，缩放只会重新归一化或说谎）、**平移**（轴跟随会话与焦点）、**hover**（字符格里没有）。
- 轴的**输入只有两种**：**行选中**与**搜索命中** —— 它们是主，轴是消费方；轴不产生过滤。
- **轴域 = 整趟会话**（不滑动窗口、不缩放，会话越长一格越粗，这是诚实的形状）；**视口**用刻度行的
  **区间底色**标出，不额外占行（帧 1d 的那一行 `▔▔▔` 并进刻度行）。
- **选中行**在轴上画一道**位置标记**（`│`）：语义是「**位置精确、长度有下限**」——不足一格不画长度。
- **回合边界**在模型泳道里画一道 `│`；迭代边界不标（一个回合 1–557 次迭代，太密）。当前选中行
  所属的回合用底色段呼应。
- **新增一档「区间底色」**进 `src/render/palette.rs`：今天没有可复用的命中底色（`BUBBLE` 是用户消息
  气泡的语义），过 [ADR 0015](../../../docs/adr/0015-mark-light-sweep.md) 那族的色板纪律。
  [搜索与折叠的形态](09-grilling-search-and-folding.md) 的命中高亮可以复用它。

### 6. 与另外两件事的关系

- **[搜索与折叠的形态](09-grilling-search-and-folding.md)**：区间聚焦**不是**另一套机制 —— 它由行选中
  与搜索命中驱动，机制本身（命中判据、褪色还是过滤）归那一票。帧 4a 留给它的输入：判据取「跨度与
  区间**相交**」还是「**开始时刻**落在区间里」—— 票面自己那个例子（取 09:12:25 → 09:12:26 时，
  bash 那行跨过了它）说明两条都真、必须选一条。
- **[长历史与行选择](10-grilling-history-and-selection.md)**：**行选中是主，轴跟着它**，不反过来。
- **「行 → 块 → 时刻」那层记账**：[图](../map.md) 的「尚未明确」第一条挂着它。这一票把需求钉成三条
  （选中驱动、命中驱动、折叠要按行替换），**归属留给 09 / 10** —— 06 只声明自己是消费方，不把
  interface 抢在手里。

### 7. 计时面与时间轴的分工

- **轴给形状、检视器给精确值**（DSH 也是这个分工）：轴读「哪一段在等、占多少」；检视器的计时面读
  确切数字（开始时刻 / 总时长 / TTFT / 生成 / 吞吐 / 计时来源）。检视器列哪几行归
  [检视器的面与内容](08-grilling-inspector.md)；本票只钉「同一批数字在两处是同一套口径」。
- **工具耗时的两个口径**：轴画 `duration_ms` 的**总跨度**；**等审批**
  （`PermissionAsked.at` → `PermissionDecided.at`）的切分**只在检视器**里出现，并说明「工具 3.0 s /
  其中等审批 2.4 s」是两个口径、不能并排放着不说明（帧 5b 的教训）。DSH 的切分也只发生在模型泳道。

### 给 spec 的交接

1. **动流那一笔先做**：[ADR 0020](../../../docs/adr/0020-first-token-time-rides-the-completion.md) 不依赖
   这次 effort 的其他部分（[图](../map.md) 冻结项 8：不依赖新数据的那半先做）。
2. **已经定死的口径**：模型 span 的上下边界、工具 span 与它的两个口径、轴域与位置感、两段切分的
   保底规则、缺失三态、降级阶梯、不可聚焦。
3. **留给 spec 的形状细节**：刻度标签的排布与稀疏化阈值、两段切分的字形 / 色调、区间底色的色号、
   降级阈值的列数、可见行数的告示语。
4. **边界**：模型可见文本零变化（投影不读新字段）；事件 schema 只多一个可选字段；键盘面只增长在
   **行选择**那一层（归 [长历史与行选择](10-grilling-history-and-selection.md)），轴一个字都不吃键盘。
