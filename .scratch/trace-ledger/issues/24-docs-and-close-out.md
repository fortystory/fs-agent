## 收口前的补记

**Schema 面是收口时补上的（2026-10-11）。** 规格 §6 与用户故事 39 给工具详情**六**面
（参数 / 输出 / Schema / 计时 / 来源 / 概述），而票 13 落了四面、票 14 补了「来源」成五面 ——
这一面**没有任何一张票接它**，于是规格与实现差一面。补的时候顺手把这两件事定下来，写文档的人
照这个口径写：

1. **面序**：分派表里工具那一行是 `参数 · 输出 · Schema · 计时 · 来源 · 概述`，**默认面仍是
   参数**（行为不跳）。所以标签条上 `Schema` 落在「输出」与「计时」之间。
2. **画什么**：这次调用那个工具在**工具表**里的声明（发给 provider 的那份 JSON Schema），
   **原样** `pretty` 打印、按覆盖层的正文宽折行 —— 与参数面同一套 `folded_text` 排法。
   数据来自 `Registry::specs()` 的 `parameters`，与 `agent` 每次请求发给 provider 的是同一份，
   所以渲染层画的就是模型手里的那一份。
3. **怎么拿到那张表**：渲染层自己够不着工具表，于是照 `number_style` / `file_viewer` 那条既有
   纪律，在**组装时注入一次**（`SessionFacts::tool_schemas`，工具名 → 那份 JSON Schema）。
   组装点在 `src/cli.rs` 两条交互式路径（单 agent 与讨论）里：工具表在建渲染器**之前**建出来，
   声明抄一份进 facts，同一张表再交给脚手架。注入的是**主会话那张表** —— 执行者手里的
   `Registry::for_executor()` 是它的子集，所以这个名字集合覆盖得了这一场会话里的每一次调用。
   工具表建完不再变（工具数组是缓存前缀的一部分），所以注入一次就够。
4. **降级那句话**：表里没有这个名字时写
   **「工具表里没有「<名字>」，这次调用的声明查不到」**（`wording::detail_schema_missing`），
   **不画空面、不编一份 schema 出来**。查不到有两条来路、对读的人是同一件事：重放一场老会话时
   那个工具已经不在这一场会话的表里；一次没有配对开始的调用（转录把工具名记成 `?`）。
5. **`CONTEXT.md` 一个字不用改**：**面**词条写的就是六面（含 Schema）。
6. **`mcp_call` 转发出去的那个工具，它的 schema 不在本地。** 这一面画的是**这次调用那个工具**
   在工具表里的声明 —— 对一次 `mcp_call` 来说就是 `mcp_call` 自己那份（它是四个元工具之一，
   确实在表里），**不是** server 端被转发工具的参数 schema。server 的工具永远不进工具表
   （`docs/mcp.md`），所以那一份本地拿不到。`parity.md` 里「写『不可用』并给替代读法、不拿
   `mcp_call` 自己的 schema 冒充」那句说的是**别把两者混成同一件事**；这次的实现没有冒充
   server 端那一份（它压根不画），但逐面文档里要把「这一面是谁的声明」写清 —— 否则读者会以为
   他看到的是被转发工具的参数。

### 与票面不同的地方

1. **分派表按实现写，不是「六个 / 三个 / 两个 / 单面」。** 票面给「检视器的面」一节定的那个
   形状，而实现里**消息与思考各是四面**：票 13 就落了「计时」面（它第 4 条写 `Message` =
   正文 · 计时 · 概述），票 15 再插进「用量」面。`spec.md` §6 里三面的 `Message` 是过时口径
   —— 逐面文档跟着各票的落地记录走（工具六面 / 消息与思考各四面 / 注入两面 / 文件·改动·待办
   单面）。
2. **`CONTEXT.md` 的「单位」词条原本不存在**，本票新立一条。票面「现状」与 `spec.md` §13 都
   说它「已随票落下」，实际那一句只住在 `spec.md` 的「补记」与 `wording.rs` 的注释里；照票面
   第 1 条把它补进词汇表。
3. **过滤词条里「在时间轴上走弱色」是错的**，改成实现的口径：未命中的段**不调弱**（只是不加
   底色，票 11 §6 / 票 23 第 4 条），而过滤期间**一律展开**、折叠集合一个字节不动（票 21 第 8
   条）——「各块自己的折叠态原样留着」那半句一并改掉。
4. **无主段落的小标题只写了两类**：`/clear` 之后那一段判不做（票 16 的落地记录：新会话段在
   转录层不产块，拿不到判据），文档写 `开场 · N 条注入` 与 `压缩 · 前面若干轮压成摘要` 并写明
   第三种不做。形状也**不带 `▸`**（展开态一律不用它，它只留给折行）—— 票面例子里的那个 `▸`
   是 04 票被它自己的 §10 推翻的写法。
5. **「启动检查不受影响」的理由按实情写。** 票面（与 `spec.md` §13）说「横带选了框架那套虚线
   之后计数自然上升」，而实现里横带的填充是块元素（`▔` / `▁` / `█`）、边界是 `│`，与虚线无关；
   这一轮让虚线计数上升的是**组头与一级折行**（它们用的就是框架那套 `┄`）。文档照实情写。
6. **`.scratch/README.md` 那一行顺手压过一轮**：旧行里「八组真帧、十二帧、24 帧」那串复述与
   六条决策票链接在 `map.md` 的「已定的决定」里各有一份，而它要收成最终票数。压缩之后实测
   非空白字符 13,191 → **12,924**，所以**没有动** `scripts/check-doc-size.py` 的入口预算棘轮。
