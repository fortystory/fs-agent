# 过滤这一档在界面上怎么被读出来：状态行与轴

Type: grilling
Status: resolved
Part of: ../map.md
Blocked by: 09, 10

## 问题

[搜索与折叠的形态](09-grilling-search-and-folding.md) 把过滤与折叠定成「重放时推什么给 `pane`」，
并把**时间轴区间聚焦整体判不做**（轴不产生过滤，视图里唯一的过滤集来自搜索命中）。但它刻意留了
两件事没拍，都写在它自己的 §13「新浮出两条 fog」里，也记在[图](../map.md) 的「尚未明确」第一条：

1. **状态行怎么显示这一档。** 要回答：`n 个命中 · 新增 M` 怎么写、搜索模式时查询串显示在哪、
   **无匹配时显示什么**、过滤态与折叠态是否也要报、以及它与 `wording::status_row` 现有四段
   （模型 + 思考强度 / 模式 / 上下文 / 状态词）那条**降级顺序**怎么排 —— 状态行是全屏唯一
   「永远在场」的一行，加东西只能从既有段里借地方。
2. **命中在轴上到底怎么画。** [时间轴与计时](06-grilling-timeline.md) 给了「区间底色」这一档
   形状，但**命中集怎么排布**没定：连续命中合成一段底色，还是每个命中块一根细刻度？未命中的段
   走弱色到什么程度？以及**轴上那个「选中」位置标记与命中底色同时出现**时谁压过谁 ——
   [长历史与行选择](10-grilling-history-and-selection.md) §9 已经把选中标记钉在**选中块的首行**
   那一刻。

## 前提（已在别处定死，别在这里重开）

- **过滤集只有一个**，来源只有搜索命中；**行选中不产生过滤**，**轴不产生过滤**（09 票 §4）。
- 过滤期间**跟随暂停**；命中的新块照样进账（09 票 §3）。
- **组头不因过滤改写** —— 那是该单位全体成员的直方图，不是命中成员的（09 票 §3）。
- 索引覆盖**整场会话**、不受 `CAP` 裁剪（09 票 §2）。
- 轴**不可聚焦**、不进键盘阶梯、不响应鼠标；轴域是**整趟会话**、视口用刻度行的区间底色标
  （06 票 §1–§3）。横轴实测 63 列、一格 ≈ 0.76 s。
- 底色通道在界面上**零先例**：全仓 `.bg(` 只有五处且全是内容语义（用户气泡、diff、外部 ANSI、
  nvim 回放）。这次要开的是**第四个通道**，所以「为什么不用 `ACCENT`/`REVERSED` 那一档」要在票里
  说清（10 票 §0 第二条）。

## 作答

2026-10-09，与维护者三轮 grilling 十一问（命中数放哪 / 写什么字 / 轴上命中怎么排 / 选中标记与
底色的叠压 / 底色画在哪一行 / 浮字位两件事同位 / 无匹配怎么写 / 未命中要不要调弱 / 合成段的阀值
/ `G` 在过滤期间做什么 / 两条通道怎么不撞）。冻结项 1（图只产 spec）、7（模型可见文本零变化）
未动；本票只碰视图的一层显示，**不动事件流、不动 `Pane`、不动键盘阶梯**。

### 0. 本轮新核的三条事实

- **状态行是两个视图共用的一行**：`wording::status_row`（`src/render/wording.rs:2236`–`:2281`）
  四段是 `[模型 + 档位, 模式, 上下文, 状态词]`，宽度阶梯三档（`&segments[..]` →
  `&segments[1..]` → `&segments[2..]`），最后一档永远在场、超宽截断而不丢。而
  `draw_status` 每帧只调一次（`src/render/tui.rs:6154`）—— 所以**在对话页显示「n 个命中」
  是一件假事**，除非把过滤读法改成「切到轨迹页才看」。
- **「N 条新行」不在状态行上**：那是内容区右下角的一个浮字，`draw_indicator`
  （`src/render/tui.rs:7041`–`:7085`）—— 跟随中不画；`fresh == 0` 时写
  `wording::back_to_bottom()`（回到最新），否则写 `wording::new_content(fresh)`（N 条新行）；
  前景是 `palette::ACCENT` + `BOLD`，贴右缘、占倒数第二行，**每视图各一个**
  （`state.indicator` / `state.trace_indicator`，`:1022`/`:1024`），**而且它是可点的**
  （`indicator_hit` → `to_bottom()`，`:3252`–`:3253`）。详情覆盖层开着的时候轨迹页那个还冻结
  （`:7051`）。
- **`Block` 的分法与轴的两条泳道不是一回事**：`Block` 有 `Delta` / `Message` / `Answer` /
  命令 / 工具 / 注入 / todo 那几类（`src/render/transcript.rs:26`），而横带只有模型与工具两条
  泳道（输入泳道 06 票已判不做）。所以「命中在轴上落在哪一行」必须有一条**可执行的判据**，
  不能靠「看起来属于哪一类」（§6）。

### 1. 状态行一块都不动

- 这是对票面第 1 条那个问句最干脆的回答：**不加段、不改降级顺序、不碰 `wording::status_row`**。
  理由是第一条事实：那一行两个视图共用，而过滤只属于轨迹页 —— 加进去就要加「只在轨迹页非空」
  这种分支，而状态行今天四段都是两边都有的。
- **这一条是对 [搜索与折叠的形态](09-grilling-search-and-folding.md) §3 的修正**：那张票写的是
  「状态行给 `n 个命中 · 新增 M`」。改成浮字位之后，它要报的那些信息一条没少，只是换了个地方。
- 顺带排掉 09 票 §13 第一条 fog 的后半句（「与现有四段的降级顺序怎么排」）—— 答案是不排。

### 2. 命中数住在内容区右下角那个浮字位

- 与新内容指示器**同一位、同一色、同一贴边算术**，每视图各一个 —— 现成的件，一个都不新造。
- 理由是它本来就是「这一页现在怎么了」的即时信息位：贴右缘、只在需要时出现、跟着 `fresh`
  那一套节奏。命中数与「有几行新内容」是同一类问题（现在这一屏是什么状态）。
- 触发条件：**过滤集非空时**走命中读法；过滤集为空时**一个字都不改**，照今天的新内容指示器。

### 3. 文案：一句话三态

- 有命中：`n 个命中`。
- 自进入过滤以来有新的命中块到达：加 `· 新增 M`（**M 是新到达的命中块数，不是新到达的行数** ——
  09 票 §3 的原话是「命中的新块照样进账」，读者要的是「有多少值得按 `n` 过去」）。
- 无匹配：**就写 `0 个命中`**，同一句话写到底。窄屏下它与有命中时一样先被截掉，语义一致；
  不为「出了事」单造一个词（那是两个读法混在一行）。
- **只在过滤期间带「新增 M」**：非过滤时那半句没有意义（没在筛，新到的行由贴底跟随直接看见）。
- 滚到底恢复跟随后，「新增」清零（你已经看过了）。这与 10 票 §8 的「视口照跟随走」同源。

### 4. 过滤期间浮字位整句让给命中，`G` 补上「回到最新」

- **过滤激活时，那个位置不再画「N 条新行」/「回到最新」，整句换成命中读法**，因此它在这一刻
  **不再是一个可点的手势位，而是一个信息位**（点它没有意义 —— 要去哪儿没有第二个目的地）。
- 回到最新改由 **`G`** 承担：10 票已定 `G` = 跳到最新并恢复跟随。
- **`G` 只恢复跟随，不动过滤**。两个状态各管各的：退出过滤已经在 `Esc` 的层序里（清搜索 →
  清过滤 → 清选中 → 交还键盘，10 票 §5），不差 `G` 这一条；而给 `G` 藏第二义（按字面猜不到它
  会改过滤）是更贵的那种代价。
- 退出过滤 → 浮字位自然回落成新内容指示器的正常逻辑。**不新造过渡状态**。

### 5. 轴上的命中：合成一段底色，落在两条泳道行

- **合成一段**：连续命中合成一段底色，画在**模型泳道与工具泳道那两行**。工具类命中只落工具
  泳道、模型类命中只落模型泳道。
- **刻度行不碰**：那一行的底色归[时间轴与计时](06-grilling-timeline.md) 的**当前视口区间**
  （一个语义、一个通道），命中不与它抢。两处底色因此是**两个具名常量**，语义域不同。
- **不做逐块细刻度**：块可以比一格还短，「保底画一格就是说谎」那条纪律在这里同样成立 ——
  与其画一堆分不清的刻度，不如把「有时段有命中」这件唯一的事说清楚。
- **阀值 = 一格**：两个命中块之间的时间间隔**小于一格**就算同一段（分界画不出来就不画），
  **大于等于一格**才断开。阈值跟着轴的分辨率走而不是写死秒数（会话越长一格越粗，短会话里几乎
  什么都连成一段 —— 这是分辨率的诚实后果，不是 bug）。那条「一格 ≈ 0.76 s」是 63 列 × 整趟
  48 秒那一次的实测，**不要当常数用**。

### 6. 落轴的判据：属不属于一次模型调用或一次工具调用

- **工具类命中 → 工具泳道**（`ToolCallStarted`/`Completed` 那一族，含由工具结果推出来的块）。
- **模型类命中 → 模型泳道**（`Message` 与它的 `Delta`/`reasoning`）。
- **注入、开场段、`Answer`（问卷作答）、`/命令`这些不落轴** —— 它们既不是模型调用也不是工具
  调用，在轴上没有位置。诚实写明这条限制：**搜到的命中不一定都在轴上出现**（搜的是整场会话，
  轴是两种时间的摘要），并写进 `docs/render.md`。这是与「不编数字」同一条纪律，不是缺陷。
- **折叠不改轴**：折行是显示状态而时间区间是事实，折起来的那一段底色照画。

### 7. 选中标记与命中底色正交，不叠压

- 10 票 §9 已定标记画在**选中块的首行**那一刻，06 票已定它的语义是「位置精确、长度有下限」。
- **它是一根前景记号（`│`，与 06 票「回合边界画一道 `│`」同一族），命中底色是背景** ——
  两者是**正交的两条通道**，同一格里共存不冲突，所以**不需要定谁压过谁**。选中落在某段命中
  底色上时，那一格同时有底色与 `│`，两件事都读得出。
- 标记的位置：**最下一行**（工具泳道行）—— 与 06 票原型里的标记一致。

### 8. 未命中段不调弱

- 09 票 §3 的措辞是「其余段走弱色」。**本票收窄成：只加底色，其余原样。**
- 理由两条：底色是整格级别的对比，足够强；而**弱色要一档新色阶**，而底色已经是零先例的第四个
  通道了（10 票 §0），能少叠一层是一层。顺带「弱到什么程度」这个永远没有客观标准的问题
  （终端主题太多）就不用回答了。
- 落败方案记在这里：整条轴调弱 + 命中段恢复原色（读法更像「高亮」，但每次过滤要重建两条泳道）。

### 9. 色板要加的那一档

- **新增一个界面域的具名常量**（与 06 票那档视口区间底色并列，两者语义不同：一个是「命中」、
  一个是「视口」）。取名与取值归 spec，但**必须在界面上能被分辨开**，否则「命中」与「当前视口」
  会被读成同一件事。
- **为什么不用 `ACCENT` / `REVERSED`**：横带三行里已经有字形（模型/工具泳道的分段记号、回合边界
  的 `│`），前景色与粗细分不出「一段时间」这个单位；而 `REVERSED` 全屏只许一个（`src/render/tui.rs:5450`）。
  底色是唯一与「一段时间」天然对齐的通道。
- **不立新 ADR**：这是视图内的局部决定，不难逆转、离开上下文也不显得奇怪。改动记在
  `docs/render.md` 与[词条](#13-术语变更点供-domain-modeling-落到-contextmd)里。

### 10. 键位与手势的收口（不改阶梯）

- 本票**不新增任何键位**，也不改 10 票那张表里的任何一行。只重申两条互动的结果：
  - `/` 进搜索 → **输入区**那一行变成查询串（09 票 §1），**状态行不显示查询串**（本票 §1）。
  - `Esc` 层序、翻页键不动选中、`[`/`]` 层级跳转 —— 全部照 10 票。

### 12. 本票排掉的 fog 与交出去的活

- **排掉两条**（09 票 §13 那两条 fog 全部结清）：状态行怎么显示这一档（**状态行不动，命中数进
  内容区右下角浮字位**）、未命中淡出在轴上怎么画（**合成一段底色，泳道行，不调弱**）。
- **顺带收窄一条**：09 票 §3 的「状态行给 `n 个命中 · 新增 M`」改写成本票的浮字位（§1）。
- **不再 graduate 新票**：11 票走完时图的「尚未明确」已经是空的（见[图](../map.md)）——
  这张图**没有 fog 了**，剩下的全是执行：`/to-spec` 折成构建计划、`/to-tickets` 拆实现票。
- **交出去的活**（全部归 spec）：两个底色常量的取名与取值、浮字位在过滤期间的判定顺序、
  阀值「一格」的取整口径、`docs/render.md` 里「搜到的命中不一定都在轴上」那条限制。

### 13. 术语变更点（供 `/domain-modeling` 落到 `CONTEXT.md`）

- **新词：新内容指示器（Indicator）** —— 内容区右下角那一个贴右缘的浮字，平时报「N 条新行」或
  「回到最新」、可点；**过滤激活时整句让给命中读法，那一刻它不再是手势位而是一个信息位**。
  它是 11 票把命中数收进来的那个位置，所以「一个位置两种角色」这件事要写进词条，否则将来有人
  把它当成单纯的滚动指示器。
- **不新增**：命中 / 过滤 / 折叠 / 选中 / 行身份 全部已在 `CONTEXT.md` 里（09、10 两票落的），
  本票没有产生新概念，只是给它们各自补了一句显示层的口径（命中在轴上是底色、过滤态在浮字位）。
- **不立新 ADR**（§9）。
