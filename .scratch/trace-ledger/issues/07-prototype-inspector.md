# 检视器分面的形态

Type: prototype
Status: resolved
Part of: ../map.md
Blocked by: 02

## 问题

DSH 的检视器按记录类型分派一组**面**：Markdown 记录给「概述 / 预览 / 原始内容 / 来源」，
工具给「参数 / 结果 / Schema / 计时」，system 给「系统提示词 / 工具 / 差异」，请求给
「选项 / 用量 / 计时」。面与面之间用一条标签条切换，面板宽度可拖、双击复位（见
[`../parity.md`](../parity.md) 的 C 节）。

衡今天的详情覆盖层只有**一个面**：一块正文。要分面，先得看形状 —— 字符格里怎么表达「这个
覆盖层里有几个面、现在在第几个」。

要出的候选（每种一两帧，覆盖层按今天的尺寸画）：

1. **顶部一条面标签条**（照主列页签条那套画法：`┄ 参数 ┆ 结果 ┆ 计时 ┄`），键位与点击都能切。
2. **面在流里分段堆叠**：不切面，滚到底就是下一面，段与段之间用小节线（`── 计时 ──` 那种既有
   画法）。长处是能对照读，短处是长正文里的第二面几乎没人滚到。
3. **无可见标签、只有页脚提示**：键位循环切面，页脚写 `↹ 面 2/4`。
4. **同一份正文的两种读法**：渲染版（今天）与原文版（DSH 的 Raw 按内容块逐块输出）切起来
   手感想不想得通 —— 这一对要单独给一帧。
5. **用量面**：本次调用 + 会话累计两组、桶为输入 / 缓存读 / 缓存写 / 输出 / 推理。今天行尾
   已经有 `in=… out=…`（ADR 0016），这一面是**另一处**读数（[图](../map.md) 冻结项 5），
   帧里要看两处同时出现时会不会读重。
6. **参数面与结果面**：参数是 JSON 时的两种画法（照原文缩进 vs 摊成键值对）；结果是完整 JSON
   数组 / 对象时要不要树（DSH 有 JsonTree），还是原文 + 缩进就够。
7. **计时面**：开始时刻 / 时长 /（有数据时）首 token / 生成 / 吞吐 / 计时来源，缺数据时那一格
   写什么（DSH 写「不可用」，这是纪律）。

## 作答

**产物两份**：一次性脚本 [`../prototype/07-inspector.py`](../prototype/07-inspector.py)（跑法写在
脚本头那行）与它生成的 [`../prototype/07-inspector.txt`](../prototype/07-inspector.txt) ——
**24 帧、755 行**。脚本是 throwaway，不进 `src/`；它内含**每行显示列的自检**（任何一行不是
`DETAIL_W` 列就退出），所以帧里的宽度是真的，不是看着差不多。

**尺寸全部照今天的实现算**（`src/render/layout.rs`）：屏幕 100×30 → `detail_width()` =
min(100 − 8, 135) = **92**；覆盖层高 = 30 − 4 = **26**，框内 24；`detail_padding` 判据成立 →
上下左右各让 1 列 → 文字区 **88 列 × 22 行**；今天的三段是标题 1 行（被点那一行自己的文字，
`ACCENT+BOLD`）+ 主体 **20 行** + 页脚 1 行（`↕ {pos}/{total} · esc 关闭`）；边框 `chrome_block()`
横 `┄` 竖 `┆`、四角是空格。主体高度在帧里固定 20 行（真终端那么多），于是「滚到哪」是有意义的。

**数据**：一条造的会话，主角是 09:12:11→09:12:12 那次 `grep`（参数六个键、落盘全文 138 行、
所属模型调用 2.0 s、首 token 1.4 s），时刻与 [账本骨架的几帧](03-prototype-ledger-skeleton.md)、
[时间轴在字符格里的候选形态](05-prototype-timeline.md) 那场逐个对上。每一个量只取数据面证过的
来源：桶是 `events::Usage` 的五个（`cached` + `miss` = `input`、`reasoning` 含在 `output` 里），
TTFT 一族走 [ADR 0020](../../docs/adr/0020-first-token-time-rides-the-completion.md) 的
`first_token_ms`。**没有的一律不画**：错误 code、历史 system prompt 的差异（不进流）、落盘全文
以外的原文。

**帧覆盖**（票面七条 + 维护者补的四组）：

| 票面那条 | 帧 |
| --- | --- |
| （基线） | 0：今天的一个面 —— 参数与输出是**两节**不是两面 |
| 1 顶部面标签条 | 1a（面里的小节标题收掉）/ 1b（留着）/ 1c（窄屏降级成 `… ┆▐计时▌`） |
| 2 面在流里堆叠 | 2a（四节连排）/ 2b（滚到第 601 行） |
| 3 只有页脚提示 | 3：`↹ 面 2/4 · ↕ 8/47 · esc 关闭` |
| 4 两种读法 | 4a（渲染版，同一条消息）/ 4b（事件的原始 JSON） |
| 5 用量面 | 5a（本次 + 这一趟）/ 5b（与行尾那两个数同屏） |
| 6 参数与结果 | 6a（缩进 JSON）/ 6b（结果走树）/ 6c（结果原文 + 缩进） |
| 7 计时面 | 7a（数据齐）/ 7b（老流没有 `first_token_ms`，三行「不可用」） |
| 补 · 来源 | 8（位置 + 那一行首行 + 回车跳过去）/ 8b（祖先链，不必跳） |
| 补 · 差异 | 9a（单栏 hunk + 重算的代价）/ 9b（拿不到时的写法与退路） |
| 补 · Schema | 10（内建与自定义工具：`spec().parameters` 拿得到）/ 10b（`mcp_call` 转发的那个拿不到） |
| 补 · 分派表 | 11：七种 `DetailKind` × 今天的形态 × 面集合（假设）× 默认面 |
| 补 · 对照 | 12：文件详情今天的样子（行号 + 语法高亮 + 打开那一刻读盘） |

**三组候选的代价**：

- **候选一（顶部面标签条）**：画法现成 —— `draw_label_bar`（标签 + `┆` + 线填满，选中
  `ACCENT+BOLD`，每个标签记一个命中矩形），代价是从主体借走一行（20 → 19）。它比 DSH 便宜的地方
  在于**不需要拖拽调宽**（字符格没有那个概念）。真正的取舍在面里的小节标题：收掉省一行，长正文
  滚到中段时却认不出自己在哪一面；留着多一处重复，换「滚到哪都认得」（帧 1a vs 1b）。窄终端降级到
  帧 1c 那一档之后，它与候选三只剩排版差别。
- **候选二（面在流里堆叠）**：**它就是今天的详情再加两节**（`── 小节 ──` 是既有画法），零新概念，
  还能对照读。代价全在「读到哪一节」：页脚那一个行号对四节是同一个数，**没有「第几面」这个位置**
  —— 帧 2b 是证据：滚到第 601 行，屏幕上只有一段正文，下面还有两节而页脚只说 `↕ 601/701`。
- **候选三（只有页脚提示）**：主体零代价（省下的两列全给内容），代价是发现性：读者事先不知道
  有几个面、叫什么，翻页前只知道自己在一个编号上。

**画出来才看清的四条**（不是讨论里想到的）：

1. **「来源」面在字符格里比 DSH 弱一大截**：那一行的文字**标题行已经给了**，所以这一面不能重复
   它 —— 唯一不可替代的能力是**跳回去**（读者滚到覆盖层底部时账本已经离那一行很远）。而跳回去要
   稳定行键，那是 [长历史与行选择](10-grilling-history-and-selection.md) 的活（今天行身份是位置
   型下标）。帧 8b 给了更省事的一档：**把祖先链列出来，不必跳**。
2. **用量面与行尾那两个数不冲突，但必须分节**：帧 5b 里 `in=18310 out=204` 与分桶那一组是同一组数
   的紧凑与分桶两读（同一口径、同一来源）；会读重的是**「这一趟」的累计**混进同一块屏幕。所以
   小节标题必须写清「本次」还是「这一趟」，且 `输入` 那一行的条形 = 缓存读 + 未命中，画成三条
   等于把它数两遍。
3. **「Schema」面拿得到一半**：`ToolSpec.parameters` 就是一份 JSON Schema（`src/tools/grep.rs`），
   内建与自定义工具都拿得到；而 `mcp_call` 转发出去的那个工具的 schema 住在 server 那边，本地
   没有 —— 这一格只能写「不可用」并给替代读法，**不能拿 `mcp_call` 自己的 schema 冒充**。
4. **分派表不是一张「所有面都能进」的表**：只有工具那一行用得上用量与计时两面（消息详情的开始
   时刻不是「那次调用」）。七种 `DetailKind` 各有一个穷尽的 match，所以这张表能在代码里穷举测，
   而不是靠约定。

**给 [检视器的面与内容](08-grilling-inspector.md) 的必拍清单**（帧是输入，判定归那一票）：

1. **面加在哪一层**：`DetailView`（`src/render/tui.rs:8548`）—— 今天一个覆盖层一个 `body`，加面就是
   「当前面 + 逐面 `Vec<DetailLine>`」，并让 `detail_scroll` / 页脚认当前面；标签条复用
   `draw_label_bar`（`:6104`），尺寸算术仍只有 `detail_text_width` / `detail_padding` 一处。
   **覆盖层的尺寸一行都不许动**（92×26 / 88×22 都是从布局常量算出来的）。
2. **哪些面、分派表**：帧 11 那张表逐条批（它是假设，不是结论）。「来源」面配不配有一个面，
   取决于 [长历史与行选择](10-grilling-history-and-selection.md) 会不会给出稳定行键。
3. **键位**：轨迹页今天**不是**键盘归属的一层（`key` 的守卫阶梯里没有它），`Tab` / `Shift+Tab`
   归输入框换行；分面的切面键要么落进覆盖层这一层，要么先回答「谁拿着键盘」——那是 10 票的地盘。
4. **页脚那对数的口径**：分面之后只能是**当前面**的行号（`↕ 8/47`），「全部面的总行数」没有意义。
5. **原文面给什么**：`events::Usage` 与事件信封拿得到原始 JSON（帧 4b）；**工具输出走落盘文件、
   注入正文是拼出来的、文件与改动是打开那一刻读盘** —— 这些地方没有原文可给，该写「拿不到」，
   不能拿渲染结果冒充。
6. **计时面与时间轴的分工**已经定了（[时间轴与计时](06-grilling-timeline.md) §7：轴给形状、
   检视器给精确值；等审批切分只在这一面）。这一票要补的是字段集合与缺数据时的写法（帧 7a/7b）。
7. **这一票没有回答的**：层级跳转到 10 票；搜索与折叠归 09 票；面名、默认面、滚动记忆、
   `parity.md` C 节的最终判定 —— 全归 08 票。

判定够用；形状的挑选与取舍归 [检视器的面与内容](08-grilling-inspector.md)。
