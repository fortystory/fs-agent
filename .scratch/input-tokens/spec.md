# 输入框里的记号：`@` 提文件、上色与 chip，以及 `/` 的任意位置

来源：2026-10-04 的两条意向 —— 先是「输入时用 `@` 选文件，参考 codex」，访谈途中又追加了
「两种记号在输入框里特殊上色、删除时整体删」，并把 `/` 的触发与提交语义也放宽成同一套规则。
2026-10-04 经 `/grill-with-docs`（20 问）折成这份 spec。

事实材料分两侧：codex 那一侧的一手调研在
[`research/01-codex-at-file-mention.md`](research/01-codex-at-file-mention.md)（commit
`afb436df`，逐条带出处）；本仓库这一侧的核对写在《现状》里。**调研只回答「codex 怎么做」，
没有一条是从它推出来的决定。**

## 问题陈述

1. **输入区没有任何候选弹窗**：`@` 今天就是个普通字符。全仓没有文件补全、没有模糊匹配库，
   `ignore` 只在 `grep` 工具里被用来遍历。
2. **`/` 菜单只认草稿最开头**（[`src/render/editor.rs:286-290`](../../src/render/editor.rs)）：
   记号必须从第一个字符起，而且看不到第一行之外。
3. **命令的解析同样绑死第一行**（[`src/cli.rs:1469-1482`](../../src/cli.rs)）：只有「第一行以
   `/` 起头」才算命令。菜单与解析今天是一致的，只放宽一侧就会让它们分家。
4. **草稿里的文本没有身份**：`/loop` 与 `@README.md` 和别的字一模一样，没有颜色，
   `Backspace` 一格一格删。
5. **`Tab::Files` 占着位却没有语义**：注释写着「这个会话碰过的文件。还没做」
   （[`src/render/tui.rs:3413-3414`](../../src/render/tui.rs)）—— 那是目前唯一的说法，
   **不是定下来的**，这份 spec 不改它、也不依赖它。
   （**2026-10-07 补注**：这一页后来由 [`files-page`](../files-page/spec.md) 落地了，那处注释也
   改成了「工作区里的文件与目录……」。本段保持当日原样，留作来源记录。）

## 方案

- **共享的文件索引**（§1）：会话级的 `FileIndex`，与 `grep` 工具同一条忽略规则。
- **记号**（§2）：`Token { prefix, start, end, query }` 加上「边界规则按前缀」的一处抽象，
  `/` 与 `@` 共用浮层、键位与 `Esc` 优先级。
- **`@` 的候选与插入**（§3）：文件 + 目录、目录下钻、插纯文本相对路径。
- **上色与 chip**（§4）：能兑现的记号才上色、才凝固成不可分割的一块。
- **`/` 的语义放宽**（§5）：任意行、任意位置的命令都算，前文（含前面的行）并入任务。
- **落点**（§6）：词表、逐面文档、手工清单、索引，以及一条 ADR。

## 用户故事

1. 作为要模型改某个文件的人，我希望在句子里直接 `@` 出它的路径，而不是手抄。
2. 作为在窄终端里打字的人，我希望打完 `@` 就看到候选，而不是等一个卡顿。
3. 作为要钻目录的人，我希望选中目录之后还能接着往下打。
4. 作为刚让模型新建了文件的人，我希望提交之后 `@` 就找得到它。
5. 作为读自己草稿的人，我希望一眼分出哪段是能被执行的命令、哪段是能指到东西的引用。
6. 作为要撤掉一个标记的人，我希望一下 `Backspace` 就把它整块删掉，而不是一格一格抠。
7. 作为在句子里插命令的人，我希望它真的生效，而我写在它前面的字不会被吃掉。

## 实现决定

### §1 文件索引（共享件）

**形状**：`FileIndex { state: Idle | Loading | Ready(Arc<Vec<PathBuf>>) }`，路径是**相对会话
cwd** 的。它是**会话级的一个值加一个查询接口**，不是渲染器私有的缓存。

- **遍历**在 `tokio::task::spawn_blocking` 里跑 `ignore::WalkBuilder::new(root)`，**与
  [`grep` 工具逐字同一条规则**（[`src/tools/grep.rs:164`](../../src/tools/grep.rs)）——
  `ignore` 的缺省：遵守 `.gitignore`、**跳过隐藏文件**、非 git 仓库也能走、固定字典序
  （`sort_by_file_path`）。**不照抄 codex**（它 `require_git(true)`、不跳隐藏文件、跟随符号
  链接）：仓库里只该有一个「什么算工作区文件」的答案，否则 `grep` 找不到的文件却能在补全里
  选出来；而把 `.env` 一类列进候选是实打实的暴露面。
  **2026-10-05 修订（真机反馈「`@.scratch/` 选不到」）**：隐藏**目录**放行，隐藏**文件**与
  `.git/` 仍不进候选 —— `.scratch/`、`.github/` 这样的目录是工作区里正常的材料，而那条暴露面
  说的是**文件**（`.env` 的内容），目录名本身不泄露什么。索引与 `grep` 因此在**这一处有意
  分家**（`grep` 仍跳过整棵隐藏子树），代价照旧留在上一条里：`grep` 搜不到的路径能在补全里
  选出来 —— 这条不对称是有意选的，不假装它还成立。
- **结果经 `tokio::sync::mpsc` 回到循环**，`tokio::select!` 加一支收它（
  [`src/render/tui.rs:405-413`](../../src/render/tui.rs) 那段已有三个来源加两个按需定时器）。
  索引**从不阻塞键盘**，也从不进任何一次按键的处理路径。
- **预热**：进 TUI 后触发第一次遍历，于是人真打 `@` 时它通常已经好了。
- **重扫**：**每次提交一条消息之后**在后台重扫一次（「改完再 `@` 它」是主要用法）。
- **作用域**：会话 cwd；工作目录跟着会话变时（`continue-by-id` 那种情形）索引重建。

### §2 记号与两个前缀

**`Token { prefix: char, start: usize, end: usize, query: String }`**，由一处纯函数从草稿文本里
推出来 —— `Input::slash_token()` 与之合并，`cli.rs` 的提交解析也调同一份。

**边界规则按前缀，是 `Token` 的一个参数，不是两套代码**：

| 前缀 | 边界 | 为什么 |
| --- | --- | --- |
| `@` | 草稿**任意位置**的 token 开头（前面是空白或草稿起点）；`src/@foo` 不触发 | 引用出现在句子里是常态（`帮我改 @src/a.rs`） |
| `/` | 草稿**任意行、任意位置**的 token 开头 | 与 `@` 对等：判据不同（一个要兑现成动作、一个要兑现成指称），位置的规则不该各写一套 |

- **一套浮层、一套键位**：`↑`/`↓` 移动、`Tab` 接受、`Esc` 关、窗口滚动与「高亮始终可见」
  全部复用 [`draw_menu`](../../src/render/tui.rs)；菜单按前缀挑**候选来源**
  （`/` → `TuiState.catalog`，`@` → §1 的索引）。
- **`Enter` 有一处刻意分叉**：`/` 菜单里它是「插入并发送」（今天如此），而 `@` 里**只能接受**
  —— 插进去的路径只是句子的一部分，发送仍旧是再按一次。
- **`Esc` 的「否掉」按 token 记账**：关掉之后同一个 token 里改字会重开（今天的 `sync_menu`
  就是这条），`Esc` 不牵连同一行里另一个记号。
- **一个句子里多个记号**：只认**光标所在**的那一个；`@` 之间互不影响。

### §3 `@` 的候选与插入

- **候选**：**文件 + 目录**，来自 §1 的索引，路径相对 cwd。
- **过滤**是**前缀匹配、大小写不敏感**，与 `/` 菜单同一条（`starts_with`）；
  **不上模糊匹配** —— 仓库里没有那个库，而多拉一个依赖不在这条 feature 的预算里。
  **2026-10-06 稍后推翻**：判据换成**分段前缀、可从任意一段起**（`cli` 找得到 `src/cli.rs`），
  排序改成「匹配起点更靠前段者优先，同分保持字典序」—— 理由与取舍在
  `.scratch/tui-feedback/spec.md` §4。仍然没有模糊（子序列）匹配。
- **排序**：路径字典序（与 `grep` 的 `sort_by_file_path` 同一条）。
- **裸 `@`（还没打字符）不列候选**：菜单不出现，打第一个字符才出现。与 codex 一致；理由与
  `/` 相反 —— 命令表只有几十条，「裸 `/` 是一份用来看的列表」成立，而文件有几千个，
  「看全部」没有意义。索引未就绪时同样什么都不显示（预热让它几乎不可能被看见）。
- **含空白的路径不进候选**：`@` 的记号按空白结束，插进去会当场断掉。文档里写明这条边界。
- **插入**：
  - 文件 → `@相对路径`，菜单关闭，光标留在末尾；
  - 目录 → `@相对路径/`，**菜单保持开着**（query 换成新前缀，接着过滤那一层）。
    `menu_accept` 今天一律设 `dismissed = true`（[`src/render/tui.rs:2768`](../../src/render/tui.rs)），
    这里要按「接受的是不是目录」分叉。
  - **2026-10-05 追记（真机反馈「补完之后还得自己敲空格」）**：命令与**文件**补完之后再补一个
    **分隔空格**，于是接着打的就是下一样东西（这一段任务、下一句话）；后面已经是一个空白时
    不补（否则写出两个连着的空格）。**目录不补** —— 补全它要的是「钻进去」，一个空格会把记号
    当场结束在目录上，下一层就过滤不出来了。`Enter` 的「插入并发送」不受影响：提交前两端会
    裁掉空白。
- **插入的是纯文本相对路径，不内联文件内容**，模型自己用 `read`/`glob` 去取 —— 与 codex
  一致，也是唯一与 `@` 在草稿里「只是一个记号」这条自洽的形状。

### §4 上色与 chip

**判据只有一条**：**能兑现的记号** —— `/` 的记要在命令表里命中，`@` 的记要在索引里命中。
**上色与 chip 用同一条判据**，所以打字过程中一块记号会忽隐忽现，补全成功那一刻才凝固。

- **颜色**：命令蓝、引用紫（`wording`/主题层给常量，不在绘制里散写）。命中不了的一律保持
  普通文本色 —— 给 `看 /tmp/x` 里的 `/tmp/x` 上蓝色会教出错误直觉。
- **chip 的性质**（一条不变量，不是散在各处的判断）：**光标永不落在记号内部**。
  - 所有移动（`←`/`→`/`↑`/`↓`/`Home`/`End`/`Ctrl-A`/`Ctrl-E`/鼠标点击）把目标位置**吸附**到
    最近的记号边界；
  - 所有删除（`Backspace`/`Delete`/`kill_word`/`kill_to_line_start`/`kill_to_line_end`）命中
    记号时**整块删**；删的是记号本身，不额外吞掉旁边的空白；
  - 内部插不进字 —— 由上一条天然成立。
- **粘贴一视同仁**：粘进来的文本按同一条推导，含有效记号就成 chip。给粘贴单开豁免等于让同一
  段文本有两种身份，而身份取决于你怎么输进来的 —— 那比这点意外更难解释。
- **推导不能住在 `Input` 里**：判据要查 `TuiState.catalog` 与 §1 的索引，而
  [`Input`](../../src/render/editor.rs) 是不认识这两样的纯文本模型。所以**区间由 `TuiState`
  算好、同步进去**（与今天 `slash.prefix` 那种「记着的值」同构），`Input` 只做**纯几何**的
  吸附与整块删。**这条 seam 是本节的重点**：它让 `Input` 继续不认识命令表与文件系统。
- **折行**：记号可能跨折行，`view()` 按字符区间分段给样式（与 markdown 渲染同一套 `Span`）。

### §5 `/` 的提交语义放宽：与 `@` 对等

- **整个草稿里任意行、任意位置**的 `/name`（name 在命令表里）都算命令，取**最靠左**的那个；
  `text.split_once('\n')` 那条「只看第一行」的限制**取消**。
- 记号**前面的文字（含它前面的每一行）并入任务**：`请 /loop 我的目标` → `Loop("请 我的目标")`。
  这一条是为了不重蹈「内建命令要么整条、要么什么都不算」那条规矩要防的事 ——
  **丢用户写下的字**（[`src/cli.rs:1473-1474`](../../src/cli.rs)）。
- **无参命令仍要求整条只有它**：`/quit`/`/exit`/`/undo`/`/clear` 的 `if whole` 不动，
  于是「请把 `/clear` 加到文档里」不会被劫持成一次清空。
- 草稿里找不到命令记号时，整条仍当普通消息（不变）。
- **实现**：把记号推导做成不依赖 `Input` 的纯函数，`cli.rs` 与 `editor.rs` 共用；
  `Submission` 的解析从「`first.starts_with('/')`」改成「**整个草稿里**第一个命中的命令记号」。
- **这一档是有牙的**（访谈里明码标价选下的）：`@` 被误认没有后果 —— 它只是个引用；而 `/`
  被误认**会真的执行**：`用 /loop 做目标循环` 这句话就是一条命令。考虑过用「要求整行以记号
  起头」挡住它，那会推翻上面「前文并入任务」那条，于是选了与 `@` 完全对等。理由与被否决的
  替代方案记在 [ADR 0012](../../docs/adr/0012-input-tokens-are-atomic.md)。

### §6 落点

- [`CONTEXT.md`](../../CONTEXT.md) 新增**记号（Token）**一条：它是**补全与呈现的单元**，
  在能兑现时是**不可分割**的一块（chip）。
- [`docs/render.md`](../../docs/render.md) 新增一节「输入框里的记号」（放在问卷那一节之后）。
- [`docs/tui-manual-checklist.md`](../../docs/tui-manual-checklist.md) 新增 ㉘，并补来源段。
- [`.scratch/README.md`](../README.md) 索引加这一行。
- **一条 ADR**：[ADR 0012](../../docs/adr/0012-input-tokens-are-atomic.md) —— 「输入框里的记号
  在能兑现时是一等单元」与「`/` 命令可在草稿**任意行、任意位置**」。两条都难回头、离开上下文会显得奇怪、
  且确实有被否决的替代方案。

### §7 明确不动的部分

- `Input` 的文本模型（`String` + `cursor: usize`）、历史（`Ctrl-P`/`Ctrl-N`）、折行数学、
  `submitted()` 的形状：**都不动**，chip 不是重写成片段序列。
- `/` 之外的键位分派、问卷、`Esc` 在输入区的既有行为、粘贴的既有规范化。
- `grep` 工具的忽略规则与 `repo_map`：它们不受影响（索引**借用**同一条规则，不改它们）。
- `Tab::Files` / `Tab::Trace`：这一轮不碰，也不为它们定型。

## 测试决定

- **索引**（新模块的单元测试 + 一条集成）：隐藏文件不进、`.gitignore` 生效、固定字典序、
  相对 cwd；预热与「提交后重扫」各一条。
- **记号推导**（`editor.rs` 单元测试）：`@` 在任意 token 开头触发而 `src/@foo` 不触发；
  `/` 与 `@` 同一条边界（含第二行）；一个句子里多个记号各算各的。
- **吸附与整块删**：`←`/`→` 跨过记号；`Backspace`/`Delete`/`kill_word` 命中记号时整块删；
  粘贴含有效记号的文本之后它成为 chip。
- **上色与 chip 判据**：`看 /tmp/x` 不上色也不是 chip；`@src/render/tui.rs`（存在）是；
  `@src/reneder/tui.rs`（不存在）不是。
- **菜单**（[`tests/render_layout.rs`](../../tests/render_layout.rs) 一类）：裸 `@` 不画菜单、
  `@` 候选画在光标处、选中目录之后菜单仍在且 query 变成新前缀。
- **命令解析**（[`src/cli.rs`](../../src/cli.rs) 的测试）：`请 /loop 我的目标` → `Loop("请 我的目标")`；
  `请把 /clear 加到文档里` → 普通消息；`/clear` 单独一行 → `Clear`（不变）。
- **文案**（[`tests/wording.rs`](../../tests/wording.rs)）：两个颜色的常量名与菜单文案。

## 明确不做

- **模糊匹配**（codex 用 nucleo）：前缀匹配够用，不为此多拉一个依赖。
- **图片特例**（codex 里 `.png` 选中变附件）：归 [`image-input`](../image-input/seed.md)。
- **`$` 或别的记号**：`Token` 的抽象为它留了位置，但这一轮只做 `/` 与 `@`。
- **无参命令出现在句子里**：`请把 /clear 加到文档里` 一律不当命令。
- **把 `Input` 改写成片段序列**（真 chip 编辑器的另一种做法）：chip 靠吸附维持，不换文本模型。
