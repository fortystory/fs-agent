# 04 — `/` 的提交语义放宽：第一行里任意位置

Type: implement
Status: ready-for-agent
Blocked by: 02

> 来源：[`../spec.md`](../spec.md) §5。菜单在票 02 里已经能在第一行任意位置弹出来；
> 这一票让**解析**跟上 —— 否则界面就是说了谎。

## 目标

- 解析**仍只看第一行**（`text.split_once('\n')` 那条不动）：多行草稿的后续行只有上色，
  不解析命令，写长消息时不该被劫持。
- 第一行里**任意位置**的 `/name`（name 在命令表里）都算命令，取**最靠左**的那个。
- 记号**前面的文字并入任务**：`请 /loop 我的目标` → `Loop("请 我的目标")`。
- **无参命令仍要求整行只有它**：`/quit`/`/exit`/`/undo`/`/clear` 的 `if whole` 不动，
  于是「请把 `/clear` 加到文档里」是普通消息，不会被劫持成一次清空。
- 第一行里找不到命令记号 → 整条仍当普通消息（不变）。
- 记号推导复用票 02 那个**不依赖 `Input`** 的纯函数，不在这里再写一份。

## 现状（2026-10-04 核实，改前先复核）

- 解析在 [`src/cli.rs:1462-1482`](../../../src/cli.rs)：`first` 是第一行 `trim()` 之后，
  `_ if first.starts_with('/')` 才进命令分支；`name` 与 `inline` 从第一个空白切开。
- `whole`（[:1475](../../../src/cli.rs)）管 `/quit`/`/exit`/`/undo`/`/clear` 的「整条才算」。
- [:1473-1474](../../../src/cli.rs) 的注释写着那条规矩的理由 —— **丢掉用户写下的东西**正是它要防的
  事；这一票的「前文并入任务」就是为了不重蹈它。
- `submission()` 已经拿到一个 `has_skill` 闭包（用来判技能），加一个「是不是命令」的判据同形。

## 收尾

- 测试（`cli.rs`）：`请 /loop 我的目标` → `Loop("请 我的目标")`；
  `请把 /clear 加到文档里` → 普通消息；`/clear` 单独一行 → `Clear`（不变）；
  `/ask-matt 优化这个` → 命令带任务（不变）；多行草稿第二行里的 `/` 不算命令。
- `cargo test`、`python3 scripts/check-language.py` 通过。

## 不做什么

- 不看第二行及以后。
- 不让无参命令在句子里生效。
- 不动 `/discuss`、`/goal-new`、`/loop` 各自的参数形状与 `task_of()`。
