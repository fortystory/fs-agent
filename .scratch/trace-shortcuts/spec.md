# 主列的切页手势与轨迹页的提示行

Status: done（2026-10-10 由维护者口述的两条直接落地；没有拆票，spec 自己收口 —— 自动化那一半
在 `tests/render_layout.rs` 与 `tests/wording.rs`，真终端走查并进 [`㉙`](../../docs/tui-manual-checklist.md)）

两条一起提，因为它们是同一件事的两面：**主列那两页**（`对话` / `轨迹`）此前只能用鼠标切，而
键盘上唯一会说话的提示行（[`TuiState::hint_line`](../../src/render/tui.rs)）对两页说的是同一套
话 —— 轨迹页上因此写着 `enter 发送`、`shift+tab 模式` 这些在那一页不成立的字。第一条给它一个
键，第二条让它说那一页自己的话。

来源是 2026-10-10 维护者的口述需求（键位由维护者选定），同日落地。它**推翻** `docs/render.md`
与 `CONTEXT.md` 里那句「两处页签都是点出来的，从不给键位」的**主列那一半**：左栏那几页
（`调用量` / `todo` / `文件` / `改动`）仍然只靠点，`Tab` 与 `Shift+Tab` 照旧归 `/` 菜单与模式
循环；页签那条老规矩的最初理由（`.scratch/sidebar-toggle/spec.md` 的「页签切换不走键盘」）没有
被推翻，变的是**主列**这一处多了一条显式的手势。

## §1 `Ctrl-V`：主列两页的切换

`Ctrl-V` 在**对话页与轨迹页之间翻一个来回** —— 两个标签只有两个，所以这就是它的全部语义。

- **与左栏开关（`Ctrl-O`）同一档的纯视图手势**：**忙闲都生效**、**不清退出举手**、不进事件流、
  不给回执（切换是立刻看得见的：整块内容区换了一页）。
- **守位照 `Ctrl-O` 今天的位置**：排在历史重放、文件查看器、选择器、详情覆盖层四个提前返回
  **之后**，`expire_exit_gesture` 之前。于是边界正好是：

  | 视图 | `Ctrl-V` | 为什么 |
  | --- | --- | --- |
  | 空闲 / 忙（回合跑着、`discuss` 跑着） | **生效** | 纯视图手势，与 `Ctrl-O`、翻页三键同类 |
  | 详情覆盖层立着 | **不生效** | 覆盖层自成一个「查看态」、独占键盘（既有分层） |
  | 历史重放中 | **不生效** | 重放期间键盘归 `replay_key`（与 `Ctrl-D`、`Esc` 一起被忽略） |
  | 文件查看器（nvim）立着 | **不生效** | 那是一块外来的屏幕，键走 [`viewer::key_bytes`](../../src/render/viewer.rs) 那张**显式转发表**；表里没有它，于是不发 |
  | 选择器立着 | **不生效** | 选择器吞下每一个非它自己的键（与 `Ctrl-O` 同一条） |
  | 问卷 / `/` 菜单 / 举手立着 | **生效** | 它们不占键盘独占权，也没有「此刻不能切页」的理由 |
  | 轨迹页的搜索模式 | **生效** | 那一层是**部分持有**，`Ctrl-*` 照旧穿透（与 `Ctrl-O`/`Ctrl-T` 同一条） |

- **切换落点与点页签逐字同路**（`TuiState::set_main_tab`）：**轨迹页重新成为当前显示页时自动回到
  持有**（`trace-ledger` 票 18 第 3 条），所以切过去之后 `↓` 立刻选得中一块，不必再点一下账本。
- **为什么不取 `Ctrl-K`**：它在输入区占着「抹到行尾」（`editor_key` 里与 `Ctrl-U` 的「抹到行首」
  成对），是输入区既有键位表里的一条 —— 而这一轮**不动任何既有键位**。**`Ctrl-V` 在 `map_key`
  里是一枚空闲键**：这一圈里没有别的含义（`Ctrl-M` 是回车、`Ctrl-J` 是换行那两条老故事不涉及
  它），所以它不需要从谁手里抢键。
- **不做**：双击 / 长按、切换动画、跨会话记住选中页（那是既有的、与 `Ctrl-O` 意愿同级的进程内
  状态）、给左栏那几页也配键（那要另立一条决定）。

## §2 轨迹页自己的提示行

提示说的是**键盘现在会做什么**，而两页的键盘语义是两份：`enter` 在对话页提交、在轨迹页开详情，
`shift+tab 模式` 只在输入区那一侧有东西可切。所以轨迹页不再铺 `KEY_HINTS`，改铺一条新的
`TRACE_HINTS`（`src/render/wording.rs`，与 `KEY_HINTS` 并排、注释体例照它）。

- **判据排在 `prompt_reply` 那个分叉之前**：主列当前显示轨迹页就取轨迹那一套，与「有没有人在读
  行」无关 —— 一次 `discuss` 没有人在读行，而轨迹页上的 `enter` 那时同样是开详情。只有不在轨迹
  页时才照旧走今天那两支（`KEY_HINTS` / `VIEWER_HINTS`）。
- **次序就是优先级**：`hint_row` 从前往后填、装不下下一条就停，出口（含举手那句催促）是**预留**
  的、任何宽度都在。这一条纪律与 `KEY_HINTS`、`VIEWER_HINTS` 逐字相同，本轮一个字都不改
  （`.scratch/sidebar-toggle/spec.md` §4、`.scratch/exit-gesture/spec.md` §2）。

表按下面前后摆，理由一条一条贴着它：

| 序 | 条目 | 为什么在这个位置 |
| --- | --- | --- |
| 1 | `↑↓/j/k 移动` | 手放在哪儿 —— 这一页的默认动作 |
| 2 | `enter 详情` | 这一页最值钱的第二件事（对话页那一条在这里换了含义） |
| 3 | `/ 搜索` | 长会话里的入口键，且不到这一页不知道 `/` 换了含义 |
| 4 | `space 折叠` | 把长流收短的日常手势 |
| 5 | `n/N 命中` | 只在过滤激活时收，与 `/` 成对 |
| 6 | `[ ] 层级` | 两级分组之间跳 |
| 7 | `{ } 全折展` | 同族的两个极端，用得比上面两条少 |
| 8 | `esc 退出层` | 退路：搜索 → 过滤 → 选中 → 还键盘，一次一层 |
| 9 | `ctrl-v 对话` | 翻回对话页 —— 纯视图手势，与 `ctrl-o` 同档 |
| 10 | `ctrl-o 左栏` | 两页共用的收尾，照既有纪律**永排最末**（`sidebar-toggle` §4） |

- **表里不放 `g` / `G` 与 `ctrl-t 换模型`**：前者是 `↑↓/j/k` 的加速档，后者开出来的浮层自带完整
  键位说明。提示表不是全量键位清单（`KEY_HINTS` 里 `ctrl-t` 被排到末位也是这条理由）。
- **文案与键位表逐字对齐**：`[ ] 层级` / `{ } 全折展` 分开写两个键（`/` 那条已经承载「两层换含义」
  这一个特例，不再多一处）；`↑↓/j/k 移动` 把方向键与 `j`/`k` 收在一条里，与 `docs/render.md`
  的轨迹页键位表同一读法。
- **两页都要提到这个键**：`KEY_HINTS` 加一条 `ctrl-v 轨迹`（**只加、不删**，既有的七条一个字
  不动），`TRACE_HINTS` 里是 `ctrl-v 对话`。位置都放在 `ctrl-o 左栏` **前面一格**：两者同档，
  而翻页签比收左栏更贴着手上的事 —— 于是同一档宽度下先让掉的是左栏开关（它本来就排在最末）。
  实测：整份对话页表要 **134 列**提示行、`ctrl-v 轨迹` **120 列**起就有；轨迹页表要 **143 列**、
  `ctrl-v 对话` **129 列**起就有。**两套都要很宽的终端才看得全新键**（提示行 = 终端宽 − 41
  列，所以 120 列的终端给 79 列提示，连 `ctrl-t 换模型` 都不在里面）—— 这是「位置就是优先级」
  的必然，也是这张表从来不是全量键位清单的原因。
- **宽度与回执照旧**：`hint_row` 是唯一的排版器，回执（复制 / 打开 / `Notice`）照旧排在最前、
  出口照旧不被挤掉；样式、宽度阶梯、出口预留一个字不改。

**与需求不同的地方及理由**

- **`[ ] 层级` / `{ } 全折展` 的写法**：需求里写的是 `` `[` `]` 层级 ``，落成文本时取
  `[ ] 层级`（两个键之间一个空格）。理由是它与既有的 `PgUp/PgDn 滚动` 同一读法，而不写成
  `[/] 层级` —— 那两个键之间本来就隔着别的键，用 `/` 连会读成「二选一」。
- **提示表的次序与需求建议的完全一致**，一处没调：核实过 `g` / `G`、`ctrl-t` 都不该进表
  （理由见上），其余的序就是使用频度与「不到这一页不知道」这两条排出来的。
- **`ctrl-o 左栏` 在 174 列终端上让位**：`ctrl-v 轨迹` 插在它前面一格之后，整份对话页提示表
  从 120 列涨到 134 列，而 174 列终端给出的提示行是 133 列 —— 差一列。这不是取舍失手，是
  「位置就是优先级」的直接结果：左栏开关本来就在最末（`sidebar-toggle` §4 定的），新键只是插
  在它前面。要看全八条得 175 列终端；轨迹页那张表要 143 列（175 列终端给 134 列提示行，所以
  轨迹页上还看不到它那一条）。
- **`Ctrl-V` 不进 nvim 查看器的转发表**：需求明写「表里没有就不发」，于是它在那里既不到 nvim
  也不切页签。**这条要留意**：nvim 自己的 `Ctrl-V`（可视块模式）因此在嵌入查看器里做不到 ——
  真机上想要它，那是一次新的决定（往表里加 `vec![0x16]`），与这一轮的两条需求无关。
- **左栏那几页没有跟着配键**：需求只给主列两页定了键位，`Tab` / `Shift+Tab` 的归处一个字没动。
- **搜索模式里它也穿透**（与 `Ctrl-O` / `Ctrl-T` 同一张名单）：轨迹页那一层是**部分持有**，
  `Ctrl-*` 一律照旧走自己的路。于是搜索立着时按 `Ctrl-V` 会切到对话页 —— 那不是新开的状态，
  **点页签今天就能到那里**（命中分派里没有搜索这一层），所以这一轮不额外加守卫；真要收，那是
  一条另外的决定（「搜索立着时不许切页」对鼠标也成立才自洽）。
- **`CONTEXT.md` 那半句落在「轨迹视图」词条而不是「左栏」词条**：左栏那条词条里确实写着
  「页签是点出来的、从不给键位」，但它说的就是**左栏自己那条页签条**，而那个单元已经**顶到
  500 字**（`scripts/check-doc-size.py` 的上限），加一个字就翻红。所以只把「两页之间按 `Ctrl-V`
  互翻」写进**轨迹视图**词条 —— 它本来就是讲这一页的。
