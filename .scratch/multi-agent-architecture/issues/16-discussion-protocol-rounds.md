# 讨论协议与轮次（含发散 vs 合成的张力）

Type: grilling
Status: resolved
Blocked by: 15, 17

## Question

决定多 agent 讨论的**推进协议**。这是本图新目的地的核心接缝。

**已定的骨架**（Chart 期定，见 map 的 Notes）——本票要把它落到可实现的协议：

| 轮次 | 发生什么 | 为什么 |
|---|---|---|
| 第 1 轮 | N 个 agent **各自独立作答，互不可见** | 保住多样性；等价于 self-consistency 的采样 |
| 揭示 | 彼此看到对方的输出 | 从众风险从这一刻开始 |
| 第 2 轮 | **只在结论冲突处**开 | 把调用数压到接近最小，回避「无差别多轮共享」这个从众主因 |
| 合成 | 聚合器产出结果 | 收敛 |

**先读** `.scratch/multi-agent-architecture/research/01-debate-conformity-and-speaker-attribution.md` 第 4 节——缓解手段的证据强度差别很大：**独立首轮 + 聚合证据最强**；**强制异议默认是负效果**；**"只暴露结论"没有任何消融证据**；**基座模型异质性是最强杠杆**；温度只影响共识**时机**不影响准确率。

**已核实的先例与缺失**（来自已解的 research 票 22，详见 `.scratch/multi-agent-architecture/research/03-orchestration-frameworks-turn-management.md`）：

- **本票第 5 问的答案是「没有先例」**：没有任何被查框架（AutoGen 0.2 / 0.4+、CrewAI、LangGraph）提供内建的「**只在结论不一致时才继续**」机制。最接近的 5 个官方构造**全部是「失败 / 停滞 / 未达标才继续」**（AutoGen `selector_func` 的 `Correct!/Incorrect!` 示例、CrewAI guardrail 重试、LangGraph evaluator-optimizer、Deep Agents `RubricMiddleware`、Magentic-One 停滞重规划）。**所以「定向第二轮」是设计，不是选型** —— 找不到能抄的实现，只能自己判断 + 后来实测。
- **终止条件的形状有强先例**：AutoGen 0.4+ 把 `TerminationCondition` 做成一等对象——**对增量消息求值**、返回 `StopMessage|None`、可用 `&` / `|` 组合，内建 11 种（max messages / text / token / timeout / handoff / source match / external / stop msg / text msg / function call / functional）。**这天然吻合票 15 的事件流**：终止 = 对事件流求值的**可组合谓词**。
- **默认值不可信**：AutoGen 0.2 的 `is_termination_msg` 默认是**严格字符串等于 `"TERMINATE"`**、`max_round` 默认 10；0.4+ 的 `max_turns` 默认 **None（不限轮）**。LangGraph 的 `recursion_limit` **文档 1000 / 代码 `"10007"`**（冲突）。
- **裁判偏见的硬数字**（本票第 1、3 问）：MT-Bench——GPT-4 位置一致性 **65.0%**，Claude-v1 仅 **23.8%** 且 **75% 偏向第一个**；缓解是 **swap / few-shot / CoT**。**Anthropic 的官方实践是「单次调用 + rubric + 0-1 分与 pass/fail」，且其自身实验发现多裁判反而更差** → 尽量**别**引入独立裁判；若引入，单次调用 + rubric，并注意 swap 会让调用数翻倍（与票 18 冲突）。

要回答：

1. **"结论冲突"怎么判定？** 这是"定向第二轮"成立的前提。谁来判、判什么（语义矛盾？关键事实不一致？还是只比最终答案）？用第三个 LLM 当裁判吗——注意研究记录**LLM 裁判有显著位置偏见与自我偏好（10% / 25%）**。
2. **讨论何时终止？** 需要一个明确的终止条件（无冲突 / 轮数用尽 / 收敛阈值）。它必须和票 15 的终止原因枚举对得上，也要和票 02 的"不信 `stop_reason`"规则共存。**讨论级终止与单次调用级终止是两个层次**，本票要分清。
3. **N = 2 时的讨论形态。** 已定讨论者就是 KIMI + DeepSeek 两个。两方讨论没有"多数投票"，所以冲突要么由聚合器裁决、要么引入一个不发言的中立裁判。**选哪条？**
4. **发散 vs 合成——本票必须正面处理的张力。** 用户选定的目的是**探索 / 发散**，但合成是收敛动作，与"要多样观点"相反。三个候选：
   - (a) 聚合器**收敛**出新答案（对求正确性对，对发散反）
   - (b) 聚合器**画出选项空间**：保留分歧、标出各自成立的前提、说明在哪一点分叉
   - (c) 不聚合，输出全部候选与它们的分歧点
5. **揭示什么。** 揭示时给对方看**全部推理**还是**只有结论**？（研究：后者**无任何消融证据**——这是个未测配置，所以它是个真选择而不是保守选择。）
6. **轮次上限**：定向第二轮之后还能不能有第三轮？上限多少？（每轮 = N 次调用，见票 18。）

## 与票 11 的边界

票 11 管的是**动态注册的外部工具**；本票管的是**讨论协议**。两者都涉及"谁说了什么算数"，但对象不同，别混。

**票 14 交接来的事实（2026-09-13）**——执行者这条支线已经定形，它给你的协议省掉了一整类问题：

- **`task` 是普通工具调用，在同一个 Turn 内阻塞到执行者结束**（票 14 第 5 节）。所以"执行者的结果何时入窗"**不需要协议操心**——它就在那一轮里，是那次调用的工具结果。你不必为"异步结果"设计"等不等/何时揭示"。
- **执行者的结论经「发起者自己的发言」进入讨论**（票 14 第 4 节）：讨论传的是**发言**，不是共享的工具历史。所以你的第 5 条（揭示什么）**只针对讨论者彼此的推理**，不涉及执行者——执行者的 raw 过程默认对**所有人**都不可见（要看走票 19 的按需 zoom）。
- **执行者的失败与讨论轮失败是两回事**（票 14 第 6 节）：前者是一条错误内容的工具结果，**讨论不因此中断**。所以你的终止条件不需要为"执行者失败"单独开一档。
- **"讨论继续、执行者在跑"是允许的**（票 14 第 5 节把 map 雾里那条并发边界答掉了）：存储层允许交错、工具层保证写不互相踩、而**结论只在完成后入窗**——所以你不用担心"边讨论边等"会提前泄露结果、污染独立首轮的多样性。
- 一个与你的第 6 条（轮次上限）有关的数字：**每个执行者自己另有 25 轮上限**（票 14 第 2 节），所以讨论的轮数上限与执行者的轮数上限是**两个旋钮**，别把它们合成一个。

## Answer

**已定（2026-09-13，grilling 三轮）。** 骨架来自 Chart 期（独立首轮 → 揭示 → 定向第二轮 → 合成）；证据来自 `research/01` 第 4 节与 `research/03`（票 22 的产物）；`StopReason` 的槽位来自票 15；投影的可见性来自票 17。

### 1. "结论冲突"怎么判：机械比较结构化结论槽（票面第 1、3 条）

**不引入独立裁判，也不额外调一次模型判分歧——判定是机械的。**

- **槽的形状**：每个讨论者的回答要在**正文之后另起一行**给出**一行结论**（自由文本，但必须是完整的一句话、不复述问题）。用**文本行**而不是结构化输出，是因为两家的 `response_format` 能力不一致（Kimi 有 `json_schema`，DeepSeek Chat 面只有 `json_object`，票 02 的能力表）——协议不能建立在只有一家支持的东西上。
- **比较规则**：归一化（去空白 / 标点 / 大小写）后 **精确相等，或一方是另一方的子串** ⇒ 视为一致；否则视为冲突。
  - **无假阴性**：两个归一化后相等的字符串不可能语义不同。
  - **假阳性高，但有界**：措辞不同即判冲突 ⇒ 第二轮多半会开。**上限就是第 4 条那个 2 轮**，所以最坏代价是多一轮（2 次调用）。
  - **它的主要价值不是"省调用"，而是"把分歧显式化"**：那两行结论就是 `DivergenceRecorded { positions }`，也是合成器解释"各自成立的前提"的输入。指望它省掉第二轮多半会失望；把它当"分歧的可观测化"则每次都成立。
- **为什么不用受控极性标签**（那样能真压缩）：它需要先知道问题属于哪一类，而开放问题没有自然标签——**硬压就是失真，且失真没有上界**。用户的目的是**发散**，失真比多花一次调用贵。
- **为什么不用第三个"不发言的中立裁判"**：研究明确——MT-Bench 位置一致性 GPT-4 仅 **65.0%**、Claude-v1 **23.8%**（**75% 偏向第一个**），且 **Anthropic 自己的实验发现多裁判反而更差**。机械判定连这个偏见都没有。
- **模型不吐槽 / 吐坏了怎么办**：**视为冲突**（保守开第二轮，并在第二轮提示里强调格式）。它的**退化解恰好是现状**（总是两轮），所以下界安全；反过来"视为无分歧"是**静默错误**（用户以为没分歧，实际是格式没吐对）——那比多花两次调用贵。
- **N = 2 没有多数投票**，所以本票**不引入裁决者**：冲突只被"**判定与记录**"，不被"裁决"——裁决发生在合成那一步（第 2 条）。这是 N=2 的正确形状：两方讨论的产物不是"谁赢"，而是"**分歧在哪、各自成立的前提是什么**"。

### 2. 聚合器的职责：画出选项空间（票面第 4 条，同时清掉 map 的雾）

**合成 = 一次独立的单发调用**（无工具、无回合、不参与轮次；**它不是一个 agent 身份**），产出**结构化的三档**：

| 档 | 内容 |
|---|---|
| **共识** | 两边都同意的部分——它就是"收敛后的答案"，但**收敛是结果，不是目标** |
| **分歧** | 分叉点 + 各方立场 + **各自成立的前提** |
| **未决** | 需要更多信息才能判的部分 |

- **为什么不是"收敛出新答案"**：那会把选项空间塌成一个答案，**与用户选定的目的（探索 / 发散）相反**。
- **为什么也不是"不聚合"**：讨论必须有产出；而且"标出在哪一点分叉"**本身就是聚合**（它需要读懂两份回答）。不聚合等于把"读完两份长回答、自己找分歧"退回给用户。
- **它不是"永远不收敛"**：当两边确实得出同一个答案时，共识段**就是**那个答案。
- 合成器的**模型**归票 18 的弱模型分流（那是它第 4 条那个问题的第一个真实用户）；本票只钉"它是一次独立调用"。

### 3. 揭示什么（票面第 5 条）

**揭示发言全文，不揭示私有推理——而且这一半已经被票 17 在机制上钉死了。**

- `reasoning_content` **根本不进投影**（票 17 第 2 节），所以"看对方的全部推理"在架构上**不可能发生**，不是我们选择不给。
- 剩下的是**他选择说出来的那份发言**：**全文揭示，不做摘要**。摘要等于我们替他改写了论点——而在讨论里，**被改写的论点就不再是他的论点**，对方会去反驳一个他从未说过的版本。
- 于是研究里那条"只暴露结论 vs 全部推理**无消融证据**"在我们的架构下缩成一个更窄的选择：我们揭示"**他说的全部**"（含理由），隐藏"**他没说的**"（`reasoning_content`）。这恰好落在"互联网文本里自然见过的形态"上——人辩论时看到的就是对方说出来的话。
- 与票 17 对工具历史的处理一致：他查了什么留**一行摘要**，结论在**他说的话里**。

### 4. 终止与轮次上限（票面第 2、6 条）

**上限 2 轮（1 轮独立 + 1 轮定向），可配。终止条件恰好落在票 15 已有的 `StopReason` 上。**

| 情形 | 事件 |
|---|---|
| 两行结论一致（或子串包含） | `RoundEnded { reason: NoDivergence }` |
| 第 2 轮后两行结论一致 | `RoundEnded { reason: Consensus }` |
| 第 2 轮后仍不一致 | `RoundEnded { reason: RoundsExhausted }`（讨论收尾，交给合成器画出选项空间） |
| 预算撞顶（票 18） | `RoundEnded { reason: BudgetExhausted }` |

- **为什么是 2 轮**：定向第二轮的设计目的就是"把调用数压到接近最小"（Chart 期），再加一轮就把这个目的抵消了；而研究说**无差别多轮共享是从众主因**，轮次越多越趋同——与"要发散"相反。
- **两个层次分清**（票面第 2 条的要求）：**单次调用级**的终止是票 02 那条"自己算、不信 `stop_reason`"；**讨论级**的终止是上表四个值，挂在 `RoundEnded` 上。两层各记各的，不要混。
- **第三轮不是新机制**：`RoundStarted { mode }` 已经有 `Independent | Targeted | Synthesis`（票 15），所以将来从 2 调到 3 是改一个数**外加重新论证**（成本上界从 5 提到 7，见末尾交接块）。

### 5. 讨论的某一轮失败（清掉 map 雾里的最后一半）

- **单侧失败**（一个讨论者这次调用以 `ProviderError` 收尾）⇒ **该方本轮缺席，讨论继续**；`RoundEnded` 照常发。
  - ⚠️ **缺席必须记成事件**（该方本轮没有 `MessageCompleted`，由**该方自己的 `TurnEnded { reason: Error }`** 表达（票 15 的收口；`RoundEnded` 没有这个字段）），否则**合成器会把"只有一份回答"读成"共识"**——这是这条路上最危险的一类误读。
- **双侧失败** ⇒ `RoundEnded { reason: Error }`，讨论以 `SessionError` 收尾。
- **不重跑**：票 02 的 adapter 已经在传输层做过有界重试（只重试 `RateLimited` / `Transport`），所以走到这里还失败的多半是**不可重试**的类（`QuotaExhausted` / `Auth` / `InvalidRequest`）——重跑白花钱。

### 6. 两条机制落点（可重算性与并发）

- **协议指令常驻私有身份（system prompt），不进流。** 理由是可重算性：票 07 的不变量是"任何 agent 的 messages 能从流 + 投影规则重算"；如果第二轮的"你看到了对方的回答，请针对分歧回应"是**追加的文本而不进流**，这条不变量当场不成立。而**投影已经给了模型判断轮次所需的一切**（`[轮 N · 名字]` 前缀 + 可选的 `RoundEnded` 行），所以身份里一句"你会看到带轮次标记的历史；若这是第二轮，针对分歧点回应"就够了。
  - 为什么不每轮注入一条 `ContextInjected`：可行，但会把**协议**变成投影要处理的内容，而且每轮一条注入会占票 17 那条**永不裁剪**的黏性档位——那是留给 AGENTS.md / 计划的。
- **同一轮里的两个讨论者并发发**（第 1、2 轮都是）：他们互不可见、无顺序依赖，串行只是白等一半墙钟。而且**异构在这里白送一个好处**——两个调用打到**两家不同的 provider**，并发预算天然分到两家，而不是把同一家的 RPM/TPM 尖峰翻倍。（与票 14 的"同一批多个调用可并发"是同一个模式。）

### 词汇

**合成器（Synthesizer）**：讨论收尾时把各方发言合成产出的**那一次调用**——**不是 agent**（无工具、无回合、不参与轮次）。所以它是 `Debater` / `Executor` 之外的**第三种参与者，但不是第三种身份**。已登记进 `CONTEXT.md`。

### 明确不做

- 独立的中立裁判、受控极性标签（第 1 节）；收敛式合成（第 2 节）；摘要式揭示（第 3 节）；第三轮（第 4 节）；失败重跑（第 5 节）；把协议指令做成注入事件（第 6 节）。

### 交接

- **票 18**：本票给出一组**确切的调用数**——**无分歧 = 3 次**（2 独立并发 + 1 合成）；**有分歧 = 5 次**（2 独立 + 2 定向 + 1 合成）。另外：**每轮 2 个调用并发 ⇒ 瞬时并发 2**（且分属两家 provider）；**合成器是一次独立调用，它的模型正是你第 4 条"弱模型分流"的第一个真实用户**；讨论的轮数上限（2）与执行者的轮数上限（25）是两个旋钮。
- **票 19**：`DivergenceRecorded { round, topic, positions }` 里的两个 `positions` **就是那两行结论**（机械产物，天然结构化、可直接展示）；`RoundEnded { reason }` 的四个值直接回答"**为什么停**"；而**单侧失败必须能一眼看出来**——否则你会把"一方缺席"读成"双方共识"，这是本票最危险的一类误读。

**票 18 交接来的一条停法（2026-09-13）**：**预算撞顶时，讨论不再开第二轮、直接进合成。**

- 合成是**唯一不能省**的调用——省掉它，整个讨论白花钱。
