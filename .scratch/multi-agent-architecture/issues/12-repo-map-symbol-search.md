## Answer

**已定（2026-09-12，grilling 与用户逐轮确认）。事实来源：`research/04-tree-sitter-and-symbol-extraction.md`（票 23 的产物）；接口受票 03 的 `Tool` trait 与票 06 的预算约束。**

### 1. 范围（票面第 3 条）

**只做符号检索（repo map）；向量检索 / RAG 判为 out of scope。** 依据：代表性实现里**没有以 RAG 为核心卖点**的；向量检索会引入**第三个 API 面（embeddings）+ 索引存储 + 切块策略**，并反向压到票 02 "只做一个 OpenAI-compatible client" 的前提。→ 已记入 map 的 `Out of scope`。

### 2. 怎么到达模型 + 何时构建（票面第 2 条）

**做成一个内建只读工具 `repo_map(focus?)`**，与票 09 的 `skill(name)` 同形：产物是流上的一条 **tool result**，`effect()` = **`ReadOnly`**（票 03），自动落进票 06 的截断 / 丢弃策略。

- **为什么不注入**：编码会话里文件几乎每轮都在变，"脏了就刷新"会让 map 之后的整段历史反复掉出缓存前缀——与票 06 的硬约束（前缀稳定 ="免费的 5~10 倍成本差"）相抵；而"开局钉住、整会话不刷新"会让它从第一轮就陈旧，且仍占常驻预算与票 06 的一个裁剪类目。
- **代价**：不再主动可见。用常驻工具清单里的那一行描述 + 系统提示里一句话补足（"探索陌生仓库前先调 `repo_map`"）。
- **刷新**：按需调用天然新鲜，**不需要脏标记与 refresh 策略**（aider 的 `auto/always/files/manual` 四档正是"注入"这个选择的代价）。重复调用便宜靠**工具内部的 mtime 缓存**（aider 用 SQLite + mtime 失效，同一思路）。
- **落点**：**`context` 的子模块**（票 01 已定），对外只暴露这一个工具。

### 3. 预算（票面第 1 条）

**固定预算，不动态伸缩。** 默认 **1,024 tokens**（aider 文档默认值），可配上限 **4,096**（aider 源码 clamp 的上限）——沿用生态里被实际用过的两个数。

- **不接受模型传 `tokens` 参数**：预算是**配置项**，不是模型的决定——与票 06 "预算不是状态、是函数"同一纪律。
- aider 的动态伸缩（`map_mul_no_files=8`）的前提是"我没有任何焦点，只好尽量全给"（官方文档原文），而我们的工具是在**带上下文的时刻**被调用的，那个前提不成立。模型要更细可以再调一次 `repo_map(focus?)`，或直接用 grep / read 深入。
- 成本性质变了：从"每轮常驻"变成"每次调用"。

### 4. 抽取与排序（票面第 4、5 条）

**抽取 = tree-sitter + 官方 `tags.scm` 约定**（`@role.kind` + `@name`），产出 `(文件, 名字, 种类)`。

- 事实边界：**`tags.scm` 只有名字，没有签名捕获、没有作用域捕获**。要在图里显示签名，得自己用 `byte_range` + `utf8_text` 取定义行——**v1 不做**，图里只有名字与种类。
- 版本事实：`tree-sitter 0.27.0` 的 MSRV 是 **1.90 / edition 2024**（本机 `rustc 1.94.0` 可用）；`tree-sitter-rust` 生成 ABI 15，运行时 ≥0.25 支持 13–15。
- **增量解析（`Tree::edit` + `parse(text, Some(&old))`）存在但 v1 不用**：它要求常驻语法树（最坏情况内存实测 ≈133MiB / 237 文件），而全量重算只要约 0.6s。留作后置优化。

**排序 = 朴素、可解释、纯函数**：

- 主信号 = **会话相关度**（最近读写过的文件 + 最近消息里出现过的标识符）；次信号 = **结构信号**（被引用 / 被定义符号的次数）。
- **不做整图 PageRank**：petgraph 的现成 `page_rank` **没有边权、没有 personalization**，照抄 aider 得自己写带权 power iteration；而传递性重要性的收益集中在大仓库。
- **接缝**：`rank(symbols, graph, context) -> scored` 是纯函数，将来换带权 PageRank 是**局部替换**，不是重构。

### 5. 明确不做

- **向量检索 / RAG**（第 1 节，已入 map 的 `Out of scope`）。
- **AST / tree-sitter 编辑**（票面已注明：与"用于读"方向相反的赌注，证据型砍掉项）。
- v1 不做：签名渲染、增量解析、跨语言（只 `tree-sitter-rust`）、图排序。
