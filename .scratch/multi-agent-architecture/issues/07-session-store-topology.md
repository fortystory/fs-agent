## Question

决定会话持久化的形状。**本票已改写**：多 agent 让"一个会话 = 一份 messages"这个前提失效。

要回答：

1. **格式与落盘时机。** 综述的收敛结论：JSONL 追加写、**每条消息立即落盘**（"格式本身不重要，『每条消息立即落盘』才重要"——goose 后期从 `.jsonl` 迁到 SQLite、Gemini 用 JSON，都印证这点）。现在落盘的是**事件流**（票 15），不是 messages。落在哪个路径？
2. **多 agent 拓扑。** 这是本票的新核心。一个"会话"里至少有：N 个讨论者、若干被派出的执行者。它们的流是：
   - **一条流容纳所有发言者**（靠 `speaker` 字段区分）
   - 还是**每个 agent 一条流**，再靠引用组装？
   综述给的先例是 **goose 的会话模型显式带父子关系**——`sessions.db` 里有 `parent_session_id`，fork 出来的会话与 `SessionType::SubAgent` 都靠它表达。**被砍掉的是 fork 这个用户手势，但多 agent 需要的是会话拓扑，这是两件事。** 本票要定拓扑怎么表达。
3. **`--continue` 如何找到最新会话。** 会话与目录绑定吗？（综述：Claude Code 会话与目录绑定，因此可以用 **git worktree** 开并行会话。）多 agent 下"最新会话"的语义还成立吗？
4. **一条不变量被打破了。** 旧图切片 2 建议建立"**发送给模型的 messages == 可落盘 trajectory**"（引 mini-SWE-agent 的线性历史设计，理由是"great for debugging & fine-tuning"）。**多 agent 的投影破坏了这个等式**：每个 agent 收到的 messages 是流的一次投影，各不相同。所以新的不变量应该是：**流是唯一的 trajectory；任何 agent 的 messages 都能从流 + 投影规则重算出来。** 请确认这条，并说明它要求投影是**纯函数**（可重放）还是可以带状态。
5. **与可观测性的关系。** 综述第 16 节说 transcript 落盘是"完整 transcript（含工具参数与结果）"的实现，且"是会话恢复的同一份数据"。确认两者共用一份数据而不是两套——票 19 依赖这个答案。
6. 明确**不做**：fork / branch 会话（用户手势）、交互式 rewind 菜单、shadow git、自建快照系统、event sourcing 架构（**注意**：这里说的不是"事件流作为真相源"，而是 OpenHands 那种多前端/多 runtime 订阅的完整 event-sourcing 架构）、SQLite。

**票 02 交接来的新约束（2026-09-12）**：终止判定要求「日志里存在**没有对应结果的 `tool_call`** 时，绝不允许再调 provider」（票 02 第 6 节）。会话恢复会正面撞上这个悬空状态（assistant 带 `tool_call`，但流里没有对应结果）——本票要定它怎么收尾：补一条合成的失败结果、丢弃这条 assistant，还是重执行。

**票 06 交接来的新约束（2026-09-12）**：工具结果截断采用"**全文落盘 + 事件里只放预览与落盘指针**"（票 06 第 3 节）。这等于把"流是唯一真相源"变成"**流 + 落盘文件**"——本票要正面回答落盘路径、形态、生命周期（清理/保留），以及**恢复时指针失效**怎么办。

**仍保留**（不在被砍之列）：每次编辑自动 git commit + `/undo`（旧图切片 7）。

答案定到存储形状、拓扑表达与落盘时机，不要实现。

**票 15 交接来的事实（2026-09-13）**：编码与写纪律已经定了，本票从**布局 / 拓扑 / 选择器**接手。

- **编码**：一个会话一个文件，**一行一条事件（JSONL）**；**`seq` 就是行号**，也是事件的**规范身份**（票 15 明确不引入第二个 id）。
- **写纪律**（第 1 条已定泰半）：**单一写入者**——writer 独占文件句柄，其余一切通过 channel 送事件。这是为了绕开 research 08 那条硬约束（`std` 的 `OpenOptions::append` **不保证**跨线程追加不交错），不是风格选择。**每条 flush，不每条 fsync**；读取时**丢弃最后一行不完整的记录**。
- **版本**：`SessionStarted { schema_version }` 承载；版本对不上**明确报错、拒绝误读，不做迁移**。
- **拓扑（第 2 条）已被部分回答**：**一条流容纳所有发言者**，靠 `speaker_id`（`Debater(id) | Executor(id) | User | System`）区分，**不按 agent 分流**。所以第 2 条只剩"一条流如何表达讨论者与执行者的**从属关系**"——票 15 给了 `SpeakerId::Executor(AgentId)` 与 `ExecutorSpawned { executor_id, parent, brief }`。
- **fork 与树形**：票 15 **不做树形日志**（信封上没有 `parent`，物理序 = 逻辑序）。所以**若**本票最终需要分支，唯一可行的形状是「**新会话 + 复制前缀**」（Claude Code 的 `--fork-session`）。注意本票第 6 条已把"fork / branch 会话（用户手势）"列为不做——两者不矛盾：不做**手势**≠不需要**拓扑**；若拓扑确实不需要分支，这条自然消失。
- **第 4 条那条不变量请照票 15 的形状确认**：流是唯一 trajectory；**投影是纯函数**（票 06/17 已经把它钉死为 `project(log, rules)`，不带裁剪状态）。

## Answer

**已定（2026-09-13，grilling，6 问逐条确认）。** 编码与写纪律来自票 15；本票接手**布局 / 拓扑 / 选择器**，外加两处交接（票 02 的悬空 `tool_call` 与 `prompt_cache_key`、票 06 的落盘指针）。

> **两处机械修正（是决定之间的合成，不是新决定；请过目）**
> 1. **会话是「一个目录」，不是「一个文件」**：Q1 的选项字面写的是 `<session-id>.jsonl`，而 Q4 的选项要求"**删会话 = 删目录**、会话是一个可搬运单元"。两者合起来只有一种形状：每个会话一个目录。→ `sessions/<cwd-slug>/<session-id>/log.jsonl` + `.../outputs/`。
> 2. **落盘文件名用 `<tool_call_id>`，不是 `<seq>`**：`seq` 由 writer 在**追加时**分配，而票 06 规定"单次结果截断在**入流前**"——落盘发生在取号之前。`tool_call_id` 此刻已知且唯一。

### 1. 落点、目录绑定与 `--continue`（票面第 1、3 条）

```
~/.local/share/fs-agent/sessions/<cwd-slug>/<session-id>/
                                             ├── log.jsonl                    ← 票 15 的事件流
                                             └── outputs/<tool_call_id>.txt   ← 票 06 的落盘（第 5 节）
```

- **数据放 `~/.local/share`，与 `~/.config/fs-agent/config.toml` 分家**（XDG：配置不是数据）。
- **`<cwd-slug>` 只用于分桶，不是真相**：权威 `cwd` 记在 `SessionStarted { cwd }` 里——slug 对含特殊字符的路径不可逆，且目录改名后追不回来。先例：Claude Code `~/.claude/projects/<project>/`、Gemini `~/.gemini/tmp/<project_hash>/chats/` 都是"全局目录 + 按项目分桶"。
- **不放项目内**：会污染用户仓库，还要每个项目记得补 `.gitignore`。
- **`--continue`**：只扫**本目录桶**，取 **mtime 最新**的那一个。用 mtime 而不是文件名时间戳，因为"最新"的语义是**最近活动**——一个昨天创建、今天被 `--continue` 追加过的会话，最近活动的是它。一次 `readdir` 足够；**不维护全局索引文件**（那会是第二个真相源，且需要自己的写入者与锁）。
- **`--resume <id>`**：精确 id，或唯一前缀。
- **会话与目录绑定**：跨目录不互相污染。这顺带保住综述那条用法——**用 git worktree 开并行会话**（每个 worktree 是不同 cwd = 不同桶）。
- **多 agent 下"最新会话"的语义不变**：会话仍是单位，不是每个 agent 一个单位（第 3 节）。

### 2. 会话 id：一条被票 02 点名的义务

- **形状**：`<UTC 时间戳>-<短随机后缀>`（例如 `20260913T203015-a7f3`）——**可排序、人可读**，且不需要中央分配器。
- **持久化在两处**：目录名，与 `SessionStarted { session_id }`。
- **`--continue` / `--resume` 后 id 不变**：恢复是**向同一个 `log.jsonl` 追加**，绝不新建 id。
- **为什么这是硬要求**：票 02 已定 `prompt_cache_key` 的值 = **会话标识**，且"**`--continue` 后必须不变**"（Kimi 的缓存分片按它走）。新建 id 就等于每次恢复都丢掉前缀缓存——那正是综述说的"免费的 5~10 倍成本差"。

### 3. 多 agent 拓扑：一个会话**一条流**（同一个目录下），执行者的事件在同一个流里（票面第 2 条）

- 票 15 已定"一条流容纳所有发言者"，靠 `speaker_id` 区分；**执行者不另立文件、不另立会话**。
- **从属关系由事件表达**：`ExecutorSpawned { executor_id, parent, brief }` 记父子，`SpeakerId::Executor(id)` 标记它的每一条事件。
- **`CONTEXT.md` 那句"Executor 用带 `parent_id` 的嵌套 Session"是内存里的值结构，不是文件布局**——嵌套 Session 共享同一条流，`seq` 仍是唯一顺序。
- **否掉的替代**：会话目录树（每个执行者一个子文件）会把票 15 刚避开的**跨总线顺序一致性**重新引回来（`seq` 不再是一个全局顺序，得额外定义跨文件拼接）；执行者完全独立成会话（自己的 id 与目录）会让"看一眼它在干嘛"变成跨会话读，且破坏"一个会话一个单元"。
- **存储层不做任何可见性裁剪**：执行者的事件默认就在流里；讨论者看不看得到是**投影规则**的事（票 14 定策略、票 17 实现）。

### 4. 恢复时撞上悬空的 `tool_call`（票 02 交接）

**补一条合成的失败结果事件**：`ToolCallCompleted { tool_call_id, ok: false, error: "会话中断于此，结果未知" }`。

- 保住票 02/03 的不变量（每个 `tool_call` 恰好一条结果），因此恢复后可以合法地再调 provider。
- **不丢弃那条 assistant**：那是截断，破只追加，且默默丢掉模型输出。
- **不重执行那个工具**：写工具的副作用可能已经发生，重执行 = 双重应用；而崩溃点可能就在写的中途——我们区分不了"跑没跑"。
- **措辞必须诚实**：**"结果未知"**，不编造成功也不编造失败。该事件的 `at` 是恢复时刻，恢复点因此隐式可查。
- **不追加第二个 `SessionStarted`**：它标记会话创建与 `schema_version`，属于整个文件，不属于某一次运行。

### 5. 工具结果全文的落盘（票 06 交接）

- **位置**：**与会话同目录**的 `outputs/`（即 `<session-id>/outputs/`）。
- **文件名 = `<tool_call_id>.txt`**（见文首机械修正 2）。
- **生命周期与会话一致**：删会话 = 删目录，导出 / 搬运是一个单元。**v1 不自动清理**（自用、磁盘便宜，删掉的就是证据）；将来若要自动清理，照 Gemini 的 `sessionRetention`（`maxAge` / `maxCount`）加在**目录**粒度上。
- **指针失效 → 降级为预览，绝不失败**：票 06 已保证**事件里带预览**，所以截断后的**消息级** trajectory 仍可从流重建；指针只是保真度的加成，不是真相源。失效时报**一次**诊断（不是每条事件报一次）。
- **模型要全文不需要新工具**：指针是一个**路径**，现有 `read_file` 就能读它。

### 6. 两条不变量的精确措辞（票面第 4、5 条）

- **精确措辞：`流 + 落盘文件 + 投影规则 → messages`。** 不再是"流是唯一真相源"——票 06 的落盘已经把这句话改写了。但**消息级** trajectory 仍只依赖流（因为预览在流里）；落盘只补**保真度**。
- **投影不读落盘文件**：`project` 保持**纯函数**（票 06/17 的核心不变量）。一旦投影做 I/O，"任何 agent 的 messages 都能重算"当场失效。
- **确认与可观测性共用一份数据**（票面第 5 条）：事件流**就是**结构化数据，票 19 的查询与索引建在这一份会话目录上，**不存在第二套日志格式**。
- **确认投影必须是纯函数**（不带裁剪状态）：票 06 已把裁剪划到投影**之后**。

### 7. 自动 commit 与 `/undo` 落在什么上（票面"仍保留"那条）

**能力保留，实现不落在 git 上；也不需要 shadow git 或快照系统。**

- 编辑工具在写入前，把**实际被替换区段的旧内容**作为**大内容**走票 06 的落盘机制：`<session-id>/outputs/<tool_call_id>.before`。
- **`/undo` 的查法不需要解析文本**：在流上找"最近一次 `ToolCallStarted { tool_name: edit_file, args.path == P }`"，按**约定路径**读那次调用的 `.before` 写回。
- **为什么必须是"实际被替换的区段"而不是 `old_string`**：票 04 的匹配梯会做"行尾空白无关 / 每行 trim"的降级匹配，命中的文本可能与 `old_string` 不完全一致——用 `old_string` 反推会写错。
- **零新事件变体、零结构改动**：指针不进 payload，靠**命名约定**从流上已有的 `tool_call_id` 推出来。
- **不做"每次编辑自动 git commit"**：它会把用户未提交的改动裹进一个用户没要的 commit，且在非 git 目录里直接失效。`/undo` 用会话自己的落盘，不依赖用户仓库的状态，也不依赖 cwd 是不是 git 仓库。
- **`.before` 不打码**（票 21 第 3 节：它是字节级还原源）。
- `/undo` 的写回**必须取与编辑同一把 per-path 锁**——它绕过了工具层，而并发的执行者可能正在改同一个文件。

### 明确不做

- fork / branch 会话（用户手势）、交互式 rewind 菜单、shadow git、自建快照系统、完整 event-sourcing 架构、SQLite。
- 全局会话索引文件（第 1 节）、自动清理（第 5 节）、第二个 `SessionStarted`（第 4 节）。
- 执行者的独立文件 / 独立会话（第 3 节）。
- **每次编辑自动 git commit**（第 7 节；它承载的能力由会话落盘的 `/undo` 覆盖）。

### 交接

- **票 04**：编辑工具需要把**实际被替换区段的旧内容**落到 `<session-id>/outputs/<tool_call_id>.before`（第 7 节）——这是 `/undo` 唯一的数据来源。
- **票 06**：落盘路径与形态已定（第 5 节）；指针失效降级为预览、绝不失败。
- **票 19**：查询与索引建在同一份会话目录（`log.jsonl` + `outputs/`）上，不存在第二套日志格式（第 6 节）。

**票 21 交接来的两条（2026-09-13）**——它按票 19 交接的"文件权限 / 保留策略"收了口：

- **权限：创建即 `0700` 目录 / `0600` 文件**，**不是事后 `chmod`**（那之间有一个窗口）。理由很具体：在常见的 `umask 022` 下默认会是 **0644，即同机其他用户可读**，而里面是**完整 transcript**（含它读过的文件内容、工具输出、可能的凭据）。

- 与你第 5 节那条"将来若要自动清理，照 Gemini 的 `sessionRetention` 加在**目录**粒度上"一致——**手动 `prune` 就是那个粒度**，自动版仍然后置。
