## 问题陈述

在真实会话里，模型每三次工具调用就有两次走 `bash`（7703 次 bash / 12555 次全部调用 = **61.4%**），
而这份用量里有三块是**工具层缺东西**造成的，不是模型偏好造成的：

1. **搜索看不到上下文**。bash 内的 `grep`/`rg` 有 5495 次，其中 **20.1% 带 `-A`/`-B`**（`-A` 903、
   `-B` 202、`-C` 1），而内建 `grep` 只有 `pattern`/`glob`/`count` —— 想看一眼函数体就只剩
   bash 一条路。更早的 spec 把"上下文用内联语法或多次调用解决"写进了《明确不做》，八天的使用
   证明那条替代方案没有被采用。
2. **每条命令都要自己写站位**。86% 的调用以 `cd` 开头（`cd` 段 6379、占全部段 23%），其中
   `cd "$(pwd)"` 517 段是纯冗余。`workdir` 参数 2026-10-09 就上线了，两天里 3175 次调用只有
   **1 次**用它（0.01%）——描述层的引导完全失效。
3. **版本控制没有一等入口**。`git` 在 bash 段里出现 1799 次（读侧 78%：`diff` 436 / `status` 395 /
   `log` 285 / `show` 78；写侧 `add` 156 / `commit` 152 / `stash` 106），而模型侧今天一次 git
   集成都没有。渲染层早就有一份宿主侧实现，模型却只能拼 shell。
4. **文件枚举只能靠 `ls`/`find`**。两者合计 832 段以上，而上游四家都给了专用的只读枚举工具。

另外两块**不该**由工具接：命令输出过滤（管道下游 177 形态 / 8558 段，占全部段 24%）本质是
shell 管道；读写文件的就地改写（634 段）已有 `edit_file`/`write_file`。这两块留 bash，理由写在
《明确不做》一节。

**判据**（本 spec 的验收由它定义）：bash 调用数与段数下降为主、token（字符近似）下降为辅，
用 2026-10-10 那份基线做同一套统计的对比。

## 方案

四项改动 + 一条验收：

1. `grep` 增加 `after` / `before` 两个可选参数，输出补齐 ripgrep 的上下文行形状；
2. `bash` 的 `workdir` 改为**必传**，结果首行回显实际站位，并删掉与 `escalation` 的旧互斥；
3. 新增一条 `git` 工具：单入口、`op` 枚举、`effect()` 按 op 分档；
4. 新增一条只读的**文件枚举**工具：按 glob 模式列出工作区里的文件路径；
5. 验收：一条命令，与已存档的基线并排看（`--since <发布日>`）。

四项里的第 1、2 项合并成**一次发布**（两次改工具声明 = 两次前缀缓存作废，合并只废一次）。

## 实现决定

### §1 `grep` 的上下文参数

- **参数面**：新增 `after`（整数，可选）与 `before`（整数，可选），语义分别等价 `rg -A N` / `rg -B N`。
  **不加 `context`**（实测 `-C` 只出现 1 次），**不加** `files_only` / `invert` / `path`。
- **值域**：非负整数；负数与非法类型是参数错误。**不设上限、不夹取**——输出被下面的 500 收口。
- **输出形状照抄 ripgrep**：命中行 `相对路径:行号:文本`（与今天一致）、上下文行
  `相对路径-行号-文本`（真实行号）、两个命中块之间插一行 `--`。**相邻命中的上下文区间重叠时合并成一块**。
- **上限语义变更**：`MAX_MATCHES = 500` 从"最多列出多少条命中"改成 **"最多列出多少行"（命中行 +
  上下文行合计）**；常量不动、不新增第二把刀。末尾那句改成数**未列出的命中行数**
  （「还有 N 条命中未列出：请缩小搜索范围，或用 `glob` 只搜一部分文件」）。
- **与 `count` 的交互**：`count: true` 与 `after`/`before` 同给时**忽略后者**（计数模式一行不列）。
- **实现方式**：用搜索器自带的前后上下文能力（`after_context` / `before_context` 与 `Sink` 的上下文回调），
  不要在收集端自己重扫补行。
- 溢出仍走既有的截断流水线（落盘 + 头尾预览 + 指针），**不新增第二套截断**。

### §2 `bash` 的 `workdir` 必传与 cwd 回显

- **`required` 从 `["command"]` 改成 `["command", "workdir"]`**。
- **允许 `"."` 表示工作区根**（这是对 charting 时那句"不允许 `.`"的修正：根必须有一个自然写法，
  而空字符串 / 绝对路径 / 哨兵值都更差；强制力来自字段必填，不是来自禁用根）。
- 非法值是**参数错误**，沿用既有的"半截写法不静默忽略"风格：省略、空字符串、不存在、落在工作区外。
  省略那句错误文案要点明"根写 `.`"，否则模型会去猜根怎么表达。
- **结果首行固定为 `cwd: <相对工作区的路径>`**（根写作 `.`），**无条件**加——`cd "$(pwd)"` 那 517 段
  的痛点恰恰是"不确定自己站在哪"，填根时最需要这行确认。其余报告（退出码、stdout、stderr）不动。
- **`cd` 冗余只改描述**：不加结果提示、不做工具层拒绝（含 `cd` 的命令占 85%，提示会变噪声；
  而 `cd` 在 `/tmp`、子 shell、`for` 循环里都是合法用法）。
- **删掉 `workdir` 与 `escalation` 的旧互斥**：必传之后两者永远同现，那条规则会打死每一次升级调用；
  它的原意图（防止借 `workdir` 自选工作区）在"必传 + 严格解析在工作区内"之后不再成立。
- 站位与边界的两段语义不变：进程站位给解析后的 `workdir`，沙箱边界仍由会话 cwd 推出来。

### §3 `git` 工具

- **一条工具，两个字段**：`op`（枚举，必填）+ `args`（字符串数组，可选，原样透传）。
- **`op` 取值**：读 `status` / `diff` / `log` / `show`；写 `add` / `commit` / `stash`。
  `rev-parse` / `branch` / `ls-files` 与那组搭测试仓库用的 `config` / `init` / `user` / `safe` **不进**（留给 bash）。
- **`effect()` 按 op 分档**：读 op = `ReadOnly`（四档全放行、不取工作区锁）；写 op = `Exclusive`
  （`add`/`commit` 写的是 `.git/index` 之类，枚举不出"恰好这些路径"）。参数错误要在 `effect()`
  之前就能判出来。先例是 MCP 转发工具那处的"按参数返回不同 `Effect`"。
- **输出原样**（stdout / stderr / 退出码），**不加 `cwd:` 首行**（站位固定为会话 cwd，没有歧义），
  溢出走既有截断流水线。
- **不给 `workdir`**：实测 `git -C` 出现 0 次，git 自己向上找仓库根；需要换目录时用 `args` 透传 `-C`。
- **安全边界不动**：沙箱仍把 `.git/config` 与 `.git/hooks` 压回只读——不能把整个 `.git` 压只读，
  否则 `git add`/`commit` 写不了 `.git/index.lock`。
- **与渲染层分工：代码不共用** —— 渲染层那件宿主侧子进程件的三条纪律（不过权限门、不过沙箱、
  不在任何一帧里 await）与模型侧的要求正相反；git 工具走工具层已有的带沙箱进程件。
  共用的只是"起一个子进程"这件事本身，不是一段代码，也不是解析与上色（渲染层要 `@@` 行与
  `diff --git` 的解析、要 ANSI）。模型侧**必须过权限门与沙箱**，渲染层那条明确不过——
  这条分界线写进文档。
- **声明与实现同批**：写 op 与读 op 一起声明、一起实现。声明了不实现会让模型调用到失败；
  分两批发布则多废一次前缀缓存。

### §4 文件枚举工具（07 票的形状，由本 spec 定）

- **一条工具，一个字段**：`pattern`（必填，相对会话 cwd 的 glob，支持 `**`，例如 `src/render/*.rs`、
  `**/*.md`、`.scratch/*/spec.md`）。**不加 `path` 参数**——路径前缀就写在 pattern 里，
  这样"只扫工作区"这个支点原样保留。
- **名字**：`glob`（上游同名，模型最熟；`list_dir` 的目录语义由 `src/*` 这类 pattern 覆盖）。
- **忽略规则与 `grep` 同一套**：遵守 `.gitignore`、跳过隐藏文件与隐藏目录。
  上游有一家让 `Glob` 与 `Grep` 用两套规则，本仓库**不跟**——同一张工具表里的两个工具看见的世界必须一致。
- **输出**：一行一条相对路径，**按路径排序**（与 `grep`、`repo_map` 同一个稳定性口径；不按 mtime，
  那要么多一次 stat、要么让输出不可预期）。不带大小与时间。
- **上限**：`MAX_PATHS = 500`（与 `grep` 的 `MAX_MATCHES` 同值，少一个新常量）；超限时末尾一句可操作的收尾。
- **`effect()`**：`ReadOnly`。
- **不做** `tree` 那档层级缩进。
- 描述里一句话写清三者分工：**符号地图**答"有哪些符号"、**`grep`** 答"某个名字在哪"、
  **本工具**答"有哪些文件"。

### §5 描述与文档

- `grep` 的描述：留一句短的劝阻，把篇幅换成正面说明——`after`/`before` 解决"命中行本身没有信息量"、
  `count: true` 解决"只要数字"、命中太多会被截断并给出一条落盘路径。
- `bash` 的描述：站位那段常量从"可选"改写成"必填 + 根写 `.` + 用它代替写 `cd`"。
- `read_file` 的描述：加一句"要看某一段就带 `offset`/`limit`"（[收编判定](issues/05-grilling-intake-verdicts.md)
  的结论：窗口读不是能力缺口，是采纳问题）。
- 文档：`grep` 的参数表 / 输出形状 / 上限语义 / 计数互斥、`bash` 的参数面、**新增一份 git 工具文档**
  与**一份文件枚举文档**（与既有工具文档同规格：为什么不是 shell 命令、参数面、输出与上限、
  分工表）、README 的工具清单。
- **不立 `CONTEXT.md` 词条**：`git`、`glob` 是工具名不是领域词；两个新说法（文件枚举、读 op / 写 op）
  住在各自文档里。

### §6 要推翻的两处既有记录

- `grep` 工具 spec 的《明确不做》里那条"`ignore_case` / `context`（`-C`）/ `max_count` 等开关：
  用 pattern 的内联语法或多次调用解决"→ 改成**已推翻**，依据写实测（`-A` 903 / `-B` 202 / `-C` 1、
  带上下文占 grep/rg 段 23.2%、形态表里 `grep -A <N> -n <PAT> <PATH>` 664 段 / 584 调用）。
- `bash-workdir` spec 的 `required` 明文与 §2 的互斥条 → 改成必填 + 允许 `.`、互斥已取消，
  依据写实测（上线后 3175 次调用只有 1 次带 `workdir`）。

### §7 发布与验收

- §1 与 §2 合并成**一次发布**（少作废一次前缀缓存）；`git` 与文件枚举可以在其后。
- 验收命令一条：

```bash
python3 .scratch/tool-coverage/research/01-shape-inventory.py --since <发布日> --top 120
```

  与 [`research/06-baseline-2026-10-10.txt`](research/06-baseline-2026-10-10.txt) 并排看。
- **量度口径**：主判据三个——每会话 bash 调用数**中位数**、段数/调用（不切管道切法）、
  命令与结果字符数**中位数**；bash 占全部工具调用的比例作辅。token 用字符近似，**不碰用量事件**
  （它带说话人、受模型行为影响，分不清"工具省下的"与"模型少说了"）。
- **样本门槛**：只看发布日（含）之后的会话，累计 **≥ 20 个含 bash 的会话**再判；样本本来就偏
  （274 个会话里 173 个一条 bash 都没有，两天占 63%），所以用中位数。
- **冲突判据**：主判据降而结果字符数中位数升超过 10% 时才要求单独解释（上下文行让结果变长是买来的东西），
  记为"待观察"、不阻塞。

### §8 不改

- `bash` 的 `Effect::Exclusive` 与沙箱边界；`grep` 只扫 cwd、不读 stdin；`repo_map` 的注入策略；
  权限模式的四档语义；渲染层 `changes.rs` 的行为与"模型可见文本一个字节不动"那条不变量。

## 测试决定

- **接缝**：沿用现有工具测试的写法——组装一个 harness（脚本化 provider + 脚本化 asker），
  让模型发一次工具调用，断言**事件流、工具结果文本与权限裁决**。这是现有工具测试用的最高层接缝，
  不需要新开一条。prior art：`tests/grep_tool.rs`（825 行，三条接缝：门与效果、命中与范围、不登记读集合）
  与 `tests/bash_tool.rs`（755 行）。
- **好测试的判据**：断言外部行为——工具声明里的参数面（哪些字段、是否必填）、`effect()` 的档位
  与四档下的裁决、结果文本的形状（分隔符、行号、块分隔、`cwd:` 首行）、上限与收尾那句、
  参数错误的文案；不断言内部函数、不断言实现用了哪个库。
- **要测什么**：
  - `grep`：上下文行的形状与合并、行号、500 的合计口径（上下文行占额度）、`count` 与 `after`/`before`
    同给时的忽略、负数报错、`after: 0` 合法；
  - `bash`：省略 `workdir` / 空串 / `"."` 允许 / 不存在 / 区外 各自的裁决与文案、结果首行的
    `cwd:` 形状（根写作 `.`）、带 `escalation` 的重试不再被互斥打死；
  - `git`：读 op 在 `readonly` 档放行、写 op 被拒或要走既有的写路径、未知 op 是参数错误、
    `args` 透传的形状、`.git/config` 与 `.git/hooks` 仍只读；
  - 文件枚举：忽略规则与 `grep` 一致、路径排序稳定、上限 500 与收尾、`effect()` 为 `ReadOnly`、
    非法的 glob 是参数错误。
- **测哪些模块**：四个工具各自的 schema / effect / 输出整形；接线处（注册表、权限门、截断流水线）
  由既有测试覆盖，不重复。

## 明确不做

- **命令输出过滤工具**（`cargo test … | grep` 那一族，stdin 类 8558 段、占全部段 24%）：工具层要接它
  只有两条路——泛化的"第二条 `bash`"（权限代价与 `bash` 相同，而劝阻无效的实证说明模型没有理由换），
  或 cargo 专用（窄到接不住 `git diff | grep`）。**留 bash**。
  *条件项*：等采纳数据积累到能分清"模型不用工具"与"根本没有工具"时，重判是否加一条泛化的
  `run(command, filter)`。这是有意留的观察项，不阻塞本 spec。
- **窗口读工具**（`sed -n` 那 2627 段）：`read_file` 早有 `offset`/`limit`，缺的是采纳——只改描述。
- **写侧文件操作**（`mkdir` 78 / `rm` 27 / `mv` / `cp`）：合计百来段，却要把写路径与权限语义再走一遍。
- **写文件与就地改写工具**（`cat >> <<HEREDOC` / `sed -i`，634 段）：`edit_file` / `write_file` 已覆盖；
  而"模型为什么不用它们"在日志里读不到（没有逐次请求的工具 schema），不开猜测性工具。
- **`python3 << HEREDOC` 工具化**（1135 段）：那等于第二条 `bash`。
- **会话日志挖掘工具**（52 段）：开发期行为，不是常态工作流。
- **`curl` 工具化**（67–104 段）：已有网页抓取工具。
- **PTY / 真机走查工具**（5 段）：这批数据里几乎不存在。
- **`grep` 的 `path` / `files_only`（`-l`）/ `invert`（`-v`）**：`path` 会把一条最干净的只读工具拖进
  "区内外"之分；后两个属于另一条线（输出模式枚举）。
- **工具名前缀统一**：维护者明示"后续再做"，与本次的目的地不同轴。
- **会话级 worktree 隔离**、**渲染层改动页的行为**：各有自己的 effort，本 spec 不碰。

## 补记

- **07 票的形状由本 spec 定**（上文 §4）。其中三处是**按已知惯例推断**、不是维护者逐条拍过的：
  工具名取 `glob`；忽略规则与 `grep` 同一套；排序按路径而非 mtime。改起来都便宜，落地前如要调整，
  只需动 §4。
- **数据快照**：2026-10-10，274 个会话 / 7703 次 bash 调用 / 35809 段（全切）。脚本
  [`research/01-shape-inventory.py`](research/01-shape-inventory.py)（一行命令、只写 stdout），
  报告 [`research/01-shape-inventory.md`](research/01-shape-inventory.md)，基线
  [`research/06-baseline-2026-10-10.txt`](research/06-baseline-2026-10-10.txt)。
- **一条硬边界**：`cd` 的"冗余率"判不了（日志只记会话起始 cwd，没有每次调用的实际 cwd）。
  所以本 spec 的立论只用「`cd <WS>` 5673 段 / 5604 调用」这个量级，**不写"其中 86% 是冗余"**。
- **冻结项的一处修正**：charting 时定过"`workdir` 必传且**不允许 `.`**"，走票时发现那会把
  "工作区根"的唯一自然写法禁掉，已改判为**必填且允许 `.`**（见 §2）。
- **§3 的一处修正**（拆实现票时发现）：原文说"与渲染层抽一层共用的只读子进程"站不住 ——
  两边的纪律正相反（渲染层不过权限门与沙箱，模型侧必须过），所以改成**代码不共用**，
  git 工具走工具层现成的进程件。**不需要 prefactor**。
- **本 spec 的判据只是"用量下降"**。原始 `grep` 工具 spec 的第一理由（默认 `ask` 档下每次搜索要
  打断人）在实测里不成立（12118 次裁决 Allow 12104、98% 跑在 `workspace` 档），不许再拿它当理由。
