## 表怎么读

- **骨架**：把 pattern、路径、文件名、字面量归一成占位符后的**段级**形态。`<WS>` = 该会话 `SessionStarted.cwd` 之下；`<TMPPATH>` = `/tmp`、`/var/tmp`、`/dev/shm` 下；`<TARGETPATH>` = `target/` 下；`<ABSPATH>` = 其它绝对路径；`<PATH>` = 相对路径；`<HEREDOC>` = heredoc 正文（正文本身不算段）；`<SUBST>` = `$(…)`、`$VAR`；`<SEP>` = `echo "---xxx---"` 这类分隔标记；`<DEVNULL>` = `/dev/null`；`<N>` = 数字；`<STR>` / `<PAT>` / `<SCRIPT>` / `<PY_SRC>` = 按命令语义标注的字面量角色。
- **段数 / 调用数**：段数按 `&&` / `||` / `;` / 换行 / 管道切段（heredoc 正文不算段）；调用数是「含该形态的 bash 调用数」，同一调用里出现多次只算一次。
- **管道%**：该形态的段里位于管道下游（输入来自上游命令）的比例。
- **可省段**：若这个形态被一等路径接住，平均能从它所在调用里省掉的段数。口径是**上限**：`cd`/`echo`/`for`/`do`/`done` 胶水段 + 管道下游段 + 管道符数，按调用内不同形态的个数分摊，形态自身若是胶水段再 +1。同一调用的多个形态会各记一份，**跨形态不可相加**。
- **判据**（冻结项 5 的四类 + heredoc 一类）：`stdin` = 输入来自管道上游；`prev` = 输入是刚生成的文件系统产物（`/tmp`、`target/`）；`write` = 批量文件系统写/删；`pty` = 需要交互或 PTY；`heredoc` = 脚本正文来自 heredoc。阈值是该形态 ≥30% 的段满足（`heredoc` 为 ≥50%）。
- **cmd中位 / res中位 / cmd总 / res总**：命令文本字符数与 `ToolCallCompleted.output` 字符数，**token 近似而非真 token**。总量按段累加，同一调用含多个形态会重复计入，跨形态不可相加。
- **成本**：1 = 改既有工具参数；2 = 开一条新工具；3 = 要改架构。按 argv0 的规则表判定（脚本里的 `COST_BY_ARGV0` + 判据覆盖），是判断不是实测，05 票可以逐条推翻。
- **排序视图**：`调用数 × 可省段 ÷ 成本档位`，降序前 20。

形态表默认列段数最高的 80 个形态（占全部 35809 段的 83.7%）；全量 1590 个形态用 `--top 1590` 一次打出，长尾每个都只有个位数段。表尾的排序视图覆盖全量形态（不限于表内 80 个）。

## 读不到的

下面这些判断我**没做**或**做不了**，以及缺什么数据。05 / 06 票要点名消费本表时，这些是已知的边界。

1. **模型的意图**：脚本只读命令文本，读不到「为什么用 bash 而不是工具」——是不知道工具有这个能力、还是参数接不住、还是习惯。判这一点需要在每个 `ToolCallStarted` 旁边看到**当时那次请求的工具表**（`ContextInjected` 事件里有上下文，但没有逐次请求的工具 schema 快照）。日志里有 `ContextInjected` 90 次，不足以覆盖 7703 次调用。
2. **真 token 数**：本表给的是字符数，不是 token。中文、代码、路径的 token/字符比不同，且结果文本里有 `退出码：…\n--- 标准输出 ---` 这类工具自己的包装。要真 token 得跑 tokenizer 并扣掉包装，本票没做。
3. **结果长度 ≠ 进上下文的字节数**：`ToolCallCompleted.output` 是工具输出全文。工具是否对超长输出做截断、模型实际看到多少，我无法从日志判定。所以 `res中位`/`res总` 是**上界**口径。
4. **`cd` 是否冗余**：判「`cd <WS>` 是纯冗余」需要知道 bash 工具执行时的工作目录（默认 cwd 是不是就是会话 cwd）。日志里没记每次调用的实际 cwd，`SessionStarted.cwd` 只是会话起始值。所以「86.1% 以 `cd` 开头里有多少是纯冗余」我复现不了；能给的只有 `cd <SUBST>`（`cd "$(pwd)"` 类）517 段这个子集。
5. **`<WS>` 归一只是近似**：调用中途 `cd` 到别处之后，后续段的相对路径判定会走偏（`cd <TMPPATH>` 131 段就是这种情况）。所以 `grep <PAT> <PATH>` 里的 `<PATH>` 不保证在工作区内，**「cwd 之外 0.9%」这类比例我复现不了**。
6. **「严格可被现有内置 grep 替代的 24.2%」**：要复现它得把 bash 里每次 grep 的参数面逐条与 `grep` 工具的 schema 对比，还要算 cwd 内外，需要读 `src/tools/grep.rs` 的现行参数面。本票只给了可对齐的那半边：**带 `-A`/`-B`/`-C` 1310/5657 = 23.2%**、`-l/-c/-v/-o/-i` 之一 493/5657 = 8.7%、管道位置 32.1%。

8. **PTY / 交互类几乎没有实例**：全量只有 1 个形态、5 段（`script`）。票面第 4 类判据在这批会话里基本不成立。真机走查若发生过，可能走的是浏览器/抓取类工具（`web_fetch` 228 次），不在 bash 里。

## 方法（脚本逐步做了什么）

1. **读**：遍历 `~/.local/share/heng/sessions/*/*/log.jsonl`，按 `tool_call_id` 把 `payload.ToolCallStarted`（`tool_name == "bash"` 的 `args.command`）与 `payload.ToolCallCompleted`（`output` 长度）配对；`payload.SessionStarted.cwd` 记为会话工作区。配不上 completed 的 6 次调用，结果长度按 0 记。
2. **切段**：手写一个小状态机，跟踪单/双引号、反引号、转义、注释与 heredoc；按 `&&`、`||`、`;`、换行、管道、`&` 切段。heredoc 正文整体跳过、不算段（正文后的内容另起一段）。`2>&1`、`&>`、`>&2` 这类重定向不切。
3. **分词与归一**：每段切成 word/redir；按 argv0 查「位置参数角色表」（`grep` 的第一个非选项参数是 `<PAT>`、`sed` 的是 `<SCRIPT>`……）与「取值 flag 表」（`-A`/`-m`/`--test` 吃掉下一个 token）；flag 排序后前置，子命令（`git status`、`cargo test`）紧跟 argv0；路径按 `/tmp`、`target/`、`SessionStarted.cwd`、绝对/相对归一；`python3 -c` / `-m` 后的正文记 `<PY_SRC>`；`echo "---xxx---"` 记 `<SEP>`；前导 `FOO=bar` 赋值前缀不当作 argv0。
4. **聚类**：形态 = 归一后的段骨架。段数按段累加；调用数是含该形态的调用去重计数。
5. **打标与排序**：四类结构判据 + heredoc 按形态内占比打标；成本按 argv0 规则表定档；`可省段` 按上文口径算；排序量 = `调用数 × 可省段 ÷ 成本`。
6. **交叉校验**：同时用「不切管道」的切法复现票面那串零散数字（`cd`/`echo`/`grep`/`sed` 的段级 argv0、段数、平均段数），用「全切」的切法复现 `grep+rg 5495`、管道位置 32.6%、`-l/-c/-v/-o/-i` 8.7%。两种切法都印在交叉校验节里。
7. **不落盘**：脚本只写 stdout，不建任何中间文件；一次 `python3 …` 跑完（沙箱会清跨调用的临时文件，见 [../map.md](../map.md) 的统计硬约束）。
