# bash 用法的形态底账：哪些形态值得收编

Type: research
Status: resolved
Part of: ../map.md
Blocked by: —

## 问题

这张图的[目的地](../map.md)是"按用量给内置工具扩编"，而**排序的输入还没有**：今天只有零散的
聚合数字（`grep` 5495 次里 32.6% 在管道位置、`sed -n` 2352 段、`cd` 6379 段……），
没有一份"按**命令形态**聚类的底账"。冻结项 4 已经把计数单位定成形态聚类、排序量定成
「出现次数 × 可省段数 ÷ 实现成本」，这份底账就是那条公式的三个因子。

**这是只读调研，不改任何代码。** 结论一律给可复跑的脚本与数字。

### 要产出的表

按**命令形态**聚类，一行一个形态，每行至少给：

1. **形态骨架**：把 pattern、路径、文件名、字面量归一成占位符后的样子，例如
   `cd <WS> && grep -n <PAT> <PATH> | head -<N>`。骨架要能一眼看出"这是一等工具能不能接住"。
2. **出现次数**：按调用数与段数两个口径给（一条 bash 调用里出现多次的形态要分别计数）。
3. **可省段数**：若这个形态被一等路径接住，平均能省掉几段（`cd` / `echo` / 管道这三类胶水
   是主要来源）。
4. **结构上可不可收编**，四类判据（对应冻结项 5）：
   - **读 stdin**：形态的输入来自管道上游（`cargo test 2>&1 | grep …`），任何"搜工作区文件"
     的工具都接不住；
   - **上一条命令的产物**：输入是文件系统里刚生成的临时产物（`/tmp`、`target/`）；
   - **批量文件系统写/删**（`rm -rf`、`mkdir -p`、`for f in …; do sed -i …`）；
   - **需要交互或 PTY**（真机走查、`timeout` + `script`、喂 stdin 给 TUI）。
5. **token 近似**：命令文本字符数 + 该次调用的结果字符数（用 `ToolCallCompleted` 的结果长度），
   给中位数与总量；这一列是判据里"token 下降"那一半的输入。
6. **实现成本档位**：改既有工具参数 / 开一条新工具 / 要改架构（三档，分别标 1 / 2 / 3）。

表尾给一张**排序视图**：按 `出现次数 × 可省段数 ÷ 成本档位` 从大到小，前 20 名。

### 硬要求

- **数据源**：`~/.local/share/heng/sessions/*/*/log.jsonl`，取 `ToolCallStarted`
  （`tool_name == "bash"` 的 `args.command`）与 `ToolCallCompleted`（结果长度）。
  快照日期与分母（会话数、bash 调用数）要写在产物开头。
- **脚本要能复跑**：产物是 `.scratch/tool-coverage/research/01-bash-shape-inventory.md`，
  脚本放同一个目录（`01-shape-inventory.py`），跑法写在产物里。
- **这个沙箱会清跨调用的临时文件**（`/tmp`、`/dev/shm`、仓库根部都实测发生过），
  所以脚本要**能在一条命令内跑完**；需要中间文件就写进 `.scratch/tool-coverage/research/`。
- **数字不许凭印象**：每个结论都要能由脚本复现；推断与实测分开写。
- **形态切分**：按 `&&` / `||` / `;` / 换行 / 管道切段，heredoc 正文不算段。

### 留给下游的两条

- [收编的逐条判定](05-grilling-intake-verdicts.md)：**`sed -n` 窗口读**（2329 段 / 1847 调用，

  说的「坦然留在 bash」；「需要 PTY」在这批数据里只有 1 形态 / 5 段。
- [验收口径](06-grilling-measurement.md)：脚本已经能出"调用数 / 段数 / 命令与结果字符数"三列；
  真 token 没算（只有字符近似），结果长度是**上界**（截断后模型实际看到多少判不了）。

### 读不到的（下游的硬边界，逐条在产物里）

- **`cd` 是否冗余判不了**：日志不记每次调用的实际 cwd，只有 `SessionStarted.cwd`；能给的只有
  `cd <SUBST>`（`cd "$(pwd)"` 类）517 段。→ 这条直接改了
  [workdir 必传](03-grilling-bash-workdir-required.md)的立论方式：它要拿「5673 段 `cd <WS>`」
  这个量级说话，不能说"其中 86% 是冗余"。
- 「严格可被现有内置 grep 替代的 24.2%」与「cwd 之外 0.9%」**无法复现**：前者要逐条对比
  `src/tools/grep.rs` 的现行参数面，后者受"中途 `cd` 之后相对路径判定走偏"影响。
- 成本档位是**规则判定**（`COST_BY_ARGV0` + 判据覆盖），05 票应逐条覆盖它。
- 可省段数是**上限**且**跨形态不可相加**（同一条调用里的多个形态各记一份）。
- 样本代表性：2026-10-08 / 10-09 两天占 63% 的调用，274 个会话几乎都是本机开发会话。
