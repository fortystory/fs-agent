# bash 的 workdir 必传与 cwd 反馈

Type: grilling
Status: resolved
Part of: ../map.md
Blocked by: —

## 问题

`bash` 的 `workdir` 参数 2026-10-09 随 [`../bash-workdir/spec.md`](../bash-workdir/spec.md)
落地，**可选**，spec 明文写着「`required` 仍是 `["command"]`」。实测：上线后 3175 次 bash
调用里只有 **1 次**带 `workdir`（0.01%），而那唯一一次是
`echo "传 workdir=docs/agents：$(pwd)"; ls` —— 像在验证参数本身。同期 `cd` 前缀照旧：
86.1% 的调用以 `cd` 开头，`cd` 段 6379（占全部段 23%）。

冻结项 8 定了方向：**改必传 + 结果回显 cwd + 识别 `cd` 冗余 + 不允许 `"."`**。这条票把形状定死。

### 要拍的问题

1. **`required` 的写法**：`["command", "workdir"]`？还是把 `workdir` 改成"省略即参数错误"
   但不进 `required`（两者对模型的可见差异不同）。省略时的错误文案是什么。
2. **`"."` 与非法值**：不允许 `"."`（冻结项 8）；那 `"./"`、`""`、绝对路径、
   工作区外的路径、不存在的目录分别回哪句错？
   [`bash-workdir/spec.md`](../bash-workdir/spec.md) 已定"目录必须已存在且落在工作区内"，
   这次的增量只是把"省略"和"`."`"也变成错误。
3. **结果回显 cwd 的形状**：每次 bash 结果里加一行「命令在 `<cwd>` 跑」？只在实际不在工作区根时
   加？放在结果首行还是末行？每次多这一行的 token 代价要算清楚（bash 是 7203 次调用，
   一行按 20 字符算就是 14 万字符量级）。
4. **`cd` 冗余怎么处理**：三种力度——
   (a) 只在结果里提示「这条命令里的 `cd` 已由 workdir 覆盖」；
   (b) 工具层拒绝含 `cd` 的命令（参数错误）；
   (c) 在工具描述里给一条改写法，不改行为。
   要分开对待 `cd "$(pwd)"`（472 次，纯冗余）与 `cd <子目录> && …`（有实际语义，
   但强烈暗示模型该用 `workdir`）。注意 (b) 会打断合法用法（`cd` 在管道或子 shell 里）。
5. **与 `escalation` 的既有互斥**：[`bash.rs`](../../../src/tools/bash.rs) 已定
   `workdir` 与 `escalation` 同现是参数错误（检查住在 `Tool::escalation`），必传之后这条还成不成立。
6. **描述常量 `WORKDIR_NOTE` 怎么改**：现在是「可选，这条命令在工作区内的哪个目录跑……
   用它代替在命令里写 `cd`」。必传之后要重写；`workdir` 的解析走
   `ctx.workspace_paths.resolve_within`（严格那份），语义不变。
7. **推翻记录**：`bash-workdir/spec.md` 的 `required` 明文与 `WORKDIR_NOTE` 要同步改正，
   标注推翻日期与依据（0.01% 采用率）。
8. **存量会话的代价**：参数面一改，所有存量会话的前缀缓存废一次
   （[ADR 0001](../../../docs/adr/0001-chinese-ui-frozen-model-text.md)）。这件事要不要一次做完，
   还是与 `grep` 的参数改动合并成一次发布（少废一次缓存）。

### 输入

- [`src/tools/bash.rs`](../../../src/tools/bash.rs)：参数面、`WORKDIR_NOTE`、`resolve_workdir`、
  `refuse_workdir_with_escalation`。[`docs/bash.md`](../../../docs/bash.md)：《`bash` 不包含什么》。
- [`../bash-workdir/spec.md`](../bash-workdir/spec.md)：四处不变式、§1 表下的描述纪律。
- 采纳率数据：`workdir` 1/3175；`cd` 段 6379；`cd "$(pwd)"` 472 次；
  grep 劝阻八天无效的同构先例。

### 约束

- 票内不得重开冻结项 8 的四条方向；只定形状与力度。
- 答案要自足，附上要改的确切行（`bash.rs` 的哪几处、`bash-workdir/spec.md` 的哪一行）。

## 作答

五问拍板。**其中一条撤掉了 charting 冻结项 8 的半个字**（"不允许 `.`"），另一条发现既有规则
在必传之后会打死每一次升级调用。

### 1. schema：必填，且**允许 `"."` 表示工作区根**（Q1 = c）

- `required` 从 `["command"]` 改成 **`["command", "workdir"]`**。
- `workdir` 接受：工作区内一个**已存在**的目录；相对路径按工作区解析（
  [`resolve_workdir`](../../../src/tools/bash.rs#L229-L251) 的既有语义不动）。
- **允许 `"."`**：它就是工作区根。charting 时那条"不允许 `.`"撤回 —— 它的意图（防止模型
  敷衍填一个值就等于没强制力）成立，但它忽略了"根"必须有个写法，而空字符串 / 绝对路径 /
  哨兵值都比 `.` 更差。强制力来自**字段必填**（模型每次必须显式声明站位），不是来自禁用根。
- 参数错误（沿用既有的"半截写法不静默忽略"风格）：
  - 省略：`bash：`workdir` 是必填的 —— 它是这条命令的站位，要工作区内一个已存在的目录（根写 \`.\`）`
  - 不存在 / 落在工作区外 / 空字符串：沿用 `resolve_within` 那套既有文案（它已经区分"区外"与"不存在"）。
  - 句尾那个 `(根写 .)` 是刻意的：不写这一句，模型会猜根该怎么表达。
- **成本如实记**：每次调用多一个必填字段（模型输出侧约 15–25 token），外加一次所有存量会话的
  前缀缓存作废（与 [grep 的上下文参数](02-grilling-grep-context.md) 合并成一次发布，见第 6 节）。

### 2. 结果回显 cwd：每次首行一行（Q2 = a）

- `bash` 的结果第一行固定为 **`cwd: <相对工作区的路径>`**（根写作 `.`），其余报告（退出码、
  stdout、stderr）一个字不动。
- **无条件**，不只在非根时加：`cd "$(pwd)"` 出现 517 段，痛点恰恰是"不确定自己站在哪"，
  而填根的时候最需要的正是这一行确认。
- 代价约 20 字符/次（7703 次调用 ≈ 15 万字符总量），相对 bash 结果本身的中位长度可接受。

### 3. `cd` 冗余：只改描述，不加提示也不拒绝（Q3 = a）

- `WORKDIR_NOTE` 里保留"用它代替在命令里写 `cd`"这句。
- **不做工具层拒绝**：`cd` 在命令里并非总是冗余（切到 `/tmp`、子 shell、`for` 循环里都合法），
  而提示会变成高频噪声（含 `cd` 的命令占 85%）。提示类干预的实证是负面的（`grep` 劝阻八天无效）。
- "`cd` 段有没有降"交给[验收口径](06-grilling-measurement.md)量。

### 4. 取消 `workdir` 与 `escalation` 的互斥（Q4 = a）

必传之后这两个字段**永远同现**，今天那条规则
（[`bash.rs:136-139`](../../../src/tools/bash.rs#L136-L139) 调
`refuse_workdir_with_escalation`，实现体 `:213-227`）会打死每一次升级调用。

- **删掉这条互斥**：`Tool::escalation` 里那次调用与 `refuse_workdir_with_escalation` 函数一并移除，
  相应测试删或改。
- 理由：它的原意图是"混起来等于让模型自选工作区"，而 `workdir` 现在必填且严格解析在工作区内，
  这个风险不再存在。

### 5. `WORKDIR_NOTE` 重写（常量，进前缀、一次定死）

现在是「**可选**，这条命令在工作区内的哪个目录跑；相对路径按工作区解析，目录必须已存在且落在
工作区内。用它代替在命令里写 `cd`；只影响这一条命令的进程，不改变其他工具解析相对路径的基准。」
改成：

> **必填**，这条命令在工作区内的哪个目录跑（**根写 `.`**）；相对路径按工作区解析，目录必须已存在
> 且落在工作区内。用它代替在命令里写 `cd`；只影响这一条命令的进程，不改变其他工具解析相对路径的基准。

### 6. 发布节奏：与 grep 的参数改动**合并成一次发布**（Q5 = a）

- 两处都在改工具声明，合并可以少作废一次前缀缓存（
  [ADR 0001](../../../docs/adr/0001-chinese-ui-frozen-model-text.md)）。
- 落地次序写进 spec 的交付说明（**不加依赖边**：02 与 03 是并列的两处参数改动，
  只是同批发布）。

### 7. 要同步改的既有文本

- [`../bash-workdir/spec.md`](../bash-workdir/spec.md) 第 30 行：`required` 仍是 `["command"]`
  → 改成 `["command", "workdir"]`，并加一行推翻记录与依据（上线后 3175 次调用里只有 1 次带它，
  [形态底账](../research/01-shape-inventory.md) 复现了这个 1）。
- 同 spec §2 的"`workdir` 与 `escalation` 同现也是参数错误"→ 标记为已取消。
- [`docs/bash.md`](../../../docs/bash.md)：参数面若列了 `workdir`，同步成必填 + 允许 `.`。
- **立论口径**：这张票的动机要拿「`cd <WS>` 5673 段 / 5604 调用」这个量级说话 ——
  [形态底账](../research/01-shape-inventory.md) 证明了"`cd` 冗余率"判不了（日志只记
  `SessionStarted.cwd`），不许写"其中 86% 是冗余"。

### 8. 留给实现的两处确认

- `resolve_workdir` 今天对 `"."` 的处理应能解析成工作区根（相对路径 join），实现时确认它不报错。
- `process::run(ctx.cwd, standing, …)` 的两段语义不动：站位给 `standing`、边界给 `ctx.cwd`。

- 没有新浮现的票。05 / 06 不受影响。
