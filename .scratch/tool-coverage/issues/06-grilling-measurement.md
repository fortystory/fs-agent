# 验收口径：怎么量调用数、段数与 token

Type: grilling
Status: resolved
Part of: ../map.md
Blocked by: 01

## 问题

冻结项 2 把判据定成「bash 调用数与段数下降（主）、token 下降（辅）」，并要求可复跑。
但**口径没有定**，于是"改动变好了"今天不可证。这条票把量度、样本与阈值定死，
让 [形态底账](01-research-bash-shape-inventory.md) 的脚本能直接长出验收表。

### 要拍的问题

1. **三个量各自怎么算**：
   - *调用数*：`ToolCallStarted.bash` 的计数，分母是"全部工具调用"（今天 61.3%）还是"每会话"？
   - *段数*：按 `&&` / `||` / `;` / 换行 / 管道切段（与[形态底账](01-research-bash-shape-inventory.md)同一套切法），
     胶水段（`cd`/`echo`/`for`/`do`/`done`）要不要单列。
   - *token*：三种口径选一——(a) 工具结果字符数（`ToolCallCompleted` 的文本长度，最直接、
     但只是近似）；(b) 会话的 `UsageRecorded`（受模型行为影响，噪声大）；
   (c) provider 请求的 input token 增量（要动 provider 侧，成本高）。**主判据是前两个，
      token 只作辅**，可以就用 (a)。
2. **对比窗口**：改动前的历史快照 vs 改动后的新会话。今天的样本是 269 个会话 / 7703 次调用，
   而 bash 集中在少数会话（96 个会话有 bash，173 个一条没有；单会话最多 1318 条）。
   要不要限定"每会话 ≥ N 次 bash"的样本，避免均值被长尾带偏。
3. **样本量与噪声**：单会话噪声大。要不要定一个最小样本（例如改动后累计 ≥ 20 个含 bash 的
   会话）才判定"变好/变坏"。
4. **反例与冲突**：若调用数降了但 token 升（比如工具返回更啰嗦的上下文），怎么判胜负。
5. **统计脚本的落点与复用**：是复用 `.scratch/tool-coverage/research/01-shape-inventory.py`，
   还是另写一份验收脚本；跑法要一行命令可复现（沙箱会清跨调用的临时文件）。
6. **基线存档**：改动前的数字要不要以文件形式钉在 `.scratch/tool-coverage/research/` 里，
   作为"改动后对比"的唯一的锚。

### 输入

- [形态底账](01-research-bash-shape-inventory.md) 的脚本与表（本票的输入）。
- [地图](../map.md) 笔记里的基线数字（快照 2026-10-10）。
- 采纳率的两个历史先例（`grep` 八天不降、`workdir` 0.01%）——它们是"没有量度就看不出改没改"
  的实证，可以作为"为什么值得花一条票定口径"的理由。

### 约束

- 票内不得重开冻结项 2 的判据本身；只定量度与样本。
- 结论要能直接写成一句可执行的命令（`python3 …`），不能停在"用一个脚本统计"。

## 作答

四问拍板，并且**当场把口径落成可跑的东西**（脚本加了 `--since`、基线已存档）。

### 1. 三个量都报，主判据是三个

| 量 | 算法 | 角色 |
| --- | --- | --- |
| bash 调用数 | **含 bash 的会话里，每会话 bash 调用数的中位数** | 主 |
| 段数 | **不切管道**切法（与历史数字可比）；全切切法另报 | 主 |
| token 近似 | 命令字符数 + 结果字符数的**中位数**（结果长度是**上界**） | 主，明确标注"字符数近似" |
| bash 占全部工具调用的比例 | 今天 61.3% | 辅 |

**不去碰 `UsageRecorded`**：它带 `speaker`、受模型行为影响，分不清"工具省下的"与"模型少说了"。

### 2. 对比窗口与样本

- **基线钉成文件**：[`research/06-baseline-2026-10-10.txt`](../research/06-baseline-2026-10-10.txt)
  （284 行，今天全量：274 个会话 / 7703 次 bash 调用 / 35809 段全切）。**存档之后不再重跑** ——
  全量口径会随新会话变化，那不是基线。
- **改动后**：只看**发布日（含）之后**的会话，累计 **≥ 20 个含 bash 的会话**再判。
- 样本偏差如实记：274 个会话里 **173 个一条 bash 都没有**；2026-10-08/09 两天占 63% 的调用。
  所以用**中位数**（单会话最多 1318 条，均值会被长尾带偏）。

### 3. 冲突判据：记为「待观察」，不阻塞（Q3 = b）

调用数与段数是主判据，token 是观察项。主判据降、而结果字符数中位数升 **超过 10%** 时，才要求
单独解释 —— 例如 `grep` 引入上下文行之后结果本来就会变长，那是[买来的东西](02-grilling-grep-context.md)，
不是回退。

### 4. 脚本与基线：已经落地（Q4 = a）

- 给 [`research/01-shape-inventory.py`](../research/01-shape-inventory.py) 加 `--since YYYY-MM-DD`：
  一个 `SINCE` 全局、`session_day` / `session_files` 两个函数、两处 `glob` 换成 `session_files()`、
  `main` 解析参数并在报告头多打一行"窗口"。**默认行为一字未变**，所以 01 报告 md 里那份
  stdout 抄录不需要重抄（已验证：全量仍是 274 会话 / 7703 调用）。
- 过滤按**会话目录名的 UTC 日期**（`20261009T151952Z-…` 的前八位）。发布日本地时间与 UTC 差 8 小时，
  判"≥ 20 个会话"时以 UTC 日为准，对比时写明。
- **验收就一条命令**：

```bash
python3 .scratch/tool-coverage/research/01-shape-inventory.py --since <发布日> --top 120
```

把它与 [`06-baseline-2026-10-10.txt`](../research/06-baseline-2026-10-10.txt) 并排看即可。
