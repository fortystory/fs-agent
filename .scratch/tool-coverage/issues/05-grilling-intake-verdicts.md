# 收编的逐条判定：文件目录、命令结果、窗口读

Type: grilling
Status: resolved
Part of: ../map.md
Blocked by: 01

## 问题

[形态底账](01-research-bash-shape-inventory.md) 给出"按形态聚类的出现次数 × 可省段数 ÷ 实现成本"
之后，这条票拿那张表**逐条判定**：做 / 变形做 / 不做。这是冻结项 3（整体重扫）的落点，
也是四条提名里"文件目录操作工具"与 fog 里几条的归宿。

判据用冻结项 5 的收敛口径：**只收编「高频 + 高胶水 + 参数补不动」的形态**；结构上不该收编的
（读 stdin、上一条命令的产物、批量文件系统写、需要 PTY）要**明说留着**，不要为了"消灭 bash"
硬做。

### 至少要判的候选

1. **文件目录操作**（四条提名之一）：`ls` 728 段、`wc` 191、`find` 104、`mkdir` 78、
   `rm` 27、`du`、`realpath`、`tree`。注意它们各自的**性质不同**：`ls`/`find` 是读，
   `mkdir`/`rm`/`mv` 是写（要付 `WritePaths` 与权限语义），`wc` 是纯计数。
   这一条最可能被判"变形做"或"不做"——数据里每一项都不到 2%，而"文件系统操作"作为一个
   类别又是典型该有一等工具的（对照上游：Claude Code 的 `Glob`、Gemini 的 `list_directory`）。
   要给出结论与理由，不要悬着。
2. **命令结果工具**（管道 grep 的正解）：`cargo test 2>&1 | grep -E "^error|FAILED"` 这类
   占管道 grep 的大头（pattern top：`^error` 189、`FAILED` 160、`^test result` 161、
   `^warning` 146）。候选做法：一条 `test` / `run` 工具直接给结构化成败与失败项；
   或者只给"跑命令 + 过滤输出"的通用形状。若结论够大，在本票里**升级成新票**，不在本票定形状。
3. **窗口读**：`sed -n '405,500p' file` 2352 段，而 `read_file` 早就有 `offset`/`limit`
   —— 这是"工具存在但模型不用"，与 `workdir` 0.01%、`grep` 劝阻八天无效同族。
   要判：改 `read_file` 的描述/形状？还是接受它只覆盖"整文件"？
4. **就地改写与写文件**：`sed -i`、python heredoc 写文件（`open(...,'w')`）、
   `cat >> tests/x.rs <<'RUST'` 追加用例。这一族要判"该不该有工具"，还是它本来
   就不该被收编（`edit_file` / `write_file` 已存在，模型仍手搓那一半）。
5. **会话日志挖掘**：`~/.local/share/heng/sessions` 的 jsonl 分析（52 次）；
   它是开发期行为还是常态工作流。
6. **真机走查**：`pty.fork` 抓帧、`--plain` 喂输入、`timeout` 跑 TUI。
   大概率判"不做"（需要 PTY，冻结项 5 的第四类），但要写下理由。
7. **`curl` / 依赖安装**：104 段 `curl`，`pip` / `npm` / `cargo install` 少量。
   已有 `web_fetch`，判"不做"或"补 `web_fetch` 的能力"。

### 每条判定要给的列

- **结论**：做 / 变形做 / 不做（"不做"也要有结论，不许悬着）。
- **理由**：带 [形态底账](01-research-bash-shape-inventory.md) 的数字（次数、可省段数、成本档位）。
- **落点**：若"做"，是改既有工具的参数/描述（冻结项 6 优先）还是开新工具；
  若是新工具，写清它接住哪一类、`effect()` 取哪一档。
- **升级**：足够大、形状还不清的，升级成新票并写进本图的任务清单。

## 作答

八类候选逐条判定：**做 1 条**（文件枚举，已升级成第 7 张票），**不做 7 条**。另覆盖了
[形态底账](01-research-bash-shape-inventory.md) 里"成本档位是规则判定、05 票应逐条覆盖"那句。

### 判定表

| # | 候选 | 数据（段数 / 调用） | 判定 | 理由 |
| --- | --- | --- | --- | --- |
| 1 | 窗口读（`sed -n` / `head -N <PATH>` / `tail -N <PATH>`） | 2627 | **不做工具** | `read_file` 早有 `offset`/`limit`、默认 2000 行 —— 能力不缺，缺的是采纳。**01 把它判成成本档 1（"改参数"）不成立：没有参数可加**。只改描述 |
| 2 | 命令输出过滤（stdin 类 177 形态） | 8558 | **不做** | 工具层只有两条路：泛化的"第二条 bash"（权限代价与 `bash` 相同，而劝阻无效的实证说明模型没有理由换），或 cargo 专用（窄到接不住 `git diff \| grep`、`clippy \| grep`）。冻结项 5 已点名这一类留在 bash |
| 3 | 文件枚举（`ls` / `find` / `tree`） | 832+ | **做** | 只读、零权限成本、上游四家标配（Claude Code `Glob` / Gemini `list_directory` / opencode `glob`）；升级成 [文件枚举工具](07-grilling-file-enumeration.md) |
| 4 | 写文件与就地改写（`cat >> <<H` / `sed -i` / `printf >>`，write 类合计） | 634 | **不做** | `edit_file` / `write_file` 已经覆盖；根因"模型为什么不用它"在 01 里明确**读不到**（日志没有逐次请求的工具 schema），不开猜测性工具 |
| 5 | `python3 << HEREDOC` | 1135 / 1090 | **不做** | 等于第二条 bash（01 的成本档 3 成立） |
| 6 | 会话日志挖掘（`~/.local/share/heng/sessions` 的 jsonl） | 52 | **不做** | 开发期行为，不是常态工作流 |
| 7 | `curl` | 67–104 | **不做** | 已有 `web_fetch` |
| 8 | PTY / 真机走查（`script`、`pty.fork`） | 5（1 形态） | **不做** | 这批数据里几乎不存在（01 的"读不到的" #8）；01 的第四类判据在本批数据里不成立 |

**写侧单列**：`mkdir` 78 / `rm` 27 / `mv` / `cp` —— 判不做。合计百来段，却要把 `WritePaths`
与权限语义再走一遍，不划算。

### 一条条件项（进 map 的「尚未明确」）

#2 的裁定是"**先不做，等使用一段时间后再判断是否添加一条泛化的 `run(command, filter)`**"。
它既不是 live 票（现在不做），也不是范围之外（在 scope 内，只是没有数据支撑决定）——
所以进 map 的「尚未明确」，并写明触发条件（累积一段时间的采纳数据之后重判）。

### 覆盖 01 的规则判定

- **窗口读**判成档 1（改参数）——**不成立**：`read_file` 没有参数可加，实际是"零改动、只改描述"。
- **`ls` / `find`** 判成档 1 / 2 —— 档 1 不成立（`grep` 与 `read_file` 都接不住枚举），
  但"开新工具"这个结论成立，档 2 对。
- **`python3 << HEREDOC`** 档 3 —— 成立（改变的是执行模型本身）。

### 「不做」清单的去向

#2 / #4 / #5 / #6 / #7 / #8 与写侧的结论**连理由整段进 spec 的「不做」一节**——
destination 要求"逐条定做/不做，不做的也要有结论"。
#1 另带一条动作：改 [`read_file`](../../../src/tools/file.rs) 的描述（加一句"要看某一段就带
`offset`/`limit`"），与 [02](02-grilling-grep-context.md) 那批描述改动同批落地。

### 与别的票的关系

- 新工具照抄 [02](02-grilling-grep-context.md) 那套惯例：输出按路径有序、上限 + 末尾一句
  可操作的收尾、溢出走既有截断流水线。
- 与 [04 git 工具](04-grilling-git-tool.md) 无耦合（一个跑子进程、一个读工作区文件）。

  与 `grep` 同例。
