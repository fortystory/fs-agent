## 目标

模型带 `after` / `before` 发一次搜索，输出里就出现上下文行与命中块的分隔：命中行与陪衬行分得清、
行号是真行号、相邻命中的上下文合并成一块；上限口径改成"列出的行"，`count` 与两个新参数各走各的。

**可 demo**：对工作区发一次带 `after: 3` 的搜索，输出能直接贴给人看。

## 现状（改前先复核）

- 内建搜索工具今天只有 `pattern` / `glob` / `count`，输出只有 `path:line:文本` 一种行形状。
- 早期的工具 spec 把上下文开关写进了《明确不做》（"用 pattern 的内联语法或多次调用解决"）——
  实测八天里 bash 内的 `-A`/`-B` 有 1105 次，那条替代方案没有被采用。
- 上限常量今天收的是"要列出来的行"；加上下文行之后这个口径必须重新钉死。

## 验收

- [x] `after` / `before` 是非负整数；负数与非法类型是参数错误
- [x] 命中行 `path:line:文本`、上下文行 `path-line-文本`（真实行号）、命中块之间一行 `--`
- [x] 相邻命中的上下文区间重叠时**合并成一块**（同一段正文不出现两遍）
- [x] 上限 = 命中行 + 上下文行的**合计**；末尾那句数的是**未列出的命中行数**
- [x] `count: true` 与 `after`/`before` 同给时忽略后者
- [x] 溢出仍走既有的截断流水线（落盘 + 头尾预览 + 指针），没有第二套截断
- [x] 工具描述改成正向用法说明（保留一句短的劝阻）
- [x] `docs/grep.md` 的参数表 / 输出形状 / 上限语义 / 计数互斥同步
- [x] 早期工具 spec 那条《明确不做》改成"已推翻"并附实测依据
- [x] 扩展既有搜索工具测试：形状、合并、合计口径、`count` 忽略、负数报错
