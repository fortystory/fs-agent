# 四分区全屏 TUI：布局、多行输入与信息面板

Status: ready-for-agent

- **来源**：`.scratch/tui-layout/map.md`（wayfinder 地图，9 张决策票全部 `resolved`）。本 spec 是那张图的**折叠**，不是新决定 —— 唯一例外见 `Further Notes`。
- **实现票落点**：`.scratch/tui-layout/issues/NN-*.md`，**编号从 `10` 起**（`01`–`09` 是设计票，不要覆盖）。
- **推翻的既有决策**：本 spec 推翻 `.scratch/fs-agent-v1/spec.md` §19 的 TUI 栈一行（`.scratch/fs-agent-v1/spec.md:526`）与用户故事 129 的「否决 alt screen」。记录在 **`docs/adr/0002-fullscreen-alt-screen-tui.md`**。
- **术语**：叙述用中文，标识符用英文。词汇表在 `CONTEXT.md` —— 特别注意 **轮次（Round）≠ 回合（Turn）**：右栏数 `TurnEnded`，标签是**「回合」**。

## Problem Statement

1. **光标是坏的，而且修不好。** inline viewport 下光标不跟随 `>`、`>` 还会在后续回合消失。`e25097e` 把视口锚到最后一行之后**问题仍然存在**：根因是视口位置本身随插入漂移（`Frame::area().y` 是视口在屏幕上的位置，`insert_before` 每插一行就把它往下推）。
2. **转录不可控。** 回看完全依赖终端 scrollback：应用内没有滚动缓冲、没有位置感、无法在窄终端里定位；live 区只有 8 行，一次工具输出就把它冲掉。
3. **关键信息会滚走。** 模型名、模式、token、上下文用量挤在启动 banner 一行里，滚上去就看不见了。
4. **输入只能单行。** 粘一段代码、写多段 brief 都得挤成一行，斜杠命令后面跟多行任务也做不到。
5. **摘要视图回看价值低。** 现在**用户自己输入的消息**被压成单行 + 截断 500 字符（assistant 的回答本来就是全文 Markdown）；粘 20 行进来只留前 500 字。

## Solution

把 TUI 从「inline 视口 + 往 scrollback 插行」换成**全屏 alt screen 四分区**：

- **上 = 基础信息**：名称+版本 / cwd / 模式 / 时钟。
- **中左 = 对话面板**：自己持有滚动缓冲（上限 20 000 **源行**，超出丢最旧），吸底但用户上滚后不抢，右缘恒留 1 列滚动条，脱离吸底时底部右缘显示可点击的「↓ N 行新内容 · 点此到底」。
- **中右 = 信息面板**：模型 / 上下文用量 / token（已用+上限、输入/输出、缓存）/ 回合；静态事实组装期注入，动态数字从事件流推。
- **下 = 输入区 + 快捷键提示行**：输入区随内容长高（1–10 行）；提示行最左是状态词，其后六条快捷键。

配套三件事：**多行输入编辑器**（Enter 提交 / Ctrl-J 换行 / 粘贴多行不提交 / 两个确认）、**模态覆盖层**（权限、计划冲突、超长粘贴、Esc 清空草稿四种问题共用）、**删除 inline 路径**（`insert_before` 循环 / `paint_scrollback` / `Viewport::Inline` / 底部 `MoveTo` 锚定）。

不动的：plain 与 headless 两个渲染器、语法高亮与 diff 着色、Markdown 渲染器、ADR 0001 冻结的模型可见文本。

## User Stories

### A. 布局与基础信息

1. 作为用户，我想在终端里看到一块固定的基础信息区（名称+版本 / cwd / 模式 / 时钟），以便随时知道自己在哪个项目、什么模式、几点。
2. 作为用户，我想让对话面板与信息面板并排，以便读回答时不用滚动就能看到 token 与上下文用量。
3. 作为用户，我想让输入区固定在底部，以便任何时候都能开始打字。
4. 作为用户，我想让输入区随内容长高（最多 10 行），以便写多段 prompt 时看得见全貌。
5. 作为用户，我想让输入区的续行缩进 2 格，以便一眼看出多行属于同一次输入。
6. 作为用户，我想让四个区域各自带边框、header 底边充当分隔横线，以便结构清楚而不重复画线。
7. 作为用户，我想在 header 与中段之间、输入区上方各留一行空白（airy），以便界面不挤。
8. 作为用户，我想让单行 header 里的字段用 ` · ` 分隔，以便与既有 banner 文案一致。

### B. 转录回看与滚动

9. 作为用户，我想让对话面板自己保存历史（上限 20 000 源行，超出丢最旧），以便不依赖终端 scrollback。
10. 作为用户，我想让新内容到达时视口自动跟随（吸底），以便不必手动往下滚。
11. 作为用户，我想在往上滚之后视口**不被抢走**，以便安静地读一段旧输出。
12. 作为用户，我想用 `PgUp` / `PgDn` 翻页（整页减 2 行重叠），以便长输出里不迷失。
13. 作为用户，我想用 `Ctrl-G` 一次回到底部，以便上滚后快速回位。
14. 作为用户，我想用滚轮滚转录（每格 3 行），以便用最自然的手势翻。
15. 作为用户，我想在脱离吸底时看到 `↓ N 行新内容 · 点此到底`，以便知道有新东西进来。
16. 作为用户，我想用鼠标点那一块就能回到底部，以便不用记键位。
17. 作为用户，我想在转录右缘看到滚动条，以便知道自己在哪儿、还有多少。
18. 作为用户，我想让滚动条的位置不因出现/消失而改变转录宽度，以便阅读时不跳。
19. 作为用户，我想让命令提交后视口无条件回到底部，以便立刻看到回答开始。
20. 作为用户，我想在拖动窗口改变大小后仍停在原来那段内容上，以便不被重排甩走。
21. 作为用户，我想看到**我输入的消息全文**（保留换行、不截断），以便回看我到底问了什么。
22. 作为用户，我想让回答仍然是全文 Markdown，以便标题、列表、代码块照旧可读。
23. 作为用户，我想让工具输出保持 4 000 字符 preview，以便一个读文件调用不会吃掉整块缓冲。

### C. 多行输入

24. 作为用户，我想用 `Enter` 提交、用 `Ctrl-J` 换行，以便在一个输入框里写多行。
25. 作为用户，我想让 `↑` / `↓` 只在缓冲内移动光标，以便多行编辑符合直觉。
26. 作为用户，我想让 `Ctrl-P` / `Ctrl-N` 专门取历史，以便历史入口不模糊。
27. 作为用户，我想让 `Home` / `End` / `Ctrl-A` / `Ctrl-E` 作用于**当前行**，以便 readline 肌肉记忆还能用。
28. 作为用户，我想让 `Ctrl-U` / `Ctrl-K` / `Ctrl-W` 也作用于当前行，以便多行下不会一口气删光。
29. 作为用户，我想让 `←` / `→` 跨行移动，以便把光标当在文本域里用。
30. 作为用户，我想让 `Backspace` / `Delete` 在行首/行尾合并两行，以便像普通编辑器一样删换行。
31. 作为用户，我想让 `↑` / `↓` 记住想要的视觉列，以便在长短行之间上下移动不跑偏。
32. 作为用户，我想粘贴多行文本时**不自动提交**，以便贴完还能改。
33. 作为用户，我想让粘贴里的 `\r\n` 归一成 `\n`、控制字符被清掉，以便粘进来的东西是干净的。
34. 作为用户，我想在一次粘贴超过 100 000 字符时先被问一句，以便误粘一个巨大文件不会卡住界面。
35. 作为用户，我想在输入了多行草稿时按 `Esc` 先被问一次，以便误按不会丢掉已经写好的东西。
36. 作为用户，我想在单行输入时 `Esc` 仍然直接清空，以便快速重打。
37. 作为用户，我想让提交只去掉首尾空白、中间换行保留，以便多段 prompt 的结构不被破坏。
38. 作为用户，我想让多行输入作为**一条** user message 进入会话，以便模型看到的是一段完整的话。
39. 作为用户，我想让斜杠命令只看第一行，以便 `/ask-matt` 后面能跟多行任务。
40. 作为用户，我想让粘贴一段以 `/` 开头的多行代码不被误判成命令，以便贴代码不会撞上 unknown command。
41. 作为用户，我想让输入历史保持进程内，以便不引入额外的存储与隐私面。

### D. 询问与确认

42. 作为用户，我想让权限询问以模态覆盖层出现，以便不会漏看一个要放行的写入。
43. 作为用户，我想让模态覆盖层压住对话面板，以便视觉上明确「现在要回答这个」。
44. 作为用户，我想让 `Esc` 在模态上等于「选安全的那个」（权限 = 拒绝、粘贴与清空 = 否），以便误按不会造成危险。
45. 作为用户，我想让权限询问同时留在转录里一条可回看的记录，以便事后复盘。
46. 作为用户，我想在模态出现时输入区不被误用，以便不会把回答打成 prompt。

### E. 降级与终端

47. 作为用户，我想在窄终端（宽度 < 80）自动隐藏右栏，以便对话面板拿到全部宽度。
48. 作为用户，我想在更窄的终端（宽度 < 60）把 header 压成一行，以便信息让位给内容。
49. 作为用户，我想让隐藏右栏**先于**压 header 发生，以便降级顺序永远一致。
50. 作为用户，我想在宽度不足 40 或高度不足 10 时只看到一句「终端太小：至少 40×10」，以便知道是尺寸问题而不是崩溃。
51. 作为用户，我想让 40×10 仍然渲染完整降级布局（1 行 header + 1 行转录 + 1 行输入 + 1 行提示），以便极窄终端也还能用。
52. 作为用户，我想让 airy 留白在高度 ≤ 11 时自动让位，以便最小尺寸下先保功能。
53. 作为用户，我想让快捷键提示行按宽度丢条目、但 `ctrl-c 退出` 永远在，以便任何宽度下都找得到出口。
54. 作为用户，我想让提示行**不出现** `shift+enter 换行`，以便不被一个实际会提交的键骗到。
55. 作为用户，我想在退出后终端恢复原状（无 raw mode 残留、鼠标选择恢复原生、alt screen 不留屏），以便退出后还能正常用终端。
56. 作为用户，我想在 TUI 崩溃（panic）时终端也被恢复，以便不用敲 `reset`。
57. 作为用户，我想让 plain / headless 模式完全不受这次改动影响，以便管道化照旧可用。

### F. 不变量

58. 作为用户，我想让所有人类可见文案仍然只由措辞层产生，以便界面改版不会把字符串散进渲染代码。
59. 作为用户，我想让模型可见文本（system prompt、投影前缀、`AgentError.message`、工具结果）**一个字节都不变**，以便前缀缓存不被废掉。
60. 作为用户，我想让 `cargo test` 全绿、`cargo clippy` 干净、`cargo fmt --check` 只留既有的两处漂移，以便改动可验收。

## Implementation Decisions

### §1 全屏与终端生命周期

- 用 **`ratatui::init()`**，不用 `init_with_options`：前者做 raw mode + `EnterAlternateScreen`（`CSI ?1049h`）+ panic hook（先 `restore()` 再调原 hook），后者**不进 alt screen**。`Viewport::Fullscreen` 是 `TerminalOptions` 的默认值，所以不必再传 options。
- **鼠标捕获与 bracketed paste 是我们自己开的**（`TerminalOptions` 连鼠标开关都没有）：进入时 `EnableMouseCapture` + `EnableBracketedPaste`，退出时**成对撤销**。
- **三条退出路径都要撤销**：`/quit`、空闲 `Ctrl-C`、panic。ratatui 的 panic hook 只 restore 终端面，不管鼠标与 paste，所以要再装一层 hook 自己关。
- **不 dump 转录**（退出 alt screen 即清；完整记录在会话日志，`--continue` 可回）。
- **删除 inline 路径**：底部锚定 `MoveTo(0, rows - 1)`、`insert_before` 插入循环、`paint_scrollback`（含 `src/render/mod.rs` 的再导出）、`Viewport::Inline(LIVE_HEIGHT)`、`LIVE_HEIGHT` / `LIVE_ROWS` 常量、每帧 `hide_cursor()`。注意 `Terminal::insert_before` 这个 **API 本身仍在**（对 Fullscreen 是 no-op），删的是用法。

### §2 四分区几何与降级阶梯

> **本节的数字已按 `.scratch/tui-ux/` 的实现回改**：airy 整体删除，Mark header 阈值
> 降到 18，Mark 内部间距对调。改后的实测表在
> `.scratch/tui-ux/prototype/geometry/geometry-table.md`（「新」列），本节与它一致。

四区各带 1 行 `Block` 边框；**header 的底边框就是那条分隔横线**（不要重复画）；中左与中右相邻、两框**共用接缝 1 列**，两端补 `┬` / `┴`；**没有 airy**（块与块之间不留空行）；右栏宽度 `clamp(⌊26%·w⌋, 25, 31)`（外框含边框）。

固定 chrome = **7 行**：`h = header 内容行 + 中段内容行 + 输入区行 + 7`。

**逐尺寸（空草稿）**：

| 40×10 | 1 | 1 | 40×3 / 38×1 | 隐藏 | 1 |

| 42×18 | 7 | 3 | 42×5 / 40×3 | 隐藏 | 1 |
| 60×24 | 7 | 9 | 60×11 / 58×9 | 隐藏 | 1 |
| 80×13 | 2 | 3 | 80×5 / 78×3 | 隐藏 | 1 |
| 80×14 | 2 | 4 | 80×6 / 54×4 | 25×6 / 23×4 | 1 |
| 80×16 | 2 | 6 | 80×8 / 54×6 | 25×8 / 23×6 | 1 |
| 80×24 | 7 | 9 | 80×11 / 54×9 | 25×11 / 23×9 | 1 |

（转录的「内容」列是**文本列**：外框减 2，再减掉为滚动条永久保留的 1 列。）

**降级阶梯（顺序固定：先隐藏右栏，再压 header）**：

1. `w < 40 或 h < 10` → 只显示「终端太小：至少 40×10」。
2. `w < 80 或 中段内容行 < 4` → **隐藏整个右栏**。
3. **右栏能出现的最小尺寸是 80×14**（中段内容 4 行，只放得下四个核心字段）。
4. 右栏内容宽 < 29（`w < 120`）→ 丢掉上下文用量的 `（6%）` 百分比，保留数值。
5. 右栏行数不足 → **先丢缓存明细，再丢输入/输出**（核心四字段永不栏内丢失）。
6. `w < 60` → header 压成 1 行（丢 cwd，只留 `HH:MM`）。**`h == 10` 时也压 1 行**。
7. **Mark header 从 `w ≥ 42 且 h ≥ 18` 出现**（`LOGO_MIN_HEIGHT = 18`），低于这个尺寸
   是文字顶栏；`h ≤ 11` 的 airy 一档已随 airy 删除。

**最反直觉的一条**：`120×24` 下输入草稿涨到 **9 行**（上限）时，中段只剩 1 行 → **右栏
整栏消失**（`max_input_rows` 也涨到 9，多出的是删 airy 的 2 行）。

**header 内容**：名称+版本 / cwd / 模式 / 时钟（`YYYY-MM-DD HH:MM`，本地时区，粒度分钟）；
**单行 header 的时钟退化成 `HH:MM`**，字段用 ` · ` 分隔。
**Mark 间距**：logo 5 行 + **空 1 行** + 信息 1 行，净高仍 7 —— 空行在 logo 与信息之间，
不在信息之下。
**输入区行数**：`clamp(草稿折行数, 1, min(10, h − 7 − header内容行))`，超出显示尾部（光标行始终可见）。
**底部块**：最后一行是提示行（内宽 = `w − 2`），提示行**不是**独立区域，而是底部块的最后一行内容。

数字来源：`.scratch/tui-ux/prototype/geometry/`（`geometry-table.md` 与 `geometry-*.txt`，
全部是 `TestBackend` 实测像素）。

### §3 对话面板：行缓冲与换行缓存

- 面板持有的是**源行**缓冲：`Block` 展开成未换行的行。**20 000 的上限按源行算**（宽度无关，可复现）；滚动与滚动条另按**显示行**算。
- 缓存 = 全量换行后的 `Vec<Line>` + **源行 → 显示行起点**索引。
- **换行口径**：逐字符、一个 CJK 字符 2 列，把带样式的行切开并保留每个 span 的样式（`pane::wrap_line`）。**不用** `Paragraph::line_count`（默认特性下被 unstable 门挡成 `pub(crate)`），**也不开** `unstable-rendered-line-info`。列宽的算术集中在 `src/render/width.rs`（`text_columns` / `char_columns` / `truncate_columns`），转录、header、输入行与指示块共用同一份 —— 已有的 `wrap_take` 只服务无样式字符串，随票 11 删除。
- **失效**：宽度变化（全量重算）与流式增量（只重算尾部）。新块到达**只增量换行尾部**并追加索引。
- 缓存**在 `draw` 闭包里按 `frame.area().width` 失效**（不设单独的 resize 分支）。
- **非 assistant 的消息不再截断**：现在那一支压成单行 + `truncate(text, 500)`，改成**保留换行的多行原样渲染**（不做 Markdown），续行按 speaker 前缀显示宽度缩进。**assistant 的消息本来就是全文 Markdown，不动。**
- 工具输出保持 4 000 字符 preview（`TOOL_PREVIEW`）与现有 `summarize_args`。

### §4 滚动、吸底与鼠标

- **默认吸底**；**任何上滚立即脱离**（PgUp 一页、滚轮一格都算）。脱离后新内容**不改变视口**。
- **提交（Enter）无条件回到底部并恢复吸底。**
- 键与手势：`PgUp` / `PgDn` = 整页 **减 2 行重叠**；`Ctrl-G` = 一次到底；滚轮 = **每格 3 行**；左键点击「点此到底」= 到底。
- **除「点此到底」外，所有区域的鼠标点击一律忽略**：不抢焦点、不做选择、不改变视口。
- 滚动位置**必须自己夹紧**在 `0..=max`（`Paragraph::scroll` 不做夹紧）。
- **滚动条**：转录右缘**恒预留 1 列**（宽度稳定），只在内容超出时画字符；`ScrollbarState` 的 `content_length` / `position` / `viewport_content_length` 都按显示行填。
- 脱离吸底时在转录区**底部右缘**显示 `↓ {n} 行新内容 · 点此到底`（无新内容时只显示 `点此到底`），整块是一个鼠标命中矩形。`n` 按**显示行**算，且是「**自离开底部以来到达的**行」而不是「视口下方还有多少行」—— 后者永远大于零，那一支就永远不会出现。指示块停在滚动条列的**内侧**一列。
- **resize 锚点**：吸底态保持吸底；脱离态保持顶部可见的**源行**。

### §5 输入编辑器 `Input`

- 编辑器拆成**独立的 `Input` 类型**（新建 `src/render/editor.rs`），`TuiState` 持有一个。搬进去的：`input` / `cursor` / `history` / `history_at` / `draft` 与全部行编辑方法、`byte_at`。留在 `TuiState` 的：转录、`live`、`ready`、`pending`、`events`、`busy`、`quit`、`prompt_reply`，以及「提交后把文本送出去」那一半。
- `Input` 新增：软换行（逻辑行 → 显示行）、光标行列计算、`insert_str`（粘贴整体插入）、`rows(width)`。列宽算术**不要**再从 `tui.rs` 搬一份：票 11 已把它收到 `src/render/width.rs`，编辑器直接用那一份，换行口径与 `pane::wrap_line` 保持一致。
- **光标的唯一真相源是一个字符索引**（逻辑行与行内偏移由它推导，不另存）；显示行/列**每次渲染算出来**，不累加维护。全屏下 `area()` 恒为 `(0,0,w,h)` 且 `set_cursor_position` 是终端绝对坐标，**没有视口偏移要加**。实现期按此收窄：存二元组等于同一件事两处写，而插入/删除要的正是扁平索引（理由见票 12 的 Comments）。
- 软换行**按字符、不按词边界**（与转录的 `pane::wrap_line` 一致）；最小单位是字符不是 grapheme 簇。`> ` 领第一行、其后每行缩进两格，因此每行装同样多的字；**正好写满一行时光标停在该行最后一格**（终端式的 pending wrap），不另起一行 —— 另起一行会把后面的草稿整体推下去。`\t` 在粘贴归一阶段展开成四个空格（缩进保住，列宽算术不必为 tab 猜宽度）。
- `↑` / `↓` **保持视觉列（goal column）**；横向移动或插入字符时清掉。

### §6 键位表

| 键 | 作用 |
| --- | --- |
| `Enter` | 提交（trim 后为空则不发消息） |
| `Ctrl-J` | 插入 `\n`（**唯一可靠的换行键**；`Key` 枚举新增 `CtrlJ`，`map_key` 的 CONTROL 分支要加 `'j'` —— 现在它落到 `_ => None`，即 Ctrl-J 被丢弃） |
| `Shift+Enter` | **等同 `Enter`（提交）** —— 不启用键盘增强协议，它在协议层不可区分，**不得广告成换行** |
| `Char` / 粘贴 | 插入 |
| `Backspace` / `Delete` | 删一个字符；在行首/行尾时**跨行合并** |
| `←` / `→` | 一行内移动，**到行首/行尾跨行** |
| `↑` / `↓` | 缓冲内移动，**保持视觉列**；首行再 `↑`、末行再 `↓` 不动（**不取历史**） |
| `Ctrl-P` / `Ctrl-N` | 历史 —— **唯一入口** |
| `Home` / `Ctrl-A` | **当前逻辑行**行首 |
| `End` / `Ctrl-E` | **当前逻辑行**行尾 |
| `Ctrl-U` / `Ctrl-K` / `Ctrl-W` | 删到**当前行**行首 / 行尾 / 删当前行内前一个词 |
| `PgUp` / `PgDn` | 转录翻页（整页减 2 行重叠） |
| `Ctrl-G` | 转录一次到底 |
| `Ctrl-C` | 忙 → 取消当前回合；闲 → 退出 |
| `Shift-Tab` | 计划模式开关 |
| `Esc` | 忙 → 取消；有模态 → 默认答案；闲且输入**多行** → 先确认清空；闲且单行 → 直接清空 |

**`Home` / `End` / `↑` / `↓` 全部归输入区** —— 转录**不得**依赖它们。

### §7 粘贴与两种确认

- `Event::Paste(String)` **不是 `Key`**：渲染循环要同时接受 `CtEvent::Key(kind == Press)` 与 `CtEvent::Paste(_)`。
- **先归一**：`\r\n` 与裸 `\r` → `\n`；**过滤掉除 `\n` / `\t` 以外的控制字符**（crossterm 不剥 `\r`、不过滤、无长度上限，保护全部自己做）。
- 按当前光标**整体插入**，**永不触发提交**。
- **超过 100 000 字符**（按 `chars().count()` 算，不是字节）→ 先确认「粘贴 N 字符？」。
- **Esc 清空多行草稿**（输入含换行）→ 先确认「清空输入？」。单行仍然直接清空。
- 两种确认都走**既有的 pending-question 机制**（`TuiState.pending` / `Question` / `AnswerChoice`），**默认答案是「否」**。

### §8 右栏信息面板

**静态事实组装期注入**（`TuiOptions` 从 `{ port }` 变成 `{ port, facts }`，构造点 `src/cli.rs:299`）：

| 字段 | 来源 |
| --- | --- |
| 会话 id | `stored.id` |
| cwd | `stored.dir` |
| 模型 | 组装期 `model` |
| 上下文窗口 | `context::usable_input(&caps)`（窗口 − 输出预留） |
| 预算上限 | `session_config.budget.limit`（`Option<u64>`） |

**模式不进注入**：进计划模式是 `ContextInjected { source: PlanMode }`、离开是 `HistorySuperseded { reason: ModeChange }`，两条都在流上；组装期注入的初值恒为「询问」，一按 Shift+Tab 就过期。

**动态数字从流推**：

| 面板字段 | 来源 | 无数据时 |
| --- | --- | --- |
| 上下文分子 | **最近一条** `UsageRecorded.usage.input_tokens`（provider 实测，**不用** `chars/4` 估算） | `—` |
| token 已用 | 累加全部 `UsageRecorded`，`Usage::total_tokens()` = input + output | `0` |
| token 上限 | 注入的 `budget_limit`；`None` → **只显示已用，不显示 `/ —`** | 整段不显示 |
| 输入 / 输出 | 同一累加器分列 | `0 / 0` |
| 缓存明细 | 同一累加器的 `cached_tokens` / `miss_tokens` | `0 / 0` |
| 回合 | 数 `EventPayload::TurnEnded` | `0` |

**口径纪律**：累加必须与 `events::total_usage` 一致 —— `cached_tokens` / `miss_tokens` 是 `input_tokens` 的**拆分**，加进合计就把同一段 prompt 数两遍；`reasoning_tokens` 已含在 `output_tokens` 内。

**不显示花费**（`Pricing` / `PriceTable` 只服务结算路径）。日后若要加，**必须**遵守「未登记 ≠ 0」：没有 `[pricing.<model>]` 就整项不显示，而不是 `$0`。

**栏内行序**：模型 / 上下文 / token / 回合 / 输入 / 输出 / 缓存。标签列 6 列左对齐，数值右对齐，千分位用半角逗号。
**刷新**：面板是 `(facts, counters, mode)` 的**纯函数**，渲染时算；`UsageRecorded` / `TurnEnded` 到达即更新计数器。忙碌态**不在面板里重复**。

### §9 模态覆盖层

- **四种 pending 问题共用一套外观**：`Permission`、`PlanConflict`、超长粘贴、Esc 清空草稿。
- 画在中段之上、垂直居中；宽度 `min(中段宽 − 4, 72)`；`Block` 边框 + `Clear` 打底，居中 `Paragraph`；文本走 `wording.rs`。
- 键位与默认答案**沿用既有 `answer_key` / `default_answer`**：权限的默认仍是 `Deny`、计划冲突是 `Keep`、两个新确认是「否」。
- 模态期间转录与输入**不接收字符键**；`Ctrl-C` 与 `Esc` 仍然有效。
- 覆盖层**不属于转录**、不随滚动移动；`Block::PermissionAsked` 本来就在流里，回看不受影响。
- **模态拥有键盘与鼠标**：字符键与 `Enter` 只用来回答问题，`Shift-Tab` 也等（它不是出路），`Esc` 与 `Ctrl-C` 仍然有效；覆盖层画出的同一帧把「点此到底」的命中矩形清掉，滚轮也不再滚它背后的转录。
- **`Esc` 的优先级按 §6 的顺序**：忙（一个回合在飞）→ 取消回合；闲 → 问题的安全答案。权限询问通常发生在一个回合中途，所以那里 `Esc` 是取消，`Ctrl-C` 是另一条出路。
- **输入区在问题期间照常显示草稿，只是不再显示光标**：键盘在回答问题，不在编辑。
- **已知限制**：覆盖层的高度受中段限制，所以在合法的最小尺寸（`40×10`，中段 3 行）下它只有一行正文，长问题的尾部（可能含候选键）会被截掉 —— 安全答案 `Esc` / `Ctrl-C` 仍可用。

### §10 底部提示行与措辞层

- 保留 `wording::status_line(busy, width)` 的形态（状态词 + 提示），**状态词在最左**。
- 提示集换成**六条**：`enter 发送` / `ctrl-j 换行` / `esc 取消` / `shift+tab 计划` / `PgUp/PgDn 滚动` / `ctrl-c 退出`。**绝不出现 `shift+enter`**；不加 `ctrl-g`（脱离吸底时底部已显示「点此到底」）。
- **降级算法改**（实现期按实测修正过一次，见 `Further Notes`）：提示从左边填、`ctrl-c 退出` 预留，**状态词只在提示后面还放得下时才加在最左** —— 窄终端宁可少一个 `就绪`，也不能少 `ctrl-j 换行`。实测：`w=40` → 3 项（无状态词）、`60` → 5、`80` → 6、`120+` → 7（首项是状态词）。
- 新增措辞（全部落在 `src/render/wording.rs`）：面板标签（模型 / 上下文 / token / 回合 / 输入 / 输出 / 缓存）、`—`、`token_pair(used, limit)`、`context_pair(used, usable)`、`cache_pair(cached, miss)`、`↓ {n} 行新内容 · 点此到底`、`点此到底`、`终端太小：至少 40×10`、`粘贴 {n} 字符？`、`清空输入？`。
- **配色沿用现有六种 + BOLD**（DarkGray 边框与提示、Yellow 询问与反馈、Cyan 轮次、Red 错误、Magenta 分歧、Green 成功）。**不需要 truecolor，不加主题配置项。**
- 通知与诊断（技能加载、unknown command、渲染器丢弃、终止原因）**全部进转录**，不引入 toast。

### §11 渲染管线与节拍

- 保留 `tokio::select!` 四路（广播 / 键盘 / console port / tick）。**每轮末尾先把广播里排队的消息整批 drain（`try_recv` 循环，单轮上限 4096 条）再画一帧** —— 一批突发只产生一帧。
- **synchronized update 只包那一次 `terminal.draw(...)`**（ratatui 不自己包），**不要把事件读取包进去**。
- **脏标记驱动**：`apply` / 键 / `Resize` / 模态变化 / 时钟**分钟**变化置脏；**无脏不画**。tick 保持 120ms，只做时钟比较。
- **不预加帧率上限**（帧成本 = 一屏 buffer diff）；若日后 profile 显示 CPU 偏高再加。
- `sse_stream` 的「每 16 个解码事件 yield 一次」**保留不动** —— 那是事件源侧的公平性修复。
- 流式增量仍走旁路进 `live` 尾缓冲（上限 4 000 字符）；`Message` 块到达时清空尾缓冲并作为**永久全文副本**追加。

### §12 CLI 接线与斜杠命令

- `src/cli.rs:299` 构造 `TuiOptions { port, facts }`。
- **斜杠命令只看第一行**：取**第一行** trim 作为判定。**五个内建命令**（`/quit`、`/exit`、`/undo`、`/plan`、`/endplan`）与**已知技能名**走命令分支；技能后面（同一行的剩余部分 + 下面每一行，按 `\n` 拼起来）是它的 task。其它一律整体当 prompt。单行行为逐字不变。
- **内建命令不带 task**，所以只有它**独占整条输入**时才算命令：`/plan` 后面还有行就不再是 `/plan`，而是按下面的规则整体当 prompt —— 那几行不能被悄悄丢掉（哪怕它们看起来像"任务"）。
- **第一行以 `/` 开头但名字不认识**分两种：**只有这一行**（整条输入就它）→ 仍是「未知命令」提示，与单行时的老行为一致；**后面还有行** → 当 prompt —— 粘一段以 `/` 开头的路径或代码不该换来一句它没打算要的 unknown command。
- 这样 `/ask-matt` + 多行 brief 可用（保住 spec §9 的用户侧技能调用），粘贴以 `/` 开头的多行文本也不再误判。

### §13 不动的东西与不变量

- **plain 与 headless 两个渲染器一行不动**（它们不碰终端状态）。
- **语法高亮（`tree-sitter-highlight`）与 diff 着色本身不动**，只改它们渲染到哪一栏。
- **Markdown 渲染器不动**。
- **ADR 0001 冻结的模型可见文本一个字节不变**：debater/synthesizer system prompt、投影的 `[轮 N · 名字]` 前缀、`AgentError.message`、fs-agent 工具结果。本 effort 只动呈现，新增字符串全在措辞层。

### §14 使用体验与视觉效果（`.scratch/tui-ux/` 的实现增量）

`.scratch/tui-ux/map.md` 的 8 张决策票已全部落地；它们**推翻或补充**了本节前面若干条，
以本节为准（`/to-spec` 已把 §2 的几何与 Mark 阈值回改，其余各条在此收口）：

- **§3 对话面板**：工具输出正文不再直接显示 —— 工具块折叠成**一行**
  （`▸ [speaker] 调用 工具 参数摘要`，失败只在行尾加 `失败`），post-hook 反馈留在折叠态，
  输出 / 错误 / 无结果进详情。转录新增**思考提示行**：reasoning delta 起
  `[speaker] … 正在思考`，正文首个 delta **原地定格**为 `▸ [speaker] ✓ 思考完成`
  （一个思考段一行，计入 20 000 源行上限）。译文全落 `src/render/wording.rs`。
- **§4 滚动与鼠标**：`mouse()` 改成**三段分派** —— 详情覆盖层 > 待答问题 > 转录；
  有待答问题时滚轮不动转录（保留旧守卫），但在其内放开**点击作答**。转录里可点的只有
  折叠提示行与「点此到底」指示条。
- **§6 键位表**：新增 **`Ctrl+D`**：空闲弹 `退出会话` 确认（默认否、`Esc` = 否、`y` 退出）；
  **忙时忽略**；有问答题时忽略；**详情覆盖层打开时关闭它**。`Ctrl-C` 行为不变。
- **§9 模态覆盖层**：新增**详情覆盖层**这一类 —— 宽度上限 90 列、居中于中段、
  `── 思考 ── / ── 参数 ── / ── 输出 ──` 分节、标题是被点行原文、底部
  `↕ n/m · esc 关闭`；`↑/↓`、`PgUp/PgDn`、滚轮滚动，`Esc` 或再点同一行关闭，打开时转录
  冻结。它**不是 `pending`**（是一个查看态），工具全文按 `tool_call_id` 读
  `outputs/<id>.txt`（上限 200 000 字符，读不到降级为预览 + `全文不可用`）。
  四种问题与问卷各自给出**鼠标命中**：覆盖层按每个 `[key] label` 区间命中，问卷选项
  **整行可点**（单选单击即确认并前进、最后一题只确认；多选只切换），底部
  `← 上一题` / `下一题 →` / `提交` 只画可用项。
- **§10 底部提示行与配色**：提示行的出口拆成两个常量 —— 空闲 `ctrl-c/ctrl-d 退出`、

- **`Block::Message` 多了一个 `reasoning: Option<String>` 字段**（`MessageCompleted.reasoning`

## Testing Decisions

### 什么算好测试

- **布局可以进 `cargo test`**：`TestBackend` 在当前默认特性下可用（无特性门，票 02 的原型已证），所以四区几何、降级阶梯、提示行条目数、滚动与吸底都能用固定尺寸 buffer 断言，**不依赖 pty**。

- **pty 只留给启动与退出**：`scripts/tui-startup-check.py` 继续负责「启动不崩、首帧正确、退出后终端干净」。

## Further Notes

- **本 spec 的三条决定推翻了先前冻结项，都已如实记录**：①inline viewport → alt screen（ADR 0002，动机是修不好的光标 bug，不是审美）；②`Shift+Enter` **不能**换行（不启用键盘增强协议，它在协议层与 `Enter` 不可区分）；③鼠标捕获**改判为开**（换来滚轮与可点击的「到最下」，代价是**复制要按住 Shift 拖拽**）。
- **spec 期修正的两处表述**（折叠时发现，已回改设计票）：①被截断 500 字的是**非 assistant** 的消息（主要是用户自己的输入），assistant 本来就是全文 Markdown；②`Paragraph::line_count` 语义正确但被 unstable 特性挡成 `pub(crate)`，因此**换行口径坚持自己算**（现在落在 `pane::wrap_line` + `src/render/width.rs`），不为一个计数开不稳定特性。
- **一条实现注意**：`map_key` 的 CONTROL 分支现在没有 `'j'`，所以 **Ctrl-J 目前是被丢弃的**，要显式加上。
- **实现期修正的三处**（票 10 落地时发现，已回改本节与相关票）：①`status_line` 的降级优先级是「**提示优先、状态词最后加**」，不是「状态词先占位」—— 后者在 40 列下会挤掉 `ctrl-j 换行`，与票 02 那张已批准的 40×10 快照（3 条、无状态词）矛盾；②单行 header 的时钟是 `HH:MM`，不是完整日期时间（快照如此）；③`a_wide_grapheme_leaves_no_blank_cell_after_it` 随 `paint_scrollback` 一起删除 —— 那个 bug 只存在于 `insert_before` 的 scratch buffer，全屏走 ratatui 自己的 buffer diff，没有可测的自家代码。
