# grilling：对话面板的滚动与渲染缓存模型

Type: grilling
Status: resolved
Blocked by: 01

## Question

对话面板从"往 scrollback 里插行"变成"一块带自己滚动缓冲的面板"（见 map Notes 第 2、3 条：上 alt screen、PgUp/PgDn 滚动、20 000 行上限、吸底但上滚后不抢）。要定下它的状态模型与缓存策略。

## 冻结的输入

上 alt screen（接受终端原生选择只覆盖可见区）；**不开鼠标捕获** —— 所以**只有键盘**能滚动，滚轮不会到达我们；历史上限 **20 000 行**，超出丢最旧；**吸底，用户上滚后不抢**。

## 需要定

1. **20 000 行的单位**。是源行（`Block` 展开后的行）还是换行后的**显示行**？换行依赖当前宽度，宽度一变计数就变 —— 上限必须定义在一个**宽度无关**的单位上。定下来并说明理由。
2. **缓存什么、什么时候失效**。`Vec<Block>` → wrap 后的行；失效时机（宽度变化 / 新块 / 流式增量）；每帧是否要重 wrap 全量（只 wrap 可见区 + 少量 overscan 够不够）。
3. **吸底语义**。上滚多少才"脱离"吸底；脱离后新内容到达时的提示（`↓ N 行新内容` 之类）显示在哪一栏；回到底部用哪个键（End？Ctrl-End？按一次还是按住）。
4. **键位**。PgUp/PgDn 的步长（整页还是半页）；`↑`/`↓` 归谁 —— 输入区有焦点时它们属于输入历史，转录是不是**只认** PgUp/PgDn/Home/End；Home/End 归输入还是转录。**必须与票 04 的键位表一致，不能两张票各说各话。**
5. **宽度变化后的锚点**。重 wrap 之后是保持顶部可见内容还是保持吸底；resize 时用户正在上滚怎么办。
6. **滚动条**。显示在哪一栏、什么时候出现、用 ratatui 的 `Scrollbar` 还是自己画（票 01 给 `Scrollbar` 的现状）。
7. **块粒度与超长块**。滚动以显示行为单位而不是以块为单位（确认）。一个 1000 行的工具输出块在面板里怎么处理 —— **先读 `src/render/` 查清现有语义**（现有的折叠/截断行为是什么？`Block` 有哪些变体？），**不要臆造**，也不要在本票里顺手改它。

## Answer

**已定（2026-09-21，grilling 两轮 + 用户逐条确认）。本票只产决策，不含实现。**

### 0. 冻结输入（含一条**被用户改判**的）

- 转录自成一栏、**自己持有滚动缓冲**；全屏 alt screen。
- ⚠️ **鼠标捕获开启** —— 2026-09-21 用户改判，**推翻 charting 时冻结的「不开鼠标捕获」**。换来两件事：**滚轮能滚转录**（每格 **3 行**）、**可点击的「到最下」**。代价：终端原生选择/复制要**按住 Shift 拖拽**（主流终端通行做法）。
- 历史上限 **20 000 源行**，超出丢最旧。
- **吸底，但用户上滚后不抢。**
- **非 assistant 的消息正文不再截断**：`src/render/tui.rs:828-834` 那一支（用户消息，以及 system 的非 assistant 消息）现在压成单行 + `truncate(text, 500)`，**改成保留换行的多行原样渲染**。**assistant 的消息本来就是全文 Markdown**（`:802-827` 走 `markdown::to_lines`，无截断），**不动**。**工具输出保留 preview**（`TOOL_PREVIEW = 4_000`，`src/render/tui.rs:56`，走 `wording::tool_output_preview`，`src/render/wording.rs:88`）。
- `PgUp` / `PgDn` = **整页减 2 行重叠**；`Ctrl-G` = 一次到底。
- `Home` / `End` / `↑` / `↓` **全部归输入区**（票 04 已定），转录**不得**依赖它们。

### 1. 上限的单位 = **源行**（宽度无关）

20 000 的上限按**源行**算：`Block` 展开成未换行的行数（`src/render/transcript.rs` 的 `Block` 列表，每个变体展开成若干 `Line`）。理由：换行依赖宽度，**按显示行计会让「删掉哪些内容」随窗口大小变化**，同一段会话在两个终端宽度下保留的内容不同 —— 不可复现。

**滚动与滚动条另按显示行算**（每帧由当前宽度算出）。两套单位的关系由 §2 的索引维护。

### 2. 缓存与失效

- 缓存对象：`Vec<SourceLine>` → **全量换行**后的 `Vec<Line>`，外加一张**源行 → 显示行起点**的索引（滚动条与锚点都要它）。
- **换行口径**：逐字符、一个 CJK 字符 2 列 —— 复用既有 `wrap_take`（`src/render/tui.rs`），**不用** `Paragraph::line_count`（默认特性下不可调用，research §12.1），**也不开** `unstable-rendered-line-info`（不值得为一个计数开不稳定特性；口径必须和转录、输入区一致，而 `wrap_take` 已经是我们自己的口径）。
- **失效条件**：① 宽度变化 ② 追加了新块 ③ 流式增量刷新尾部。**只在 ①③ 重算**；② 只换行新增的尾部并追加索引（增量）。
- **全量还是可见区**：① 必须全量（宽度变了，索引全废，而滚动条与锚点要精确总数）；③ 只重算尾部那一块。20 000 行的全量换行是**宽度变化时的一次性成本**，可接受。
- 换行结果**不落盘**（纯内存），与 20 000 行上限一致。

### 3. 吸底、脱离与回来

- **默认吸底**：新内容到达且处于吸底态 → 视口跟到底部。
- **任何上滚立即脱离**吸底（PgUp 一页也算，滚轮一格也算）。脱离后**新内容不改变视口**。
- 脱离期间在**转录区底部右缘**显示 `↓ N 行新内容 · 到最下`（措辞归票 06），**整块可鼠标点击**；`Ctrl-G` 与 PgDn 按到底等价。
- **提交（Enter）时无条件回到底部并恢复吸底** —— 刚发出去的消息，用户要看回答。这是本票自己加的规则，不改变「上滚后不抢」。

### 4. 键位与鼠标（与票 04 的表合起来才是完整键位表）

| 输入 | 作用 |
| --- | --- |
| `PgUp` | 上翻**整页减 2 行**（2 行重叠，避免迷失） |
| `PgDn` | 下翻整页减 2 行；**到底即恢复吸底** |
| `Ctrl-G` | 一次到最下并恢复吸底 |
| 滚轮上 / 下 | 滚转录，**每格 3 行**（鼠标捕获已开） |
| 左键点击「↓ N 行新内容 · 到最下」 | 回到底部并恢复吸底 |
| 其它区域的左键点击 | **忽略** —— 不抢焦点、不做选择、不改变视口 |
| `Home` / `End` / `↑` / `↓` | **不属于转录**（归输入区，票 04） |

鼠标事件类型：`crossterm::event::MouseEventKind::ScrollUp/ScrollDown`、`Down(MouseButton::Left)`；进入/退出用 `EnableMouseCapture` / `DisableMouseCapture` **成对**（`ratatui::init` 不开鼠标，research §1.3，所以要自己发）。命中矩形由票 06 在布局里算（几何来自票 02），本票只要求「**整块可比点**、其它区域忽略」。

### 5. 宽度变化后的锚点

- **吸底态**：resize 后**保持吸底**（重新贴底）。
- **脱离态**：保持**顶部可见的那条源行** —— 记的是源行号（宽度无关），resize 后按新索引换回显示行。这样重排不会把用户正在看的内容顶走。
- resize 期间用户正在上滚（同一批事件里）→ 按脱离态处理，不吸底。

### 6. 滚动条

- **始终预留转录区右缘 1 列**（宽度稳定，避免"滚动条出现 → 变窄 → 重排"的抖动），**只在内容超出可见区时画字符**。
- 用 ratatui 的 `Scrollbar` / `ScrollbarState`（`ratatui-widgets`，research §4.5）；`content_length` / `position` / `viewport_content_length` 都按**显示行**填。
- 脱离吸底时滚动条要有"不在底部"的可见差异（配色/箭头归票 06 的主题项，本票只要求存在差异）。

### 7. 块粒度与超长块

- 滚动以**显示行**为单位，**不是以块为单位**（一个块可以被截断在视口上下缘）。
- **非 assistant 消息不再截断**（§0）：这是本票唯一的保真度变更。动机还多一层 —— 票 04 上了多行输入，**用户粘 20 行进来，转录里只留前 500 字**，而那正是最需要看全的一类内容。渲染时**不做 Markdown**（用户输入不是 Markdown 文档，原样保留换行更诚实），续行按 speaker 前缀的显示宽度缩进（复用 `a_message_continuation_indents_by_the_label_display_width` 那套算法）。
- **工具输出保持 preview**（4 000 字符 + `…（结果已省略）`）：工具输出是噪音，且一个读文件调用就能吃掉缓冲的一大块。**不在本票里改这个数值。**
- 现有其它截断（`summarize_args`、`wording::tool_output_preview`）原样保留。
