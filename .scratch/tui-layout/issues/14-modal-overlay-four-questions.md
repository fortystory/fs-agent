# 14: 模态覆盖层：四种等待回答的问题

**What to build:** 把权限询问从「占掉输入行的黄色提示」改成**模态覆盖层**，并让四种 pending 问题共用同一套外观与回答机制：权限、计划冲突、超长粘贴确认、Esc 清空草稿确认。

Blocked by: 10, 12

Status: ready-for-agent

**参考:** spec §9（模态覆盖层）、§7（两种确认）、§10（措辞层）

- [x] 覆盖层外观：画在中段（转录 + 右栏）**之上**、垂直居中；宽度 `min(中段宽 − 4, 72)`；`Block` 边框 + `Clear` 打底 + 居中 `Paragraph`；问题文本与可接受键走 `wording.rs`
- [x] 四种 `Question` 共用：`Permission` / `PlanConflict` / 超长粘贴（12 新增）/ Esc 清空草稿（12 新增）
- [x] 键位与默认答案**沿用既有 `answer_key` / `default_answer`**：权限默认 `Deny`、计划冲突默认 `Keep`、两个新确认默认**否**
- [x] `Esc` 在模态上 = 默认答案；`Ctrl-C` 仍然有效
- [x] 模态期间转录与输入**不接收字符键**（现状的 `pending.is_some()` 分支）；模态消失后焦点回输入区
- [x] 覆盖层**不属于转录、不随滚动移动**；`Block::PermissionAsked` 仍留在流里可回看
- [x] 措辞新增：`粘贴 {n} 字符？`、`清空输入？`，以及四种问题各自的可接受键提示
- [x] 用例：四种问题各渲染一次（`TestBackend` 断言覆盖层出现且背景被遮住）；默认答案正确；模态期间字符键不改变输入缓冲

**实现完成（2026-09-21）**。落点：`src/render/tui.rs` 新增 `draw_modal`（在 `draw_frame` 最后调用，压在中段之上）、`mouse` 的 pending 守卫、`draw_bottom` 改为**总是画草稿**（问题期间只收起光标）；`src/render/wording.rs` 给两个新确认补上可接受键；`tests/render_layout.rs` 新增 5 个用例、`tests/wording.rs` 改 1 个。

**三处实现期的选择**：

1. **模态拥有鼠标，不只是键盘**。票面只写了「模态期间转录与输入不接收字符键」；但滚轮会滚它背后的转录、而「点此到底」的命中矩形仍在（覆盖层把它盖住了却仍可点）。所以 `mouse()` 加了与 `paste()` 同样的 pending 守卫，且覆盖层画出的同一帧把 `state.indicator` 清空 —— 覆盖层看不到的东西也不该点得到。
2. **问题文本用 `pane::wrap_text` 折行**，覆盖层高度随之长到最多铺满中段。票面说「居中 `Paragraph`」；若只截一行，长权限问题会把候选键截掉，而键正是这一层存在的理由。折行复用了转录那一份列宽口径，没有新实现。
3. **输入区在问题期间照常显示草稿**。票面只说输入不接收字符键，没说要不要隐藏；草稿是用户写的东西，藏起来会在回答之后突然冒出来。收起光标是关键的一半：键盘在回答问题，不在编辑。

**与票 12 的交接修正**：票 12 的实现把两个新确认写成不带键的纯问题（`粘贴 {n} 字符？` / `清空输入？`），本票按「每条问题自带可接受键」补齐，并回改了票 12 留下的那条措辞断言。

**一处测试方法的教训**：验证 `Clear`（背景被擦掉而不是盖上去）时，第一版用例拿**长**权限问题来断「盒子内部只有问题文本」——它恰好把面板标签所在的列也写满了，所以去掉 `Clear` 依然全绿（变异 MISSED）。换成**短**问题（清空草稿）后，问题两侧的留白正落在面板标签上，去掉 `Clear` 立刻转红 ✓。

**基线**：`cargo test` **534 passed / 0 failed**（529 → +5 模态用例，另有 1 条措辞用例改写）；`cargo clippy --all-targets` 干净；`cargo fmt --check` 只剩 `src/context/repo_map.rs` 的既有漂移；pty 启动检查 3/3 GREEN。

**评审收口**（`/code-review` 双轴，2026-09-21）：

Standards 轴：

- **覆盖层的几何跑到了画家手里**（`saturating_sub(4)`、`/2`、内部矩形），而 `layout` 自认是几何的唯一家。已归位：`Regions::modal_width()` 与 `Regions::modal(rows) -> Option<Rect>`，加一个 `layout::inner(area)`；`MODAL_MAX_WIDTH` 也搬进 `layout`。
- `Pending::prompt` 的文档还写着「放在输入行的位置」—— 那个位置在本 commit 里已经没了（草稿留在输入区，问题搬到覆盖层）。已改。
- 测试里 `cells` / `row_text` / `panel_text` 是同一段「按显示宽度步进取列」的循环三份 —— 收敛成一份，另两个调它。

Spec 轴：

- **`Esc` 的优先级写错了**：清单里写「`Esc` 在模态上 = 默认答案」，实际只有在**不忙**时成立 —— 键位表的顺序是「忙 → 取消回合」在前，而权限询问恰恰发生在一个回合中途（`busy` 为真）。行为**不改**（spec §6 与票 04/06 的表就是这么排的，`Ctrl-C` 始终是取消），改为把这条**验证**补齐：新增用例钉住「忙 + 有问询时 `Esc` 仍是取消，问询等它自己的键」。
- **`Shift-Tab` 原本能穿过模态**（它在 pending 守卫之前）—— 与 spec §9「模态期间只有 `Ctrl-C` 与 `Esc` 仍然有效」不符。已把 pending 守卫提到它前面，并加断言。
- **`request()` 会覆盖 `Pending::Loop` 并丢掉回传通道**（与票 12 评审抓过的粘贴 bug 同类）。循环一次只问一个问题并等待答案，所以到不了；现在明确「保住屏幕上那一个、丢掉迟到的那个」（丢掉的 sender 会让循环得到拒绝，是孤儿问询的安全读法），并加用例。
- **「垂直居中」原本没有断言**（把 `area.y` 改成 `middle.y` 照样全绿）—— 补上「上下留白相差不超过一行」（中段高 14、盒子高 3，整数除法必然多一行在下）。
- **「模态消失后焦点回输入区」原本只靠手工清单** —— `TestBackend` 其实记光标（`cursor_visible` / `cursor_position`），所以补了一条自动用例：问题期间没有光标，答完之后回到原处。
- **40×10 下长权限问题的候选键会被截掉**（中段只有 3 行 → 覆盖层只有 1 行正文）。这是票面把覆盖层定在中段、且最小尺寸合法的必然结果，**没有改行为**：如实写进本票 Comments 与 spec §9（安全答案 `Esc`/`Ctrl-C` 仍可用）。

**一处修正自己的说法**：早先 Comments 写「折行以免截掉候选键」过满 —— 折行只在**中段装得下**时保住键；40×10 那一档保不住。

**未改的两条**：`clear_draft_confirm` 返回 `String`（调用点就在同一 commit 里，签名随之）；鼠标守卫与「问题期间照画草稿」超出票面字面 —— 但前者是票面「模态拥有键盘」的必然延伸（覆盖层盖住的东西不该还能点/滚），后者是把「输入不接收字符键」读成「输入区还在，只是不吃键」，两条都已在上面的 Comments 里申报。

**本轮变异检验**：取消垂直居中、问题期间也画光标、把 `BackTab` 挪回守卫之前、删掉「一次只问一个」的守卫 —— 四处全部被抓到。
