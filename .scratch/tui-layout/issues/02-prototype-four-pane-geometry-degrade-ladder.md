# prototype：四分区几何与降级阶梯

Type: prototype
Status: resolved
Blocked by: 01

## Question

用**看得见的东西**定下四分区布局的几何与降级阶梯 —— 这是"让 TUI 更美观"这句要求唯一能被检验的地方。

**冻结的输入**（见 map 的 Notes，不得重开）：header 放名称+版本 / cwd / 模式 / 时钟；中右面板放模型 / token / 上下文用量 / 轮次；**降级顺序 = 先隐藏右栏，再压 header**；最小尺寸 **40×10**；输入区**随内容长高、上限 10 行**。

## 需要定

1. **网格**。header 占几行（1 行还是 2 行）？中段水平怎么切 —— 右栏是**固定列宽**（min/max 是多少）还是**百分比**？中左与中右之间用什么分隔：`Block` 边框、空白 gutter、还是暗色竖线？
2. **输入区**。1 → 10 行的生长规则；多行时的提示符与续行缩进（第二行起是否留出 `> ` 那么宽的空白）；到 10 行之后内部怎么滚动。
3. **快捷键提示行**。在每个宽度下留哪几条（`ctrl-c` 退出**必须**在）；它属于输入区还是独立最后一行。
4. **降级阶梯**。每一档的阈值与生效顺序（先隐藏右栏，再压 header）；**40×10 下到底显示什么**——是否只剩一行"终端太小"。
5. **观感**。留白、分隔强度、header 字段之间的分隔符、右栏标签与数值的对齐。

### 1. 四区几何与「chrome 成本」

四个区域各自带边框，于是**固定 chrome = 7 行**：

| 组成 | 行数 |
| --- | --- |
| header 块上下边框 | 2（**底边框就是 header 下那条横线**，不是额外一行） |
| 中段块上下边框 | 2 |
| 底部块上下边框 | 2 |
| 快捷键提示行 | 1（底部块的最后一行**内部**内容，不是独立屏幕行） |
| **合计** | **7** |

行预算：`h = header 内容行 + 中段内容行 + 输入区行 + (airy ? 2 : 0) + 7`
列预算（中段）：`转录外框 + 右栏外框 − 1 = w`（两个 Block **共用接缝那 1 列**，不画两条；接缝两端补 `┬` / `┴` 成 T 形）

- 右栏：**外框** `= clamp(⌊26%·w⌋, 25, 31)`，**内容宽 = 外框 − 2**。下限 25 是因为最长的核心行 `上下文  12,345 / 200,000` 要 23 列内容宽（25 − 2）；上限 31 是因为再宽也只是让转录更宽。
- **可见后果（不是 bug）**：因为「每个区域都有边框」+「airy 留一行空行」，header 底边框与中段块顶边框之间会**隔着 1 行空白出现两条横线**。这是 airy + 全边框的必然结果，不是重复画了 header 的横线。若嫌线太重，被否决的 gutter / 竖线方案见 §7。
- 2 行 header 的分工（与第一版相同）：**第 1 行 = 名称+版本（左）/ 时钟（右）**；**第 2 行 = cwd（左）/ `模式 询问`（右）**，所以 2 行 header 不用分隔符。
- 1 行 header：`名称+版本 · cwd · 模式 · 时钟(HH:MM)`，**cwd 是第一个被丢的字段**，再放不下才丢时钟；名称+版本与模式恒在。

### 3. 高度方向：输入区怎么和中段抢行数（chosen 组合，w=120 实测）

`输入区行数 = clamp(草稿折行数, 1, min(10, h − 7(chrome) − header 内容行 − (airy ? 2 : 0) − 1))`

| h | header 内容行 | airy | 输入上限 | 草稿 1 行时 输入/中段 | 右栏 | 说明 |
| --- | --- | --- | --- | --- | --- | --- |
| 10 | 1 | **无** | 1 | 1 / 1 | 隐藏 | 冻结最小高度；airy 放不下 |
| 11 | 2 | 无 | 1 | 1 / 1 | 隐藏 | |
| 12 | 2 | 无 | 2 | 1 / 2 | 隐藏 | |
| 13 | 2 | **有** | 1 | 1 / 1 | 隐藏 | 从 13 行起 airy 才回得来 |
| 14 | 2 | 有 | 2 | 1 / 2 | 隐藏 | |
| 15 | 2 | 有 | 3 | 1 / 3 | 隐藏 | 差 1 行就能出现右栏 |
| 16 | 2 | 有 | 4 | 1 / 4 | **出现**（只 4 个核心字段） | 右栏能出现的最小高度 |
| 20 | 2 | 有 | 8 | 1 / 8 | 全 7 行 | |
| 24 | 2 | 有 | 10 | 1 / 12 | 全 7 行 | 正常档 |
| 24 | 2 | 有 | 10 | 3 / 10（草稿 3 行） | 全 7 行 | |
| 24 | 2 | 有 | 10 | **10 / 3**（草稿 12 行） | **整个隐藏** | 中段只剩 3 行 < 4 |
| 50 | 2 | 有 | 10 | 10 / 29 | 全 7 行 | |

- **最反直觉的一条**：`120×24` 下草稿涨到 10 行时，输入区吃满上限，中段只剩 3 行 → **右栏整栏消失**（见 `chosen-120x24-input-12-lines.txt`）。这是 airy（2 行）+ 边框（6 行）把固定成本抬到 7 行之后的直接后果。
- `h ≤ 15` 时输入上限塌到 1–3 行：小高度下 chrome + airy 基本吃完了。
- **续行缩进 2 格**，`> ` 只在第一行；超出上限时显示**尾部**（底部锚定，光标行始终可见）。
- 高度不直接隐藏右栏；是**输入区长大 → 中段内容行变少 → 右栏放不下 4 个核心字段 → 整栏隐藏**。

### 4. 降级阈值表（chosen 组合重算）

| 触发条件 | 动作 | 丢掉什么 |
| --- | --- | --- |
| `w < 40` **或** `h < 10` | 只画一行居中「终端太小：至少 40×10」 | 全部；这是**唯一**的「太小」档 |
| `w < 80` | **隐藏整个右栏**（降级第 1 步） | 右栏全部字段；转录吃满宽度 |
| 中段**内容**行 `< 4` | 隐藏整个右栏 | 同上（高度路径，含输入区长大的情形） |
| 转录**内容**宽 `< 20 列` | 隐藏整个右栏 | 同上（保护转录可读性；`w ≥ 80` 时实测恒满足） |
| 右栏内容宽 `< 29`（即 **w < 120**） | 丢**上下文百分比**后缀 `（6%）` | 只丢 `（6%）`；`12,345 / 200,000` 数值本身留下 |
| 右栏可用行数不足 | 先丢**缓存**明细，再丢**输入/输出**两行 | 见 §5 的强制单调规则 |
| `w < 60` | **压 header 到 1 行**（降级第 2 步） | 先丢 cwd，再丢时钟的日期（`HH:MM` 化） |
| `w ≥ 60` 且 `h = 10` | 压 header 到 1 行 | 同上（此时中段只有 1 行 → 右栏早已隐藏） |
| airy 两行放不下（`w < 60` 且 `h ≤ 11`，或 `w ≥ 60` 且 `h ≤ 12`） | **丢 airy**（三档里第一个被丢的） | 两行空白；转录/输入各得 1 行 |
| 其它 | 不降级 | — |

- **40×10 不是「终端太小」**：它渲染完整降级布局 —— 四个带边框的区域 + 1 行 header + 1 行转录 + 1 行输入 + 1 行提示，**没有右栏、没有 airy**。只有 `w<40` 或 `h<10` 才是「太小」。
- **「先隐藏右栏、再压 header」仍然成立，而且是被结构保证的**：header 只在 `w < 60`（右栏按宽度本就不可见）或 `w ≥ 60 且 h = 10`（中段内容只有 1 行，右栏按高度早已隐藏）时压缩。任何右栏可见的尺寸，header 都是 2 行（`w ≥ 60` 时）。
- **airy 与 header 的优先级**：`plan()` 的候选顺序是 `(header 2 行, airy)` → `(header 2 行, 无 airy)` → `(header 1 行, airy)` → `(header 1 行, 无 airy)`，取第一个放得下的。即 **header 的第二行是结构性的、airy 是装饰性的**，先丢 airy；header 压缩最后。所以 `120×12` 是「header 2 行 + 无 airy + 中段 2 行」，不是「header 1 行 + airy + 中段 1 行」。
- **右栏 vs airy**：小高度下（如 `80×15`）会**留着 airy、隐藏右栏**。这是照冻结顺序来的 —— 右栏是最先被牺牲的区域，airy 不是区域。

### 5. 栏内 token 块的行序（票 05 定了显示什么，这里定怎么排）

标签列 **6 列左对齐**（最宽标签是 `上下文`）+ 1 列空格；**数值右对齐到面板内容区右缘**；模型名左对齐并 `…` 右侧截断（票 05 §6）。

| # | 标签 | 值 | 可丢？ |
| --- | --- | --- | --- |
| 1 | `模型` | `claude-sonnet-4-5`（内容宽 23 时会截成 `claude-sonnet-4…`） | **永不丢** |
| 2 | `上下文` | `12,345 / 200,000`，宽够时加 `（6%）` | 数值**永不丢**；`（6%）` 是最先丢的宽度细节 |
| 3 | `token` | `12,345 / 100,000`；`budget_limit == None` 时只有 `12,345`（**不显示** `/ —`） | **永不丢** |
| 4 | `回合` | `7` | **永不丢** |
| 5 | `输入` | `9,000` | 细节行，可丢 |
| 6 | `输出` | `3,345` | 细节行，可丢 |
| 7 | `缓存` | `9,000 / 3,345`（cached / miss） | 细节行，**最先丢** |

- **丢弃顺序严格按票 05 §7**：`缓存 → 输入/输出 → 上下文百分比`。宽度先筛「哪些行放得下」，行数不够时按中段内容行裁剪；**强制单调** —— 一旦 `输入/输出` 被丢，`缓存` 一定也被丢（不允许「留缓存、丢输入/输出」的反序）。
- 7 行是上限；右栏内容行 ≥ 7 时全出（`h ≥ 20` 实测）。`12,345 / 200,000` 这类复合值整体右对齐，不对 `/` 两边分别对齐。
- 讨论模式的 `RoundStarted { round }` **不进面板**（票 05 已把面板语义钉在 `TurnEnded` 上）。

### 6. 提示行（快捷键）

它是**底部块的最后一行内部内容**（不是独立屏幕行，因为它和输入框同属「下」那个区域）。`ctrl-c 退出` **恒在**（算法为它预留位置），其余从左往右加，放不下就停在上一档。内宽 = `w − 2`。

| w | 内宽 | 实际显示 | 列数 |
| --- | --- | --- | --- |
| 40（最小） | 38 | `enter 发送 · ctrl-j 换行 · ctrl-c 退出` | 38（正好占满） |
| 60 | 58 | `enter 发送 · ctrl-j 换行 · esc 取消 · ctrl-c 退出` | 49 |
| 80 | 78 | `enter 发送 · ctrl-j 换行 · esc 取消 · shift+tab 计划 · ctrl-c 退出` | 66 |
| 120 / 174 | 118 | 再加 `PgUp/PgDn 滚动`，全 6 条 | 83 |

- 顺序：`enter 发送 / ctrl-j 换行 / esc 取消 / shift+tab 计划 / PgUp/PgDn 滚动 / ctrl-c 退出`。
  其中 `enter 发送`、`esc 取消`、`shift+tab 计划`、`ctrl-c 退出` 是 `wording.rs:366` 的既有 4 条（措辞与相对顺序原样保留）；`ctrl-j 换行`、`PgUp/PgDn 滚动` 是本 effort 新增。这 6 条要进**同一张键位表**，与票 03 / 票 04 共用（map 的跨票约束）。
- **`shift+enter 换行` 已删除，不得再出现**：票 04 决定不启用键盘增强协议，Shift+Enter 在协议层等同 Enter（提交），广告成换行是错的。第一版快照里的该提示已作废（见 §7）。
- 忙碌词（`工作中` / `就绪`）**不在**提示行里 —— 落位归票 06。

### 7. 被否决的变体（保留可查，不要据此实现）

### 8. 40×10 的结论 —— **仍然成立，但代价是 airy 被丢**（需要用户点头的一条）

如实回答用户的问题：

- **40×10 仍然画得出可用的降级布局**：`chosen-40x10.txt` 是实测渲染 —— 四个区域都带边框（3 + 3 + 4 = 10 行），header 1 内容行（`fs-agent 0.1.0 · 模式 询问 · 14:32`，cwd 被丢），转录 1 行内容，输入 1 行，提示行 1 行（`enter 发送 · ctrl-j 换行 · ctrl-c 退出`，38 列正好占满）。**不是「终端太小」。**
- **代价**：`h ≤ 11` 时 **airy 的两行空白被丢掉**，因为 `chrome 7 + header 1 + airy 2 + 输入 1 + 转录 1 = 12 > 10`。
- 因此**「完整选定组合」（含 airy）的最小尺寸是**：
  - `w < 60`：**40×12**（见 `chosen-40x12.txt`）
  - `w ≥ 60`：**60×13**（header 要 2 行）
- **需要用户决定**（三条路，探针目前实现的是 (a)）：
  - **(a) 保持冻结的 40×10**，接受 airy 在 `h ≤ 11` 时降级。← **本 Answer 采用这条**，因为 40×10 是 charting 冻结的，本票无权改。
  - (b) 把最小尺寸改成 **40×12 / 60×13**，让 airy 在所有支持尺寸里恒在。
  - (c) 保持 40×10 且坚持 airy 恒在 —— **不可能**：10 行放不下 `chrome 7 + header 1 + airy 2 + 输入 1 + 转录 1 = 12`。
