# 输入区三行 + 忙碌时 mark 的色环

Status: ready-for-agent（一次 grilling 的折叠：两条决议由用户拍定，第三轮只定参数；实现票 `01`–`03`）

- **来源**：用户口头的两条优化需求（「把文本输入框加到 3 行高」「加一个动画表示 fs-agent 正在工作」）+ 三轮问答。**不是** wayfinder 图，也没有 prototype：这两条都不需要可运行的答案。
- **术语**：新增 `CONTEXT.md` 词条 **忙碌脉冲（Pulse）**（§渲染）。
- **与旧决议的关系**：`.scratch/tui-sidebar/spec.md` §8 与 `docs/render.md` 都写着「这个 `select!` 是三条来源、**没有定时器**」。本 spec **部分推翻**那一条 —— 定时器回来，但只为脉冲存在，且只在一次运行在飞时 arm（§2、§4）。
- **落点**：`src/render/tui.rs`、`src/render/layout.rs`、`tests/`、`README.md`、`docs/render.md`、`docs/tui-manual-checklist.md`、`CONTEXT.md`。

## Problem Statement

1. **输入区只有一行高时，落笔区会跟着草稿跳。** 现在 `输入行数 = clamp(草稿折行数, 1, 10)`：空草稿时是一条线，敲进三行草稿就长成三条，转录被顶掉两行。用户想要一块**稳定的、能看见自己写了三行**的地方 —— 写多行提示词是这个 CLI 的常态。
2. **忙碌态只有一个静态标点。** 界面上唯一说「我在干活」的东西是提示行左侧那两个汉字 `工作中`，而宽屏上视线最常停留的地方是左栏顶部的 mark —— 它现在完全静止。一个静止的程序和一个死了的程序在屏幕上没有区别。

## Solution

- **输入区最少 3 行**（**不带**自己的边框）：草稿折行数不足 3 时输入区仍占 3 行，超过 3 时照旧长到 10 行上限。
- **忙碌时 mark 整块按彩虹色环变色**：100ms 一帧、12 帧走完一圈（1.2 秒），空闲时回到原来的静态渐变。

```
│ 左栏：mark（忙碌时整块在色环上走）         │ 转录
│                                            │   （h − 7 − 输入行数）
│ ── tab 条 ──                               ├── 状态行上分隔线 ──
│                                            │ 状态行：模型 … │ 模式 … │ 上下文 …%
│                                            ├── 输入区上分隔线 ──
│                                            │ 输入区（3–10 行，草稿在顶部）
│                                            ├── 提示行上分隔线 ──
│                                            │ 提示行（就绪 / 工作中 · 快捷键 · 退出）
```

## User Stories

### A. 输入区三行

1. 作为用户，我想让输入区至少 3 行高，以便我一次能看见三行草稿，而不必让框跟着字长高。
2. 作为用户，我想让输入区在第 4 行才开始长高、并照旧在 10 行封顶，以便行数账仍然简单。
3. 作为用户，我想让这 3 行只是「有地方写」，不引来第二圈边框，以便界面里仍然只有一圈外框。
4. 作为用户，我想在终端太矮（40×10）时优先保住转录的那一行，以便输入区的最小高度不把转录挤没。
5. 作为用户，我想让草稿仍然从输入区**顶部**开始写，以便光标位置与今天完全一样。
6. 作为用户，我想让多行草稿的 `Esc` / 粘贴 / 光标行为一个字节都不变，以便这次只动几何、不动编辑器。

### B. 忙碌脉冲

7. 作为用户，我想在 fs-agent 工作时看到 mark 在变色，以便一眼知道它还在跑，而不是卡住了。
8. 作为用户，我想让色环 12 帧、1.2 秒走一圈，以便它读起来像「在动」而不是「在闪」。
9. 作为用户，我想让整块 mark 同一帧同一个颜色，以便这个信号是「在动」而不是「某一行在动」。
10. 作为用户，我想让空闲时 mark 回到原来的静态渐变，以便「动」这个信号只属于忙碌态。
11. 作为用户，我想让动画只在 mark 真的画出来时存在（`w ≥ 120` 且 `h ≥ 16`），不在窄屏上假装有动画。
12. 作为用户，我想让空闲时没有任何定时器在跑（CPU 不动、不空转），以便这个动画不变成一台常开的马达。
13. 作为用户，我想让运行结束时色环回到第一帧，以便下一次运行从同一个起点开始。

### C. 不变量

14. 作为用户，我想让所有人类可见文案仍然只由措辞层产生，以便界面改动不把字符串散进渲染代码。
15. 作为用户，我想让模型可见文本（system prompt、投影前缀、`AgentError.message`、工具结果）一个字节都不变，以便前缀缓存不被废掉。
16. 作为用户，我想让 plain / headless 两个渲染器完全不受影响，以便管道化照旧可用。
17. 作为用户，我想让事件 schema 与投影完全不动（脉冲是纯渲染器状态），以便回落与重放不受影响。
18. 作为用户，我想让 `cargo test` 全绿、`cargo clippy --all-targets` 干净、`cargo fmt --check` 只留既有的两处漂移，以便改动可验收。

## Implementation Decisions

### §1 输入区：最少三行

- **落点**：`layout::plan`。`输入行数 = clamp(草稿折行数, MIN_INPUT_ROWS = 3, max_input_rows(h))`，`max_input_rows` 照旧 = `min(10, h − CHROME − 1)`（转录底线 1 行）。
- **地板优先级：转录底线 > 输入区最小高度。** 40×10 下 `max_input_rows = 2`，所以那一档输入区是 **2 行**、转录 1 行；`h ≥ 12` 的每一档都是 3 行。用户故事 4 就是这么落地的。
- **草稿仍在顶部对齐**：第 1 行是 `> `，后面是留白；`editor::Input::view` 的语义不改（空草稿仍然只产出一行，留白由 `Paragraph` 铺满输入区矩形）。
- **不多画边框**（用户故事 3）：输入区上下的共享分隔线由外壳画（`draw_shell` 的三条横线之一），这次不新增 `Block`。
- **转录行数的新账**（`h − 7 − 输入行数`）：

  | 尺寸 | 输入行数 | 转录行数 | 旧值 |
  | --- | --- | --- | --- |
  | 40×10 | 2（地板，转录底线赢） | 1 | 2 |
  | 80×14 | 3 | 4 | 6 |
  | 40/60/80/100/120×24 | 3 | 14 | 16 |
  | 174×50 | 3 | 40 | 42 |

### §2 忙碌脉冲：mark 的彩虹色环

- **`PULSE_PALETTE: [Color; 12]`** —— 六个色相 × 明/暗两支，顺序绕色环：`LightMagenta, Magenta, LightBlue, Blue, LightCyan, Cyan, LightGreen, Green, LightYellow, Yellow, LightRed, Red`。第 0 帧是 `LightMagenta`（mark 空闲态顶部的颜色），所以从空闲切进忙碌的第一帧几乎无缝，之后色相开始走（用户故事 8）。
- **整块同步**（用户故事 9）：忙碌时 mark 的 5 行是**同一个**颜色 `PULSE_PALETTE[pulse % 12]`；空闲时是原来的静态渐变（上 4 行 `LightMagenta`、底行 `Magenta`）。**接受的代价**：忙碌时「上亮下暗」的立体感消失，mark 读起来是一块平色 —— 换来的是「它在动」，而运行一结束渐变就回来。
- **落在画笔里**：`tui.rs` 的 `mark_lines(pulse: Option<u64>)`；`None` = 空闲渐变，`Some(n)` = 色环第 `n` 帧。字形仍是 `wording::logo_lines()`，**`wording` 一个字节不改**（用户故事 14）。
- **脉冲计数器 `TuiState.pulse: u64`**：只在忙碌时被 `TuiState::tick` 推进；`ConsoleRequest::RunState { running: false }` 时**归零**（用户故事 13）。渲染读 `state.busy().then_some(state.pulse)` —— 忙碌与否只由循环说（见 `TuiState::busy` 的 rustdoc），脉冲**不自己推断**。
- **节拍 `PULSE_FRAME = 100ms`**：`tokio::time::interval` **常驻一个值**、`MissedTickBehavior::Delay`，`select!` 里那条臂带 `if state.busy()` 守卫，所以**空闲时不 arm、不 wake**（用户故事 12）。用 interval 而不是「每次循环一个 `sleep`」：后者在事件洪流里会被每次循环重置，脉冲再也不前进，而动画恰恰最该在那种时候在动。
- **可见性**（用户故事 11）：mark 只在左栏的宽档（`w ≥ 120`）且高度够（`h ≥ 16`）时画，所以动画只在那里可见；窄档的文字身份行**不**跟着变色。窄屏上脉冲照旧 tick，但帧差为空 —— 不画不变，代价是每 100ms 一次空 diff，只在忙碌时。
- **帧差**：色环之外没有任何像素变化，所以每帧只写 mark 那 38×5 个格子，一次 `BeginSynchronizedUpdate` 里一笔。

### §3 不变量与不动的东西

- **不动**：事件 schema 与 `project()`（用户故事 17）、模型可见文本（ADR 0001）、plain / headless 渲染器、键位表、`/` 菜单、详情覆盖层、回合条、语法高亮。
- **不新增措辞**：这次没有新的中文串 —— 颜色与行数是画笔和布局的事。`src/render/wording.rs` 只读不改。
- **不做**：mark 之外的任何忙碌动画（状态字转轮、输入框律动、转录底部动效）、窄档身份行变色、输入区的独立边框与底部对齐（见 `Out of Scope`）。

### §4 与旧决议的关系（回改）

`.scratch/tui-sidebar/spec.md` §8 与 `docs/render.md` 都写着「三条来源、没有定时器」，并逐条论证过「没有任何东西等着被注意到」。那个论证在当时是对的，本 spec 给它加一个**第四种来源**：**只有忙碌时才存在的脉冲定时器**。两处按本 spec 回改，并写明「空闲时它仍然不存在」这条边界 —— 否则下一个人会把定时器当成可以随便加东西的地方（票 03）。

## Testing Decisions

- **布局（`tests/render_layout.rs`，`TestBackend` 接缝不变）**：矩阵的转录行数改成新账（40×10 → 1、80×14 → 4、其余 24 行档 → 14、174×50 → 40）；空草稿在 80×24 下输入区仍占 3 行（转录 14）且 `> ` 在第 1 行、后两行是空行；3 行草稿给同样的 14 行（**几何不再变化**，这是本票的核心断言）；5 行草稿 → 转录 12（仍然会长）；11 行草稿 → 封顶 10 行、转录 7。
- **脉冲（同一接缝）**：`RunState { running: true }` 后 `tick()` 一次 → mark 5 行**全部**是 `PULSE_PALETTE[1]`；tick 满 12 次回到 `PULSE_PALETTE[0]`；空闲态 → 顶部 `LightMagenta`、底行 `Magenta`（既有的 `the_mark_is_lit_from_above_and_only_on_the_wide_rung` 保留，作为**空闲**的断言）。
- **状态（`tests/render_tui.rs`）**：`tick()` 只在 `running` 时推进并置脏；空闲 `tick()` 不动（`is_dirty()` 保持原值）；`RunState { running: false }` 把脉冲归零。
- **窄屏**：`w < 120` 或 `h < 16` 没有 mark，脉冲照旧 tick 但一帧都不改像素。
- **手工清单**（`docs/tui-manual-checklist.md`）：新增两条 —— 真终端里色环读起来是「在动」还是「在闪」（含 100ms 在慢终端上会不会被自己拖慢）、3 行输入区的光标位置。
- **基线**：`cargo test` 全绿；`cargo clippy --all-targets` 干净；`cargo fmt --check` 只留 `src/context/repo_map.rs` 与 `tests/repo_map.rs` 两处既有漂移（不要顺手格式化那两个文件）。

## Out of Scope

- **mark 之外的忙碌动画**：状态字前的转轮、输入框里的方块律动、转录底部的「思考中」动效 —— 本轮三选一里选了 mark 色环，其余不取。
- **窄档（`80 ≤ w < 120`）的文字身份行跟着变色**：用户明确接受「动画只在宽屏可见」。
- **输入区的独立边框**（3 行内容 + 2 行边框）与**草稿底部对齐**：都被否掉了，界面里仍然只有一圈外框，草稿仍然从顶部写。
- **`轨迹` / `文件` 页、任何键位新增、plain / headless 渲染器**。
- **把脉冲做成可配置**（`[tui] pulse_ms` / 关掉动画）：没有需求，等真有人嫌晃眼再说。
