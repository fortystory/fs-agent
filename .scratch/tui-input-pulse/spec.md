# 输入区三行 + 「正在工作」的下落短横

Status: ready-for-agent（一次 grilling 的折叠 + 两轮真机反馈；实现票 `01`–`05`）

- **来源**：用户口头的两条优化需求（「把文本输入框加到 3 行高」「加一个动画表示 fs-agent 正在工作」）+ 三轮问答，以及看到真机之后的两句反馈（票 04「闪的太快」、票 05「变的很突然，先不让它变色了，代码留着」）。**不是** wayfinder 图，也没有 prototype：这几条都不需要可运行的答案。
- **术语**：`CONTEXT.md`（§渲染）新增 **下落短横（FallingDash）** 与 **忙碌脉冲（Pulse）**（票 06 之前叫「转动短横」，随实现改名）。
- **与旧决议的关系**：`.scratch/tui-sidebar/spec.md` §8 与 `docs/render.md` 都写着「这个 `select!` 是三条来源、**没有定时器**」。本 spec **部分推翻**那一条 —— 定时器回来，但只为脉冲存在，且只在一次运行在飞时 arm（§2、§4）。
- **落点**：`src/render/tui.rs`、`src/render/layout.rs`、`src/render/wording.rs`、`tests/`、`README.md`、`docs/render.md`、`docs/tui-manual-checklist.md`、`CONTEXT.md`。

## Problem Statement

1. **输入区只有一行高时，落笔区会跟着草稿跳。** 现在 `输入行数 = clamp(草稿折行数, 1, 10)`：空草稿时是一条线，敲进三行草稿就长成三条，转录被顶掉两行。用户想要一块**稳定的、能看见自己写了三行**的地方 —— 写多行提示词是这个 CLI 的常态。
2. **忙碌态只有一个静态标点。** 界面上唯一说「我在干活」的东西是提示行左侧那两个汉字 `工作中`，而宽屏上视线最常停留的地方是左栏顶部的 mark —— 它现在完全静止。一个静止的程序和一个死了的程序在屏幕上没有区别。

## Solution

- **输入区最少 3 行**（**不带**自己的边框）：草稿折行数不足 3 时输入区仍占 3 行，超过 3 时照旧长到 10 行上限。
- **「正在工作」由 `fs-agent` 里那个短横表示**：它**往下落** —— 形状始终是一条 `▀▀▀▀`，每 250ms 落一行、1.25 秒落到底，再从最上面出现；宽档落过 mark 自己的五行，窄档落过文字身份行里那一格能表达的三个高度。
  > **实现期修正（票 04–07）**：忙碌信号换过四次，每次都是真机反馈。① 六个色相 × 明/暗两支 = 12 帧 @100ms → 读作**闪**；② 六个亮色相 = 6 帧 @400ms → 读作**突然**；③ 短横旋转（`─ ╲ │ ╱`）→ 用户判为「不太好看」；④ 就这样：**一条横线往下落**。色环代码按用户要求留在仓库里但撤出屏幕（§2）。

```
│ 左栏：mark（忙碌时整块在色环上走）         │ 转录
│                                            │   （h − 7 − 输入行数）
│ ── tab 条 ──                               ├── 状态行上分隔线 ──
│                                            │ 状态行：模型 … │ 模式 … │ 上下文 …%
│                                            ├── 输入区上分隔线 ──
│                                            │ 输入区（3–10 行，草稿在顶部）
│                                            ├── 提示行上分隔线 ──
│                                            │ 提示行（就绪 / 工作中 · 快捷键 · 退出）
```

## User Stories

### A. 输入区三行

1. 作为用户，我想让输入区至少 3 行高，以便我一次能看见三行草稿，而不必让框跟着字长高。
2. 作为用户，我想让输入区在第 4 行才开始长高、并照旧在 10 行封顶，以便行数账仍然简单。
3. 作为用户，我想让这 3 行只是「有地方写」，不引来第二圈边框，以便界面里仍然只有一圈外框。
4. 作为用户，我想在终端太矮（40×10）时优先保住转录的那一行，以便输入区的最小高度不把转录挤没。
5. 作为用户，我想让草稿仍然从输入区**顶部**开始写，以便光标位置与今天完全一样。
6. 作为用户，我想让多行草稿的 `Esc` / 粘贴 / 光标行为一个字节都不变，以便这次只动几何、不动编辑器。

### B. 忙碌脉冲

7. 作为用户，我想在 fs-agent 工作时看到 `fs-agent` 里那个短横在**往下落**，以便一眼知道它还在跑，而不是卡住了。
8. 作为用户，我想让它每 250ms 落一行、1.25 秒落到底再从最上面出现，以便它读起来像「在动」—— 三版别的动法（闪、突然、旋转）都在真机上被判掉了（票 04–06）。
9. 作为用户，我想让它的**形状始终是那条 `▀▀▀▀`**，以便「在动」不等于「换了个字形」（票 06/07 的教训）。
10. 作为用户，我想让颜色不再参与这个信号，以便 mark 的品红渐变在忙碌时也照旧。
11. 作为用户，我想在空闲时看到它回到**原来那一行**（mark 的第 3 行），以便静止的 mark 与动画出现之前逐字节相同。
12. 作为用户，我想让这个信号**两档都看得到**：宽档落过 mark 的五行，窄档（`80 ≤ w < 120`）落过文字身份行里那一格；只有无左栏（`w < 80`）才没有。
13. 作为用户，我想让空闲时没有任何定时器在跑（CPU 不动、不空转），以便这个动画不变成一台常开的马达。
14. 作为用户，我想让运行结束时短横回到静止那一行，以便下一次运行从最上面重新落。
15. 作为用户，我想让色环的**代码留着**（用户明确要求），但**不在屏幕上**，以便将来想要颜色信号时还有起点。

### C. 不变量

14. 作为用户，我想让所有人类可见文案仍然只由措辞层产生，以便界面改动不把字符串散进渲染代码。
15. 作为用户，我想让模型可见文本（system prompt、投影前缀、`AgentError.message`、工具结果）一个字节都不变，以便前缀缓存不被废掉。
16. 作为用户，我想让 plain / headless 两个渲染器完全不受影响，以便管道化照旧可用。
17. 作为用户，我想让事件 schema 与投影完全不动（脉冲是纯渲染器状态），以便回落与重放不受影响。
18. 作为用户，我想让 `cargo test` 全绿、`cargo clippy --all-targets` 干净、`cargo fmt --check` 只留既有的两处漂移，以便改动可验收。

## Implementation Decisions

### §1 输入区：最少三行

- **落点**：`layout::plan`。`输入行数 = clamp(草稿折行数, MIN_INPUT_ROWS = 3, max_input_rows(h))`，`max_input_rows` 照旧 = `min(10, h − CHROME − 1)`（转录底线 1 行）。
- **地板优先级：转录底线 > 输入区最小高度。** 40×10 下 `max_input_rows = 2`，所以那一档输入区是 **2 行**、转录 1 行；`h ≥ 12` 的每一档都是 3 行。用户故事 4 就是这么落地的。
- **草稿仍在顶部对齐**：第 1 行是 `> `，后面是留白；`editor::Input::view` 的语义不改（空草稿仍然只产出一行，留白由 `Paragraph` 铺满输入区矩形）。
- **不多画边框**（用户故事 3）：输入区上下的共享分隔线由外壳画（`draw_shell` 的三条横线之一），这次不新增 `Block`。
- **转录行数的新账**（`h − 7 − 输入行数`）：

  | 尺寸 | 输入行数 | 转录行数 | 旧值 |
  | --- | --- | --- | --- |
  | 40×10 | 2（地板，转录底线赢） | 1 | 2 |
  | 80×14 | 3 | 4 | 6 |
  | 40/60/80/100/120×24 | 3 | 14 | 16 |
  | 174×50 | 3 | 40 | 42 |

### §2 忙碌信号：`fs-agent` 里那个短横在往下落

- **下落短横（FallingDash）**：**形状不变、只有位置在变** —— 一条 `▀▀▀▀` 每 250ms 往下一行，落到底再从最上面出现（票 07）。它是**唯一**的忙碌信号，两档身份都戴它：
  - **宽档**：落过 mark 自己的**五行**（那一格就是 mark 的五行 —— mark 拼的是 `fs-agent`，八个 4 列字形格、中间隔一列空格，短横是第三格，占第 10…13 列；除了第 3 行那一格是空的，**四列在每一行都是空白**，正好腾出一条下落的路）。帧 `n` 落在第 `n % 5` 行，字形恒为 `▀`（`DASH_BAR`）。
  - **窄档**（`80 ≤ w < 120`）：文字身份行 `fs-agent 0.1.0` 里那一格 —— 一行里没有五行可走，所以落成**一个格子里能表达的三个高度**：`wording::DASH_FALL = ['▀', '▀', '█', '▄', '▄']`（高、高、满、低、低），下标与 mark 同一套帧（都是 `phase % 5`）。
  - **无左栏**（`w < 80`）：什么都没有，这是唯一没有信号的档。
  - **静止的 mark 一字不改**（票 06，用户纠正）：`None`（没有运行）映射到 `rows.len() / 2` —— mark 原来画短横的第 3 行，也就是 `logo_lines` 自己那四列。**一条回归测试直接拿 `logo_lines` 的第 10…13 列去比**。票 05 曾把静止短横换成线 `────`、票 06 曾让它旋转，都被否掉了：只在忙碌时出现的动画不许改掉静止时的样子。
- **颜色撤出屏幕**：忙碌时 mark 不再变色 —— 静止的品红渐变（上 4 行 `LightMagenta`、底行 `Magenta`）**始终**如此。`PULSE_PALETTE`（6 个亮色相）与它的性质测试**保留**，rustdoc 写明「现在不在屏幕上、留着备用」，另有一条测试盯着**它没有偷偷回屏**（票 05；用户原话是「先不让它变色了，代码留着」）。
- **节拍 `PULSE_FRAME = 250ms`**：一落 1.25 秒。
- **脉冲计数器 `TuiState.pulse: u64`**：只在忙碌时被 `TuiState::tick` 推进，`RunState { running: false }` 时**归零**；渲染读 `state.busy().then_some(state.pulse)` —— 忙碌与否只由循环说，脉冲**不自己推断**。
- **时钟**：`tokio::time::interval` 常驻一个值、`MissedTickBehavior::Delay`，`select!` 里那条臂带 `if state.busy()` 守卫，所以**空闲时不 arm、不 wake**。用 interval 而不是「每次循环一个 `sleep`」：后者在事件洪流里会被每次循环重置，短横会在最该落的时候停住。
- **帧差**：下落之外没有任何像素变化，所以每帧只写那一格（4 格）。

### §3 不变量与不动的东西

- **不动**：事件 schema 与 `project()`（用户故事 17）、模型可见文本（ADR 0001）、plain / headless 渲染器、键位表、`/` 菜单、详情覆盖层、回合条、语法高亮。
- **措辞层只加字形**：票 01–04 没往 `wording` 里加过东西；票 05/06/07 加了 `DASH_FALL` 与 `identity_falling`（曾叫 `DASH_TURN` / `identity_turning`，随实现改名）—— 那五个高度是**可见字形**，按仓库的规矩归措辞层；`identity_falling` 从 `identity()` 换字符而来，前缀与版本号仍只有一份拼法。这几票仍然**没有一个新中文串**。
- **不做**：输入区以外的任何忙碌动画（状态字转轮、输入框律动、转录底部动效 —— 颜色信号两版都退役了，见 `Out of Scope`）、输入区的独立边框与底部对齐。

### §4 与旧决议的关系（回改）

`.scratch/tui-sidebar/spec.md` §8 与 `docs/render.md` 都写着「三条来源、没有定时器」，并逐条论证过「没有任何东西等着被注意到」。那个论证在当时是对的，本 spec 给它加一个**第四种来源**：**只有忙碌时才存在的脉冲定时器**。两处按本 spec 回改，并写明「空闲时它仍然不存在」这条边界 —— 否则下一个人会把定时器当成可以随便加东西的地方（票 03）。

## Testing Decisions

- **布局（`tests/render_layout.rs`，`TestBackend` 接缝不变）**：矩阵的转录行数改成新账（40×10 → 1、80×14 → 4、其余 24 行档 → 14、174×50 → 40）；空草稿在 80×24 下输入区仍占 3 行（转录 14）且 `> ` 在第 1 行、后两行是空行；3 行草稿给同样的 14 行（**几何不再变化**，这是本票的核心断言）；5 行草稿 → 转录 12（仍然会长）；11 行草稿 → 封顶 10 行、转录 7。
- **下落短横（同一接缝）**：短横那一格（120×24 下 mark 的第 10…13 列 × 五行）逐帧读出来当文字看，五帧写成**五段字符画**（同一行 `▀▀▀▀` 从第 1 行挪到第 5 行），两圈确认回到第一行；**每帧形状相同**这条把「旋转」「换字形」彻底排除；同时逐帧断言 mark 的五行颜色**始终**是静止渐变（「不再变色」的回归断言）。
- **静止那一格逐字符等于 `logo_lines`**：直接把 `logo_lines()` 的第 10…13 列拿来比 —— 这条是「不许再改静止字形」的回归断言。
- **窄档也落**：100×24 忙碌时身份行是 `fs{X}agent {版本}`，`X` 依次是 `▀ ▀ █ ▄ ▄`；空闲时仍是 `fs-agent {版本}`（启动检查脚本的锚点）。
- **色环留在屏幕外**：palette 仍是 6 项、每项都是 `Light*`，且在 174×50 的忙碌帧里**没有一个格子**穿 ring 上那些不在 mark 渐变里的颜色。
- **状态（`tests/render_tui.rs`）**：`tick()` 只在 `running` 时推进并置脏；空闲 `tick()` 不动（`is_dirty()` 保持原值）；`RunState { running: false }` 把脉冲归零。
- **无左栏**：`w < 80` 时既没有 mark 也没有身份行，脉冲照旧 tick 但两帧逐格相等（票 05 之后 100×24 不再属于这一档 —— 窄档身份行也转）。
- **手工清单**（`docs/tui-manual-checklist.md` ⑯）：真终端里短横转起来是否读作「在动」、每帧亮度是否不变、大量输出时是否照旧在转、空闲 CPU 是否接近 0、停下是否回到静止、3 行输入区的光标位置。
- **基线**：`cargo test` 全绿；`cargo clippy --all-targets` 干净；`cargo fmt --check` 只留 `src/context/repo_map.rs` 与 `tests/repo_map.rs` 两处既有漂移（不要顺手格式化那两个文件）。

## Out of Scope

- **颜色信号**：`PULSE_PALETTE` 的色环两版（12 帧明暗交替 @100ms、6 帧亮色相 @400ms）都在真机上被否掉，票 05 把它撤出屏幕。**代码按用户要求保留**，但不再有任何东西渲染它 —— 想再上屏得先解决「整块同时换色显得突然」这个问题。
- **短横的其他动法**：旋转（票 05/06 的四个朝向）、换字形（`▚ █ ▞`、`─ ╲ │ ╱`）、左右移动、落到底停一拍 —— 都试过或议过，最终只要「一条 `▀▀▀▀` 从上往下落」。
- **mark 之外的忙碌动画**：状态字前的转轮、输入框里的方块律动、转录底部的「思考中」动效 —— 都不取。
- **无左栏（`w < 80`）时的忙碌信号**：那一档没有任何身份可转，界面里唯一说「在跑」的仍是提示行的 `工作中`。
- **输入区的独立边框**（3 行内容 + 2 行边框）与**草稿底部对齐**：都被否掉了，界面里仍然只有一圈外框，草稿仍然从顶部写。
- **`轨迹` / `文件` 页、任何键位新增、plain / headless 渲染器**。
- **把脉冲做成可配置**（`[tui] pulse_ms` / 关掉动画）：没有需求，等真有人嫌晃眼再说。
