# 输入区三行 + 提示符色相

Status: ready-for-agent（一次 grilling 的折叠 + 四轮真机反馈；实现票 `01`–`08`）

- **来源**：用户口头的两条优化需求（「把文本输入框加到 3 行高」「加一个动画表示 fs-agent 正在工作」）+ 三轮问答，以及看到真机之后的四句反馈（票 04「闪的太快」、票 05「变的很突然，先不让它变色了，代码留着」、票 07「也不太好看，改成一条横线往下落」、票 08「先不动这个 mark 了，下落先关了；我找了个脚本，修改提示符 `>` 的颜色」）。**不是** wayfinder 图，也没有 prototype：这几条都不需要可运行的答案。
- **术语**：`CONTEXT.md`（§渲染）新增 **提示符色相（PromptHue）**、**脉冲（Pulse）**、**下落短横（FallingDash）**（最后一个标为已退出屏幕）。
- **与旧决议的关系**：`.scratch/tui-sidebar/spec.md` §8 与 `docs/render.md` 都写着「这个 `select!` 是三条来源、**没有定时器**」。本 spec **推翻**那一条：定时器回来（票 02），先只在忙碌时 arm（票 02–07），再因提示符常驻而**改成常开**（票 08，§2b）。
- **落点**：`src/render/tui.rs`、`src/render/layout.rs`、`src/render/wording.rs`、`tests/`、`README.md`、`docs/render.md`、`docs/tui-manual-checklist.md`、`CONTEXT.md`。

## Problem Statement

1. **输入区只有一行高时，落笔区会跟着草稿跳。** 现在 `输入行数 = clamp(草稿折行数, 1, 10)`：空草稿时是一条线，敲进三行草稿就长成三条，转录被顶掉两行。用户想要一块**稳定的、能看见自己写了三行**的地方 —— 写多行提示词是这个 CLI 的常态。
2. **忙碌态只有一个静态标点。** 界面上唯一说「我在干活」的东西是提示行左侧那两个汉字 `工作中`，而宽屏上视线最常停留的地方是左栏顶部的 mark —— 它现在完全静止。一个静止的程序和一个死了的程序在屏幕上没有区别。

## Solution

- **输入区最少 3 行**（**不带**自己的边框）：草稿折行数不足 3 时输入区仍占 3 行，超过 3 时照旧长到 10 行上限。
- **界面里唯一在动的东西是输入区的提示符**：`❱ ` 的颜色**在 agent 工作时**走 —— 色相每 3.3 秒绕一圈、饱和度同时以 2.1 秒的周期呼吸（24 位真彩，参数取自用户自用的一条脚本）；**轮到用户打字时它停在静止色**。
- **左栏完全静止**：mark 与文字身份行都不动（§2，票 08）。
  > **实现期修正（票 04–09）**：忙碌信号换了六次，每次都是真机反馈。① 六个色相 × 明/暗两支 = 12 帧 @100ms → 读作**闪**；② 六个亮色相 = 6 帧 @400ms → 读作**突然**；③ 短横旋转（`─ ╲ │ ╱`）→ 「不太好看」；④ 一条横线往下落 → 「也不太好看」；⑤ mark 不动、提示符一直变色 → 「在 agent 工作时才变色，用户输入时不变色」；⑥ **就这样**：提示符只在一次运行在飞时走色，静止时停在固定色。色环与下落两套代码都按用户要求留在仓库里、都撤出屏幕。

```
│ 左栏：mark（忙碌时整块在色环上走）         │ 转录
│                                            │   （h − 7 − 输入行数）
│ ── tab 条 ──                               ├── 状态行上分隔线 ──
│                                            │ 状态行：模型 … │ 模式 … │ 上下文 …%
│                                            ├── 输入区上分隔线 ──
│                                            │ 输入区（3–10 行，草稿在顶部）
│                                            ├── 提示行上分隔线 ──
│                                            │ 提示行（就绪 / 工作中 · 快捷键 · 退出）
```

## User Stories

### A. 输入区三行

1. 作为用户，我想让输入区至少 3 行高，以便我一次能看见三行草稿，而不必让框跟着字长高。
2. 作为用户，我想让输入区在第 4 行才开始长高、并照旧在 10 行封顶，以便行数账仍然简单。
3. 作为用户，我想让这 3 行只是「有地方写」，不引来第二圈边框，以便界面里仍然只有一圈外框。
4. 作为用户，我想在终端太矮（40×10）时优先保住转录的那一行，以便输入区的最小高度不把转录挤没。
5. 作为用户，我想让草稿仍然从输入区**顶部**开始写，以便光标位置与今天完全一样。
6. 作为用户，我想让多行草稿的 `Esc` / 粘贴 / 光标行为一个字节都不变，以便这次只动几何、不动编辑器。

### B. 忙碌脉冲

7. 作为用户，我想在输入区看到 `❱ ` 而不是 `> `，并且它的颜色一直在变，以便即使我只是在想题，界面也看得出是活的。
8. 作为用户，我想让那个颜色走得**慢**（色相 3.3 秒一圈）并同时轻轻呼吸（约 2.1 秒一个周期），以便它读起来像呼吸，而不是闪或跳。
9. 作为用户，我想让它用 24 位真彩，以便色相在走的时候看不出台阶。
10. 作为用户，我想让提示符**两列还是两列**（`❱` 与 `>` 同宽），以便换一个字形不移动任何人的文字。
11. 作为用户，我想让左栏**完全静止**（mark 与身份行都不动），以便界面上只有一处动画。
12. 作为用户，我想让提示符**只在 agent 工作时**变色，轮到我自己打字时它**停住**，以便颜色是「它在想」的信号，而不是在我手下一直晃的东西。
13. 作为用户，我想让静止色**每次都是同一个**（脚本第 0 帧那个颜色），以便我认得出「它休息的样子」，也分得清「该我说了」。
14. 作为用户，我想让色环与下落短横的**代码留着**（用户明确要求），但都不在屏幕上，以便将来想要它们时还有起点。

### C. 不变量

14. 作为用户，我想让所有人类可见文案仍然只由措辞层产生，以便界面改动不把字符串散进渲染代码。
15. 作为用户，我想让模型可见文本（system prompt、投影前缀、`AgentError.message`、工具结果）一个字节都不变，以便前缀缓存不被废掉。
16. 作为用户，我想让 plain / headless 两个渲染器完全不受影响，以便管道化照旧可用。
17. 作为用户，我想让事件 schema 与投影完全不动（脉冲是纯渲染器状态），以便回落与重放不受影响。
18. 作为用户，我想让 `cargo test` 全绿、`cargo clippy --all-targets` 干净、`cargo fmt --check` 只留既有的两处漂移，以便改动可验收。

## Implementation Decisions

### §1 输入区：最少三行

- **落点**：`layout::plan`。`输入行数 = clamp(草稿折行数, MIN_INPUT_ROWS = 3, max_input_rows(h))`，`max_input_rows` 照旧 = `min(10, h − CHROME − 1)`（转录底线 1 行）。
- **地板优先级：转录底线 > 输入区最小高度。** 40×10 下 `max_input_rows = 2`，所以那一档输入区是 **2 行**、转录 1 行；`h ≥ 12` 的每一档都是 3 行。用户故事 4 就是这么落地的。
- **草稿仍在顶部对齐**：第 1 行是 `> `，后面是留白；`editor::Input::view` 的语义不改（空草稿仍然只产出一行，留白由 `Paragraph` 铺满输入区矩形）。
- **不多画边框**（用户故事 3）：输入区上下的共享分隔线由外壳画（`draw_shell` 的三条横线之一），这次不新增 `Block`。
- **转录行数的新账**（`h − 7 − 输入行数`）：

  | 尺寸 | 输入行数 | 转录行数 | 旧值 |
  | --- | --- | --- | --- |
  | 40×10 | 2（地板，转录底线赢） | 1 | 2 |
  | 80×14 | 3 | 4 | 6 |
  | 40/60/80/100/120×24 | 3 | 14 | 16 |
  | 174×50 | 3 | 40 | 42 |

### §2 左栏静止（下落与色环都退出屏幕）

- **mark 与文字身份行都不动**（票 08）：`draw_sidebar_identity` 传 `mark_lines(None)` 并用 `wording::identity()`，左边那一栏就是这个动画出现之前的样子 —— mark 的五行走它原来的品红渐变（上 4 行 `LightMagenta`、底行 `Magenta`），短横停在 `logo_lines` 自己那一行。
- **代码留着、测试跟着走**：`mark_lines(frame)`（含 `DASH_BAR` 与那张逐步下落的行表）、`PULSE_PALETTE`、`wording::DASH_FALL` / `identity_falling` 全部保留。离开屏幕的代码**不能靠集成测试驱动**，所以：
  - 下落的逐帧断言搬进 `src/render/tui.rs` 的 `#[cfg(test)] mod tests`（`mark_lines(Some(n))` 每帧一行、形状恒为 `▀▀▀▀`、第 `n % 5` 行）；
  - `identity_falling` 的用例留在 `tests/wording.rs`（它是 pub 的），注释里写明「今天不在渲染路径上」；
  - 集成侧反过来多一条**「它没有偷偷回屏」**：跑一个回合 tick 若干帧，mark 的五格颜色与短横那一格逐帧相同，且那几格不等于落到底/落到顶的形状。
- **`PULSE_PALETTE`** 与下落代码同命：留着、有人看着、别接回渲染路径。

### §2b 提示符色相：`❱ ` 一直在变色

- **字形**：`editor::PROMPT = "❱ "`。`❱`（U+2771）在本宽度层算 **1 列**，所以 `prompt_columns()` 仍是 2 —— 布局预留、换行缩进、光标列算法一个字节都不用改。**风险**：终端若把模糊宽度字符按双列画（部分 CJK 配置），提示符会多占一列；手工清单里有一条专门查这个，真出现了只改 `editor::PROMPT` 一个常量。
- **一处可上色的接缝**：`editor::Input::view` 把每行的引导（第 1 行是提示符、其余行是等宽缩进）与正文拆成**两个 span**，画笔才有一处可以只给提示符上色。字符内容与列数不变，`tests/render_editor.rs` 的 `rows()` 把 span 拼回整串，用例因此不受影响。
- **颜色**（画笔里的纯函数 `prompt_colour(frame) -> Color`）：色相每秒 **0.3** 圈（约 3.3 秒一轮）、饱和度 `0.55 + 0.2·sin(每秒 3.0 弧度)`（约 2.1 秒一个周期）、明度 **0.85**；HSV→RGB 与 `colorsys.hsv_to_rgb` 同样取整，所以**同一时刻的颜色与用户脚本一致**（脚本 0.3 秒时的 `(216, 146, 63)` 就是我们第 5 帧）。输出 `Color::Rgb` —— 仓库里第一处 24 位真彩，理由是色相走 16 色的名字会看出台阶。
- **节拍 `PULSE_FRAME = 60ms`**：约 16 帧/秒，肉眼看是连续变色。
- **只在一次运行在飞时走色**（票 09，把票 08 的「常开」收回去）：`select!` 那条臂带 `if state.busy()` 守卫，`tick()` 内部同样判定忙碌，`RunState { running: false }` 把 `pulse` **归零**。
  - **静止色 = 第 0 帧**（脚本那个 `(216, 97, 97)`）：空闲时提示符恒为它，每次运行也从它开始走。取舍在票 09 里写清：换成「停在运行时最后一色」（不归零）只要删一行，但那样静止色每次都不一样，认不出「它休息的样子」。
  - **代价换回来的东西**：空闲时那台时钟**不存在** —— 没有唤醒、没有重画，键盘是唯一能唤醒循环的东西；`interval` + `MissedTickBehavior::Delay` 照旧，所以事件洪流也不会让颜色停。
- **只染提示符那一格**：让每行引导都上色是省事，但滚动到草稿中部时那几格是缩进空格 —— 按「这一行 span 的内容就是 `PROMPT`」判定，只有真的是提示符时才上色（滚动后提示符不在屏幕上，也就没有动画，与它不在屏幕上一致）。

### §3 不变量与不动的东西

- **不动**：事件 schema 与 `project()`、模型可见文本（ADR 0001）、plain / headless 渲染器、键位表、`/` 菜单、详情覆盖层、回合条、语法高亮、mark 的静止字形（票 06 的教训：只在动画里出现的东西不许改掉静止的样子）。
- **措辞层只加字形**：票 01–04 没往 `wording` 里加过东西；票 05/06/07 加了 `DASH_FALL` 与 `identity_falling`（曾叫 `DASH_TURN` / `identity_turning`，随实现改名）—— 那五个高度是**可见字形**，按仓库的规矩归措辞层；`identity_falling` 从 `identity()` 换字符而来，前缀与版本号仍只有一份拼法。这几票仍然**没有一个新中文串**。
- **不做**：输入区以外的任何忙碌动画（状态字转轮、输入框律动、转录底部动效 —— 颜色信号两版都退役了，见 `Out of Scope`）、输入区的独立边框与底部对齐。

### §4 与旧决议的关系（回改）

`.scratch/tui-sidebar/spec.md` §8 与 `docs/render.md` 都写着「三条来源、没有定时器」，并逐条论证过「没有任何东西等着被注意到」。那个论证在当时是对的，本 spec 给它加一个**第四种来源**：**只有忙碌时才存在的脉冲定时器**。两处按本 spec 回改，并写明「空闲时它仍然不存在」这条边界 —— 否则下一个人会把定时器当成可以随便加东西的地方（票 03）。

## Testing Decisions

- **布局（`tests/render_layout.rs`，`TestBackend` 接缝不变）**：矩阵的转录行数改成新账（40×10 → 1、80×14 → 4、其余 24 行档 → 14、174×50 → 40）；空草稿在 80×24 下输入区仍占 3 行（转录 14）且 `> ` 在第 1 行、后两行是空行；3 行草稿给同样的 14 行（**几何不再变化**，这是本票的核心断言）；5 行草稿 → 转录 12（仍然会长）；11 行草稿 → 封顶 10 行、转录 7。
- **提示符**：`120×24` 的帧里按屏幕找 `❱`（不按矩形），断言那一格的前景是 `Color::Rgb(216, 97, 97)`（脚本第 0 帧的颜色）、tick 之后每帧都不同；正文那一格仍是终端自己的前景 + 粗体（**提示符的颜色不进草稿**）。
- **一帧只动那两个格子**：`120×24` / `60×24` / `40×10` 三档各取相邻两帧，逐格比对，变化的格子必须**恰好**是提示符占的两格（这条同时守住「mark 静止」与「没有别的东西在动」）。
- **mark 静止**：跑一个回合 tick 若干帧，短横那一格逐帧相同、且逐字符等于 `logo_lines` 的第 10…13 列；mark 五行的颜色也逐帧不变；并断言它**不等于**落到底/落到顶的形状。
- **窄档身份行静止**：100×24 忙碌 + tick，恒为 `fs-agent {版本}`。
- **提示符两列**：`editor::PROMPT == "❱ "`、`prompt_columns() == 2`（`tests/render_editor.rs`）。
- **单元测试**（`src/render/tui.rs`）：下落逐帧的形状（留在屏幕外的代码自己看着）；`prompt_colour` 在脚本的若干时刻与 `colorsys` 的输出逐字节一致；`hsv_to_rgb` 的单色与色轮闭合。
- **色环留在屏幕外**：palette 仍是 6 项、每项都是 `Light*`，且在 174×50 的忙碌帧里**没有一个格子**穿 ring 上那些不在 mark 渐变里的颜色。
- **状态（`tests/render_tui.rs`）**：`tick()` 只在 `running` 时推进并置脏；空闲 `tick()` 不动（`is_dirty()` 保持原值）；`RunState { running: false }` 把脉冲归零。
- **无左栏**：`w < 80` 时既没有 mark 也没有身份行，脉冲照旧 tick 但两帧逐格相等（票 05 之后 100×24 不再属于这一档 —— 窄档身份行也转）。
- **手工清单**（`docs/tui-manual-checklist.md` ⑯）：真终端里短横转起来是否读作「在动」、每帧亮度是否不变、大量输出时是否照旧在转、空闲 CPU 是否接近 0、停下是否回到静止、3 行输入区的光标位置。
- **基线**：`cargo test` 全绿；`cargo clippy --all-targets` 干净；`cargo fmt --check` 只留 `src/context/repo_map.rs` 与 `tests/repo_map.rs` 两处既有漂移（不要顺手格式化那两个文件）。

## Out of Scope

- **颜色信号**：`PULSE_PALETTE` 的色环两版（12 帧明暗交替 @100ms、6 帧亮色相 @400ms）都在真机上被否掉，票 05 把它撤出屏幕。**代码按用户要求保留**，但不再有任何东西渲染它 —— 想再上屏得先解决「整块同时换色显得突然」这个问题。
- **左栏的任何动法**：旋转、换字形、下落、变色 —— 票 04–07 各试过一版，全部撤下（票 08）。将来想动 mark，先看 `mark_lines` 与它旁边那条单元测试。
- **提示符的其它动法**：闪、跳色、固定 16 色、把草稿一起染色、给颜色加配置项 —— 都不取。
- **无左栏（`w < 80`）时的左栏信号**：本来就没有左栏，不需要。
- **mark 之外的忙碌动画**：状态字前的转轮、输入框里的方块律动、转录底部的「思考中」动效 —— 都不取。
- **无左栏（`w < 80`）时的忙碌信号**：那一档没有任何身份可转，界面里唯一说「在跑」的仍是提示行的 `工作中`。
- **输入区的独立边框**（3 行内容 + 2 行边框）与**草稿底部对齐**：都被否掉了，界面里仍然只有一圈外框，草稿仍然从顶部写。
- **`轨迹` / `文件` 页、任何键位新增、plain / headless 渲染器**。
- **把脉冲做成可配置**（`[tui] pulse_ms` / 关掉动画）：没有需求，等真有人嫌晃眼再说。
