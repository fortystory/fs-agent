# 模型可见的说明与状态事件

Type: implement
Status: done
Blocked by: 03

> 规格：`.scratch/sandbox/spec.md` §8（记录与可见性）。

## 目标

模型知道自己在沙箱里（这样它被拒之后不会反复试）；审计者能在事件流里看到当时的沙箱状态。

## 落点

`src/tools/bash.rs`（工具描述）、`src/render/wording.rs`、`src/events.rs`（log-only 事件）、`tests/` 下的措辞与事件测试。

## 具体行为

1. **`bash` 工具描述加一句**（中文，模型可见 —— ADR 0005）：命令跑在一个沙箱里——工作区与一列缓存目录可写，区外只读；**被拒绝说明越界了，不是命令写错了**；**`/tmp` 每次调用都是新的**，同一条命令内可用、跨命令不保留。它是请求前缀的一部分，所以是常量成本、一次定死，不随会话变化。
2. **状态事件**：会话组装完成、探测有结果之后，追加一条 **log-only** 事件（不进 `messages`），字段至少含：模式（`bwrap` / `off`）与不可用时的原因。形状照着现有的 log-only 事件来。
3. **界面不显示**（spec §8）：TUI 状态行与左栏都不动——沙箱在一个会话内基本不变，而左栏已经很挤。
4. `wording.rs` 收全部给人看的文案（探测失败、两条出路、状态事件的描述文本）。

## 测试

- `bash` 的工具描述含那句说明（逐字断言）；
- 一次新会话的事件流里有且只有一条沙箱状态事件，`mode` 与探测结果一致；
- 那条事件**不改变**投影出来的 `messages` —— 与不带它时逐字相同（前缀稳定性）；
- `mode = "off"` 时事件如实写 `off`。
