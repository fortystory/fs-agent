bubblewrap

图解 · 它是干什么的，凭什么管用

它不锁东西，它换你看到的世界

同一台电脑，两份「房间清单」。

房间里摆什么，由 bubblewrap 说了算。真实世界一点没动。

先给一个空房子，再把要的搬进来

你不搬的，它就不存在。

真的：bwrap -- /bin/sh 会报「找不到 /bin/sh」—— 空房子里什么都没有。

三种搬法

搬进来的时候，可以贴封条

🔒

搬进来 + 贴封条

--ro-bind 外面 里面

看得见、读得到，改不了。想写就报「只读」。

✏️

搬进来 + 能改

--bind 外面 里面

这份是能动的。工作区就用这个。

🧻

换个一次性的

--tmpfs /tmp

里面是新的空盒子，随便写；程序一退就没了。

🚪

顺手换别的清单

--unshare-net --unshare-pid

网络、别的程序，也各有一份「看得见吗」的清单。

一条真实的命令，逐段读

bwrap \
  --ro-bind / /            # 整个外面：搬进来，贴封条
  --bind "$PWD" "$PWD"     # 工作区：这份能改
  --dev /dev               # 设备（不搬的话很多程序起不来）
  --proc /proc             # 进程信息
  --unshare-pid            # 连「还有谁在跑」也不让它看
  --die-with-parent        # 我死了，里面的东西一起死
  -- bash -lc "make test"  # 真正要跑的命令

最后那条命令完全不知道自己在盒子里。它只是照常跑。

程序一退，房间就没了

外面的世界从头到尾没被改过。

被换掉的只是「这份清单」。它住在程序自己身上，程序一走就散。

它为什么不需要 root？

每个人都能给自己开一个小世界，在里面当管理员。

但这个「管理员」出了小世界一文不值 —— 所以不用给它特权。

它自己说：我不是安全边界

它管的是「别让程序乱来」，不是「防坏人」。

所以它适合的场景是：给一次自动操作一个可靠的失败点。

bubblewrap = 给程序换一份「看得见什么」的清单。

换清单这件事由内核担保，程序自己拆不掉；程序一走，清单就散。
