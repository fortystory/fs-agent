# 界面中文化：给人看的文本收进一个措辞层

Status: ready-for-agent

- **来源**：一次 `/grill-with-docs` 访谈敲定的 12 条决定，其中「哪些文本可以翻、哪些冻结」的边界已落成 `docs/adr/0001-chinese-ui-frozen-model-text.md`。本 spec 是那次访谈的折叠，不是新决定。
- **实现票落点**：`.scratch/chinese-ui/issues/NN-*.md`（由 `/to-tickets` 生成）。
- **前置**：`.scratch/fs-agent-v1/issues/23-width-in-columns-not-bytes.md`（中文宽度）已先行修完。它顺带暴露的两条与本次直接相关：状态行在窄终端会被硬截断、`speaker_label` 的续行缩进按字符数算。
- **术语**：叙述用中文（讨论者 / 执行者 / 合成器 / 事件 / 事件流 / 投影 / 转录 / 渲染器 / 回合 / 轮次 / 预算 / 落点），代码标识符用英文（`Debater` / `Executor` / `Synthesizer` / `Event` / `EventLog` / `project()` / `Session` / `Round` / `Turn` / `Block` / `Entry`）。正式词汇表在根目录 `CONTEXT.md`。

## Problem Statement

这个工具的叙述语言、spec、术语表全都是中文，模型也被要求用中文作答——但**围着对话的那一圈界面文本仍然是英文**：转录里的回合与轮次叙述（`turn iteration 1`、`round 1 (Independent)`、`turn ended: Completed`）、状态行与按键提示、权限与计划模式的询问、`/undo` 之类命令的反馈、三份 `--help`、启动与运行错误、以及 `sessions ls|show|replay|stats` 的全部输出。每次用完这个工具都要在两种语言之间来回切。

更难受的是两件与翻译本身无关、但会被翻译放大成日常问题的事：

1. **同一句话在四个地方各写一遍。** 转录由 TUI 与 plain 两个画家各画一遍，headless 又从事件自己导一遍文本，`sessions show` 再从第三种呈现类型（已结束会话的轮次分组视图）拼一遍。所以「把界面改成中文」在当前形状下会产出四份中文副本，而且**一定会漏**——现状就是漏着的：同一句话有四份实现。
2. **给人看的字没有任何单一位置可以一眼看全。** 想知道「界面上到底有哪些字」只能逐个文件读，于是任何一次措辞改动都无法确认覆盖率，也没法用一条测试守住它。

还有一处会直接影响观感：状态行是固定 62 列，在 40 列的终端上会被渲染库按宽度硬截断，`ctrl-c quit` 那几个字根本不会出现（票 23 记录）。

## Solution

把「给人看的文本」收进**一个措辞层**，并把它全部改成中文：

- **一个来源。** 新的措辞模块是所有人类可见短语的唯一出处：转录的叙述、状态行与按键提示、交互反馈、帮助、错误、以及 `sessions` 的输出词汇。它是一组**纯函数**（领域值 → 中文短语），与画家的样式和结构无关——颜色仍归画家，plain 的逐行前缀、TUI 的缩进、`sessions show` 的轮次分组各留原样。
- **翻译范围就是措辞层的全部调用点**，而措辞层本身让「还有没有漏的」变成「看一个模块」。
- **硬编码中文，不做运行期语言切换。** 没有 locale 参数、没有语言表、没有 i18n 依赖；换语言就是改这个模块。
- **枚举不再把 Rust 的调试格式印给人看。** 轮次模式、上下文来源、历史原因、停止原因、权限来源各有一个显式中文映射。
- **模型可见的那一侧原样冻结**（ADR 0001）：讨论者与合成器的 system prompt、投影拼出的轮次前缀、`AgentError` 的消息、以及 fs-agent 自己生成的工具结果文本。它们已经是中文，而且改它们会废掉 provider 的前缀缓存。
- **状态行变成宽度敏感**：按可用列数决定显示哪几条提示，窄终端先丢按键提示、只留状态词。
- **帮助文本从「直接打印」变成「返回字符串」的纯函数**，于是措辞层覆盖得到它，`main` 只负责打印。

## User Stories

### A. 转录（TUI 与 plain）

1. 作为用户，我想让转录里除了说话人名字之外的所有文字都是中文，以便读自己的工具输出时不必切换语言。
2. 作为用户，我想让轮次分节线是中文（例如「第 2 轮（独立首轮）」），以便一眼看懂现在处在讨论协议的哪一步。
3. 作为用户，我想让回合的开始与收尾叙述是中文，以便跟上进度。
4. 作为用户，我想让停止原因在文字上是中文，以便读懂这一回合为什么结束。
5. 作为用户，我想让工具调用的一行摘要是中文，以便快速扫过一串调用。
6. 作为用户，我想让工具的失败原因与后置 hook 的反馈是中文，以便判断要不要干预。
7. 作为用户，我想让权限询问与裁决的措辞是中文，以便清楚自己在同意什么、以及是谁做的决定。
8. 作为用户，我想让计划模式冲突的询问（覆盖 / 追加 / 保留）是中文，以便做出选择。
9. 作为用户，我想让执行者的派发与收尾叙述是中文，以便看懂嵌套会话在做什么。
10. 作为用户，我想让分歧块的标题与缩进条目是中文，以便读懂讨论的分歧点。
11. 作为用户，我想让方括号提示（上下文的注入来源、历史被取代、渲染器诊断）是中文，且其中的枚举值也用中文说明而不是内部名字，以便这些提示是给人读的。
12. 作为用户，我想让「没有消息」「流上没有结果」这类占位文本是中文，以便空白处也能读懂。
13. 作为用户，我想让说话人标签沿用既有形式（讨论者用它的名字、用户与系统用中文归属），以便转录的每一行归属仍然一眼可辨。

### B. 状态行与交互反馈

14. 作为用户，我想让状态行的工作 / 就绪状态是中文，以便知道现在能不能打字。
15. 作为用户，我想让按键提示用中文描述动作、键位名保持原文，以便知道按哪个键做什么。
16. 作为用户，我想让状态行在窄终端上按宽度取舍提示，以便它不再被硬截断、始终能读完。
17. 作为用户，我想让权限询问与计划冲突的输入行提示是中文。
18. 作为用户，我想让 `/undo`、`/plan`、`/endplan` 的反馈与未知命令的提示是中文。
19. 作为用户，我想让启动横幅（模型、模式、会话位置）是中文标签，以便启动时就知道自己站在哪一档。

### C. 帮助与错误

20. 作为用户，我想让主命令的帮助是中文。
21. 作为用户，我想让交互式会话的帮助是中文。
22. 作为用户，我想让 `probe`、`prune`、`sessions` 各自的帮助是中文。
23. 作为用户，我想让参数解析错误是中文，以便知道自己敲错了哪一项。
24. 作为用户，我想让启动期的拒绝与失败（以 root 运行、配置读不出、会话建不起来、运行环境缺失）是中文。
25. 作为用户，我想让会话级错误的错误码带中文说明，同时原始细节原样保留，以便既能读懂、又不丢排查线索。

### D. 可观测性（`sessions`）

26. 作为用户，我想让 `sessions ls` 的表头与「无会话」提示是中文。
27. 作为用户，我想让 `sessions show` 的轮次分组标题、过滤词与状态标签是中文。
28. 作为用户，我想让 `sessions replay` 与 `sessions stats` 的字段名、计价说明与统计标签是中文。
29. 作为用户，我想让「未登记的模型显示为无价格」这类说明性文本是中文。

### E. headless

30. 作为用户，我想让 headless 的进度叙述（走诊断出口的那些）是中文，以便我用管道或脚本时也读得懂。
31. 作为用户，我想让 headless 的纯净性契约在这次改动后不变——标准输出里仍然只有最终产物——以便我的管道不被打断。

### F. 术语与可维护性

32. 作为用户，我想让界面里的领域词与 `CONTEXT.md` 已定的中文名一致（讨论者 / 执行者 / 合成器 / 回合 / 轮次 / 投影 / 转录 / 预算 / 落点），以便界面和文档说的是同一套话。
33. 作为维护者，我想让「再加一条给人看的文本」只需要动一个地方，以便不会再长出第五份副本。
34. 作为维护者，我想让措辞层有它自己的测试，以便改文案时不必同时改三个画家的测试。
35. 作为维护者，我想让模型可见文本被明确标记为冻结、并让措辞层够不到它，以便将来没有人顺手把它一起翻了。
36. 作为维护者，我想让枚举对人类的呈现有唯一映射，以便不会再有人把内部调试格式直接印到界面上。

## Implementation Decisions

- **新增一个措辞模块。** 纯函数：领域值 → 中文短语。调用方是 TUI 的块渲染、plain 的绘制、headless 的事件叙述、帮助文本、错误文本、以及 `sessions` 的输出。它是本次唯一新增的接缝。
- **措辞层不管样式、也不管结构。** 颜色/加粗仍归画家；plain 的逐行说话人前缀、TUI 的缩进、`sessions show` 的轮次分组各留原样。共享的只有短语本身。
- **不做运行期 locale。** 没有语言参数、没有回退表、不引入 i18n 依赖。换语言等于改这个模块。
- **枚举对人类的呈现集中到唯一映射。** 轮次模式、上下文来源、历史原因、停止原因、权限来源、以及 provider 的结束原因，各有一个显式中文映射；已经存在的轮次模式标签（独立首轮 / 定向第二轮 / 合成）并入措辞层。界面上不再出现调试格式的枚举。
- **状态行变成宽度敏感。** `TuiState` 的状态行按可用列数取舍：窄终端先丢按键提示、只留状态词。它今天是固定 62 列，会被渲染库按宽度硬截断。
- **说话人续行缩进改为按显示列。** TUI 现在按字符数算缩进；标签一旦中文化，字符数与列数就会不一致（例如「用户」归属标签是 4 个字符 6 列），缩进会短 2 列。这一条必须与标签改动同一票落地。
- **会话级错误：细节保持英文、码加中文。** 事件流里的错误细节原样透传（它是诊断线索，且日志只追加），中文说明由渲染时按错误码映射。
- **冻结面（ADR 0001），措辞层不得被调用：** 讨论者与合成器的 system prompt、投影拼出的轮次前缀、`AgentError` 的消息、fs-agent 自己生成的工具结果文本。这些会进入模型的 `messages`，是 provider 缓存前缀的一部分。
- **headless 保留事件式推导**，只把短语换成措辞模块的；不并进共享的呈现类型。
- **帮助文本改为返回字符串的纯函数**，打印归 `main`。
- **两种呈现类型不统一。** `Block`（实时）与 `Entry`（已结束会话的轮次分组视图）保持各自的结构，措辞层同时服务两者。

## Testing Decisions

**什么样的测试是好测试。** 只测外部行为。对这个 feature，外部行为有两层，两层的断言方式不同：

1. **措辞层**：给定领域值，产出哪句中文。**这一层断言确切文本**——因为「单一来源」正是本 feature 的主张，而只有在这一层断言，才能区分「一处产出」和「四份一样长的副本」。
2. **画家与 CLI**：断言**语义**，不断言文本内容——画了没有、严重度颜色是否可区分、内容进的是滚动区还是实时区、标准输出的纯净性是否保持。在这一层断言文本会把本 feature 的收益（改一处、测一处）原样还回去。

**哪些模块会被测。**

- 措辞模块（新增接缝）：每个短语一条断言；状态行的宽度取舍也在这一层（给定宽度取哪几条提示，纯函数、无终端）。
- TUI 的显示状态与块渲染：沿用现有的无终端测试，断言改为语义。
- plain 渲染器：沿用现有的注入 sink 测试，断言改为语义。
- `sessions` 的可观测性：沿用现有「跑真 CLI、对 fixture 会话断言标准输出」的测试。
- headless 的标准输出纯净性：沿用既有的那条回归断言，本 feature 不得让它变红。

**prior art。**

- `tests/render_plain.rs`：注入两个 sink 后对事件序列断言输出——本 feature 沿用它的接缝，只改断言的口径。
- `tests/render_tui.rs`：无终端断言显示状态与块渲染；本 feature 新增的措辞测试与它同级。
- `tests/observe_cli.rs`：真 CLI 对 fixture 会话断言标准输出。
- `tests/e2e_single_turn.rs`：标准输出只放最终产物的那条端到端回归。
- 枚举标签的先例已经在讨论协议里存在（轮次模式的中文标签），本 feature 把它收进措辞层并推广到其余枚举。

## Out of Scope

- **运行期 locale**、语言切换、任何 i18n 依赖。
- **模型可见文本的翻译**（ADR 0001 冻结）：system prompt、投影前缀、说话者自身的错误消息、fs-agent 自己生成的工具结果文本。
- **统一两种呈现类型**（`Block` 与 `Entry`）。它们是两个不同用途的视图，本次只让措辞层同时服务它们。
- **让 headless 走共享的呈现类型**（S2 已定：保留它的事件式推导）。
- **改写事件流里已有的数据**：已经写下的错误细节、工具结果、消息正文一律不动（日志只追加、永久回放，语言按写入时刻冻结）。
- **面向实现者的文档**：`docs/*.md` 是英文的，但它们是给实现者的说明，不是界面文本；`CONTEXT.md` 本来就是中文。
- **TUI 终端所有权那一层缺接缝的问题**（票 21 与票 23 已记录）。本 feature 不新增那个接缝。
- **`truncate` 的内容预算单位**（按字符还是按列）。它不影响布局正确性，留待单独决定。

## Further Notes

- **术语纪律**：界面一律用 `CONTEXT.md` 已定的中文名。glossary 里没有的概念，先补 glossary 再写界面。本次盘点下来**不需要补新词**——「事件流 / 投影 / 转录 / 渲染器」这四个已有的词已经把可翻与冻结的边界画清楚了；边界本身作为**决定**记在 ADR 0001，不进 glossary（那里不许有实现决策）。
- **顺序已经买到的收益**：中文宽度的两个 bug 先修完了，所以本次遇到的对齐问题不会和「刚换成中文」混在一起分不清归谁。票 23 记的三条发现里有两条（状态行截断、续行缩进）在本 spec 范围内。
- **中文宽度让每一处对齐都变敏感**：每条票都必须在自己那条接缝上跑一次断言，不能只靠肉眼看「像是中文了」。
- **翻译的失败模式是漏，不是错**：措辞模块就是为了让「漏没漏」变成可回答的问题。逐条断言确切文本是这条主张的守门人。
