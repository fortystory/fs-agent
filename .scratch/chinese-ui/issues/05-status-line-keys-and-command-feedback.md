# 05: 状态行、按键提示与命令反馈

**What to build:** 会话里那一圈常驻文字出中文：状态行的工作 / 就绪状态、按键提示、`/undo` 与计划模式命令的反馈、未知命令的提示、以及启动横幅。其中**状态行要变成宽度敏感**：按可用列数取舍提示，窄终端先丢按键提示、只留状态词。

Blocked by: 01

Status: done

**参考:** spec §Implementation Decisions（`.scratch/chinese-ui/spec.md`）、票 23（中文宽度：状态行截断那条发现）

- [x] 状态行的工作 / 就绪状态是中文
- [x] 按键提示用中文描述动作，**键位名保持原文**（enter / esc / shift+tab / ctrl-c）
- [x] 状态行**按可用列数取舍提示**：窄终端上不再被硬截断、余下的部分总能读完整；「给定宽度 → 显示哪几条提示」这条判断在无终端层可断言
- [x] `/undo`、`/plan`、`/endplan` 的反馈是中文
- [x] 未知命令的提示是中文，且仍然告诉用户可用的命令
- [x] 启动横幅（模型 / 模式 / 会话位置）的标签是中文
- [x] 被碰到的既有断言改成断语义

**顺序:** 与其余 02–08 没有依赖，但都会往票 01 建的同一个措辞模块追加函数；两票同时改它会冲突，按号做或分批做。

## Comments

- 需求侧对应 spec 的 14–16、18–19 号 user story。
- 宽度敏感这条不是美化：今天状态行固定 62 列，40 列的终端上渲染库会在边界处直接停住，尾部那几个字根本不会出现（票 23 实测）。中文译完约 55 列，窄终端仍然放不下，所以必须按宽度取舍。
