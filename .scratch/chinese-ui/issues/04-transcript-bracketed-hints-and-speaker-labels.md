# 04: 转录：方括号提示与说话人标签

**What to build:** 三类方括号提示出中文——上下文注入的来源、历史被取代、渲染器自身的诊断——并且提示里的枚举值也换成中文说明，不再是内部名字。同时把用户与系统的说话人标签中文化（讨论者名字保持原样）。**续行缩进必须在同一票里改成按显示列算**：它现在按字符数算，标签一改就会错列。

Blocked by: 01

Status: ready-for-agent

**参考:** spec §Implementation Decisions（`.scratch/chinese-ui/spec.md`）、票 23（中文宽度：缩进那条发现）

- [ ] 上下文注入来源的方括号提示是中文
- [ ] 历史被取代的方括号提示是中文
- [ ] 渲染器自身的诊断（例如丢弃了多少事件）是中文
- [ ] 提示里的枚举值用中文说明，不再是调试格式的内部名字；新增所需的两个枚举映射
- [ ] 用户与系统的说话人标签中文化；讨论者名字原样保留
- [ ] **续行缩进按显示列计算**：中文标签下续行与首行对齐（今天按字符数算，会短 2 列）
- [ ] 两种画家都覆盖；被碰到的既有断言改成断语义

**顺序:** 与其余 02–08 没有依赖，但都会往票 01 建的同一个措辞模块追加函数；两票同时改它会冲突，按号做或分批做。

## Comments

- 需求侧对应 spec 的 11、13 号 user story。
- 缩进这条是票 23 的实测发现：中文字符数与列数不等（标签可能是 4 字符 6 列），所以「改标签」和「改缩进」不能分成两票，否则中间那一票的对齐是错的。
