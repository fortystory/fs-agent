# 05 — grilling：极小页高与三种空态

Type: grilling
Status: resolved
Part of: ../map.md
Blocked by: 04

## 问题

[01 号票](01-charting-decisions.md) 把「摘要页 + 折叠完成项 + 折行」定了，于是这一页有了三个
**今天不存在**的状态，每一个都会让「摘要」这个词露出破绽。几何由 [04 号票](04-prototype-page-and-detail.md)
先量出来，这一票在那些数字上裁定。

要谈清：

1. **页区极小**：页区地板 3 行（块字那一档 5 行），再小就不叫地板了。3 行里要放进度行 + 条目
   —— 放一条还是一条都不放？放不下时是**只留进度行**，还是像今天那样先给计数行（今天的规则是
   「计数行先留出来」，`todo.rs:56-75`）？窄终端（24 行）上用户会看到什么。
2. **全部做完**：未完成项为空、进度行写 `11/11 完成` —— 条目区留白、画一句「都做完了」、
   还是那一页就只剩一行进度？全部做完之后这一页还有存在的理由吗（页签是**闩**，清空列表它
   也不摘）。
3. **列表被清空**：模型发了一次 `todo([])` 或干脆不发 —— 页里写什么。一句「还没有待办」？
   空块？还是把进度行画成 `0/0`？这一句措辞归 `wording`，要定。
4. **一条放不下**：折行后的一条内容比页区还高 —— 截断到页区高度？照 `＋N 项` 的口径把它报成
   「放不下」？给出别的一种：这一条只画第一行 + 一个记号。
5. **`＋N 项` 的口径**：折掉完成项之后，那个数字说的是「还有几项**未完成**没画出来」还是
   「清单里总共几项」。**这一条与第 4 条一起定**。
6. **空列表时那个弹窗**：按钮还在不在？点开写什么（`没有待办`？还是干脆不开）？冻结项 8 说
   弹窗是快照，所以空列表的快照就是空 —— 但空弹窗是坏体验。
7. **降过级的情形**：终端 <80 列时左栏整栏隐藏（`layout.rs:72-73`），那这一页就完全看不见 ——
   有没有替代路径（提示行说一句？转录里那一行本来就在）？**默认答案可能是「不做」**，但要写明理由。

## 作答

六问，**2026-10-09 维护者当场拍板，全取推荐**。数字来自
[04 号票](04-prototype-page-and-detail.md) 的帧草图与
[02 号票](02-research-wiring-for-todo-page.md) 第 10 条的算式。

1. **极小页区（40×3 / 40×5 / 28×5）= 进度行 + `＋N 项`，一条都不画**。
   40×3 的帧就是全部正文：`2/11 · 1 个在做          详情` + `＋9 项`。28×5 能画出一条折行项（3 行）
   再报 `＋8 项`。
   **被否决**：砍第一条砍到几行算几行（一半的句子比没有更糟，且把正在进行的那条切了）；
   **被否决**：只留进度行不报溢出（读者不知道下面还有东西）。
   注意这一档**永远只有宽档会到 3 行**（120×12），窄档最矮是 28×5 —— 所以「一条都画不出」是
   120×12 那一档独有的一帧，不是一般情况。
2. **全部做完 = 就一行 `11/11 完成`**。不加句子，条目区留白。
   **页签不动**：它本来就是一只**闩**（`todo.rs:8-10`）—— 见过一次非空列表，此后整个会话都在，
   清空列表也不摘。做完了仍在，是「这一页回答『还有什么没做』，答案是没有」。
   **被否决**：完成后页签退场（推翻 `todo-and-modes` §4 的「看见就一直在」）；
   **被否决**：加一句「都做完了」（信息已经在计数里，而那一句会变成常驻文案）。
3. **列表被清空 = 一句 `还没有待办`**，页签仍在。措辞落 `wording`（`todo_empty()` 一族，照
   `files_loading()` / `changes_empty()` 的惯例）。
   **被否决**：进度行写成 `0/0`（形状与有列表时相同，但读不出「该做点什么」）；
   **被否决**：什么都不画（一块空白分不清是「没有」还是「坏了」）。
4. **一条放不下 = 画它的前几行，末行末尾加 `…`**（`…` 是既有记号，文件页的名字超宽就用它收尾）。
   **被否决**：跳过它并计入 `＋N 项`（口径统一，但正在进行的那条会被那个数字藏起来，而它正是
   最该被看见的一条）；**被否决**：截断到页区高度不加记号（看不出是「长」还是「坏」）。
5. **`＋N 项` 的口径**由 [04 票](04-prototype-page-and-detail.md) 定为**没画出来的未完成项数**；
   本票补一条与之配套的：**被 `…` 截断的那条不算进去**（它至少露了一行）。所以那个数字永远是
   「一条都没露出来的还有几条」。
6. **空列表时不给按钮**：进度行上那一小块**不画、不可点**，点不开弹窗。列表重新落地（哪怕
   只有一项）它自己回来。
   **被否决**：按钮照旧、弹窗里写「没有待办」（形状一致，但空弹窗是坏体验；弹窗的存在理由是
   「看全」，没有可看的东西就没有弹窗）。
7. **终端 <80 列（左栏整栏隐藏）不做替代路径**：不加提示行、不加别的入口。
   理由有二：转录里那次 `todo` 调用本来就在屏幕上（用户读得到模型刚提交的整份列表）；
   而左栏的可见性是**用户自己的**意图（`Ctrl-O`，`sidebar-toggle` 的立论）加终端宽度，两条判据
   相乘 —— 我们不该在用户明确收起之后往别处塞一份。
   **被否决**：提示行说一句进度（把页上的东西搬一句过去，窄屏从此多一条常驻信息，而它是复述）。
