> 规格：[`../spec.md`](../spec.md) 的实现决定 §2 与 §3 的字形那一条、用户故事 A 与 B 的大部分
> （[grilling：charting 当场拍板](../issues/01-charting-decisions.md) 的第 2、3、6、7、10 条）。
> 这是这一 feature 的 **tracer bullet**：面板 → 行 → 屏幕，这条窄而完整的路径一次打通。命中区域
> 与详情留给 10。

**What to build:** 模型提交一份待办之后，左栏 `todo` 页的**第一行**是一条进度行（`2/11 · 1 个在做`），
下面列的是**全部未完成**的项，正在做的那条排在最上。做完的项从页上消失（今天它们占着行，于是
「剩下的事」在页面上不是任何一块连续的东西）。

## 验收

- [ ] 页区第一行是进度行，三种情形都对：有正在做的写 `2/11 · 1 个在做`、全做完写 `11/11 完成`、
      其余只写 `2/11`
- [ ] 页上**只列未完成**的项；已完成的项不再出现
- [ ] 正在做的那条排在最上，其余保持模型提交的顺序
- [ ] 状态字形是 `☐` 待办 / **`●`** 正在做 / `✓` 做完；`▸` 不再出现在这一页
- [ ] 带目标条目 id 的项仍画出那两位数字（它是「这项对目标清单哪一条」的凭据）
- [ ] 页签仍是**闩**：见过一次非空列表之后，清空列表它仍在
- [ ] 三句文案与三个字形归进措辞层里 `todo` 一族的**独立小节**（照改动页那一族的分隔注释写法），
      不继续堆在今天那三句的旁边
- [ ] 帧测试只读**左栏那几列**（既有纪律：转录里可能含同样的词，断言要能定位到左栏）
- [ ] 窄口测试：给一块页区矩形，面板吐出的行是「第一行进度 + 若干条目」；页区只有一行时只出进度行
- [ ] 这一票**不接命中区域**：点页里任何一格仍然什么都不做（那条既有测试照旧绿）

## 评论

落地（2026-10-09）：面板的 `lines` 从「末行一条计数」换成「**首行一条进度** + 未完成项」，
`in_progress` 的按提交顺序置顶、其余保持原序（`partition` 一次过，不排序）。措辞层里给 `todo`
一族起了**独立小节**：`todo_progress(done, total, busy)` 替掉 `todo_count`，三枚字形搬进去，
`TODO_IN_PROGRESS` 从 `▸` 换成 `●`，于是「`▸` 在 todo 页是进行中」那条**双义登记整段删掉**
（字形不再同形，登记也就没有对象了）。

四个既有断言跟着改了形状，都在说同一件新事实：帧测试重写成「进度行在最上 + 正在做排最前 +
做完的不在页上 + 页上没有 `▸`」；「放得下就全画」那条从 `已完成 0/12` 改成 `0/12`；清空那条从
`已完成 0/0` 改成 `0/0`；面板级与真实会话那两条逐行比对换成新形状。命中区域没动 ——
`clicking_a_todo_row_opens_nothing` 照旧绿（那是 10 票要改写的）。

`cargo test --test render_layout` 273 passed / `--test todo` 14 passed；clippy 与基线同（84 条
既有警告，本票没有新增）。
