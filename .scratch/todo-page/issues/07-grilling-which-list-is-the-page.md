# 07 — grilling：多 speaker 时页上那一份是谁的

Type: grilling
Status: resolved
Part of: ../map.md
Blocked by: —

## 问题

[01 号票](01-charting-decisions.md) 定了这一页怎么画，但它没碰**它画的是哪一份列表**。今天
[`TodoPanel::observe`](../../../src/render/todo.rs) 排除 `SpeakerId::Executor`，所以**讨论者
（debate participant）的那几份与主会话的落进同一个 `items`**、后落地的那份整份胜出（工具是
replace-all，`todo.rs:4-13`）。页还是纯读数时这件事不容易被看见；页变成「摘要 + 弹窗、看全靠
弹窗」之后，读者会直接读到**别人那一份**。

要谈清：

1. **今天到底是谁的那一份**：先核事实 —— `SpeakerId` 有哪些值、`observe` 收到过哪几种、
   讨论会话里同一次发言能不能同时带两份 `todo` 调用（能的话后落地胜就是没有规则的规则）。
2. **页上标不标出处**：像转录那样给这一页标出 speaker / 头像，还是这一页**只算主会话**的
   （讨论者的调用不再落进它）？后者等于改投影规则，代价是什么。
3. **讨论会话里的语义**：一次 debate 里每一方各有一份计划 —— 用户想看的是「本方」还是「各方」？
   各方要不要分行、要不要能切换。
4. **抖动**：后落地胜 + 展开的折行 + 折叠完成项 —— 多方交替提交时这一页会不会每帧都在变。
   要不要「每一方各一份快照，按最后落地时间取」这一种更稳的规则。
5. **执行者那份**：仍然**不进**左栏（[01 号票](../map.md#明确不做) 的明确不做里写着）—— 确认一遍，
   顺带说清它在转录里是不是仍然读得到（[`todo.rs:11-13`](../../../src/render/todo.rs) 说读得到）。

这一票若发现「页上那一份是谁」根本不是呈现问题、而是投影规则问题，**说出来**并按
[01 号票](../map.md#tracker-事实与降级本图适用) 的规矩办：要么留在本图（它确实是这一页画什么的
前提），要么记进 map 的「明确不做 / 尚未明确」并说明理由。

## 作答

四问，**2026-10-09 维护者当场拍板，全取推荐**。

**先核事实**（本票自己查的，`src/events.rs:85-90`、`src/render/todo.rs:36-49`、
`src/discussion/protocol.rs:127`）：

1. `SpeakerId` 有四个变体：`Debater(ParticipantId)` / `Executor(ParticipantId)` / `User` /
   `System`。工具调用块带 speaker，页排除的只有 `Executor`。
2. 所以页上那份今天的准确说法是：**最后一次由任意讨论者（`Debater`）提交的整份列表** ——
   单 agent 会话里那就是主会话那一份，而 discussion 里各方都往同一个 `items` 里落，**最后一个
   落地者整份胜出**（工具是 replace-all）。`User` / `System` 不调用工具，不参与。
3. 讨论协议要求发言者必须是 `Debater`（`discussion/protocol.rs:127`），而讨论是**严格轮流**的 ——
   所以「最后一个落地者」在视觉上就是「刚发言的那一方」。

据此：

1. **取哪一份：保持「最后一个非执行者落地者胜」，规则一个字不改。** 不引入「本方」概念 ——
   discussion 里双方对等，没有「我这一方」；也不把各方并排 —— 那要么占多屏，要么要焦点行与键盘，
   两者都超出本次 destination（[「明确不做」](../map.md#明确不做)：不加键盘遍历）。
   执行者那份**仍然不进左栏**，与 `todo-and-modes` §2 一致：那是它自己的工作记录，只在转录里
   读得到（转录里每一方的 `todo` 调用都是一条 Tool 行，页上则只有非执行者那一份）。
2. **归属只写进弹窗标题**：`── 待办 · kimi ──`（名字取 `wording::speaker_label` 那一族的形式）。
   **页上不标** —— 28 列里进度行已经 `文案 15 + 间隙 9 + 详情 4 = 28`（04 票第 2 条），挤不进
   第三样东西；而左栏三页一律**不给色**（文件页、改动页都靠结构而不是颜色分层），给 todo 页开
   一个 speaker 色会是那一族里的唯一例外。读者想确认是谁，点开弹窗就知道。
3. **抖动：接受切换。** 轮流协议下切换的频率就是发言的频率，而「刚才是谁在动手」正是这一页
   此刻最该告诉读者的事。**被否决**：第一次提交后冻住（页会停止回答「现在是谁在做」，而那正是
   多 agent 会话里最常被问的那件事）。
4. **这不是投影问题，是呈现的一个属性** —— 页上那份一直就是「最后一次非执行者提交」，变的只是
   现在把**它是谁**说出来了。所以留在本图，不必另起 effort。

**给 spec 的一条实现提醒**：`TodoPanel` 现在只有 `seen` 与 `items`，要留住 speaker 就得加
**一个字段**（记最近一次被观察到的那个 `todo` 块的 speaker）；`DetailKind::Todo` 的标题在**打开
那一刻**取它（快照的一部分，冻结项 8），此后 `observe` 改写 `state.todo` 不影响开着的弹窗
（02 票第 3 条已经确认这条不需要额外机制）。
