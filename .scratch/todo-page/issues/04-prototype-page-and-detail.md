## 问题

[01 号票](01-charting-decisions.md) 把形状定死了（页顶一条进度行 + 全部未完成项、`in_progress`
置顶、长文本折行、已完成项折掉、放不下报 `＋N 项`、进度行右端一个按钮、点开是新增的一种详情），
但**没有一张图**。在 40×15 与 28×19 两块页区、以及 135 列封顶的弹窗里，这些排在一起到底长什么样？

这一票只画**长什么样**，不重开形状。走 `/prototype`：**画出来**，把取定值与被丢掉的备选收进
本票 `## 作答`。几何与接线事实取自 [02 号票](02-research-wiring-for-todo-page.md)（那票先跑）；
别人的先例取自 [03 号票](03-research-other-agents-plan-ui.md)。

### A. 页那一侧

1. **先量**：按 `layout.rs` 的真实算式，120×24 与 80×24 两档页区各多少行；**页区地板那一档**
   （3 行，块字 5 行）下「进度行 + 一条折行后的条目」放不放得下 —— 放不下就要回去改 05 票的问题。
2. **进度行**：文案 `3/11 · 1 个在做` 在 28 列里占几列；全部做完那一档 `11/11 完成` 几列；
   右端的按钮留几列才不至于把文案挤断。**量出来**，放不下时列出三个退路（换更短的文案 /
   按钮只用一个字形 / 按钮移到页内第一行）各要几列 —— 选哪一条是 06 票的事，这里只出数。
3. **条目行**：字形 + 可选 id（两位数字）+ 内容。折行的**续行缩进到哪一列**（字形列之后？
   id 之后？两格？），带 id 与不带 id 的两种行折完之后还同列吗 —— 文件页那条「同层名字严格同列」
   的规矩在这儿能不能照抄。
4. **折行预算**：折行是按 `pane::wrap_text` 那一套吗，预算从哪几列里扣；一个 60 字的中文 `content`
   在 28 列里折成几行。
5. **`in_progress` 置顶**：置顶之后其余项保持原顺序 —— 帧里画一个「提交顺序与显示顺序不同」的
   例子（模型把第 5 项标成在做），看这个置换读不读得出来。
6. **`＋N 项`**：折掉完成项之后，它报的是「还有几项**未完成**没画出来」；这一行是占页区一行、
   还是替代掉最后一行。
7. **状态字形**：换掉 `▸` 之后用哪一个（在 `wording.rs` 既有字形集里挑，还是新登记一个）；
   `☐` 与 `✓` 留不留。

### B. 弹窗那一侧

8. **标题**：写什么（`待办` / `待办清单` / 进度那一句）；135 列封顶下居中还是靠左。
9. **正文宽度**：用 `Regions::detail_text_width()`；两档各多少列。
10. **整份列表的排版**：进度行 + 进行中 + 待做 + 已完成（降暗）。已完成那几项**另起一段还是
    连续排**（map「尚未明确」那条在这里出答案）；一段之间要不要空行或一条分隔线。
11. **带 id 的行**：`✓ 03 补测试` 这种，id 列宽固定几格、折行续行对齐到哪一列。
12. **滚动**：条目多到一屏之外时，弹窗自己滚（详情覆盖层本来就支持）；滚到底要不要一句
    「还有 N 项」。
13. **框那一圈**：宽度用满还是留白；与左栏那一页的关系要不要在弹窗里说一句（哪一份列表、谁写的）。

## 作答

**产物**：[`prototype/frame.py`](../prototype/frame.py) —— 一份可执行的帧草图（`python3
.scratch/todo-page/prototype/frame.py` 重画五块：`page` / `wrap` / `indent` / `detail` /
`variants`）。它按仓库的真实常量算（出处标在脚本顶部每一行右边），折行是 `pane::wrap_line` 的
最小复刻。**2026-10-09 维护者当场对着帧拍板**（五问：续行、前缀口径、弹窗里完成项、进行中的
字形、折行劈词）。

### A. 页那一侧

1. **几何**（与 [02 票](02-research-wiring-for-todo-page.md) 第 10 条一致）：120×24 ⇒ 页区
   **40×15**，80×24 ⇒ **28×19**；**3 行地板只在宽档出现**（120×12），窄档最矮是 80×10 的
   **28×5**，块字档 5 行地板是 120×32 的 40×5。**3 行那一档放不下任何一条**（见第 6 条），
   喂给 [05 票](05-grilling-cramped-and-empty.md)。
2. **进度行与按钮在窄档放得下**：文案 `2/11 · 1 个在做` 占 **15 列**（`2/11` 4 列 + `wording::SEP`
   的 ` · ` 3 列 + `1 个在做` 8 列），全做完那一档 `11/11 完成` 占 **12 列**。窄档 28 列 ⇒
   **文案 15 + 间隙 9 + `详情` 4 = 28**。三个退路的账都量了：按钮只用一个 ASCII 记号（3 列、
   间隙 10）；整页可点、不要按钮（间隙 13）；换更短文案 `2/11`（4 列、间隙 20）。**按钮的字形
   留给 [06 票](06-grilling-hit-regions-and-overlays.md)** —— 它问的正是「那一小块好不好找」，
   而这里给出的结论是**四个退路全都放得下**，所以那不是几何问题而是可发现性问题。
3. **前缀取 `aligned`**：字形 1 + 空格 1 + id 2 + 空格 1 = **5 列**，带 id 与不带 id 的两行
   **内容严格同列**（照抄文件页「字形列每行都占满两格」那条规矩）。代价是窄档正文只剩 **23 列**。
   **被否决**：`tight`（有 id 才占那 3 列，内容 26 列，但两类行不齐 —— 帧 A 组第三条就是它）；
   **被否决**：不留 id 列（正文 26 列，但页上再也看不到「这项对目标清单的哪一条」的凭据，
   而 `CONTEXT.md` 的「待办列表」词条把 id 写成认得出的关键）。
4. **折行预算**：前缀 5 列扣掉之后，窄档正文 23 列 / 宽档 35 列。实测条数：3 字 1 行；25 字
   **3 行 / 2 行**；42 字 **4 行 / 3 行**；120 字 **11 行 / 8 行**。`wrap_line` **按字符硬切、
   不保词**（`pane.rs:444-464`），所以 `/to-tickets` 在真机上就是 `/to-ticke` + `ts`。
   **这一条照旧，不为本页另写保词折行** —— `wrap_line` 是公共件（工具输出、diff、问答题都在用），
   为了一页去动它是更大的一个决定，而 28 列侧栏里一次断词可以接受。**写进 spec 的已知代价**与
   真机观感项。
5. **`in_progress` 置顶读得出来**：帧里第 5 项被标成在做、页上它排在第一条，置换一眼可见
   （`●` 与 `☐` 的区别加上位置）。**不另加视觉分层**（置顶 + 字形已经够）。
6. **`＋N 项` 报的是没画出来的未完成项数**，占页区**最后一行**（挤掉一条条目的位置）。
   40×3 那一档它就是全部正文：`2/11 · 1 个在做` + `＋9 项`，**一条都画不出来**；28×5 那一档
   能画一条（折 3 行）+ `＋8 项`。
7. **状态字形**：`☐` 待办 / **`●`** 进行中 / `✓` 完成。**`●` 是维护者当场挑的**（备选 `◐`
   `▓`）；`▸` 退出这一页 —— 它今天与转录里可折叠块的标记同形（`wording.rs:1907`）。
   **要在真机上核的一件事**：`☐` `✓` `●` 都是 East Asian **Ambiguous** 宽度，帧里按**一列**算
   （与 `☐` 今天在窄档的实际排布一致）；换字体后若 `●` 变成两列，前缀就变成 6 列、正文少一列。

### B. 弹窗那一侧

8. **标题**：`── 待办 ──…── esc 关闭 ──`，照 `wording::detail_section` 的 `── 名字 ──` 一族
   （`wording.rs:351`）与覆盖层既有的 `esc 关闭` 页脚。
9. **正文宽度**：`Regions::detail_text_width()` —— 120 列屏 ⇒ **112**，80 列屏 ⇒ **72**
   （`min(屏宽-4, 135)` 减边框 2 与两侧内边 2，`layout.rs:602-628`）。**不是框宽**。
10. **完成项连续排**：`✓` + MUTED，一段空行隔开即可，**不加 `── 已完成 ──` 小标题**（页顶那句
    `2/11` 已经说了「11 条里 2 条做完」，标题是重复的第二份）。帧 C 组是两种摆法并排。降暗落
    **`MUTED`**（`palette.rs:23`；票 02 第 6 条：色板里没有 dim 这一档，`MUTED` 的注释明说
    「再退一档只能靠结构」—— 完成项有 `✓`，结构已经在）。
11. **带 id 的行**：与页同一条 `item_lines`，id 位补满、续行对齐到内容列（帧里
    `~✓    摸清仓库现状…` 那几行）。弹窗折行走 `folded_text`（`tui.rs:8517-8533`），与页同一套。
12. **滚动**：交给覆盖层既有的滚动（`detail_scroll`，`tui.rs:8588-8594`），**不另写一句
    「还有 N 项」** —— 滚到底就是底，`detail_footer(position, total)` 那一族已经在页脚写着位置。
13. **宽度用满**（`detail_text_width` 就是满的那个），标题里**不写**「哪一份列表、谁写的」——
    打开它只可能来自这一页的按钮，而 [07 票](07-grilling-which-list-is-the-page.md) 要回答的是
    「多 speaker 时页上那一份是谁的」；那件事若有结论再补标题，不在这里先占一行。

### C. 真机观感项（折 spec 时写进手工清单）

- 两档下这一页读不读得下去 —— 尤其窄档 23 列正文，一条 25 字就折 3 行，一屏读得到几条。
- `●` 在真字体下是一列还是两列（见第 7 条）。
- `MUTED` 的完成项在真配色下退不退得后；三枚字形在 28 列里够不够分。
- 进度行右端那一小块按钮（4 列）好不好找、误不误触。
- 折行把 `/to-tickets` 断成两片时，读起来刺不刺眼。

### D. 这一票与图的关系

- 图「尚未明确」里三片雾在这里出答案：**弹窗里完成项怎么分组**（连续降暗）、**按钮在窄档放不
  放得下**（四个退路全放得下，于是它是可发现性问题而不是几何问题，交给 06）、**`＋N 项` 的口径**
  （没画出来的未完成项数）。
- **原型的净产出是那个撞车**：冻结项 5 写「续行缩进到字形列」，而 `pane.rs:442` 写着「续行从
  第零列起 —— 窗格是一份日志，缩进会主张一种折行后的文字并没有的结构」。维护者当场判**缩进**
  （本页不是日志；缩进主张的是「这片属于哪一项」，那是真结构）。spec 里要写清它是对 `wrap_line`
  纪律的一次**有意例外**，以及为什么。
- **没有新 fog 浮出来**：40×3 那一档一条都画不出来这件事不是新雾，它本来就是 05 票第 1 问。
